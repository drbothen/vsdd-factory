=== Property descriptions ===

prop_extract_frontmatter_byte_equals_prefix (Property 1 — structural oracle):
  Input: arbitrary Vec<u8> up to 512 bytes
  Verifies three independent structural invariants:
  A. Prefix invariant: extracted is always a byte-prefix of input (starts_with check)
  B. Delimiter partition (None case): if extracted == input, no delimiter form is
     present anywhere in input (all 4 forms: \n---\n, \r\n---\r\n, \n---/\r\n--- at EOF)
  B. Delimiter partition (Some case): if extracted is a proper prefix, the bytes
     immediately after extracted begin with one of the 4 delimiter sequences
  C. Minimality: extracted contains no inline delimiter (\n---\n or \r\n---\r\n) —
     ensures the first occurrence is used, not a later one
  Oracle is NOT tautological: it never recomputes expected offset via impl's search
  algorithm. A shared ordering/offset bug is caught by Invariant C.

prop_extract_frontmatter_is_deterministic (Property 2 — determinism):
  Input: arbitrary Vec<u8> up to 512 bytes
  Verifies: two consecutive calls with same input produce byte-identical output slices
  Closes: VP-096 determinism requirement

prop_extract_frontmatter_crlf_byte_equals_prefix (Property 3 — CRLF known-answer):
  Input: prefix (Vec<u8> no-LF, 0..100) + "\r\n---\r\n" + suffix (Vec<u8> no-LF, 1..50)
  Verifies: extracted == input[0..prefix.len()] exactly (exclusive of delimiter)
  The prefix and suffix are LF-free so no LF delimiter can appear before the CRLF form,
  making the expected offset deterministic.
  Closes: EC-017 (CRLF line endings) + BC-4.13.001 v1.15 Invariant 9 CRLF clause
