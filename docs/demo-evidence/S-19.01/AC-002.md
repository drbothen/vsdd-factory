# AC-002 Evidence: Stale-Verdict Detection via check-stale-verdict.sh

**Story:** S-19.01 — pr-manager hardening: READY verdict HEAD-SHA pinning + release-PR merge-strategy guard + shell-dialect simulation discipline
**AC:** AC-002 (traces to BC-5.42.001 PC-2, Invariant 2)

## Claim

Before the orchestrator issues a merge instruction, it MUST invoke
`check-stale-verdict.sh <pr_number> <covered_sha>`. The script calls
`gh pr view <pr_number> --json headRefOid,state` and compares the returned SHA
against `covered_sha`. If they differ (stale verdict), the script exits non-zero
with `STALE_READY_VERDICT: PR #<n> HEAD <current> != covered_sha <pinned>` on
stderr. Fail-closed arms also cover: closed/merged PR state (arm 3), null/absent
state field (arm 3a), malformed gh JSON (arm 4), and malformed covered_sha.

**T-003** (negative control — stale verdict): Mocks `gh pr view --json headRefOid`
returning `bbbb1111...` while `covered_sha=aaaa0000...`. Asserts exit 1 and
`STALE_READY_VERDICT` sentinel in stderr, along with both SHAs and the PR number.

**T-004** (positive control — fresh verdict): Mocks `gh pr view --json headRefOid`
returning the same SHA as `covered_sha`. Asserts exit 0 (silent success).

**T-013** (canonical format gate): Verifies the exact BC-5.42.001 §Description b
wording verbatim:
`STALE_READY_VERDICT: PR #42 HEAD bbbb111111111111111111111111111111111111 != covered_sha aaaa000000000000000000000000000000000000`

**T-016** (EC-002 / Invariant 5): 40-char uppercase-hex covered_sha is rejected
before any `gh` call with `READY_SHA_MISSING: covered_sha is malformed`.
Confirms lowercase-only enforcement.

**T-018** (EC-003 / ADR-030 §Decision 2 arm 3): Mocks `gh` returning
`state=closed` with a matching headRefOid. Despite SHA match, the closed state
triggers `CHECK_STALE_VERDICT_ERROR: PR #42 is closed (expected: open)`. PR
closed between READY verdict and check invocation is a blocking condition.

**T-019** (arm 4 — malformed JSON): Mocks `gh` returning empty string `""` (not
valid JSON). The script cannot parse headRefOid or state; emits
`CHECK_STALE_VERDICT_ERROR: unable to parse gh JSON response for PR #42`. Ensures
no silent pass-through on unparseable output.

**T-020** (F-P5-001 — JSON null headRefOid): Mocks `gh` returning
`{"headRefOid":null,"state":"open"}` (JSON null, not a string). The grep-based
parser cannot match the unquoted null; the script correctly detects the absent
SHA and emits `CHECK_STALE_VERDICT_ERROR` (arm 4 catch-all).

**T-033** (F-P15-001 — null state field): Mocks `gh` returning
`{"headRefOid":"cccc...","state":null}`. Even though the SHA matches, the null
state cannot be confirmed as "open". The script fails-closed with
`CHECK_STALE_VERDICT_ERROR: unable to determine PR state for PR #42` (arm 3a).
This is the critical fail-closed arm added in the pass-15 fix burst.

### Script path: `plugins/vsdd-factory/bin/check-stale-verdict.sh`

Key implementation properties verified by the tests above:

- Bash-3.2 compatible: uses `while IFS= read -r` (no `mapfile`), `grep -oE`,
  `printf`, and `tr` — no bash 4.0+ features.
- Step 1: validates `covered_sha` via `grep -qE '^[0-9a-f]{40}$'` before any
  network call — uppercase hex or malformed strings fail before `gh` is invoked.
- Step 2: invokes `gh pr view "${PR_NUMBER}" --json headRefOid,state 2>/dev/null`;
  on failure emits `READY_SHA_FETCH_FAILED` verbatim (BC-5.42.001 EC-001).
- Step 3: parses both `headRefOid` and `state` fields in a single gh call (a
  single JSON fetch, not two separate calls — efficient and atomic).
- Arms 3/3a/4: close all fail-open paths: closed state, null state field,
  malformed JSON, absent headRefOid.
- Step 4: SHA comparison with `[[ "${LIVE_SHA}" == "${COVERED_SHA}" ]]`.
