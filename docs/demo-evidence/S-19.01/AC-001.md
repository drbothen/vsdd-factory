# AC-001 Evidence: covered_sha Enforcement via pr-manager-completion-guard WASM Hook

**Story:** S-19.01 — pr-manager hardening: READY verdict HEAD-SHA pinning + release-PR merge-strategy guard + shell-dialect simulation discipline
**AC:** AC-001 (traces to BC-5.42.001 PC-1, Invariant 1, Invariant 5)

## Claim

Every READY verdict emitted by the pr-manager SubagentStop message MUST include
a `covered_sha: <40-lowercase-hex>` field. The `pr-manager-completion-guard` WASM
hook (SubagentStop event) inspects `last_assistant_message`; if a READY verdict
token is present but no valid `covered_sha:` field exists, the hook emits advisory
code `READY_SHA_MISSING`. When `gh pr view` fails or returns empty,
`check-stale-verdict.sh` exits non-zero with
`READY_SHA_FETCH_FAILED: gh pr view failed for PR #<pr_number>` on stderr.

**T-014** (AC-001 / BC-5.42.001 EC-001 canonical format): Verifies exact verbatim

**T-032** (AC-001 / F-S1901-P12-001): Verifies `pr-manager.md` Step 8-pre-A
does NOT contain a `re-fetch-covered_sha` fallback. The orchestrator MUST halt
and re-dispatch pr-reviewer when `covered_sha` is absent — it must never silently
re-fetch the SHA itself, which would nullify the staleness guarantee.
