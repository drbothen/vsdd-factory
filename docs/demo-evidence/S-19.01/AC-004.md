# AC-004 Evidence: Darwin-Leg Shell-Dialect Simulation Discipline

**Story:** S-19.01 — pr-manager hardening: READY verdict HEAD-SHA pinning + release-PR merge-strategy guard + shell-dialect simulation discipline
**AC:** AC-004 (traces to BC-5.42.001 D-g operational discipline note; not a direct BC Postcondition — darwin-leg discipline is an auxiliary enforcement mechanism for BC-5.42.001 Invariant 3)

## Claim

Darwin-leg CI script validation in the test harness uses `/bin/bash` (macOS system
Bash 3.2.x), not `bash` from PATH (which may be Homebrew Bash 5.x). A preflight
assertion in `bats setup_file` verifies that `/bin/bash --version` contains
`version 3.2` on macOS runners; on wrong interpreter, exits non-zero with
`DARWIN_LEG_WRONG_INTERPRETER`. The `bats-darwin-leg-macos` CI job runs on
`macos-latest` as a required status check. A mechanism test (T-017) extracts the
`while IFS= read -r` loop fragment from `release.yml` (the rc.22 failure site) and
executes it under `/bin/bash` 3.2 with a fixture registry, pinning the regression.

Note: T-009 is correctly skipped on macOS (it is a Linux-runner guard that asserts
      graceful skip behavior on non-Darwin platforms; the bats-darwin-leg-macos CI
      job runs on macOS, so this skip is the expected result per EC-003).

**T-008** (wrong interpreter gate): Invokes `darwin-leg-preflight.sh` with
`PREFLIGHT_BASH_BIN` seam set to `stub-bash-version.sh` (which reports
`GNU bash, version 5.1.0(1)-release`). Asserts exit non-zero and
`DARWIN_LEG_WRONG_INTERPRETER` in stderr. Confirms the preflight sentinel fires
when `/bin/bash` is not 3.2.x.

**T-009** (Linux graceful skip): On Linux runners (uname != Darwin), the darwin-leg
preflight exits 0 immediately. This test is skipped on macOS (correct: it tests the
Linux-platform guard, which is not exercised on macOS). The `bats-darwin-leg-macos`
CI job only runs on `macos-latest`, so this test documents EC-003 behavior without
false-failing the macOS suite.

**T-017** (regression pin — rc.22 failure site): The critical mechanism test.

1. Builds a fixture work directory with a copy of `hooks-registry.toml` and stub
   `.wasm` files for every declared plugin.
2. Extracts the "Verify registry-declared WASM plugins are staged" step shell body
   from `release.yml` via `awk`, stripping the 10-space YAML indent, prefixing
   `#!/bin/bash` and `set -euo pipefail`, and writing to a temp script.
3. Pre-flight: confirms the extracted fragment contains `while IFS= read -r` and
   does NOT contain `mapfile` (regression detection: if `mapfile` is ever
   reintroduced into `release.yml`, this check fails with a clear error message).
4. Positive test: runs the extracted fragment under `/bin/bash "${pos_script}"`.
   Asserts exit 0 and `Registry-vs-staged: all` staging verdict in output.
5. Negative control: creates a `mapfile`-based equivalent and runs it under
   `/bin/bash`. Asserts exit non-zero (mapfile fails under bash 3.2). Confirms
   the positive test is load-bearing — not a vacuous pass because bash 3.2 is
   actually in use.

### Darwin-leg preflight assertion (setup_file)

```bash
# From plugins/vsdd-factory/tests/pr-manager-hardening.bats setup_file:
if [[ "$(uname)" != "Darwin" ]]; then
    return 0
fi
local bash_version
bash_version="$(/bin/bash --version 2>/dev/null | head -1)"
if ! printf '%s' "${bash_version}" | grep -q 'version 3\.2'; then
    printf 'DARWIN_LEG_WRONG_INTERPRETER: expected /bin/bash 3.2.x, got %s\n' \
        "${bash_version}" >&2
    return 1
fi
```

This runs in `setup_file` (before any test) — failure aborts the entire suite,
preventing any darwin-leg test from executing under the wrong interpreter.
