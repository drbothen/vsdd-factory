## 2. Verification method rationale

- **Kani (VP-116).** The shard-cap comparison (`projected_size = current + net_delta`; inclusive
  `<=` boundary) is pure bounded integer arithmetic — the class Kani verifies exhaustively
  (overflow/underflow freedom + boundary correctness), independent of the provisional numeric cap.
  This is the strongest available method and matches the architect's "what needs Kani" framing for
  the cap formula. (Kani CLI version alignment may defer execution to CI, per the VP-070 precedent.)
- **proptest (VP-119, VP-121, VP-123, VP-125).** The load-bearing safety invariants are universally
  quantified over arbitrary write / seal / prepend / monolithic-input sequences (no-over-cap,
  bounded active count, no-data-loss, content preservation, bounded live changelog). Generated
  sequences explore state spaces a fixed fixture cannot; VP-123 adds a golden-file round-trip against
  real oversized cycle-log samples.
- **integration (VP-118, VP-124, VP-128, VP-130).** Ordering/atomicity on a live filesystem
  (seal-then-block, crash-atomicity/idempotency), multi-file cross-reference integrity (second-level
  addressing vs ARCH-INDEX), and the two-PR sequencing gate are real-substrate/process properties —
  the dispatcher-harness + CI-gate class VP-093/VP-105/VP-072 already use.
- **unit-test (VP-117, VP-120, VP-122, VP-127).** Deterministic dispatch/selection/wording/glob
  properties with small enumerable fixture spaces (mock-FS zero-cost bypass, Cross-Validator MIN
  table, retry-wording table, zero-lookup read-counter, glob exclusion + fail-loud index).
- **static-check (VP-126, VP-129).** Source/config structural invariants best enforced by CI grep —
  "reuse `rotate_changelog`, don't reimplement" and the `hooks-registry.toml` Bash-arm-exclusion /
  closed-cohort config audit (the VP-061 / VP-046 / VP-099 enforcement class).
