## Part A — Findings

### F-P1-001 — BLOCKER — read_prefix max_bytes=8192 is premise-false; guard silently inert on production STATE.md

**Location:** `crates/hook-plugins/verify-factory-lock/src/lib.rs` — `host::read_prefix` call at source HEAD b7200d3d  
**Observation:** The Phase-B implementation called `host::read_prefix(".factory/STATE.md", 8192, READ_TIMEOUT_MS)`. BC-4.13.001 §Precondition 3 Phase-B derivation cited ADR-026 §Decision 7 as the basis for 8192 as a "frontmatter-only read" bound. ADR-026 §Decision 7 specifies line-count thresholds for STATE.md size governance (≤200 lines warn, ≤500 lines block) — it is not a byte-bound on frontmatter, and the 8192-byte figure does not appear in ADR-026 §Decision 7 or anywhere else in ADR-026. The actual production STATE.md (measured 2026-07-16): 178,742 bytes total; closing `---` frontmatter delimiter at byte offset 35,175; `last_amended:` field occupies bytes ~2,527..35,174 (32,648 bytes of the prefix). At max_bytes=8192, `host::read_prefix` returns a 8,192-byte prefix that contains only: `---`, `document_type:`, `level:`, `version:`, `status:`, `producer:`, `timestamp:`, and the first ~200 bytes of `last_amended:`. Neither the `factory_lock:` TOML block nor the closing `---` delimiter is present in this prefix. When `extract_frontmatter` receives this prefix, it finds no second `---` delimiter and falls back to full-input treatment → returns a `MalformedLockBlock` result → guard interprets MalformedLockBlock as unlocked (fail-open per PC7) → returns Continue without inspecting the lock. The guard is silently inert: it never reads a valid lock block, never detects a held lock, and always returns Continue regardless of lock state.  
**Correct bound:** 262144 bytes (the STATE.md byte envelope). BC-4.13.001 §Precondition 3 Phase-A established this envelope as the largest STATE.md the operator is permitted to use (BC-5.40.001 §Precondition 6 same bound). ADR-025 §Decision 14 (Phase-A read_file cap) was set at 262144 for the same structural reason. The Phase-B structural guarantee is: on-envelope STATE.md files always have their closing `---` within the first 262144 bytes of the file. Any STATE.md that fits within the Phase-A envelope has its frontmatter fully readable from a 262144-byte prefix.  
**Routing:** architect (ADR-025 §Decision 15 max_bytes adjudication + VP-095 title correction + proof_method update); PO (BC-4.13.001 Phase-B §Precondition 3 bound correction); SW (S-19.07 story bound sweep); implementer (code fix + WASM rebuild)  
**Status:** CLOSED — arch-s1907-bound 93596a03 (ADR-025 §Decision 15 v1.16→v1.17: max_bytes adjudicated 8192→262144; ADR-026 §Decision 7 premise-false derivation retracted; structural guarantee documented); arch-vp095 3f821d35 (VP-095 v1.2→v1.3: title updated to reflect structural guarantee via read_prefix(262144); proof_method integration→unit+static; POLICY 9: VA v1.10 + VCM v1.7); PO 92e4e325 (BC-4.13.001 v1.16→v1.17: Phase-B §Precondition 3 bound corrected 8192→262144); SW 101ebfb8 (S-19.07 v1.17→v1.18: bound sweep 8192→262144 in 12 AC/task/test-inventory sites); implementer df0e6c76 (lib.rs `read_prefix` max_bytes 8192→262144); WASM rebuild 81803dbb.

### F-P1-002 — HIGH — fixture coverage gap: no test exercises factory_lock block past the 8192-byte frontmatter boundary

**Location:** `plugins/vsdd-factory/tests/verify-factory-lock-read-prefix.bats` + `plugins/vsdd-factory/tests/verify-factory-lock/verify-factory-lock.bats` — all test fixtures at source HEAD b7200d3d  
**Observation:** Every bats fixture in the Phase-B test suite that exercises the WASM guard uses a minimal mock STATE.md where the `factory_lock:` block falls within the first ~200–500 bytes of frontmatter. T-005-ec005 creates a mock STATE.md inline: `---\ndocument_type: state\n...\nfactory_lock:\n  holder: "test"\n  ...`. The entire frontmatter fits in under 500 bytes — well under 8192. The verify-factory-lock.bats suite likewise uses fixtures constructed from small mock files. With max_bytes=8192, the guard reads the full mock frontmatter correctly in every test case, passes the fixture assertions, and appears behaviorally correct. No test constructs a mock STATE.md that replicates the production shape where `last_amended:` precedes `factory_lock:` and occupies >8192 bytes. The Phase-B test suite at b7200d3d was therefore structurally unable to detect that the guard was silently inert against the live production STATE.md. This is a HIGH-severity coverage gap: the production regression was masked by fixture shape, not by a logic error in the test assertions themselves.  
**Fix required:** Add a regression fixture that mimics the production STATE.md shape — a `last_amended:` field large enough to push the `factory_lock:` block past the 8192-byte mark — and verify that the guard correctly detects a held lock even with that large-frontmatter fixture. The bound fix (F-P1-001, df0e6c76 raising max_bytes to 262144) is a prerequisite: without the bound fix, even this new fixture would confirm the failure; with the bound fix, the fixture becomes the regression test that proves the bound is correctly set.  
**Routing:** implementer (regression fixture + verification that guard fires on lock-held large-STATE.md)  
**Status:** CLOSED — implementer 83b0f97c (real-shape 35KB-frontmatter regression fixture: `last_amended:` padded to 35,175 bytes mirroring measured production offset; `factory_lock:` block placed at byte offset beyond 8192; assertion confirms guard returns exit 2 (block) on held-lock large-STATE.md; passes at max_bytes=262144 confirming F-P1-001 fix is correct and load-bearing).
