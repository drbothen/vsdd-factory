## Part A — Findings

### F-P8-001 (MEDIUM — BLOCKING)

**AC-005 jq execution-position gap: `{ jq`, `) jq`, `( jq` forms not covered; AC-003 mutual-parity cross-cite introduced one-directional dependency.**

**Finding:** AC-005 is framed in v1.8 as detecting `jq` anywhere in the file (whole-file scan). The pass-7 acceptance of O-2 ("AC-005 jq preflight is whole-file — accepted-as-designed") was correct for the whole-file adequacy argument, but it left a structural gap: the bats positive controls for AC-005 did not cover execution positions that follow brace-group `{`, case-pattern `)`, or subshell `(` prefixes:

```bash
{ jq . "$file"; }        # brace-group execution — not tested
) jq . "$file";;         # case-pattern execution — not tested
( jq . "$file" )         # subshell execution — not tested
```

The whole-file scan catches `jq` in these positions, but the test suite had no positive controls confirming that these execution forms are caught. This means a future regression narrowing the jq detector to a line-start anchor would produce no new test failures — the gap is undetectable without the controls.

Additionally, AC-003 in v1.8 carried the rationale "parity with AC-005" as a justification for the IFS positional logic. This cross-cite introduced a one-directional dependency: AC-003's correctness was stated in terms of another AC's design, which is brittle — if AC-005's semantics change, AC-003's rationale becomes stale or misleading without any direct failing indicator.

**Fix required:**
1. test-writer: broaden jq_re bats positive-control set to include brace-group (`{ jq`), case-pattern (`) jq`), and subshell (`( jq`) execution positions. Confirm 68/68 bats GREEN. Zero real-script over-match.
2. story-writer: reframe AC-003 and AC-005 rationales as SELF-CONTAINED semantics — each AC justified by its own detection logic, not by cross-citation to a sibling AC. Remove the "parity with AC-005" clause from AC-003. Update story to v1.9.

**Note on subshell coverage:** jq covers subshell `(` whereas IFS does not (subshell IFS assignment does not leak to parent shell; hence IFS detection correctly scopes to non-subshell forms). This semantic difference is the reason the two ACs cannot share a single "parity" rationale — they have different soundness boundaries.

**Fix commits:** test-writer 70c9fdd1; story-writer 646bf898.

### O-1 (LOW)

**AC-002 `${var@U}`, `${var@L}`, `${var@u}` bash-4.4 transform operators not covered.**

**Finding:** AC-002 detects bash 4+ parameter expansion operators including `${var@Q}`, `${var@E}`, `${var@P}`, `${var@A}`. The `@U`, `@L`, and `@u` transform operators (uppercase/lowercase/first-uppercase) were introduced in bash 4.4 and are not covered by the regex or the bats positive controls. A contributor using `${var@U}` would evade the detector.

**Note on `${arr[@]}`:** The `@` in `${arr[@]}` (array expansion) does not trigger false-positive because the regex correctly requires the `@` to be followed by a transform letter (`[A-Z]` or specific letters), not `]`.

**Fix:** Extend the terminal alternation to `@[ULu]`; add positive controls for each form. Guard: confirm `${arr[@]}` and `${BASH_SOURCE[0]}` remain clean (no over-match).

**Fix commits:** test-writer 70c9fdd1; technical-writer 57b09645.

### O-2 (LOW)

**AC-004 phase-2 acceptance test hardcoded double-quoted `"import yaml"` form only.**

**Finding:** AC-004 detects Python-runtime dependency usage (`import yaml`, `import toml`, etc.) in skill scripts. The bats positive control for AC-004 used:

```bash
echo "import yaml" | ...
```

with a hardcoded double-quote delimiter. If a script uses single-quoted `'import yaml'` in a heredoc or string literal, the test infrastructure would still catch it (the grep searches raw file content, not the shell-quoting context), but the positive control itself does not verify single-quoted forms, leaving a documentation gap about what forms are accepted.

**Fix:** Accept both single and double quotes in the positive-control fixture: `["']import yaml["']`. Confirm the test still runs GREEN.

**Fix commits:** test-writer 70c9fdd1.
