# S-25.02 F2 PRD Delta: Artifact Sharding Layer 2 — BC Authorship

## 0. Summary

This burst authors 7 new Behavioral Contracts (BC-1.18.005 through BC-1.18.010 under SS-01, and
BC-7.08.001 under SS-07) implementing the architect's ADR-051 two-mechanism Layer-2 shard-rotation
design, registers a new capability (CAP-043) in `capabilities.md`, and inserts the corresponding
rows into `BC-INDEX.md` (v5.50 / 1,997 BCs → v5.51 / 2,004 BCs). No VPs are authored (formal-verifier
follows). The S-25.02 story body is NOT rewritten (story-writer's domain at F3) — this doc records
the BC-authorship burst and the inputs story-writer needs at F3.

### BC ID allocation and collision check

The architect's F1/F2 enumeration carried BC-1.18.005–007 forward as provisional IDs and flagged
BC-7.NN.001 for confirmation against BC-INDEX at F2 close. Confirmed at authoring time:

- **BC-1.18.005–010**: no collision. The `ss-01/` directory and `BC-INDEX.md` both showed
  `BC-1.18.004` as the last-registered member of the BC-1.18 family; BC-1.18.005–010 are the next
  six free sequential slots. (BC-1.18.008/009/010 were NOT in the original F1 enumeration — F1 only
  proposed 4 BCs for SS-01 — but their numbers were still the next free slots after the F2
  architecture-elaboration burst identified the three additional required BCs.)
- **BC-7.08.001**: the F1/F2 docs left the `SS` slot as "BC-7.NN.001, architect to confirm." Direct
  inspection of the live `ss-07/` directory listing (`BC-7.01.001` through `BC-7.07.002`, confirmed
  via `ls` at authoring time) and a `BC-INDEX.md` grep for `BC-7.08`/`BC-7.09` (zero hits) show
  `BC-7.08` is the next free family slot. Allocated as **BC-7.08.001** — no collision, no
  reconciliation needed against the architect's provisional numbering (the architect explicitly
  deferred the exact number to product-owner/BC-authorship time).

## 2. New Capability

**CAP-043 — Artifact Sharding Layer 2: Size-Triggered Shard Rotation for Cycle Append-Logs and
BC-INDEX Structured-Catalog Sharding**, registered in `.factory/specs/domain-spec/capabilities.md`
(v1.16 → v1.17, CAP count 42 → 43). Justification: no existing capability covers artifact-size-
triggered shard rotation. Distinguished from CAP-041 (INDETERMINATE outcome DETECTION-and-
quarantine, which this capability's root-cause PREVENTION extends — CAP-041 explicitly anticipates
this as its own "Ratified Future Phase Layer 2" per ADR-047 §Decision 8b) and CAP-042 (one specific
`last_amended`-field write-path fix, whose `rotate_changelog` primitive CAP-043 reuses as a
component). BC-7.08.001 (the Cohort B flip) is anchored to CAP-041, not CAP-043, because the
registry `failure_policy` assignment itself is squarely CAP-041's domain (extending the existing
Cohort mechanism to a second human-confirmed set) — CAP-043's shard-bounding postconditions are a
cited dependency/precondition for BC-7.08.001, not its own capability anchor.

## 4. New Error-Taxonomy Variants

The project's existing `E-xxx-NNN` convention (`E-REG`, `E-PAY`, `E-CAP`, `E-PLG`, `E-SNK`, `E-ACT`,
`E-HK`, per `prd.md` §5.1) is extended with a new category for shard-management failures. Per
CLAUDE.md's production-grade default, this is defined in-scope now rather than deferred:

| Prefix | Category | Severity | Exit code / HookResult | Examples |
|---|---|---|---|---|
| `E-SHD-NNN` | Shard management errors | broken → fail-loud | `HookResult::Error` (native gate, no dispatcher exit-code semantics apply — this is a PreToolUse hook outcome, not a process exit code) | `E-SHD-001`: seal-rename failure (disk full / permission error) mid-roll (BC-1.18.006 EC-003); `E-SHD-002`: shard-index file missing or corrupt at dispatch time (BC-1.18.007 EC-005, story's own EC-005); `E-SHD-003`: backfill-split content-preservation verification failure (BC-1.18.008 EC-004, Postcondition 6); `E-SHD-004`: `rotate_changelog` invocation failure during B1 rotation (BC-1.18.009 EC-003) |

**Note for whichever agent next authors `.factory/specs/prd-supplements/error-taxonomy.md`:** that
supplement file does not yet exist on disk despite `prd.md` §5.1 referencing it (a pre-existing
dangling reference, not introduced by this burst — flagged for spec-steward/state-manager routing,
not fixed here as it is out of S-25.02's scope). When it is materialized, the `E-SHD-NNN` row above
should be added to it alongside the existing seven categories.
