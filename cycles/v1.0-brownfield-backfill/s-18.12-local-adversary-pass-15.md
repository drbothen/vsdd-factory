### O-1 (LOW — non-blocking, POLICY 11 sibling-sweep, authorial-intent)

**AC-002 case-modifier test only checks global guard `has_guard`; it does NOT replicate AC-001's positional guard-precedence assertion (`_ep_guard_precedes_source`).**

**Finding:** The `test_portability_case_modifier` oracle (AC-002) verifies that a case-modifier usage in a scan-set file is caught ONLY if the `has_guard` flag is false at scan time. AC-001's oracle adds a stronger positional check (`_ep_guard_precedes_source`) which verifies that the guard precedes the first source line. AC-002 does not replicate this positional check. A future case-modifier in a new entrypoint that has a guard placed AFTER the source lines would be caught by AC-001 (guard fails positional check → scan → detected) but not by AC-002 (guard present anywhere → `has_guard=true` → AC-002 check skipped → miss). No such script exists today; whether AC-002 should carry the same positional guard check is authorial intent.

**Disposition:** ACCEPTED-AS-DOCUMENTED-PROSPECTIVE-SCOPE-BOUNDARY (D-739). No current entrypoint has a guard placed after its source lines. Hardening now would change the frozen artifact. The asymmetry is acknowledged as a prospective design question, not a current defect. FREEZE DISCIPLINE.

---

### O-2 (LOW — non-blocking, POLICY 11)

**Guard-presence is evaluated scan-set-GLOBALLY — a guard in one entrypoint file can satisfy the gate for a different file in the scan set.**

**Finding:** The AC-001 and AC-002 oracles detect guard presence across the entire scan set collectively (`has_guard` is set from any scan-set member). A guard in `wave-handoff.sh` satisfies the gate for a hypothetical future STANDALONE script that uses `declare -A` or `${var^^}` directly without sourcing `wave-handoff.sh` and without its own guard. Such a standalone script would false-GREEN: `has_guard=true` from the entrypoint satisfies the global guard-presence requirement, so the array-declaration or case-modifier detector is not invoked. EC-006 soundness-boundary reasoning about lib-sourcing entrypoints did not explicitly enumerate standalone feature-user scripts with direct use and no own guard. No such standalone script exists today.

**Disposition:** ACCEPTED-AS-DOCUMENTED-PROSPECTIVE-SCOPE-BOUNDARY (D-739). No standalone direct-use scripts exist in the current scan set. Hardening requires regex or gate-structure change to the frozen artifact. FREEZE DISCIPLINE.

### O-3 (LOW — non-blocking, POLICY 13)

**python_re/jq_re wrapper group `(xargs|if|then|do|else|elif|time|env|command|sudo)` under-matches other command wrappers: `exec`, `nohup`, `nice`, `timeout`, `stdbuf`.**

**Finding:** The wrapper-group alternation arm in python_re and jq_re covers 9 wrapper tokens but omits `exec`, `nohup`, `nice`, `timeout`, `stdbuf` (e.g., `exec python3 x.py`, `timeout 5 jq …`). Scripts are mandated python/jq-free by SKILL.md §149. Direct invocation forms are caught by the base arms of the respective regex. The wrapper-group arm extends detection to indirect invocations via known wrappers; the omitted forms are additional indirect invocation paths not in the enumerated set. No current scan-set script uses any of these forms.

**Disposition:** ACCEPTED-AS-DOCUMENTED-PROSPECTIVE-SCOPE-BOUNDARY (D-739). All current scripts are python/jq-free per SKILL.md §149. Direct invocation forms (`python3 x.py`, `jq .`) ARE caught by the base arms; the gap exists only in the wrapper-group arm enumeration. Hardening now would change the frozen regex without closing any real current gap. Below the Drift Item threshold: direct forms covered; all current scripts compliant. FREEZE DISCIPLINE.

### O-4 (LOW — non-blocking, POLICY 13)

**case_mod_re terminal alternation `@[ULu]` covers only bash-4.4 case-transform trio; bash-5.0+ `@Q`/`@E`/`@P`/`@A`/`@a`/`@k`/`@K` not detected.**

**Finding:** AC-002 `case_mod_re` enumerates bash-4.4 `@`-transforms (`@U`, `@L`, `@u`) and the array spread operators. Bash 5.0 introduced additional `@`-transforms (`@Q` quoted, `@E` escaped, `@P` prompt-expanded, `@A` assignment-form, `@a` attributes) and bash 5.1 added `@k`/`@K`. None of these forms appear in any current scan-target script. The AC-002 scope explicitly enumerates only the bash-4.4 case-transform trio (`@U`, `@L`, `@u`) as the portability concern boundary.

**Disposition:** ACCEPTED-AS-DOCUMENTED-PROSPECTIVE-SCOPE-BOUNDARY (D-739). The enumeration is intentionally bounded to the bash-4.4 case-transform trio per AC-002 scope. No current script uses bash-5.0+ `@`-operator forms. FREEZE DISCIPLINE.

**Disposition:** ACCEPTED-AS-DOCUMENTED-PROSPECTIVE-SCOPE-BOUNDARY (D-739). The arm is exercised via sibling controls. This is a control-labeling completeness note, not a tautology defect. Below the Drift Item threshold: the arm functions correctly and is verified through sibling coverage. FREEZE DISCIPLINE.
