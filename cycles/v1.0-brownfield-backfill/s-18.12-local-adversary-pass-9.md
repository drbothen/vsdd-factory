### O-1 (LOW — non-blocking, prospective)

**AC-002 `@`-operators limited to `@[ULuQEPAKka]`; additional bash-5.2+ operators `@x` (hex-dump) and other forward forms not detected.**

**Finding:** AC-002 covers the `${var@operator}` parameter transform family. The current enumeration includes `@Q`, `@E`, `@P`, `@A`, `@K`, `@k`, `@a`, `@U`, `@L`, `@u` (bash 4.4+; extended by pass-8 hardening to include `@U`, `@L`, `@u`). Future bash releases may introduce additional transform operators (e.g., `@x` hex-dump was discussed in the bash-devel list for bash 5.3). No current scan-target script in `plugins/vsdd-factory/skills/wave-handoff/*.sh` or the E-18 corpus uses any such hypothetical form.

**Disposition:** ACCEPTED-AS-DOCUMENTED-PROSPECTIVE-SCOPE-BOUNDARY (D-733). The AC form-set is intentionally bounded to known bash-4.4+ forms (`@[ULuQEPAKka]`). No current script uses undocumented future operators. This is a forward-looking observation about potential future bash evolution, not a defect in the current artifact. Hardening now would change the artifact and offer no protection against any real current script.

---

### O-2 (LOW — non-blocking, prospective)

**AC-001 array-detector step-1 pattern matches only `(local|declare)` forms; bash-4 synonym `typeset -A` not detected.**

**Finding:** AC-001 detects `declare -A` and `local -A` as bash 4+ associative array declarations. The `typeset -A` synonym (legacy ksh/bash form) is not covered by the step-1 detection regex. No current scan-target script uses `typeset -A` — all array declarations in `plugins/vsdd-factory/skills/wave-handoff/*.sh` use either `declare` or `local`.

**Disposition:** ACCEPTED-AS-DOCUMENTED-PROSPECTIVE-SCOPE-BOUNDARY (D-733). `typeset` is a deprecated synonym; modern bash scripts use `declare`. No current script triggers this gap. The bounded form-set is intentional. Hardening now would change the artifact without closing any real gap in the current codebase.

---

### O-3 (LOW — non-blocking, prospective)

**AC-004 phase-1 `import[[:space:]]+yaml` detection is unanchored; a prose comment `# import yaml` within a skill script would phase-1 match then phase-2 FAIL on dependency check.**

**Finding:** The phase-1 detection pattern for AC-004 (`import[[:space:]]+yaml` or equivalent) does not exclude commented lines (lines beginning with `#`). A future skill script that includes a doc-comment such as:

```bash
# This script does NOT import yaml; it avoids PyYAML entirely
```

would match phase-1 and then fail phase-2 (no corresponding shebang `#!/usr/bin/env python` preceding it), generating a false positive. No current script in the scan corpus contains such a comment.

**Disposition:** ACCEPTED-AS-DOCUMENTED-PROSPECTIVE-SCOPE-BOUNDARY (D-733). No such comment exists in any current `.sh` file. The phase-2 filter is a guard against false positives from commented-out import lines. The specific unanchored-comment scenario is a prospective edge case with no current manifestation. Hardening now would change the artifact and risk introducing regressions in the phase-2 logic.

---

### O-4 (LOW — non-blocking, documentation gap)

**Story S-18.12 pins the AC-004 phase-2 acceptance regex verbatim but not the phase-1 detection regex; phase-1 regex forms are enumerated in prose only.**

**Finding:** The AC-004 acceptance criteria in `S-18.12-portability-lint-guard-extension.md` specifies the phase-2 acceptance test (regex match against the phase-2 output confirming a Python shebang or `python[0-9.]*` invocation) but delegates phase-1 detection to prose enumeration rather than a pinned regex literal. This means a future maintainer could change the phase-1 detection pattern without a story-level spec update flagging the delta.

**Disposition:** ACCEPTED-AS-DOCUMENTED (D-733). The AC form accurately captures the testable behavior at the phase-2 boundary (which is the verifiable acceptance criterion). Phase-1 enumeration in prose is the pattern established for all five ACs in this story — it is the consistent authoring convention. This is a documentation style observation, not a functional defect. The spec is self-consistent within its established pattern.

### O-5 (LOW — non-blocking, [process-gap])

**`run-all.sh` discovers bats test files by glob with no assertion that the 5 S-18.12 portability tests specifically ran; a regression removing the S-18.12 test file would not fail the suite.**

**Disposition:** OUT OF SCOPE for S-18.12 (adversary explicitly scopes this to test-harness infrastructure, not an S-18.12 artifact defect).
