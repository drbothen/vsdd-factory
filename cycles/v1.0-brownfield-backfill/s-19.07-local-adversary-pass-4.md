### F-P4-002 — MEDIUM — spec-command portability: AC-001 Gate B canonical command uses BSD-broken semicolon-label sed form

**Location:** `S-19.07-verify-factory-lock-read-prefix-migration.md` v1.20 — §AC-001 Gate B canonical command block  
**Observation:** The Gate B canonical command in AC-001 uses the form `sed -n ':a; s:/\*[^*]*\*+([^/*][^*]*\*+)*/::; ta'` where `:a` is the sed label and the entire expression is a single `-n 'script'` argument. On macOS BSD sed (the runtime environment for darwin CI runners and the darwin-confirmed test environment), this form is broken: the `:a` at the start of the single-string argument is parsed as a literal pattern match rather than as a label definition, causing the block-comment strip loop to silently fail and pass the entire lib.rs source text — including block-comment occurrences of `host::read_file`, `STATE_MD_MAX_BYTES`, and `TooLarge` — through to the downstream `grep -qE "host::read_file|STATE_MD_MAX_BYTES|TooLarge"`. This produces false-negative exits (gate exits non-zero/passes when it should fail) for any lib.rs source that retains these symbols only in block comments. The portable fix — using separate `-e ':a;'` `-e 's:...::'` `-e 'ta'` expressions, or equivalently `-e ':a; s:...:; ta'` — is already confirmed working on darwin: both the evidence bullet inline in AC-001 Gate B and the bats test T-001b use the `-e` multi-expression form. The canonical command and any other verbatim occurrence of the single-string `:a; s:...` pattern in the story must be corrected to match the portable form already proven in the evidence bullet and bats.  
**Routing:** story-writer (correct AC-001 Gate B canonical command to portable `-e` form matching evidence bullet + bats T-001b; sweep entire story for any other verbatim semicolon-label single-string sed occurrences; confirm gate exits correctly on darwin).  
**Status:** ROUTED — story-writer in flight; expected closure S-19.07 v1.21 (lands with pass-5 burst)
