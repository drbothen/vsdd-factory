**Observation:** The S-19.09 story (AC-006, AC-007, Test Plan §T-009/T-010, File Structure section) specifies that `T-009` and `T-010` are cargo unit tests placed in `internal_log.rs` `#[cfg(test)]`, each using `assert_eq!` to pin the string values of `PLUGIN_COMPLETED` and `PLUGIN_TIMEOUT`. The tests exist only as `grep` invocations in the bats suite (`host-abi-hygiene.bats`), which assert that the const names appear in the source file — they do not pin the runtime value of the const. The bats approach covers the behavioral intent (the constants exist and have the correct string values as confirmed by D21 grep-gate), but does not satisfy the spec-mandated artifact form. Under `tdd_mode:strict` the SPEC-wins rule requires the specified test artifact structure to exist; the implementer cannot substitute a different mechanism without a spec amendment.
**Severity rationale:** LOW because: (1) correctness is not at risk — the const values are exercised by the full executor path and by bats event-value assertions; (2) the gap is artifact-form only, not behavioral; (3) the bats grep-gates provide mutation-liveness coverage of the const names. However, spec-conformance is not optional under `tdd_mode:strict`.
**Fix required:** Add both `T-009` and `T-010` as `assert_eq!` value-pin tests in `internal_log.rs` `#[cfg(test)]`. Story v1.1 scope includes symmetry adjudication for whether `PLUGIN_COMPLETED`/`PLUGIN_TIMEOUT` both require value-pin or only one (adversary defers to test-writer dispatch per story v1.1).
