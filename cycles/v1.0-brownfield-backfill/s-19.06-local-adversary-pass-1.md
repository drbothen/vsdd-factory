## Part A — Findings

### F-P1-001 — MEDIUM — [story-gate defect] AC-003 static gate fails against correct code

**Location:** Story v1.19 §AC-003 Gate — `read_prefix.rs` static assertion  
**Observation:** The AC-003 static gate was intended to verify that OUTPUT_TOO_LARGE (-3) never appears in production return paths. As written, the gate matched the `"output too large"` message string and the `-3` literal inside T-004's `#[cfg(test)]` module, specifically inside the `assert_ne!(result, -3)` assertion and its inline documentation comment. These are test-module strings, not production occurrences. A gate that fires on test assertions rather than production code is structurally inverted: it would silently "pass" (the gate was never executed — not wired into any suite) on broken code that removed the assertion, and would report false violations on correct code that keeps it. Additionally, the gate used the `:a;ta` label form (GNU sed extension), incompatible with BSD sed on macOS CI runners.  
**Production code status:** OUTPUT_TOO_LARGE (-3) is confirmed structurally unreachable in the production implementation. `file.take(max_bytes)` caps the read at exactly `max_bytes` bytes; the returned buffer length is always ≤ max_bytes, so the `if buf.len() > max_bytes` guard (which would trigger -3) can never be true. The production code is clean; the gate was the defect.  
**Fix required:** Rewrite gate to a POSIX awk pipeline scoped to production code only (exclude `#[cfg(test)]` block); add explicit execution site in the bats suite with embedded mutation-liveness fixture.  
**Routing:** story-writer (gate form amendment) + test-writer (execution site T-009g)  
**Status:** CLOSED — story-writer bd52d357 (story v1.19→v1.20: production-scoped POSIX awk pipeline + execution site declared) + test-writer 29df1cba (T-009g executes the gate; mutation-liveness fixture confirms gate fires on injected OUTPUT_TOO_LARGE production path)

### F-P1-002 — HIGH — [POLICY 20 single-point defense] release.yml/ci.yml exclusion chain has no presence guard

**Location:** `.github/workflows/release.yml` `--exclude read-prefix-fixture` line; `.github/workflows/ci.yml` wasm build steps and staging loops  
**Observation:** Three independent gaps in the POLICY 20 single-point defense requirement:  
1. **No presence gate on release exclusion:** The release.yml `--exclude read-prefix-fixture` line (added at 04509235) had no test or gate verifying it existed in the actual workflow file. T-011 tested a reimplementation of the exclusion logic in Rust — passing even if the exclusion line was deleted from release.yml — providing false confidence.  
2. **ci.yml builds fixture without exclusion:** Three workspace wasm build steps in ci.yml compiled `read-prefix-fixture` without an exclusion clause. Staging logic in those steps would copy the fixture artifact. The artifact was gitignored but could still be present in the build environment; a future environment change could cause it to appear in a production bundle with no existing gate blocking it.  
3. **One-directional declared-⊆-staged check:** The existing bundle integrity assertion verified that declared artifacts were staged, but not the reverse. A staged wasm file not in the declared list (such as a fixture that slipped through) had no detection gate.  
**Why HIGH:** POLICY 20 is a single-point defense: the exclusion is the sole mechanism preventing fixture contamination of the release bundle. A guard with no redundant verification path and missing sibling sites is a HIGH finding under POLICY 20's defense-in-depth requirement.  
**TD-VSDD-060 sweep result:** The devops leg found a 4th and 5th staging loop (total 5: 3 ci.yml + 2 release.yml) beyond the adversary's initial count of 3 staging loops, confirming the sibling-site sweep was load-bearing.  
**Fix required:** (a) Add `--exclude read-prefix-fixture` (or equivalent build-step exclusion) to all 3 ci.yml workspace wasm builds; (b) Add named stale-cache case-skips in all 5 staging loops (3 ci.yml + 2 release.yml); (c) Add T-009h: exact-count presence-gate asserting all exclusion anchors exist (1 release build exclusion + 3 ci build exclusions + 3+2 staging skips), fires on removal AND un-swept additions; embedded mutation-liveness.
