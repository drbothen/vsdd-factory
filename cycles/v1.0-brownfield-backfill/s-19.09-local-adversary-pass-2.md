## Part A — Findings

### F-P2-001 — MEDIUM — [harness-liveness] T-002 bytes_correct asserts ret==0 and out_ptr>0 only — never loads out_len nor compares bytes to fixture

**Location:** `crates/factory-dispatcher/src/invoke.rs` — T-002 (`bytes_correct` test function)
**Observation:** T-002 is the sole in-story test covering D19 production marshalling for `read_prefix`. The test asserts `ret == 0` (host function returned success) and `out_ptr > 0` (pointer is non-null). However, it never extracts `out_len` from `memory[4:8]` (the second return slot) and never compares `memory[out_ptr..out_ptr+out_len]` to the fixture content. AC-002 mandates a byte assertion for the `read_prefix` production path; AC-002 text specifies "byte-for-byte parity with the fixture content." The current test would pass even if the marshalling wrote garbage bytes at `out_ptr` — the only observable check is that the pointer is non-zero. No in-tree consumer of this path exists until S-19.07, making T-002 the sole coverage of D19 production marshalling correctness.
**Severity rationale:** MEDIUM (not HIGH) because the production registration itself is verified by T-001 (setup_host_on_store_data path instantiation) and the underlying `write_wasm_bytes` function is unit-tested separately. The gap is in end-to-end byte-parity coverage of the marshalling round-trip, which is the critical assertion for AC-002.
**Fix required:** Extend T-002 to: (1) extract `out_len` from `memory[4:8]`; (2) assert `memory[out_ptr..out_ptr+out_len]` equals fixture bytes; (3) mutation-check: verify test fails when fixture content is altered; (4) optionally add `head_c` bound variant verifying truncated-read semantics.
**Routing:** test-writer (T-002 byte-assertion + mutation-check + optional head_c variant)
**Status:** OPEN — test-writer dispatched (in flight)

### F-P2-002 — LOW — [temp-path flake risk] T-002 uses fixed hardcoded temp-file path; sibling tests use tempdir isolation

**Location:** `crates/factory-dispatcher/src/invoke.rs` — T-002 temp-file construction
**Observation:** T-002 constructs a temporary file at a fixed hardcoded path (e.g., `/tmp/test_read_prefix_file` or equivalent). Under parallel test execution (`cargo test --jobs N`), multiple test processes writing the same fixed path will collide, producing flaky test failures that are environment-dependent and hard to diagnose. Sibling tests T-001 and T-003 use `tempdir`-based isolation (tempfile crate or std `tempdir` equivalent), which is the established pattern in this test file.
**Severity rationale:** LOW because: (1) current CI runs single-threaded by default for this suite; (2) the test fails safely (collision → panic → test failure rather than silent pass with wrong data); (3) no production code is affected.
**Fix required:** Migrate T-002 temp-file construction to use `tempdir` (consistent with T-001/T-003 pattern). Sweep T-001 and T-003 for consistent pattern application.
**Routing:** test-writer (same dispatch as F-P2-001)
**Status:** OPEN — test-writer dispatched (in flight); same dispatch as F-P2-001
