**Location:** S-19.06 story v1.20 §Architecture Mapping
**Observation:** The §Architecture Mapping listed the existence-check (path allowed + resolve_path) as the first step in the execution path, before the max_bytes=0 short-circuit. The actual implementation in `read_prefix.rs` short-circuits first: `if max_bytes == 0 { return Ok(Vec::new()); }` executes before any path resolution. BC-1.17.001 EC-001 states "The file is not read" for the max_bytes=0 case — the BC supports the short-circuit-first ordering of the implementation. The story §Architecture Mapping was the misaligned artifact.
**Impact:** Low — no production behavior defect. The implementation is correct and BC-aligned. A future implementer reading only the story, however, could write steps in the mapped order and incur an unnecessary path-check before the short-circuit, introducing a regression in EC-001 behavior. Additionally, the EC-001 entry did not pin the composite case (max_bytes=0 + file absent → empty return, no path check), leaving the boundary underspecified.
**Fix required:** (a) Reorder §Architecture Mapping so max_bytes=0 short-circuit appears before existence-check. (b) Pin EC-001 as a composite case: max_bytes=0 → return `Ok(Vec::new())` immediately; no file read and no path check. (c) Add T-012 regression guard exercising max_bytes=0 with an absent-file fixture path, confirming NOT_FOUND is not returned (short-circuit precedes path check).
