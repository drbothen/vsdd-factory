## Part A — Findings

### F-P6-001 — LOW — [EC-002 coverage gap] D19 empty-body branch (`ptr=0/len=0/OK/no-grow`) has zero test coverage at production and prepare() level

**Location:** `crates/factory-dispatcher/src/invoke.rs` — D19 `prepare()` empty-body branch; S-19.09 story v1.3 AC-002
**Observation:** The D19 production-path registration in `invoke.rs` implements a `prepare()` call whose empty-body branch (when the dispatch package body pointer is null / length is zero) returns OK and skips the grow-and-copy path. This edge case (`ptr=0 / len=0 / OK / no-grow`) is explicitly enumerated in the D19 narrative and is a distinct code path from the non-empty path tested by AC-002. Neither the `invoke.rs` production-level test suite nor any `prepare()`-level unit test exercises this branch. AC-002 binds only the non-empty precondition (`body_len > 0` on the happy path); the empty-body variant is structurally unbound.
**Severity rationale:** LOW because: (1) the three code lines in the empty branch are trivially mirrored logic (null-check + len-check + early-return); (2) the SDK guard for the empty case is exercised transitively by existing happy-path tests that construct non-empty payloads; (3) there is no behavioral contract that independently mandates the empty-body OK semantics — it is an internal implementation invariant, not a user-observable BC. However, under the production-grade default, enumerated edge cases in a TDD story require explicit coverage; a mutant that changes the empty-body return to an error would not be killed by the current test suite.
**Fix required:** Test-writer adds T-015 exercising the empty-body branch of `prepare()`: assert OK return, assert no grow occurs (buffer length invariant holds pre/post), and provide mutation evidence that the no-grow assertion would kill a mutant returning `Err`. No story version change required (test-only remediation; no story artifact edit triggered by this finding).
