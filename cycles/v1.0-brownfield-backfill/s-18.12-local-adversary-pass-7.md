## Observations (Non-Blocking LOW)

### O-1 (LOW — HARDENED same-burst)

**AC-003 IFS step-1 anchor omitted brace-group `{ IFS=…; }` and case-pattern `) IFS=…` current-shell global-mutation forms.** The step-1 regex:

```
(^|;|&&|&|[|][|]|(then|do|else|elif)[[:space:]]|\{[[:space:]]+|[)][[:space:]]+)[[:space:]]*(export[[:space:]]+|readonly[[:space:]]+|declare[[:space:]]+-g[[:space:]]+)?IFS=
```

was missing two anchors for legitimate IFS mutation patterns:
- Brace-group form: `{ IFS=…; }` — the `\{[[:space:]]+` alternation was absent
- Case-pattern form: `) IFS=…` — the `[)][[:space:]]+` alternation was absent

While no real production script in the scan set currently uses these forms, their absence created a prospective false-negative gap: a future contributor adding `{ IFS=$'\n'; }` idiom (common in portable shell scripts) would evade the detector.

**Hardened same-burst (D-731):**
- test-writer (commit 7a2b3ccf): extended the step-1 anchor to include `\{[[:space:]]+` and `[)][[:space:]]+` alternations; added positive controls (brace-group `{ IFS=... }` and case-pattern `) IFS=...` MUST flag); added negative controls (`foo() {` function-definition brace and `$(cmd)` subshell close-paren MUST NOT flag); real-script scan net violations = 0 (zero over-match confirmed).
- technical-writer (commit 5d5c3ad6): propagated byte-identical updated regex to bash-portability.md §3 documentation.
- story-writer (commit 642bbb8b): propagated byte-identical updated regex to story AC-003 enumeration; version bumped v1.7→v1.8.

Final step-1 regex (byte-identical across test/doc/story):

```
(^|;|&&|&|[|][|]|(then|do|else|elif)[[:space:]]|\{[[:space:]]+|[)][[:space:]]+)[[:space:]]*(export[[:space:]]+|readonly[[:space:]]+|declare[[:space:]]+-g[[:space:]]+)?IFS=
```

Byte-parity verified by orchestrator across test/doc/story. Real-script scan violations = 0.

### O-2 (LOW — ACCEPTED-AS-DESIGNED)

**AC-005 jq preflight is whole-file, not positional (asymmetric with AC-001).** AC-001 detects associative-array usage positionally (scans for `-A` flag in `declare` context), while AC-005 scans for bare `jq` anywhere in the file. This asymmetry means a commented-out `jq` invocation inside a `# NOT USED` section would still trigger the detector.

**Accepted-as-designed:** jq is prohibited by wave-handoff SKILL.md (scripts MUST NOT shell out to jq); any `jq` presence — even commented — in a wave-handoff skill script is a code-review concern. Whole-file detection is adequate defense-in-depth for a wholesale-prohibited dependency. The asymmetry with AC-001 is intentional: jq is categorically forbidden, not conditionally conditional like bash 4+ features. Positional refinement is intentionally out of scope.

**Documented in bash-portability.md:** AC-005 soundness-boundary note added (technical-writer 5d5c3ad6). No story or test change needed.
