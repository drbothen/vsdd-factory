## Failure Mode Verification

The 3 unit tests fail via `Err("Phase-B required")` return from the test mock — the Phase-A implementation calls `host::read_file`, not `host::read_prefix`. The mock is wired to the `read_prefix` call site and returns an error when the Phase-A code path is active, causing `HookResult::Continue` where the tests assert `HookResult::Block` (T-003, EC-001) or correct Continue-without-soft-warning (T-004). This is the correct Red Gate mechanism: the failures are behavioral, not panic-at-`todo!()`, reflecting the Phase-A-vs-Phase-B behavioral divergence.

The 4 bats tests fail via static-grep and registry-entry assertions directly against the current Phase-A source:
- T-001a: grep exits 1 (no `read_prefix` in lib.rs)
- T-001b: grep exits 0 (Phase-A symbols present in non-comment code; gate requires non-zero)
- T-002-vfl / T-002-vfl-bash: awk per-entry gate finds `capabilities.read_file` with count=1, `capabilities.read_prefix` with count=0

T-001b's mutation-liveness block-comment fixture PASSES at Red Gate, confirming the F-P9-003 sed block-comment strip is load-bearing: old gate (line-comment only) would exit 0 on a block-comment-wrapped fixture (symbols wrongly counted as code), new gate correctly exits 1 (block-comment stripped, symbols absent from non-comment scope). Gate scoping is production-code-only via `awk` at `#[cfg(test)]` boundary — documented rationale: test mocks legitimately name Phase-A symbols (`read_file` callback struct field) and must not trigger Gate B.

T-005-ec005 SKIP is documented as RED per bats convention (skip≠pass); requires dispatcher binary and WASM artifact that are not present at Red Gate time.

No `#[should_panic]` masking. No vacuously-passing new tests.
