| F-P14-001 | HIGH (blocking) | **POLICY 11/13: guard_re presence-oracle applied WITHOUT stripping comment lines.** The `test_portability_guard_present` test in `wave-handoff.bats` contains a guard-presence oracle that greps the content of each scan-target script for `$guard_re` WITHOUT first stripping comment lines. A Bash script containing only a commented-out guard `# [[ ${BASH_VERSINFO[0]} -ge 4 ]]` would match the guard_re pattern on the comment line, causing the oracle to falsely report the guard as present — even though no executable guard exists. The `grep -vE '^[[:space:]]*#'` comment-stripping pre-filter is absent from both the AC-001 guard oracle and the AC-002 guard oracle (both check for guard presence). No negative controls (`pc_commented_guard`, `pc_commented_guard_ac002`) exist to verify that commented-out guards are correctly rejected. Blast radius: AC-001 guard oracle AND AC-002 guard oracle both affected. This is the testable escalation of D-734 O-4 "paper-guard" observation: O-4 was accepted as a prospective soundness boundary, but the negative control test that would ENFORCE the boundary was missing. With the negative control, the gap is a definite defect, not a prospective concern. Root cause class: TD-VSDD-059 paper-fix detection — a guard that is only commented out (not deleted) would pass this oracle, defeating the paper-fix detection requirement. | **REMEDIATED** — test-writer 00272990: `grep -vE '^[[:space:]]*#'` comment-strip pre-filter applied to executable content extraction before `guard_re` match in BOTH AC-001 and AC-002 oracles; `pc_commented_guard` negative control added (asserting AC-001 oracle FAILS on content with only `# [[ ${BASH_VERSINFO[0]} -ge 4 ]]`); `pc_commented_guard_ac002` negative control added (asserting AC-002 oracle FAILS on content with only commented guard). 68/68 bats GREEN confirmed at 00272990. |
| F-P14-002 | MEDIUM (blocking) | **POLICY 4: bash-portability.md §1 and §2 mis-described guard-check mechanism as "token-presence."** Section §1 of `bash-portability.md` stated the guard check "checks that a `BASH_VERSINFO`-based guard exists (token-presence)" and §2 carried the same description. The actual mechanism after pass-13 and prior hardening is executable-position detection with comment-stripping: the oracle uses `grep -vE '^[[:space:]]*#'` to exclude comment lines before the guard_re match. The description "token-presence" is inaccurate because (1) it implies a simple grep of the full file content including comments, and (2) it does not convey that the detection is positional (guard must appear on an executable line). Users reading §1/§2 would believe the detection is a naive token search, not understanding the comment-stripping semantics or that commenting out the guard defeats a non-stripping oracle. The doc error was introduced when the mechanism was first described and was not updated as the oracle was refined. | **REMEDIATED** — test-writer 00272990: §1 and §2 in `bash-portability.md` updated to describe "executable-position detection with comment-stripping via `grep -vE '^[[:space:]]*#'`" — accurately reflecting the guard_re oracle's actual behavior after F-P14-001 remediation. |
| O-1 | LOW (non-blocking, prospective) | AC-002 `case_mod_re` pattern covers `@[ULu]` bash-4.4 case-transform operators (`${var@U}`, `${var@L}`, `${var@u}`). Bash 5.0 added `@Q` (quoted), `@E` (escaped), `@P` (prompt), `@A` (assignment) operators. None of these forms appear in current scan-target scripts. | **ACCEPTED** — documented prospective scope boundary; current scripts contain no bash-5.0 `@`-operator forms; extending detection would require a regex change to the frozen artifact; FREEZE DISCIPLINE. |
| O-2 | LOW (non-blocking, prospective) | AC-003 `ifs_step1_re` pattern detects IFS assignments preceded by command separators, operators, and keywords, but does not cover the `declare IFS='|'` direct-declare form (no preceding separator). The form `declare IFS='|'` is a valid global IFS mutation that would be missed. No current scan-target scripts use this form. | **ACCEPTED** — documented prospective scope boundary; current scripts do not use direct `declare IFS=` form; extending would require regex change to frozen artifact; FREEZE DISCIPLINE. |
