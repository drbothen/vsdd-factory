## Part A — Findings

### F-P1-001 [BLOCKER] — emit fns dead-code; drain loop never wired

**Summary:** The `emit_*` family of functions (emit_completion, emit_telemetry_event, etc.) are declared but never called from the main task loop. The drain loop that was specified in the story to flush the async sink channel on shutdown is absent from the implementation. The functions compile but are unreachable dead code; no telemetry event ever reaches the sink.

**Evidence:** grep for callers of `emit_completion` and `emit_telemetry_event` in the implementation crate returns zero results outside the function definitions themselves. The story's AC-001 and AC-002 require events to be drained on task completion; no such drain is present.

**Impact:** The entire story deliverable is non-functional. All telemetry events are silently discarded. The sink channel is never read.

**Routing:** implementer (wire drain loop + call sites) + test-writer (T-001/T-002 must exercise the wired path, not stubs)

**Closes:** F-P1-001

---

### F-P1-002 [HIGH] — T-001, T-002, T-004 tautological: test body matches stub body, never fails

**Summary:** Tests T-001, T-002, and T-004 were written against the stub implementations. Each test constructs a sink, calls an emit function, and asserts the call returns `Ok(())`. Since the stub implementation is `fn emit_completion(...) -> Result<()> { Ok(()) }`, the test trivially passes with or without any real implementation. The tests cannot detect the dead-code defect (F-P1-001) because they test the stub's return value, not the observable side-effect (channel message delivered to drain).

**Evidence:** T-001 body: `assert!(emit_completion(...).is_ok())`. Stub body: `Ok(())`. These are structurally identical; the test provides zero discriminating power.

**Impact:** False green CI. F-P1-001 would pass all three tests even in its broken state.

**Routing:** test-writer (rewrite T-001/T-002/T-004 to assert observable channel delivery, not just Ok return)

**Closes:** F-P1-002

---

### F-P1-003 [HIGH] — main-task-emission design constraint absent from story spec

**Summary:** The story (S-19.05) does not specify the constraint that telemetry emission must occur on the main task thread and that the drain loop must run as part of the main task's shutdown sequence (not a detached background thread). This constraint is load-bearing: if a background thread drains the channel, the sink file may be written after the process exits, producing empty or partial output. The design constraint is implied by BC-3.08.001 but is not stated in S-19.05 AC-002 or EC-004.

**Impact:** Without an explicit story constraint, an implementer can comply with the spec while using a detached background thread, producing a subtly broken implementation that passes all current tests.

**Routing:** story-writer (add main-task-emission constraint to S-19.05 AC-002 / EC-004) + product-owner (BC-3.08.001 rationale review)

**Closes:** F-P1-003

---

### F-P1-004 [MED] — Mutex acquisition missing in drain loop scaffold

**Summary:** The drain loop scaffold in the implementation acquires a `Receiver<TelemetryEvent>` from the channel but does not hold the Mutex guard while draining. The Mutex is released before the drain loop begins, creating a window where a concurrent emit call could write to the channel after the drain has completed but before the file is finalized. This violates the "exactly-once delivery to sink" invariant implied by AC-001.

**Impact:** Race condition under concurrent task completion + drain. Low probability in practice (single-threaded event loop) but structurally incorrect.

**Routing:** implementer (hold Mutex across drain + file write)

**Closes:** F-P1-004

---

### F-P1-005 [MED] — ENV_SINK_FILE static leg: vacuous pass with no assertion

**Summary:** The test for the `VSDD_SINK_FILE` environment-variable leg (T-003 or equivalent) sets the env var to a temp path, calls the emit function, and then asserts the function returned `Ok(())`. It does NOT assert that the file was created at the specified path, nor that it contains the expected serialized event. The test passes vacuously even if the env-var leg is never reached.

**Impact:** The release-mode opt-in behavior (the core deliverable of AC-003) is untested at the observable level.

**Routing:** implementer (ensure env-var leg writes the file) + test-writer (assert file existence + content)

**Closes:** F-P1-005
