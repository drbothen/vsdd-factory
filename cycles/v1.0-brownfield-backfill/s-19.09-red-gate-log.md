## Failure Mode Verification

T-001 and T-002 fail via wasmtime-level link error at `linker.instantiate`: "unknown import: `vsdd::read_prefix` has not been defined." This is the definitive production-path instantiation signal: the production linker (`Linker<StoreData>` via `setup_host_on_store_data` in `invoke.rs`) does not register `read_prefix`, so any WASM plugin importing `vsdd::read_prefix` fails at instantiation on the production dispatch path. This is the exact gap codified in ADR-025 §Decision 16 (D19): S-19.06 registered `read_prefix` on the test linker (`setup_linker`, `Linker<HostContext>`) but NOT on the production dispatcher path.

T-003 fails via `linker.get(store, "vsdd", "read_prefix") == None` — a structural absence gate confirming the same gap via a lighter API (no module instantiation required).

T-013 fails via assertion on the `plugin.completed` timestamp field in the dispatch event payload (absent in current production path implementation, per D22 in ADR-025 §Decision 19).

The 9 bats tests (T-004..T-012) fail via static-grep and structural gates against the Phase-A source. T-009/T-010/T-011 include mutation-liveness fixtures confirming each gate's grep pattern is load-bearing.

No `#[should_panic]` masking. No vacuously-passing new tests.

## Process Gap — Rework Round (orchestrator-verified 2026-07-15)

**Initial commit d039f3e5 was rejected.** The initial red gate used compile-error reds (E0425 on missing constants): tests referenced constants that did not exist in the Phase-A codebase, causing the crate test build to fail entirely and masking whether the runtime tests were genuinely red for the right reason. The orchestrator rejected this per the assertion-error rule: red gate tests MUST fail via assertion errors (or equivalent behavioral failures), NOT via compile errors that prevent the test suite from running.

**Additional WAT ordering bug discovered and fixed in faf127ce.** The initial fixture WAT had imports appearing after memory declarations, which triggers a WASM parse panic before the load-bearing assertions could execute. Corrected to imports-first ordering per the WASM binary format spec.

**Restructure (faf127ce):** Tests were rewritten as bats grep-gates (T-009/T-010 with mutation-liveness) and compile-safe cargo unit tests (T-001..T-003 call `setup_host_on_store_data` via its public API with correct `Store<StoreData>` + `WasiCtx` arguments; T-013 uses a fixture dispatch payload). This form:
1. Never introduces compile errors into the main crate build
2. Fails via assertion errors / wasmtime-level link errors (behavioral, not compile-time)
3. Mutation-liveness fixtures confirm that bats grep gates are load-bearing

**Lesson candidate (first occurrence):** Red-gate authoring MUST NOT use compile-error red forms — compile errors mask sibling tests' verification by preventing the entire test suite from building. To be codified at S-19.09 convergence burst if the cascade concurs (as `L-BB-red-gate-compile-error-reds-mask-sibling-tests`).

## Harness Form — Production-Path Instantiation Gate

T-001/T-002/T-003 call `setup_host_on_store_data` directly with `Store<StoreData>` + `WasiCtx` — the minimum-overhead production-path instantiation gate. This gate class was absent for the S-19.06 red gate (which tested the test-path linker `setup_linker`/`Linker<HostContext>`) and is the gap that allowed the D19 issue (read_prefix absent from the production linker) to survive the S-19.06 merge. T-001..T-003 close this gap prospectively, per the lesson `L-BB-additive-host-abi-functions-require-production-path-instantiation`: any new host ABI function MUST have a production-path instantiation gate at Red Gate time.
