## Part A — Findings

### F-P6-001 — MEDIUM (BLOCKING): AC-001 guard-detector does not enforce the entrypoint-positional soundness boundary documented in bash-portability.md §1 and EC-006

**What:** bash-portability.md §1 and EC-006 define the entrypoint-guard model: the bash-4 guard MUST be positionally earlier in the entrypoint file than the first `source` (`.`) statement that pulls in a `local -A` lib. This soundness boundary is described in prose but the AC-001 bats detector contains no assertion that `guard_line < first_source_line`. A new unguarded entrypoint that sources a `local -A` lib is EC-006's documented FAIL case, but the detector accepts it if the lib itself contains a guard further down — the entrypoint-positional requirement is NOT enforced.

**Concrete scenario:** Create a new entrypoint `new-entry.sh` with no bash-4 guard at all but which sources `wave-handoff-lib.sh` (which contains `local -A map`). Under the current test, the guard detector PASSES because it finds a guard somewhere in the sourced chain. Under the documented EC-006 model, this MUST FAIL because the entrypoint has no guard.

**Where:** `plugins/vsdd-factory/tests/wave-handoff.bats` — AC-001 test suite; specifically missing: (a) a structural check asserting `guard_line < first_source_line` for each non-lib entrypoint that sources a `local -A` lib, (b) a synthetic positive-control test with an unguarded entrypoint → must FAIL, (c) a guarded negative control confirming POLICY 11 non-tautology.

**Why it matters:** The guard model is the core safety boundary for S-18.12. Documenting the boundary without enforcing it defeats the purpose of the static lint gate.

**Routing:** test-writer (add structural check + synthetic EC-006 positive control + guarded negative control). No regex altered.

**Status:** FIXED in burst D-730 by test-writer (commit 77147d3e): added (a) real-script structural check asserting `guard_line < first_source_line` for every non-lib entrypoint that sources a `local -A` lib (wave-handoff.sh guard@9 < source@20 → PASS), (b) synthetic EC-006 positive control (unguarded entrypoint → detector MUST FAIL), (c) guarded negative control (POLICY 11 non-tautology). No regex string altered.

### O-4 — LOW [process-gap]: regression-detector tests emitted no positive-coverage line on the PASS path

**What:** The 5 portability regression-detector tests (AC-001 through AC-005) reported only a pass/fail exit code on success. On the PASS path, the test produced no machine-greppable output confirming the scope of what was scanned (how many files, which ACs). A silent green path cannot distinguish between "scanned 5 files, none flagged" and "scanned 0 files, nothing to flag" — a scope-narrowing silent failure is undetectable.

**Routing:** test-writer (add `echo "AC-00N: scanned=${#sh_files[@]} files"` or equivalent output on success path to each test).

**Process-gap classification:** This is a process-gap (O-4 tagged [process-gap]) because it is an architectural defect in how the test harness communicates scope — not a one-off miss but a structural class. MUST be codified per S-7.02 Cycle-Closing Checklist step-3.

**Status:** FIXED in burst D-730 by test-writer (commit 77147d3e): each of the 5 tests now emits `AC-00N: scanned=${#sh_files[@]} files` on the PASS path. Confirmed scanned=5 on current scan set. L-BB-regression-detector-tests-must-emit-positive-coverage-line codified in lessons.md.
