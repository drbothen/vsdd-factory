### O-1 (LOW — non-blocking, POLICY 13 / sibling-sweep, authorial-intent)

**AC-002 case-modifier test uses only scan-set-global `has_guard`; it does NOT replicate AC-001's `_ep_guard_precedes_source` positional check.**

**Finding:** The `test_portability_case_modifier` oracle (AC-002) verifies that a case-modifier usage in a scan-set file is caught ONLY if the `has_guard` flag is false at scan time. AC-001's oracle adds a stronger positional check (`_ep_guard_precedes_source`) asserting the guard precedes the first source line. AC-002 does not replicate this positional check. A future entrypoint that uses a case modifier (e.g., `${var^^}`) and has a BASH_VERSINFO guard placed AFTER a `source` call would pass AC-002 (guard present anywhere → `has_guard=true` → AC-002 satisfied) but would crash bash 3.2 when the case modifier executes before the bash-4+ guard is reached. No such entrypoint exists today; no current scan-set script has post-source guards.

**Disposition:** ACCEPTED-AS-DOCUMENTED-PROSPECTIVE-SCOPE-BOUNDARY (D-740). No current entrypoint has a post-source guard. The asymmetry is acknowledged as a prospective design question for a future case-modifier entrypoint author. FREEZE DISCIPLINE.

### O-2 (LOW — non-blocking, POLICY 13)

**python_re/jq_re `[|;&]` char-class arm — the `;` sub-branch and bare `|` sub-branch lack individually-labelled dedicated positive controls; only `\|`/pipe-arm and `&`/background-arm are separately exercised.**

**Finding:** The `[|;&]` alternation in python_re/jq_re covers semicolon-separated, pipe-separated, and ampersand-separated invocations. The `&` member is exercised via the background-execution controls. The `|` member is exercised via the pipe/xargs arm controls. The `;` member has no individually-labelled fixture (e.g., no `pc_bad_py_semicolon` or `pc_bad_jq_semicolon` control). The arm is verified non-tautological because at least two of its three character-class members are positively exercised via sibling arm fixtures, but the `;` member in isolation lacks an explicit positive control. This is a single POSIX bracket expression and not load-bearing coverage-wise.

**Disposition:** ACCEPTED (control-completeness note; FREEZE DISCIPLINE). The arm is exercised via sibling members. A pure-absence scenario for the full char-class requires all three members to be simultaneously unexercised; that is not the case.

### O-3 (LOW — non-blocking, POLICY 13) — RECORD AS DRIFT ITEM

**The violation detectors (AC-001..005 scan loops) do NOT strip comment lines before matching; only the guard oracle applies `grep -vE '^[[:space:]]*#'` comment stripping.**

**Finding:** AC-001 guard oracle applies `grep -vE '^[[:space:]]*#'` before evaluating guard_re — this prevents a commented-out guard from satisfying the guard-presence check (F-P14-001 fix). However, the violation detectors in the same 5 portability tests that check for BAD patterns (array_re, case_mod_re, ifs_step1-3_re, python_re, jq_re) do NOT strip comment lines before running the scan regex. A shell comment like `# example: python3 foo.py` or `# old guard: [[ ${BASH_VERSINFO[0]} -ge 4 ]]` in a scan-target script would be false-MATCH by a violation detector — triggering a spurious test failure. Currently no false positives exist: write-wave-state.sh line 195 contains `# the ...` which has `IFS` but the scanner happens to miss it because `the ` precedes IFS= (no step-1 anchor hit). This non-detection is fragile — a comment edits changing the token order could introduce a false positive. No current false positive in the 68/68 GREEN result.

**Disposition:** ACCEPTED now (prospective; no current false positive). Record as Drift Item: "extend comment-strip (`grep -vE '^[[:space:]]*#'`) to violation detectors for parity with guard oracle" with target = S-18.12 pre-PR polish burst (before demo-recorder) OR POST-E-18 hardening. FREEZE DISCIPLINE for current 3-CLEAN streak.

### O-4 (LOW — non-blocking, POLICY 13)

**ifs_step2_re subshell exemption covers only line-start subshells; a non-line-start subshell `result=$( (cmd; IFS='|'; foo) )` would false-positive.**

**Finding:** AC-003 step-2 exemption for subshell IFS is anchored to line-start patterns (`^\s*\(`). The current scan targets contain no such nested-subshell IFS assignment.

**Disposition:** ACCEPTED-AS-DOCUMENTED-PROSPECTIVE-SCOPE-BOUNDARY (D-740). No such non-line-start nested-subshell IFS form exists in any current scan target. FREEZE DISCIPLINE.

### O-5 (LOW — non-blocking, POLICY 4/13)

**guard_re presence oracle — any `[` character ANYWHERE on the line before a bare BASH_VERSINFO reference satisfies the guard oracle (e.g., `arr[0]=$BASH_VERSINFO` would false-GREEN as a guard-present line).**

**Finding:** The guard_re pattern is `\[\[.*BASH_VERSINFO` or similar. The `[` anchor means any line with `[` before `BASH_VERSINFO` would satisfy `_ep_guard_precedes_source`. Currently no such non-conditional BASH_VERSINFO reference exists — the only BASH_VERSINFO reference in scan targets is the real conditional guard in wave-handoff.sh.

**Disposition:** ACCEPTED-AS-DOCUMENTED-PROSPECTIVE-SCOPE-BOUNDARY (D-740). No non-conditional BASH_VERSINFO reference exists in any current scan target. FREEZE DISCIPLINE.
