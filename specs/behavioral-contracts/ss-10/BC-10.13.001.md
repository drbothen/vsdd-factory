# BC-10.13.001: last-amended-migrate — Sanctioned Rust CLI for One-Time `last_amended`/`changelog:` Migration Plus Changelog Rotation (POLICY 21-Compliant)

## Description

A committed, platform-agnostic Rust `bin/` binary (POLICY 21 `no_new_shell_scripts` — explicitly
NOT a new `.sh` script) that performs two functions mandated by ADR-049/S-15.03 AC-006: (1) a
one-time migration bringing `STORY-INDEX.md`, `BC-INDEX.md`, `ARCH-INDEX.md`, `VP-INDEX.md`, and
`STATE.md` fully into the ADR-049 shape (adding `changelog:` to `STORY-INDEX.md`, confirming
`last_amended` is strictly current-entry-only on all five, and remediating the pre-existing
D-1144 unescaped-double-quote defect in `BC-INDEX.md`/`ARCH-INDEX.md`/`STATE.md`); and (2) as a
safety-net utility, rotation of an over-long `changelog:` sequence into a per-cycle archive under
`.factory/cycles/<cycle-name>/`, mirroring how `burst-log.md`/`decision-log.md` already archive
per cycle. Delivering this tool removes the need for any future POL-3/TD-FACTORY-HOOK-BYPASS-001
ad hoc exception request for this class of problem (large-single-scalar-line surgery) — invoking
the tool is the sanctioned path going forward.

## Preconditions

1. The tool is invoked against one of the five ADR-049-governed files (or, for the migration
   subcommand, against all five in one run) by an operator or an orchestrator-dispatched agent
   with filesystem write access to `.factory/`.

2. For the migration subcommand: the target file's current `last_amended` value is already in a
   D-1149-slim current-entry form (a single dated entry, optionally with a trailing
   `[Prior history → <file>-amendment-history.md]` pointer note) — the tool is a shape-completion
   and escape-remediation utility, not a general-purpose mega-line splitter (that surgery was
   D-1149's one-time human-authorized exception and is out of this tool's scope).

3. For the rotation subcommand: the target file's `changelog:` sequence has grown past an
   operator-configurable or tool-default size threshold, and a destination cycle name (matching
   an existing or newly-created `.factory/cycles/<cycle-name>/` directory) is supplied.

## Postconditions

### PC1 — migration completes `changelog:` coverage across all five files

Running the migration subcommand against `STORY-INDEX.md` adds a `changelog:` top-level YAML
sequence to its frontmatter if absent (completing the D-448(b)/D-414(c) deferral already recorded
in `STORY-INDEX.md`'s own header blockquote). Running it against `ARCH-INDEX.md`, `BC-INDEX.md`,
or `VP-INDEX.md` — which already carry `changelog:` — is a verified no-op on that field (the tool
confirms presence and structural validity rather than re-adding it). Running it against
`STATE.md` never adds a `changelog:` field (ADR-049 Decision 4 — `STATE.md` relies on its
body-level `## Decisions Log`/`## Phase Progress` instead).

### PC2 — migration confirms/enforces current-entry-only `last_amended` on all five files

For each of the five files, the tool asserts (and, if violated, corrects) that `last_amended` is
a single dated entry with no nested `[Prior: <date> (vX.Y) — ...]` bracket referencing a
different dated entry. Where a file is already compliant (the expected state post-D-1149,
modulo PC3's escape defect), this is a verified no-op.

### PC3 — D-1144 escape remediation on the three defective files

For `BC-INDEX.md`, `ARCH-INDEX.md`, and `STATE.md` — the three files carrying the pre-existing
D-1144 unescaped-literal-double-quote defect in their current `last_amended` entry — the tool
rewrites the offending entry with every embedded literal `"` escaped to `\"`, producing a value
that parses cleanly under strict YAML `safe_load`. The entry's substantive text (every character
other than the escape insertions) is preserved verbatim. `VP-INDEX.md` and `STORY-INDEX.md` are
unaffected by this postcondition (not part of the D-1144 defect set).

### PC4 — migration is idempotent

Running the migration subcommand a second time (or any subsequent time) against an
already-migrated file produces a verified-clean report with zero file mutations — the tool
detects the already-compliant shape and takes no destructive or duplicating action (it never
double-adds a `changelog:` field, never double-escapes an already-escaped quote, and never
re-wraps an already-current-entry-only `last_amended`).

### PC5 — rotation archives without data loss

Running the rotation subcommand against a file whose `changelog:` sequence exceeds the size
threshold moves the oldest N items (operator-specified count, or all-but-the-most-recent-K by
tool default) into a new or appended `.factory/cycles/<cycle-name>/<file-basename>-changelog-archive.md`
file, verbatim, and removes exactly those items from the source file's `changelog:` sequence,
leaving a discoverability pointer (e.g. a comment or a `changelog_archive:` frontmatter field
naming the archive path) in the source file. No `changelog:` item's `date:`/`change:` text content
is altered by rotation — only its location changes.

### PC6 — the tool never touches the frozen D-1149 sidecars

Neither the migration nor the rotation subcommand ever writes to, reads for mutation, or deletes
any of the five `*-amendment-history.md` sidecar files. They remain a frozen pre-migration archive
per S-15.03 §Migration and ADR-049 Decision 5. The tool MAY read them read-only for reporting
purposes (e.g., confirming they exist and are referenced by a pointer note) but never mutates
them.

## Invariants

1. **Rust `bin/` binary, not a shell script (POLICY 21).** The tool is delivered as a compiled
   Rust binary under `plugins/vsdd-factory/bin/` (or an equivalent Rust workspace crate producing
   such a binary), never as a new `.sh` script, satisfying `no_new_shell_scripts`.

2. **Idempotent on every subcommand.** Both migration and rotation are safe to re-run; neither
   subcommand's second invocation against an unchanged target produces a different result or a
   file mutation (see PC4; the same property extends to rotation — re-running rotation
   immediately after a successful rotation, before the threshold is exceeded again, is a
   verified-clean no-op).

3. **Safe on arbitrarily long input.** The tool processes files up to and including the
   pre-migration mega-line scale (D-1149's 323,499-char `STORY-INDEX.md` frontmatter scalar as
   the calibration ceiling) without unbounded memory growth or non-linear runtime blowup — it is
   the sanctioned mechanism precisely because Edit/Write-tool-mediated manual editing cannot
   safely handle content at this scale (per the D-1149 justification for the original one-time
   POL-3 exception).

4. **Every write the tool performs satisfies BC-5.45.001's write-path invariants.** The tool is
   itself a conforming writer under BC-5.45.001 — its own migration/rotation writes never
   introduce a new inline `[Prior: ...]` bracket chain, and every value it emits parses under
   strict YAML `safe_load`.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Migration invoked against a file already fully compliant with ADR-049 shape | Verified-clean report; zero mutations (PC4). |
| EC-002 | Migration invoked against `STORY-INDEX.md` for the first time (no `changelog:` field exists) | `changelog:` sequence added (initially empty, or seeded with the current `last_amended` entry as its first item per the migration's own initial-seed convention — tool documentation MUST state which); `last_amended` unchanged if already current-entry-only. |
| EC-003 | Migration invoked against a file whose `last_amended` still contains a nested `[Prior: ...]` bracket chain (a pre-D-1149 or otherwise non-conforming file) | Out of scope for this tool per Precondition 2 — the tool reports the file as NOT eligible for migration (distinct from "already migrated") and does not attempt the large-scale bracket-splitting surgery; that remains a human-authorized POL-3 exception if it recurs elsewhere. |
| EC-004 | Rotation invoked against a file whose `changelog:` sequence is below the size threshold | No-op; tool reports current size vs. threshold and takes no action. |
| EC-005 | Rotation invoked with a `<cycle-name>` that does not yet exist under `.factory/cycles/` | Tool creates the target directory (consistent with how `burst-log.md`/`decision-log.md` archives are created per cycle) before writing the archive file. |
| EC-006 | Migration invoked against `STATE.md` | `changelog:` field is never added (PC1); only `last_amended` current-entry-only confirmation (PC2) and, if applicable, D-1144 escape remediation (PC3) apply. |
| EC-007 | A `*-amendment-history.md` sidecar file is missing or unreadable when the tool runs a reporting pass | Tool reports the missing sidecar as an informational finding but does not fail the migration/rotation operation on the file itself — sidecar presence is not a precondition for PC1-PC5 (PC6 governs write-avoidance, not read-availability). |
