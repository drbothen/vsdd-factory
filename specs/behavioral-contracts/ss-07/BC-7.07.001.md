# BC-7.07.001: precompact-flush native WASM plugin fires synchronously on PreCompact; hermetic (STATE.md + git only); renews factory lock natively when held via crates/factory-lock::renew_lock() (no-op when absent); commits (local) with `PreCompact flush <cycle>/<step>` message; appends commit SHA to precompact-flush-log; pushes to remote; on append failure: SHA-pinned reset (`git reset --soft SHA_B^` when HEAD==SHA_B; no-reset + human-intervention exit 2 when HEAD!=SHA_B); exit 2 on commit failure (local; no network) or push failure (network); fail-open on crash

## Description

`precompact-flush` is a native WASM plugin (compiled from `crates/hook-plugins/precompact-flush/`) registered under `event = "PreCompact"` in `hooks-registry.toml`. It fires before each harness auto-compaction event and ensures that `STATE.md` and wave-critical state are committed and pushed to the `factory-artifacts` branch before compaction proceeds. The full flush sequence is: (1) commit (local git operation — no network), (2) append commit SHA to precompact-flush-log, (3) push to remote (network operation). The plugin is hermetic (reads only STATE.md and git; never reads in-context state), renews the factory lock natively via `crates/factory-lock::renew_lock()` (no bash exec; ADR-028 Decision 2) before committing, and exits 2 to block compaction on any of: git commit failure (local; no network involvement), precompact-flush-log append failure, or git push failure (network/remote). On append failure the plugin captures `SHA_B` immediately after commit, then compares `CURRENT_HEAD` to `SHA_B`: if equal, executes `git -C <factory-artifacts-worktree> reset --soft SHA_B^` (SHA-PINNED) to undo the orphan local commit before exiting 2, preventing a BC-5.41.003 false-positive block on the next burst; if not equal (concurrent commit landed), does NOT reset and exits 2 with a human-intervention message. On push failure, the local commit and log entry already exist — retry is push-only. It exits 0 (fail-open) only on success, no-op (clean state), or STATE.md-unreadable conditions. This implements ADR-026 Decision 6 in full.

## Preconditions

1. The plugin is registered in `hooks-registry.toml` as:
   ```toml
   [[hooks]]
   name = "precompact-flush"
   event = "PreCompact"
   plugin = "hook-plugins/precompact-flush.wasm"
   priority = 100
   timeout_ms = 30000
   on_error = "continue"
   async = false

   [hooks.capabilities.read_file]
   path_allow = [".factory/"]

   [hooks.capabilities.write_file]
   path_allow = [".factory/"]

   [hooks.capabilities.exec_subprocess]
   binary_allow = ["git"]
   env_allow = ["HOME", "GIT_CONFIG_GLOBAL", "XDG_CONFIG_HOME", "PATH", "SSH_AUTH_SOCK"]
   ```
   Note: `binary_allow = ["git"]` ONLY — `"bash"` is explicitly absent (ADR-028 §Decision 2). No `[hooks.config]` block; no `shell_bypass_acknowledged`. (Native WASM stanza per ADR-028 §Decision 2 corrected TOML schema.) `PATH` is required for git to locate `ssh` and credential helpers (needed by `git push`). `SSH_AUTH_SOCK` is required for SSH agent communication. Without these, `git push` over SSH will fail with authentication errors. The dispatcher's `exec_subprocess` runs with `env_clear` followed by re-injection of only the names listed in `env_allow`; omitting `PATH` or `SSH_AUTH_SOCK` causes authentication failure on `git push` over SSH even if all other env vars are present.
2. The Claude Code harness version >= v2.1.105 (PreCompact blocking supported).
3. The dispatcher routes `PreCompact` events to registered plugins (BC-1.15.001 postconditions satisfied).
4. The native WASM plugin performs lock renewal natively in Rust via `crates/factory-lock` (a shared library crate). Lock renewal does NOT invoke `bash factory-lock-write.sh renew`. The bash helper `plugins/vsdd-factory/bin/factory-lock-write.sh` remains available for agent/skill callers (e.g., the `state-burst` skill per ADR-025 §Decision 11 Mechanism 1) but is NOT a dependency of the native WASM plugin. The binding `renew_lock()` signature is `pub fn renew_lock(state_md_content: &str) -> Result<RenewOutcome, LockError>` (pure content-in/content-out; ADR-028 §Decision 9). The path-based form `renew_lock(&Path)` / `renew_lock(&factory_artifacts_path)` is STRUCK. The plugin caller owns all host I/O: `host::read_file(".factory/STATE.md")` → `state_md_content`; then `renew_lock(&state_md_content)` → on `Ok(Renewed(new_content))`: `host::write_file(".factory/STATE.md", new_content)`. `crates/factory-lock` contains NO `std::fs` calls and is WASM-hermetic. Factory-artifacts worktree path is discovered via runtime `git worktree list --porcelain` (ADR-028 §Decision 1); the plugin executes `git worktree list --porcelain`, parses the stanza whose `branch` line is `refs/heads/factory-artifacts`, and uses that stanza's `worktree` absolute path. The discovered absolute path is used ONLY as the `git -C <abs>` argument for every git subprocess — host `read_file`/`write_file` always use `.factory/`-relative paths gated by `path_allow`. Canonical invariant: discovered-worktree == `<CLAUDE_PROJECT_DIR>/.factory`. If worktree discovery fails — either because the `git worktree list --porcelain` subprocess exits non-zero (environment/git error) OR because the output contains no stanza with `branch refs/heads/factory-artifacts` (configuration error) — the plugin exits 0 (fail-open per `on_error = continue`) but MUST write a DURABILITY DEGRADED advisory to stderr (ADR-028 §Decision 13). The advisory messages are:
   - Git command failed: `precompact-flush: DURABILITY DEGRADED — git worktree list command failed (exit <N>); factory-artifacts worktree cannot be discovered; flush SKIPPED this compaction event. Check PATH/git configuration.`
   - Factory-artifacts not found: `precompact-flush: DURABILITY DEGRADED — factory-artifacts branch not found in git worktree list output; flush SKIPPED this compaction event. Ensure the factory-artifacts worktree is mounted at .factory/ (run: git worktree add .factory factory-artifacts).`
   The LOUD advisory (uppercase `DURABILITY DEGRADED` prefix) distinguishes this from a normal no-op (clean state) and ensures a human reading session logs can identify a silently-disabled durability session. This is distinct from PC7 (STATE.md unreadable → `precompact-flush: STATE.md unreadable; flush skipped.`): PC7 is a quiet advisory because an unreadable STATE.md is a recoverable transient condition; a missing worktree is a structural configuration failure requiring human action.
   After the factory-artifacts stanza is found, the plugin MUST perform a startup canonicalize assertion before proceeding: `canonicalize(discovered_worktree_abs_path) == canonicalize(ctx.cwd + "/.factory")`. If they MATCH, proceed normally (Domain A `.factory/`-relative host I/O and Domain B `git -C <discovered>` are consistent — same filesystem location). If they MISMATCH, emit to stderr: `precompact-flush: DURABILITY DEGRADED — factory-artifacts worktree path mismatch: discovered <discovered_path> but expected <cwd>/.factory; flush SKIPPED to prevent split-tree data loss. Ensure factory-artifacts is mounted at .factory/ (run: git worktree add .factory factory-artifacts).` and exit 0 (fail-open — do NOT proceed with a split-tree flush). If `canonicalize()` itself fails on either path (path does not exist), treat as MISMATCH and emit the DURABILITY DEGRADED mismatch advisory; exit 0. The factory-artifacts worktree is ALWAYS mounted at `<CLAUDE_PROJECT_DIR>/.factory` by project convention; "non-standard mounts" are NOT supported (any "supports non-standard mounts" language from prior versions is STRUCK). This startup assertion mechanically enforces the canonical invariant at runtime rather than relying solely on ADR documentation (ADR-028 §Decision 1 v1.3). `renew_lock()` outputs `expires_at` in EXACTLY `YYYY-MM-DDTHH:MM:SSZ` format (UTC, second precision, uppercase Z suffix — NOT chrono rfc3339 `+00:00` form). `renew_lock()` returns `Err` on malformed blocks where the `factory_lock:` key IS present; the hook caller treats `Err` as advisory (fail-open per §EC-004). `Ok(RenewOutcome::NoOp)` (lock key absent or lock null/absent — including malformed-fence-without-lock-key) → skip renewal, proceed.
5. The `factory-artifacts` branch is accessible via `git`.
6. `STATE.md` is accessible at `.factory/STATE.md` relative to the plugin root or working directory.

**Note — Committer identity (A15; ADR-028 §Decision 18):** The plugin does NOT validate that the git committer identity (resolved from `HOME`/`~/.gitconfig` via `env_allow` per Precondition 1) matches the `factory_lock.holder` field in STATE.md. This is acceptable because: (a) the factory-lock mechanism serializes single-session access — the session that holds the lock is the session performing the flush, so committer and lock holder are the same operator by construction; (b) committer identity is validated at the OS/git level (if no identity is configured, `git commit` exits non-zero → flush fails safely at exit 2 per §PC6); (c) cross-referencing committer vs. holder is fragile and out of scope for a durability hook. This is an informational note, not a blocking precondition.

## Postconditions

1. **STATE.md read from filesystem**: The hook reads `STATE.md` via direct filesystem read (`cat .factory/STATE.md` or equivalent); it determines context identity from `STATE.md` frontmatter `current_cycle:` and `current_step:` fields. It does NOT look for a non-existent `current_wave:` field. It does NOT rely on in-context reasoning, environment variables set by the LLM, or piped session context.

2. **custom_instructions NOT used**: The hook does NOT read from `custom_instructions`, `system_prompt`, or any in-context LLM mechanism. These are unreliable on auto-compaction (confirmed in F1 research). All flush data comes from STATE.md and git.

3. **Factory lock renewed or skipped**: The plugin reads the `factory_lock:` block from `STATE.md`. If `factory_lock:` is absent from STATE.md or `factory_lock.holder` is absent/null, the lock is not held and the lock-renewal step is skipped entirely (no-op per ADR-025 opt-in model; ADR-026 Decision 6 §Step 2). If the lock IS held, the plugin natively updates `factory_lock.expires_at = now + 2700s` in STATE.md via `crates/factory-lock::renew_lock()` — a pure Rust in-process update with no `exec_subprocess` call for renewal. The `holder` and `locked_at` fields are preserved unchanged. Lock renewal failure is treated as a non-fatal warning (advisory); the flush proceeds and attempts the commit regardless. Lock renewal failure does NOT cause exit 2. (ADR-028 §Decision 2; EC-004.) `factory_lock.expires_at` is output in EXACTLY `YYYY-MM-DDTHH:MM:SSZ` format (UTC, second precision, uppercase Z suffix — matches BC-5.40.001 §Invariant 2 and `factory-lock-write.sh` output format; NOT chrono rfc3339 `+00:00` form; use `chrono::Utc::now().format("%Y-%m-%dT%H:%M:%SZ").to_string()` — NOT `to_rfc3339()`). Parse outcomes from `crates/factory-lock-parse::parse_factory_lock()`: `Ok(None)` (lock absent, null, empty block, or no frontmatter in STATE.md) → skip renewal (no-op, no advisory); `Ok(Some)` (valid lock block with all three sub-fields present) → update `expires_at` to `now + 2700s`; `Err(MalformedLockBlock)` (block present but malformed — missing field, empty field, missing closing fence) → emit advisory warning to stderr + proceed (fail-open). When lock is held and renewal succeeds, the renewed STATE.md is staged in the subsequent `git -C <wt> add -A` step and therefore included in the flush commit (renewal MUST precede git add). `crates/factory-lock::renew_lock()` performs a `factory_lock:` key presence pre-check before invoking the full fence-aware parser. If `factory_lock:` is NOT present in the frontmatter region — regardless of fence shape (including malformed/unclosed fence) — `renew_lock()` returns `Ok(RenewOutcome::NoOp)` immediately: this matches bash `factory-lock-write.sh renew` behavior of silently exiting 0 when the lock key is absent (ADR-028 §Decision 9). `Err(LockError::Malformed)` is returned ONLY when `factory_lock:` IS present but the block is malformed. The hook caller treats `Err` as advisory (fail-open per §EC-004). `Ok(RenewOutcome::NoOp)` is returned both for lock-absent and for lock-key-absent-with-malformed-fence, preserving bash parity. Note (A14 — NoOp-on-identical): `renew_lock()` returns `Ok(RenewOutcome::NoOp)` in two distinct cases: (a) lock key is absent from frontmatter (pre-check returns false), and (b) lock is held but the recomputed `expires_at` is byte-identical to the existing value (same wall-clock second — ADR-028 §Decision 16). In case (b), `renew_lock()` does NOT write STATE.md; `RenewOutcome::Renewed` is returned ONLY when `expires_at` actually changes.

4. **Factory-artifacts commit**: The hook stages and commits `STATE.md` (and any other factory-artifacts files with pending changes) to the `factory-artifacts` branch with commit message: `PreCompact flush <cycle>/<step> <ISO-8601-timestamp>` where `<cycle>` and `<step>` are the `current_cycle:` and `current_step:` values read from STATE.md frontmatter (e.g., `PreCompact flush v1.0-feature-context-durability-E18/S-18.04 2026-06-14T12:00:00Z`).

5. **Exit 0 on flush success or clean state**: If the commit lands successfully, the hook exits 0. If there are no pending changes on `factory-artifacts` (clean state, nothing to flush), the hook exits 0 without creating an empty commit.

6. **Exit 2 on commit failure (block compaction — LOCAL failure only)**: If the git commit command fails (lock contention, permission error, or other local filesystem error), the hook exits 2. This signals the dispatcher to block compaction via `block_intent = true`. The hook writes a diagnostic message to stderr before exiting 2. Note: `git commit` is a purely LOCAL operation — it writes to the local git object store and does NOT involve any network communication. Network errors cannot originate from `git commit`; they belong to `git push` (PC8b). At the time of commit failure, no precompact-flush-log entry has been appended and no push has been attempted.

6b. **Exit 2 on push failure (block compaction — NETWORK/REMOTE failure)**: After the git commit succeeds and the precompact-flush-log append succeeds, the hook executes `git push` to synchronize the local commit to the remote `factory-artifacts` branch. If `git push` fails for any reason (network error, remote rejection, authentication failure), the hook exits 2. This signals the dispatcher to block compaction via `block_intent = true`. The hook writes a diagnostic message to stderr: `precompact-flush: git push failed; local commit <SHA_B> and log entry intact; retry is push-only`. The hook writes a diagnostic message to stderr before exiting 2. Note: at the time of push failure, the local commit exists on `factory-artifacts` and the precompact-flush-log entry has already been appended — these are NOT rolled back. Retry requires only a `git push` (not a re-commit).

7. **Exit 0 + warn on STATE.md unreadable**: If STATE.md is absent or unreadable, the hook exits 0 (fail-open per ADR-026 Decision 6 `on_error = "continue"` spirit). A warning is written to stderr: `precompact-flush: STATE.md unreadable; flush skipped.`

8. **precompact-flush-log append (SHA-pinned concurrent-commit guard — F-P5-002 + F-P6-006)**: After the git commit succeeds, the hook immediately captures `SHA_B=$(git -C <factory-artifacts-worktree> rev-parse HEAD)`. It then APPENDS a new line to `.factory/hooks/precompact-flush-log` (creating the file if absent) containing four space-separated fields: `<ISO-timestamp> <SHA_B> <cycle>/<step> commit` where `commit` is the literal string `commit` (the object type, pre-embedded by the shell hook — NOT the output of a live `git cat-file -t` call at validation time). **The appended line MUST be terminated by exactly one LF (`\n`), INCLUDING when it is the final line in the file.** The file therefore always ends with `\n` after every successful append. This `\n`-termination guarantee is the upstream obligation VP-090 §0 relies on for its one-entry-per-physical-line counting semantics: implementations MUST use `echo "..." >> precompact-flush-log` or equivalent (`printf "%s\n" "..."`) — NOT `printf "%s"` (which omits the trailing newline). A conforming implementation that appends without a trailing `\n` violates this postcondition even if the four-field content is otherwise correct. **Absent-log baseline (CV-003; ADR-028 §Decision 12):** If `host::read_file` on `.factory/hooks/precompact-flush-log` returns an error — including `CAPABILITY_DENIED` when the file does not yet exist (because `canonicalize()` in `read_file` fails on non-existent files) — the plugin MUST treat the error as EMPTY prior content (`""`). The new entry is concatenated to `""` and written via `host::write_file` (which supports creating new files per BC-2.02.011 EC-005). This is NOT an append failure and does NOT trigger the SHA-pinned reset guard; it is the intended first-flush behavior. The SHA-pinned reset guard fires only when `write_file` returns an error AFTER the `read_file` step (empty-baseline or not). Do NOT treat a `read_file` error on the log path as an append failure. **If the append (write_file) fails**, the hook executes the following SHA-pinned concurrent-commit guard:
   - (1) Capture `SHA_B` immediately after `git commit` (this capture MUST happen BEFORE the append attempt so SHA_B is available on failure).
   - (2) Compare `CURRENT_HEAD=$(git -C <worktree> rev-parse HEAD)` to `SHA_B`.
   - (3a) **If CURRENT_HEAD == SHA_B** (no concurrent commit landed): execute `git -C <factory-artifacts-worktree> reset --soft SHA_B^` (SHA-PINNED to `SHA_B^`, NOT `HEAD~1` — rationale: `HEAD~1` is a relative reference that could discard a concurrent SHA_C commit if HEAD has moved; `SHA_B^` always resolves to the parent of the KNOWN flush commit regardless of any intervening commits). Write diagnostic to stderr: `precompact-flush: SHA append to precompact-flush-log failed; orphan commit reverted (SHA_B=<sha>); blocking compaction`. Exit 2.
   - (3b) **If CURRENT_HEAD != SHA_B** (a concurrent commit landed between SHA_B creation and this check): do NOT reset — resetting would discard the concurrent commit (SOUL.md Rule 4: no silent data loss). Exit 2 immediately with error message: `precompact-flush: append failed; concurrent commit advanced HEAD; SHA_B=<sha_b>; current HEAD=<current_head>; human intervention required`.
   - (4) **If the reset itself fails** (step 3a reset exits non-zero): exit 2; human intervention required.
   **Note on `--soft` staged-state behavior**: `--soft SHA_B^` restores the working tree index to the state staged for SHA_B. If STATE.md or other files changed between SHA_B creation and the reset (e.g., a concurrent state-manager turn), those changes appear as unstaged working-tree changes in the retry — they are NOT reverted. The retry commit WILL include those changes if they are re-staged. This is the correct behavior for the common case.
   The ordering is: (1) capture SHA_B immediately after `git commit`, (2) attempt append to precompact-flush-log, (3) IF append fails: compare CURRENT_HEAD to SHA_B — if equal: `reset --soft SHA_B^` then exit 2; if not equal: exit 2 with human-intervention message (do NOT reset), (4) IF append succeeds: execute `git push` to remote, (5) IF push fails: exit 2 with `precompact-flush: git push failed; local commit <SHA_B> and log entry intact; retry is push-only`, (6) IF push succeeds: exit 0. Prior log lines are retained as history; only the last line is authoritative. The ONLY exit codes this hook ever produces are 0 (success, no-op, or STATE.md-unreadable fail-open) and 2 (git commit failure (LOCAL) OR append-failure-after-SHA-pinned-reset OR concurrent-commit-guard-triggered OR git push failure (NETWORK)). Exit 1 is not used.

9. **Hook crash — on_error = "continue"**: If the hook script crashes before emitting an exit code (set -euo pipefail failure, WASM sandbox error), the dispatcher's `on_error = "continue"` setting treats the crash as exit 0. Compaction proceeds. The crash is logged to the dispatcher internal log with `plugin.crashed`.

## Invariants

1. **Hermetic invariant**: The hook reads ONLY from (a) `STATE.md` on the filesystem, and (b) `git` commands. It MUST NOT read from: environment variables set by the LLM, `custom_instructions`, in-context tool call results, or any other session-state mechanism. This closes the anti-deadlock invariant (F1 regression risk §4.1 R1).

2. **`custom_instructions` exclusion is absolute**: Any implementation of `precompact-flush` (whether shell or native WASM) that reads `$CUSTOM_INSTRUCTIONS` or invokes any harness API to retrieve session context is a specification violation, regardless of fallback behavior.

3. **Native lock renewal is conditional; full execution order is canonical**: If `factory_lock:` is absent or `factory_lock.holder` is absent/null in STATE.md, the lock is not held and the renewal step is skipped (no-op). If the lock IS held, the renewal must occur before the git commit. The complete canonical execution order is: (1) discover factory-artifacts worktree abs-path via `git worktree list --porcelain` (the ONLY git command that does NOT use `-C`; runs against the main repo to discover the worktree path), (2) read STATE.md via host `read_file` (`.factory/`-relative path; Domain A), (3) invoke `crates/factory-lock::renew_lock(state_md_content)` (ADR-028 §Decision 9): if `Ok(RenewOutcome::NoOp)` (factory_lock: key absent regardless of fence shape, OR lock null/absent): skip step 4 (no `write_file` call; no-op); proceed to step 5; if `Ok(RenewOutcome::Renewed(new_content))`: proceed to step 4 (write renewed STATE.md); if `Err(Malformed)` (factory_lock: key IS present but block malformed): emit advisory warning to stderr; skip step 4; proceed to step 5, (4) if `RenewOutcome::Renewed`: write updated STATE.md via host `write_file` (`.factory/`-relative path; Domain A; `new_content` from `renew_lock()` return value); outputs `expires_at = now + 2700s` in EXACTLY `YYYY-MM-DDTHH:MM:SSZ` format; preserves `holder` and `locked_at`; renewal MUST precede git add so the renewed `expires_at` is staged, (5) `git -C <wt> add -A` — stages ALL changes in the factory-artifacts worktree: tracked modifications, tracked deletions, AND new untracked files. This ensures that new `.factory/` files created during the session (but not yet tracked by git) are captured in the flush commit and not silently lost on compaction. IMPORTANT: if step 3 returned `RenewOutcome::NoOp` AND `git -C <wt> diff --cached` is empty after staging, the plugin MUST apply INV5 (exit 0; do NOT create an empty commit); the empty-commit guard is evaluated after git add using post-add staging state, not pre-renewal staging state, (6) `git -C <wt> commit -m "PreCompact flush <cycle>/<step> <ISO-timestamp>"` (LOCAL — no network), (7) capture `SHA_B=$(git -C <wt> rev-parse HEAD)` IMMEDIATELY after commit (MUST precede append attempt), (8) attempt append to precompact-flush-log via host `read_file` + string concat + host `write_file` (read-modify-write; `.factory/`-relative path; Domain A) — the appended line MUST be terminated by exactly one LF (`\n`), INCLUDING when it is the final line in the file (use `echo "..." >>` or `printf "%s\n" "..."` — NOT `printf "%s"`; omitting the trailing `\n` violates PC8's newline-termination guarantee and VP-090 §0's structural precondition), (9) IF append fails: `CURRENT_HEAD=$(git -C <wt> rev-parse HEAD)` — if equal to SHA_B: `git -C <wt> reset --soft SHA_B^` (SHA-PINNED), write diagnostic, exit 2; if not equal: exit 2 with human-intervention message (do NOT reset), (10) IF append succeeds: `git -C <wt> push origin factory-artifacts` (NETWORK), (11) IF push fails: exit 2 with diagnostic `precompact-flush: git push failed; local commit <SHA_B> and log entry intact; retry is push-only`; IF push succeeds: exit 0. No step may be reordered. In particular, SHA_B capture (step 7) MUST precede the append attempt (step 8); the append (step 8) MUST precede the push (step 10); the concurrent-commit check MUST precede any reset; and any reset MUST precede exit 2 in the equal-HEAD case. The push (step 10) is NOT attempted if append fails (step 9 exits 2 before reaching step 10). ALL git subprocesses in steps 5–11 MUST use `git -C <wt>` where `<wt>` is the absolute worktree path discovered in step 1. Bare `git add`, `git commit`, `git push`, `git rev-parse`, `git reset` commands WITHOUT `-C` are FORBIDDEN (they would operate on the main repo instead of the factory-artifacts worktree, corrupting the SHA guard and committing to the wrong branch).

3a. **`renew_lock()` error semantics, RenewOutcome enum, and fail-open caller policy**: `crates/factory-lock::renew_lock()` has the binding pure signature `pub fn renew_lock(state_md_content: &str) -> Result<RenewOutcome, LockError>` (ADR-028 §Decision 9). The `RenewOutcome` enum is: `NoOp` (lock key absent or lock null — STATE.md unchanged) or `Renewed(String)` (lock was held and expires_at was updated — contains new full STATE.md content). The path-based form `renew_lock(&Path)` or `renew_lock(&factory_artifacts_path)` is STRUCK; the plugin caller owns all host I/O. `crates/factory-lock` contains NO `std::fs` calls (WASM-hermetic). `crates/factory-lock::renew_lock()` returns `Err(LockError::Malformed)` ONLY when `factory_lock:` IS present but the block is malformed (block present but missing field, empty field, missing closing fence after the key is found) — this is the library's faithful preservation of the bash `factory-lock-write.sh renew` exit-1-on-RenewalMissed semantics at the library layer. The library does NOT swallow the error or return `Ok(RenewOutcome::NoOp)` for blocks where the key IS present but malformed. The `precompact-flush` hook CALLER is the authoritative fail-open policy point: it downgrades `Err` to an advisory warning to stderr and proceeds with the flush commit. Future callers that require fatal semantics on malformed blocks may treat `Err` as fatal. When lock is held and renewal succeeds (`RenewOutcome::Renewed`), the renewed `expires_at` mutates STATE.md before `git -C <wt> add -A`; this means the flush commit is non-empty from the renewal change IF AND ONLY IF `expires_at` actually differs from the committed value (NOT a violation of INV5's empty-commit guard — see A14 NoOp-on-identical). When `RenewOutcome::NoOp`, no `write_file` call is made; the staging area is unchanged by the renewal step; INV5 must be evaluated after `git -C <wt> add -A` using `git -C <wt> diff --cached` — if staging is empty AND step 3 returned `NoOp`: exit 0 clean-state (do NOT force a commit). Note on NoOp-on-identical-expires_at (A14): `renew_lock()` returns `RenewOutcome::Renewed(content)` IFF the lock was held AND the recomputed `expires_at` string DIFFERS from the existing `expires_at` value (byte-comparison). If the recomputed value is byte-identical (same wall-clock second), the function returns `Ok(RenewOutcome::NoOp)` — no `write_file` is performed. This ensures `RenewOutcome::Renewed` is a reliable signal that STATE.md content actually changed (ADR-028 §Decision 16).

4. **Commit message format is canonical**: The commit message MUST match the pattern `PreCompact flush <cycle>/<step> <ISO-timestamp>` exactly (with a single space between `<cycle>/<step>` and the timestamp). The subject must begin with the literal prefix `PreCompact flush ` (case-sensitive, with trailing space). This general prefix is used by `validate-burst-log` and `validate-dispatch-advance` to exempt the commit from TD-VSDD-053 `MULTI_COMMIT_CHAIN_NOT_ALLOWED` detection (BC-5.41.003).

5. **Empty commit is forbidden**: If `git diff --cached factory-artifacts` shows no changes, the hook must NOT create an empty commit. It exits 0 silently or with an info message: `precompact-flush: no pending changes; flush skipped.`

6. **Plugin error hardening**: The plugin uses idiomatic Rust error propagation (`Result<T, E>`) throughout. Unhandled errors propagate via the `?` operator. No `unwrap()` or `expect()` in non-test code paths. Panics are treated as crashes triggering `on_error = "continue"` fail-open per Postcondition 9 (consistent with BC-1.15.001 dispatcher `plugin.crashed` handling).

7. **Log pruning is DEFERRED to S-18.04b AC-N (F-P32-005)**: This BC's PC8 and Inv3 govern append-only growth of `precompact-flush-log`. ADR-026 §Crash-Consistency Design item 4 mandates a pruning step (prune to most-recent-500 entries when entry count exceeds 1000, implemented by a `precompact-flush-prune.sh` helper invoked by `check-state-health`), but explicitly defers it to S-18.04b AC-N. The v1 implementation permits UNBOUNDED append-only growth. At ~120 bytes/line (4-field format), 1000 entries ≈ 120KB — acceptable as a bridge per ADR-026 §Crash-Consistency Design item 4 rationale. This BC's append postconditions (PC8/Inv3) do NOT yet cover pruning. When S-18.04b AC-N ships, a v1.N+1 amendment will lift the pruning obligation into a new Postcondition.
