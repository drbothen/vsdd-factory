# BC-7.07.001: precompact-flush native WASM plugin fires synchronously on PreCompact; hermetic (STATE.md + git only); renews factory lock natively when held via the identity-gated shared function crates/factory-lock::renew_lock_if_holder() (no-op when absent, when holder mismatches the plugin's own resolved git identity, or when the recorded lock is already expired; emits factory.lock.renewal_indeterminate + log_warn when identity resolution itself fails on a self-held, non-expired lock — ADR-046 Decision 3/4); commits (local) with `PreCompact flush <cycle>/<step>` message; appends commit SHA to precompact-flush-log; pushes to remote; on append failure: SHA-pinned reset (`git reset --soft SHA_B^` when HEAD==SHA_B; no-reset + human-intervention exit 2 when HEAD!=SHA_B); exit 2 on commit failure (local; no network) or push failure (network); fail-open on crash

## Description

`precompact-flush` is a native WASM plugin (compiled from `crates/hook-plugins/precompact-flush/`) registered under `event = "PreCompact"` in `hooks-registry.toml`. It fires before each harness auto-compaction event and ensures that `STATE.md` and wave-critical state are committed and pushed to the `factory-artifacts` branch before compaction proceeds. The full flush sequence is: (1) commit (local git operation — no network), (2) append commit SHA to precompact-flush-log, (3) push to remote (network operation). The plugin is hermetic (reads only STATE.md and git; never reads in-context state). Before committing, it resolves its own caller identity via `exec_subprocess(["git", "config", "user.email"])` and renews the factory lock natively via the SHARED, identity-gated `crates/factory-lock::renew_lock_if_holder()` function (ADR-046 Decision 1(b)/3 — no bash exec; the same function BC-4.17.001's `stamp-state-timestamp` plugin calls). Renewal is a no-op when: no lock is held; the resolved identity does not match the recorded `holder`; the recorded lock is already expired (never resurrected, regardless of identity match); or `expires_at` is malformed (never repaired). When identity resolution itself fails (subprocess error, timeout, or empty stdout) while a self-held, non-expired lock IS present, the plugin emits `factory.lock.renewal_indeterminate` (`host::emit_event`) plus a `host::log_warn` (ADR-046 Decision 4) and proceeds without renewing — this is diagnostic-only and never blocks the flush. The plugin exits 2 to block compaction on any of: git commit failure (local; no network involvement), precompact-flush-log append failure, or git push failure (network/remote). On append failure the plugin captures `SHA_B` immediately after commit, then compares `CURRENT_HEAD` to `SHA_B`: if equal, executes `git -C <factory-artifacts-worktree> reset --soft SHA_B^` (SHA-PINNED) to undo the orphan local commit before exiting 2, preventing a BC-5.41.003 false-positive block on the next burst; if not equal (concurrent commit landed), does NOT reset and exits 2 with a human-intervention message. On push failure, the local commit and log entry already exist — retry is push-only. It exits 0 (fail-open) only on success, no-op (clean state), or STATE.md-unreadable conditions. This implements ADR-026 Decision 6 in full, amended per ADR-046 Decision 3 for the identity-gated renewal.

Factory-artifacts worktree path is discovered via runtime `git worktree list --porcelain` (ADR-028 §Decision 1); the plugin executes `git worktree list --porcelain`, parses the stanza whose `branch` line is `refs/heads/factory-artifacts`, and uses that stanza's `worktree` absolute path. The discovered absolute path is used ONLY as the `git -C <abs>` argument for every git subprocess — host `read_file`/`write_file` always use `.factory/`-relative paths gated by `path_allow`. Canonical invariant: discovered-worktree == `<CLAUDE_PROJECT_DIR>/.factory`. If worktree discovery fails — either because the `git worktree list --porcelain` subprocess exits non-zero (environment/git error) OR because the output contains no stanza with `branch refs/heads/factory-artifacts` (configuration error) — the plugin exits 0 (fail-open per `on_error = continue`) but MUST write a DURABILITY DEGRADED advisory to stderr (ADR-028 §Decision 13). The advisory messages are:
   - Git command failed: `precompact-flush: DURABILITY DEGRADED — git worktree list command failed (exit <N>); factory-artifacts worktree cannot be discovered; flush SKIPPED this compaction event. Check PATH/git configuration.`
   - Factory-artifacts not found: `precompact-flush: DURABILITY DEGRADED — factory-artifacts branch not found in git worktree list output; flush SKIPPED this compaction event. Ensure the factory-artifacts worktree is mounted at .factory/ (run: git worktree add .factory factory-artifacts).`
   The LOUD advisory (uppercase `DURABILITY DEGRADED` prefix) distinguishes this from a normal no-op (clean state) and ensures a human reading session logs can identify a silently-disabled durability session. This is distinct from PC7 (STATE.md unreadable → `precompact-flush: STATE.md unreadable; flush skipped.`): PC7 is a quiet advisory because an unreadable STATE.md is a recoverable transient condition; a missing worktree is a structural configuration failure requiring human action.
   After the factory-artifacts stanza is found, the plugin MUST perform a startup canonicalize assertion before proceeding: `canonicalize(discovered_worktree_abs_path) == canonicalize(ctx.cwd + "/.factory")`. If they MATCH, proceed normally (Domain A `.factory/`-relative host I/O and Domain B `git -C <discovered>` are consistent — same filesystem location). If they MISMATCH, emit to stderr: `precompact-flush: DURABILITY DEGRADED — factory-artifacts worktree path mismatch: discovered <discovered_path> but expected <cwd>/.factory; flush SKIPPED to prevent split-tree data loss. Ensure factory-artifacts is mounted at .factory/ (run: git worktree add .factory factory-artifacts).` and exit 0 (fail-open — do NOT proceed with a split-tree flush). If `canonicalize()` itself fails on either path (path does not exist), treat as MISMATCH and emit the DURABILITY DEGRADED mismatch advisory; exit 0. The factory-artifacts worktree is ALWAYS mounted at `<CLAUDE_PROJECT_DIR>/.factory` by project convention; "non-standard mounts" are NOT supported (any "supports non-standard mounts" language from prior versions is STRUCK). This startup assertion mechanically enforces the canonical invariant at runtime rather than relying solely on ADR documentation (ADR-028 §Decision 1 v1.3). `renew_lock()` outputs `expires_at` in EXACTLY `YYYY-MM-DDTHH:MM:SSZ` format (UTC, second precision, uppercase Z suffix — NOT chrono rfc3339 `+00:00` form). `renew_lock()` returns `Err` on malformed blocks where the `factory_lock:` key IS present; the hook caller treats `Err` as advisory (fail-open per §EC-004). `Ok(RenewOutcome::NoOp)` (lock key absent or lock null/absent — including malformed-fence-without-lock-key) → skip renewal, proceed.
5. The `factory-artifacts` branch is accessible via `git`.
6. `STATE.md` is accessible at `.factory/STATE.md` relative to the plugin root or working directory.

**Note — Committer identity (A15; ADR-028 §Decision 18):** The plugin does NOT validate that the git committer identity (resolved from `HOME`/`~/.gitconfig` via `env_allow` per Precondition 1) matches the `factory_lock.holder` field in STATE.md. This is acceptable because: (a) the factory-lock mechanism serializes single-session access — the session that holds the lock is the session performing the flush, so committer and lock holder are the same operator by construction; (b) committer identity is validated at the OS/git level (if no identity is configured, `git commit` exits non-zero → flush fails safely at exit 2 per §PC6); (c) cross-referencing committer vs. holder is fragile and out of scope for a durability hook. This is an informational note, not a blocking precondition.

## Postconditions

1. **STATE.md read from filesystem**: The hook reads `STATE.md` via direct filesystem read (`cat .factory/STATE.md` or equivalent); it determines context identity from `STATE.md` frontmatter `current_cycle:` and `current_step:` fields. It does NOT look for a non-existent `current_wave:` field. It does NOT rely on in-context reasoning, environment variables set by the LLM, or piped session context.

2. **custom_instructions NOT used**: The hook does NOT read from `custom_instructions`, `system_prompt`, or any in-context LLM mechanism. These are unreliable on auto-compaction (confirmed in F1 research). All flush data comes from STATE.md and git.

3. **Factory lock renewed or skipped (identity-gated, amended 2026-08-25, return-contract corrected 2026-08-26 — ADR-046 §Decision 1(b)/3)**: The plugin calls the shared `factory_lock::renew_lock_if_holder<F, I>(content: &str, resolve_identity: I, now_fn: F) -> Result<(RenewOutcome, Option<SkipReason>), LockError>` function (F-001 — the SAME canonical signature BC-4.17.001's `stamp-state-timestamp` plugin calls; both BCs state the IDENTICAL return contract). `resolve_identity` is a **lazy** closure — `|| classify_identity_resolution(host::exec_subprocess(["git", "config", "user.email"]))` (see the shared-classifier mandate below, F-003) — that `renew_lock_if_holder` invokes **at most once, and only when the decision tree actually reaches the identity-comparison step**; the plugin never calls `exec_subprocess` eagerly or independently of that closure. The function evaluates, in order, the same canonical five cases ADR-046 §Decision 1(b) specifies (case numbering harmonized 2026-08-26, O-P4-002, to match BC-4.17.001's PC2 and the ADR verbatim: Malformed=1, AlreadyExpired=2, NotHolder=3, IdentityResolutionFailed=4, Success=5; absent/empty-holder is the ADR's pre-existing, unnumbered "0th" case): **0th (pre-existing, unnumbered)** — `factory_lock:` absent from STATE.md or `factory_lock.holder` absent/null/empty-string → `Ok((RenewOutcome::NoOp, None))` — the lock is not held, renewal is skipped entirely (no-op per ADR-025 opt-in model; ADR-026 Decision 6 §Step 2) — `resolve_identity` is NOT invoked, no `exec_subprocess` call is made; **case 1 (Malformed)** `holder` non-empty but `expires_at` present and unparseable (malformed) → **`Err(LockError::Malformed(msg))`** (F-001: a distinct `Err` return, NOT a `NoOp`/`SkipReason` value — `SkipReason` has no `Malformed` variant) — `resolve_identity` is NOT invoked; the plugin, as caller, downgrades this `Err` to an advisory `host::log_warn` and the flush proceeds unblocked, with no write to `expires_at`; **case 2 (AlreadyExpired)** `holder` non-empty, `expires_at` parseable, but ALREADY EXPIRED (`now >= expires_at`) → `Ok((RenewOutcome::NoOp, Some(SkipReason::AlreadyExpired)))` — `resolve_identity` is NOT invoked; an already-expired lock is never resurrected by this plugin, consistent with `verify-factory-lock` PC2 (`LockExpired`) treating an expired lock as free for any caller (BC-4.17.001 F-009 disposition, applied here for parity between the two `renew_lock_if_holder` call sites); **cases 3–5** `holder` non-empty, `expires_at` parseable, and NOT expired → `resolve_identity()` is invoked (the ONLY point at which it is invoked): **case 3 (NotHolder)** on `Resolved(email)` (trimmed through `trim_git_email`) NOT byte-equal to `holder` → `Ok((RenewOutcome::NoOp, Some(SkipReason::NotHolder)))` — the expected, correct outcome for a non-holder session; **case 4 (IdentityResolutionFailed)** on `Failed(reason)` (subprocess error, non-zero exit, timeout, or empty stdout — classified via the shared `factory_lock::classify_identity_resolution` function, F-003) → `Ok((RenewOutcome::NoOp, Some(SkipReason::IdentityResolutionFailed { reason, holder, locked_at, expires_at })))` (**F-P21-001** — struct variant, the three non-`reason` fields sourced from `lock_state.holder`/`.locked_at`/`.expires_at` already parsed at the holder-present step, no re-parse), and the plugin destructures this returned variant directly and emits `host::emit_event("factory.lock.renewal_indeterminate", &[("plugin", "precompact-flush"), ("holder", holder), ("locked_at", locked_at), ("expires_at", expires_at), ("resolution_error", reason)])` plus a `host::log_warn` (ADR-046 Decision 4), since a self-held, non-expired lock's renewal could not be confirmed one way or the other; **case 5 (Success)** on `Resolved(email)` byte-equal to `holder` → `Ok((RenewOutcome::Renewed(new_content), None))`, and the plugin natively updates `factory_lock.expires_at = now + TTL_SECONDS` (2700 seconds) in STATE.md. In every case, the `holder` and `locked_at` fields are preserved unchanged. Lock renewal failure (of any kind — mismatch, already-expired, identity-resolution-failed, or malformed) is treated as a non-fatal, non-blocking condition; the flush proceeds and attempts the commit regardless. No renewal outcome causes exit 2. (ADR-028 §Decision 2; ADR-046 §Decision 1(b)/3/4; EC-004; EC-010.)

   **Shared-classifier mandate (F-003):** the plugin MUST construct its `resolve_identity` closure by calling the shared `factory_lock::classify_identity_resolution((exit_code, stdout) -> IdentityResolution)` function on its raw `exec_subprocess` result — the SAME function BC-4.17.001's `stamp-state-timestamp` plugin calls. This function carries the load-bearing empty-stdout→`IdentityResolutionFailed` rule (aligned with BC-4.13.001 EC-009's identical classification). This plugin and BC-4.17.001's hook MUST NOT independently re-derive this `(exit_code, stdout) -> IdentityResolution` classification — this extends the existing "MUST NOT independently re-derive `renew_lock_if_holder`/`trim_git_email`" mandate (Related BCs) to this classifier as well. `factory_lock.expires_at` is output in EXACTLY `YYYY-MM-DDTHH:MM:SSZ` format (UTC, second precision, uppercase Z suffix — matches BC-5.40.001 §Invariant 2 and `factory-lock-write.sh` output format; NOT chrono rfc3339 `+00:00` form; use `chrono::Utc::now().format("%Y-%m-%dT%H:%M:%SZ").to_string()` — NOT `to_rfc3339()`). Parse outcomes from `crates/factory-lock-parse::parse_factory_lock()`: `Ok(None)` (lock absent, null, empty block, or no frontmatter in STATE.md) → skip renewal (no-op, no advisory); `Ok(Some)` (valid lock block with all three sub-fields present) → update `expires_at` to `now + 2700s`; `Err(MalformedLockBlock)` (block present but malformed — missing field, empty field, missing closing fence) → emit advisory warning to stderr + proceed (fail-open). When lock is held and renewal succeeds, the renewed STATE.md is staged in the subsequent `git -C <wt> add -A` step and therefore included in the flush commit (renewal MUST precede git add). `crates/factory-lock::renew_lock()` performs a `factory_lock:` key presence pre-check before invoking the full fence-aware parser. If `factory_lock:` is NOT present in the frontmatter region — regardless of fence shape (including malformed/unclosed fence) — `renew_lock()` returns `Ok(RenewOutcome::NoOp)` immediately: this matches bash `factory-lock-write.sh renew` behavior of silently exiting 0 when the lock key is absent (ADR-028 §Decision 9). `Err(LockError::Malformed)` is returned ONLY when `factory_lock:` IS present but the block is malformed. The hook caller treats `Err` as advisory (fail-open per §EC-004). `Ok(RenewOutcome::NoOp)` is returned both for lock-absent and for lock-key-absent-with-malformed-fence, preserving bash parity. Note (A14 — NoOp-on-identical): `renew_lock()` returns `Ok(RenewOutcome::NoOp)` in two distinct cases: (a) lock key is absent from frontmatter (pre-check returns false), and (b) lock is held but the recomputed `expires_at` is byte-identical to the existing value (same wall-clock second — ADR-028 §Decision 16). In case (b), `renew_lock()` does NOT write STATE.md; `RenewOutcome::Renewed` is returned ONLY when `expires_at` actually changes.

4. **Factory-artifacts commit**: The hook stages and commits `STATE.md` (and any other factory-artifacts files with pending changes) to the `factory-artifacts` branch with commit message: `PreCompact flush <cycle>/<step> <ISO-8601-timestamp>` where `<cycle>` and `<step>` are the `current_cycle:` and `current_step:` values read from STATE.md frontmatter (e.g., `PreCompact flush v1.0-feature-context-durability-E18/S-18.04 2026-06-14T12:00:00Z`).

5. **Exit 0 on flush success or clean state**: If the commit lands successfully, the hook exits 0. If there are no pending changes on `factory-artifacts` (clean state, nothing to flush), the hook exits 0 without creating an empty commit.

6. **Exit 2 on commit failure (block compaction — LOCAL failure only)**: If the git commit command fails (lock contention, permission error, or other local filesystem error), the hook exits 2. This signals the dispatcher to block compaction via `block_intent = true`. The hook writes a diagnostic message to stderr before exiting 2. Note: `git commit` is a purely LOCAL operation — it writes to the local git object store and does NOT involve any network communication. Network errors cannot originate from `git commit`; they belong to `git push` (PC8b). At the time of commit failure, no precompact-flush-log entry has been appended and no push has been attempted.

6b. **Exit 2 on push failure (block compaction — NETWORK/REMOTE failure)**: After the git commit succeeds and the precompact-flush-log append succeeds, the hook executes `git push` to synchronize the local commit to the remote `factory-artifacts` branch. If `git push` fails for any reason (network error, remote rejection, authentication failure), the hook exits 2. This signals the dispatcher to block compaction via `block_intent = true`. The hook writes a diagnostic message to stderr: `precompact-flush: git push failed; local commit <SHA_B> and log entry intact; retry is push-only`. The hook writes a diagnostic message to stderr before exiting 2. Note: at the time of push failure, the local commit exists on `factory-artifacts` and the precompact-flush-log entry has already been appended — these are NOT rolled back. Retry requires only a `git push` (not a re-commit).

7. **Exit 0 + warn on STATE.md unreadable**: If STATE.md is absent or unreadable, the hook exits 0 (fail-open per ADR-026 Decision 6 `on_error = "continue"` spirit). A warning is written to stderr: `precompact-flush: STATE.md unreadable; flush skipped.`

8. **precompact-flush-log append (SHA-pinned concurrent-commit guard — F-P5-002 + F-P6-006)**: After the git commit succeeds, the hook immediately captures `SHA_B=$(git -C <factory-artifacts-worktree> rev-parse HEAD)`. It then APPENDS a new line to `.factory/hooks/precompact-flush-log` (creating the file if absent) containing four space-separated fields: `<ISO-timestamp> <SHA_B> <cycle>/<step> commit` where `commit` is the literal string `commit` (the object type, pre-embedded by the shell hook — NOT the output of a live `git cat-file -t` call at validation time). **The appended line MUST be terminated by exactly one LF (`\n`), INCLUDING when it is the final line in the file.** The file therefore always ends with `\n` after every successful append. This `\n`-termination guarantee is the upstream obligation VP-090 §0 relies on for its one-entry-per-physical-line counting semantics: implementations MUST use `echo "..." >> precompact-flush-log` or equivalent (`printf "%s\n" "..."`) — NOT `printf "%s"` (which omits the trailing newline). A conforming implementation that appends without a trailing `\n` violates this postcondition even if the four-field content is otherwise correct. **Absent-log baseline (CV-003; ADR-028 §Decision 12):** If `host::read_file` on `.factory/hooks/precompact-flush-log` returns an error — including `CAPABILITY_DENIED` when the file does not yet exist (because `canonicalize()` in `read_file` fails on non-existent files) — the plugin MUST treat the error as EMPTY prior content (`""`). The new entry is concatenated to `""` and written via `host::write_file` (which supports creating new files per BC-2.02.011 EC-005). This is NOT an append failure and does NOT trigger the SHA-pinned reset guard; it is the intended first-flush behavior. The SHA-pinned reset guard fires only when `write_file` returns an error AFTER the `read_file` step (empty-baseline or not). Do NOT treat a `read_file` error on the log path as an append failure. **If the append (write_file) fails**, the hook executes the following SHA-pinned concurrent-commit guard:
   - (1) Capture `SHA_B` immediately after `git commit` (this capture MUST happen BEFORE the append attempt so SHA_B is available on failure).
   - (2) Compare `CURRENT_HEAD=$(git -C <worktree> rev-parse HEAD)` to `SHA_B`.
   - (3a) **If CURRENT_HEAD == SHA_B** (no concurrent commit landed): execute `git -C <factory-artifacts-worktree> reset --soft SHA_B^` (SHA-PINNED to `SHA_B^`, NOT `HEAD~1` — rationale: `HEAD~1` is a relative reference that could discard a concurrent SHA_C commit if HEAD has moved; `SHA_B^` always resolves to the parent of the KNOWN flush commit regardless of any intervening commits). Write diagnostic to stderr: `precompact-flush: SHA append to precompact-flush-log failed; orphan commit reverted (SHA_B=<sha>); blocking compaction`. Exit 2.
   - (3b) **If CURRENT_HEAD != SHA_B** (a concurrent commit landed between SHA_B creation and this check): do NOT reset — resetting would discard the concurrent commit (SOUL.md Rule 4: no silent data loss). Exit 2 immediately with error message: `precompact-flush: append failed; concurrent commit advanced HEAD; SHA_B=<sha_b>; current HEAD=<current_head>; human intervention required`.
   - (4) **If the reset itself fails** (step 3a reset exits non-zero): exit 2; human intervention required.
   **Note on `--soft` staged-state behavior**: `--soft SHA_B^` restores the working tree index to the state staged for SHA_B. If STATE.md or other files changed between SHA_B creation and the reset (e.g., a concurrent state-manager turn), those changes appear as unstaged working-tree changes in the retry — they are NOT reverted. The retry commit WILL include those changes if they are re-staged. This is the correct behavior for the common case.
   The ordering is: (1) capture SHA_B immediately after `git commit`, (2) attempt append to precompact-flush-log, (3) IF append fails: compare CURRENT_HEAD to SHA_B — if equal: `reset --soft SHA_B^` then exit 2; if not equal: exit 2 with human-intervention message (do NOT reset), (4) IF append succeeds: execute `git push` to remote, (5) IF push fails: exit 2 with `precompact-flush: git push failed; local commit <SHA_B> and log entry intact; retry is push-only`, (6) IF push succeeds: exit 0. Prior log lines are retained as history; only the last line is authoritative. The ONLY exit codes this hook ever produces are 0 (success, no-op, or STATE.md-unreadable fail-open) and 2 (git commit failure (LOCAL) OR append-failure-after-SHA-pinned-reset OR concurrent-commit-guard-triggered OR git push failure (NETWORK)). Exit 1 is not used.

9. **Hook crash — on_error = "continue"**: If the hook script crashes before emitting an exit code (set -euo pipefail failure, WASM sandbox error), the dispatcher's `on_error = "continue"` setting treats the crash as exit 0. Compaction proceeds. The crash is logged to the dispatcher internal log with `plugin.crashed`.

## Invariants

1. **Hermetic invariant**: The hook reads ONLY from (a) `STATE.md` on the filesystem, and (b) `git` commands. It MUST NOT read from: environment variables set by the LLM, `custom_instructions`, in-context tool call results, or any other session-state mechanism. This closes the anti-deadlock invariant (F1 regression risk §4.1 R1).

2. **`custom_instructions` exclusion is absolute**: Any implementation of `precompact-flush` (whether shell or native WASM) that reads `$CUSTOM_INSTRUCTIONS` or invokes any harness API to retrieve session context is a specification violation, regardless of fallback behavior.

3. **Native lock renewal is conditional and identity-gated (amended 2026-08-25; return-contract corrected 2026-08-26, ADR-046 §Decision 1(b)/3); full execution order is canonical**: `renew_lock_if_holder` itself — not a caller-side pre-check — decides, internally, whether `factory_lock:` is absent, `factory_lock.holder` is absent/null/empty-string, `expires_at` is malformed, or `expires_at` is already expired; in every one of those cases the renewal step is skipped WITHOUT any `exec_subprocess` identity-resolution call (`resolve_identity` is not invoked). Only if `holder` is non-empty, `expires_at` is parseable, and NOT expired does `renew_lock_if_holder` invoke the plugin's `resolve_identity` closure to decide whether to renew: on a match (post-`trim_git_email`), renewal proceeds; on a mismatch, or a resolution failure, renewal is skipped (see step 3's full outcome enumeration below). When renewal DOES proceed, it must occur before the git commit. The complete canonical execution order is: (1) discover factory-artifacts worktree abs-path via `git worktree list --porcelain` (the ONLY git command that does NOT use `-C`; runs against the main repo to discover the worktree path), (2) read STATE.md via host `read_file` (`.factory/`-relative path; Domain A), (3) construct the lazy `resolve_identity: FnOnce() -> IdentityResolution` closure — `|| classify_identity_resolution(host::exec_subprocess(["git","config","user.email"]))` (F-003; shared classifier, not re-derived) — WITHOUT invoking it, then invoke `crates/factory-lock::renew_lock_if_holder(state_md_content, resolve_identity, now_fn) -> Result<(RenewOutcome, Option<SkipReason>), LockError>` (F-001; ADR-046 §Decision 1(b), wrapping ADR-028 §Decision 9's existing `renew_lock` sequence): on `Err(LockError::Malformed(msg))` (the `factory_lock:` key is present but `expires_at` is unparseable — `resolve_identity` was NOT invoked for this case): emit advisory `host::log_warn`; skip step 4 (no `write_file` call); proceed to step 5; on `Ok((RenewOutcome::NoOp, Some(SkipReason::AlreadyExpired)))` (`resolve_identity` NOT invoked), `Ok((RenewOutcome::NoOp, Some(SkipReason::NotHolder)))`, or `Ok((RenewOutcome::NoOp, Some(SkipReason::IdentityResolutionFailed { reason, holder, locked_at, expires_at })))` (**F-P21-001** — struct variant, sourced from `lock_state.holder`/`.locked_at`/`.expires_at` already parsed at the holder-present step, no re-parse; on `IdentityResolutionFailed`, additionally destructure the returned variant and call `host::emit_event("factory.lock.renewal_indeterminate", &[("plugin", "precompact-flush"), ("holder", holder), ("locked_at", locked_at), ("expires_at", expires_at), ("resolution_error", reason)])` + `host::log_warn` per ADR-046 Decision 4): skip step 4 (no `write_file` call; no-op); proceed to step 5; on `Ok((RenewOutcome::Renewed(new_content), None))`: proceed to step 4 (write renewed STATE.md); on `Ok((RenewOutcome::NoOp, None))` (lock absent/holder-absent, or the existing byte-identical-suppression guard firing on a genuine `Resolved+Match`): skip step 4; proceed to step 5, (4) if `RenewOutcome::Renewed`: write updated STATE.md via host `write_file` (`.factory/`-relative path; Domain A; `new_content` from `renew_lock_if_holder`'s return value); outputs `expires_at = now + 2700s` in EXACTLY `YYYY-MM-DDTHH:MM:SSZ` format; preserves `holder` and `locked_at`; renewal MUST precede git add so the renewed `expires_at` is staged, (5) `git -C <wt> add -A` — stages ALL changes in the factory-artifacts worktree: tracked modifications, tracked deletions, AND new untracked files. This ensures that new `.factory/` files created during the session (but not yet tracked by git) are captured in the flush commit and not silently lost on compaction. IMPORTANT: if step 3 returned `Err(LockError::Malformed(..))` or `Ok((RenewOutcome::NoOp, _))` (i.e., step 4 was skipped for any reason) AND `git -C <wt> diff --cached` is empty after staging, the plugin MUST apply INV5 (exit 0; do NOT create an empty commit); the empty-commit guard is evaluated after git add using post-add staging state, not pre-renewal staging state, (6) `git -C <wt> commit -m "PreCompact flush <cycle>/<step> <ISO-timestamp>"` (LOCAL — no network), (7) capture `SHA_B=$(git -C <wt> rev-parse HEAD)` IMMEDIATELY after commit (MUST precede append attempt), (8) attempt append to precompact-flush-log via host `read_file` + string concat + host `write_file` (read-modify-write; `.factory/`-relative path; Domain A) — the appended line MUST be terminated by exactly one LF (`\n`), INCLUDING when it is the final line in the file (use `echo "..." >>` or `printf "%s\n" "..."` — NOT `printf "%s"`; omitting the trailing `\n` violates PC8's newline-termination guarantee and VP-090 §0's structural precondition), (9) IF append fails: `CURRENT_HEAD=$(git -C <wt> rev-parse HEAD)` — if equal to SHA_B: `git -C <wt> reset --soft SHA_B^` (SHA-PINNED), write diagnostic, exit 2; if not equal: exit 2 with human-intervention message (do NOT reset), (10) IF append succeeds: `git -C <wt> push origin factory-artifacts` (NETWORK), (11) IF push fails: exit 2 with diagnostic `precompact-flush: git push failed; local commit <SHA_B> and log entry intact; retry is push-only`; IF push succeeds: exit 0. No step may be reordered. In particular, SHA_B capture (step 7) MUST precede the append attempt (step 8); the append (step 8) MUST precede the push (step 10); the concurrent-commit check MUST precede any reset; and any reset MUST precede exit 2 in the equal-HEAD case. The push (step 10) is NOT attempted if append fails (step 9 exits 2 before reaching step 10). ALL git subprocesses in steps 5–11 MUST use `git -C <wt>` where `<wt>` is the absolute worktree path discovered in step 1. Bare `git add`, `git commit`, `git push`, `git rev-parse`, `git reset` commands WITHOUT `-C` are FORBIDDEN (they would operate on the main repo instead of the factory-artifacts worktree, corrupting the SHA guard and committing to the wrong branch).

3a. **`renew_lock()` error semantics, RenewOutcome enum, and fail-open caller policy**: `crates/factory-lock::renew_lock()` has the binding pure signature `pub fn renew_lock(state_md_content: &str) -> Result<RenewOutcome, LockError>` (ADR-028 §Decision 9). The `RenewOutcome` enum is: `NoOp` (lock key absent or lock null — STATE.md unchanged) or `Renewed(String)` (lock was held and expires_at was updated — contains new full STATE.md content). The path-based form `renew_lock(&Path)` or `renew_lock(&factory_artifacts_path)` is STRUCK; the plugin caller owns all host I/O. `crates/factory-lock` contains NO `std::fs` calls (WASM-hermetic). `crates/factory-lock::renew_lock()` returns `Err(LockError::Malformed)` ONLY when `factory_lock:` IS present but the block is malformed (block present but missing field, empty field, missing closing fence after the key is found) — this is the library's faithful preservation of the bash `factory-lock-write.sh renew` exit-1-on-RenewalMissed semantics at the library layer. The library does NOT swallow the error or return `Ok(RenewOutcome::NoOp)` for blocks where the key IS present but malformed. The `precompact-flush` hook CALLER is the authoritative fail-open policy point: it downgrades `Err` to an advisory warning to stderr and proceeds with the flush commit. Future callers that require fatal semantics on malformed blocks may treat `Err` as fatal. When lock is held and renewal succeeds (`RenewOutcome::Renewed`), the renewed `expires_at` mutates STATE.md before `git -C <wt> add -A`; this means the flush commit is non-empty from the renewal change IF AND ONLY IF `expires_at` actually differs from the committed value (NOT a violation of INV5's empty-commit guard — see A14 NoOp-on-identical). When `RenewOutcome::NoOp`, no `write_file` call is made; the staging area is unchanged by the renewal step; INV5 must be evaluated after `git -C <wt> add -A` using `git -C <wt> diff --cached` — if staging is empty AND step 3 returned `NoOp`: exit 0 clean-state (do NOT force a commit). Note on NoOp-on-identical-expires_at (A14): `renew_lock()` returns `RenewOutcome::Renewed(content)` IFF the lock was held AND the recomputed `expires_at` string DIFFERS from the existing `expires_at` value (byte-comparison). If the recomputed value is byte-identical (same wall-clock second), the function returns `Ok(RenewOutcome::NoOp)` — no `write_file` is performed. This ensures `RenewOutcome::Renewed` is a reliable signal that STATE.md content actually changed (ADR-028 §Decision 16).

**Reconciliation with `renew_lock_if_holder` (F-001, added 2026-08-26; corrected 2026-08-26 — O-P9-001, adversarial spec review pass 9, LOW):** this Invariant describes the underlying `renew_lock()`/`renew_lock_with_now` semantics that `renew_lock_if_holder` (Invariant 3b) wraps. `renew_lock_with_now` (this Invariant, above) treats `expires_at` as an OPAQUE `String` throughout: the structural parse it delegates to (`factory_lock_parse::parse_factory_lock`) validates only that the `expires_at` sub-field is PRESENT and non-empty — never that its value is a parseable ISO-8601 datetime — and `renew_lock_with_now`'s own byte-identical-suppression guard (`new_expires_at == lock_state.expires_at`) is a plain string comparison that never parses the existing `expires_at` value either. `renew_lock_with_now`'s `Err(LockError::Malformed)` therefore fires ONLY for STRUCTURAL defects the underlying parser detects (missing field, empty field, missing closing fence) — NEVER for a structurally-present-but-date-unparseable `expires_at` (confirmed by inspection of `crates/factory-lock/src/lib.rs`'s `renew_lock_with_now` and `crates/factory-lock-parse/src/lib.rs`'s `parse_factory_lock`).

`renew_lock_if_holder`'s case 1 (`Malformed` — `expires_at` present but unparseable, Invariant 3 step 1; Invariant 3b) and case 2 (`AlreadyExpired` — `now >= expires_at`) BOTH require a NEW ISO-8601 parse step — `renew_lock_if_holder` MUST call the canonical `factory_lock_parse::parse_iso8601` directly (no independent re-derivation of ISO-8601 parsing logic) — layered ABOVE `renew_lock_with_now`'s unchanged structural-parse-then-byte-compare sequence — neither case is reachable at the wrapped `renew_lock_with_now` layer today. (Grounding correction, F-P13-002, LOW, adversarial spec review pass 13: the prior text additionally claimed this is "the same parser `verify-factory-lock` already uses for its own expiry check," attributing call-site identity between the two. Ground truth (`crates/hook-plugins/verify-factory-lock/src/lib.rs`): `verify-factory-lock`'s own expiry check calls a LOCALLY-DEFINED `pub fn parse_iso8601(s: &str) -> Result<DateTime<Utc>, LockCheckError>` — a distinctly-typed function, not `factory_lock_parse::parse_iso8601` itself — which happens to internally delegate its parsing to `factory_lock_parse::parse_iso8601` (via the `flp` alias) before remapping the error type. So `verify-factory-lock` and `renew_lock_if_holder` are not calling the identical function at their respective call sites today, even though `verify-factory-lock`'s local wrapper currently forwards to the same canonical parser under the hood. Consolidating both call sites onto one shared parse call is a candidate future cleanup, not a currently-true attribution — not asserted as load-bearing here.) Consequently, `renew_lock_if_holder`'s case-1 `Err(LockError::Malformed(msg))` is NOT propagated verbatim from a `renew_lock_with_now` call: it is RE-DERIVED at the `renew_lock_if_holder` layer by this new `parse_iso8601` check. What IS preserved verbatim is the error TYPE — `LockError::Malformed`, not downgraded to a `SkipReason` variant (`SkipReason` has no `Malformed` case) — while the TRIGGERING CONDITION is new (ISO-8601 unparseability of a present `expires_at`), distinct from the field-presence/non-emptiness condition `renew_lock_with_now`'s wrapped structural parse enforces. `renew_lock_with_now`'s own structural-malformed path and its Success-case byte-identical-suppression guard (both described earlier in this Invariant) remain exactly as specified and UNCHANGED by `renew_lock_if_holder` — only the new pre-identity malformed-date and expiry checks are additions layered on top, not replacements. The `precompact-flush` hook CALLER remains the one fail-open policy point that downgrades any `Err(LockError::Malformed)` — whether it originates from a direct `renew_lock()`/`renew_lock_with_now` structural check (not reachable via this plugin's `PreCompact` renewal step, which calls `renew_lock_if_holder` exclusively — see Invariant 3) or from `renew_lock_if_holder`'s own new date-parse check (the actual call site) — to an advisory `log_warn`.

3b. **Identity gate, `SkipReason` enum, and the canonical `Err(LockError::Malformed)` case at the `precompact-flush` call site (new 2026-08-25; return-contract corrected 2026-08-26 — ADR-046 §Decision 1(b)/3/4 — Companion Amendment 3)**: `renew_lock_if_holder<F, I>(content: &str, resolve_identity: I, now_fn: F) -> Result<(RenewOutcome, Option<SkipReason>), LockError> where F: Fn() -> DateTime<Utc>, I: FnOnce() -> IdentityResolution` (F-001, pass-3 — the canonical `Result`-wrapped signature with a **lazy** `resolve_identity` closure, corrected from the pre-2026-08-26 bare-tuple, eagerly-identity-parameterized description this Invariant previously carried) is the SHARED function this plugin calls instead of `renew_lock` for its `PreCompact` renewal step (BC-4.17.001's `stamp-state-timestamp` plugin is the sibling call site — both MUST call the SAME function with the SAME signature, never independently re-derive the identity comparison). `resolve_identity` is invoked by `renew_lock_if_holder` itself, at most once, only when the decision tree reaches the identity-comparison step (cases 3–5 of the canonical five-case table below, not case 5 alone — this note corrected 2026-08-26, O-P4-002, alongside the case-numbering harmonization) — the plugin supplies the closure but never calls `exec_subprocess` eagerly or outside it. `IdentityResolution` is `Resolved(String)` (the `trim_git_email`-trimmed caller email, produced by THIS plugin's `resolve_identity` closure via the shared `factory_lock::classify_identity_resolution` classifier — pass-3 F-003, below — `crates/factory-lock` itself performs no `exec_subprocess`) or `Failed(String)` (the resolution error).

   `renew_lock_if_holder`'s canonical five-case return-value table at this call site (ADR-046 §Decision 1(b); IDENTICAL to BC-4.17.001's PC2 table — F-001, pass-3):

   | # | Condition | Return | `resolve_identity()` invoked? |
   |---|---|---|---|
   | 1 | Malformed `expires_at` (holder present) | `Err(LockError::Malformed(msg))` | No |
   | 2 | `AlreadyExpired` (holder present, `expires_at` parses, `now >= expires_at`) | `Ok((RenewOutcome::NoOp, Some(SkipReason::AlreadyExpired)))` | No |
   | 3 | `NotHolder` (not expired, resolved email ≠ holder) | `Ok((RenewOutcome::NoOp, Some(SkipReason::NotHolder)))` | Yes |
   | 4 | `IdentityResolutionFailed` (not expired, resolution failed) | `Ok((RenewOutcome::NoOp, Some(SkipReason::IdentityResolutionFailed { reason, holder, locked_at, expires_at })))` — the three non-`reason` fields are `lock_state.holder`/`.locked_at`/`.expires_at`, already parsed at the holder-present step, not re-derived (**F-P21-001**) | Yes |
   | 5 | Success (not expired, resolved email == holder) | `Ok((RenewOutcome::Renewed(new_content), None))`, or `Ok((RenewOutcome::NoOp, None))` on the same-second byte-identical guard | Yes |

   (A sixth, pre-existing, zero-th case — `holder` empty, i.e. no lock held at all — returns `Ok((RenewOutcome::NoOp, None))` without reaching any of the five numbered checks; `resolve_identity` is not invoked.)

   **`Malformed` (case 1) is a distinct `Err` return, NOT a `SkipReason` value** — `SkipReason` has only three variants at this call site (`NotHolder`, `IdentityResolutionFailed { reason: String, holder: String, locked_at: String, expires_at: String }` — struct variant, **F-P21-001**, corrected from a bare-`String` tuple variant — see below, `AlreadyExpired`); there is no `SkipReason::Malformed`. `AlreadyExpired` (case 2) is the product-owner extension per BC-4.17.001 F-009, applied here for parity between the two call sites (ADR-046 §Decision 1(b) enumerates it; see historical F-003 disposition below). `renew_lock_if_holder` evaluates the malformed check and the expiry precheck BEFORE attempting identity resolution — neither an `Err(Malformed)` nor an `AlreadyExpired` outcome ever triggers `resolve_identity()`/`exec_subprocess`, since neither outcome depends on who is asking. Only on `IdentityResolutionFailed` (case 4) — i.e., only when the malformed check and the expiry precheck have already confirmed a self-held, non-expired, well-formed lock IS present and resolution alone failed — does the plugin destructure the returned `SkipReason::IdentityResolutionFailed { reason, holder, locked_at, expires_at }` variant directly (**F-P21-001**, ADR-046 §Decision 1(b)/§Decision 4 — NOT an unbound `<lock.*>` reference, and NOT a re-parse of `.factory/STATE.md`'s `factory_lock:` block; the three lock fields are sourced from `renew_lock_if_holder`'s own independent `flp::parse_factory_lock(content)` parse result — a `LockState` (crate `factory-lock-parse`), NOT a `FactoryLock` (the distinct struct in crate `factory-lock`, produced only by `factory_lock::parse_lock` via explicit field-by-field conversion) — parsed once by `renew_lock_if_holder` itself, before its holder-present / `parse_iso8601`-malformed / already-expired / identity-match checks (**F-P25-001**, corrected 2026-08-26: this is NOT and cannot be sourced from any local internal to the wrapped `renew_lock_with_now` sequence — that binds a private local unreachable from a wrapper); the F-P21-001 single-source, no-re-parse guarantee is preserved unchanged — it continues to govern the two WASM call sites, which still never re-parse STATE.md) and call `host::emit_event("factory.lock.renewal_indeterminate", &[("plugin", "precompact-flush"), ("holder", holder), ("locked_at", locked_at), ("expires_at", expires_at), ("resolution_error", reason)])` and `host::log_warn`. On `Err(Malformed)` (case 1), the plugin instead emits an advisory `host::log_warn` with no `emit_event` call (see Invariant 3, Postcondition 3). No event is emitted for `NotHolder` or `AlreadyExpired` (these are legitimate, unambiguous skips, not failures — ADR-046 Decision 4 non-goal, unchanged).

   **Shared-classifier mandate (F-003, pass-3):** the plugin's `resolve_identity` closure MUST call the shared `factory_lock::classify_identity_resolution((exit_code, stdout) -> IdentityResolution)` function on its raw `exec_subprocess` result — the SAME function BC-4.17.001's `stamp-state-timestamp` plugin calls, carrying the load-bearing empty-stdout→`IdentityResolutionFailed` rule (aligned with BC-4.13.001 EC-009's identical classification). This plugin and BC-4.17.001's hook MUST NOT independently re-derive this classification.

   **(Historical, pass-2) F-003** — ADR-046 v1.2 §Decision 1(b) enumerates `AlreadyExpired` as this call site's third `SkipReason` variant, reconciling the ADR text with both BCs — resolved 2026-08-26.

4. **Commit message format is canonical**: The commit message MUST match the pattern `PreCompact flush <cycle>/<step> <ISO-timestamp>` exactly (with a single space between `<cycle>/<step>` and the timestamp). The subject must begin with the literal prefix `PreCompact flush ` (case-sensitive, with trailing space). This general prefix is used by `validate-burst-log` and `validate-dispatch-advance` to exempt the commit from TD-VSDD-053 `MULTI_COMMIT_CHAIN_NOT_ALLOWED` detection (BC-5.41.003).

5. **Empty commit is forbidden**: If `git diff --cached factory-artifacts` shows no changes, the hook must NOT create an empty commit. It exits 0 silently or with an info message: `precompact-flush: no pending changes; flush skipped.`

6. **Plugin error hardening**: The plugin uses idiomatic Rust error propagation (`Result<T, E>`) throughout. Unhandled errors propagate via the `?` operator. No `unwrap()` or `expect()` in non-test code paths. Panics are treated as crashes triggering `on_error = "continue"` fail-open per Postcondition 9 (consistent with BC-1.15.001 dispatcher `plugin.crashed` handling).

7. **Log pruning is DEFERRED to S-18.04b AC-N (F-P32-005)**: This BC's PC8 and Inv3 govern append-only growth of `precompact-flush-log`. ADR-026 §Crash-Consistency Design item 4 mandates a pruning step (prune to most-recent-500 entries when entry count exceeds 1000, implemented by a `precompact-flush-prune.sh` helper invoked by `check-state-health`), but explicitly defers it to S-18.04b AC-N. The v1 implementation permits UNBOUNDED append-only growth. At ~120 bytes/line (4-field format), 1000 entries ≈ 120KB — acceptable as a bridge per ADR-026 §Crash-Consistency Design item 4 rationale. This BC's append postconditions (PC8/Inv3) do NOT yet cover pruning. When S-18.04b AC-N ships, a v1.N+1 amendment will lift the pruning obligation into a new Postcondition.
