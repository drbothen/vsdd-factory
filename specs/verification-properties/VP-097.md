# VP-097: path_util::resolve_path_for_allowlist Traversal Defense — .. Sequences Cannot Resolve Outside Allowlist Prefixes

## Property Statement

`path_util::resolve_path_for_allowlist(path: &str, allowlist: &[&str]) -> Result<PathBuf, CapabilityDenied>`
MUST satisfy the traversal defense invariant:

For ANY string `path` and ANY allowlist, if `path` contains one or more `..` path components,
the rejoin algorithm CANNOT produce a resolved `PathBuf` whose canonical string representation
starts with a prefix NOT in `allowlist`. Formally:

```
∀ path: &str, ∀ allowlist: &[&str]:
  path.contains("..") →
    resolve_path_for_allowlist(path, allowlist) ∈ {
      Err(CapabilityDenied),           // traversal rejected
      Ok(p) where allowlist.iter().any(|prefix| p.starts_with(prefix))
    }
```

No `Ok` result may resolve to a path outside all declared prefixes. This closes the
path-traversal vector identified in BC-2.02.011 EC-001 and BC-2.07.001.

## Source Contract

- **BC:** BC-2.07.001 §Invariant 1 — allowlist-bounded file access; absent-but-allowlisted files return
  NOT_FOUND (-5) not CAPABILITY_DENIED (-1); traversal (`..`) rejected.
- **BC:** BC-2.02.011 §EC-001 — path traversal sequences MUST NOT escape declared
  `path_allow` prefixes; rejoin must reject or canonicalize before allowlist check.
- **ADR:** ADR-025 Decision 13 — `codes::NOT_FOUND = -5` distinguishes absent-file from
  policy-denied.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| kani-proof | cargo kani | yes — path string bounded to 64 bytes, allowlist bounded to 1 entry of 32 bytes | traversal-escape impossibility; CapabilityDenied on any path resolving outside all prefixes |

### Why Kani

The traversal defense property is a safety invariant over all possible path inputs. Kani's
bounded model checking can exhaustively verify the rejoin algorithm for all paths up to a
bounded length. This is the correct tool for a security boundary property that cannot be
falsified by random sampling alone.

## Proof Harness Skeleton

```rust
// File: crates/factory-dispatcher/src/path_util_kani.rs
#[cfg(kani)]
mod kani_proofs {
    use super::*;

    #[kani::proof]
    #[kani::unwind(16)]
    fn verify_traversal_defense() {
        // Symbolic path: up to 64 bytes (sufficient to encode "../../etc/passwd")
        let path_len: usize = kani::any();
        kani::assume(path_len <= 64);
        let path_bytes: [u8; 64] = kani::any();
        let path_str = std::str::from_utf8(&path_bytes[..path_len])
            .unwrap_or("safe-fallback");

        // Symbolic allowlist prefix (single entry, bounded to 32 bytes)
        let prefix_len: usize = kani::any();
        kani::assume(prefix_len > 0 && prefix_len <= 32);
        let prefix_bytes: [u8; 32] = kani::any();
        let prefix = std::str::from_utf8(&prefix_bytes[..prefix_len])
            .unwrap_or(".factory/");
        let allowlist = [prefix];

        // Exercise the resolver
        let result = resolve_path_for_allowlist(path_str, &allowlist);

        // Safety property: if Ok, resolved path must be within allowlist
        if let Ok(resolved) = result {
            let resolved_str = resolved.to_string_lossy();
            let within_allowlist = allowlist.iter()
                .any(|p| resolved_str.starts_with(p));
            assert!(within_allowlist,
                "TRAVERSAL ESCAPE: resolved path is not in allowlist");
        }
        // Err(CapabilityDenied) is always acceptable
    }
}
```
