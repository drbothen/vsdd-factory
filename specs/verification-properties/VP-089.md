# VP-089: postcompact-reanchor.sh Emits Re-Anchor Block From Git-Sourced STATE.md, Appends Log Entry, Makes No factory-artifacts Commits, Exits 0 on All Error Paths

## Property

The `postcompact-reanchor.sh` hook MUST satisfy four provable properties when invoked on
a PostCompact event:

### §1 Stdout Re-Anchor Block — Git-Sourced, Correct Format

The hook emits a re-anchor block to stdout in the format:

```
[PostCompact Re-anchor] context=<current_cycle>/<current_step> sha=<develop_sha>
Source: factory-artifacts STATE.md (verified at <ISO-timestamp>)
```

Where:
- `<current_cycle>` is the `current_cycle:` field from `git show factory-artifacts:.factory/STATE.md`.
- `<current_step>` is the `current_step:` field from the same source.
- `<develop_sha>` is the output of `git rev-parse origin/develop` (or `refs/remotes/origin/develop`)
  executed at hook invocation time — NOT read from `last_verified_develop_sha:` in STATE.md frontmatter.
  Rationale: `last_verified_develop_sha:` is a HANDOFF.md field (ADR-026 §Decision 2 schema), NOT a
  STATE.md frontmatter field. STATE.md frontmatter contains only `current_step:`, `current_cycle:`,
  `phase:`, and document-metadata fields. Reading a non-existent field yields empty string → `sha=UNKNOWN`
  on every real PostCompact firing (F-P1-001 phantom-field anchoring defect). Canonical source is the
  live git command. On git failure, the hook falls through to `sha=UNKNOWN` with `status=warn` (fail-open,
  DI-024 advisory; exit 0 always).
- Values are NOT read from in-context LLM knowledge, `custom_instructions`, or environment
  variables set by the LLM (BC-7.07.002 Inv2 — values sourced from factory-artifacts git, not
  in-context).
- There is no `current_wave:` field on STATE.md; the hook MUST NOT reference or emit one
  (DI-023 phantom-field prohibition applies).

- **Precondition:** PostCompact fires; `factory-artifacts` STATE.md has `current_cycle: <v>`,
  `current_step: <s>`; `git rev-parse origin/develop` returns a 40-char hex SHA `<sha>`.
- **Postcondition (PC1):** stdout contains exactly
  `[PostCompact Re-anchor] context=<v>/<s> sha=<sha>` followed by the Source line.

### §2 Log Entry Appended to Daily Log File

The hook appends a structured JSONL entry to
`.factory/logs/postcompact-reanchor-YYYY-MM-DD.jsonl` (date derived from the event
timestamp, matching the dispatcher-internal-log daily-file pattern). The entry MUST contain
fields: `event`, `current_cycle`, `current_step`, `develop_sha`, `timestamp`,
`status` ("ok" or "warn"). There is no `wave_id` field in the log entry (BC-7.07.002 PC2 —
the hook has no defined source for wave-ordinal data).

- **Precondition:** `.factory/logs/` directory exists (or hook creates it on first write).
- **Postcondition (PC2):** The daily log file gains one new JSONL line; the entry has all six
  required fields; no `wave_id` field is present; `status` is `"ok"` on the happy path.

### §3 No factory-artifacts Commits — Strictly Read-Only on Branch

The hook MUST NOT execute `git commit`, `git push`, `git add`, or any write operation
targeting `factory-artifacts`. It reads from `factory-artifacts` via `git show` but produces
no write side effects on the branch (BC-7.07.002 Inv1).

- **Postcondition (PC3):** After the hook runs, `git log --oneline factory-artifacts` has
  the same HEAD as before the hook ran. No new commit appears. No staged changes exist on
  `factory-artifacts`.
- **Anti-postcondition:** Any code path that produces a `git commit` or `git push` to
  `factory-artifacts` from this hook is a specification violation (Inv1 absolute prohibition).

### §4 Exit 0 on All Error Paths — Fail-Open Advisory

The hook MUST exit 0 on ALL error conditions, including:
- `factory-artifacts` branch unreachable or `git show` fails (EC-002).
- STATE.md present on `factory-artifacts` but `current_cycle:` or `current_step:` fields
  absent (EC-003 — emit `context=UNKNOWN`).
- `.factory/logs/` directory does not exist and cannot be created (EC-005).
- Hook script crashes (EC-004 — `on_error=continue` in hooks-registry.toml).
- Hook exit code 2 is emitted (EC-007 — PostCompact harness ignores block-intent regardless;
  implementation MUST use exit 0 on all paths).

- **Postcondition (PC4):** Under each error scenario above, the hook exits 0; stdout contains
  an advisory message (`[PostCompact Re-anchor] WARN: ...`); session continues normally.
- **Anti-postcondition:** Any non-zero exit code from this hook is a specification violation
  (PostCompact is advisory-only per DI-024; the hook is not in the CAP-032 guarantee chain).

## Invariant Classification: Safety (Best-Effort Scope Boundary)

DI-024 defines the PostCompact re-anchor as BEST-EFFORT with NO correctness guarantee.
It is NOT in the CAP-032 continuity-guarantee chain. This VP verifies that the hook faithfully
implements this design intent: it must fail open (exit 0) on all paths, never commit to
factory-artifacts, and source its values from external git state. A hook that exits non-zero
on errors or commits to factory-artifacts would violate both DI-024 and Inv1 of BC-7.07.002.

The stdout re-anchor block is the hook's sole correctness obligation: if STATE.md is readable,
the block must accurately reflect factory-artifacts STATE.md values read via `git show`, not
in-context LLM state.

## Proof Harness Skeleton (Unit Test / Bats)

```bash
# File: plugins/vsdd-factory/tests/postcompact-reanchor.bats
# Anchor: postcompact_reanchor_correctness

@test "postcompact-reanchor.sh emits re-anchor block with context from factory-artifacts STATE.md and sha from git rev-parse" {
    # Setup: factory-artifacts STATE.md with:
    #   current_cycle: v1.0-feature-context-durability-E18
    #   current_step: S-18.04
    #   (NOTE: no last_verified_develop_sha field — that is a HANDOFF.md field, not STATE.md frontmatter)
    # Setup: git remote origin/develop resolves to abc123def456abc123def456abc123def456abc1 (40-char hex)
    # Invoke: echo '{"hook_event_name":"PostCompact","session_id":"test"}' | \
    #         bash plugins/vsdd-factory/hooks/postcompact-reanchor.sh
    # Assert: stdout contains canonical re-anchor line with sha from git rev-parse origin/develop
    assert_output --partial "[PostCompact Re-anchor] context=v1.0-feature-context-durability-E18/S-18.04 sha=abc123def456"
    assert_output --partial "Source: factory-artifacts STATE.md"
    # Assert: no "current_wave" in output (phantom field must not appear)
    refute_output --partial "current_wave"
}

@test "postcompact-reanchor.sh appends JSONL log entry with correct fields, no wave_id" {
    # Invoke hook with valid STATE.md on factory-artifacts
    # Assert: daily log file has one new line
    # Assert: line is valid JSON with fields: event, current_cycle, current_step,
    #         develop_sha, timestamp, status="ok"
    # Assert: line does NOT contain "wave_id" field
    LOG_LINE=$(tail -1 "$LOG_FILE")
    echo "$LOG_LINE" | jq -e '.event' >/dev/null
    echo "$LOG_LINE" | jq -e '.current_cycle' >/dev/null
    echo "$LOG_LINE" | jq -e '.current_step' >/dev/null
    echo "$LOG_LINE" | jq -e '.develop_sha' >/dev/null
    echo "$LOG_LINE" | jq -e '.status == "ok"' >/dev/null
    refute ( echo "$LOG_LINE" | jq -e '.wave_id' >/dev/null )
}

@test "postcompact-reanchor.sh does not commit to factory-artifacts" {
    # Capture HEAD before hook runs
    HEAD_BEFORE=$(git -C "$FACTORY_ARTIFACTS_DIR" rev-parse factory-artifacts)
    # Invoke hook
    echo '{"hook_event_name":"PostCompact","session_id":"test"}' | \
        bash plugins/vsdd-factory/hooks/postcompact-reanchor.sh
    # Assert: factory-artifacts HEAD unchanged
    HEAD_AFTER=$(git -C "$FACTORY_ARTIFACTS_DIR" rev-parse factory-artifacts)
    [ "$HEAD_BEFORE" = "$HEAD_AFTER" ]
    # Assert: no staged changes on factory-artifacts
    run git -C "$FACTORY_ARTIFACTS_DIR" diff --cached --name-only
    assert_output ""
}

@test "postcompact-reanchor.sh exits 0 and emits WARN when factory-artifacts unreachable" {
    # Setup: disable git access (e.g., unset FACTORY_ARTIFACTS_DIR or chmod 000 .git)
    # Invoke hook
    echo '{"hook_event_name":"PostCompact","session_id":"test"}' | \
        FACTORY_ARTIFACTS_DIR="/nonexistent" bash plugins/vsdd-factory/hooks/postcompact-reanchor.sh
    # Assert: exit 0 (fail-open)
    assert_success
    assert_output --partial "[PostCompact Re-anchor] WARN: factory-artifacts unreachable"
}

@test "postcompact-reanchor.sh exits 0 and emits context=UNKNOWN when STATE.md fields absent" {
    # Setup: factory-artifacts STATE.md exists but has no current_cycle: or current_step:
    # Invoke hook
    echo '{"hook_event_name":"PostCompact","session_id":"test"}' | \
        bash plugins/vsdd-factory/hooks/postcompact-reanchor.sh
    # Assert: exit 0; output contains context=UNKNOWN
    assert_success
    assert_output --partial "context=UNKNOWN"
}

@test "postcompact-reanchor.sh exits 0 when log directory creation fails" {
    # Setup: .factory/logs/ does not exist; filesystem is read-only
    chmod 555 "$FACTORY_DIR/.factory"
    echo '{"hook_event_name":"PostCompact","session_id":"test"}' | \
        bash plugins/vsdd-factory/hooks/postcompact-reanchor.sh
    # Assert: exit 0 (falls back to stdout-only advisory)
    assert_success
    chmod 755 "$FACTORY_DIR/.factory"  # restore
}
```

## Feasibility Assessment

**Fully feasible as bats unit tests.** `postcompact-reanchor.sh` is a shell script with no
live-session dependency. All four properties can be verified by:

1. Setting up a controlled `factory-artifacts` git fixture with known STATE.md content.
2. Invoking `bash plugins/vsdd-factory/hooks/postcompact-reanchor.sh` directly with a
   synthetic PostCompact JSON event on stdin.
3. Asserting on stdout content (re-anchor block format), the daily JSONL log file
   (structured entry with correct fields, no `wave_id`), the `factory-artifacts` HEAD
   before/after (no commit produced), and exit code under all error scenarios.

No live Claude Code session or LLM harness is required. These are pure shell-unit tests
in the tradition of the existing `precompact-flush` and `wave-gate` bats suites.

A VP for this BC is NOT optional at F3 (per BC-7.07.002 VP Anchors rationale): the absence
of a VP for `postcompact-reanchor.sh` would leave the silent-regression risk unguarded per
DI-024's intent.
