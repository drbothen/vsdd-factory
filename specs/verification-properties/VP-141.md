# VP-141: POLICY-1 (`append_only_numbering`) Audit Scope Is Always Archive-Inclusive for a Layer-2-Sharded Artifact — An ID Whose Sole Occurrence Has Been Archived Is Never Silently Excluded From Reuse/Gap/Uniqueness Detection

## Property Statement

1. **Archive-inclusive scope invariant.** For any Layer-2-sharded artifact (the four mechanism-A
   artifacts — `decision-log.md`, `burst-log.md`, `lessons.md`, `session-checkpoints.md`), a
   POLICY-1 (`append_only_numbering`) append-only, gap, or uniqueness audit's EFFECTIVE glob scope
   is ALWAYS the archive-inclusive whole-corpus set — `<stem>*.md` (active shards + current file)
   UNION `archive/<artifact-stem>/<stem>*.md` (archived shards). It is NEVER §Postcondition 3's
   default-exclusion glob. This is the explicit, named carve-out of BC-1.18.007 §Postcondition 6
   from §Postcondition 3's general "opt-in required for `archive/`" default, justified because
   append-only-numbering integrity is inherently a whole-HISTORY property (contrast VP-122's
   §Property Statement point 1, which asserts the DEFAULT glob correctly excludes `archive/` for
   the general, current/recent-state whole-corpus validators).

2. **No-silent-exclusion detection invariant.** When a `D-NNN`/`BC`/`VP`/story-ID's SOLE prior
   occurrence has aged into `archive/<artifact-stem>/`, a subsequent write that attempts to reuse
   that same ID IS flagged as a POLICY-1 violation — never silently missed (BC-1.18.007 §EC-006 and
   its Canonical Test Vector: `D-042` present ONLY inside `archive/decision-log/decision-log.0003.md`,
   a new write reusing `D-042` → violation detected). This is the exact converse of VP-122 §EC-003,
   where a generic non-POLICY-1 whole-corpus validator correctly stays opt-in-excluded from that same
   archived shard.

3. **Dual-surface binding.** Because POLICY-1 has `lint_hook: null` in `.factory/policies.yaml`
   today (no automated WASM/native validator implements it), the archive-inclusive obligation binds
   the PRESENT agent-instruction enforcement surface — the `consistency-validator` and
   adversary-prompt agent definitions AND POLICY-1's own `verification_steps` entry in
   `.factory/policies.yaml` MUST specify archive-inclusive scanning — and binds ANY future
   automated POLICY-1 hook IDENTICALLY (that hook's design MUST inherit the archive-inclusive
   default from day one). The property holds across the present and future enforcement surface with
   no gap at the transition (BC-1.18.007 §Postcondition 6, "Present-day enforcement mechanism").

### Why integration + static-check (dual method)

POLICY-1 has `lint_hook: null` — there is no single code module whose unit test could carry the
property. The load-bearing behavior is a whole-corpus scan over a real directory tree that mixes
active and archived shards (an FS-substrate property, the integration/fixture class VP-124/VP-128
already use), so the primary leg is an integration/fixture test asserting the archived-only-ID
reuse is DETECTED per BC-1.18.007's Canonical Test Vector. The second, load-bearing-today surface is
the agent-instruction enforcement text (and, in future, a hook's scope config), which is a source/
config structural invariant best enforced by a static/compliance grep (the VP-126/VP-129/VP-134
static-check class). Both legs verify one property — archive-inclusive POLICY-1 scope — across the
present agent-level and any future automated surface (§Property Statement point 3), so they are
carried on a single VP rather than split (the primary tool for §3/§Coverage tallying is
`integration`).

    // Fixture: D-042 present ONLY inside archive/decision-log/decision-log.0003.md
    let tree = fixture_tree(
        active   = ["decision-log.0009.md", "decision-log.md"],   // no D-042 here

    let audit = policy1_uniqueness_audit(&tree, "decision-log"); // archive-inclusive scope

    let reuse = audit.check_new_write(with_id = "D-042");
    assert!(reuse.is_policy1_violation());                       // reuse flagged, not missed
}

#[test]
fn test_BC_1_18_007_PC6_scope_strictly_superset_of_default_glob() {
    let tree = fixture_with_archived_shards("decision-log");

    assert!(policy1_scope.is_superset_of(&default_scope));
