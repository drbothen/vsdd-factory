# VP-082: PreCompact Flush Commits to factory-artifacts Before Compaction Proceeds

## Property

When the Claude Code harness triggers `PreCompact` (manual `/compact` OR auto-compaction),
and `precompact-flush.sh` determines that flush is required (uncommitted state changes in
STATE.md since last flush), the hook MUST commit the current STATE.md and wave-critical
state to `factory-artifacts` BEFORE the harness compacts the context window.

Formally:
- **Precondition:** `PreCompact` event fires. Uncommitted state changes exist relative to last `precompact_flush_sha`.
- **Invariant:** The flush commit MUST land on `factory-artifacts` before the hook exits with 0 (allow) or 2 (block).
- **Postcondition A (flush required and successful):** `factory-artifacts` HEAD is advanced. An entry of the form `<ISO-timestamp> <SHA> <cycle>/<step> commit` is appended to `.factory/hooks/precompact-flush-log` BEFORE the git push (the embedded `commit` token is the `git cat-file -t` result for WASM corroboration). Hook exits 0 (allow compaction to proceed).
- **Postcondition B (flush required but commit fails):** Hook exits 2 (block compaction). Compaction is deferred. Error logged to stderr.
- **Postcondition C (no uncommitted state changes):** Hook exits 0 without committing. No-op path.
- **Postcondition D (hook crashes):** `on_error = "continue"` means compaction proceeds. Durability is best-effort on crash (ADR-026 §Decision 6).
- **Postcondition E (append failure — F-P10-003):** On failure to append to `.factory/hooks/precompact-flush-log` after a successful local commit (SHA_B): (a) if `git rev-parse HEAD == SHA_B` (no concurrent commit landed): execute `git -C <factory-artifacts-worktree> reset --soft SHA_B^` (SHA-PINNED, not `HEAD~1`) to undo the orphan local commit; then exit 2 (block compaction); (b) if `git rev-parse HEAD != SHA_B` (a concurrent commit advanced HEAD beyond SHA_B): do NOT reset; exit 2 immediately with error message `precompact-flush: append failed; concurrent commit advanced HEAD; SHA_B=<sha_b>; human intervention required`; (c) if the reset itself fails: exit 2; human intervention required. Rationale: without the SHA-pinned reset in case (a), SHA_B is a real local commit that is never logged and never pushed — on the next retry, SHA_C is committed and logged, `validate-burst-log` WASM reads the last log line (SHA_C), cannot corroborate SHA_B, and produces a false-positive `MULTI_COMMIT_CHAIN_NOT_ALLOWED` block. Per ADR-026 §F-P6-006, the SHA-pinned form `SHA_B^` always resolves to the parent of the KNOWN flush commit, regardless of any intervening commits on the ref; `HEAD~1` is forbidden because it resolves to whatever HEAD~1 is AT RESET TIME, which may be a concurrent commit if another session burst landed between SHA_B creation and the reset.

## Invariant Classification: Safety (Flush Commit Barrier)

This is a safety property. The factory's durability guarantee for intra-wave compaction
rests entirely on this hook executing its flush before the context window is replaced.
The blocking exit-2 path is the enforcement mechanism.

## Feasibility Assessment

**Feasible as bats integration test.** The `precompact-flush.sh` hook is a shell script that
reads `STATE.md` and executes git operations against `factory-artifacts`. Both are testable
with a synthetic local git setup in a bats test fixture. The `legacy-bash-adapter` dispatcher
path can be exercised by piping a synthetic `PreCompact` event JSON to the hook directly.

The lock-renewal step (factory-lock-write.sh renew) is tested by checking that `expires_at`
advances in the commit, consistent with S-17.04 AC-pattern.
