# VP-131: BC-INDEX changelog: rotate_changelog Failure Fails Loud as HookResult::Error (E-SHD-004); Frontmatter Left in Its Pre-Rotation State

## Property Statement

Mechanism B1's rotation failure path is loud and leaves no partial state — the exact symmetric
counterpart of mechanism A's seal-rename fail-loud leg (VP-120), the backfill-split preservation-gate
fail-loud leg (VP-124), and the retention missing-index fail-loud leg (VP-122). Every mechanism-A
fail-loud path (E-SHD-001 → VP-120, E-SHD-002 → VP-122, E-SHD-003 → VP-124) has a verification
property; this VP closes the parallel gap for B1's `rotate_changelog`-failure path (E-SHD-004).

1. **rotate_changelog failure is HookResult::Error, never Block, never Continue.** When the gate's
   B1 handler invokes `rotate_changelog` on an over-N `changelog:` prepend and that invocation
   itself fails (e.g., the sealed changelog-shard file cannot be written — disk full, permission
   error), the gate returns `HookResult::Error` (taxonomy `E-SHD-004`) — NOT `Block` (a normal
   successful rotation's outcome, VP-125's block-and-retry path) and NOT `Continue` (which would let
   an unrotated, over-N write proceed) (BC-1.18.009 §EC-003, §Postcondition 6).

2. **Pre-rotation state preserved; the triggering prepend is not applied.** On a `rotate_changelog`
   failure the live frontmatter `changelog:` sequence is left byte-for-byte in its pre-rotation
   state: no partial trim, no partial sealed shard treated as authoritative, and the agent's own
   pending prepend is NOT applied by the gate (the gate never prepends — VP-126) (BC-1.18.009
   §EC-003 "the frontmatter is left in its pre-rotation state", §Postcondition 6 fail-loud). This is
   the item-count-shape analogue of VP-120's "no shard-index entry is published and the canonical
   file is left in its pre-roll state."

3. **The error is specific, never generic.** The `HookResult::Error` message names the artifact and
   the failing operation (`rotate_changelog invocation failed for <artifact>: <io-error>`,
   `E-SHD-004` per `error-taxonomy.md`) — never a generic "write failed."

## Source Contract

- **BC:** BC-1.18.009 §EC-003, §Postcondition 6, §Invariant 4 (block-and-retry is the only
  successful-rotation outcome; a failed rotation is `Error`, not a silent `Continue`).
- **Error taxonomy:** `E-SHD-004` (`rotate_changelog invocation failed for <artifact>: <io-error>`)
  per `.factory/specs/prd-supplements/error-taxonomy.md` §Error Catalog (Shard management errors).
- **SDK:** `crates/hook-sdk/src/result.rs` `HookResult` (Continue/Block/Error three-variant
  contract — the same structural fact BC-1.18.009 §Postcondition 6 cites).

### Why unit-test

The failure path is a single injected error condition on a pure, deterministic handler branch — a
hand-crafted table over {rotate succeeds → Block (VP-125's path), rotate fails → Error} gives
exhaustive coverage of the fail-loud branch with no value space a generator would broaden. This
matches VP-120's unit-test rationale for the symmetric mechanism-A seal-rename fail-loud leg exactly
(single injected FS error, deterministic branch).

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/shard_b1_rotate_failure_test.rs
// VP-131: BC-1.18.009 EC-003 / PC6 — rotate_changelog failure fails loud (E-SHD-004)

#[test]
fn test_BC_1_18_009_EC003_rotate_changelog_failure_is_error_not_block_or_continue() {
    let fs = MockFs::failing_changelog_shard_write();      // disk-full / permission on sealed shard
    let r = shard_manager::b1_handle_changelog_overflow("BC-INDEX", &fs);
    assert!(matches!(r, HookResult::Error { .. }));        // E-SHD-004, fail-loud
    // never a successful-rotation Block, never a silent over-N Continue:
    assert!(!matches!(r, HookResult::Block { .. } | HookResult::Continue));
    if let HookResult::Error { message } = r {
        assert!(message.contains("rotate_changelog") && message.contains("BC-INDEX"));
    }
}

#[test]
fn test_BC_1_18_009_EC003_frontmatter_left_in_pre_rotation_state_on_failure() {
    let fs = MockFs::failing_changelog_shard_write();
    let before = fs.read_frontmatter_changelog("BC-INDEX");
    let _ = shard_manager::b1_handle_changelog_overflow("BC-INDEX", &fs);
    assert_eq!(fs.read_frontmatter_changelog("BC-INDEX"), before);  // byte-for-byte pre-rotation
    assert!(fs.no_sealed_changelog_shard_promoted());              // no partial shard authoritative
}
```
