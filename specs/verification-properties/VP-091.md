# VP-091: validate-heavy-op-delegation Emits DelegationRecommended Advisory on Pattern-Matching Bash Commands and Returns Continue in All Cases (Never Blocks)

## Property

The `validate-heavy-op-delegation` WASM gate MUST satisfy five provable properties when invoked via the factory-dispatcher on a PreToolUse Bash tool call event.

### §0 Structural Precondition — Pure-Parse WASM Gate, No Side Effects

**This precondition is load-bearing for all §1–§4 property semantics.**

The gate is a native WASM plugin registered in `hooks-registry.toml` as:

```toml
[[hooks]]
name = "validate-heavy-op-delegation"
event = "PreToolUse"
plugin = "hook-plugins/validate-heavy-op-delegation.wasm"
tool = "Bash"
on_error = "continue"
async = false
timeout_ms = 5000

[hooks.config]
patterns = [
  "cargo test --release",
  "grep -r",
  "grep -R",
  "find . -name",
  "find . -type",
  "./run-all.sh",
  "./run-bats.sh"
]
```

The gate reads ONLY the `command` field from the PreToolUse payload. It performs NO git subprocess invocation, NO filesystem reads, NO context-window reads, and NO network calls. Pattern matching is substring containment (case-sensitive; first-match semantics). This precondition is guaranteed by BC-4.15.001 Invariant 1 (pure-parse; no filesystem, subprocess, or context access) and ADR-026 §Decision 8 (WASM for pure-function command-string matching; no side effects).

### §1 Never Blocks — Always Returns Continue (Inv2)

**The gate MUST return `block_intent = false` (Continue) under ALL conditions** — pattern match, no match, and crash (fail-open via `on_error = "continue"`).

Per BC-4.15.001 Invariant 2: setting `block_intent = true` or returning any non-Continue result from within the gate's own non-crash logic is a specification violation. The advisory mode is the complete behavioral specification for v1; promotion to blocking requires a separate BC amendment (§Future Mode in BC-4.15.001 is non-normative).

- **Precondition:** Any valid PreToolUse Bash payload; any configured pattern list (including empty).
- **Postcondition (PC1):** The dispatcher returns Continue to the harness. `block_intent` is false. The Bash tool call is not blocked. Exit code 0 or 2 from the gate's WASM body does not matter — the harness evaluates `block_intent`, not exit code, for blocking semantics. The `on_error = "continue"` field independently guarantees fail-open on crash.

**Machine-stable assertion target (per L-F2-machine-stable-count-assertion):** The Continue verdict is asserted by inspecting the dispatcher's response field (`block_intent = false`) in the PostToolUse event JSON, not by parsing human-readable output. The bats harness checks the exit code of the factory-dispatcher process invocation (exit 0 = Continue delivered to harness; the test fixture must confirm no block was registered in the dispatcher trace).

### §2 Pattern Match → Dual-Channel DelegationRecommended Advisory (PC-B)

When the Bash command string matches at least one configured pattern (first-match semantics; substring containment; case-sensitive), the gate MUST emit BOTH:

**(B-1) stderr emission:** A human/LLM-visible nudge message to stderr. The message MUST convey the matched pattern, a `command_preview` of ≤120 characters (truncated with `…` / U+2026 if command > 120 chars), and the delegation recommendation. The gate MUST NOT write to stdout (stdout is the dispatcher's tool-result channel).

**(B-2) plugin.log structured record:** A structured advisory record emitted to the dispatcher's `plugin.log` channel with fields:
- `level: warn`
- `code: DelegationRecommended`
- `matched_pattern`: the exact first-matching pattern string
- `command_preview`: first ≤120 characters of the command string (truncated with `…` if longer)
- `message`: human-readable delegation recommendation

Both emissions (B-1 and B-2) are REQUIRED on a pattern match. Emitting to only one channel is a BC-4.15.001 specification violation (PC-B both-required clause).

Per BC-4.15.001 Invariant 3 (first-match; deterministic): only ONE `DelegationRecommended` advisory is emitted per invocation, regardless of how many patterns would match.

**Machine-stable assertion target:** The `plugin.log` structured record (B-2) is the machine-stable signal for test harnesses — the structured record with `code: DelegationRecommended` and `matched_pattern: "<pattern>"` is asserted against the dispatcher's internal log output. Stderr (B-1) is asserted by capturing the dispatcher's stderr file descriptor and verifying it contains the canonical `command_preview` value. This follows L-F2-machine-stable-count-assertion: the count of `DelegationRecommended` records in `plugin.log` (exactly 1) is the deterministic assertion, not a presentation-coupled regex over human-readable stderr.

- **Precondition:** Bash command matches at least one configured pattern.
- **Postcondition (PC2):** Exactly one `DelegationRecommended` record appears in `plugin.log` for this invocation; stderr contains the matched-pattern nudge. Gate returns Continue.

### §3 No Match → No Advisory Emitted (PC-A)

When the Bash command string does NOT match any configured pattern (after exhausting the full list), the gate returns Continue immediately with NO stderr emission and NO `plugin.log` record.

Per BC-4.15.001 PC-A: the absence of any emission is a load-bearing postcondition, not merely an omission. A gate that emits a spurious advisory on no-match is a specification violation.

- **Precondition:** Bash command does not match any pattern in the configured list.
- **Postcondition (PC3):** No `DelegationRecommended` record in `plugin.log` for this invocation. Stderr from the gate is empty (or contains only pre-invocation output, not any advisory nudge for this command). Gate returns Continue.

### §4 Non-Bash Tool Call → No-Op (PC-D)

The registry `tool = "Bash"` filter prevents the dispatcher from invoking this plugin on non-Bash tool calls. From the gate's perspective, any non-Bash PreToolUse event is a no-op: the dispatcher does not dispatch the plugin, Continue is the effective result, and no emission occurs.

Per BC-4.15.001 PC-D: this is a correct-by-registration property, verifiable by confirming the dispatcher does not invoke the plugin on a Write, Edit, or Read tool PreToolUse event.

- **Postcondition (PC4):** For a Write, Edit, or Read PreToolUse payload, the factory-dispatcher does NOT invoke `hook-plugins/validate-heavy-op-delegation.wasm`. No `DelegationRecommended` record in `plugin.log`. Effective Continue.

### §5 command_preview ≤120-Character Truncation Is Invariant (Inv4)

The `command_preview` field in BOTH the stderr message (§2 B-1) and the `plugin.log` record (§2 B-2) MUST be truncated to ≤120 characters. If the full command string is ≤120 characters, the preview equals the full command string. If the full command string exceeds 120 characters, the preview is the first 120 characters followed by `…` (U+2026), yielding a 121-character field (120 chars + 1 Unicode code point).

Per BC-4.15.001 Invariant 4: truncation is applied identically in both emission channels. A preview that differs between B-1 and B-2 is a specification violation.

- **Precondition:** Bash command string is >120 characters and matches a pattern.
- **Postcondition (PC5):** `command_preview` in `plugin.log` is exactly `<first-120-chars>…`. Stderr nudge message carries the same 121-character preview. Gate returns Continue.

## Invariant Classification: Behavioral-Invariant (Advisory Mode; SS-04 Pure-Parse WASM)

DI-020 is cited because this gate is a PREVENTIVE-ADVISORY measure that reduces the probability of context-window saturation triggering an uncoordinated mid-wave compaction event — the DI-020 wave/phase boundary transition state-loss failure class. By nudging agents away from heavy Bash operations (large cargo test runs, recursive grep traversals, full bats suites) in the primary orchestrator context, the gate reduces context-window pressure that would otherwise risk violating DI-020. The gate is NOT a direct enforcer of DI-020 (it never blocks), but supports the DI-020 invariant as a preventive-advisory per OQ-4.4 (ADR-026 §Decision 12 rationale).

The never-blocks guarantee (§1 / BC-4.15.001 Invariant 2) is the most critical property: a VP that does not verify the always-Continue invariant under all conditions (including crash, empty pattern list, and concurrent-command scenarios) would leave a silent regression risk open. If this gate began blocking in any code path without an explicit BC amendment, it would be an unauthorized behavioral change.

## Proof Harness Skeleton (Unit Test / Bats)

```bash
# File: plugins/vsdd-factory/tests/validate-heavy-op-delegation.bats
# Anchor: validate_heavy_op_delegation_invariants
# Proof method: unit-test via factory-dispatcher WASM invocation (dispatcher pipes synthetic
# PreToolUse event JSON to validate-heavy-op-delegation.wasm; asserts on dispatcher output)

# Helper: emit a synthetic PreToolUse Bash event JSON
make_bash_event() {
    local cmd="$1"
    printf '{"hook_event_name":"PreToolUse","tool_name":"Bash","tool_input":{"command":"%s"},"session_id":"test-vp091"}' \
        "$(printf '%s' "$cmd" | sed 's/"/\\"/g')"
}

@test "validate-heavy-op-delegation returns Continue on pattern match (cargo test --release)" {
    # Setup: default pattern list includes "cargo test --release"
    # Invoke: pipe synthetic PreToolUse Bash event to factory-dispatcher
    run bash -c 'make_bash_event "cargo test --release --workspace" | \
        ./"$DISPATCHER_BIN" 2>"$STDERR_FILE"'
    # Assert: dispatcher does not block (exit 0 = Continue delivered)
    [ "$status" -eq 0 ]
    # Assert: plugin.log contains exactly one DelegationRecommended record for this invocation
    DELEGATION_COUNT=$(grep -c '"code":"DelegationRecommended"' "$PLUGIN_LOG_FILE" || true)
    [ "$DELEGATION_COUNT" -eq 1 ]
    # Assert: matched_pattern is "cargo test --release" (first match)
    grep -q '"matched_pattern":"cargo test --release"' "$PLUGIN_LOG_FILE"
    # Assert: command_preview is present and does not exceed 120 chars (Inv4)
    PREVIEW=$(grep '"code":"DelegationRecommended"' "$PLUGIN_LOG_FILE" | \
        python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('command_preview',''))" 2>/dev/null || true)
    [ "${#PREVIEW}" -le 121 ]  # ≤120 chars + optional U+2026 ellipsis
    # Assert: stderr contains nudge message (B-1 emission)
    grep -q "cargo test --release" "$STDERR_FILE"
}

@test "validate-heavy-op-delegation returns Continue with no advisory on no-match (cargo fmt)" {
    # Command does not match any default pattern
    run bash -c 'make_bash_event "cargo fmt --check --all" | \
        ./"$DISPATCHER_BIN" 2>"$STDERR_FILE"'
    # Assert: dispatcher does not block
    [ "$status" -eq 0 ]
    # Assert: no DelegationRecommended in plugin.log for this invocation
    DELEGATION_COUNT=$(grep -c '"code":"DelegationRecommended"' "$PLUGIN_LOG_FILE" || true)
    [ "$DELEGATION_COUNT" -eq 0 ]
    # Assert: stderr advisory is empty (no nudge emitted on no-match)
    STDERR_CONTENT=$(cat "$STDERR_FILE")
    [ -z "$STDERR_CONTENT" ] || ! echo "$STDERR_CONTENT" | grep -q "DelegationRecommended"
}

@test "validate-heavy-op-delegation emits exactly one advisory on multi-pattern match (first-match semantics, Inv3)" {
    # Command matches both "grep -r" and would match a hypothetical second grep variant if present
    # First-match semantics: only "grep -r" triggers the advisory
    run bash -c 'make_bash_event "grep -r TODO . | grep -R FIXME" | \
        ./"$DISPATCHER_BIN" 2>"$PLUGIN_LOG_FILE_ERR"'
    [ "$status" -eq 0 ]
    # Assert: exactly one DelegationRecommended record (Inv3: single advisory per invocation)
    DELEGATION_COUNT=$(grep -c '"code":"DelegationRecommended"' "$PLUGIN_LOG_FILE" || true)
    [ "$DELEGATION_COUNT" -eq 1 ]
    # Assert: matched_pattern is "grep -r" (first match in pattern list order)
    grep -q '"matched_pattern":"grep -r"' "$PLUGIN_LOG_FILE"
}

@test "validate-heavy-op-delegation truncates command_preview to 120 chars + ellipsis on long command (Inv4)" {
    # Setup: construct a 200-character Bash command containing "grep -r"
    LONG_CMD="grep -r TODO $(printf '%0.s-' {1..190})"
    # Verify fixture is >120 chars
    [ "${#LONG_CMD}" -gt 120 ]
    run bash -c 'make_bash_event "'"$LONG_CMD"'" | ./"$DISPATCHER_BIN" 2>"$STDERR_FILE"'
    [ "$status" -eq 0 ]
    # Assert: plugin.log command_preview is exactly 121 chars (120 + U+2026 ellipsis code point)
    PREVIEW=$(grep '"code":"DelegationRecommended"' "$PLUGIN_LOG_FILE" | \
        python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('command_preview',''))" 2>/dev/null || true)
    # The ellipsis character U+2026 is 3 bytes in UTF-8 but 1 code point; wc -m counts code points
    PREVIEW_CODEPOINTS=$(printf '%s' "$PREVIEW" | wc -m)
    [ "$PREVIEW_CODEPOINTS" -eq 121 ]
    # Assert: preview ends with U+2026 ellipsis
    LAST_CHAR=$(printf '%s' "$PREVIEW" | python3 -c "import sys; s=sys.stdin.read(); print(s[-1])")
    [ "$LAST_CHAR" = "…" ]
}

@test "validate-heavy-op-delegation is not dispatched on non-Bash tool call (PC-D)" {
    # Setup: synthetic PreToolUse Write event (not Bash)
    WRITE_EVENT='{"hook_event_name":"PreToolUse","tool_name":"Write","tool_input":{"file_path":"/tmp/test.md","content":"test"},"session_id":"test-vp091"}'
    run bash -c 'printf "%s" "$WRITE_EVENT" | ./"$DISPATCHER_BIN" 2>"$STDERR_FILE"'
    [ "$status" -eq 0 ]
    # Assert: no DelegationRecommended in plugin.log (tool filter excludes Write)
    DELEGATION_COUNT=$(grep -c '"code":"DelegationRecommended"' "$PLUGIN_LOG_FILE" || true)
    [ "$DELEGATION_COUNT" -eq 0 ]
    # Assert: no advisory in stderr
    ! grep -q "DelegationRecommended" "$STDERR_FILE" 2>/dev/null || true
}
```

## Feasibility Assessment

**Fully feasible as bats unit tests via factory-dispatcher invocation.** `validate-heavy-op-delegation.wasm` is a native WASM plugin invoked by the factory-dispatcher on PreToolUse Bash events. All five properties can be verified by:

1. Constructing synthetic PreToolUse event JSON objects with controlled `command` field values.
2. Piping them to the factory-dispatcher binary (`$DISPATCHER_BIN`), which loads the WASM plugin via the hook registry.
3. Asserting on: (a) dispatcher exit code 0 (Continue — no block), (b) the structured `plugin.log` record count and field values (machine-stable signal for B-2 advisory presence), (c) stderr content (B-1 advisory presence), and (d) `plugin.log` record absence on no-match and non-Bash events.

The test assertions for §1 (always-Continue) and §3 (no advisory on no-match) use machine-stable signals: the dispatcher exit code and the structured `plugin.log` `code: DelegationRecommended` field, respectively. This follows L-F2-machine-stable-count-assertion: count assertions target structured plugin.log records (a deterministic JSON field), not presentation-coupled regex over human-readable stderr.

No live Claude Code session or LLM harness is required. These are pure dispatcher-level invocation tests, consistent with the existing bats test suites for sibling WASM gates (`validate-wave-handoff-completeness`, `validate-burst-log`).

**Precondition for test execution:** `hook-plugins/validate-heavy-op-delegation.wasm` must exist at the path declared in `hooks-registry.toml`. This is the S-18.06 deliverable (the WASM crate + registry entry). The bats tests serve as acceptance tests for S-18.06.
