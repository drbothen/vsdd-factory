# VP-088: rehydrate-wave Reads wave-state.yaml From Git (Not Working Tree), Injects Exactly Listed Specs, Blocks on Missing Manifest, No RAG Fallback

## Property

The `rehydrate-wave` skill MUST satisfy four provable properties:

### §1 Git-Sourced Manifest — No Working-Tree Fallback

`wave-state.yaml` is read exclusively from `factory-artifacts` via
`git show factory-artifacts:wave-state.yaml` (or equivalent git-read command). The skill
MUST NOT read from:
- The working-tree path `.factory/wave-state.yaml` (even if that file exists and differs
  from the branch version).
- In-context LLM memory or session state.
- A locally cached copy that may be stale.

- **Precondition:** `wave-state.yaml` exists on `factory-artifacts` branch; a different (stale)
  copy exists at `.factory/wave-state.yaml` in the working tree.
- **Postcondition (PC1):** The skill uses the content from `git show factory-artifacts:wave-state.yaml`.
  The stale working-tree copy is ignored. The injected file set reflects the branch version.
- **Test approach:** Provide mismatched content (branch version = stories: [S-18.02], working-tree
  = stories: [S-18.99]); assert that the injected context matches the branch version.

### §2 Exact-List Injection Semantics

The set of injected files is EXACTLY:

```
Set(stories[*].spec_files) UNION Set(arch_files) UNION {state_pointer}
```

Neither a subset nor a superset of this set is acceptable (BC-6.24.001 Inv2).

- **Precondition:** `wave-state.yaml` specifies `stories: [{id: S-18.02, spec_files: [A.md, B.md]}]`,
  `arch_files: [C.md, D.md, E.md]`, `state_pointer: ".factory/STATE.md"`.
- **Postcondition (PC2):** Exactly 6 files are injected: A.md, B.md (story spec_files),
  C.md, D.md, E.md (arch_files), and .factory/STATE.md (state_pointer). The skill emits a
  human-readable summary listing all injected files before pausing for confirmation.
  No additional files from prior waves or the broader spec corpus are included.

### §3 Hard Block on Missing Manifest — RehydrationError

When `wave-state.yaml` does not exist on `factory-artifacts`, the skill MUST hard-block
with a clear error. No injection occurs. No RAG fallback is attempted.

- **Precondition:** `factory-artifacts` branch does NOT contain `wave-state.yaml`.
- **Postcondition (PC3):** Skill emits: `RehydrationError: wave-state.yaml not found on
  factory-artifacts; cannot rehydrate. Run /wave-handoff on wave N to produce the manifest.`
  No files are injected. Exit is non-zero (error condition).
- **Anti-postcondition:** The skill MUST NOT fall back to semantic retrieval, RAG, or
  guessing spec files from the repository. Any fallback path that injects files without a
  manifest is a specification violation (BC-6.24.001 Inv3, ADR-026 §Decision 4).

### §4 EPIC-COMPLETE Path — Reads HANDOFF.md, Not wave-state.yaml

When the final wave has completed (EPIC-COMPLETE), `wave-handoff` writes `HANDOFF.md` with
`epic_status: complete` and does NOT write `wave-state.yaml`. When `rehydrate-wave` detects
this condition, it MUST:
- Read `HANDOFF.md` (not `wave-state.yaml`) for context.
- Detect `epic_status: complete` in `HANDOFF.md`.
- Inject `STATE.md` + `arch_files` from `HANDOFF.md` only.
- Emit message: "Epic complete — no next-wave stories".
- NOT error on the absence of `wave-state.yaml`.

- **Precondition:** `factory-artifacts` has no `wave-state.yaml`; `HANDOFF.md` has
  `epic_status: complete` and `next_wave_stories: []`.
- **Postcondition (PC4):** Skill detects EPIC-COMPLETE; injects STATE.md + arch_files from
  HANDOFF.md; emits "Epic complete" message; does not raise RehydrationError.

## Why This VP Is Safety-Critical

BC-6.24.001 Inv1 mandates that the manifest is always git-sourced. A working-tree fallback
would allow a stale in-memory or locally-edited copy to contaminate rehydration context —
precisely the fabricated-state failure class that CAP-032 and DI-023 exist to prevent. Inv2
mandates exact-list semantics: a superset injection loads prior-wave BCs into context
(context pollution); a subset injection drops required BCs (incomplete context). The
RehydrationError on missing manifest (§3) is the production-grade fail-loud mechanism that
prevents silent operation in a degraded state — a RAG fallback would hide the fact that the
wave-handoff skill was never run.

## Proof Harness Skeleton (Integration — Bats + Manual Session Test)

```bash
# File: plugins/vsdd-factory/tests/rehydrate-wave-bats.bats
# Anchor: rehydrate_wave_git_source_and_exact_list

@test "rehydrate-wave reads wave-state.yaml from factory-artifacts not working tree" {
    # Setup: factory-artifacts:wave-state.yaml has stories: [{id: S-18.02, spec_files: [real.md]}]
    # Setup: .factory/wave-state.yaml (working tree) has stories: [{id: S-18.STALE, ...}]
    # Invoke: run_rehydrate_wave_skill
    # Assert: output lists real.md (branch version); does not list S-18.STALE (working tree)
    assert_output --partial "real.md"
    refute_output --partial "S-18.STALE"
}

@test "rehydrate-wave injects exactly union of stories[*].spec_files + arch_files + state_pointer" {
    # Setup: wave-state.yaml: stories=[{id:S-18.02, spec_files:[A.md, B.md]}],
    #        arch_files:[C.md, D.md, E.md], state_pointer:".factory/STATE.md"
    # Invoke: run_rehydrate_wave_skill
    # Assert: injected file count = 6 (A.md + B.md + C.md + D.md + E.md + STATE.md)
    # Assert: each file listed in output; confirmation prompt shown
    INJECTED_COUNT=$(skill_output | grep -c "^  - ")
    [ "$INJECTED_COUNT" -eq 6 ]
    assert_output --partial ".factory/STATE.md"
    assert_output --partial "Confirm rehydration"  # operator confirmation prompt
}

@test "rehydrate-wave hard-blocks with RehydrationError when wave-state.yaml missing" {
    # Setup: factory-artifacts branch has no wave-state.yaml; no HANDOFF.md with epic_status
    # Invoke: run_rehydrate_wave_skill
    # Assert: error output contains "RehydrationError: wave-state.yaml not found on factory-artifacts"
    # Assert: no files injected
    assert_failure
    assert_output --partial "RehydrationError: wave-state.yaml not found on factory-artifacts"
}

@test "rehydrate-wave handles EPIC-COMPLETE by reading HANDOFF.md not wave-state.yaml" {
    # Setup: factory-artifacts has no wave-state.yaml;
    #        HANDOFF.md has epic_status: complete, next_wave_stories: [], arch_files: [C.md]
    # Invoke: run_rehydrate_wave_skill
    # Assert: exit 0; output contains "Epic complete — no next-wave stories"
    # Assert: STATE.md + C.md injected; no RehydrationError
    assert_success
    assert_output --partial "Epic complete — no next-wave stories"
    assert_output --partial ".factory/STATE.md"
    assert_output --partial "C.md"
}
```

**Note on context-injection presentation (BC-6.24.001 PC2):** The step where the skill
presents injected spec content to the LLM session cannot be automated via bats (it requires
an active Claude Code session). This step requires a manual session test at F3, documented
as S-18.03 AC (manual acceptance criterion). The four bats tests above cover all structurally
verifiable properties (git-source, exact-list enumeration, error on missing manifest,
EPIC-COMPLETE path).

## Feasibility Assessment

**Feasible as bats integration test for §1/§2/§3/§4 structural properties.** The
`rehydrate-wave` skill's manifest-read, file-enumeration, error, and EPIC-COMPLETE branches
can all be exercised without a live LLM session by:

1. Setting up a `factory-artifacts` git fixture with controlled `wave-state.yaml` and/or
   `HANDOFF.md` content.
2. Invoking the skill in a controlled environment.
3. Asserting on the skill's stdout/stderr (file list, error message, confirmation prompt,
   EPIC-COMPLETE message).

The LLM-side context injection (PC2 — "presents them as context to the session") requires
a manual session test. This is noted as a known split-coverage boundary in BC-6.24.001 VP
Anchors rationale.
