# VP-111: Migration Subcommand Is Idempotent, Including Immediately After a PC7 Full-Recovery Split

## Property Statement

1. Running the migration subcommand a second (or any subsequent) time against an already-compliant
   file produces a verified-clean report with zero file mutations (PC4).
2. Running it a second time after a `changelog:` bootstrap (EC-002) produces zero further
   mutations.
3. `Check` mode after a successful `Apply` reports zero mutations (Invariant 2's `Check`/`Apply`
   report-equivalence).
4. Immediately after a PC7 full-recovery split has resolved an inline `[Prior: ...]` chain, the
   file reclassifies as `Eligibility::CurrentEntryOnly` — a re-run is governed by PC4, not by PC7
   again: it does NOT re-detect a chain (there is none left) and does NOT re-split (PC7 step 8 /
   Invariant 2).

## Source Contract

- **BC:** BC-10.13.001 §Postcondition 4 (PC4) — migration is idempotent; §Postcondition 7 step 8 —
  full-recovery split is idempotent (fires at most once per pre-existing chain); Invariant 2 —
  idempotent on every subcommand, extended to full-recovery split.
- **ADR:** ADR-049 §Decision 6, §Decision 7.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| unit-test | Rust (`#[test]`, tempfile fixtures) | yes — fixed fixture set | already-compliant no-op; post-bootstrap no-op; `Check`-after-`Apply` zero-mutation equivalence; PC7-rerun-is-noop (split-then-rerun) |

### Why unit-test

Idempotency here is a deterministic property of a pure classify-then-write pipeline
(`check_eligibility` → dispatch → write) exercised end-to-end against tempfile fixtures. No
property-based generator is required: the four fixed fixtures cover every reachable
already-compliant/post-bootstrap/check-mode/post-split state the migration subcommand can be
re-invoked against.
