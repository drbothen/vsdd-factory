# VP-120: Block-Reason Retry Instruction Is a Pure Function of the Original Tool Name; Seal-Rename Failure Fails Loud as HookResult::Error

## Property Statement

The observable outcome of a roll is a deterministic, actionable `Block` on the normal path and a
loud `Error` on the failure path — never a silent success and never a generic message.

1. **Retry-wording determinism.** The block reason's retry instruction is a pure function of the
   ORIGINAL blocked tool name (BC-1.18.006 §Postcondition 2, §Invariant 4): `Edit`/`MultiEdit` →
   "reissue as a fresh `Write` containing only your new entry…"; `Write` → "simply retry
   unchanged." The reason text also always names the artifact, the cap in bytes, and the
   now-empty-current-shard fact. It is never randomized, never omitted, never the generic
   "write failed, try again."

2. **Block is the only normal-path variant.** For a normal (non-crash) over-cap write, the gate
   returns `HookResult::Block` — never `Continue` (which would permit an over-cap write) and never
   `Error` (a normal rotation is not an error) (BC-1.18.006 §Invariant 1).

3. **Seal-rename failure fails loud.** If the seal rename cannot complete (permission error, disk
   full), the gate returns `HookResult::Error` (taxonomy `E-SHD-001`), NOT `Block` and NOT
   `Continue`; no shard-index entry is published and the canonical file is left in its pre-roll
   state (BC-1.18.006 §EC-003).

## Source Contract

- **BC:** BC-1.18.006 §Postcondition 2, §Invariant 1, §Invariant 4, §EC-003.
- **Error taxonomy:** `E-SHD-001` (seal-rename failure mid-roll) per the S-25.02 F2 PRD-delta §4.
- **SDK:** `crates/hook-sdk/src/result.rs` `HookResult` (Continue/Block/Error three-variant contract).

| Fail-loud seal error | unit-test | Rust `#[test]` with an injected rename-failure FS | outcome is `Error` (E-SHD-001), not Block/Continue; no index entry written | feasible-pending-harness (F4 code) |

### Why unit-test

The wording is a pure total function of an enum tool name (two classes) and the failure path is a
single injected error condition — a hand-crafted table gives exhaustive coverage of both, with no
value space a generator would broaden.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/shard_block_message_test.rs
// VP-120: BC-1.18.006 PC2/INV1/INV4/EC-003

#[test]
fn test_BC_1_18_006_PC2_retry_wording_is_pure_function_of_tool_name() {
    let msg_edit = shard_manager::block_reason(Tool::Edit, "burst-log", cap = 49_152);
    assert!(msg_edit.contains("reissue as a fresh `Write`"));
    let msg_write = shard_manager::block_reason(Tool::Write, "burst-log", cap = 49_152);
    assert!(msg_write.contains("simply retry unchanged"));
    assert!(msg_edit.contains("49152") && msg_write.contains("burst-log"));
}

#[test]
fn test_BC_1_18_006_EC003_seal_rename_failure_is_error_not_block() {
    let fs = MockFs::failing_rename();
    let r = shard_manager::seal_and_roll("decision-log", &fs);
    assert!(matches!(r, HookResult::Error { .. }));   // E-SHD-001, fail-loud
    assert!(fs.no_index_written());
}
```
