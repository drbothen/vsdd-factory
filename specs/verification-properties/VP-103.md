# VP-103: Host OutputTooLarge Then Plugin Ok(exit:0) Yields INDETERMINATE for fail-closed Plugin

## Property Statement

For any plugin with `failure_policy = FailClosed`:

When ANY host function call from within the plugin returns `OutputTooLarge = -3` to the plugin
(setting the dispatcher's per-invocation `host_output_too_large_seen` flag to `true`), AND the
plugin subsequently completes with `exit_code = 0`, the executor MUST classify the outcome as
`DispatchOutcome::Indeterminate` — NOT `DispatchOutcome::Pass`.

This property addresses the **OutputTooLarge detection gap**: a plugin that receives OutputTooLarge
from a host function (meaning it could not read the data it needed to validate) may silently
return exit_code=0 without recognizing the significance of the -3 return. From the dispatcher's
perspective (without the Store flag), this is indistinguishable from "validation passed." The
Store-flag mechanism closes this gap.

Negative constraint: If `host_output_too_large_seen = true` AND `exit_code = 0` AND
`failure_policy = FailOpen`, the outcome MUST NOT be classified as blocking INDETERMINATE (only
an advisory `plugin.indeterminate` event with cause `output-too-large`).

Negative constraint: If `host_output_too_large_seen = false` AND `exit_code = 0`, outcome
remains PASS regardless of `failure_policy`.

## Source Contract

- **BC:** BC-1.18.001 §Postcondition 1 —
  cannot-complete due to OutputTooLarge MUST yield INDETERMINATE for fail-closed plugins.
- **ADR:** ADR-047 §Decision 6 — OutputTooLarge detection via per-invocation Store flag
  `host_output_too_large_seen: bool`; host function wrappers set this flag when returning -3
  to the guest; executor checks post-invocation.
- **ADR:** ADR-047 §Decision 1 — INDETERMINATE trichotomy; condition (c): `PluginResult::Ok { exit_code: 0 }` WITH `host_output_too_large_seen == true`.
- **ADR:** ADR-025 Decision — `OutputTooLarge = -3` host function return code definition.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| unit-test | Rust (#[test]) | yes — 5 cases covering complete decision table for OutputTooLarge axis | fail-closed + OTL + exit_code=0 → INDETERMINATE; fail-open + OTL + exit_code=0 → NOT INDETERMINATE; fail-closed + OTL + exit_code=1 → FAIL (plugin correctly propagated); no-OTL + exit_code=0 → PASS; no-OTL + exit_code=0 + fail-closed → PASS |

### Why unit-test

The `host_output_too_large_seen` flag is per-invocation dispatcher-internal state (not WASM ABI).
The `classify_outcome` function takes it as a pure `bool` parameter. No WASM runtime, no mock
host function wiring needed for this VP. The Store-flag SET pathway (host wrappers setting the
flag when returning -3) is validated separately at the integration level in VP-105's end-to-end
scenario.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/src/tests/vp_103_indeterminate_output_too_large.rs
// VP-103: BC-1.18.001 PC1 — OutputTooLarge + exit_code=0 → INDETERMINATE for fail-closed plugins

#[cfg(test)]
mod vp_103 {
    use super::*;
    use crate::executor::{classify_outcome, DispatchOutcome, FailurePolicy, PluginResult};

    #[test]
    fn test_BC_1_18_001_output_too_large_plus_exit0_fail_closed_yields_indeterminate() {
        // The critical case: plugin saw OutputTooLarge from host fn, silently returned exit_code=0
        let result = PluginResult::Ok { exit_code: 0 };
        let policy = FailurePolicy::FailClosed;
        let host_output_too_large_seen = true; // host fn returned -3 during this invocation
        let outcome = classify_outcome(&result, policy, host_output_too_large_seen);
        assert_eq!(outcome, DispatchOutcome::Indeterminate,
            "VP-103: OutputTooLarge seen + exit_code=0 + fail-closed MUST yield INDETERMINATE (ADR-047 §D6)");
    }

    #[test]
    fn test_BC_1_18_001_output_too_large_plus_exit0_fail_open_not_blocking_indeterminate() {
        // Negative: fail-open must not produce blocking INDETERMINATE even with OTL seen
        let result = PluginResult::Ok { exit_code: 0 };
        let policy = FailurePolicy::FailOpen;
        let host_output_too_large_seen = true;
        let outcome = classify_outcome(&result, policy, host_output_too_large_seen);
        assert_ne!(outcome, DispatchOutcome::Indeterminate,
            "VP-103: OutputTooLarge seen + exit_code=0 + fail-open MUST NOT yield blocking INDETERMINATE (ADR-047 §D7)");
    }

    #[test]
    fn test_BC_1_18_001_output_too_large_plus_exit1_yields_fail_not_indeterminate() {
        // Plugin correctly propagated OutputTooLarge as an error (exit_code=1): outcome is FAIL
        let result = PluginResult::Ok { exit_code: 1 };
        let policy = FailurePolicy::FailClosed;
        let host_output_too_large_seen = true; // OTL seen, but plugin correctly blocked
        let outcome = classify_outcome(&result, policy, host_output_too_large_seen);
        assert_eq!(outcome, DispatchOutcome::Fail,
            "VP-103: OutputTooLarge seen + exit_code=1 MUST yield FAIL (plugin correctly blocked; AMD-003 preserved)");
    }

    #[test]
    fn test_BC_1_18_001_no_output_too_large_exit0_fail_closed_yields_pass() {
        // Normal case: no OTL seen, exit_code=0, fail-closed → PASS (flag=false, no interference)
        let result = PluginResult::Ok { exit_code: 0 };
        let policy = FailurePolicy::FailClosed;
        let host_output_too_large_seen = false;
        let outcome = classify_outcome(&result, policy, host_output_too_large_seen);
        assert_eq!(outcome, DispatchOutcome::Pass,
            "VP-103: No OTL + exit_code=0 + fail-closed MUST remain PASS (backward compat invariant)");
    }

    #[test]
    fn test_BC_1_18_001_output_too_large_flag_is_per_invocation() {
        // Verify the flag is reset per invocation: a second invocation with no OTL
        // must not inherit the OTL state from a prior invocation.
        // This test checks that classify_outcome takes flag as a parameter (not global state).
        let result = PluginResult::Ok { exit_code: 0 };
        let policy = FailurePolicy::FailClosed;
        // Simulate second invocation: fresh flag = false
        let outcome = classify_outcome(&result, policy, /*host_output_too_large_seen=*/ false);
        assert_eq!(outcome, DispatchOutcome::Pass,
            "VP-103: Per-invocation Store flag MUST be reset between invocations (ADR-047 §D6 scope constraint)");
    }
}
```
