# VP-105: Next-Advance Gate Blocks Agent Dispatch and git commit/push While Marker Exists, Passes When Absent

## Property Statement

The `validate-unvalidated-mutation-marker` gate (two hooks-registry registrations: Arm 1 for
`^Agent$`, Arm 2 for `^Bash$` with git commit/push command filter) MUST enforce:

**Postcondition A — Marker exists → block:**
When `.factory/unvalidated-mutation.marker` exists, the plugin MUST return `exit_code = 2`
(block dispatch) with a human-readable block message containing: the plugin name, artifact path,
cause, and the recommended recovery action.

**Postcondition B — Marker absent → pass:**
When `.factory/unvalidated-mutation.marker` does not exist, the plugin MUST return `exit_code = 0`
(allow dispatch), unconditionally.

**Postcondition C — Non-matching Bash and non-Agent tool calls unaffected:**
Bash dispatches where `is_git_commit_or_push(command)` returns `false` (the git subcommand is not
`commit` or `push` — e.g., `git status`, `git log`, `git diff`, `git fetch`,
`git commit-graph write`), Read, Edit, Write, MultiEdit, and all other tool types MUST NOT be
blocked by this plugin. The Arm 2 Bash matcher (`validate-unvalidated-mutation-marker-git`) only
gates exact git `commit` or `push` subcommands. Note: `git commit-graph write` is NOT blocked
because its subcommand is `commit-graph`, not `commit` (EC-011; this is why the illustrative
regex is NOT the authoritative rule — it false-positives on `commit-graph`).

**Postcondition D — Marker exists + git commit/push Bash dispatch → block:**
When `.factory/unvalidated-mutation.marker` exists AND `is_git_commit_or_push(command)` returns
`true` — meaning the first non-option token after `git` (and any tolerated git global options
such as `-C <path>`, `-c <key>=<val>`, `--namespace`, `--no-pager`, `--git-dir`) is exactly
`commit` or `push` — the `validate-unvalidated-mutation-marker-git` plugin registration MUST
return `exit_code = 2` (block) with the same human-readable recovery message as Arm 1 (plugin
name, artifact path, cause, recovery command, manual escape hatch).

**Postcondition E — Marker absent + git commit/push Bash dispatch → pass:**
When `.factory/unvalidated-mutation.marker` does not exist AND a Bash dispatch's `command`
matches the git commit/push pattern, the plugin MUST return `exit_code = 0` (allow),
unconditionally.

This VP requires integration testing through the real dispatcher binary because:
(a) the PreToolUse hook dispatch chain is the mechanism under test, and
(b) the exit_code=2 block behavior from a registered WASM plugin on Agent dispatch is precisely
    what the factory-dispatcher enforces.

## Source Contract

- **BC:** BC-1.18.002 §PC1 — gate blocks Agent dispatch when marker exists (PC-A).
  §PC2 — gate blocks git commit/push when marker exists (PC-D). §PC3 — gate passes when
  marker absent, Agent arm (PC-B). §PC4 — gate passes when marker absent, git arm (PC-E).
- **ADR:** ADR-047 §Decision 4 (v1.1) — Next-Advance Gate plugin specification: TWO hooks-registry
  entries — Arm 1 (`validate-unvalidated-mutation-marker`, `tool = "^Agent$"`) and Arm 2
  (`validate-unvalidated-mutation-marker-git`, `tool = "^Bash$"`, command-filter for git
  commit/push). Both: `on_error=block`, `failure_policy=fail-open`, exit_code=2 block message.
- **ADR:** ADR-047 §Decision 9 (v1.1 — human ratification amendment) — Extended gate scope:
  Agent dispatch AND git commit/push both blocked while marker exists; non-matching Bash and
  other tool types unaffected.
- **ADR:** ADR-047 §Decision 5 — Marker clear protocol: manual `rm` or successful re-validation
  unblocks BOTH gate arms simultaneously.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| integration | bats (real factory-dispatcher binary + registered WASM plugin) | yes — 7 scenarios | Arm 1: marker-exists → Agent blocked (PC-A); marker-absent → Agent pass (PC-B); manual rm unblocks (PC-B); Edit not gated (PC-C). Arm 2: marker-exists + git-commit → Bash blocked (PC-D); marker-absent + git-push → Bash pass (PC-E); git-status not gated when marker exists (PC-C) |
| unit-test | Rust (#[test] within plugin crate) | yes — 4 test functions | guard_logic::evaluate_gate: marker-exists → BlockDispatch; marker-absent → Allow; read-error → Allow (fail-open). guard_logic::is_git_commit_or_push: git commit and git push variants match; git commit-graph write does NOT match (EC-011); git status, git log, git diff, git fetch do NOT match (PC-C); global-option forms (git -C path commit, git -c k=v push, git --no-pager commit) DO match (EC-012) |

### Why integration + unit-test

The PreToolUse dispatch chain behavior (block_intent=true vs false based on plugin exit_code)
is only observable through the real dispatcher binary registered with the full hooks-registry.
Unit tests cover the plugin's internal `guard_logic` function in isolation; integration tests
verify the complete dispatch chain behavior including the dispatcher's block_intent evaluation.

#!/usr/bin/env bats
# plugins/vsdd-factory/tests/validate-unvalidated-mutation-marker.bats
# VP-105: BC-1.18.002 PC1+PC2+PC3+PC4 — next-advance gate blocks/passes based on marker presence

setup() {
    FACTORY_DIR=$(mktemp -d)
    mkdir -p "$FACTORY_DIR/.factory"
    export VSDD_SINK_FILE=$(mktemp --suffix=.jsonl)
}

teardown() {
    rm -rf "$FACTORY_DIR"
    rm -f "$VSDD_SINK_FILE"
}

@test "VP-105-A: marker exists → Agent dispatch blocked (exit_code=2)" {
    # Write a valid marker file
    cat > "$FACTORY_DIR/.factory/unvalidated-mutation.marker" <<'TOML'
timestamp = "2026-08-30T00:00:00Z"
plugin_name = "regression-gate"
artifact_path = "/tmp/.factory/STATE.md"
cause = "fuel"
trace_id = "deadbeef-0001-0001-0001-000000000001"
TOML

    # Dispatch an Agent PreToolUse event and check block_intent=true
    local result
    result=$(run_dispatcher_pretooluse_agent "$FACTORY_DIR")
    echo "Dispatcher result: $result"
    [[ "$result" == *"block_intent=true"* ]] || {
        echo "FAIL: Expected block_intent=true when marker exists; got: $result"
        return 1
    }
}

@test "VP-105-B: marker absent → Agent dispatch allowed (exit_code=0)" {
    # No marker file present
    [ ! -f "$FACTORY_DIR/.factory/unvalidated-mutation.marker" ] || \
        rm "$FACTORY_DIR/.factory/unvalidated-mutation.marker"

    local result
    result=$(run_dispatcher_pretooluse_agent "$FACTORY_DIR")
    [[ "$result" != *"block_intent=true"* ]] || {
        echo "FAIL: Expected allow (no block_intent) when marker absent; got: $result"
        return 1
    }
}

@test "VP-105-C: manual rm of marker unblocks subsequent dispatch" {
    # Write marker
    echo 'timestamp = "2026-08-30T00:00:00Z"
plugin_name = "convergence-tracker"
artifact_path = "/tmp/.factory/BC-INDEX.md"
cause = "epoch"
trace_id = "aaaaaaaa-0001-0001-0001-000000000001"' > "$FACTORY_DIR/.factory/unvalidated-mutation.marker"

    # Verify it blocks first
    local result1
    result1=$(run_dispatcher_pretooluse_agent "$FACTORY_DIR")
    [[ "$result1" == *"block_intent=true"* ]] || { echo "FAIL: expected block before rm"; return 1; }

    # Operator manual escape hatch
    rm "$FACTORY_DIR/.factory/unvalidated-mutation.marker"

    # Verify it no longer blocks
    local result2
    result2=$(run_dispatcher_pretooluse_agent "$FACTORY_DIR")
    [[ "$result2" != *"block_intent=true"* ]] || {
        echo "FAIL: Expected unblock after rm; dispatch still blocked"
        return 1
    }
}

@test "VP-105-D: Edit tool dispatch not gated (non-Agent tools unaffected)" {
    # Marker present but should not block Edit
    echo 'timestamp = "2026-08-30T00:00:00Z"
plugin_name = "validate-burst-log-structure"
artifact_path = "/tmp/.factory/burst-log.md"
cause = "fuel"
trace_id = "bbbbbbbb-0002-0002-0002-000000000002"' > "$FACTORY_DIR/.factory/unvalidated-mutation.marker"

    # Dispatch an Edit PreToolUse event (not Agent)
    local result
    result=$(run_dispatcher_pretooluse_edit "$FACTORY_DIR")
    [[ "$result" != *"block_intent=true"* ]] || {
        echo "FAIL: Edit dispatch MUST NOT be gated by validate-unvalidated-mutation-marker; got: $result"
        return 1
    }
}

@test "VP-105-E: marker exists + git commit Bash dispatch → blocked (PC-D)" {
    # Write a valid marker file
    cat > "$FACTORY_DIR/.factory/unvalidated-mutation.marker" <<'TOML'

@test "VP-105-F: marker absent + git commit Bash dispatch → passes (PC-E)" {

    [ ! -f "$FACTORY_DIR/.factory/unvalidated-mutation.marker" ] || \

    # Dispatch a Bash PreToolUse event with command = "git push origin factory-artifacts"

// crates/hook-plugins/validate-unvalidated-mutation-marker/src/tests/vp_105_guard_logic.rs
// VP-105 unit-test component: guard_logic pure behavior

#[cfg(test)]
mod vp_105 {
    use super::*;
    use crate::guard_logic::{evaluate_gate, GateDecision};
    use std::path::Path;
    use tempdir::TempDir;
    use std::fs;

    #[test]
    fn test_BC_1_18_002_marker_present_yields_block() {
        let dir = TempDir::new("vp105").unwrap();
        let marker_path = dir.path().join(".factory").join("unvalidated-mutation.marker");
        fs::create_dir_all(dir.path().join(".factory")).unwrap();
        fs::write(&marker_path, r#"timestamp = "2026-08-30T00:00:00Z"
plugin_name = "regression-gate"
artifact_path = "/tmp/STATE.md"
cause = "fuel"
trace_id = "deadbeef-0001-0001-0001-000000000001"
"#).unwrap();

        let decision = evaluate_gate(dir.path());
        assert_eq!(decision, GateDecision::BlockDispatch,
            "VP-105: marker present MUST yield BlockDispatch (exit_code=2)");
    }

    #[test]
    fn test_BC_1_18_002_marker_absent_yields_allow() {
        let dir = TempDir::new("vp105_absent").unwrap();
        fs::create_dir_all(dir.path().join(".factory")).unwrap();
        // No marker file

        let decision = evaluate_gate(dir.path());
        assert_eq!(decision, GateDecision::Allow,
            "VP-105: marker absent MUST yield Allow (exit_code=0)");
    }

    #[test]
    fn test_BC_1_18_002_read_error_yields_allow_fail_open() {
        // If the marker file cannot be read (permission error, etc.), gate is fail-open
        let dir = TempDir::new("vp105_err").unwrap();
        // Do NOT create .factory/ directory — simulate read-path not accessible
        // evaluate_gate must return Allow when it cannot determine marker presence
        // (fail-open per ADR-047 §Decision 4: gate itself is failure_policy=fail-open)
        let decision = evaluate_gate(dir.path());
        assert_eq!(decision, GateDecision::Allow,
            "VP-105: gate read-error MUST yield Allow (gate is failure_policy=fail-open)");
    }

    // --- Arm 2: git commit/push command pattern (PC-D, PC-E, PC-C) ---

    #[test]
    fn test_BC_1_18_002_git_commit_command_matches_pattern() {
        use crate::guard_logic::is_git_commit_or_push;
        // git commit variants
        assert!(is_git_commit_or_push("git commit -m 'test'"),
            "VP-105: 'git commit' MUST match the git-commit/push pattern");
        assert!(is_git_commit_or_push("git commit --amend --no-edit"),
            "VP-105: 'git commit --amend' MUST match");
        // git push variants
        assert!(is_git_commit_or_push("git push origin factory-artifacts"),
            "VP-105: 'git push' MUST match the git-commit/push pattern");
        assert!(is_git_commit_or_push("git push --force-with-lease"),
            "VP-105: 'git push --force-with-lease' MUST match");
        // Non-matching git subcommands MUST NOT match (PC-C)
        assert!(!is_git_commit_or_push("git status --porcelain"),
            "VP-105: 'git status' MUST NOT match (PC-C: must not be gated)");
        assert!(!is_git_commit_or_push("git log --oneline -5"),
            "VP-105: 'git log' MUST NOT match");
        assert!(!is_git_commit_or_push("git diff HEAD~1"),
            "VP-105: 'git diff' MUST NOT match");
        assert!(!is_git_commit_or_push("git fetch origin"),
            "VP-105: 'git fetch' MUST NOT match");
        // Non-git commands
        assert!(!is_git_commit_or_push("cargo test --workspace"),
            "VP-105: non-git commands MUST NOT match");
        // EC-011: git commit-graph write — subcommand is commit-graph, NOT commit; MUST NOT match
        assert!(!is_git_commit_or_push("git commit-graph write"),
            "VP-105 EC-011: 'git commit-graph write' MUST NOT match — subcommand is commit-graph, not commit");
        // EC-012: git global options before subcommand are tolerated
        assert!(is_git_commit_or_push("git -C .factory commit -m \"state\""),
            "VP-105 EC-012: 'git -C .factory commit' MUST match — global option -C tolerated, subcommand is commit");
        assert!(is_git_commit_or_push("git -c user.email=x push origin main"),
            "VP-105 EC-012: 'git -c key=val push' MUST match — global option -c tolerated, subcommand is push");
        assert!(is_git_commit_or_push("git --no-pager commit --amend --no-edit"),
            "VP-105 EC-012: 'git --no-pager commit' MUST match — global option --no-pager tolerated");
    }
}
