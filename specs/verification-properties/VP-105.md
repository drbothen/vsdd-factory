# VP-105: Next-Advance Gate Blocks Agent Dispatch and git commit/push While Marker Exists, Passes When Absent

## Property Statement

The `validate-unvalidated-mutation-marker` gate (two hooks-registry registrations: Arm 1 for
`^Agent$`, Arm 2 for `^Bash$` with git commit/push command filter) MUST enforce:

**Postcondition A — Marker exists → block:**
When `.factory/unvalidated-mutation.marker` exists, the plugin MUST return `exit_code = 2`
(block dispatch) with a human-readable block message containing: the plugin name, artifact path,
cause, and the recommended recovery action.

**Postcondition B — Marker absent → pass:**
When `.factory/unvalidated-mutation.marker` does not exist, the plugin MUST return `exit_code = 0`
(allow dispatch), unconditionally.

**Postcondition C — Non-matching Bash and non-Agent tool calls unaffected:**
Bash dispatches where `is_git_commit_or_push(command)` returns `false` (the git subcommand is not
`commit` or `push` — e.g., `git status`, `git log`, `git diff`, `git fetch`,
`git commit-graph write`), Read, Edit, Write, MultiEdit, and all other tool types MUST NOT be
blocked by this plugin. The Arm 2 Bash matcher (`validate-unvalidated-mutation-marker-git`) only
gates exact git `commit` or `push` subcommands. Note: `git commit-graph write` is NOT blocked
because its subcommand is `commit-graph`, not `commit` (EC-011). Additional non-blocking cases
from the v1.2 five-dimension algorithm: compound command `git status && git log --oneline` →
NOT blocked because no segment resolves to subcommand `commit` or `push` (EC-019);
`cat gitfile` → NOT blocked because `basename("cat") ≠ "git"` (EC-020). Exception: a command
with an unrecognized option such as `git --unknown-flag commit` IS blocked via fail-safe (EC-022)
because the subcommand position cannot be determined with certainty from the closed recognized
option set — this is the conservative posture for a security-critical gate.

**Postcondition D — Marker exists + git commit/push Bash dispatch → block:**
When `.factory/unvalidated-mutation.marker` exists AND `is_git_commit_or_push(command)` returns
`true` per the v1.3 algorithm, the `validate-unvalidated-mutation-marker-git` plugin
registration MUST return `exit_code = 2` (block) with the same human-readable recovery message as
Arm 1 (plugin name, artifact path, cause, recovery command, manual escape hatch). The v1.3
algorithm covers the SIX-dimension test surface: (a) exact subcommand match — `commit` or `push`
only (full-token, case-sensitive; `commit-graph` does NOT match); (b) complete recognized
arg-taking option set — `-C`, `-c`, `--namespace`, `--git-dir`, `--work-tree`, `--super-prefix`,
`--config-env` each consume one following separate-token argument before the subcommand is
identified; (c) compound splitting — split on `&&`, `||`, `;`, `|`, `&`, and newline into
independent segments; any segment returning `true` causes the function to return `true`;
(d) basename identification — `basename(executable) = "git"` after stripping leading path
components and leading `env VAR=x` prefix tokens; (e) fail-safe on unrecognized options — any
option starting with `-` that is not in the complete recognized arg-taking or no-arg sets causes
an immediate `true` return (block) because the subcommand position cannot be determined;
(f) POSIX quote-aware tokenization via `shell-words` crate (Phase 1b) — quoted-literal git
invocations are IN SCOPE: `git "commit"` → blocked (EC-024), `git 'push' origin` → blocked
(EC-025), `g'i't commit` → blocked (EC-026); ad-hoc quote-stripping is explicitly forbidden —
only the `shell-words` crate provides POSIX parser-equivalence and eliminates the
parser-differential bypass class.
Representative examples: `git --git-dir .git commit -m "state"` → blocked (EC-013);
`git status && git commit -m "x"` → blocked (EC-015); `/usr/bin/git commit -m "init"` → blocked
(EC-017); `git --unknown-flag commit` → blocked via fail-safe (EC-022); `git "commit"` → blocked
(EC-024); `g'i't commit` → blocked (EC-026).
OUT OF SCOPE (NOT blocked by design — undecidable for static string analysis; Threat Model):
`$(git commit -m "x")` (command substitution; EC-027), `echo x | xargs git commit` (xargs
indirection; EC-028), `eval "git push origin main"` (dynamic eval; EC-029) — allowed under
fail-open posture; caught by durable marker and other layers (see BC-1.18.002 §Threat Model).

**Postcondition E — Marker absent + git commit/push Bash dispatch → pass:**
When `.factory/unvalidated-mutation.marker` does not exist AND a Bash dispatch's `command`
matches the git commit/push pattern, the plugin MUST return `exit_code = 0` (allow),
unconditionally.

This VP requires integration testing through the real dispatcher binary because:
(a) the PreToolUse hook dispatch chain is the mechanism under test, and
(b) the exit_code=2 block behavior from a registered WASM plugin on Agent dispatch is precisely
    what the factory-dispatcher enforces.

## Source Contract

- **BC:** BC-1.18.002 §PC1 — gate blocks Agent dispatch when marker exists (PC-A).
  §PC2 — gate blocks git commit/push when marker exists (PC-D). §PC3 — gate passes when
  marker absent, Agent arm (PC-B). §PC4 — gate passes when marker absent, git arm (PC-E).
- **ADR:** ADR-047 §Decision 4 (v1.1) — Next-Advance Gate plugin specification: TWO hooks-registry
  entries — Arm 1 (`validate-unvalidated-mutation-marker`, `tool = "^Agent$"`) and Arm 2
  (`validate-unvalidated-mutation-marker-git`, `tool = "^Bash$"`, command-filter for git
  commit/push). Both: `on_error="continue"` (dispatcher fail-open-on-crash — if the WASM plugin
  crashes the dispatcher allows the tool call through), `failure_policy=fail-open`, exit_code=2
  block message. Two-axis model per ADR-039: (i) `on_error="continue"` governs the
  DISPATCHER-LEVEL response to plugin crash (fail-open); (ii) the FILTER-INTERNAL Phase-3
  fail-safe (unrecognized `-`-option → return `true`/block) governs the plugin's OWN posture
  when command structure is ambiguous. These two axes are orthogonal.
- **ADR:** ADR-047 §Decision 9 (v1.1 — human ratification amendment) — Extended gate scope:
  Agent dispatch AND git commit/push both blocked while marker exists; non-matching Bash and
  other tool types unaffected.
- **ADR:** ADR-047 §Decision 5 — Marker clear protocol: manual `rm` or successful re-validation
  unblocks BOTH gate arms simultaneously.

## Proof Method

| Method | Tool | Bounded? | Coverage |

| integration | bats (real factory-dispatcher binary + registered WASM plugin) | yes — 7 scenarios | Arm 1: marker-exists → Agent blocked (PC-A); marker-absent → Agent pass (PC-B); manual rm unblocks (PC-B); Edit not gated (PC-C). ### Why integration + unit-test

The PreToolUse dispatch chain behavior (block_intent=true vs false based on plugin exit_code)
is only observable through the real dispatcher binary registered with the full hooks-registry.
Unit tests cover the plugin's internal `guard_logic` function in isolation; integration tests
verify the complete dispatch chain behavior including the dispatcher's block_intent evaluation.

        // EC-019: compound git status && git log — no segment has commit or push as subcommand
        assert!(!is_git_commit_or_push("git status && git log --oneline"),
            "VP-105 EC-019: 'git status && git log' MUST NOT match — no segment subcommand is commit or push");
        // EC-020: cat gitfile — basename is not git
        assert!(!is_git_commit_or_push("cat gitfile"),
            "VP-105 EC-020: 'cat gitfile' MUST NOT match — basename('cat') != 'git'");
        // EC-024: quoted subcommand — git "commit" — POSIX quote-aware tokenization (Phase 1b, shell-words)
        assert!(is_git_commit_or_push(r#"git "commit""#),
            "VP-105 EC-024: 'git \"commit\"' MUST match — Phase 1b quote-aware tokenization strips quotes, subcommand is commit");
        // EC-025: single-quoted push — git 'push' origin
        assert!(is_git_commit_or_push("git 'push' origin"),
            "VP-105 EC-025: \"git 'push' origin\" MUST match — Phase 1b single-quote tokenization, subcommand is push");
        // EC-026: quoted executable — g'i't commit
        assert!(is_git_commit_or_push("g'i't commit"),
            "VP-105 EC-026: \"g'i't commit\" MUST match — Phase 1b unquotes executable token to 'git', subcommand is commit");
        // EC-027: command substitution — $(git commit -m "x") — OUT OF SCOPE; static string analysis cannot detect
        assert!(!is_git_commit_or_push(r#"$(git commit -m "x")"#),
            "VP-105 EC-027: command substitution MUST NOT match — undecidable for static string analysis (out of scope by design)");
        // EC-028: xargs indirection — echo x | xargs git commit — OUT OF SCOPE; pipeline feeds args dynamically
        assert!(!is_git_commit_or_push("echo x | xargs git commit"),
            "VP-105 EC-028: xargs indirection MUST NOT match — dynamic argument construction out of scope by design");
        // EC-029: dynamic eval — eval "git push origin main" — OUT OF SCOPE; eval string not parsed
        assert!(!is_git_commit_or_push(r#"eval "git push origin main""#),
            "VP-105 EC-029: dynamic eval MUST NOT match — eval operand is a runtime string, not parseable statically");
    }
}
