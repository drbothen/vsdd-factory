# VP-101: host::read_prefix Returns Byte-Exact Prefix of len <= max_bytes; Never OUTPUT_TOO_LARGE; Absent File Returns NOT_FOUND (-5)

## Property Statement

`host::read_prefix(path, max_bytes)` MUST satisfy three postconditions:

**Postcondition A — Byte-exact prefix:**
For any allowlisted `path` that exists and has `file_size` bytes,
`host::read_prefix(path, max_bytes)` MUST return `Ok(content)` where
`content.len() == min(file_size, max_bytes)` and `content == file_bytes[0..content.len()]`.
The returned content is the exact file prefix, not a truncated-with-marker result
(BC-1.17.001 PC1).

**Postcondition B — Never OUTPUT_TOO_LARGE:**
`host::read_prefix` MUST NEVER return `OUTPUT_TOO_LARGE (-3)` regardless of file size or
`max_bytes` value. Truncation is the contract; the caller sets `max_bytes` to declare their
buffer bound. Returning `OUTPUT_TOO_LARGE` would contradict the prefix semantics
(BC-1.17.001 PC2).

**Postcondition C — Absent file returns NOT_FOUND (-5):**
For an absent-but-allowlisted path, `host::read_prefix` MUST return `NOT_FOUND = -5`. It MUST
NOT return `CAPABILITY_DENIED = -1`. Same NOT_FOUND/CAPABILITY_DENIED discrimination as
`host::read_file` (ADR-025 Decision 13; BC-1.17.001 PC3).

This VP is verified by both an integration suite (Postconditions A–C end-to-end) and a proptest
component (Postcondition A pure prefix property over arbitrary file sizes and max_bytes values).

## Source Contract

- **BC:** BC-1.17.001 v1.0 — `read_prefix` additive host function; byte-exact prefix semantics;
  never OUTPUT_TOO_LARGE; absent-file NOT_FOUND (-5); HOST_ABI_VERSION=1 unchanged (additive
  entry point per ADR-025 Decision 15).
- **ADR:** ADR-025 Decision 13 — `codes::NOT_FOUND = -5` allocation.
- **ADR:** ADR-025 Decision 15 — `read_prefix` additive host function; HOST_ABI_VERSION treatment
  (additive entry point mirrors Decision 13 precedent; version unchanged).

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| integration | bats (dispatcher binary + synthetic probe WASM) | yes — absent file, file < max_bytes, file == max_bytes, file > max_bytes | NOT_FOUND; byte-exact prefix; OUTPUT_TOO_LARGE absence |
| proptest | Rust proptest (pure slice truncation property) | yes — 1024 trials, arbitrary file sizes and max_bytes | byte-exact prefix: `result == file[0..min(size,max)]`; determinism |

### Why integration + proptest

Postcondition C (absent file → NOT_FOUND) requires the real dispatcher binary and host ABI.
Postconditions A and B for the byte-exact prefix property are also best verified end-to-end via
integration. The proptest component provides complementary exhaustive coverage of the pure
prefix-truncation logic independently of the WASM runtime, catching any off-by-one in the
`min(file_size, max_bytes)` calculation.

```rust
// proptest component: crates/factory-dispatcher/tests/proptest_read_prefix.rs
use proptest::prelude::*;

/// Simulate read_prefix pure truncation logic (no I/O)
fn simulate_prefix(file_bytes: &[u8], max_bytes: usize) -> &[u8] {
    &file_bytes[..std::cmp::min(file_bytes.len(), max_bytes)]
}

proptest! {
    #![proptest_config(ProptestConfig::with_cases(1024))]

    #[test]
    fn prop_byte_exact_prefix(
        file_bytes in proptest::collection::vec(any::<u8>(), 0..65536),
        max_bytes in 0usize..131072,
    ) {
        let result = simulate_prefix(&file_bytes, max_bytes);
        let expected_len = std::cmp::min(file_bytes.len(), max_bytes);
        prop_assert_eq!(result.len(), expected_len,
            "prefix len must equal min(file_size, max_bytes)");
        prop_assert_eq!(result, &file_bytes[..expected_len],
            "prefix content must equal file bytes[0..expected_len]");
    }

    #[test]
    fn prop_no_output_too_large(
        file_bytes in proptest::collection::vec(any::<u8>(), 0..65536),
        max_bytes in 0usize..131072,
    ) {
        // read_prefix never exceeds max_bytes; thus OUTPUT_TOO_LARGE is structurally impossible
        let result = simulate_prefix(&file_bytes, max_bytes);
        prop_assert!(result.len() <= max_bytes,
            "read_prefix result must never exceed max_bytes (OUTPUT_TOO_LARGE impossible)");
    }
}
```
