# VP-128: BC-INDEX Second-Level Addressing Is Manifest-Keyed With Single-Authoritative-Row Integrity and ARCH-INDEX-Sourced Prefix Mapping

## Property Statement

Mechanism B2's second level and its cross-reference integrity hold after the split.

1. **Manifest-keyed second-level addressing.** For a sub-sharded subsystem (SS-05, SS-06 at F4
   activation), a lookup of a specific `BC-5.YY.NNN` first reads the top-level shard-manifest to
   discover `sub_sharded=true` + the `sub_manifest` path, then reads that per-subsystem sub-manifest
   to determine which growth-based sub-shard (`.a`/`.b`/…) holds the ID range — TWO manifest reads
   for a sub-sharded subsystem, versus ZERO for a non-sub-sharded one (BC-1.18.010 §Postcondition 4,
   §EC-001). The SAME size-check gate triggers second-level sub-sharding for any subsystem, not just
   SS-05/SS-06.

2. **Single-authoritative-row integrity.** After the first-level split, no BC ID's row appears in
   both `BC-INDEX.md`'s body and a shard file (or, post-second-level, two sub-shards): every row
   lives in exactly one (sub-)shard file, and `BC-INDEX.md`'s body carries zero per-BC table rows
   (BC-1.18.010 §Invariant 3, §Postcondition 1). This is the cross-reference integrity a sharded
   catalog must preserve — verified by a full-corpus scan asserting exactly one row per BC ID.

3. **Mapping-source-of-truth.** The BC-S-prefix→SS-NN mapping B2's addressing uses is byte-identical
   to ARCH-INDEX's own Subsystem Registry `BC-S Prefix` column — never an independently hardcoded or
   duplicated table (BC-1.18.010 §Invariant 2).

### Why integration

These properties span multiple real files (the top-level manifest, per-subsystem sub-manifests, the
shard files, ARCH-INDEX, and `BC-INDEX.md`'s residual body) — they require a harness that parses the
actual on-disk shard set and cross-references ARCH-INDEX, the same class as VP-072
(single-source-of-truth) and the consistency-validator scans.

```rust
// crates/factory-dispatcher/tests/bcindex_second_level_addressing_test.rs
// VP-128: BC-1.18.010 PC1/PC4/INV2/INV3/EC-001

#[test]
fn test_BC_1_18_010_PC4_subsharded_lookup_uses_two_manifest_reads() {
    let cx = ShardCorpus::with_subsharded("SS-05");
    let fs = cx.counting_fs();
    let path = shard_manager::resolve_subsystem_shard_path_counting("BC-5.39.006", &fs);
    assert!(path.starts_with("shards/BC-INDEX-SS-05."));           // e.g. .b.md
    assert_eq!(fs.manifest_reads(), 2);                            // top-level + sub-manifest
}

#[test]
fn test_BC_1_18_010_INV3_single_authoritative_row_across_corpus() {
    let cx = ShardCorpus::post_split();
    let dupes = cx.bc_ids_present_in_more_than_one_row();
    assert!(dupes.is_empty());
    assert_eq!(cx.rows_in_bcindex_body(), 0);
}

#[test]
fn test_BC_1_18_010_INV2_mapping_matches_arch_index() {
    assert_eq!(shard_manager::bc_prefix_map(), arch_index::subsystem_registry_prefix_map());
}
```
