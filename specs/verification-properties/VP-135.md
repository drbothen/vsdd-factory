# VP-135: B1 Backfill Migration Content Preservation — Every Migrated changelog: Item Preserved Byte-for-Byte in the Single Evergreen Archive; Concat Reproduces the Original History

## Property Statement

The one-time B1 cold-start `changelog:` backfill migration (BC-1.18.012) relocates the oldest
`changelog:` items out of `BC-INDEX.md`'s frontmatter without ever mutating an item's text — the
direct `changelog:`-item-count analogue of VP-123's mechanism-A byte-for-byte preservation and
VP-132's mechanism-B2 body-split preservation.

1. **Byte-for-byte item preservation.** For an arbitrary starting `changelog:` sequence of any
   length, every item the migration moves out of the live frontmatter appears verbatim — its
   `date:` and `summary:` text unchanged, byte-for-byte — in the SINGLE evergreen archive file
   `.factory/specs/behavioral-contracts/BC-INDEX-changelog-archive.md` (BC-1.18.012 §Postcondition
   4). No item is reflowed, re-quoted, truncated, or re-ordered relative to the others.

2. **Single evergreen archive, not per-seq shards.** The overflow tail is APPENDED to the ONE
   evergreen archive file BC-1.18.009 Postcondition 2/5 establishes — never a per-`seq` sealed-shard
   directory and never a separate migration-specific location (BC-1.18.012 §Postcondition 2). The
   migration reuses the SAME `rotate_changelog` primitive B1's ongoing rotation uses, via the SAME
   generalized `archive_path`-parameterized call surface.

3. **Round-trip reconstructs the full history.** Concatenating (the archive file content, in
   append order oldest-to-newest) followed by (the retained live `changelog:` sequence,
   newest-first) reproduces the full pre-migration item set with no gaps and no duplicates. Each
   input item lands in exactly ONE destination (archived XOR retained), never both — the content
   half of BC-1.18.012 §Invariant 2's no-double-count / no-drop guarantee.

The illustrative retention target `N` is **PROVISIONAL-until-F4** (BC-1.18.005 §Postcondition 6 /
§Postcondition 8 cold/steady split); the content-preservation and round-trip properties hold for any
`N` and any starting item count — only the boundary between archived and retained shifts with `N`,
never the preservation itself.

| Round-trip reconstruction | proptest + golden-file | `proptest!` + a golden fixture of the real ~1,997-item `BC-INDEX.md` `changelog:` | `concat(archive_append_order) + retained_live == original` (no gap, no dup); each item archived XOR retained | feasible-pending-harness (F4 code) |

### Why proptest

Content preservation and the archived-XOR-retained partition are universally quantified over
arbitrary starting sequences and any `N`; generated sequences (varying lengths, oversized items,
the exact-at-`N` boundary) explore a space a fixed fixture cannot, and a golden round-trip against
the real cold-start `changelog:` corpus anchors it to production data — exactly the VP-123 / VP-132
rationale, keyed here to the item-count model.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/proptest_b1_backfill_preservation.rs
// VP-135: BC-1.18.012 PC4/PC2/INV2 — B1 cold-start changelog backfill content preservation

proptest! {
    #[test]
    fn prop_every_migrated_item_preserved_byte_for_byte((items, n) in arb_changelog_and_cap()) {
        let mut idx = SimBcIndex::with_changelog(items.clone());
        idx.run_b1_backfill_migration(/*keep_recent*/ n);   // BC-1.18.012 one-time migration
        let archived = idx.read_archive_items_append_order();  // BC-INDEX-changelog-archive.md
        let retained = idx.read_live_changelog_newest_first();
        // content preserved: archive + retained (as a multiset over item bytes) == original
        prop_assert_eq!(sorted_bytes(archived.iter().chain(retained.iter())),
                        sorted_bytes(items.iter()));
        // round-trip: append-order archive then newest-first retained reproduces original order
        prop_assert_eq!(concat_history(&archived, &retained), original_order(&items));
        // exactly one destination per item (archived XOR retained)
        for it in &items { prop_assert!(archived.contains(it) ^ retained.contains(it)); }
    }
}
```
