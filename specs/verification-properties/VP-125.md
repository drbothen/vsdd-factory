# VP-125: BC-INDEX changelog: Rotation Bounds the Live Sequence at N Items With Zero History Loss

## Property Statement

Mechanism B1 (BC-INDEX frontmatter `changelog:` auto-rotation) bounds the live frontmatter while
never losing history, over an arbitrary sequence of prepends — modeled under BC-1.18.009 v1.1's
**CORRECTED single-actor block-and-retry contract** (F-S2502-F2-001): on an over-N prepend the gate
performs ONLY the rotate/trim (to N-1 items) then returns `HookResult::Block`; the new item's prepend
is landed EXCLUSIVELY by the agent's own retried `Edit`/`Write`/`MultiEdit` call. The withdrawn v1.0
"gate rotates AND prepends, then Continues" design is NOT modeled — it was unsound (double-actor
prepend / stale-payload clobber).

1. **Bounded live sequence.** After any sequence of `changelog:` item prepends, the live
   frontmatter `changelog:` sequence never exceeds `N` items (BC-1.18.009 §Postcondition 1). `N` is
   a config value; the bound holds for any `N`. A single oversized changelog item still counts as
   exactly ONE item toward `N` (BC-1.18.009 §EC-004) — B1's rotation is item-count-triggered, not
   per-item-byte-triggered.

2. **Single-actor block-and-retry — no double-prepend, no lost item, terminating retry.** For the
   over-N case, the sequence is modeled as TWO tool-call events, not one (BC-1.18.009 §Postcondition
   2 CORRECTED, §Invariant 4):
   - **Event 1 (the blocked write).** The gate sees `current_item_count + 1 > N`, invokes
     `rotate_changelog` ONLY (trimming the live sequence to N-1 items and APPENDING the overflow tail
     to the SINGLE evergreen archive `BC-INDEX-changelog-archive.md`), and returns `Block` — WITHOUT
     prepending the agent's new item (the gate never calls `prepend_changelog_item`; see VP-126).
     Post-Event-1 live length is exactly `N-1`.
   - **Event 2 (the retry).** The agent re-issues its write against the now-rotated file; its prepend
     lands via `Continue` (item count `N-1+1 = N`, not exceeding `N`) — the SOLE prepend of the new
     item, applied EXACTLY ONCE. Post-Event-2 live length is exactly `N`.
   The modeled outcome for any over-N prepend is therefore: the new item appears in the live sequence
   exactly once (no double-prepend from a gate-side + agent-side pair), the archived tail item is not
   silently re-introduced (no stale-payload clobber), and the block→retry pair terminates (the retry
   does not itself re-trigger rotation, since post-rotation length is `N-1`). Under-N prepends
   (EC-002) are a single `Continue` event, unchanged.

3. **No history loss (single evergreen archive).** Every `changelog:` item ever prepended remains
   recoverable — live in the frontmatter, or byte-for-byte APPENDED to the SINGLE, evergreen,
   append-only archive file `.factory/specs/behavioral-contracts/BC-INDEX-changelog-archive.md`
   (BC-1.18.009 §Postcondition 5 CORRECTED — NEVER a per-`seq` sealed-shard directory; no prior
   appended content is ever overwritten, truncated, or deleted by a subsequent rotation). The total
   recoverable item count equals the total prepend count and is monotonically non-decreasing
   (§Invariant 2). Reading the archive file (append order, oldest-to-newest) followed by the live
   `changelog:` sequence (newest-first) reproduces the full history with no gaps or duplicates —
   and, under the corrected single-actor contract, with no duplicate arising from a double-actor
   prepend.

### Why proptest

All three are universal invariants over an arbitrary prepend sequence with a variable `N` —
proptest's generated sequences (including the oversized-single-item boundary case and the exact-at-N
boundary that triggers block→retry) cover the state space a fixed fixture cannot. The rotation logic
under test is `rotate_changelog` (reused, gate-side only; see VP-126); the prepend is agent-side
only. This VP proves the observable bounded/lossless/single-actor outcome of the corrected
block-and-retry sequence.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/proptest_bcindex_changelog_rotation.rs
// VP-125: BC-1.18.009 PC1/PC2(CORRECTED)/PC5/INV2/INV4/EC-002/EC-004
//
// The sim models the SINGLE-ACTOR block-and-retry contract: apply_prepend() returns a
// GateOutcome; on Block the caller (agent) retries. The gate NEVER prepends (VP-126);
// only the agent's (possibly-retried) write prepends.

proptest! {
    #[test]
    fn prop_live_changelog_bounded_under_block_and_retry((prepends, n) in arb_prepends_and_cap()) {
        let mut idx = SimBcIndex::with_changelog_cap(n);
        for item in prepends {
            // Event 1: agent's write hits the gate.
            match idx.gate_evaluate_prepend(&item) {
                GateOutcome::Continue => { idx.agent_prepend(item); }       // under-N: single actor
                GateOutcome::Block => {
                    // gate rotated/trimmed to n-1 and did NOT prepend:
                    prop_assert_eq!(idx.live_changelog_len(), n - 1);
                    // Event 2: agent retries against the rotated file; retry lands the sole prepend.
                    prop_assert!(matches!(idx.gate_evaluate_prepend(&item), GateOutcome::Continue));
                    idx.agent_prepend(item);                                // exactly once
                }
                GateOutcome::Error => { /* rotate failure — VP-131 covers fail-loud */ }
            }
            prop_assert!(idx.live_changelog_len() <= n);                    // bounded after every event
        }
    }

    #[test]
    fn prop_no_double_prepend_and_no_history_loss(prepends in arb_prepends()) {
        let mut idx = SimBcIndex::with_changelog_cap(50);
        let mut count = 0;
        for item in prepends {
            match idx.gate_evaluate_prepend(&item) {
                GateOutcome::Continue => idx.agent_prepend(item),
                GateOutcome::Block => { idx.gate_evaluate_prepend(&item); idx.agent_prepend(item); }
                GateOutcome::Error => continue,
            }
            count += 1;
            prop_assert_eq!(idx.recoverable_item_count(), count);           // == prepends: no loss, no dup
            prop_assert_eq!(idx.count_occurrences(&item), 1);               // single-actor: no double-prepend
        }
    }
}
```
