# VP-081: Wave Cannot Close Without Verified Handoff (wave_id > 1)

## Property

When the factory attempts to close wave N (where N > 1), the `wave-gate` skill MUST be
blocked from declaring wave close unless a verified `HANDOFF.md` exists on the
`factory-artifacts` branch with all ADR-026 §Decision 2 required fields present and
syntactically valid.

Formally:
- **Precondition:** The `wave-gate` close-wave step is executing for wave N > 1. The shell
  caller (wave-gate/wave-handoff skill, BC-5.41.001) determines non-first-wave status from
  real substrate: sprint-state.yaml dependency-order topological sort wave-group ordinal > 1
  for product pipelines, OR presence of a prior HANDOFF.md on `factory-artifacts` for the
  engine context (there is no `current_wave:` field on STATE.md). The shell caller derives
  `wave_id` from this substrate and embeds it in the HANDOFF.md payload BEFORE writing.
  The WASM gate's own wave-identity determination is PAYLOAD-ONLY (F-A005): it reads `wave_id`
  from the YAML in `handoff_content` and derives wave-1 identity INTERNALLY inside
  `check_handoff_completeness` — there is no external `is_first_wave` field (eliminated by
  F-A005). The gate does NOT read sprint-state.yaml, factory-artifacts, or git to determine
  wave identity.
- **Invariant:** `wave-gate` MUST invoke `validate-wave-handoff-completeness` gate before emitting any wave-close completion marker.
- **Postcondition A (HANDOFF.md absent at wave-close):** the SHELL `wave-gate` skill (BC-5.41.001 PC9) returns `Error("HandoffMissing")` and halts. This leg is SHELL-SIDE: the shell wave-gate detects HANDOFF.md absence on `factory-artifacts` BEFORE invoking any WASM gate. The `validate-wave-handoff-completeness` WASM gate is NOT triggered on file-absence (BC-4.14.001 EC-011) and NEVER emits `HandoffMissing`. No wave-close marker emitted.
- **Postcondition B (HANDOFF.md present but incomplete):** gate returns `HandoffIncomplete` block with field name. `wave-gate` halts. No wave-close marker emitted.
- **Postcondition C (HANDOFF.md present and complete):** gate returns `Continue`. `wave-gate` proceeds to wave-close marker emission.
- **Postcondition D (wave_id == 1 in handoff_content YAML):** gate returns `Continue` unconditionally (wave-1 no-op per ADR-026 §Decision 9). The WASM gate derives wave-1 identity internally from the parsed `wave_id` value in `handoff_content` (F-A005 payload-only); the shell caller is responsible for embedding `wave_id: 1` in the HANDOFF payload when appropriate. No external `is_first_wave` flag exists (eliminated by F-A005).
- **Postcondition E (wave_id ABSENT from payload):** gate FAILS CLOSED — does NOT return `Continue`. Proceeds to full validation; blocks with `HandoffIncomplete: ["wave_id"]` (and any other missing required fields). Absent `wave_id` is NOT treated as wave-1. The VP-INDEX VP-081 Full Index row advertises this fail-closed behavior.

## Invariant Classification: Safety (Hard Block)

This is a safety property. A partial wave-close (close marker emitted without verified handoff)
could result in wave N+1 starting from incomplete or fabricated state. The gate must never
allow a false-positive pass through.

## Feasibility Assessment

**Feasible as integration test.** The `validate-wave-handoff-completeness` WASM gate and
`wave-gate` skill are deterministic, file-system-only operations. An integration test can
set up a synthetic `factory-artifacts` checkout with controlled HANDOFF.md content and
invoke the gate directly. No network or real git push required for the gate check itself.

The anti-fabrication cross-checks (git SHA verification) are tested by providing synthetic
`git rev-parse origin/develop` stubs in the test harness.
