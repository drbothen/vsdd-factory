# VP-083: Completeness Gate Is No-Op on Wave-1 and HANDOFF.md Absent

## Property

The `validate-wave-handoff-completeness` WASM gate MUST return `Continue` (not block)
in two specific conditions that must not create false-positive blocking:

1. **Wave-1 no-op:** When the pipeline is on the first wave — determined by the absence of any prior HANDOFF.md on `factory-artifacts` OR by the wave-group ordinal being 1 in the sprint-state.yaml topological sort — regardless of whether HANDOFF.md exists (it may not exist yet on the first wave). There is no `current_wave:` field on STATE.md; "wave 1" is a derived fact, not a stored field.
2. **HANDOFF.md absent AND wave > 1 outside of wave-close context:** When the gate
   fires on a Write/Edit event that is NOT a HANDOFF.md write (e.g., other `factory-artifacts`
   file writes) AND no HANDOFF.md exists yet.

The gate blocks ONLY when:
- The target file being written IS `HANDOFF.md`, AND one or more required fields are
  missing or malformed; OR
- `wave-gate` skill explicitly invokes the gate in "close-wave check" mode AND
  HANDOFF.md is absent AND wave_id > 1.

Formally:
- **Postcondition (wave_id = 1, no HANDOFF.md):** `Continue`. No block.
- **Postcondition (wave_id = 1, HANDOFF.md exists):** `Continue`. No block (gate is wave-1 no-op regardless).
- **Postcondition (wave_id > 1, non-HANDOFF.md write):** `Continue`. No block.
- **Postcondition (wave_id > 1, HANDOFF.md write, all fields present):** `Continue`.
- **Postcondition (wave_id > 1, HANDOFF.md write, field missing):** `HandoffIncomplete(<field_name>)` block.

## Invariant Classification: Invariant (No False-Positive Block)

A false-positive block on wave-1 or on normal file writes would block the factory
from operating at all. This invariant ensures the gate is safe to deploy without
disrupting existing pipelines.

## Proof Harness Skeleton (Unit Test)

```rust
// File: crates/hook-plugins/validate-wave-handoff-completeness/tests/unit_tests.rs
// Anchor: no_false_positive_on_wave_1

use validate_wave_handoff_completeness::{check_handoff_completeness, GateContext, GateResult};

// NOTE: GateContext uses `is_first_wave: bool` (derived from prior-HANDOFF.md absence
// on factory-artifacts OR from wave-group ordinal=1 in sprint-state.yaml topo-sort).
// GateContext does NOT have a `current_wave: u32` field — there is no `current_wave:`
// on STATE.md. The gate receives the first-wave predicate pre-computed by its caller.

#[test]
fn wave_1_no_op_no_handoff() {
    let ctx = GateContext {
        // is_first_wave=true because no prior HANDOFF.md exists on factory-artifacts
        is_first_wave: true,
        file_path: "factory-artifacts/SOME_OTHER_FILE.md".to_string(),
        handoff_content: None,
        close_wave_mode: false,
    };
    assert_eq!(check_handoff_completeness(&ctx), GateResult::Continue);
}

#[test]
fn wave_1_no_op_even_with_handoff_present() {
    let ctx = GateContext {
        // is_first_wave=true even if HANDOFF.md file is being written — wave-1 is unconditional no-op
        is_first_wave: true,
        file_path: "factory-artifacts/HANDOFF.md".to_string(),
        handoff_content: Some("wave_id: 1\n".to_string()),  // incomplete but wave-1 is no-op
        close_wave_mode: false,
    };
    assert_eq!(check_handoff_completeness(&ctx), GateResult::Continue);
}

#[test]
fn wave_gt_1_non_handoff_write_no_block() {
    let ctx = GateContext {
        // is_first_wave=false because prior HANDOFF.md exists on factory-artifacts
        // (sprint-state.yaml topo-sort ordinal > 1)
        is_first_wave: false,
        file_path: "factory-artifacts/STATE.md".to_string(),
        handoff_content: None,
        close_wave_mode: false,
    };
    assert_eq!(check_handoff_completeness(&ctx), GateResult::Continue);
}

#[test]
fn wave_gt_1_handoff_write_missing_sha_blocks() {
    let ctx = GateContext {
        // is_first_wave=false; wave ordinal 3 from sprint-state.yaml topo-sort
        is_first_wave: false,
        file_path: "factory-artifacts/HANDOFF.md".to_string(),
        handoff_content: Some("wave_id: 3\n# missing last_verified_develop_sha\n".to_string()),
        close_wave_mode: false,
    };
    assert!(matches!(
        check_handoff_completeness(&ctx),
        GateResult::Block { code: "HandoffIncomplete", .. }
    ));
}

#[test]
fn wave_gt_1_handoff_write_all_fields_present_continues() {
    let ctx = GateContext {
        // is_first_wave=false; wave ordinal 3 from sprint-state.yaml topo-sort
        is_first_wave: false,
        file_path: "factory-artifacts/HANDOFF.md".to_string(),
        handoff_content: Some(valid_handoff_fixture()),
        close_wave_mode: false,
    };
    assert_eq!(check_handoff_completeness(&ctx), GateResult::Continue);
}
```

## Feasibility Assessment

**Feasible as Rust unit test.** The gate logic is a pure function over a `GateContext`
struct containing the file path, current wave, HANDOFF.md content, and mode flag.
No side effects, no git access required at the unit level. The integration-level
git-SHA cross-check is tested separately in VP-081 integration harness.

WASM fuel consumption is bounded: the gate parses only HANDOFF.md frontmatter fields
(not the body) and does not perform I/O beyond `host::read_file` on the target path.
