# VP-083: Completeness Gate Is No-Op on Wave-1 or Non-HANDOFF.md Writes

## Property

The `validate-wave-handoff-completeness` WASM gate MUST return `Continue` (not block)
in two specific conditions that must not create false-positive blocking:

1. **Wave-1 no-op (PAYLOAD-ONLY):** When `payload.wave_id == 1` — the gate reads `wave_id`
   directly from the HANDOFF Write/Edit payload (`is_first_wave = (payload.wave_id == 1)`).
   No filesystem, git, sprint-state.yaml, or factory-artifacts read is performed to determine
   first-wave status. The shell wave-handoff skill (BC-5.41.001) is responsible for deriving
   `wave_id` from real substrate and embedding it in the payload before writing.
2. **Non-HANDOFF.md target write (wave > 1):** When the gate fires on a Write/Edit event
   whose target file is NOT `HANDOFF.md` (e.g., other `factory-artifacts` file writes such
   as STATE.md, wave-state.yaml, etc.). The gate performs no field validation and returns
   `Continue` unconditionally for non-HANDOFF.md targets regardless of whether a HANDOFF.md
   exists on the branch. The WASM gate is a pure-parse gate operating on the Write/Edit
   payload; it cannot perform a filesystem probe to determine HANDOFF.md file-absence.

The gate blocks ONLY when:
- The target file being written IS `HANDOFF.md`, AND one or more required fields are
  missing or malformed; OR
- `wave_id` is ABSENT from the payload → gate FAILS CLOSED: proceeds to full validation,
  blocking with `HandoffIncomplete: ["wave_id"]` (absent `wave_id` is NOT treated as wave-1).

Formally:
- **Postcondition (payload.wave_id == 1):** `Continue`. No block. Wave-1 no-op unconditional.
- **Postcondition (payload.wave_id > 1, non-HANDOFF.md write):** `Continue`. No block.
- **Postcondition (payload.wave_id > 1, HANDOFF.md write, all fields present):** `Continue`.
- **Postcondition (payload.wave_id > 1, HANDOFF.md write, field missing):** `HandoffIncomplete(<field_name>)` block.
- **Postcondition (wave_id ABSENT from payload):** Gate FAILS CLOSED — proceeds to full validation; blocks with `HandoffIncomplete: ["wave_id"]` (and any other missing required fields). Does NOT return `Continue`.

## Invariant Classification: Invariant (No False-Positive Block)

A false-positive block on wave-1 or on normal file writes would block the factory
from operating at all. This invariant ensures the gate is safe to deploy without
disrupting existing pipelines.

## Proof Harness Skeleton (Unit Test)

```rust
// File: crates/hook-plugins/validate-wave-handoff-completeness/tests/unit_tests.rs
// Anchor: no_false_positive_on_wave_1

use validate_wave_handoff_completeness::{check_handoff_completeness, GateContext, GateResult};

// NOTE: GateContext uses `is_first_wave: bool` computed PAYLOAD-ONLY by the gate itself:
// `is_first_wave = (payload.wave_id == 1)`. The gate reads `wave_id` from the HANDOFF
// Write/Edit payload — no prior-HANDOFF.md filesystem read, no sprint-state.yaml read,
// no git access. The shell wave-handoff skill (BC-5.41.001) derives `wave_id` from real
// substrate and embeds it in the payload before writing. The WASM gate is a CONSUMER of
// `wave_id`, not a DERIVER. Absent `wave_id` is NOT treated as wave-1: it is a fail-closed
// condition (see `wave_id_absent_fails_closed` test below).

#[test]
fn wave_1_no_op_no_handoff() {
    let ctx = GateContext {
        // is_first_wave=true because payload.wave_id == 1 (caller embedded wave_id=1)
        is_first_wave: true,
        file_path: "factory-artifacts/SOME_OTHER_FILE.md".to_string(),
        handoff_content: None,
        close_wave_mode: false,
    };
    assert_eq!(check_handoff_completeness(&ctx), GateResult::Continue);
}

#[test]
fn wave_1_no_op_even_with_handoff_present() {
    let ctx = GateContext {
        // is_first_wave=true because payload.wave_id == 1 — wave-1 is unconditional no-op
        // regardless of HANDOFF.md content; the gate returns Continue without parsing fields
        is_first_wave: true,
        file_path: "factory-artifacts/HANDOFF.md".to_string(),
        handoff_content: Some("wave_id: 1\n".to_string()),  // incomplete but wave-1 is no-op
        close_wave_mode: false,
    };
    assert_eq!(check_handoff_completeness(&ctx), GateResult::Continue);
}

#[test]
fn wave_gt_1_non_handoff_write_no_block() {
    let ctx = GateContext {
        // is_first_wave=false because payload.wave_id > 1 (caller embedded wave_id=2)
        is_first_wave: false,
        file_path: "factory-artifacts/STATE.md".to_string(),
        handoff_content: None,
        close_wave_mode: false,
    };
    assert_eq!(check_handoff_completeness(&ctx), GateResult::Continue);
}

#[test]
fn wave_gt_1_handoff_write_missing_sha_blocks() {
    let ctx = GateContext {
        // is_first_wave=false because payload.wave_id == 3 (caller embedded wave_id=3)
        is_first_wave: false,
        file_path: "factory-artifacts/HANDOFF.md".to_string(),
        handoff_content: Some("wave_id: 3\n# missing last_verified_develop_sha\n".to_string()),
        close_wave_mode: false,
    };
    assert!(matches!(
        check_handoff_completeness(&ctx),
        GateResult::Block { code: "HandoffIncomplete", .. }
    ));
}

#[test]
fn wave_gt_1_handoff_write_all_fields_present_continues() {
    let ctx = GateContext {
        // is_first_wave=false because payload.wave_id == 3 (caller embedded wave_id=3)
        is_first_wave: false,
        file_path: "factory-artifacts/HANDOFF.md".to_string(),
        handoff_content: Some(valid_handoff_fixture()),
        close_wave_mode: false,
    };
    assert_eq!(check_handoff_completeness(&ctx), GateResult::Continue);
}

#[test]
fn wave_id_absent_fails_closed() {
    // EC-010: when wave_id is ABSENT from the payload, the gate does NOT return Continue.
    // It FAILS CLOSED: proceeds to full validation and blocks with HandoffIncomplete: ["wave_id"].
    // Absent wave_id is NOT treated as wave-1. The gate's is_first_wave check requires wave_id
    // to be present and equal to 1; absence is a missing-required-field condition.
    let ctx = GateContext {
        // wave_id absent from payload — gate receives is_first_wave=false (absence is not wave-1)
        is_first_wave: false,
        file_path: "factory-artifacts/HANDOFF.md".to_string(),
        // payload omits wave_id field entirely
        handoff_content: Some("last_verified_develop_sha: abc123\n# wave_id is absent\n".to_string()),
        close_wave_mode: false,
    };
    let result = check_handoff_completeness(&ctx);
    assert!(matches!(
        result,
        GateResult::Block { code: "HandoffIncomplete", .. }
    ), "Expected HandoffIncomplete block when wave_id is absent; gate must fail closed");
    // Additionally verify the block message names wave_id as a missing field
    if let GateResult::Block { message, .. } = result {
        assert!(message.contains("wave_id"),
            "HandoffIncomplete block message must name 'wave_id' when it is absent from payload");
    }
}
```

## Feasibility Assessment

**Feasible as Rust unit test.** The gate logic is a pure function over a `GateContext`
struct containing the file path, `is_first_wave` flag (computed PAYLOAD-ONLY as
`payload.wave_id == 1`), HANDOFF.md content, and mode flag. No filesystem or git access
at the unit level — the `wave_id` value is read from the HANDOFF payload, and
`is_first_wave` is a derived boolean the gate computes before any field validation.
The fail-closed path (absent `wave_id` → HandoffIncomplete) is equally testable as
a unit test: supply a payload with wave_id absent and assert the Block result.
The integration-level git-SHA cross-check is tested separately in VP-081 integration harness.

WASM fuel consumption is bounded: the gate parses only HANDOFF.md frontmatter fields
(not the body) and does not perform I/O beyond `host::read_file` on the target path.
