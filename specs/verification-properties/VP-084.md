# VP-084: PreCompact Flush Commit Is Lifecycle-Distinct From State-Manager Burst Commit

## Property

A PreCompact flush commit on `factory-artifacts` (produced by `precompact-flush.sh`)
is a lifecycle-orthogonal event that MUST NOT be counted as a state-manager burst commit
for TD-VSDD-053 single-commit-per-burst enforcement.

Formally:
- **Precondition:** A PreCompact hook fires mid-wave and `precompact-flush.sh` commits
  to `factory-artifacts` with message matching `PreCompact flush <cycle>/<step> <ISO-timestamp>`
  (canonical format per ADR-026 §Decision 6 step 4; the old `wave-<N>` form is obsolete).
- **Subsequent state-manager burst:** The state-manager performs a normal burst (Commits
  A/B/C/D/E sequence) after the PreCompact flush.
- **Postcondition A:** The `validate-burst-log` hook does NOT fire `MULTI_COMMIT_CHAIN_NOT_ALLOWED`
  for the PreCompact flush commit + the subsequent state-manager burst commit, even if
  both appear in consecutive `git log factory-artifacts` positions.
- **Postcondition B:** The burst-log entry for the state-manager burst contains exactly
  ONE logical burst commit citation. The PreCompact flush commit is NOT cited as a
  Commit A/B/C/D/E step.
- **Postcondition C:** The `MULTI_COMMIT_CHAIN_NOT_ALLOWED` detector fires ONLY for
  state-manager bursts where two consecutive commits both contain "backfill" / "Stage N" /
  "Stage N+1" in their commit messages — NOT for PreCompact prefix commits.

## Invariant Classification: Invariant (Lifecycle Boundary)

This invariant ensures that the factory's TD-VSDD-053 multi-commit-chain detector does not
produce false-positive blocks due to the presence of legitimate PreCompact flush commits in
the `factory-artifacts` history.

## Proof Harness Skeleton (Integration / Bats)

**F-P5-004 note:** The real artifact for `validate-burst-log` is `hook-plugins/validate-burst-log.wasm`, registered in `hooks-registry.toml` as a native WASM plugin invoked via the factory-dispatcher (event: PostToolUse; tool: Edit|Write). There is no `validate-burst-log.sh` shell script. The harness MUST invoke the WASM plugin through the dispatcher by piping a synthetic PostToolUse event JSON — the same path used in production. Direct `bash ... .sh` invocation is incorrect and would silently test nothing.

```bash
# File: plugins/vsdd-factory/tests/precompact-burst-lifecycle.bats
# Anchor: precompact_flush_does_not_trigger_multi_commit_chain_block

@test "PreCompact flush commit followed by state-manager burst does not trigger TD-VSDD-053" {
    # Setup: synthetic factory-artifacts branch
    # Step 1: simulate precompact-flush.sh commit with canonical message format "PreCompact flush <cycle>/<step> <ISO-timestamp>"
    git -C "$FACTORY_ARTIFACTS_DIR" commit --allow-empty -m "PreCompact flush v1.0-feature-context-durability-E18/pass-2 2026-06-14T12:00:00Z"
    # Step 2: append a matching entry to precompact-flush-log (four-field format required by BC-5.41.003 PC1)
    FLUSH_SHA=$(git -C "$FACTORY_ARTIFACTS_DIR" rev-parse HEAD)
    echo "2026-06-14T12:00:00Z ${FLUSH_SHA} v1.0-feature-context-durability-E18/pass-2 commit" >> "$FACTORY_ARTIFACTS_DIR/.factory/hooks/precompact-flush-log"
    # Step 3: simulate state-manager burst commit (Commit E)
    git -C "$FACTORY_ARTIFACTS_DIR" commit --allow-empty -m "state: pass-N burst Commit E — D-NNN codification"
    # Step 4: invoke validate-burst-log WASM via factory-dispatcher (PostToolUse event on Edit tool)
    EVENT_JSON=$(cat <<EOF
{"event":"PostToolUse","tool":"Edit","input":{"file_path":".factory/STATE.md"},"output":{"success":true},"session_id":"test-session"}
EOF
)
    run bash -c "echo '$EVENT_JSON' | ./hooks/dispatcher/bin/$(uname -s | tr '[:upper:]' '[:lower:]')-$(uname -m)/factory-dispatcher"
    # Assert: dispatcher exits 0 (no block_intent for MULTI_COMMIT_CHAIN_NOT_ALLOWED)
    assert_success
    # Assert: no "MULTI_COMMIT_CHAIN" in dispatcher stderr summary
    refute_output --partial "MULTI_COMMIT_CHAIN"
}

@test "Burst-log entry for state-manager burst cites exactly one burst commit" {
    # Setup: burst-log entry written after a PreCompact flush + state-manager burst
    # Invoke validate-burst-log WASM via factory-dispatcher (PostToolUse on Write to .factory/STATE.md)
    EVENT_JSON=$(cat <<EOF
{"event":"PostToolUse","tool":"Write","input":{"file_path":".factory/STATE.md"},"output":{"success":true},"session_id":"test-session"}
EOF
)
    run bash -c "echo '$EVENT_JSON' | ./hooks/dispatcher/bin/$(uname -s | tr '[:upper:]' '[:lower:]')-$(uname -m)/factory-dispatcher"
    assert_success
    # Assert: burst-log entry Parent-commit block cites the state-manager Commit E SHA, not PreCompact SHA
    # (Verified by dispatcher not emitting MULTI_COMMIT_CHAIN_NOT_ALLOWED block)
    refute_output --partial "MULTI_COMMIT_CHAIN"
}
```

## Feasibility Assessment

**Feasible as bats integration test via factory-dispatcher.** The `validate-burst-log`
artifact is `hook-plugins/validate-burst-log.wasm` — a native WASM plugin invoked by the
factory-dispatcher on PostToolUse events for Edit|Write tool calls. A bats test constructs
a synthetic `factory-artifacts` branch with a controlled commit history, writes a synthetic
`precompact-flush-log` with the correct four-field entry for the flush commit, and pipes a
synthetic PostToolUse JSON event to the factory-dispatcher binary. The dispatcher routes the
event to `validate-burst-log.wasm` and returns block_intent (or not) in its exit code and
stderr summary line. This is the production invocation path — it exercises the WASM plugin
through the same event-routing mechanism used at runtime.

**F-P5-004 closure note:** Prior harness versions called `bash plugins/vsdd-factory/hooks/validate-burst-log.sh`, which does not exist. The `validate-burst-log` plugin is a native WASM crate (confirmed by hooks-registry.toml: `plugin = "hook-plugins/validate-burst-log.wasm"`). Invoking a non-existent shell script would cause the test to fail at the `bash` invocation with file-not-found, not at the property assertion — making it a false-red gate. The corrected harness uses the dispatcher binary path, which is the correct verification surface for a WASM plugin.

The key implementation requirement is that the `validate-burst-log` and
`validate-dispatch-advance` WASM plugins MUST be updated to exempt commits with the
`PreCompact flush ` message prefix (the canonical exemption prefix per ADR-026 §Decision 10;
covers all `<cycle>/<step>` forms; the old `PreCompact flush wave-` form is obsolete and
MUST NOT be used as the exemption pattern — it would miss non-wave engine-context commits)
from the MULTI_COMMIT_CHAIN detector, using the three-gate corroboration logic in
BC-5.41.003 PC1 (SHA match + field-4 equals `commit` + genuine-absence fallback).
This exemption MUST be implemented in S-18.04 alongside the hook itself.

The precompact-flush-log four-field entry MUST be present in the test setup for case (a)
(log present, SHA matches, field-4 = `commit`) to be exercised. A separate test vector
MUST omit the log to exercise case (c) (genuine absence → prefix-match alone sufficient).
