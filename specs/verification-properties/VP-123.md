# VP-123: Backfill-Split Content Preservation — Concatenated Shards Reproduce the Original Byte-for-Byte and Every Record Lands in Exactly One Shard

## Property Statement

The one-time backfill-split of a pre-existing oversized append-log preserves content exactly. This
is the load-bearing content-preservation invariant of the whole Layer-2 backfill (BC-1.18.008).

1. **Byte-for-byte reconstruction.** For any monolithic input file, the concatenation of all sealed
   shards in `seq` order followed by the final current file reproduces the original file content
   byte-for-byte (modulo the new shard/index metadata, which is additive) (BC-1.18.008
   §Postcondition 6a). No bytes are lost, added, or reordered across the split.

2. **Record integrity — exactly once.** Every structural record present in the original file
   (a `D-NNN` decision-log row, a burst-log `h2` block, a lessons entry, a session-checkpoint entry)
   appears in EXACTLY ONE resulting shard — never zero, never two (BC-1.18.008 §Postcondition 6b,
   §Invariant 2). Partition points are always at structural record boundaries native to the
   artifact's format, never mid-record.

3. **Correct shard count.** The split produces `ceil(current_bytes / shard_cap_bytes)` partitions
   (BC-1.18.008 §Postcondition 2), each `<= shard_cap_bytes` except a single record legitimately
   larger than the cap (VP scope of §EC-002 `oversized_record: true` is out of this VP's core
   preservation claim but is not violated by it).

The concrete `shard_cap_bytes` is **PROVISIONAL-until-F4**; the preservation and record-integrity
properties hold for any cap and any structural boundary set, so they are locked now.

| Record integrity (exactly once) | proptest | Rust `proptest!` over synthetic fixtures with known record counts | property: `sum(records_per_shard) == original_record_count`, each record in exactly one shard | feasible-pending-harness (F4 code) |

### Why proptest / golden-file

Content preservation is a universal round-trip property over arbitrary monolithic inputs (variable
size, variable record boundaries) — proptest's generated fixtures plus golden-file round-trips
against real oversized cycle-log samples give far stronger assurance than a single hand-crafted
example, exactly the assurance a data-preserving one-time migration demands.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/proptest_backfill_preservation.rs
// VP-123: BC-1.18.008 PC2/PC6/INV2

proptest! {
    #[test]
    fn prop_concat_reproduces_original(mono in arb_monolithic_appendlog(), cap in arb_cap()) {
        let out = shard_manager::backfill_split(&mono, cap);
        let recombined = out.sealed.iter().map(|s| s.bytes()).chain([out.current.bytes()]).concat();
        prop_assert_eq!(recombined, mono.bytes());               // byte-for-byte
    }

    #[test]
    fn prop_every_record_in_exactly_one_shard(mono in arb_appendlog_with_known_records(), cap in arb_cap()) {
        let out = shard_manager::backfill_split(&mono, cap);
        prop_assert_eq!(out.total_records(), mono.record_count());
        prop_assert!(out.no_record_spans_two_shards());
    }
}
```
