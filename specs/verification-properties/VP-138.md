# VP-138: Staged Roll Self-Heals a Truncate-After-Seal Crash (E-SHD-006)

## Property Statement

BC-1.18.006's roll is a STAGED, four-step, crash-recoverable operation — (a) read canonical content,
(b) publish the sealed shard as a brand-new `<stem>.<seq:04>.md` file, (c) atomically truncate the
canonical file's content in place, (d) publish the shard-index entry — with three distinct crash
points (one named `E-SHD-NNN` code each, ADR-051 Decision 11). This VP covers the SECOND crash point:
step (c) fails AFTER step (b) succeeded (`E-SHD-006`).

1. **Post-crash state is a detectable duplicate, never data loss.** When the truncate (step (c))
   fails after the sealed-shard publish (step (b)) succeeded, the sealed shard `<stem>.<seq:04>.md`
   durably exists holding a byte-for-byte copy of the pre-roll content, AND the canonical file STILL
   holds that same content (not yet truncated) — a transient, DETECTABLE duplicate-content state,
   not a data-loss state (BC-1.18.006 §Postcondition 1 step (c) / §EC-010). No item is lost: the
   full content is recoverable from EITHER file.

2. **Self-healing resume-from-truncate.** On the NEXT dispatch attempt for this artifact, BEFORE
   evaluating any new trigger, the gate checks whether a sealed shard exists at the index's
   next-expected `seq` path whose content is byte-identical to the canonical file's CURRENT content;
   if so, it recognizes "seal published, truncate did not" and resumes from step (c) ALONE —
   re-attempting only the truncate + index publish, NEVER re-writing the already-correct sealed
   shard (BC-1.18.006 §Postcondition 1 step (c) recovery). No operator intervention is required.

3. **Idempotent by construction.** Because step (b)'s `write_atomic` create is itself a no-op if
   reissued against identical content, re-running the sequence — whether it resumes from (c) or
   restarts from (a) — never produces a second sealed shard, a doubled `[[shard]]` index entry, or a
   lost record. After recovery the census holds: exactly one sealed shard at that `seq`, the
   canonical file correctly empty, and the index carrying exactly one appended entry for the roll.

4. **Canonical filename never renamed away.** Throughout the crash-and-recover cycle the canonical
   path (e.g. `decision-log.md`) resolves to SOME valid file at every observable instant — pre-roll
   content, then (after recovery's atomic replace-onto-existing truncate) empty — never absent, and
   never renamed to a sealed name (BC-1.18.006 §Invariant 3).

### Why integration

Crash-atomicity and self-healing recovery are real-substrate filesystem/process properties: the
partial-write must be induced against a live filesystem and the recovery observed across two
dispatch invocations — the fault-injection integration class VP-124 / VP-133 use for the analogous
mechanism-A / B2 crash-recovery legs. A pure unit test cannot express the two-invocation
detect-and-resume behavior.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/shard_roll_eshd006_recovery_test.rs
// VP-138: BC-1.18.006 PC1 step (c) / EC-010 — E-SHD-006 self-healing resume-from-truncate

#[test]
fn test_BC_1_18_006_EC010_truncate_after_seal_crash_is_detectable_duplicate_not_loss() {
    let cx = DispatchHarness::with_cycle_fixture(current_bytes = 45_000, cap = 49_152);
    let content_before = cx.read("decision-log.md");
    cx.inject_fs_failure_at_step_c();                       // truncate fails after seal publish
    let _ = cx.dispatch_write("decision-log.md", payload = 5_000);
    assert!(cx.path_exists("decision-log.0001.md"));        // sealed shard durably published
    assert_eq!(cx.read("decision-log.0001.md"), content_before);
    assert_eq!(cx.read("decision-log.md"), content_before); // canonical NOT yet truncated (duplicate)
    // no data loss: content recoverable from either file
}

#[test]
fn test_BC_1_18_006_EC010_next_dispatch_self_heals_resume_from_truncate() {
    let cx = DispatchHarness::with_cycle_fixture(current_bytes = 45_000, cap = 49_152);
    let sealed_before = { cx.inject_fs_failure_at_step_c();
                          cx.dispatch_write("decision-log.md", payload = 5_000);
                          cx.read("decision-log.0001.md") };
    cx.clear_fs_failure();
    cx.dispatch_write("decision-log.md", payload = 5_000);  // next attempt self-heals
    assert_eq!(cx.read("decision-log.0001.md"), sealed_before); // sealed shard NOT rewritten
    assert_eq!(cx.byte_len("decision-log.md"), 0);          // canonical now truncated
    assert_eq!(cx.read_shard_index("decision-log").shards.iter().filter(|s| s.seq == 1).count(), 1);
}
```
