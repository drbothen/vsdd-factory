# VP-087: wave-state.yaml Is Produced Atomically With HANDOFF.md, Stories List Derives From Real Substrate, BrokenSprintState Blocks on Non-Terminal Stories

## Property

The `wave-handoff` skill MUST satisfy four provable properties when invoked at wave close:

### §1 Atomicity — wave-state.yaml and HANDOFF.md Committed Together

`wave-state.yaml` and `HANDOFF.md` MUST appear in a single git commit on the
`factory-artifacts` branch. No path exists where one file is committed without the other
(except the EPIC-COMPLETE exception defined in §4 below, where `wave-state.yaml` is
deliberately absent).

- **Precondition:** `wave-handoff` is invoked; stories in `sprint-state.yaml` have
  `status: pending` or `status: draft`.
- **Postcondition (PC1):** `git log --name-only -1 factory-artifacts` lists BOTH
  `wave-state.yaml` and `HANDOFF.md` in the same commit. Commit message matches
  `HANDOFF wave-<N> <ISO-timestamp>` pattern (ADR-026 §Decision 4 commit-message form).

### §2 Stories List Derives From Real Substrate — No Phantom Fields, No RAG

The `stories` list in `wave-state.yaml` MUST derive exclusively from:
1. `sprint-state.yaml` entries with `status: pending` or `status: draft`.
2. The dependency-order graph from `STORY-INDEX.md` `depends_on:` arrays (topological sort).
3. Each story's `spec_files:` derived from that story's `bcs:` frontmatter array (resolved
   to file paths) and any `arch_deps:` entries.

No `wave:` frontmatter field on story files is referenced (that field does not exist per
DI-023). No semantic vector retrieval (RAG) is performed over the spec corpus.

- **Precondition:** Two invocations of `wave-handoff` on the same `sprint-state.yaml` +
  `STORY-INDEX.md` state.
- **Postcondition (PC2):** Both invocations produce byte-identical `stories` and
  `arch_files` lists (modulo `generated_at` timestamp and `generated_from_handoff_sha`).
  This is the determinism invariant from BC-5.41.002 Inv2.
- **Negative postcondition:** A story with `status: in-progress`, `status: blocked`, or
  any non-terminal, non-pending status does NOT appear in `wave-state.yaml`.

### §3 BrokenSprintState — Hard Error on Non-Terminal Stories With No Pending/Draft

When `sprint-state.yaml` has no entries with `status: pending` or `status: draft`, BUT
one or more entries have a non-terminal, non-pending/draft status (e.g., `status: in-progress`,
`status: blocked`), the `wave-handoff` skill MUST abort with exit 1.

This requirement applies to ANY status token that is neither a terminal state
(`merged`, `withdrawn`, `cancelled`) nor a pending/draft state (`pending`, `draft`).
It includes explicitly enumerated non-terminal active states (`in-progress`, `blocked`,
`partial`) AND any UNKNOWN/unenumerated token not in the terminal or pending/draft set
(e.g., a future `review-pending` or a misspelled `inprogress`). Per ADR-026
§Terminal-Wave Discriminator: terminal states are `merged/withdrawn/cancelled`; non-terminal
active states are `pending/draft/partial/in-progress/blocked`; "Unknown/unrecognized status
values are treated as non-terminal for safety." BC-5.41.002 EC-001b establishes the hard
error: any entry with non-terminal status (e.g., `in-progress`, `blocked`) and no
pending/draft entries present triggers BrokenSprintState exit 1.

- **Precondition A (enumerated):** `sprint-state.yaml` contains no pending/draft entries;
  at least one entry has `status: in-progress` or `status: blocked`.
- **Postcondition (PC3):** `wave-handoff` exits 1; stderr contains the canonical message:
  "BrokenSprintState: stories in non-terminal, non-pending states exist but no next-wave
  stories are pending/draft. Update sprint-state.yaml to reflect actual story states."
  (ADR-026 §Terminal-Wave Discriminator). No `wave-state.yaml` is written. No
  `HANDOFF.md` is written for this BrokenSprintState path.
- **Precondition B (unenumerated):** `sprint-state.yaml` contains no pending/draft entries;
  at least one entry has a DELIBERATELY UNKNOWN status token (e.g., `status: review-pending`)
  that is not in any known status set (not terminal, not pending/draft, not a known active
  state). This is the discriminating fixture that prevents a hard-coded `in-progress`/`blocked`-
  only implementation from passing while violating EC-001b.
- **Postcondition (PC3b):** Same as PC3 — `wave-handoff` exits 1 with the canonical
  BrokenSprintState message; no `wave-state.yaml` written; no `HANDOFF.md` written.
- **Anti-postcondition:** A silent exit 0 or a `wave-state.yaml` with `stories: []`
  written silently is a SOUL.md §4 violation (DI-023 empty-list hard error). An
  implementation that only checks for known status tokens and silently exits 0 on an
  unknown token also violates this property.

### §4 EPIC-COMPLETE Exception — No wave-state.yaml Written, Exit 0

When ALL entries in `sprint-state.yaml` have terminal status (merged, withdrawn, or
cancelled) and there are no pending/draft entries, `wave-handoff` MUST:
- Exit 0.
- Write `HANDOFF.md` with `epic_status: complete` and `next_wave_stories: []`.
- NOT write `wave-state.yaml`.
- Emit the EPIC-COMPLETE operator stdout message before exiting (BC-5.41.002 PC7).

- **Precondition:** `sprint-state.yaml` has no pending/draft entries; all entries have
  terminal status.
- **Postcondition (PC4):** Exit 0; `HANDOFF.md` present on `factory-artifacts` with
  `epic_status: complete`; `wave-state.yaml` absent from the commit. Stdout contains the
  EPIC-COMPLETE message per BC-5.41.002 PC7.

## Why This VP Is Safety-Critical

BC-5.41.002 Inv1 makes `wave-state.yaml` the SOLE rehydration vehicle for the
`rehydrate-wave` skill (BC-6.24.001). If `wave-state.yaml` can be written without
`HANDOFF.md` in the same commit (atomicity failure), or if its `stories` list derives from
phantom fields or RAG rather than real substrate (DI-023 violation), rehydration produces
incorrect or incomplete context at wave start. BrokenSprintState silence (§3) is a SOUL.md
§4 violation that causes subsequent waves to silently skip stories that were never resolved.

## Proof Harness Skeleton (Integration — Bats)

```bash
# File: plugins/vsdd-factory/tests/wave-handoff-bats.bats
# Anchor: wave_handoff_atomicity_and_substrate_derivation

@test "wave-state.yaml and HANDOFF.md committed in single git commit" {
    # Setup: factory-artifacts git repo fixture; sprint-state.yaml with S-18.02 status=pending,
    #        S-18.03 status=draft; STORY-INDEX.md with both stories; wave-handoff invoked.
    # Invoke: run_wave_handoff_skill
    # Assert: git log --name-only -1 factory-artifacts lists both wave-state.yaml and HANDOFF.md
    # Assert: git log --format="%s" -1 factory-artifacts matches "^HANDOFF wave-[0-9]+ "
    run git -C "$FACTORY_ARTIFACTS_DIR" log --name-only -1
    assert_output --partial "wave-state.yaml"
    assert_output --partial "HANDOFF.md"
    # Assert: ONLY one commit was produced (no double-commit)
    COMMIT_COUNT=$(git -C "$FACTORY_ARTIFACTS_DIR" log --oneline | head -5 | grep -c "HANDOFF wave-")
    [ "$COMMIT_COUNT" -eq 1 ]
}

@test "wave-state.yaml stories list derives from sprint-state.yaml status:pending/draft only" {
    # Setup: sprint-state.yaml: S-18.02 status=pending, S-18.03 status=draft,
    #        S-18.01 status=in-progress (non-pending — must not appear in manifest)
    # Invoke: run_wave_handoff_skill
    # Assert: wave-state.yaml stories list contains S-18.02 and S-18.03
    # Assert: wave-state.yaml does NOT contain S-18.01
    MANIFEST=$(git -C "$FACTORY_ARTIFACTS_DIR" show factory-artifacts:wave-state.yaml)
    echo "$MANIFEST" | grep -q "S-18.02"
    echo "$MANIFEST" | grep -q "S-18.03"
    refute ( echo "$MANIFEST" | grep -q "S-18.01" )
}

@test "wave-state.yaml is deterministic across two invocations on same input" {
    # Setup: same sprint-state.yaml + STORY-INDEX.md as above
    # Invoke wave-handoff twice; capture stories+arch_files from both runs (strip generated_at + sha)
    # Assert: stripped lists are byte-identical
    MANIFEST_1=$(extract_stories_and_arch_files "$FIRST_RUN_MANIFEST")
    MANIFEST_2=$(extract_stories_and_arch_files "$SECOND_RUN_MANIFEST")
    [ "$MANIFEST_1" = "$MANIFEST_2" ]
}

@test "wave-handoff exits 1 with BrokenSprintState error when non-terminal stories and no pending" {
    # Setup: sprint-state.yaml: S-18.01 status=in-progress; no status=pending or status=draft
    # Covers Precondition A (enumerated non-terminal state — BC-5.41.002 EC-001b)
    # Invoke: run_wave_handoff_skill
    # Assert: exit code 1
    # Assert: stderr contains canonical BrokenSprintState message
    assert_failure
    assert_stderr --partial "BrokenSprintState: stories in non-terminal, non-pending states exist"
    # Assert: wave-state.yaml NOT written
    run git -C "$FACTORY_ARTIFACTS_DIR" show factory-artifacts:wave-state.yaml
    assert_failure  # file does not exist on factory-artifacts
}

@test "wave-handoff exits 1 with BrokenSprintState error when story has UNKNOWN unenumerated status" {
    # Setup: sprint-state.yaml: S-18.01 status=review-pending (deliberately unknown/unenumerated
    #        token — not terminal, not pending/draft, not a known active state).
    # No status=pending or status=draft entries present.
    # Covers Precondition B (unenumerated) — discriminates against hard-coded in-progress/blocked
    # only implementations that would silently pass an unknown token (BC-5.41.002 EC-001b).
    # Invoke: run_wave_handoff_skill
    # Assert: exit code 1 (BrokenSprintState fires on unknown status, not just known active states)
    assert_failure
    # Assert: stderr contains canonical BrokenSprintState message
    assert_stderr --partial "BrokenSprintState: stories in non-terminal, non-pending states exist"
    # Assert: wave-state.yaml NOT written (PC3b)
    run git -C "$FACTORY_ARTIFACTS_DIR" show factory-artifacts:wave-state.yaml
    assert_failure  # file does not exist on factory-artifacts
    # Assert: HANDOFF.md NOT written for this BrokenSprintState path
    run git -C "$FACTORY_ARTIFACTS_DIR" show factory-artifacts:HANDOFF.md
    assert_failure
}

@test "wave-handoff exits 0 with EPIC-COMPLETE when all stories terminal" {
    # Setup: sprint-state.yaml: S-18.01 status=merged, S-18.02 status=merged, S-18.03 status=merged
    # Invoke: run_wave_handoff_skill
    # Assert: exit 0
    # Assert: HANDOFF.md has epic_status: complete
    # Assert: wave-state.yaml NOT written
    # Assert: stdout contains EPIC-COMPLETE message
    assert_success
    HANDOFF=$(git -C "$FACTORY_ARTIFACTS_DIR" show factory-artifacts:HANDOFF.md)
    echo "$HANDOFF" | grep -q "epic_status: complete"
    run git -C "$FACTORY_ARTIFACTS_DIR" show factory-artifacts:wave-state.yaml
    assert_failure  # wave-state.yaml not present for EPIC-COMPLETE
    assert_output --partial "EPIC-COMPLETE: All stories in sprint-state.yaml"
}
```

## Feasibility Assessment

**Feasible as bats integration test.** The `wave-handoff` skill is a shell/script-based
deliverable (S-18.01). Bats tests can:

1. Set up a minimal `factory-artifacts` git worktree fixture with controlled
   `sprint-state.yaml` and `STORY-INDEX.md` inputs.
2. Invoke the `wave-handoff` skill (or its underlying orchestration script) in a controlled
   environment.
3. Assert on the resulting git commit structure (both files present), `wave-state.yaml`
   content, exit codes, and stderr messages.

The atomicity assertion (single commit with both files) and the BrokenSprintState error
message are directly observable via `git log --name-only -1`. The EPIC-COMPLETE path
(wave-state.yaml absent, HANDOFF.md has `epic_status: complete`) is verifiable by checking
whether `git show factory-artifacts:wave-state.yaml` fails.

The context-injection step (presenting content to the LLM) is out of scope for this VP —
that layer is covered by VP-088 (rehydrate-wave skill).
