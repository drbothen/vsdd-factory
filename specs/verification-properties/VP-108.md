# VP-108: marker.cleared Audited-Clear Event — Clear Path Emission Correctness (BC-1.18.003 §PC1/PC3/PC4; ADR-048 §D4)

## Property Statement

For each of the three audited clear paths defined in BC-1.18.003 and ADR-048 §Decision 4,
when a `.factory/unvalidated-mutation.marker` is cleared, the dispatcher MUST emit a
`marker.cleared` event to the sink with the correct `clear_mode`, `actor_type`, `trace_id`,
`plugin_name`, `artifact_path`, `reason` (when applicable), and `timestamp` fields. The
crash-path native TTL-allow path (BC-1.18.003 §EC-014) MUST NOT emit a `marker.cleared`
event.

The four postconditions are:

**Postcondition 1 — REVALIDATED clear (BC-1.18.003 §PC1):**
When the same plugin+artifact_path pair that wrote the marker subsequently returns a PASS
outcome via `evaluate_gate`, the gate plugin deletes the marker (idempotent) and emits:
`marker.cleared` with `clear_mode = "REVALIDATED"`, `actor_type = "validator"`,
`trace_id = <current trace_id>`, `plugin_name = <plugin_name>`,
`artifact_path = <artifact_path>`, `reason = null` (absent), `timestamp = <ISO8601>`.

**Postcondition 2 — TTL_EXPIRED clear (BC-1.18.003 §PC4 — TTL-loudness) [v1.1 — dispatcher-native, corrected]:**
When the dispatcher-native `check_and_clear_expired_marker` pre-check (called from `executor.rs`'s
tier-execution loop, before invoking the Arm 1/Arm 2 WASM gate plugin) finds `expires_at <=
now(UTC)` (expired marker), it auto-deletes the marker and emits: `marker.cleared` with
`clear_mode = "TTL_EXPIRED"`, `actor_type = "deadman"`, `trace_id = <marker's own trace_id>`,
`plugin_name = <marker's own plugin_name>`, `artifact_path = <marker's own artifact_path>`,
`reason = null` (absent), `timestamp = <ISO8601>`. This is the TTL-loudness requirement per
ADR-048 §Decision 4 — TTL auto-expiry is now an audited event, not a silent self-healing path.
**Correction (v1.1, ADR-048 §D4 v1.2):** this MUST NOT be emitted from inside the WASM gate
plugin's `evaluate_gate` — the `emit_event` host ABI's RESERVED_FIELDS enrichment would
unconditionally overwrite `trace_id`/`plugin_name` with the CURRENT gate-plugin's own dispatch
identity, not the marker's, making the wire contract above structurally unachievable from WASM.
By the time `evaluate_gate` runs (after this pre-check), the marker is guaranteed already
absent-or-non-expired, so `evaluate_gate` performs no TTL logic of its own.

**Postcondition 3 — OPERATOR_OVERRIDE clear (BC-1.18.003 §PC3 + ADR-048 §D4) [v1.1 — dispatcher-native, corrected]:**
When the dispatcher-native `reconcile_raw_delete` function (invoked from the same pre-check's
marker-absent branch) detects a `RAW_DELETE_DETECTED` condition (operator out-of-band marker
removal that occurred while the dispatcher was running, inferred via a bounded scan of the
current day's FileSink `events-*.jsonl` for an unmatched `plugin.indeterminate`), it
retroactively emits: `marker.cleared` with `clear_mode = "OPERATOR_OVERRIDE"`, `actor_type =
"operator"`, `trace_id = <trace_id from the unmatched plugin.indeterminate event>`, `plugin_name
= <plugin_name>` (from the same unmatched event), `artifact_path = <artifact_path>` (from the
same unmatched event), `reason = <non-null string describing the operator action>`, `timestamp =
<ISO8601>`. The `reason` field MUST be non-null for OPERATOR_OVERRIDE. **Correction (v1.1,
ADR-048 §D4 v1.2):** this was PREVIOUSLY ENTIRELY UNIMPLEMENTED (S-25.01 pass-2 F-P2-003 MED);
this postcondition's function anchor (`reconcile_raw_delete`) is dispatcher-native for the same
RESERVED_FIELDS-wall reason as Postcondition 2 — it was never a candidate for WASM-plugin-side
implementation once the wall is understood.

**Postcondition 4 — Crash-path native TTL-allow does NOT emit (BC-1.18.003 §EC-014):**
When the dispatcher's native `block_if_marker_check` check finds an expired marker (PC6 path:
crash + absent/expired marker → Allow), the dispatcher allows the dispatch WITHOUT emitting
a `marker.cleared` event. Only `check_and_clear_expired_marker` (the normal-path pre-check;
Postcondition 2, v1.1 — corrected from "the gate plugin's `evaluate_gate` path") emits
`marker.cleared` on TTL_EXPIRED. The crash-path and the normal-path pre-check are distinct
dispatcher-native functions; `block_if_marker_check` runs only on plugin crash/timeout and does
not call `check_and_clear_expired_marker` or `emit_marker_cleared`.

**Wire format (BC-3.08.001 Event 9 / ADR-048 §Decision 4):**

| Field | Type | Required? | Notes |
|-------|------|-----------|-------|
| `type` | string | always | `"marker.cleared"` |
| `clear_mode` | string enum | always | `"REVALIDATED"` / `"TTL_EXPIRED"` / `"OPERATOR_OVERRIDE"` |
| `actor_type` | string enum | always | `"validator"` / `"deadman"` / `"operator"` |
| `trace_id` | string | always | Non-null in nominal operation |
| `plugin_name` | string | always | Name of the plugin that wrote the marker (or last-known for OPERATOR_OVERRIDE) |
| `artifact_path` | string | always | Path of the artifact that was being validated |
| `reason` | string | OPERATOR_OVERRIDE only; null/absent otherwise | Description of operator action |
| `timestamp` | string (ISO8601) | always | Emission timestamp |

## Source Contract

- **BC:** BC-1.18.003 §PC1 — REVALIDATED clear: PASS outcome for same plugin+artifact triggers
  marker delete + emit `marker.cleared(REVALIDATED, validator, trace_id, reason=null)`.
- **BC:** BC-1.18.003 §PC3 — OPERATOR_OVERRIDE retroactive reconciliation: RAW_DELETE_DETECTED
  → emit `marker.cleared(OPERATOR_OVERRIDE, operator, trace_id, reason=non-null)`.
- **BC:** BC-1.18.003 §PC4 — TTL_EXPIRED clear with loudness: `expires_at <= now` → marker
  auto-delete + emit `marker.cleared(TTL_EXPIRED, deadman, trace_id, reason=null)`.
- **BC:** BC-1.18.003 §EC-014 — crash-path native TTL-allow does NOT emit `marker.cleared`.
- **BC:** BC-3.08.001 Event 9 — `marker.cleared` wire format: eight mandatory fields; `reason`
  conditional (non-null for OPERATOR_OVERRIDE, absent/null for others).
- **ADR:** ADR-048 §Decision 4 — Audited Clear Event: introduces `marker.cleared` as the 9th
  dispatcher domain event; defines three `clear_mode` values and `actor_type` mapping; mandates
  TTL-loudness (TTL auto-expiry now emits audited event); defines RAW_DELETE_DETECTED
  reconciliation for OPERATOR_OVERRIDE.
- **ADR:** ADR-048 §Decision 4 v1.2 Emission-Point Correction (S-25.01 LOCAL adversary pass 2
  F-P2-002 HIGH + F-P2-003 MED) — ALL THREE `clear_mode` emissions are dispatcher-native
  (`emit_marker_cleared` in `indeterminate_marker.rs`), never emitted from inside the WASM gate
  plugin via `emit_event` (RESERVED_FIELDS enrichment makes a foreign trace_id/plugin_name
  structurally unachievable from WASM). TTL_EXPIRED is detected+cleared by
  `check_and_clear_expired_marker` (new); OPERATOR_OVERRIDE is detected+reconciled by
  `reconcile_raw_delete` (new) — both run in `executor.rs`'s tier-execution loop before invoking
  the Arm 1/Arm 2 plugin on the normal path. `guard_logic::evaluate_gate` no longer contains any
  TTL or emission logic.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| unit-test | Rust (#[test] within dispatcher crate) | yes — 4 test functions | (PC1) REVALIDATED path: `delete_marker_if_pass` with valid marker + matching PostToolUse PASS outcome → `marker.cleared` emitted with `clear_mode=REVALIDATED`, `actor_type=validator`, `reason=null` [v1.1: corrected from "`evaluate_gate` with... PASS outcome" — `evaluate_gate` is the PreToolUse gate-decision function and never receives a PostToolUse PASS outcome; the REVALIDATED clear pathway is `delete_marker_if_pass`, called from `executor.rs`'s PostToolUse callsites]; (PC2) TTL_EXPIRED path: `check_and_clear_expired_marker` with expired `expires_at` → `marker.cleared` emitted with `clear_mode=TTL_EXPIRED`, `actor_type=deadman`, `reason=null` [v1.1: corrected from "`evaluate_gate` with expired `expires_at`" — moved dispatcher-native per ADR-048 §D4 v1.2]; (PC3) OPERATOR_OVERRIDE path: `reconcile_raw_delete` RAW_DELETE_DETECTED reconciliation → `marker.cleared` emitted with `clear_mode=OPERATOR_OVERRIDE`, `actor_type=operator`, `reason=non-null` [v1.1: dispatcher-native, corrected]; (PC4) crash-path native-TTL-allow: `block_if_marker_check` with expired marker → returns Allow, NO `marker.cleared` emitted |

### Why unit-test

All four postconditions are verifiable as pure unit tests:
- PC1/PC2/PC3 test the `emit_marker_cleared` call site in `indeterminate_marker.rs` via
  controlled marker fixtures. The emission function is pure (takes data in, produces event).
- PC4 tests that `block_if_marker_check` (dispatcher native check) does NOT call
  `emit_marker_cleared` — verifiable by asserting the sink event count before/after.

No end-to-end bats harness is required for these structural emission properties. The integration
harness for VP-079 Event 9 will extend to cover the full dispatch-chain emission of
`marker.cleared` in Phase-6 formal hardening (consistent with VP-079's SITE_8 scope note
pattern for new event types).

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/src/tests/vp_108_marker_cleared_event.rs
// VP-108: BC-1.18.003 §PC1/PC3/PC4 + BC-3.08.001 Event 9 + ADR-048 §D4
// marker.cleared audited-clear event emission correctness.

#[cfg(test)]
mod vp_108 {
    use super::*;
    use crate::indeterminate_marker::{
        delete_marker_if_pass, check_and_clear_expired_marker, reconcile_raw_delete,
        MarkerClearedEvent,
    };
    use crate::sink::test_helpers::CapturingSink;
    use std::fs;
    use tempfile::TempDir;

    /// Postcondition 1 (BC-1.18.003 §PC1): REVALIDATED clear emits marker.cleared correctly.
    /// Same plugin+artifact_path PASS outcome → delete marker + emit REVALIDATED event.
    #[test]
    fn test_revalidated_clear_emits_marker_cleared() {
        let dir = TempDir::new("vp108_revalidated").unwrap();
        let marker_path = dir.path().join(".factory").join("unvalidated-mutation.marker");
        fs::create_dir_all(dir.path().join(".factory")).unwrap();
        // Write a valid, non-expired marker
        fs::write(
            &marker_path,
            "timestamp = \"2026-08-31T00:00:00Z\"\n\
             plugin_name = \"regression-gate\"\n\
             artifact_path = \"/tmp/.factory/STATE.md\"\n\
             cause = \"fuel\"\n\
             trace_id = \"deadbeef-0108-0001-0001-000000000001\"\n\
             expires_at = \"2099-01-01T00:00:00Z\"\n",
        ).unwrap();

        let sink = CapturingSink::new();
        let trace_id = "deadbeef-0108-0001-0001-000000000001";
        // Call delete_marker_if_pass with matching plugin+artifact PASS outcome
        delete_marker_if_pass(
            &marker_path,
            "regression-gate",
            "/tmp/.factory/STATE.md",
            trace_id,
            &sink,
        ).unwrap();

        // marker.cleared MUST be emitted
        let events = sink.events();
        assert_eq!(events.len(), 1, "VP-108 PC1: exactly one marker.cleared event must be emitted");
        let event = &events[0];
        assert_eq!(event.r#type, "marker.cleared", "VP-108 PC1: type must be 'marker.cleared'");
        assert_eq!(event.clear_mode, "REVALIDATED", "VP-108 PC1: clear_mode must be 'REVALIDATED'");
        assert_eq!(event.actor_type, "validator", "VP-108 PC1: actor_type must be 'validator'");
        assert_eq!(event.trace_id, trace_id, "VP-108 PC1: trace_id must match");
        assert_eq!(event.plugin_name, "regression-gate", "VP-108 PC1: plugin_name must match marker");
        assert_eq!(event.artifact_path, "/tmp/.factory/STATE.md", "VP-108 PC1: artifact_path must match");
        assert!(event.reason.is_none(), "VP-108 PC1: reason must be null/absent for REVALIDATED");
        assert!(!event.timestamp.is_empty(), "VP-108 PC1: timestamp must be present");
        // marker must be deleted
        assert!(!marker_path.exists(), "VP-108 PC1: marker must be deleted after REVALIDATED clear");
    }

    /// Postcondition 2 (BC-1.18.003 §PC4 + ADR-048 §D4 TTL-loudness):
    /// TTL_EXPIRED clear emits marker.cleared — TTL auto-expiry is now audited.
    #[test]
    fn test_ttl_expired_clear_emits_marker_cleared() {
        let dir = TempDir::new("vp108_ttl").unwrap();
        let marker_path = dir.path().join(".factory").join("unvalidated-mutation.marker");
        fs::create_dir_all(dir.path().join(".factory")).unwrap();
        // Write a marker with an expired expires_at
        fs::write(
            &marker_path,
            "timestamp = \"2020-01-01T00:00:00Z\"\n\
             plugin_name = \"regression-gate\"\n\
             artifact_path = \"/tmp/.factory/STATE.md\"\n\
             cause = \"fuel\"\n\
             trace_id = \"deadbeef-0108-0002-0002-000000000002\"\n\
             expires_at = \"2020-01-02T00:00:00Z\"\n",
        ).unwrap();

        let sink = CapturingSink::new();
        let trace_id = "deadbeef-0108-0002-0002-000000000002";
        // v1.1 (ADR-048 §D4 v1.2): check_and_clear_expired_marker is the dispatcher-native
        // pre-check — a plain Rust function call, NOT a WASM invocation. It is called from
        // executor.rs's tier-execution loop BEFORE the Arm 1/Arm 2 gate plugin runs. There is
        // no `evaluate_gate_with_sink` — that name described a cross-WASM-boundary call that
        // cannot exist (a WASM guest cannot hold a reference to a host-side CapturingSink).
        let now = chrono::DateTime::parse_from_rfc3339("2020-01-03T00:00:00Z")
            .unwrap()
            .with_timezone(&chrono::Utc);
        let cleared = check_and_clear_expired_marker(dir.path(), now, &sink)
            .expect("VP-108 PC2: check_and_clear_expired_marker must not error");
        assert!(cleared.is_some(), "VP-108 PC2: expired marker must be detected and cleared");

        let events = sink.events();
        assert_eq!(events.len(), 1, "VP-108 PC2: exactly one marker.cleared event must be emitted");
        let event = &events[0];
        assert_eq!(event.r#type, "marker.cleared", "VP-108 PC2: type must be 'marker.cleared'");
        assert_eq!(event.clear_mode, "TTL_EXPIRED", "VP-108 PC2: clear_mode must be 'TTL_EXPIRED'");
        assert_eq!(event.actor_type, "deadman", "VP-108 PC2: actor_type must be 'deadman'");
        assert_eq!(event.trace_id, trace_id, "VP-108 PC2: trace_id must be the MARKER's own trace_id, not the gate plugin's dispatch trace_id");
        assert!(event.reason.is_none(), "VP-108 PC2: reason must be null/absent for TTL_EXPIRED");
        assert!(!marker_path.exists(), "VP-108 PC2: expired marker must be auto-deleted");

        // Companion assertion (v1.1): after the native pre-check runs, evaluate_gate (the WASM
        // gate plugin's pure presence-check, unit-tested separately in the hook-plugins crate)
        // must see the marker as absent and return Allow with no TTL logic of its own. This
        // cross-crate assertion belongs to the hook-plugins crate's own test suite, not here —
        // noted for test-writer AC completeness.
    }

    /// Postcondition 3 (BC-1.18.003 §PC3 + ADR-048 §D4 RAW_DELETE_DETECTED):
    /// OPERATOR_OVERRIDE clear emits marker.cleared with non-null reason.
    #[test]
    fn test_operator_override_clear_emits_marker_cleared_with_reason() {
        let sink = CapturingSink::new();
        let trace_id = "deadbeef-0108-0003-0003-000000000003";
        let reason = "operator manually deleted marker via rm during active session";
        // reconcile_raw_delete is called when RAW_DELETE_DETECTED condition is observed
        reconcile_raw_delete(
            "regression-gate",
            "/tmp/.factory/STATE.md",
            trace_id,
            reason,
            &sink,
        );

        let events = sink.events();
        assert_eq!(events.len(), 1, "VP-108 PC3: exactly one marker.cleared event must be emitted");
        let event = &events[0];
        assert_eq!(event.clear_mode, "OPERATOR_OVERRIDE", "VP-108 PC3: clear_mode must be 'OPERATOR_OVERRIDE'");
        assert_eq!(event.actor_type, "operator", "VP-108 PC3: actor_type must be 'operator'");
        assert!(
            event.reason.as_deref().map(|r| !r.is_empty()).unwrap_or(false),
            "VP-108 PC3: reason MUST be non-null and non-empty for OPERATOR_OVERRIDE \
             (BC-1.18.003 §PC3; ADR-048 §D4)"
        );
    }

    /// Postcondition 4 (BC-1.18.003 §EC-014):
    /// Crash-path native TTL-allow does NOT emit marker.cleared.
    /// block_if_marker_check with expired marker returns Allow without emitting any event.
    #[test]
    fn test_crash_path_native_ttl_allow_does_not_emit_marker_cleared() {
        let dir = TempDir::new("vp108_crash_ttl").unwrap();
        let marker_path = dir.path().join(".factory").join("unvalidated-mutation.marker");
        fs::create_dir_all(dir.path().join(".factory")).unwrap();
        // Write a marker with an expired expires_at
        fs::write(
            &marker_path,
            "timestamp = \"2020-01-01T00:00:00Z\"\n\
             plugin_name = \"regression-gate\"\n\
             artifact_path = \"/tmp/.factory/STATE.md\"\n\
             cause = \"epoch\"\n\
             trace_id = \"deadbeef-0108-0004-0004-000000000004\"\n\
             expires_at = \"2020-01-02T00:00:00Z\"\n",
        ).unwrap();

        let sink = CapturingSink::new();
        // block_if_marker_check is the dispatcher native check, separate from evaluate_gate
        let decision = block_if_marker_check(&marker_path, &sink);
        assert_eq!(decision, BlockIfMarkerDecision::Allow,
            "VP-108 PC4: crash-path expired marker MUST return Allow (BC-1.18.003 §EC-014; ADR-048 §D1 PC6)");

        // MUST NOT emit marker.cleared — crash-path native check is not an audited clear path
        let events = sink.events();
        assert!(
            events.iter().all(|e| e.r#type != "marker.cleared"),
            "VP-108 PC4: crash-path native TTL-allow MUST NOT emit marker.cleared \
             (BC-1.18.003 §EC-014; ADR-048 §D4)"
        );
    }
}
```
