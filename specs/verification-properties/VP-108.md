# VP-108: Marker Lifecycle Audited Events — Write and Clear Path Emission Correctness (BC-1.18.001 §PC4; BC-1.18.003 §PC1/PC3/PC4/PC5; ADR-048 §D4 v1.5)

## Property Statement

**Write path (new, v1.3 — ADR-048 §D4 v1.4 / F-P6-001):** When the dispatcher successfully writes
`.factory/unvalidated-mutation.marker` (BC-1.18.001 PC4 — PostToolUse, fail-closed, INDETERMINATE),
it MUST emit `marker.written` (BC-3.08.001 Event 10) via `HostContext::emit_internal` immediately
after the write succeeds — never before the write is attempted, never when the write fails. This is
the positive creation record that makes the OPERATOR_OVERRIDE reconciliation premise (below) sound.

**Clear path (BC-1.18.003 §PC1/PC3/PC4/PC5):** For each of the four audited clear paths
(REVALIDATED, TTL_EXPIRED, OPERATOR_OVERRIDE, and — as of v1.2 — SUPERSEDED), when a
`.factory/unvalidated-mutation.marker` is cleared or overwritten, the dispatcher MUST emit a
`marker.cleared` event via `HostContext::emit_internal` (never a raw `InternalLog::write`, never
the WASM `emit_event` host ABI) with the correct `clear_mode`, `actor_type`, `trace_id`,
`plugin_name`, `artifact_path`, `reason` (when applicable), and `timestamp` fields. The
crash-path native TTL-allow path (BC-1.18.003 §EC-014) MUST NOT emit a `marker.cleared`
event.

The eight postconditions are (PC1–PC5 are clear-path; PC6 is the write-path postcondition; PC7 is
the negative control that directly regression-tests F-P6-001; PC8 is the negative control that
directly regression-tests F-P9-001):

**Postcondition 1 — REVALIDATED clear (BC-1.18.003 §PC1) [v1.8 — trace_id-source/emission-locus/
trigger corrected, F-P15-001]:**
When the marker's own plugin+artifact_path pair is dispatched again and the NAMED validator's
PostToolUse invocation produces a PASS outcome (`classify_outcome == Pass`) — guarded in
`executor.rs`'s `execute_tier` by `marker_plugin == entry_clone.name && entry_clone.event ==
"PostToolUse"` (a PreToolUse PASS from the same plugin MUST NOT clear the marker, per BC-1.18.003
INV2) — the dispatcher (NOT the WASM gate plugin) reads all marker fields via
`read_all_marker_fields(&marker_path)` BEFORE deletion, calls `delete_marker_if_pass` (idempotent),
and on `Ok(true)` emits, via `emit_marker_cleared(&base_ctx_for_event, fields, "REVALIDATED",
"validator", None)`: `marker.cleared` with `clear_mode = "REVALIDATED"`, `actor_type =
"validator"`, `trace_id = <the marker's own trace_id, read from the marker TOML before deletion>`,
`plugin_name = <marker's own plugin_name>`, `artifact_path = <marker's own artifact_path>`,
`reason = null` (absent), `timestamp = <ISO8601>`. **Correction (v1.8, F-P15-001):** this
postcondition's delete+emit is DISPATCHER-NATIVE for the same RESERVED_FIELDS-wall reason already
documented at Postconditions 2/3/5 below — a WASM gate plugin cannot emit an event carrying the
marker's foreign trace_id/plugin_name, since the `emit_event` host ABI's RESERVED_FIELDS enrichment
unconditionally overwrites `trace_id`/`plugin_name` with the CURRENT gate-plugin's own dispatch
identity. `evaluate_gate` (the WASM gate plugin) only returns an Allow/Block marker-presence
decision and performs no clear-emission of its own; the PASS that triggers this postcondition is
`classify_outcome == Pass`, produced by the NAMED validator's own PostToolUse invocation, NOT
`evaluate_gate`. Pre-v1.8, this postcondition incorrectly attributed the trigger to `evaluate_gate`,
the emission locus to "the gate plugin," and the `trace_id` to `<current trace_id>` (rather than
the marker's own, read from the marker TOML) — a partial-fix regression: the F-P2-002/F-P3-001
emission-locus + trace_id-source corrections (see Postconditions 2/3/5's own "Correction" notes)
were applied there but never swept into this postcondition.

**Postcondition 2 — TTL_EXPIRED clear (BC-1.18.003 §PC4 — TTL-loudness) [v1.2 — emission-mechanism
corrected]:**
When the dispatcher-native `check_and_clear_expired_marker` pre-check (called from `executor.rs`'s
tier-execution loop, before invoking the Arm 1/Arm 2 WASM gate plugin) finds `expires_at <=
now(UTC)` (expired marker), it auto-deletes the marker and emits, via `ctx.emit_internal(ev)`:
`marker.cleared` with `clear_mode = "TTL_EXPIRED"`, `actor_type = "deadman"`, `trace_id = <marker's
own trace_id>`, `plugin_name = <marker's own plugin_name>`, `artifact_path = <marker's own
artifact_path>`, `reason = null` (absent), `timestamp = <ISO8601>`. This is the TTL-loudness
requirement per ADR-048 §Decision 4 — TTL auto-expiry is now an audited event, not a silent
self-healing path. **Correction (v1.1, ADR-048 §D4 v1.2):** this MUST NOT be emitted from inside
the WASM gate plugin's `evaluate_gate` — the `emit_event` host ABI's RESERVED_FIELDS enrichment
would unconditionally overwrite `trace_id`/`plugin_name` with the CURRENT gate-plugin's own
dispatch identity, not the marker's, making the wire contract above structurally unachievable from
WASM. By the time `evaluate_gate` runs (after this pre-check), the marker is guaranteed already
absent-or-non-expired, so `evaluate_gate` performs no TTL logic of its own. **Further correction
(v1.2, ADR-048 §D4 v1.3):** the emission call itself MUST be `ctx.emit_internal(ev)` (`ctx: &
HostContext`), NOT a raw `log.write(&ev)` call on a bare `&InternalLog` — `emit_internal` is the
same dual-sink primitive (InternalLog + `ctx.events` stub queue) every sibling BC-3.08.001
dispatcher-native event already uses; a raw `InternalLog::write` silently diverges from that
established pattern (S-25.01 pass-3 F-P3-001 MEDIUM) and never reaches `ctx.events` (the queue
`VSDD_SINK_FILE` and the future S-4.07 Router/FileSink both drain).

**Postcondition 3 — OPERATOR_OVERRIDE clear (BC-1.18.003 §PC3 + ADR-048 §D4) [v1.3 — reconciliation
premise corrected]:**
When the dispatcher-native `reconcile_raw_delete` function (invoked from the same pre-check's
marker-absent branch) detects a `RAW_DELETE_DETECTED` condition (operator out-of-band marker
removal that occurred while the dispatcher was running, inferred via a bounded scan of the
current day's `dispatcher-internal-{date}.jsonl` — see scan-target correction below — for an
unmatched `marker.written`), it retroactively emits, via `ctx.emit_internal(ev)`:
`marker.cleared` with `clear_mode = "OPERATOR_OVERRIDE"`, `actor_type =
"operator"`, `trace_id = <trace_id from the unmatched marker.written event>`, `plugin_name
= <plugin_name>` (from the same unmatched event), `artifact_path = <artifact_path>` (from the
same unmatched event), `reason = <non-null string describing the operator action>`, `timestamp =
<ISO8601>`. The `reason` field MUST be non-null for OPERATOR_OVERRIDE. **Correction (v1.1,
ADR-048 §D4 v1.2):** this was PREVIOUSLY ENTIRELY UNIMPLEMENTED (S-25.01 pass-2 F-P2-003 MED);
this postcondition's function anchor (`reconcile_raw_delete`) is dispatcher-native for the same
RESERVED_FIELDS-wall reason as Postcondition 2 — it was never a candidate for WASM-plugin-side
implementation once the wall is understood. **Further correction (v1.2, ADR-048 §D4 v1.3) — scan
target:** the bounded scan MUST target `<InternalLog log_dir>/dispatcher-internal-{date}.jsonl`
(obtained via `ctx.internal_log.as_ref().map(|l| l.log_dir())`), NOT a literal `events-{date}
.jsonl`. `InternalLog` is the only log every default production dispatcher run writes
unconditionally; a literal `events-{date}.jsonl` file is not durably produced absent an opt-in
`VSDD_SINK_FILE` or the not-yet-`main.rs`-wired S-4.07 Router/FileSink. Scanning a file that is
not durably written would make RAW_DELETE_DETECTED permanently inert in every real deployment —
this is a load-bearing correction, not a cosmetic rename (S-25.01 pass-3 F-P3-001 MEDIUM).
**Further correction (v1.3, ADR-048 §D4 v1.4) — scan MATCH TYPE and premise:** the scan MUST match
on unmatched `"marker.written"` records (BC-3.08.001 Event 10), NOT unmatched
`"plugin.indeterminate"` records (with or without a `failure_policy == "fail-closed"` filter). The
pre-v1.3 premise — "an unmatched fail-closed `plugin.indeterminate` proves a marker was durably
written" — is FALSE: `plugin.indeterminate` (Event 8) is emitted for EVERY INDETERMINATE outcome
regardless of hook phase (BC-3.08.001 Event 8 trigger), while the marker write is PostToolUse-only
(BC-1.18.001 INV4) and may itself fail (EC-007). A PreToolUse fail-closed INDETERMINATE (verified
reachable via `validate-factory-path-staging`, PreToolUse `^Bash$` fail-closed, Cohort
A-immediate/EFFECTIVE-NOW) or a PostToolUse marker-write I/O failure both produce an unmatched
`plugin.indeterminate` with NO marker ever written — under the pre-v1.3 premise,
`reconcile_raw_delete` would fabricate `marker.cleared(OPERATOR_OVERRIDE)` for these cases
(S-25.01 adversary pass 6 F-P6-001 MEDIUM). `marker.written` is emitted ONLY after a confirmed
successful marker write (Postcondition 6), so an unmatched `marker.written` record is
definitionally proof a marker existed and was later cleared by something other than the three
already-audited paths — the reconciliation premise is TRUE BY CONSTRUCTION under the v1.3 scan
target, not merely narrowed. The `failure_policy == "fail-closed"` filter on the OLD
`"plugin.indeterminate"` match arm is REMOVED — it is structurally redundant against
`"marker.written"`, which is never emitted for a fail-open dispatch.

**Postcondition 4 — Crash-path native TTL-allow does NOT emit (BC-1.18.003 §EC-014):**
When the dispatcher's native `block_if_marker_check` check finds an expired marker (PC6 path:
crash + absent/expired marker → Allow), the dispatcher allows the dispatch WITHOUT emitting
a `marker.cleared` event. Only `check_and_clear_expired_marker` (the normal-path pre-check;
Postcondition 2) emits `marker.cleared` on TTL_EXPIRED. The crash-path and the normal-path
pre-check are distinct dispatcher-native functions; `block_if_marker_check` runs only on plugin
crash/timeout and does not call `check_and_clear_expired_marker`, `reconcile_raw_delete`, or
`emit_marker_cleared`.

**Postcondition 5 — SUPERSEDED clear (BC-1.18.001 INV3 cross-pair overwrite; ADR-048 §D4 v1.3;
S-25.01 pass-3 F-P3-002 LOW) [NEW in v1.2; emission point corrected in v1.4]:**
When `write_indeterminate_marker`'s caller detects that a marker ALREADY EXISTS for a `(plugin_
name, artifact_path)` pair DIFFERENT from the new INDETERMINATE event about to overwrite it
(single-marker last-writer-wins, BC-1.18.001 INV3), it reads the EXISTING marker's fields BEFORE
the temp+rename overwrite — this read is unavoidable, since the write itself overwrites the file
the fields are read from — and, **only after `write_indeterminate_marker` returns `Ok(())`**
(**correction, v1.4, ADR-048 §D4 v1.5 — see below**), via `ctx.emit_internal(ev)`, emits:
`marker.cleared` with `clear_mode = "SUPERSEDED"`, `actor_type = "system"`, `trace_id = <SUPERSEDED
marker's own trace_id>`, `plugin_name = <SUPERSEDED marker's own plugin_name>`, `artifact_path =
<SUPERSEDED marker's own artifact_path>`, `reason = "SUPERSEDED: marker overwritten by a new
plugin.indeterminate event for a different (plugin_name, artifact_path) pair before being
cleared; last-writer-wins (BC-1.18.001 INV3)"` (non-null — `SUPERSEDED` joins `OPERATOR_OVERRIDE`
as a `reason`-mandatory `clear_mode`), `timestamp = <ISO8601, time of the overwrite>`. When the
existing marker's `(plugin_name, artifact_path)` is the SAME as the new event's, NO `SUPERSEDED`
event is emitted (continuous quarantine of the same target, not a cross-pair supersession).
**Correction (v1.4, ADR-048 §D4 v1.5, S-25.01 pass-9 F-P9-001 MEDIUM) — emission point:** pre-v1.4,
this postcondition described the emission as occurring BEFORE the overwrite, unconditionally on
the pre-overwrite READ, not on the WRITE's outcome. That formulation is FALSE-fabricating: if
`write_indeterminate_marker` subsequently returns `Err(_)` (EC-007, disk full / permissions,
swallowed best-effort — the identical failure mode the v1.3 `marker.written` fix already accounts
for), the OLD marker is still durably present and still enforcing, yet a SUPERSEDED record has
already been emitted falsely claiming it was overwritten — a fabricated audit record under the
identical NIST AU-3/AU-10 defect class this postcondition exists to close. The corrected rule:
emission happens ONLY after `write_indeterminate_marker` confirms `Ok(())`, in the SAME arm as
Postcondition 6's `marker.written` emission (both fire back-to-back in that arm: SUPERSEDED for the
OLD pair, if applicable, then `marker.written` for the NEW pair). On `Err(_)`: NEITHER event is
emitted (see Postcondition 8). Rationale: without this event, `reconcile_raw_delete` (Postcondition 3) has no record that the
superseded pair was ever cleared, and a LATER raw-delete of the (now-different) marker causes it
to falsely emit `marker.cleared(OPERATOR_OVERRIDE)` for the superseded pair — attributing a human
action that never happened to that pair (a NIST AU-3/AU-10 event-content/non-repudiation defect).
`SUPERSEDED` closes the gap: `reconcile_raw_delete`'s existing `type == "marker.cleared" =>
unmatched.remove(&key)` match logic already treats any `clear_mode` as closing the key, so no
change to Postcondition 3's matching logic is required.

**Postcondition 6 — `marker.written` creation emission (BC-1.18.001 PC4 v1.4; BC-3.08.001 Event 10;
ADR-048 §D4 v1.4; S-25.01 adversary pass 6 F-P6-001 MEDIUM) [NEW in v1.3]:**
When `write_indeterminate_marker` returns `Ok(())` (the atomic marker write succeeded), its caller
(`executor.rs`, the same INDETERMINATE-outcome callsite that also calls
`emit_superseded_if_cross_pair`) emits, via `ctx.emit_internal(ev)` and the new `emit_marker_written`
function (`indeterminate_marker.rs`): `marker.written` with `trace_id = <the marker's own
trace_id — the current dispatch's trace_id>`, `plugin_name = <the marker's own plugin_name>`,
`artifact_path = <the marker's own artifact_path>`, `cause = <the marker's own cause>`,
`expires_at = <the marker's own expires_at>`, `timestamp = <ISO8601, time of the write>`. When
`write_indeterminate_marker` returns `Err(_)` (write failure, EC-007), NO `marker.written` event is
emitted — this is the entire point of the postcondition: a write FAILURE must never produce the
same positive-creation record a write SUCCESS produces, or the reconciliation premise in
Postcondition 3 (v1.3) would be unsound again for the write-failure case.

**Postcondition 7 — negative control: PreToolUse fail-closed INDETERMINATE does not fabricate
OPERATOR_OVERRIDE (BC-1.18.001 INV4; ADR-048 §D4 v1.4; S-25.01 adversary pass 6 F-P6-001 MEDIUM,
direct regression test) [NEW in v1.3]:**
Given a fail-closed `plugin.indeterminate` (Event 8) record on a PreToolUse dispatch — which, per
BC-1.18.001 INV4/PC4, NEVER triggers a marker write, and therefore NEVER emits `marker.written`
(Postcondition 6) — a subsequent `reconcile_raw_delete(factory_root, ctx)` call with the marker
absent (trivially, correctly absent — none was ever written) MUST NOT emit
`marker.cleared(OPERATOR_OVERRIDE)` for that `(plugin_name, artifact_path)` pair.
`ctx.drain_events()` after the call MUST be empty (or contain only events unrelated to this pair).
This is the direct regression test for F-P6-001: the pre-v1.3 proof harness for Postcondition 3
seeded a raw `plugin.indeterminate` JSON line directly into the fixture log and asserted
`reconcile_raw_delete` DOES emit `OPERATOR_OVERRIDE` — that fixture is INDISTINGUISHABLE, under the
pre-v1.3 implementation, from the genuinely-defective PreToolUse case this postcondition now
regression-tests; it MASKED the bug by construction (it never seeded a PreToolUse-shaped event,
only a generic `plugin.indeterminate` line with no `event` phase context, and the pre-v1.3
implementation could not tell the two apart). Postcondition 7 seeds the same
`plugin.indeterminate` shape but asserts the OPPOSITE outcome — this positive/negative test PAIR
(PC3 positive: unmatched `marker.written` → reconcile; PC7 negative: unmatched
`plugin.indeterminate` with no `marker.written` → NO reconcile) is what proves the fix, not either
test in isolation.

**Postcondition 8 — negative control: cross-pair overwrite with write FAILURE emits NEITHER
SUPERSEDED NOR marker.written (BC-1.18.001 PC4/INV3; ADR-048 §D4 v1.5; S-25.01 adversary pass 9
F-P9-001 MEDIUM, direct regression test) [NEW in v1.4]:**
Given an existing marker for pair A `(plugin_a, artifact_a)` and a new INDETERMINATE event for a
DIFFERENT pair B `(plugin_b, artifact_b)` about to overwrite it, when
`write_indeterminate_marker(&pair_b_fields, &marker_path)` returns `Err(_)` (simulating EC-007 —
e.g. an unwritable parent directory), the caller MUST NOT emit `marker.cleared(clear_mode=
"SUPERSEDED")` for pair A, and MUST NOT emit `marker.written` for pair B. `ctx.drain_events()`
after the call MUST be empty. This is the direct regression test for F-P9-001: the pre-v1.4 proof
harness for Postcondition 5 emitted the SUPERSEDED event BEFORE calling
`write_indeterminate_marker` at all, so the fixture could not distinguish "the overwrite is about
to happen" from "the overwrite happened" — a write failure was structurally unrepresentable in
that harness ordering. Postcondition 8 forces the write to be attempted (and to fail) BEFORE any
emission decision is made, proving the corrected `executor.rs` ordering (read old fields → attempt
write → emit only on `Ok(())`) actually withholds both events on failure. This is structurally
parallel to Postcondition 7 (which regression-tests the OPERATOR_OVERRIDE fabrication route) but
covers the SUPERSEDED-specific fabrication route PC7 does not exercise — PC7's fixture never
attempts a write at all (PreToolUse never reaches the marker-write branch), whereas PC8's fixture
DOES attempt a write (and that write fails), which is the scenario unique to the SUPERSEDED
emission point.

## Source Contract

- **BC:** BC-1.18.001 §PC4 (v1.4 addition) — marker write success → emit `marker.written` with the
  marker's own trace_id/plugin_name/artifact_path/cause/expires_at; write failure → no emission.
- **BC:** BC-1.18.003 §PC1 — REVALIDATED clear: PASS outcome for same plugin+artifact triggers
  marker delete + emit `marker.cleared(REVALIDATED, validator, trace_id, reason=null)`.
- **BC:** BC-1.18.003 §PC3 (v1.5 correction) — OPERATOR_OVERRIDE retroactive reconciliation:
  RAW_DELETE_DETECTED against unmatched `marker.written` (NOT `plugin.indeterminate`) → emit
  `marker.cleared(OPERATOR_OVERRIDE, operator, trace_id, reason=non-null)`.
- **BC:** BC-1.18.003 §PC4 — TTL_EXPIRED clear with loudness: `expires_at <= now` → marker
  auto-delete + emit `marker.cleared(TTL_EXPIRED, deadman, trace_id, reason=null)`.
- **BC:** BC-1.18.003 §EC-014 — crash-path native TTL-allow does NOT emit `marker.cleared`.
- **BC:** BC-1.18.001 INV3 (v1.4 correction) — SUPERSEDED clear: cross-pair marker overwrite under
  single-marker last-writer-wins → emit `marker.cleared(SUPERSEDED, system, superseded pair's own
  trace_id, reason=non-null)` only after `write_indeterminate_marker` returns `Ok(())` (NOT before
  the overwrite is attempted); on `Err(_)`, no SUPERSEDED emission.
- **BC:** BC-3.08.001 Event 9 — `marker.cleared` wire format: eight mandatory fields; `reason`
  conditional (non-null for OPERATOR_OVERRIDE and — v1.3 — SUPERSEDED, absent/null for others).
- **ADR:** ADR-048 §Decision 4 — Audited Clear Event: introduces `marker.cleared` as the 9th
  dispatcher domain event; defines three `clear_mode` values and `actor_type` mapping; mandates
  TTL-loudness (TTL auto-expiry now emits audited event); defines RAW_DELETE_DETECTED
  reconciliation for OPERATOR_OVERRIDE.
- **ADR:** ADR-048 §Decision 4 v1.3 Emission-Mechanism Precision Correction (S-25.01 LOCAL
  adversary pass 3 F-P3-001 MEDIUM + F-P3-002 LOW) — ALL FOUR `clear_mode` emissions go via
  `ctx.emit_internal(ev)` (`ctx: &HostContext`), never a raw `InternalLog::write` and never the
  WASM `emit_event` host ABI; `reconcile_raw_delete`'s scan target is `dispatcher-internal-{date}

  `actor_type = "system"` emitted by `write_indeterminate_marker`'s caller at cross-pair overwrite.
- **ADR:** ADR-048 §Decision 4 v1.2 Emission-Point Correction (S-25.01 LOCAL adversary pass 2
  F-P2-002 HIGH + F-P2-003 MED) — ALL THREE `clear_mode` emissions are dispatcher-native
  (`emit_marker_cleared` in `indeterminate_marker.rs`), never emitted from inside the WASM gate
  plugin via `emit_event` (RESERVED_FIELDS enrichment makes a foreign trace_id/plugin_name
  structurally unachievable from WASM). TTL_EXPIRED is detected+cleared by
  `check_and_clear_expired_marker` (new); OPERATOR_OVERRIDE is detected+reconciled by
  `reconcile_raw_delete` (new) — both run in `executor.rs`'s tier-execution loop before invoking
  the Arm 1/Arm 2 plugin on the normal path. `guard_logic::evaluate_gate` no longer contains any
  TTL or emission logic.
- **ADR:** ADR-048 §Decision 4 v1.4 Reconciliation-Premise Correction (S-25.01 adversary pass 6
  F-P6-001 MEDIUM) — new `marker.written` event (BC-3.08.001 Event 10), emitted by
  `write_indeterminate_marker`'s caller ONLY after a confirmed successful write;
  `reconcile_raw_delete`'s scan retargeted from unmatched `plugin.indeterminate`
  (`failure_policy=fail-closed`) to unmatched `marker.written` — closing the false-attribution gap
  reachable via any PreToolUse fail-closed INDETERMINATE (marker never written, BC-1.18.001 INV4)
  or PostToolUse marker-write I/O failure (EC-007).
- **ADR:** ADR-048 §Decision 4 v1.5 Emission-Point Correction (S-25.01 adversary pass 9 F-P9-001
  MEDIUM) — `emit_superseded_if_cross_pair`'s call relocated from before `write_indeterminate_
  marker`'s call to inside its `Ok(())` arm, alongside `emit_marker_written`; on `Err(_)`, NEITHER
  `marker.cleared(SUPERSEDED)` NOR `marker.written` is emitted. HUMAN-RATIFIED 2026-09-01 (POLICY
  22; D-1142); no wire-format or event-count change.

### Why unit-test

All eight postconditions are verifiable as pure unit tests using the SAME `HostContext::new(...)`
+ `ctx.drain_events()` harness already proven for the rest of the BC-3.08.001 catalog (e.g.
`host/emit_event.rs`'s `test_BC_3_08_001_s19_05_t003a_...`) — with the two module-location
exceptions PC1 and PC4 noted below (corrected v1.7/F-P12-001):
- PC2/PC3/PC5/PC6/PC7/PC8 construct a `HostContext` (with `internal_log: Some(Arc::new(InternalLog::new
  (tempdir)))` where the function under test also needs a durable log — PC3, PC5, PC6, PC7, PC8's
  file-backed fixtures in particular), call the function under test, then call `ctx.drain_events()`
  and assert on the returned `Vec<InternalEvent>`'s `type_`/`fields`. `HostContext::emit_internal`
  is deterministic given its inputs (takes data in, produces/queues an event) — no WASM invocation,
  no network, no non-determinism.
- PC1 (module-location exception, v1.7/F-P12-001): its real implementing test,
  `test_BC_1_18_003_named_plugin_pass_clears_marker_via_execute_tiers`, lives in
  `crates/factory-dispatcher/tests/marker_integration.rs`, not `indeterminate_marker.rs`'s
  `#[cfg(test)] mod tests`. It is a `#[tokio::test(flavor = "current_thread")]` integration test
  that compiles a real WASM PASS plugin and drives the full `execute_tiers` pipeline — deterministic
  and bounded (no external I/O, no non-determinism beyond the WASM engine's own reproducible
  execution), but not a pure-function unit test in the PC2/PC3/PC5/PC6/PC7/PC8 sense. It asserts on
  the durably-written `dispatcher-internal-{date}.jsonl` log rather than on a bare `ctx.drain_events()`
  return value, because the `HostContext` used internally by `execute_tiers` is not directly
  observable from the test's call site.
- PC4 (module-location + structural exception, v1.7/F-P12-001): `block_if_marker_check` (dispatcher
  native check) and its caller `plugin_block_if_marker` take NO `HostContext`/sink parameter at all
  — there is no `ctx.drain_events()` to assert on, and none is needed: the absence of a sink
  parameter in the function signature is itself the proof that neither function can call
  `emit_internal`/`emit_marker_cleared`. Its real implementing test,
  `test_BC_1_18_002_block_if_marker_crashed_expired_marker_allows`, lives in `executor.rs`'s own
  `#[cfg(test)] mod tests` (sibling to, but a separate module from, `indeterminate_marker.rs`'s),
  because `plugin_block_if_marker` — the crash-path wrapper this postcondition's "crash-path"
  framing refers to — is private to `executor.rs`.
- PC7 (negative control) requires the fixture log to seed a `plugin.indeterminate` record ONLY
  (no `marker.written` record) — the absence of `marker.written` in the fixture is itself the
  test condition, distinguishing it from PC3's fixture, which seeds BOTH the eligibility context
  AND an explicit `marker.written` line.
- PC8 (negative control, NEW v1.4; test anchor corrected v1.6/F-P12-001) exercises
  `emit_write_tied_audit_events(ctx, write_result, marker_path, existing, fields)`
  (`indeterminate_marker.rs`) DIRECTLY, passing a synthesized `Err(io::Error)` as `write_result` —
  this helper takes the write's `io::Result<()>` as a parameter rather than calling
  `write_indeterminate_marker` itself precisely so the `Err(_)` no-emit path is unit-testable
  without forcing a real filesystem failure (per the helper's own doc comment). `existing =
  Some(&pair_a)` (a DIFFERENT `(plugin_name, artifact_path)` pair than `fields`/pair B) exercises
  the cross-pair SUPERSEDED path — the sibling positive control,
  `test_ADR_048_D4_v1_3_superseded_clear_emits_for_cross_pair_overwrite`, already covers the
  `Ok(())` arm and is intentionally not re-derived here. This distinguishes PC8 from PC7, whose
  fixture never attempts a write at all (the PreToolUse case never reaches the write branch): PC8
  proves that a write which IS attempted and DOES fail correctly suppresses both tied events,
  because `emit_write_tied_audit_events` is now the single place (both `executor.rs` callsites
  route through it, TD-VSDD-060) that makes the Ok(())/Err(_) emission decision. (The pre-v1.6
  skeleton described this postcondition as forcing `write_indeterminate_marker` itself to fail via
  an unwritable path fixture — that pattern remains valid for PC6, which still calls
  `write_indeterminate_marker` directly, but PC8's real implementing test calls the extracted
  helper instead, per the F-P12-001 correction.)

No end-to-end bats harness is required for these structural emission properties. The integration
harness for VP-079 Event 9 will extend to cover the full dispatch-chain emission of
`marker.cleared` in Phase-6 formal hardening (consistent with VP-079's SITE_8 scope note
pattern for new event types).
