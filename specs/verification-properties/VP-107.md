# VP-107: Ungated-Escape Invariant: rm, Edit/Write, and TTL Auto-Expiry Are Never Blocked by the Next-Advance Gate (BC-1.18.002 §INV6; ADR-048 §D3)

## Property Statement

The `validate-unvalidated-mutation-marker` gate (Arm 1: `^Agent$`; Arm 2: `^Bash$` with
`is_git_commit_or_push` command filter) MUST NEVER gate the three recovery operations, even
while a non-expired `.factory/unvalidated-mutation.marker` exists (ADR-048 §Decision 3;
BC-1.18.002 §INV6).

**Postcondition A — `rm .factory/unvalidated-mutation.marker` is ungated (INV6-i):**
A Bash dispatch of `rm .factory/unvalidated-mutation.marker` is NOT gated by Arm 2 of the
`validate-unvalidated-mutation-marker` gate, regardless of marker state. This follows from
`is_git_commit_or_push` returning `false` for this command: Phase 2 of the filter identifies
`basename("rm") = "rm" ≠ "git"`, so the Arm 2 filter returns `false`; Arm 1 applies only to
`^Agent$` dispatches, not to `^Bash$`. Confirmed ungated by construction. (EC-031)

**Postcondition B — Edit and Write re-validation dispatches are ungated (INV6-ii):**
Edit and Write tool dispatches are NOT gated by either arm of the gate. Arm 1 fires only on
tool name matching `^Agent$`; Arm 2 fires only on tool name matching `^Bash$`. "Edit" and
"Write" match neither `^Agent$` nor `^Bash$` in any registry-level regex evaluation, so neither
arm is triggered for these tools. Confirmed ungated by construction. (EC-032)

**Postcondition C — TTL auto-expiry provides passive self-healing with no dispatch required (INV6-iii):**
After `UNVALIDATED_MUTATION_MARKER_TTL_SECONDS` (86400) seconds have elapsed since the marker
was written, any subsequent gate evaluation on the normal execution path finds `expires_at ≤ now
(UTC)` and returns `exit_code=0` (Allow), auto-deleting the expired marker (BC-1.18.003 §PC4).
No operator dispatch of any kind is required for this self-healing path. On the crash path,
the dispatcher's native `block_if_marker` check also finds the marker expired and returns Allow
(ADR-048 §Decision 1 — PC6). In either case, the system escapes the quarantine state passively.
(EC-033)

**Why formalize as an explicit VP:** ADR-048 §Decision 1 tightened the gate's crash behavior
(block_if_marker — see VP-105 PC-G/PC-H). A future refactor that accidentally (a) expanded
Arm 2's command filter to match `rm`, or (b) added `Edit`/`Write` to a gate arm's `tool`
pattern, or (c) made TTL expiry require a dispatch, would close the escape surface and produce
an irrecoverable quarantine state. VP-107 provides a load-bearing unit test verifying all three
escape paths remain open, ensuring future refactors cannot silently break recoverability.

## Source Contract

- **BC:** BC-1.18.002 §INV6 — Ungated-Escape Invariant: the gate MUST NEVER block (a) the
  `rm .factory/unvalidated-mutation.marker` Bash dispatch; (b) Edit/Write dispatches; (c) TTL
  auto-expiry (no dispatch required). Three independent recoverability guarantees.
- **ADR:** ADR-048 §Decision 3 — Ungated-Escape Invariant: formalizes the three escape paths
  and mandates they be verified by VP-107. Block_if_marker crash behavior (Decision 1) does not
  affect any of these three paths.
- **ADR:** ADR-048 §Decision 2 — Marker TTL Deadman: `UNVALIDATED_MUTATION_MARKER_TTL_SECONDS
  = 86_400`. TTL check on normal path is in the gate plugin's `evaluate_gate`; on crash path in
  the dispatcher's `block_if_marker_check`.
- **ADR:** ADR-047 §Decision 4 — gate `tool` patterns: Arm 1 `^Agent$`, Arm 2 `^Bash$`.
  Edit/Write are not in either pattern.
- **BC:** BC-1.18.003 §PC4 — TTL-expiry clear: expired marker → Allow + auto-delete on normal
  path.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| unit-test | Rust (#[test] within plugin crate) | yes — 3 test functions | (A) `is_git_commit_or_push("rm .factory/unvalidated-mutation.marker")` → false (EC-031): basename "rm" ≠ "git"; (B) tool-pattern structural: "Edit" does not match `^Agent$` or `^Bash$`; "Write" does not match `^Agent$` or `^Bash$` (EC-032); (C) `evaluate_gate` called with expired `expires_at` (≤ now UTC) → Allow (`GateDecision::Allow`); marker auto-deleted (EC-033, INV6-iii) |

### Why unit-test

All three escape path properties are verifiable as pure unit tests in the plugin crate:
- (A) is a pure function test of `is_git_commit_or_push` with a specific input string.
- (B) is a structural regex assertion (no runtime call needed; Rust `regex::Regex::new(r"^Agent$").is_match("Edit")` → false).
- (C) is a pure function test of `evaluate_gate` with a controlled expired-timestamp fixture.

No end-to-end dispatch chain is required because the property is "this operation is never
gated" — which is proven by showing the filter returns false / tool pattern doesn't match /
gate returns Allow for the expired marker. The dispatcher-level registration invariant (tool
patterns for Edit/Write) is additionally verifiable via registry inspection.

## Proof Harness Skeleton

```rust
// crates/hook-plugins/validate-unvalidated-mutation-marker/src/tests/vp_107_ungated_escape.rs
// VP-107: BC-1.18.002 §INV6 — Ungated-Escape Invariant
// Three recovery paths are never blocked by the gate.

#[cfg(test)]
mod vp_107 {
    use super::*;
    use crate::guard_logic::{evaluate_gate, is_git_commit_or_push, GateDecision};
    use std::fs;
    use tempfile::TempDir;

    /// Postcondition A (EC-031, INV6-i): rm marker Bash dispatch is NOT gated.
    /// is_git_commit_or_push returns false for "rm .factory/unvalidated-mutation.marker"
    /// because basename("rm") = "rm" ≠ "git" (Phase 2 filter returns false).
    /// Arm 2 does not gate this dispatch. Arm 1 applies only to ^Agent$.
    #[test]
    fn test_rm_marker_not_gated_is_git_commit_or_push_false() {
        assert!(
            !is_git_commit_or_push("rm .factory/unvalidated-mutation.marker"),
            "VP-107 EC-031: 'rm .factory/unvalidated-mutation.marker' MUST NOT match \
             is_git_commit_or_push — basename('rm') ≠ 'git'; Arm 2 does NOT gate rm dispatches \
             (BC-1.18.002 §INV6-i; ADR-048 §D3)"
        );
        // Additional variants to confirm the rm escape hatch is not accidentally gated
        assert!(
            !is_git_commit_or_push("rm -f .factory/unvalidated-mutation.marker"),
            "VP-107 EC-031: 'rm -f .factory/unvalidated-mutation.marker' MUST NOT match"
        );
        assert!(
            !is_git_commit_or_push("/bin/rm .factory/unvalidated-mutation.marker"),
            "VP-107 EC-031: '/bin/rm ...' MUST NOT match — basename('/bin/rm') = 'rm' ≠ 'git'"
        );
    }

    /// Postcondition B (EC-032, INV6-ii): Edit and Write tool dispatches are NOT gated.
    /// Neither Arm 1 (^Agent$) nor Arm 2 (^Bash$) tool patterns match "Edit" or "Write".
    /// Confirmed by structural regex assertion — no gate arm fires for these tool names.
    #[test]
    fn test_edit_write_tools_not_matched_by_gate_arm_patterns() {
        // Arm 1 pattern: ^Agent$
        // Arm 2 pattern: ^Bash$
        // "Edit" and "Write" must not match either pattern.
        let arm1_pattern = regex::Regex::new(r"^Agent$")
            .expect("VP-107: Arm 1 tool pattern must compile");
        let arm2_pattern = regex::Regex::new(r"^Bash$")
            .expect("VP-107: Arm 2 tool pattern must compile");

        assert!(
            !arm1_pattern.is_match("Edit"),
            "VP-107 EC-032: 'Edit' tool MUST NOT match Arm 1 pattern '^Agent$' \
             (BC-1.18.002 §INV6-ii; ADR-048 §D3)"
        );
        assert!(
            !arm1_pattern.is_match("Write"),
            "VP-107 EC-032: 'Write' tool MUST NOT match Arm 1 pattern '^Agent$'"
        );
        assert!(
            !arm2_pattern.is_match("Edit"),
            "VP-107 EC-032: 'Edit' tool MUST NOT match Arm 2 pattern '^Bash$'"
        );
        assert!(
            !arm2_pattern.is_match("Write"),
            "VP-107 EC-032: 'Write' tool MUST NOT match Arm 2 pattern '^Bash$'"
        );
        // Confirm the patterns DO match what they're supposed to (sanity check)
        assert!(
            arm1_pattern.is_match("Agent"),
            "VP-107 sanity: Arm 1 pattern MUST match 'Agent'"
        );
        assert!(
            arm2_pattern.is_match("Bash"),
            "VP-107 sanity: Arm 2 pattern MUST match 'Bash'"
        );
    }

    /// Postcondition C (EC-033, INV6-iii): TTL auto-expiry provides passive self-healing.
    /// evaluate_gate called with an expired expires_at returns Allow (exit_code=0).
    /// Marker is auto-deleted. No operator dispatch required for this escape path.
    /// This is the passive self-healing path — system self-heals without any action.
    #[test]
    fn test_ttl_expired_marker_evaluate_gate_returns_allow() {
        let dir = TempDir::new("vp107_ttl").unwrap();
        let marker_path = dir.path().join(".factory").join("unvalidated-mutation.marker");
        fs::create_dir_all(dir.path().join(".factory")).unwrap();

        // Write a marker with an expires_at in the PAST (expired TTL)
        // Use a timestamp well in the past to guarantee expiry
        let past_expires_at = "2020-01-01T00:00:00Z";
        fs::write(
            &marker_path,
            format!(
                "timestamp = \"2019-12-31T00:00:00Z\"\n\
                 plugin_name = \"regression-gate\"\n\
                 artifact_path = \"/tmp/.factory/STATE.md\"\n\
                 cause = \"fuel\"\n\
                 trace_id = \"deadbeef-0107-0107-0107-000000000107\"\n\
                 expires_at = \"{past_expires_at}\"\n"
            )
            .as_bytes(),
        ).unwrap();

        // evaluate_gate MUST return Allow for an expired marker (BC-1.18.003 §PC4; INV6-iii)
        let decision = evaluate_gate(&marker_path);
        assert_eq!(
            decision,
            GateDecision::Allow,
            "VP-107 EC-033: evaluate_gate with expired expires_at MUST return Allow — \
             TTL auto-expiry provides passive self-healing (no dispatch required; \
             BC-1.18.002 §INV6-iii; ADR-048 §D3; BC-1.18.003 §PC4)"
        );

        // Marker MUST be auto-deleted after expired gate evaluation
        assert!(
            !marker_path.exists(),
            "VP-107 EC-033: expired marker MUST be auto-deleted by evaluate_gate \
             (BC-1.18.003 §PC4 idempotent delete)"
        );
    }
}
```
