# VP-107: Ungated-Escape Invariant: Edit/Write Re-Validation Dispatch Is Not Matched by Either Gate Arm (T1 Primary Recovery; BC-1.18.002 §INV6; ADR-048 §D3)

## Property Statement

The `validate-unvalidated-mutation-marker` gate (Arm 1: `^Agent$`; Arm 2: `^Bash$` with
`is_git_commit_or_push` command filter) MUST NEVER gate the Tier-1 primary agent recovery
operation, even while a non-expired `.factory/unvalidated-mutation.marker` exists (ADR-048
§Decision 3 v1.1; BC-1.18.002 §INV6).

**Scope — T1 only:** ADR-048 §Decision 3 v1.1 defines a four-tier recovery model. VP-107
verifies T1 only — Edit/Write re-validation (inherently ungated). T2 (TTL deadman) is covered
by VP-106. T3 (human out-of-band rm) requires no gate-pattern verification. T4 (agent-tool
Bash rm) is DE-SANCTIONED: the crash path `block_if_marker` check runs for ALL `^Bash$`
dispatches with no `is_git_commit_or_push` filter on the crash arm (BC-1.18.002 §PC5/§INV6
v1.6 amendment) — agent-tool rm MAY be blocked on crash path and is not a reliable escape.

**Postcondition B — Edit and Write re-validation dispatches are ungated (INV6-ii):**
Edit and Write tool dispatches are NOT gated by either arm of the gate. Arm 1 fires only on
tool name matching `^Agent$`; Arm 2 fires only on tool name matching `^Bash$`. "Edit" and
"Write" match neither `^Agent$` nor `^Bash$` in any registry-level regex evaluation, so neither
arm is triggered for these tools. This property holds even during a gate-plugin crash (the
crash path `block_if_marker` check operates at the dispatcher level and keys on tool name
pattern; Edit/Write still do not match). Confirmed ungated by construction. (EC-032)

**Why formalize as an explicit VP:** ADR-048 §Decision 1 tightened the gate's crash behavior
(block_if_marker — see VP-105 PC-G/PC-H). T1 is the primary, always-available recovery path:
an agent performing Edit/Write re-validation does not need to wait for TTL expiry or request
human intervention. A future refactor that accidentally added `Edit`/`Write` to a gate arm's
`tool` pattern would close the T1 escape surface and eliminate the primary agent recovery path.
VP-107 provides a load-bearing unit test verifying the T1 path remains open, ensuring future
refactors cannot silently break the primary recovery surface.

  Edit/Write are not in either pattern.

### Why unit-test

The T1 escape path property is verifiable as a pure unit test in the plugin crate:
- (B) is a structural regex assertion (no runtime call needed; Rust `regex::Regex::new(r"^Agent$").is_match("Edit")` → false).

No end-to-end dispatch chain is required because the property is "this operation is never
gated" — which is proven by showing the tool pattern does not match. The dispatcher-level
registration invariant (tool patterns for Edit/Write) is additionally verifiable via registry
inspection. T2 (TTL expiry — pure function test of `evaluate_gate`) is VP-106 scope.

## Proof Harness Skeleton

```rust
// crates/hook-plugins/validate-unvalidated-mutation-marker/src/tests/vp_107_ungated_escape.rs
// VP-107: BC-1.18.002 §INV6 — Ungated-Escape Invariant (T1 only)
// T1 primary agent recovery path: Edit/Write dispatch is never blocked by the gate.
// Scope note: T2 (TTL deadman) is VP-106 scope. T4 (agent-tool rm) is de-sanctioned.

#[cfg(test)]
mod vp_107 {
    use super::*;

    /// Postcondition B (EC-032, INV6-ii): Edit and Write tool dispatches are NOT gated.
    /// Neither Arm 1 (^Agent$) nor Arm 2 (^Bash$) tool patterns match "Edit" or "Write".
    /// Confirmed by structural regex assertion — no gate arm fires for these tool names.
    /// This property holds even on the crash path: block_if_marker keys on tool name
    /// pattern and Edit/Write do not match ^Agent$ or ^Bash$.
    #[test]
    fn test_edit_write_tools_not_matched_by_gate_arm_patterns() {
        // Arm 1 pattern: ^Agent$
        // Arm 2 pattern: ^Bash$
        // "Edit" and "Write" must not match either pattern.
        let arm1_pattern = regex::Regex::new(r"^Agent$")
            .expect("VP-107: Arm 1 tool pattern must compile");
        let arm2_pattern = regex::Regex::new(r"^Bash$")
            .expect("VP-107: Arm 2 tool pattern must compile");

        assert!(
            !arm1_pattern.is_match("Edit"),
            "VP-107 EC-032: 'Edit' tool MUST NOT match Arm 1 pattern '^Agent$' \
             (BC-1.18.002 §INV6-ii; ADR-048 §D3 v1.1 T1)"
        );
        assert!(
            !arm1_pattern.is_match("Write"),
            "VP-107 EC-032: 'Write' tool MUST NOT match Arm 1 pattern '^Agent$'"
        );
        assert!(
            !arm2_pattern.is_match("Edit"),
            "VP-107 EC-032: 'Edit' tool MUST NOT match Arm 2 pattern '^Bash$'"
        );
        assert!(
            !arm2_pattern.is_match("Write"),
            "VP-107 EC-032: 'Write' tool MUST NOT match Arm 2 pattern '^Bash$'"
        );
        // Confirm the patterns DO match what they're supposed to (sanity check)
        assert!(
            arm1_pattern.is_match("Agent"),
            "VP-107 sanity: Arm 1 pattern MUST match 'Agent'"
        );
        assert!(
            arm2_pattern.is_match("Bash"),
            "VP-107 sanity: Arm 2 pattern MUST match 'Bash'"
        );
    }
}
```
