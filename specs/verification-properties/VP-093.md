# VP-093: Dispatcher Injects git_context Into payload.extra on PostToolUse Bash git-commit Events; Fail-Open on Git Error; No Injection on Non-Qualifying Events

## Property

The factory-dispatcher binary MUST inject a `git_context` JSON object into
`payload.extra` for every PostToolUse Bash event whose `tool_input.command`
contains a `git commit` invocation targeting the factory-artifacts worktree
(`-C .factory` or equivalent path reference). The injection MUST satisfy:

**Postcondition A — Four-field completeness on qualifying events:**
For any qualifying PostToolUse Bash git-commit event where git succeeds,
`payload.extra["git_context"]` MUST be present with all four string fields:
- `head_subject` — subject line of HEAD commit (non-empty on non-initial commits)
- `head_sha` — full 40-character hex SHA of HEAD
- `head_parent_subject` — subject line of HEAD^ (empty string on initial commit)
- `head_parent_sha` — full 40-character hex SHA of HEAD^ (empty string on initial commit)

No field may be omitted and no field may be `null` — all four are always present as
JSON strings (BC-1.16.001 PC1, Invariant 5).

**Postcondition B — Fail-open on git error:**
If any git command fails (non-zero exit code, git not found, not a git repo,
permission denied), the dispatcher MUST inject `git_context` with all four fields
set to `""` (empty string) and route the enriched payload to registered plugins.
The dispatcher MUST NOT block, abort, or fail-close the hook dispatch on a git error.
The dispatcher MUST log a `warn`-level tracing event (BC-1.16.001 PC2).

**Postcondition C — No injection on non-qualifying Bash events:**
PostToolUse Bash events whose command does NOT contain `git commit` targeting
factory-artifacts MUST NOT receive `git_context` injection. The payload is routed
without the `git_context` key (BC-1.16.001 PC3).

**Postcondition D — No injection on non-Bash PostToolUse events:**
PostToolUse events for `tool = "Edit"`, `tool = "Write"`, `tool = "Agent"`, or
any non-Bash tool MUST NOT receive `git_context` injection. No command inspection
is performed for non-Bash tools (BC-1.16.001 PC4).

**Postcondition E — HOST_ABI_VERSION unchanged:**
`git_context` rides in the existing `extra` map field of `HookPayload` (the
`#[serde(flatten)]` field). No new named field is added to `HookPayload`. No new
host function is added to the SDK's `host` module. HOST_ABI_VERSION remains 1
(BC-1.16.001 PC5, ADR-029 §Decision 4).

## Invariant Classification: Invariant (Host-Layer Enrichment Contract)

This invariant ensures the factory-dispatcher correctly enriches the hook payload
with commit context so that downstream WASM chain-detection gates (BC-5.41.003)
can evaluate multi-commit chains without calling `exec_subprocess` from WASM
(ADR-029 §Decision 3, exec-free WASM boundary). The invariant also governs the
fail-open posture that preserves pipeline availability at the cost of skipping
chain detection when git context cannot be obtained.

## Proof Harness Skeleton (Integration / Bats)

**Implementation note:** The real artifact is `crates/factory-dispatcher/src/invoke.rs`
(dispatcher binary). The harness MUST invoke the factory-dispatcher binary with synthetic
PostToolUse events via its stdin or IPC channel — the same production invocation path
used in the hook chain. A synthetic git repository for factory-artifacts is constructed
in the bats setup phase to provide real HEAD/HEAD^ commit subjects and SHAs.

```bash
# File: plugins/vsdd-factory/tests/vp093-git-context-injection.bats
# Anchor: dispatcher_injects_git_context_on_qualifying_bash_commit_event

@test "VP-093-A: Dispatcher injects four-field git_context on qualifying PostToolUse Bash git-commit event" {
    # Setup: synthetic factory-artifacts git repo with two commits
    git -C "$FACTORY_ARTIFACTS_DIR" commit --allow-empty -m "state: burst-1 Commit E"
    HEAD_SHA=$(git -C "$FACTORY_ARTIFACTS_DIR" rev-parse HEAD)
    HEAD_SUBJECT="state: burst-1 Commit E"
    git -C "$FACTORY_ARTIFACTS_DIR" commit --allow-empty -m "state: burst-2 Commit E"
    HEAD2_SHA=$(git -C "$FACTORY_ARTIFACTS_DIR" rev-parse HEAD)
    HEAD2_SUBJECT="state: burst-2 Commit E"
    # Synthetic PostToolUse Bash event: git commit on factory-artifacts
    EVENT_JSON=$(cat <<EOF
{"event":"PostToolUse","tool":"Bash","tool_input":{"command":"git -C .factory commit -m \"state: burst-2 Commit E\""},"output":{"success":true},"session_id":"test-session-vp093"}
EOF
)
    run bash -c "echo '$EVENT_JSON' | ./hooks/dispatcher/bin/$(uname -s | tr '[:upper:]' '[:lower:]')-$(uname -m)/factory-dispatcher"
    # Assert: dispatcher exits 0 (no block for valid context)
    assert_success
    # Assert: git_context field emitted in dispatcher plugin dispatch log / payload propagation
    # Verify by reading dispatcher internal log for the test session trace
    TRACE_LOG=$(grep '"test-session-vp093"' .factory/logs/dispatcher-internal-*.jsonl | tail -1)
    # Assert git_context.head_subject equals HEAD2_SUBJECT
    run bash -c "echo '$TRACE_LOG' | jq -r '.payload.extra.git_context.head_subject'"
    assert_output "$HEAD2_SUBJECT"
    # Assert git_context.head_sha is a 40-char hex string
    run bash -c "echo '$TRACE_LOG' | jq -r '.payload.extra.git_context.head_sha' | grep -E '^[0-9a-f]{40}$'"
    assert_success
    # Assert git_context.head_parent_subject equals HEAD_SUBJECT (HEAD^)
    run bash -c "echo '$TRACE_LOG' | jq -r '.payload.extra.git_context.head_parent_subject'"
    assert_output "$HEAD_SUBJECT"
    # Assert git_context.head_parent_sha is a 40-char hex string
    run bash -c "echo '$TRACE_LOG' | jq -r '.payload.extra.git_context.head_parent_sha' | grep -E '^[0-9a-f]{40}$'"
    assert_success
}

@test "VP-093-B: Dispatcher injects all-empty git_context on git error (fail-open)" {

    BOGUS_DIR=$(mktemp -d)
    EVENT_JSON=$(cat <<EOF
{"event":"PostToolUse","tool":"Bash","tool_input":{"command":"git -C $BOGUS_DIR commit -m \"should fail\""},"output":{"success":true},"session_id":"test-session-vp093b"}
EOF
)
    run bash -c "echo '$EVENT_JSON' | ./hooks/dispatcher/bin/$(uname -s | tr '[:upper:]' '[:lower:]')-$(uname -m)/factory-dispatcher"

    assert_success
    # Assert: all four git_context fields are empty strings
    TRACE_LOG=$(grep '"test-session-vp093b"' .factory/logs/dispatcher-internal-*.jsonl | tail -1)
    run bash -c "echo '$TRACE_LOG' | jq -r '[.payload.extra.git_context | .head_subject, .head_sha, .head_parent_subject, .head_parent_sha] | @csv'"
```

## Feasibility Assessment

**Feasible as bats integration test via factory-dispatcher binary.** The `git_context`
injection is dispatcher host-layer behavior in `crates/factory-dispatcher/src/invoke.rs`.
A bats test constructs a synthetic factory-artifacts git repository with known commit
history, then pipes synthetic PostToolUse JSON events to the factory-dispatcher binary.
The dispatcher enriches the payload and routes it to registered plugins; the test
inspects the dispatcher's internal JSONL log (`.factory/logs/dispatcher-internal-*.jsonl`)
to verify that `payload.extra.git_context` contains the expected four-field structure.

**Why integration (not unit-test):** The property spans the dispatcher binary's
command-detection heuristic, the host-layer git subprocess execution, the payload
enrichment logic, and the plugin routing step — all of which require the actual binary
to be exercised end-to-end. A unit test of individual sub-functions would not catch
wiring failures between command detection and payload injection.

**F-P5-004 pattern applied:** The proof harness MUST invoke the factory-dispatcher
binary via its production IPC/stdin path. There is no standalone `git_context.sh`
script to invoke directly. The implementation site is
`crates/factory-dispatcher/src/invoke.rs` and the binary is the correct verification
surface.

**HOST_ABI_VERSION unchanged:** Because `git_context` rides in `HookPayload.extra`
(the `HashMap<String, serde_json::Value>` flatten field), no new named struct field
is added and no new host function is required. Existing plugins that do not read
`git_context` are unaffected and do not require recompile.

**Fail-open posture testable:** By constructing a git error path (invalid repository
path or permission denial), the test can verify that the dispatcher still exits 0
and injects the all-empty `git_context` object, rather than propagating the git
error as a block or crash.
