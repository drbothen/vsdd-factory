# VP-085: PreCompact Flush Hook Is Hermetic — Reads STATE.md+Git Only, Never In-Context Reasoning

## Property

The `precompact-flush.sh` hook script MUST determine all flush parameters (wave ID,
current SHA, lock holder, etc.) SOLELY from:

1. The `STATE.md` file on `factory-artifacts` (read via git or filesystem).
2. Git CLI calls (`git rev-parse`, `git log`, `git status`).
3. Standard filesystem reads (e.g., `.factory/hooks/precompact-flush-log` — append-only side-channel log).

The hook MUST NOT:
- Accept wave context from the PreCompact JSON event body's `custom_instructions` field
  (that field is unreliable on auto-compaction and is explicitly excluded from the design).
- Execute any operation that requires the LLM's active in-context state (the hook runs
  in a subprocess, isolated from the LLM context).
- Fail with an unhandled error if `custom_instructions` is absent or empty.

Formally:
- **Precondition:** PreCompact event fires with any trigger value (`manual` or `auto`).
  `custom_instructions` field in the JSON input MAY be absent, empty, or present.
- **Invariant:** The hook determines context identity by reading `STATE.md` frontmatter
  fields `current_cycle:` and `current_step:` — NOT from `custom_instructions`, NOT from
  any in-context variable, and NOT from a non-existent `current_wave:` field. There is no
  `current_wave:` field on STATE.md. The flush commit message uses the form
  `PreCompact flush <current_cycle>/<current_step> <ISO-timestamp>`.
- **Postcondition A (custom_instructions absent):** Hook executes flush successfully.
  No error. Exit code 0 or 2 based on flush outcome.
- **Postcondition B (custom_instructions present but empty):** Same as A.
- **Postcondition C (custom_instructions present with content):** Same as A.
  `custom_instructions` content is ignored entirely.
- **Postcondition D (STATE.md unreadable):** Hook exits 0 (fail-open per Decision 6
  `on_error=continue`). Logs warning to stderr.

## Invariant Classification: Safety (Anti-Deadlock)

This is the anti-deadlock invariant from F1 regression risk §4.1 R1. If the flush hook
required in-context reasoning, it could deadlock: the hook fires BEFORE the compaction
(to prevent context loss), but the in-context state is the very thing that might be stale
or about to be compacted. Reading only from external sources (STATE.md + git) breaks this
circular dependency.

## Proof Harness Skeleton (Unit Test / Bats)

```bash
# File: plugins/vsdd-factory/tests/precompact-hermetic.bats
# Anchor: precompact_flush_ignores_custom_instructions

@test "precompact-flush.sh succeeds when custom_instructions is absent" {
    # Construct PreCompact JSON WITHOUT custom_instructions field
    echo '{"hook_event_name":"PreCompact","trigger":"auto","session_id":"test-123","transcript_path":"/tmp/t.jsonl","cwd":"'"$TEST_CWD"'"}' \
        | bash plugins/vsdd-factory/hooks/precompact-flush.sh
    assert_success_or_exit2  # 0 or 2, never other codes
}

@test "precompact-flush.sh succeeds when custom_instructions is empty string" {
    echo '{"hook_event_name":"PreCompact","trigger":"auto","session_id":"test-123","transcript_path":"/tmp/t.jsonl","cwd":"'"$TEST_CWD"'","custom_instructions":""}' \
        | bash plugins/vsdd-factory/hooks/precompact-flush.sh
    assert_success_or_exit2
}

@test "precompact-flush.sh reads current_cycle+current_step from STATE.md not custom_instructions" {
    # Setup: STATE.md with current_step: "pass-4" and current_cycle: "v1.0-feature-context-durability-E18"
    #        (NO current_wave: field — that field does not exist on STATE.md)
    # Setup: PreCompact JSON with custom_instructions: "wave 99" (misleading; must be ignored)
    echo '{"hook_event_name":"PreCompact","trigger":"manual","session_id":"test-123","transcript_path":"/tmp/t.jsonl","cwd":"'"$TEST_CWD"'","custom_instructions":"wave 99"}' \
        | bash plugins/vsdd-factory/hooks/precompact-flush.sh
    # Assert: commit message contains cycle/step from STATE.md (not "wave-99" from custom_instructions)
    run git -C "$FACTORY_DIR" log --format="%s" -1 factory-artifacts
    assert_output --partial "v1.0-feature-context-durability-E18/pass-4"
    refute_output --partial "wave-99"
}

@test "precompact-flush.sh exits 0 with warning when STATE.md unreadable" {
    chmod 000 "$FACTORY_DIR/.factory/STATE.md"
    echo '{"hook_event_name":"PreCompact","trigger":"auto","session_id":"test-123","transcript_path":"/tmp/t.jsonl","cwd":"'"$TEST_CWD"'"}' \
        | bash plugins/vsdd-factory/hooks/precompact-flush.sh
    # Assert: exit 0 (fail-open per on_error=continue)
    assert_success
    chmod 644 "$FACTORY_DIR/.factory/STATE.md"  # restore
}
```

## Feasibility Assessment

**Feasible as bats unit test.** The hermetic requirement can be verified by:
1. Providing synthetic PreCompact JSON with controlled `custom_instructions` values and
   observing that the flush uses STATE.md's `current_cycle:` + `current_step:` values instead
   (there is no `current_wave:` field on STATE.md — the hook must read the correct fields).
2. Verifying that the commit message always reflects the `<cycle>/<step>` format from STATE.md,
   never the `custom_instructions` content.
3. Testing the `STATE.md` unreadable fail-open path.

All test cases require only a local git repo and controlled filesystem — no network needed.
