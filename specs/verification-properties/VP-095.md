# VP-095: verify-factory-lock Never Receives output_too_large for Any STATE.md Size — Structural Guarantee via host::read_prefix(262144) (BC-1.17.001 PC-3); Large-STATE.md Frontmatter Correctly Parsed from 262144-Byte Prefix

## Property Statement

`verify-factory-lock` WASM plugin (Phase-B; S-19.07) reads `.factory/STATE.md` via
`host::read_prefix(path, max_bytes=262144, timeout_ms)`. By BC-1.17.001 §PC-3,
`read_prefix` NEVER returns `OUTPUT_TOO_LARGE` (-3): the `max_bytes` argument IS the
output cap; content beyond it is not read rather than rejected with an error code. This
makes `OUTPUT_TOO_LARGE` structurally impossible for `verify-factory-lock` on any
STATE.md of any byte-size, regardless of compaction discipline or file growth. The
`STATE_MD_MAX_BYTES` constant and all `TooLarge`/`OutputTooLarge` error-handling code are
removed at S-19.07; the only non-success codes `read_prefix` can return are
`CAPABILITY_DENIED (-1)` and `NOT_FOUND (-5)`, both handled by the PC6 fail-open path.

The residual behavioral property is: when STATE.md is larger than 262144 bytes, the plugin
correctly locates and parses the `factory_lock:` frontmatter block from the 262144-byte
prefix. This holds because the 262144-byte bound equals the established STATE.md byte
envelope (BC-4.13.001 §Precondition 3 Phase-A; BC-5.40.001 §Precondition 6): any
on-envelope STATE.md file has its frontmatter closing `---` delimiter necessarily within
the 262144-byte prefix, regardless of how large the frontmatter grows. **Retraction of
the 8192 bound (v1.3):** the v1.2 claim that "compaction discipline guarantees STATE.md
frontmatter is well under 2 KiB" is premise-false — ADR-026 §Decision 7 is a line-count
discipline (≤200/≤500 lines), not a byte bound; the inlined `last_amended` changelog
convention causes frontmatter to currently occupy ~35,175 bytes (measured 2026-07-16:
STATE.md total 178,742 bytes; closing `---` at byte 35,175; `last_amended` field alone
32,648 bytes); at max_bytes=8192 the guard is silently inert. Root disease anchored to
S-15.03 PRIORITY-A structured-changelog migration. The property is proven by the S-19.07
AC-003 unit-test family with injectable mock callbacks that enforce `max_bytes == 262144`.

**Phase-A property (S-19.02; superseded by this v1.2 amendment):** The Phase-A
property asserted zero `OUTPUT_TOO_LARGE` denials for STATE.md sizes up to
`STATE_MD_MAX_BYTES=262144`, proven via bats integration fixtures (five boundary
fixtures: 65535, 65536, 131072, 262144, 262145 bytes). That property is structurally
superseded: Phase-B removes `STATE_MD_MAX_BYTES`, `host::read_file`, and all
`TooLarge`/`OutputTooLarge` handling from the plugin. The Phase-A harness is retired;
it lives in git history at historical path
`plugins/vsdd-factory/tests/vp095-verify-factory-lock-size-cap.bats` (no line pins
per TD-VSDD-091).

## Source Contract

- **BC:** BC-4.13.001 Phase-B §Precondition 3 — once `host::read_prefix` is available
  and S-19.07 merges, the guard MUST read `.factory/STATE.md` via
  `host::read_prefix(path, max_bytes=262144, timeout_ms)` (per ADR-025 §Decision 15
  v1.17 adjudicated bound; BC-4.13.001 §Precondition 3 Phase-B as amended in BC-4.13.001 v1.17). The `STATE_MD_MAX_BYTES` constant and all `TooLarge`/`OutputTooLarge`
  handling are removed. `[hooks.capabilities.read_prefix]` with
  `path_allow = [".factory/STATE.md"]` replaces `[hooks.capabilities.read_file]`.
- **BC:** BC-1.17.001 §PC-3 — `read_prefix` NEVER returns `OUTPUT_TOO_LARGE` (-3);
  `max_bytes` IS the cap; data beyond the cap is not read, not rejected with -3. This is
  the behavioral contract distinguishing `read_prefix` from `read_file`.
- **ADR:** ADR-025 §Decision 15 — `host::read_prefix` additive host function allocation
  (HOST_ABI_VERSION=1 retained); separate `[hooks.capabilities.read_prefix]` block
  required; independent from `capabilities.read_file`; never `OUTPUT_TOO_LARGE`; absent
  path returns `NOT_FOUND (-5)`.

### Why unit+static (adjudicated from integration)

The Phase-B property has two components, each proven by the appropriate method:

**Structural component** (BC-1.17.001 §PC-3): The `read_prefix` contract guarantees
NEVER `OUTPUT_TOO_LARGE`. For VP-095 specifically, this guarantee activates only when
the guard actually calls `read_prefix` — not `read_file`. Bats Gate B (T-001b in
`verify-factory-lock-read-prefix.bats`) verifies via sed+grep symbol-absence that
`host::read_file`, `STATE_MD_MAX_BYTES`, and `TooLarge` are absent from non-comment
production code in `verify-factory-lock/src/lib.rs`. Their absence confirms the guard
exclusively uses `read_prefix`, making -3 impossible by BC-1.17.001 §PC-3.

**Behavioral component** (large STATE.md → correct frontmatter parse): Proven by the
AC-003 large-fixture unit-test family. Each test injects a mock `read_prefix` callback
that enforces `max_bytes == 262144` by returning `Err` for any other value. The guard
must call the mock with exactly `max_bytes=262144`; any call with a different bound
fails the mock check → guard returns `Continue` → the expected `Block` assertion fails →
RED gate. This provides strong discrimination against any incorrect bound value.

A dispatcher-binary integration test is not required for Phase-B: the structural
guarantee is host-ABI-level (proven independently by VP-101 for `host::read_prefix`),
and the behavioral property targets pure `guard_logic` with injectable callbacks — no
WASM runtime is needed.
