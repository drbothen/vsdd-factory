# VP-114: Exactly-One changelog: Prepend, Byte-for-Byte-Untouched Pre-Existing Items, and Never-Wrap last_amended

## Property Statement

For any one of the five ADR-049-governed files (`STORY-INDEX.md`, `BC-INDEX.md`, `ARCH-INDEX.md`,
`VP-INDEX.md`; `STATE.md` is governed separately by PC3's body-level-record exception, out of this
VP's scope) undergoing a write under BC-5.45.001's discipline:

1. The `changelog:` sequence grows by EXACTLY ONE new list item — a list-item prepend, never a
   rewrite-in-place of the sequence or of any existing item (PC2).
2. The new item is inserted at position 0 (first) and carries the FULL TEXT of the entry that
   `last_amended` held immediately before this write, including any trailing
   `[Prior history → ...]` pointer note.
3. Every PRE-EXISTING `changelog:` item is left BYTE-FOR-BYTE UNTOUCHED — this is verified as an
   exact equality check on each pre-existing item's raw text before vs. after the write, not merely
   a count check.
4. `last_amended` is OVERWRITTEN with ONLY the new entry — the agent never reads the field's
   existing value and concatenates it back as a `[Prior: ...]` bracket or any other nested form
   (PC1; the never-wrap half of this discipline).

This is the conforming-writer property the crate's own `changelog::prepend_changelog_item` +
`frontmatter::set_last_amended` implement — the SAME discipline BC-5.45.001 also mandates for every
future manual state-manager burst against these five files, of which this crate's own migration
writes are one conforming example, not the only one.

## Source Contract

- **BC:** BC-5.45.001 §Postcondition 1 (PC1) — `last_amended` overwritten, never wrapped;
  §Postcondition 2 (PC2) — the displaced entry is prepended to `changelog:` (files that have one);
  Invariant 4 — `changelog:` grows by append only, never by in-place rewrite of an existing item.
- **ADR:** ADR-049 §Decision 1, §Decision 2, §Decision 4.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| unit-test | Rust (`#[test]`) | yes — fixed fixture with 2 pre-existing items | exactly-one-item growth; new item is first and carries the displaced entry's full text; pre-existing items untouched byte-for-byte |

### Why unit-test

`prepend_changelog_item` is a pure, deterministic sequence-mutation function
(`FrontmatterDoc, ChangelogItem) -> ()`) with no I/O beyond the in-memory `FrontmatterDoc`
representation — a fixed 2-pre-existing-item fixture exercises the full growth/ordering/
byte-identity decision table the BC's original `proptest` candidates (diff pre/post sequences)
targeted. The strict-YAML-validity leg of BC-5.45.001's discipline (Invariant 3, shared substance
with BC-10.13.001 Invariant 4) is verified jointly with VP-113 rather than duplicated here, since
both properties depend on the identical `escape::escape_value` pre-write pass.
