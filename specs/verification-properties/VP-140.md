# VP-140: Item-Count Trigger Off-By-One (`current_item_count + 1 > N`) and `low_water_mark` Rotation-Target Config Validation (Default `floor(N/2)`; Fail-Loud on `>= N` or Negative)

## Property Statement

The native gate's `"frontmatter-changelog-array"` (mechanism B1) trigger path is proven correct on
two deterministic, small-fixture facets that VP-116/VP-117 (both scoped to the `"flat"` byte-size
shape) do not touch: the item-count trigger's boundary partition, and the `low_water_mark`
rotation-target config's default-and-fail-loud validation. This is the item-count-shape analogue of
VP-116's role — VP-116 proves the `"flat"` byte-size boundary (`projected_size <= shard_cap_bytes`);
this VP proves the `"frontmatter-changelog-array"` item-count boundary
(`current_item_count + 1 > N`) and the config surface (`N`, `low_water_mark`) that boundary and its
rotation target are driven by.

1. **Shape-dispatch is a config-declared property, read once (BC-1.18.005 §Postcondition 8
   shape-declaration, §Invariant 5).** For a matched artifact, the gate selects the item-count check
   iff the `[[shard]]` entry's `shape` field is `"frontmatter-changelog-array"` (and the byte-size
   check iff `"flat"`); the selection reads the config `shape` field exactly once and never sniffs
   the target file's actual content or extension. A config entry that omits `shape` entirely is
   fail-loud (`HookResult::Error`, §EC-009), never a silent default to either shape.

2. **Item-count trigger off-by-one (BC-1.18.005 §Postcondition 8 trigger-condition, §EC-008).** The
   trigger fires iff `current_item_count + 1 > N`, equivalently iff `current_item_count >= N`, where
   `current_item_count` is the count of the live frontmatter `changelog:` sequence and `N` is the
   config threshold. The boundary partition is proven exactly over the three-cell table:
   - `current_item_count == N - 1`: `(N-1) + 1 = N`, NOT `> N` → **Continue** (the agent's prepend
     lands, bringing the sequence to exactly `N`; EC at "10 items, N=50" generalizes here).
   - `current_item_count == N`: `N + 1 > N` → **trigger fires** (§EC-008: "at exactly N items ...
     `current_item_count + 1 = N+1 > N` → trigger fires"); BC-1.18.009's rotate-then-block-and-retry
     outcome applies.
   - `current_item_count == N + 1` (a transient over-fill): `(N+1) + 1 > N` → **trigger fires**.
   The comparison uses `current_item_count + 1 > N`, never `>=` on the raw count and never a byte-size
   comparison for this shape (BC-1.18.005 §Postcondition 8 "NEVER a byte-size comparison"). The `+ 1`
   addend does not wrap: `current_item_count` is bounded by the live sequence length (itself
   `<= N` in steady state per BC-1.18.009, and finite even at cold-start), so no overflow arises in
   the bounded item-count domain — the reason a small-fixture unit-test, not Kani, is the fitting
   method for this boundary (see Why unit-test).

3. **`low_water_mark` default is `floor(N/2)`, computed at config-load time (BC-1.18.005
   §Postcondition 8 rotation-target-config bullet, §Invariant 4 extended, §EC-010).** When a
   `"frontmatter-changelog-array"` entry omits `low_water_mark`, the loaded config value is exactly
   `floor(N / 2)` — computed at config-load time, NEVER a constant hardcoded into `shard_manager.rs`
   as a fallback (e.g., `N = 50 → low_water_mark = 25`; `N = 51 → floor(51/2) = 25`). `N` and
   `low_water_mark` are both configuration, never embedded constants.

4. **`low_water_mark` fail-loud validation `0 <= low_water_mark < N` (BC-1.18.005 §Postcondition 8
   rotation-target-config bullet, §EC-011).** A declared `low_water_mark` is validated at config-load
   time against `0 <= low_water_mark < N`. A violating value is NEVER silently clamped and NEVER
   silently defaulted around — the config is treated as malformed and the gate returns
   `HookResult::Error` (mirroring §EC-009's "no silent default for malformed shape" posture, extended
   to this field). The boundary partition is proven exactly:
   - `low_water_mark == N` (the degenerate `>= N` boundary): **`HookResult::Error`** (fail-loud).
   - `low_water_mark == N - 1`: **VALID** — `N - 1 < N` satisfies the constraint; loads normally, no
     error (this is the boundary the withdrawn "always trim to `N-1`" design used; it is a legal
     `low_water_mark` value, merely a poor one for amortization — Decision 14 — not a config error).
   - `low_water_mark < 0` (negative): **`HookResult::Error`** (fail-loud).
   - `0 <= low_water_mark < N` (interior): **VALID** — loads normally.

This VP proves the *shape* of the item-count trigger boundary and the config surface, both of which
are locked NOW. The concrete numeric `N` is a config value (its illustrative `N ≈ 50` is not an
F4-calibrated byte constant — the item-count trigger is deliberately NOT byte-denominated, so it
carries no PROVISIONAL-until-F4 numeric dependency); the proof is parameterized over symbolic `N`
and holds for any configured value.

## Proof Method

| Leg | Method | Tool | Coverage | Status |
|-----|--------|------|----------|--------|
| Shape-dispatch read-once | unit-test | Rust `#[test]` + mock config + content-read counter | item-count check selected iff `shape == "frontmatter-changelog-array"`; `shape` read once; content never sniffed; omitted `shape` → `Error` | feasible-pending-harness (F4 code) |
| Item-count trigger off-by-one | unit-test | Rust `#[test]`, table over `current_item_count ∈ {N-1, N, N+1}` for symbolic `N` | fires iff `current_item_count + 1 > N`; `N-1` → Continue, `N`/`N+1` → fire; no byte comparison; no `+1` wrap in the bounded item domain | feasible-pending-harness (F4 code) |
| `low_water_mark` default | unit-test | Rust `#[test]` over several `N` (even/odd) with `low_water_mark` omitted | loaded value == `floor(N/2)`; computed at load time, not a hardcoded fallback | feasible-pending-harness (F4 code) |
| `low_water_mark` fail-loud validation | unit-test | Rust `#[test]`, table over `low_water_mark ∈ {N (>=N), N-1 (valid), 0 (valid), -1 (negative)}` | `>= N` and negative → `HookResult::Error` (never clamped/defaulted); `N-1` and interior valid → loads, no error | feasible-pending-harness (F4 code) |

### Why unit-test

All four facets are deterministic dispatch/selection/config-validation properties with a small,
fully enumerable fixture space — a mock config, a content-read counter, a three-cell trigger-boundary
table, and a four-cell config-validation table. Hand-crafted representative fixtures give exhaustive
coverage of the exact boundaries that matter (`N-1`/`N`/`N+1` for the trigger; `N`/`N-1`/`0`/`-1` for
the config). This is the same enforcement class as VP-117 (the `"flat"`-shape dispatch/selection unit
VP) and VP-120/VP-122/VP-131 (fail-loud config/error unit legs). Kani is NOT selected here — unlike
VP-116's `"flat"` byte-size `projected_size` arithmetic (large `u64` byte values with real
wrap/saturation risk over a symbolic cap), the item-count trigger is a single `current_item_count + 1
> N` comparison over small, bounded item counts (`<= N` in steady state), where no overflow arises;
and the `low_water_mark` fail-loud legs return `HookResult::Error` on malformed config, which is a
config-parse/error property Kani cannot express. Unit-test is the single method that covers all four
facets coherently under the single-method-per-VP convention.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/shard_item_count_trigger_test.rs
// VP-140: BC-1.18.005 PC8 (item-count trigger boundary + low_water_mark config validation)

#[test]
fn test_BC_1_18_005_PC8_shape_dispatch_read_once_and_content_not_sniffed() {
    let cfg = MockShardConfig::entry("BC-INDEX.md", Shape::FrontmatterChangelogArray, /*N*/ 50);
    let content = ContentReadCounter::new();
    let check = shard_manager::select_check(&cfg, "BC-INDEX.md", &content);
    assert!(matches!(check, ShardCheck::ItemCount { .. }));
    assert_eq!(cfg.shape_field_reads(), 1);   // read once, per INV5
    assert_eq!(content.reads_for_shape_decision(), 0); // never sniffs content
    // omitted shape → fail-loud (EC-009)
    let bad = MockShardConfig::entry_no_shape("X.md");
    assert!(matches!(shard_manager::select_check(&bad, "X.md", &content), ShardCheck::Error(_)));
}

#[test]
fn test_BC_1_18_005_PC8_item_count_trigger_off_by_one() {
    for n in [1u64, 2, 50, 999] {                     // symbolic N
        assert_eq!(shard_manager::item_count_triggers(n - 1, n), false); // N-1 → Continue
        assert_eq!(shard_manager::item_count_triggers(n,     n), true);  // exactly N → fire (EC-008)
        assert_eq!(shard_manager::item_count_triggers(n + 1, n), true);  // N+1 → fire
        // equivalence with the raw condition, no wrap in the bounded item domain:
        assert_eq!(shard_manager::item_count_triggers(n, n), (n + 1) > n);
    }
}

#[test]
fn test_BC_1_18_005_PC8_EC010_low_water_mark_defaults_to_floor_n_half() {
    for (n, expected) in [(50u64, 25u64), (51, 25), (2, 1), (1, 0)] {
        let cfg = MockShardConfig::entry_changelog("BC-INDEX.md", n, /*low_water_mark*/ None);
        assert_eq!(shard_manager::load_low_water_mark(&cfg).unwrap(), expected); // floor(N/2), load-time
    }
}

#[test]
fn test_BC_1_18_005_PC8_EC011_low_water_mark_fail_loud_boundary() {
    let n = 50u64;
    // >= N (incl. the degenerate == N) → Error; negative → Error; NEVER clamped/defaulted:
    assert!(matches!(shard_manager::load_low_water_mark(&changelog_cfg(n, Some(50))),  Err(_))); // == N
    assert!(matches!(shard_manager::load_low_water_mark(&changelog_cfg(n, Some(51))),  Err(_))); // > N
    assert!(matches!(shard_manager::load_low_water_mark_signed(&changelog_cfg_i(n, -1)), Err(_))); // negative
    // N-1 and interior values are VALID (N-1 satisfies < N — a legal, if poorly-amortized, floor):
    assert_eq!(shard_manager::load_low_water_mark(&changelog_cfg(n, Some(49))).unwrap(), 49); // N-1 valid
    assert_eq!(shard_manager::load_low_water_mark(&changelog_cfg(n, Some(0))).unwrap(),  0);  // 0 valid
    assert_eq!(shard_manager::load_low_water_mark(&changelog_cfg(n, Some(25))).unwrap(), 25); // interior
}
```
