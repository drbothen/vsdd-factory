# VP-117: Native Shard-Cap Trigger — Unmatched-Path Zero-Cost Bypass, Cross-Validator Minimum Rule, and Byte-Denominated Comparison

## Property Statement

The native `shard_manager` gate dispatches correctly around the size check, and computes the
effective per-artifact cap correctly, without ever paying a filesystem cost on the ~99% of tool
calls Layer 2 does not touch.

1. **Unmatched-path zero-cost bypass.** If the tool-call target path matches no `[[shard]]` config
   entry, the gate returns `Continue` immediately, issuing ZERO `stat()`/`metadata()` calls and
   performing no cap arithmetic (BC-1.18.005 §Postcondition 1, §Invariant 3). The config-match test
   provably precedes any filesystem access.

2. **Cross-Validator Minimum Rule.** For a matched artifact, the effective `shard_cap_bytes` equals
   the MINIMUM of the per-plugin caps of every Cohort B validator that reads that artifact
   (BC-1.18.005 §Postcondition 5): `burst-log.md` → `MIN(validate-burst-log, regression-gate,
   convergence-tracker)`; `decision-log.md`/`lessons.md`/`session-checkpoints.md` →
   `MIN(regression-gate, convergence-tracker)` (validate-burst-log's cap is NOT applied to the
   three it does not read). No single global cap is used.

3. **Byte denomination.** Every quantity the gate compares (`current_shard_bytes`, `payload_bytes`,
   `projected_size`, `shard_cap_bytes`) is a byte count — never a line count or other non-byte unit
   (BC-1.18.005 §Postcondition 4, §Invariant 2). A `lessons.md`-shaped fixture (well under its
   D-442(e) line budget yet hundreds of KB) confirms a line-count proxy would mis-classify it.

The concrete per-plugin cap numbers are **PROVISIONAL-until-F4** (they are the F4 synthetic
calibration harness's output); the MIN relationship, the zero-cost bypass, and the byte denomination
are structural and locked now — the proof is table-driven over injected cap values and holds for any
values the harness produces.

| Zero-cost bypass | unit-test | Rust `#[test]` + mock filesystem call counter | assert 0 `stat()` calls for a non-matching path | feasible-pending-harness (F4 code) |
| Cross-Validator Minimum | unit-test | Rust `#[test]`, table-driven over 4 mechanism-A artifacts × 3 Cohort B plugins | effective cap == MIN of applicable per-plugin caps | feasible-pending-harness (F4 code) |
| Byte denomination | unit-test | Rust `#[test]` against a byte-oracle fixture (lessons.md-shaped) | compared value equals byte length, not line count | feasible-pending-harness (F4 code) |

### Why unit-test

These are deterministic dispatch/selection properties with a small, fully enumerable fixture space
(a mock FS counter and a 4×3 cap table). Hand-crafted representative fixtures give exhaustive
coverage; a mock filesystem is the natural way to assert the zero-`stat()` claim, which no
property-generator improves.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/shard_cap_trigger_test.rs
// VP-117: BC-1.18.005 PC1/PC4/PC5/INV1-3

#[test]
fn test_BC_1_18_005_PC1_unmatched_path_issues_zero_stat_calls() {
    let fs = MockFs::counting();
    let r = shard_manager::evaluate_shard_gate("some/unrelated/file.md", &fs, /*payload*/ 100);
    assert_eq!(r, GateOutcome::Continue);
    assert_eq!(fs.stat_calls(), 0);            // no filesystem cost on the 99% path
}

#[test]
fn test_BC_1_18_005_PC5_cross_validator_minimum_rule() {
    // burst-log.md: read by all three → MIN over three caps
    assert_eq!(shard_manager::effective_cap("burst-log", &caps{vbl:40_000, rg:49_152, ct:52_000}), 40_000);
    // decision-log.md: not read by validate-burst-log → MIN over two caps only
    assert_eq!(shard_manager::effective_cap("decision-log", &caps{vbl:40_000, rg:49_152, ct:52_000}), 49_152);
}

#[test]
fn test_BC_1_18_005_PC4_byte_not_line_denominated() {
    // lessons.md-shaped fixture: under line budget, over byte cap → rolls on bytes
    let f = fixture_under_line_budget_over_byte_cap();
    assert!(shard_manager::over_cap(f.byte_len, /*cap*/ 49_152));
}
```
