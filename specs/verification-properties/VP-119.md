# VP-119: No Sealed Shard Ever Exceeds Its Recorded Cap and the Canonical Filename Is Never Renamed Away Across Any Roll Sequence

## Property Statement

Over an arbitrary sequence of writes against a simulated sharded artifact, two safety invariants
hold at every step:

1. **No over-cap sealed shard.** For every `[[shard]]` entry the roll mechanism produces, its
   `bytes_at_seal` is `<= shard_cap_bytes` as recorded in the index at seal time (BC-1.18.006
   §Postcondition 3). Because the seal happens before the block and the blocked call is never
   applied, no downstream reader can ever observe a shard above its own recorded cap — this holds
   *relative to whatever cap is configured*, so it is independent of the F4-provisional numeric
   value.

2. **Stable current filename.** The canonical filename (e.g. `decision-log.md`) is never itself
   renamed to a sealed name across any roll sequence (BC-1.18.006 §Postcondition 6, §Invariant 3):
   `stat(canonical_path)` always succeeds and never resolves to a sealed inode from a prior roll —
   only the content behind the canonical name is replaced by the seal+create sequence.

## Source Contract

- **BC:** BC-1.18.006 §Postcondition 3 (no-over-cap), §Postcondition 6 (stable-current-filename),
  §Invariant 3 (canonical filename never moves).
- **ADR:** ADR-051 §Decision 3 (stable-current-filename addressing), §Decision 4 (shard-index).

## Proof Method

| Leg | Method | Tool | Coverage | Status |
|-----|--------|------|----------|--------|
| No-over-cap | proptest | Rust `proptest!` over arbitrary write sequences against a simulated artifact | property: every sealed shard's `bytes_at_seal <= shard_cap_bytes` | feasible-pending-harness (F4 code) |
| Stable-current-filename | proptest | Rust `proptest!` over arbitrary roll sequences | property: `stat(canonical)` always succeeds; canonical inode never equals any sealed inode | feasible-pending-harness (F4 code) |

### Why proptest

Both are universally-quantified invariants over *arbitrary* write/roll sequences, not a fixed
fixture — proptest's generated sequences (variable payload sizes, interleavings) explore the state
space a hand-crafted table cannot. The property is stated relative to the recorded cap, so it is
value-agnostic and needs no F4 constant.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/proptest_shard_safety.rs
// VP-119: BC-1.18.006 PC3/PC6/INV3

proptest! {
    #[test]
    fn prop_no_sealed_shard_exceeds_recorded_cap(seq in arb_write_sequence()) {
        let mut art = SimArtifact::new(cap = arb_cap());
        for w in seq { art.apply_or_roll(w); }
        for shard in art.index().sealed() {
            prop_assert!(shard.bytes_at_seal <= art.index().shard_cap_bytes);
        }
    }

    #[test]
    fn prop_canonical_filename_never_sealed(seq in arb_write_sequence()) {
        let mut art = SimArtifact::new(cap = arb_cap());
        let canon = art.canonical_inode();
        for w in seq {
            art.apply_or_roll(w);
            prop_assert!(art.stat_canonical().is_ok());
            prop_assert_ne!(art.canonical_inode_now(), art.any_sealed_inode());
            let _ = canon;
        }
    }
}
```
