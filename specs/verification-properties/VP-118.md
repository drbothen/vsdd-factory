# VP-118: Staged Four-Step Roll (Read → Publish Sealed Copy → Atomic-Truncate Canonical In-Place → Append Index) Completes Before the Block; Shard and Index Land in the Same Invocation; Index Is Append-Only-Tail

## Property Statement

When BC-1.18.005's trigger fires, the roll is a STAGED, four-step operation (BC-1.18.006
§Postcondition 1 CORRECTED) that is observably complete and atomic by the time the caller sees the
block — modeled under the copy-then-atomic-truncate-in-place seal, NOT the withdrawn v1.0/v1.1
rename-away mechanism.

1. **Staged four-step roll, complete before the Block.** At the instant the caller receives
   `HookResult::Block`, all four steps have completed (BC-1.18.006 §Postcondition 1):
   (a) the canonical file's pre-roll content was read; (b) a sealed shard was published as a
   brand-NEW file `<stem>.<seq:04>.md` (a byte-for-byte copy of that content, via `write_atomic`);
   (c) the canonical file's content was atomically REPLACED with empty in place (via `write_atomic`
   temp-file-then-`rename(temp, canonical)` — an atomic replace-onto-existing, NEVER a rename of the
   canonical path away, so the canonical path is never absent at any instant); and (d) the shard-index
   TOML now contains the `[[shard]]` entry for this roll. The dispatcher harness reads the sealed
   file and the index the moment it observes the Block and finds both present — neither lags behind
   the block.

2. **Same-invocation atomicity.** The sealed-shard publish (step (b)) and the shard-index write
   (step (d)) are both filesystem writes issued by the SAME PreToolUse invocation, before any
   `git add`/`git commit` (BC-1.18.006 §Postcondition 4). Both are present in the working tree
   together, so TD-VSDD-053 single-commit-per-burst holds structurally for shard+index atomicity
   regardless of which agent or skill issued the original tool call.

3. **Ordered per-step, never reordered.** The index is never published before the sealed shard is
   durably written, and the canonical is never truncated before its content is copied into the
   sealed shard (BC-1.18.006 §Invariant 2) — verified by asserting the on-disk state at each
   observable step of a harness-driven roll. Each of steps (b), (c), (d) is its own independent
   `write_atomic` temp-file-then-rename.

4. **Append-only-tail index; canonical never renamed away.** The seal APPENDS exactly one new
   `[[shard]]` entry with `seq` incrementing monotonically from 1, never rewriting or reordering a
   prior entry (BC-1.18.006 §Postcondition 5) — a prior seal's entry is byte-identical before and
   after this roll. The canonical filename (e.g. `decision-log.md`) is never renamed to a sealed
   name; only its CONTENT is replaced via the atomic rename-onto-existing (BC-1.18.006 §Invariant 3),
   and the gate itself has no semantic understanding of where within the file the write lands
   (§Invariant 5 append-only-tail assumption).

## Source Contract

- **BC:** BC-1.18.006 §Postcondition 1 (staged four-step roll, CORRECTED) / §Postcondition 4
  (same-invocation) / §Postcondition 5 (append-only-tail index), §Invariant 2 (per-step ordering),
  §Invariant 3 (canonical never renamed away), §Invariant 5 (append-only-tail edit assumption).
- **ADR:** ADR-051 §Decision 11 (staged, crash-recoverable per-write roll sequence), §Decision 3
  (copy-then-atomic-truncate-in-place seal), §Decision 4 (shard-index schema).
- **Precedent:** `write_indeterminate_marker`/`write_atomic` temp-file-then-rename atomic publish
  (the SAME primitive steps (b), (c), (d) each reuse; no new atomic-write primitive is introduced).

### Why integration

The ordering/atomicity/append-only guarantee is about the real dispatcher PreToolUse path against a
live filesystem — it cannot be shown by a pure unit test of a helper; it needs the actual gate
invocation observing on-disk state across the staged sequence, the same harness class VP-093/VP-105
use. (The crash-recovery of a partial staged sequence is covered separately by VP-138/VP-139.)

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/shard_roll_ordering_test.rs
// VP-118: BC-1.18.006 PC1(staged 4-step)/PC4/PC5/INV2/INV3/INV5

#[test]
fn test_BC_1_18_006_PC1_staged_roll_complete_when_block_observed() {
    let cx = DispatchHarness::with_cycle_fixture(current_bytes = 45_000, cap = 49_152);
    let content_before = cx.read("decision-log.md");
    let res = cx.dispatch_write("decision-log.md", payload = 5_000);
    assert!(matches!(res, HookResult::Block { .. }));
    // (b) sealed shard published as a NEW file holding the pre-roll content:
    assert!(cx.path_exists("decision-log.0001.md"));
    assert_eq!(cx.read("decision-log.0001.md"), content_before);
    // (c) canonical atomically truncated IN PLACE (never renamed away):
    assert_eq!(cx.byte_len("decision-log.md"), 0);
    // (d) index appended the [[shard]] entry:
    let idx = cx.read_shard_index("decision-log");
    assert_eq!(idx.shards.last().unwrap().seq, 1);
}

#[test]
fn test_BC_1_18_006_PC4_shard_and_index_both_staged_before_any_git() {
    let cx = DispatchHarness::with_cycle_fixture(current_bytes = 45_000, cap = 49_152);
    cx.dispatch_write("decision-log.md", payload = 5_000);
    assert!(cx.working_tree_contains("decision-log.0001.md"));
    assert!(cx.working_tree_contains("decision-log.shard-index.toml"));
}

#[test]
fn test_BC_1_18_006_PC5_INV3_index_append_only_and_canonical_never_renamed() {
    let cx = DispatchHarness::with_cycle_fixture(current_bytes = 45_000, cap = 49_152);
    let canon_inode = cx.inode("decision-log.md");
    cx.dispatch_write("decision-log.md", payload = 5_000);         // seq 1
    let seq1 = cx.read_shard_index("decision-log").shards[0].clone();
    cx.fill_current_shard(45_000);
    cx.dispatch_write("decision-log.md", payload = 5_000);         // seq 2
    let idx = cx.read_shard_index("decision-log");
    assert_eq!(idx.shards[0], seq1);                               // prior entry byte-identical (append-only)
    assert_eq!(idx.shards[1].seq, 2);                              // monotonic append at the tail
    assert!(cx.stat("decision-log.md").is_ok());                  // canonical always present
    assert_ne!(cx.inode("decision-log.md"), cx.any_sealed_inode()); // never a sealed inode
    let _ = canon_inode;
}
```
