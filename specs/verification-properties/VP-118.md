# VP-118: Roll Executes Seal→Create→Atomic-Index-Publish Before the Block Is Returned; Shard and Index Land in the Same Invocation

## Property Statement

When BC-1.18.005's trigger fires, the roll is observably complete and atomic by the time the caller
sees the block.

1. **Seal-then-block ordering.** At the instant the caller receives `HookResult::Block`, the current
   shard has already been sealed (renamed to `<stem>.<seq:04>.md`), a fresh empty current file
   exists at the canonical name, and the shard-index TOML already contains the `[[shard]]` entry for
   this roll (BC-1.18.006 §Postcondition 1). The dispatcher harness reads the index file the moment
   it observes the Block and finds the seal entry present — the seal is never lagging behind the
   block.

2. **Same-invocation atomicity.** The shard-index write (step (c)) and the seal rename (step (a))
   are both filesystem writes issued by the SAME PreToolUse invocation, before any `git add`/`git
   commit` (BC-1.18.006 §Postcondition 4). Both are present in the working tree together, so
   TD-VSDD-053 single-commit-per-burst holds structurally for shard+index atomicity regardless of
   which agent or skill issued the original tool call.

3. **Never reordered.** The index is never published before the seal completes, and the fresh file
   is never created before the old content is sealed away (BC-1.18.006 §Invariant 2) — verified by
   asserting the on-disk state at each observable step of a harness-driven roll.

### Why integration

The ordering/atomicity guarantee is about the real dispatcher PreToolUse path against a live
filesystem — it cannot be shown by a pure unit test of a helper; it needs the actual gate
invocation observing on-disk state, the same harness class VP-093/VP-105 use.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/shard_roll_ordering_test.rs
// VP-118: BC-1.18.006 PC1/PC4/INV2

#[test]
fn test_BC_1_18_006_PC1_index_entry_present_when_block_observed() {
    let cx = DispatchHarness::with_cycle_fixture(current_bytes = 45_000, cap = 49_152);
    let res = cx.dispatch_write("decision-log.md", payload = 5_000);
    assert!(matches!(res, HookResult::Block { .. }));
    let idx = cx.read_shard_index("decision-log");
    assert_eq!(idx.shards.last().unwrap().seq, 1);                 // seal entry present at Block time
    assert!(cx.path_exists("decision-log.0001.md"));
    assert_eq!(cx.byte_len("decision-log.md"), 0);                 // fresh current shard
}

#[test]
fn test_BC_1_18_006_PC4_shard_and_index_both_staged_before_any_git() {
    let cx = DispatchHarness::with_cycle_fixture(current_bytes = 45_000, cap = 49_152);
    cx.dispatch_write("decision-log.md", payload = 5_000);
    assert!(cx.working_tree_contains("decision-log.0001.md"));
    assert!(cx.working_tree_contains("decision-log.shard-index.toml"));
}
```
