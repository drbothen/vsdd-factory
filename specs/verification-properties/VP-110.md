# VP-110: Full-Recovery Split Completes in Bounded Time/Memory for Arbitrarily Long Input (Linear-Scan Property)

## Property Statement

For a `last_amended` raw value of arbitrary length (including the D-1149 calibration ceiling of
~323,499 to ~350,000 characters with dozens of chained entries):

1. `check_eligibility`'s classification is a single `str::contains` call (Two-Way substring-search
   algorithm) — one linear-time pass over the haystack, never re-scanned.
2. `split_tail_entries`'s marker scan is a single forward-scanning cursor: each `str::find` call
   searches only the REMAINING slice from the current cursor onward, never re-scanning from index
   0 — the total work across all iterations is `O(n)` in the tail's length.
3. `migrate_file`'s end-to-end PC7 split against a mega-line fixture completes within a bounded
   wall-clock budget, not merely "eventually" — no unbounded memory growth or non-linear runtime
   blowup, satisfying BC-10.13.001 Invariant 3.

This is precisely the operation Edit/Write-tool-mediated manual editing cannot perform safely at
this scale, and is why PC7 (not just PC2's maintain-only shape-confirmation) makes the tool a full
replacement for D-1149's one-time human-authorized POL-3 exception.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| unit-test | Rust (`#[test]`, wall-clock assertion) | yes — asserts completion within a fixed time budget against a fixed mega-line fixture | eligibility classification bounded-time (`check_eligibility`); end-to-end split bounded-time (`migrate_file` PC7 path) |

### Why unit-test (not benchmark/proptest)

The BC's original candidate proof method proposed a `benchmark`/`proptest` sweep across a range of
chain sizes to demonstrate linear (not super-linear) growth empirically. The property this VP
registers today is the weaker, already-implemented guarantee: a single fixed mega-line fixture
(calibrated to the D-1149 323,499-char case) completes within a bounded wall-clock budget — this is
sufficient to catch a regression to quadratic/backtracking behavior (which would blow the budget by
orders of magnitude on a fixture this size) without requiring a parametrized benchmark harness. The
STRUCTURAL argument for true `O(n)` complexity is carried by the code itself (see Proof Harness
Skeleton comments: single forward cursor, no backtracking regex, no repeated substring re-scan from
index 0) and is verifiable by inspection of `split_tail_entries`/`check_eligibility`. A
multi-size-sweep benchmark remains a valid future hardening step and is not required to close this
VP's initial registration, since no BC postcondition or invariant requires empirical curve-fitting
— only "no unbounded memory growth or non-linear runtime blowup" at the documented calibration
scale, which the fixed-fixture bounded-time assertion already demonstrates.
