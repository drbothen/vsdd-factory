# VP-136: B1 Backfill Migration — Independent-Census Integrity, Fail-Loud Rollback (E-SHD-003), and Idempotency Against an Already-Steady-State Sequence

## Property Statement

The B1 cold-start `changelog:` backfill migration (BC-1.18.012) is census-verified, fail-loud, and
idempotent — the direct `changelog:`-item-count analogue of VP-124 (mechanism A) and VP-133
(mechanism B2), consolidating three same-method (integration) obligations per the single-method-per-VP
convention.

1. **Independent-census integrity.** The migration captures a FRESH pre-migration `changelog:`
   item count (a re-enumeration, NOT `BC-INDEX.md`'s `total_bcs` field, which counts BC rows, a
   different oracle) and, after `rotate_changelog` completes, verifies
   `(items retained in the live frontmatter) + (items appended to the archive) == (pre-migration
   count)` EXACTLY (BC-1.18.012 §Postcondition 3, §Invariant 2). A byte-identical archive append
   that nonetheless duplicates one item and drops another (a compensating error) still FAILS the
   census — census and content-preservation (VP-135) are independently mandatory; neither
   substitutes for the other.

2. **Fail-loud rollback on census failure.** If the census does not reconcile, the migration
   ABORTS: `BC-INDEX.md`'s frontmatter is left byte-identical to its exact pre-migration state — no
   partially-rotated `changelog:` sequence and no partial archive append is ever treated as
   authoritative (BC-1.18.012 §Postcondition 5, §Invariant 3). The failure surfaces `E-SHD-003`
   (reused per §Postcondition 5 — its wording is artifact-generic, not decision-log-specific), never
   a silent partial success.

3. **Never partially applied.** At every observable instant — before, during, and after — the live
   `changelog:` sequence is either the FULL original (cold, oversized) sequence or the FULL
   post-migration (`<= N`-item) sequence; it is never observed holding archived items still
   duplicated in the frontmatter, nor missing items that were neither retained nor archived
   (BC-1.18.012 §Invariant 3, §EC-004 recovery from an interrupted prior attempt).

4. **Idempotency against an already-steady-state sequence.** Re-running the migration against a
   `changelog:` sequence already `<= N` items (its own prior success, or a subsequent BC-1.18.009
   per-write rotation, already brought it under N) is a safe no-op: it detects the sequence is
   within bound and exits WITHOUT invoking `rotate_changelog` again — zero writes, frontmatter
   unchanged (BC-1.18.012 §Postcondition 7, §EC-003, §EC-006). This is the SAME under-N condition
   as BC-1.18.009 EC-002, evaluated once at F4 activation instead of per-write.

Numeric `N` is **PROVISIONAL-until-F4**; every property here is relative to the configured `N` and
the measured pre-migration count, so the property is structural and value-agnostic.

## Proof Method

| Leg | Method | Tool | Coverage | Status |
|-----|--------|------|----------|--------|
| Independent census | integration | dispatcher/migration harness over synthetic `changelog:` fixtures of varying sizes | `retained + archived == pre-migration count`; fresh enumeration, not `total_bcs` | feasible-pending-harness (F4 code) |
| Fail-loud rollback | integration (fault injection) | injected census-mismatch (1 item lost in a simulated corrupted `rotate_changelog`) | migration ABORTS `E-SHD-003`; frontmatter byte-identical to pre-attempt state | feasible-pending-harness (F4 code) |
| Idempotency | integration | double-invocation fixture; already-`<= N` fixture | second run / already-steady-state: zero `rotate_changelog` calls, zero writes | feasible-pending-harness (F4 code) |

### Why integration

Census reconciliation over the live frontmatter, crash/mismatch rollback leaving the file
byte-identical, and double-invocation idempotency are real-substrate filesystem/process properties
against `rotate_changelog`'s actual `write_atomic` ordering — the fault-injection integration class
VP-124 / VP-133 already use, not a pure-helper unit test. The three obligations share this single
method, so they are consolidated into one VP (the VP-124 / VP-133 consolidation precedent).

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/b1_backfill_migration_test.rs
// VP-136: BC-1.18.012 PC3/PC5/PC7/INV2/INV3/EC-002..EC-006

#[test]
fn test_BC_1_18_012_PC3_census_reconciles_exactly() {
    let idx = SimBcIndex::with_changelog_items(1997);
    let before = idx.pre_migration_item_count();            // fresh enumeration, not total_bcs
    let r = idx.run_b1_backfill_migration(/*keep_recent*/ 50);
    assert!(r.is_ok());
    assert_eq!(idx.retained_item_count() + idx.archived_item_count(), before); // 50 + 1947 == 1997
}

#[test]
fn test_BC_1_18_012_PC5_census_failure_aborts_fail_loud_original_preserved() {
    let idx = SimBcIndex::with_changelog_items(1997);
    let snapshot = idx.read_frontmatter_bytes();
    let r = idx.run_b1_backfill_migration_with_injected_census_mismatch(/*keep_recent*/ 50);
    assert!(matches!(r, Err(ShardError::Preservation { code, .. }) if code == "E-SHD-003"));
    assert_eq!(idx.read_frontmatter_bytes(), snapshot);     // byte-identical pre-migration state
}

#[test]
fn test_BC_1_18_012_PC7_idempotent_no_op_when_already_within_bound() {
    let idx = SimBcIndex::with_changelog_items(40);         // already <= N=50
    let before = idx.read_frontmatter_bytes();
    let r = idx.run_b1_backfill_migration(/*keep_recent*/ 50);
    assert!(r.is_ok());
    assert_eq!(idx.rotate_changelog_invocations(), 0);      // no-op
    assert_eq!(idx.read_frontmatter_bytes(), before);       // unchanged
}
```
