# VP-115: Bounded last_amended Byte Length Across Cumulative Bursts (Fuel-Relief Structural Proxy)

## Property Statement

This VP registers all three of BC-4.18.001's postconditions as one property with three legs of
distinct maturity — PC1 is PROVEN today by a real crate unit test; PC2/PC3 are fully specified but
not yet harnessed (their harness is a dispatcher-level regression fixture outside this crate's own
scope).

1. **PC1 (structural bound — PROVEN).** After any number N ≥ 0 of synthetic bursts, each
   overwriting `last_amended` and prepending one `changelog:` item under BC-5.45.001's discipline,
   `last_amended`'s own byte length never exceeds a fixed per-entry ceiling — it is always exactly
   one dated entry, independent of N. This is the structural guarantee that a mega-line (the
   pre-fix 323,499-char case) cannot re-form. Verified across all five ADR-049-governed target
   files, including a fixture entry carrying a D-1144 quote defect (confirming the escape fix does
   not itself grow the byte-length ceiling).

2. **PC2 (synthetic-burst fuel-budget regression — feasible-pending-harness).** A representative
   run of N synthetic state-manager bursts against a post-migration fixture completes within the
   configured fuel budget for the real `legacy-bash-adapter`-hosted validator(s), producing zero
   `plugin.indeterminate`(cause=fuel) events. NOT YET IMPLEMENTED in this crate — requires a
   dispatcher-binary-level regression fixture (`crates/hook-plugins/legacy-bash-adapter/` +
   `crates/factory-dispatcher/src/invoke.rs`), which is a separate harness from
   `last-amended-migrate`'s own crate tests.

3. **PC3 (differential pre-fix/post-fix reproduction — feasible-pending-harness).** A differential
   test comparing a PRE-FIX mega-line fixture (which MUST reproduce fuel exhaustion, establishing
   the negative control) against a POST-FIX ADR-049-shaped fixture at equivalent cumulative history
   depth (which MUST NOT exhaust the fuel budget). NOT YET IMPLEMENTED; same dispatcher-level
   harness dependency as PC2.

## Source Contract

- **BC:** BC-4.18.001 §Postcondition 1 (PC1), §Postcondition 2 (PC2), §Postcondition 3 (PC3);
  Invariant 1 — fuel consumption grows at most linearly with `changelog:` size, independent of
  burst count for `last_amended` specifically; Invariant 2 — this BC changes no validator code and
  no fuel-cap constant.
- **ADR:** ADR-049 §Context (743-fuel-timeouts/day symptom); ADR-042 §Decision 1
  (`DEFAULT_FUEL_CAP`).

## Proof Method

| PC | Method | Tool | Bounded? | Coverage | Status |

| PC2 | integration | bats + real `legacy-bash-adapter` WASM validator via factory-dispatcher binary | to be determined by harness design | N-synthetic-burst run against a post-migration fixture; assert zero `plugin.indeterminate`(cause=fuel) | feasible-pending-harness |

### Why unit-test for PC1, and why PC2/PC3 remain feasible-pending-harness

PC1 is a pure structural claim about `last_amended`'s byte length as a function of burst count —
provable entirely within `last-amended-migrate`'s own crate via a synthetic-burst loop over
in-memory `FrontmatterDoc` state, with no dependency on the real WASM validator runtime. PC2/PC3
are claims about the REAL `legacy-bash-adapter`-hosted validator's fuel consumption under the
`factory-dispatcher` binary — this requires a harness that invokes the actual dispatcher binary
against WASM plugins (the same class of harness VP-086/VP-093/VP-105 in this index already use),
which is architecturally outside `last-amended-migrate`'s own crate (a standalone CLI binary with
no WASM/dispatcher dependency). Registering PC2/PC3 as `feasible-pending-harness` here — rather
than leaving them as BC-level "TBD — route to architect" — closes the spec-gap (a VP-NNN ID with a
fully specified Property Statement and Proof Method now exists) while being honest that the harness
itself is test-writer/formal-verifier follow-up work, not something achievable by an
architecture-file-only VP-registration burst.
