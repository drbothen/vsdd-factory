# VP-100: Drain-Timer Expiry Emits Exactly One plugin.abandoned Per In-Flight (plugin_name, entry_index); No plugin.completed Follows for Same Trace

## Property Statement

When the async drain timer expires (at `ASYNC_DRAIN_WINDOW_MS` per DI-019), for each in-flight
async plugin task identified by `(plugin_name, entry_index)`:

**Postcondition A — Exactly-one plugin.abandoned:**
The dispatcher MUST emit exactly ONE `plugin.abandoned` event with the matching `plugin_name`
and `entry_index` fields. No second `plugin.abandoned` for the same `(plugin_name, entry_index)`
MUST be emitted in the same dispatcher invocation (BC-3.08.001 §Invariant 6).

**Postcondition B — No plugin.completed follows:**
After `plugin.abandoned` is emitted for `(plugin_name, entry_index, trace_id)`, no
`plugin.completed` event with the same `trace_id + plugin_name + entry_index` triple MUST
appear in `events-*.jsonl`. The task is terminated; completion is impossible
(BC-3.08.001 §Invariant 6).

**Postcondition C — Mandatory fields present:**
Each `plugin.abandoned` event MUST carry all mandatory fields: `type`, `trace_id`,
`session_id`, `plugin_name`, `entry_index`, `timestamp`
(BC-3.08.001 Invariant 6 field table).

## Source Contract

- **BC:** BC-3.08.001 §Invariant 6 — drain-timer `plugin.abandoned` exactly-once; no
  `plugin.completed` follows; mandatory field set.
- **Domain Invariant:** DI-019 — canonical `ASYNC_DRAIN_WINDOW_MS` constant governing when drain
  timer fires.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| integration | bats (dispatcher binary + synthetic async-plugin fixtures) | yes — 2 in-flight tasks; timer-expired scenario | exactly-one count; no-plugin.completed; mandatory fields |

### Why integration

The property spans the async drain loop in `factory_dispatcher::main::run`, the event emission
path, and FileSink I/O. Bats fixtures construct registries with N slow async plugins (that
exceed the drain window), allow the timer to fire, and assert the resulting JSONL output.
Mirrors VP-079 Scenario 5 pattern.

## Proof Harness Skeleton

```bash
#!/usr/bin/env bats
# vp100-plugin-abandoned.bats
# VP-100: BC-3.08.001 §Invariant 6 — exactly one plugin.abandoned per in-flight at drain expiry

PLUGIN_ROOT=""
SINK_FILE=""

setup() {
    PLUGIN_ROOT=$(mktemp -d)
    SINK_FILE=$(mktemp --suffix=.jsonl)
    mkdir -p "$PLUGIN_ROOT/hook-plugins" "$PLUGIN_ROOT/test-fixtures"
    printf '%s\n' "sleep 60" > "$PLUGIN_ROOT/test-fixtures/sleep60.sh"
    printf '%s\n' "exit 0"   > "$PLUGIN_ROOT/test-fixtures/exit0.sh"
    chmod +x "$PLUGIN_ROOT/test-fixtures/"*.sh
    # Create registry with 2 slow async plugins + 1 fast sync plugin
    printf '%s' '
schema_version = 2

[[hooks]]
name = "sync-gate"
plugin = "hook-plugins/legacy-bash-adapter.wasm"
on_error = "block"
async = false
event = "PostToolUse"
priority = 50
[hooks.config]
script_path = "test-fixtures/exit0.sh"

[[hooks]]
name = "slow-async-1"
plugin = "hook-plugins/legacy-bash-adapter.wasm"
on_error = "continue"
async = true
timeout_ms = 50
event = "PostToolUse"
priority = 100
[hooks.config]
script_path = "test-fixtures/sleep60.sh"

[[hooks]]
name = "slow-async-2"
plugin = "hook-plugins/legacy-bash-adapter.wasm"
on_error = "continue"
async = true
timeout_ms = 50
event = "PostToolUse"
priority = 101
[hooks.config]
script_path = "test-fixtures/sleep60.sh"
' > "$PLUGIN_ROOT/hooks-registry.toml"
}

teardown() {
    rm -rf "$PLUGIN_ROOT"
    rm -f "$SINK_FILE"
}

dispatch_event() {
    local envelope
    envelope='{"hook_event_name":"PostToolUse","tool_name":"Write","session_id":"vp100-test","tool_input":{},"output":{}}'
    printf '%s' "$envelope" | \
        CLAUDE_PLUGIN_ROOT="$PLUGIN_ROOT" \
        VSDD_SINK_FILE="$SINK_FILE" \
        CLAUDE_PROJECT_DIR="$PLUGIN_ROOT" \
        factory-dispatcher 2>/dev/null || true
}

@test "VP-100-A: exactly one plugin.abandoned per in-flight task at drain expiry" {
    dispatch_event
    local count_1
    count_1=$(grep '"type":"plugin.abandoned"' "$SINK_FILE" 2>/dev/null | grep '"plugin_name":"slow-async-1"' | wc -l | tr -d ' ')
    [ "$count_1" -eq 1 ] || {
        echo "FAIL: expected 1 plugin.abandoned for slow-async-1; got $count_1"; return 1
    }
    local count_2
    count_2=$(grep '"type":"plugin.abandoned"' "$SINK_FILE" 2>/dev/null | grep '"plugin_name":"slow-async-2"' | wc -l | tr -d ' ')
    [ "$count_2" -eq 1 ] || {
        echo "FAIL: expected 1 plugin.abandoned for slow-async-2; got $count_2"; return 1
    }
}

@test "VP-100-B: no plugin.completed follows plugin.abandoned for same plugin" {
    dispatch_event
    local abandoned_plugin
    abandoned_plugin=$(grep '"type":"plugin.abandoned"' "$SINK_FILE" 2>/dev/null | head -1 \
        | python3 -c "import sys,json; d=json.loads(sys.stdin.read()); print(d['plugin_name'])" 2>/dev/null)
    [ -n "$abandoned_plugin" ] || skip "no plugin.abandoned in sink"
    if grep '"type":"plugin.completed"' "$SINK_FILE" 2>/dev/null | grep -q "\"plugin_name\":\"$abandoned_plugin\""; then
        echo "FAIL: plugin.completed found after plugin.abandoned for $abandoned_plugin"
        return 1
    fi
}

@test "VP-100-C: plugin.abandoned carries all mandatory fields" {
    dispatch_event
    local line
    line=$(grep '"type":"plugin.abandoned"' "$SINK_FILE" 2>/dev/null | head -1)
    [ -n "$line" ] || skip "no plugin.abandoned in sink"
    for field in type trace_id session_id plugin_name entry_index timestamp; do
        echo "$line" | python3 -c "
import sys,json
d=json.loads(sys.stdin.read())
assert '$field' in d, 'MISSING field: $field'
" || { echo "FAIL: mandatory field '$field' absent from plugin.abandoned"; return 1; }
    done
}
```
