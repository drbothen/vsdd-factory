# VP-106: Successful Re-Validation Deletes Marker (artifact-scoped; EC-008/EC-009); fail-open INDETERMINATE Writes No Marker

## Property Statement

This VP covers two complementary properties that define the lifecycle boundaries of the marker:

**Postcondition A — Successful re-validation clears the marker (artifact-scoped):**
When the same plugin that produced INDETERMINATE is subsequently dispatched PostToolUse on the
same artifact and produces `DispatchOutcome::Pass` (exit_code=0, `host_output_too_large_seen=false`),
the executor MUST delete `.factory/unvalidated-mutation.marker`. "Same artifact" means the current
dispatch's artifact path matches the marker's `artifact_path` field by exact string equality of the
normalized absolute path (BC-1.18.003 §PC1/§INV2; ADR-047 §D5). The deletion MUST be idempotent
(no error if marker is already absent at delete time). After deletion, a subsequent Agent dispatch
MUST be allowed by the gate (VP-105 Postcondition B path).

**Postcondition B — fail-open INDETERMINATE writes no marker:**
When a plugin with `failure_policy = FailOpen` produces INDETERMINATE (any cause: fuel, epoch,
OutputTooLarge), the executor MUST NOT write `.factory/unvalidated-mutation.marker`. A
`plugin.indeterminate` advisory event MAY be emitted, but no durable marker is written and the
next-advance gate is NOT triggered.

This is the explicit backward-compatibility preservation test from ADR-047 §Decision 7.

**Postcondition C — fail-closed FAIL does not clear the marker:**
When the re-validating plugin produces FAIL (exit_code!=0), the marker MUST NOT be deleted.
The unvalidated state persists until either a successful re-validation or manual operator deletion.

**Postcondition D — Different non-empty artifact does not clear the marker (EC-008):**
When the same plugin named in the marker's `plugin_name` field is dispatched PostToolUse and
produces `DispatchOutcome::Pass`, BUT the current artifact path is a different non-empty path
than the marker's `artifact_path`, the executor MUST NOT delete the marker. Artifact A's
quarantine persists — the plugin validated artifact B successfully but artifact A was never
re-validated. The gate remains active until the named plugin produces PASS on artifact A
specifically, or the operator performs manual deletion (BC-1.18.003 §INV2; ADR-047 §D5).

**Postcondition E — Empty marker artifact_path triggers name-only clear (EC-009):**
When the marker's `artifact_path` field is empty (written by a non-artifact-scoped validator
such as a wave-gate or path-staging validator), the artifact-path matching condition is
vacuously satisfied. If the same plugin named in `plugin_name` produces `DispatchOutcome::Pass`
on any artifact, the executor MUST delete the marker. Plugin-name equality alone suffices for
clearance in this case (BC-1.18.003 §PC1/§INV2 empty-path exception; ADR-047 §D5).

**Postcondition F — TTL-expiry clear path: expired marker → cleared by dispatcher-native pre-check
(BC-1.18.003 §PC4; ADR-048 §D2; retargeted v1.5 per ADR-048 §D4 v1.2):**
When `check_and_clear_expired_marker` (dispatcher-native, `indeterminate_marker.rs`) reads the
marker TOML and the `expires_at` field is present AND has elapsed (current UTC time is at or
after `expires_at`), it MUST automatically delete the marker file and return `Some(fields)`
(signaling the caller — `executor.rs`'s tier-execution loop — to treat the dispatch as Allow and
to emit `marker.cleared(TTL_EXPIRED)`, per VP-108 Postcondition 2). This is the TTL deadman path:
after `UNVALIDATED_MUTATION_MARKER_TTL_SECONDS = 86_400` seconds (24 hours), the marker self-heals
without any operator action. This native pre-check runs BEFORE the WASM gate plugin's
`evaluate_gate` is invoked — an expired marker is deleted, and the dispatch treated as Allow,
before `evaluate_gate` (which has no `expires_at` awareness of its own as of ADR-048 §D4 v1.2)
ever sees it. **v1.5 correction:** v1.0–v1.4 attributed this decision to `evaluate_gate` itself;
that attribution is superseded — `evaluate_gate` cannot honor the `marker.cleared` wire contract
(BC-3.08.001 Event 9) from inside the WASM sandbox (RESERVED_FIELDS wall; ADR-048 §D4 v1.2), so
the TTL determination, deletion, and (per VP-108) emission are all dispatcher-native.
Emission-field correctness is VP-108 Postcondition 2 scope, not duplicated here — this VP's scope
remains the clear DECISION (Some/None + file state), matching its established framing relative to
VP-108 (see VP-108's Cross-dependency note).

**Postcondition G — Legacy marker without expires_at field → non-expired, NOT cleared
(conservative; INV5; retargeted v1.5 per ADR-048 §D4 v1.2):**
When `check_and_clear_expired_marker` reads a marker TOML where the `expires_at` field is absent
(marker written before ADR-048 §D2 introduced the TTL field) or present-but-not-yet-elapsed, it
MUST treat the marker as non-expired: return `None` and leave the marker file in place
undeleted. The subsequent `evaluate_gate` invocation then sees a still-present marker and
returns Block (exit_code=2) unconditionally — `evaluate_gate` requires no `expires_at` awareness
to do this once TTL determination has moved dispatcher-native; it is a pure presence check. The
conservative posture prevents a TTL-migration path from inadvertently unblocking a quarantine.
Operators must manually clear legacy markers. This ensures backward compatibility with
pre-ADR-048 marker files (BC-1.18.003 §INV5; ADR-048 §D2). **v1.5 correction:** as with
Postcondition F, v1.0–v1.4 attributed the "treat as non-expired" determination to `evaluate_gate`
itself; that determination is now made by `check_and_clear_expired_marker` — `evaluate_gate`'s
resulting Block behavior is an unconditional consequence of marker presence, not a TTL-aware
decision of its own.

**INV5 — Marker-level TTL (BC-1.18.003 §Invariant 5):**
Every marker produced after the ADR-048 §D2 TTL extension MUST include an `expires_at` field
set to `write_time + UNVALIDATED_MUTATION_MARKER_TTL_SECONDS` (86400 seconds). This invariant
is stamped by the writer (`write_indeterminate_marker` in `indeterminate_marker.rs`). The
TTL guarantee: no marker persists beyond 24 hours from its write time regardless of dispatch
activity or operator inaction.

## Source Contract

- **BC:** BC-1.18.003 §Postcondition 1 —
  successful re-validation (same plugin, same artifact, PASS outcome) deletes the marker.
- **BC:** BC-1.18.004 §Postcondition 2 —
  fail-open INDETERMINATE writes no marker (backward-compatibility preservation).
- **ADR:** ADR-047 §Decision 5 — Marker Clear Protocol; artifact-scoped clear requires (a)
  plugin_name match AND (b) artifact_path match (exact normalized absolute path equality);
  empty `artifact_path` falls back to name-only (EC-009); NOT cleared by FAIL re-validation;
  NOT cleared by same plugin on different non-empty artifact (EC-008); idempotent deletion.
- **BC:** BC-1.18.003 §Invariant 2 — clear is scoped to named plugin AND original artifact;
  empty-path exception: if marker's `artifact_path` is empty, plugin_name equality alone suffices.
- **ADR:** ADR-047 §Decision 2 — `failure_policy = fail-open` → INDETERMINATE is advisory-only,
  no marker written.
- **ADR:** ADR-047 §Decision 7 — Backward-Compatibility Contract; `test_BC_1_18_004_fail_open_default_preserves_advisory_behavior` must not be deleted.
- **BC:** BC-1.18.003 §Postcondition 4 (PC4) — TTL-expiry clear path: expired `expires_at` → `check_and_clear_expired_marker` (dispatcher-native) deletes the marker (PC-F above; retargeted v1.5 per ADR-048 §D4 v1.2 — `evaluate_gate` has no `expires_at` awareness).
- **BC:** BC-1.18.003 §Invariant 5 (INV5) — marker-level TTL: every marker written after ADR-048 §D2 stamps `expires_at = write_time + 86400s`; legacy absent `expires_at` treated as non-expired (PC-G above).
- **ADR:** ADR-048 §Decision 2 — `expires_at` TTL field: `write_indeterminate_marker` stamps it; `check_and_clear_expired_marker` (dispatcher-native, v1.5 retarget) checks it and auto-deletes on expiry; legacy absent `expires_at` treated as non-expired (conservative).
- **ADR:** ADR-048 §Decision 4 v1.2 Emission-Point Correction (v1.5 addition) — TTL determination moved from `evaluate_gate` (WASM) to `check_and_clear_expired_marker` (dispatcher-native) because the marker.cleared wire contract cannot be honored from inside the WASM sandbox (RESERVED_FIELDS wall).

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| unit-test | Rust (#[test] with tempdir) | yes — 10 cases covering all postconditions and edge cases | PASS-re-validation deletes marker (same plugin + same artifact; PC-A); fail-open INDETERMINATE no marker (PC-B); FAIL re-validation preserves marker (PC-C); idempotent delete — marker already absent; fail-open default (absent field) no marker; same plugin + DIFFERENT non-empty artifact PASS does NOT delete (EC-008; PC-D); empty marker artifact_path + name match PASS deletes (EC-009; PC-E); TTL: expired expires_at → `check_and_clear_expired_marker` returns Some + auto-deletes marker (PC-F; v1.5 retarget); TTL: non-expired expires_at → `check_and_clear_expired_marker` returns None + `evaluate_gate` Block still active; legacy absent expires_at → `check_and_clear_expired_marker` returns None + `evaluate_gate` Block conservative (PC-G/INV5; v1.5 retarget) |

### Why unit-test

The marker clear pathway (`delete_marker_if_pass`) is a pure function of
`(outcome: DispatchOutcome, policy: FailurePolicy, dir: &Path, current_artifact_path: &str)` →
`Result<(), io::Error>`. It reads the marker TOML (when present) to compare `plugin_name` and
`artifact_path` fields before deciding whether to delete, enabling artifact-scoped clear (EC-008)
and the empty-path fallback (EC-009). The marker write pathway for fail-open is verified by
asserting `write_indeterminate_marker` is NOT called when `FailurePolicy::FailOpen`. Both are
in-process Rust calls with no WASM dependency. Tempdir fixtures capture filesystem state.

// crates/factory-dispatcher/src/tests/vp_106_marker_lifecycle.rs
// VP-106: BC-1.18.003 PC1 + BC-1.18.004 PC2 — marker lifecycle (clear on re-validation; fail-open no marker)

#[cfg(test)]
mod vp_106 {
    use super::*;
    use crate::indeterminate_marker::{
        write_indeterminate_marker, delete_marker_if_pass, check_and_clear_expired_marker,
        IndeterminateCause,
    };
    use crate::executor::{DispatchOutcome, FailurePolicy};
    use std::fs;
    use tempdir::TempDir;

    fn factory_dir(parent: &TempDir) -> std::path::PathBuf {
        let d = parent.path().join(".factory");
        fs::create_dir_all(&d).unwrap();
        parent.path().to_path_buf()
    }

    fn marker_path(dir: &std::path::Path) -> std::path::PathBuf {
        dir.join(".factory").join("unvalidated-mutation.marker")
    }

    fn write_marker(dir: &std::path::Path) {
        write_indeterminate_marker(
            dir,
            "regression-gate",
            &dir.join(".factory").join("STATE.md"),
            IndeterminateCause::Fuel,
            "deadbeef-0001-0001-0001-000000000001",
        ).unwrap();
    }

    /// Write a marker with an explicit artifact_path string (supports empty string for EC-009).
    fn write_marker_for_artifact(dir: &std::path::Path, artifact_path_str: &str) {
        let marker_dir = dir.join(".factory");
        fs::create_dir_all(&marker_dir).unwrap();
        let marker_file = marker_dir.join("unvalidated-mutation.marker");
        let content = format!(
            "timestamp = \"2026-08-31T00:00:00Z\"\nplugin_name = \"regression-gate\"\nartifact_path = {:?}\ncause = \"fuel\"\ntrace_id = \"deadbeef-0001-0001-0001-000000000001\"\n",
            artifact_path_str
        );
        fs::write(&marker_file, content).unwrap();
    }

    #[test]
    fn test_BC_1_18_003_pass_revalidation_deletes_marker() {
        let tmp = TempDir::new("vp106_clear").unwrap();
        let dir = factory_dir(&tmp);

        // Pre-condition: marker exists
        write_marker(&dir);
        assert!(marker_path(&dir).exists(), "setup: marker must exist before re-validation");

        // Simulate PASS outcome on same plugin, same artifact (artifact_path must match marker)
        let artifact = dir.join(".factory").join("STATE.md");
        delete_marker_if_pass(DispatchOutcome::Pass, FailurePolicy::FailClosed, &dir, artifact.to_str().unwrap())
            .expect("delete_marker_if_pass must not error");

        assert!(!marker_path(&dir).exists(),
            "VP-106: PASS re-validation MUST delete .factory/unvalidated-mutation.marker (BC-1.18.003 PC1)");
    }

    #[test]
    fn test_BC_1_18_004_fail_open_indeterminate_writes_no_marker() {
        // This is the canonical backward-compatibility preservation test (ADR-047 §Decision 7)
        // DO NOT DELETE THIS TEST — it must be cited in the story spec
        let tmp = TempDir::new("vp106_failopen").unwrap();
        let dir = factory_dir(&tmp);

        // Simulate INDETERMINATE outcome on fail-open plugin
        // (the executor should NOT call write_indeterminate_marker for fail-open)
        // Here we test the guard condition directly:
        let should_write = should_write_marker(DispatchOutcome::Indeterminate, FailurePolicy::FailOpen);
        assert!(!should_write,
            "VP-106: fail-open INDETERMINATE MUST NOT trigger marker write (BC-1.18.004 PC2; ADR-047 §D7)");
        // Explicitly assert no marker file was created
        assert!(!marker_path(&dir).exists(),
            "VP-106: no marker file MUST exist after fail-open INDETERMINATE dispatch");
    }

    #[test]
    fn test_BC_1_18_003_fail_revalidation_preserves_marker() {
        let tmp = TempDir::new("vp106_fail_preserve").unwrap();
        let dir = factory_dir(&tmp);

        // Pre-condition: marker exists
        write_marker(&dir);
        assert!(marker_path(&dir).exists());

        // Simulate FAIL outcome on re-validation (plugin found the write was bad)
        let artifact = dir.join(".factory").join("STATE.md");
        delete_marker_if_pass(DispatchOutcome::Fail, FailurePolicy::FailClosed, &dir, artifact.to_str().unwrap())
            .expect("delete_marker_if_pass on Fail MUST NOT error");

        assert!(marker_path(&dir).exists(),
            "VP-106: FAIL re-validation MUST NOT delete marker; unvalidated state persists (ADR-047 §D5)");
    }

    #[test]
    fn test_BC_1_18_003_idempotent_delete_when_marker_absent() {
        let tmp = TempDir::new("vp106_idempotent").unwrap();
        let dir = factory_dir(&tmp);

        // No marker file
        assert!(!marker_path(&dir).exists());

        // Delete when absent: must be a no-op (not an error) — artifact_path irrelevant (no marker to read)
        let artifact = dir.join(".factory").join("STATE.md");
        let result = delete_marker_if_pass(DispatchOutcome::Pass, FailurePolicy::FailClosed, &dir, artifact.to_str().unwrap());
        assert!(result.is_ok(),
            "VP-106: idempotent delete MUST NOT error when marker is already absent (ADR-047 §D5)");
    }

    #[test]
    fn test_BC_1_18_004_fail_open_absent_field_default_no_marker() {

        let tmp = TempDir::new("vp106_default").unwrap();
        let dir = factory_dir(&tmp);

        // FailurePolicy::default() == FailOpen (all current ~76 plugins)
        let should_write = should_write_marker(DispatchOutcome::Indeterminate, FailurePolicy::default());
        assert!(!should_write,
            "VP-106: absent failure_policy (default=FailOpen) INDETERMINATE MUST NOT write marker (ADR-047 §D7)");
    }

    #[test]
    fn test_BC_1_18_003_different_artifact_no_clear() {
        // EC-008: same plugin, DIFFERENT non-empty artifact, PASS → marker NOT cleared.
        // Artifact A quarantine persists — plugin validated artifact B but A was never re-validated.
        let tmp = TempDir::new("vp106_ec008").unwrap();

        let artifact_a = dir.join(".factory").join("STATE.md").to_str().unwrap().to_string();

        // Write marker for artifact A
        write_marker_for_artifact(&dir, &artifact_a);
        assert!(marker_path(&dir).exists(), "setup: marker must exist before re-validation");

        delete_marker_if_pass(DispatchOutcome::Pass, FailurePolicy::FailClosed, &dir, &artifact_b)

        assert!(marker_path(&dir).exists(),
            "VP-106 EC-008: same plugin + DIFFERENT non-empty artifact PASS MUST NOT clear marker; \

    }

    fn test_BC_1_18_003_empty_artifact_path_clear() {
        // EC-009: empty marker artifact_path → name-only match suffices → marker cleared.
        // Covers non-artifact-scoped validators (wave-gate, path-staging) with no artifact context.
        let tmp = TempDir::new("vp106_ec009").unwrap();
        let dir = factory_dir(&tmp);

        // Write marker with empty artifact_path (non-artifact-scoped validator)
        write_marker_for_artifact(&dir, "");
        assert!(marker_path(&dir).exists(), "setup: marker must exist before re-validation");

        // Simulate PASS on any artifact — empty-path fallback: plugin_name equality alone suffices
        let any_artifact = dir.join(".factory").join("STATE.md").to_str().unwrap().to_string();

            .expect("delete_marker_if_pass must not error");

        assert!(!marker_path(&dir).exists(),
            "VP-106 EC-009: empty marker artifact_path + same plugin PASS MUST delete marker \
             (empty-path fallback; BC-1.18.003 §PC1/§INV2; ADR-047 §D5)");
    }

    // `check_and_clear_expired_marker`. `evaluate_gate` no longer parses `expires_at` at all —
    // TTL determination, deletion, and (per VP-108) the `marker.cleared(TTL_EXPIRED)` emission
    // are all dispatcher-native, because the WASM `emit_event` ABI cannot carry a foreign
    // trace_id/plugin_name (ADR-048 §D4 v1.2 rationale).

    #[test]
    fn test_BC_1_18_003_ttl_expired_check_and_clear_returns_some_and_deletes() {

        // returns Some(fields) and deletes the marker. (Emission correctness is VP-108 PC2.)
        // ADR-048 §D2: UNVALIDATED_MUTATION_MARKER_TTL_SECONDS = 86400; expires_at stamped at write time.
        let tmp = TempDir::new("vp106_ttl_expired").unwrap();
        let dir = factory_dir(&tmp);
        let marker = marker_path(&dir);

        // Write a marker with expires_at in the past (1 second before epoch = 1970, well expired)
        let content = "timestamp = \"2026-08-30T00:00:00Z\"\n\
                       plugin_name = \"regression-gate\"\n\
                       artifact_path = \"/tmp/.factory/STATE.md\"\n\
                       cause = \"fuel\"\n\
                       trace_id = \"ffffffff-0006-0006-0006-000000000006\"\n\
                       expires_at = \"1970-01-01T00:00:01Z\"\n";
        fs::write(&marker, content).unwrap();
        assert!(marker.exists(), "setup: marker must exist before check_and_clear_expired_marker");

        let now = chrono::Utc::now();
        let cleared = check_and_clear_expired_marker(&dir, now)
            .expect("VP-106 PC-F: check_and_clear_expired_marker must not error");

        // expired → Some(fields)
        assert!(cleared.is_some(),
            "VP-106 PC-F: expired expires_at MUST yield Some(fields) — TTL deadman path; \
             BC-1.18.003 §PC4; ADR-048 §D2/§D4 v1.2");
        // auto-delete
        assert!(!marker.exists(),
            "VP-106 PC-F: check_and_clear_expired_marker MUST auto-delete the marker after TTL expiry \
             (BC-1.18.003 §PC4; ADR-048 §D2/§D4 v1.2)");
    }

    #[test]
    fn test_BC_1_18_003_ttl_non_expired_check_and_clear_returns_none_and_gate_blocks() {
        // INV5: non-expired expires_at → check_and_clear_expired_marker returns None (no clear);
        // evaluate_gate (which now performs NO expires_at parsing) then sees the still-present
        // marker and returns Block unconditionally — quarantine still active.
        let tmp = TempDir::new("vp106_ttl_active").unwrap();
        let dir = factory_dir(&tmp);
        let marker = marker_path(&dir);

        // Write a marker with expires_at far in the future (year 2099)
        let content = "timestamp = \"2026-08-31T00:00:00Z\"\n\
                       plugin_name = \"regression-gate\"\n\
                       artifact_path = \"/tmp/.factory/STATE.md\"\n\
                       cause = \"fuel\"\n\
                       trace_id = \"ffffffff-0007-0007-0007-000000000007\"\n\
                       expires_at = \"2099-01-01T00:00:00Z\"\n";
        fs::write(&marker, content).unwrap();

        let now = chrono::Utc::now();
        let cleared = check_and_clear_expired_marker(&dir, now)
            .expect("VP-106 INV5: check_and_clear_expired_marker must not error");

        assert!(cleared.is_none(),
            "VP-106 INV5: non-expired expires_at MUST yield None — not yet a clear event; \
             TTL not yet elapsed; BC-1.18.003 §INV5");
        assert!(marker.exists(),
            "VP-106 INV5: non-expired marker MUST NOT be auto-deleted");

        // Companion: evaluate_gate, given the still-present marker, unconditionally Blocks —
        // it performs no expires_at math of its own (ADR-048 §D4 v1.2).
        let decision = evaluate_gate(&marker);
        assert!(matches!(decision, GateDecision::Block { .. }),
            "VP-106 INV5: evaluate_gate MUST Block on a still-present marker regardless of \
             expires_at content — it has no TTL awareness under ADR-048 §D4 v1.2");
    }

    #[test]
    fn test_BC_1_18_003_legacy_absent_expires_at_not_cleared_gate_blocks_conservative() {
        // PC-G: legacy marker without expires_at field → check_and_clear_expired_marker treats
        // it as non-expired (returns None, does not delete); evaluate_gate then Blocks.
        // ADR-048 §D2 backward-compatibility: pre-ADR-048 markers lack expires_at; conservative
        // posture blocks rather than silently allowing. Operator must manually clear.
        let tmp = TempDir::new("vp106_legacy").unwrap();
        let dir = factory_dir(&tmp);
        let marker = marker_path(&dir);

        // Write a marker WITHOUT expires_at (legacy format pre-ADR-048)
        let content = "timestamp = \"2026-08-30T00:00:00Z\"\n\
                       plugin_name = \"regression-gate\"\n\
                       artifact_path = \"/tmp/.factory/STATE.md\"\n\
                       cause = \"fuel\"\n\
                       trace_id = \"ffffffff-0008-0008-0008-000000000008\"\n";
        // NOTE: no expires_at field
        fs::write(&marker, content).unwrap();

        let now = chrono::Utc::now();
        let cleared = check_and_clear_expired_marker(&dir, now)
            .expect("VP-106 PC-G: check_and_clear_expired_marker must not error");

        assert!(cleared.is_none(),
            "VP-106 PC-G/INV5: legacy marker (absent expires_at) MUST yield None — treated as \
             non-expired; conservative posture; BC-1.18.003 §INV5; ADR-048 §D2 backward-compatibility");
        assert!(marker.exists(),
            "VP-106 PC-G/INV5: legacy marker MUST NOT be auto-deleted");

        let decision = evaluate_gate(&marker);
        assert!(matches!(decision, GateDecision::Block { .. }),
            "VP-106 PC-G/INV5: legacy marker (absent expires_at) MUST yield Block via \
             evaluate_gate — operator must manually rm; BC-1.18.003 §INV5");
    }
