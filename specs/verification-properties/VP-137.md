# VP-137: B1 Backfill Migration Introduces No New Cohort-B Dependency and No Ordering Dependency on BC-1.18.008 or BC-1.18.011

## Property Statement

The B1 cold-start `changelog:` backfill migration (BC-1.18.012) is an INDEPENDENT one-time operation
that introduces no undocumented sequencing dependency — the direct analogue of VP-134's B2
no-new-Cohort-B guarantee, complementing VP-129/VP-130's Cohort-B-flip audits.

1. **No new Cohort-B dependency.** The migration operates entirely on `BC-INDEX.md`'s frontmatter
   `changelog:` sequence — a DIFFERENT size driver than mechanism A's four append-logs (BC-1.18.008)
   or mechanism B2's per-BC body tables (BC-1.18.011). `regression-gate` and `convergence-tracker`
   do not read `BC-INDEX.md` at all (per the F2 architecture-delta migration-impact map), so
   `BC-7.08.001`'s Cohort B fail-closed flip gating is UNCHANGED by this BC (BC-1.18.012
   §Postcondition 6). A static audit confirms `hooks-registry.toml`'s Cohort B `failure_policy`
   sequencing never references this migration's completion as a precondition, and the migration
   handler touches no Cohort-B `failure_policy` state.

2. **No ordering dependency on BC-1.18.008 or BC-1.18.011.** No implementation may introduce a
   sequencing dependency between this migration and mechanism A's backfill-split (BC-1.18.008) or
   mechanism B2's migration (BC-1.18.011); all three are independent one-time operations scheduled
   at the SAME F4 activation boundary (BC-1.18.012 §Postcondition 6, §Invariant 4). A static audit
   confirms neither BC-1.18.008's nor BC-1.18.011's execution gating cites BC-1.18.012, and this
   migration's own entry point cites neither as a precondition.

3. **Making it a precondition is a detectable defect.** An implementer wiring this migration as a
   precondition for the flip or for the sibling migrations is a scope violation of §Postcondition
   6 / §Invariant 4 (BC-1.18.012 §EC-005) — the static check MUST flag it, not accept it.

This property is structural and has NO F4-provisional numeric dependency.

### Why static-check

"No new dependency" and "no ordering dependency" are structural, source/config-level invariants best
enforced by the cheapest mechanism — a CI grep asserting the absence of the forbidden references —
the same enforcement class as VP-129 (Cohort B config audit), VP-134 (B2 no-new-dependency), and
VP-061 (agent-prompt discipline presence). A behavioral test cannot prove the ABSENCE of a
dependency; the static scan is the right tool.
