# VP-133: B2 BC-INDEX Body Split — Independent-Census Integrity, Crash-Atomicity, Fail-Loud Rollback (E-SHD-005), Idempotency, and SS-05/SS-06 Second-Level Sub-Split Census

## Property Statement

The governed one-time B2 migration is census-honest, safe to interrupt, safe to re-run, and fails
loud without leaving a partial state — BC-1.18.008 §Postcondition 5/6 + §Invariant 3's exact analogue
(VP-124), specialized to `BC-INDEX.md`'s ID-keyed census partition. This VP consolidates the four
same-method (integration) load-bearing safety obligations of BC-1.18.011, per the verification-delta
single-method-per-VP convention (the same consolidation VP-124 applies for BC-1.18.008).

1. **Independent-census integrity — every BC-ID in EXACTLY one shard.** After the split, every
   `BC-X.YY.NNN` ID present in the pre-split census (a fresh enumeration of the original body's
   rows, cross-checked against `BC-INDEX.md`'s `total_bcs` frontmatter as an independent
   count-oracle) appears in EXACTLY ONE resulting shard/sub-shard file — never zero, never two; the
   union of all shard files' row counts equals the pre-split census count exactly; and
   `BC-INDEX.md`'s post-split body contains ZERO per-BC rows (BC-1.18.011 §Postcondition 2, §EC-001
   duplicated-row negative control). The census is independently mandatory alongside VP-132's
   content-preservation: a byte-identical concatenation that nonetheless duplicates one row and drops
   another (a compensating error) STILL fails this census (BC-1.18.011 §Invariant 2).

2. **Crash-atomicity — staging + verify + atomic replace, all-or-nothing.** All shard files and the
   shard-manifest TOML are written to a staging location first; `BC-INDEX.md`'s body is atomically
   replaced (temp-file-then-rename, reusing BC-1.18.006's primitives) ONLY after both
   content-preservation (VP-132) and the census verify clean. A simulated crash at any staging step
   leaves `BC-INDEX.md`'s body in exactly one of two valid states — fully original or fully split —
   never a partial/corrupt intermediate (BC-1.18.011 §Postcondition 3, §Invariant 3, §EC-002).

3. **Fail-loud rollback (E-SHD-005).** If EITHER content-preservation OR the census fails, the
   migration ABORTS: `BC-INDEX.md`'s original monolithic body is left completely untouched, no
   partial shard set is treated as authoritative, no partial `§Subsystem Shard Manifest` is
   published, and a loud `HookResult::Error` / migration-abort surfaces (taxonomy `E-SHD-005`,
   naming the mismatch — e.g., the duplicated BC-ID) (BC-1.18.011 §Postcondition 4, §EC-001,
   §EC-003-error, §EC-004). This is VP-124's fail-loud preservation-gate (E-SHD-003) analogue for
   B2's census gate.

4. **Idempotency.** Running the migration twice against an already-split `BC-INDEX.md`, or resuming
   from a verified-complete staged state, does not re-split, re-duplicate, or corrupt any shard: the
   operation either resumes from the last verified-complete checkpoint or detects the already-split
   end-state (zero per-BC rows in the body) and exits as a no-op (BC-1.18.011 §Postcondition 5,
   §EC-003 resume-from-checkpoint, §EC-006 completed-run no-op).

5. **SS-05/SS-06 second-level sub-split census.** The census/atomicity/rollback/idempotency
   obligations hold IDENTICALLY at the sub-shard level for SS-05 and SS-06: every `BC-5.*` row lands
   in exactly one of `shards/BC-INDEX-SS-05.a.md`/`.b.md`/… with the SS-05-scoped total matching an
   independent pre-split count of `BC-5.*` rows (likewise SS-06), all within the SAME one-time
   operation; a sub-shard-level census failure aborts the ENTIRE operation, not just the affected
   subsystem (BC-1.18.011 §Postcondition 6, §EC-004).

## Proof Method

| Leg | Method | Tool | Coverage | Status |
|-----|--------|------|----------|--------|
| Independent-census integrity | integration | full-corpus census comparison against synthetic `BC-INDEX` fixtures with known BC-ID sets (including a duplicated-row negative-control fixture); cross-check against `total_bcs` | every census ID in exactly one shard; union == census count; body has zero per-BC rows | feasible-pending-harness (F4 code) |
| Crash-atomicity | integration | fault-injection harness (real B2 split against a tempdir fixture, simulated crash at each of N staging steps) | post-recovery body ∈ {fully original, fully split} | feasible-pending-harness (F4 code) |
| Fail-loud rollback | integration | harness with an injected census mismatch (duplicated row) and an injected preservation mismatch | abort with `Error` (E-SHD-005) naming the mismatch; original body untouched | feasible-pending-harness (F4 code) |
| Idempotency | integration | double-invocation against an already-split fixture + resume-from-verified-staged-checkpoint fixture | second run / resume adds zero shards, no double-split | feasible-pending-harness (F4 code) |
| SS-05/SS-06 sub-split census | integration | sub-shard-scoped census comparison for SS-05 (`BC-5.*`) and SS-06 (`BC-6.*`) fixtures | sub-shard row counts sum to the independent per-subsystem count; a sub-shard census failure aborts the whole operation | feasible-pending-harness (F4 code) |

### Why integration (fault-injection + full-corpus census)

Census integrity is a full-corpus cross-reference property (every BC-ID across all shard files vs a
fresh enumeration vs `total_bcs`); crash-atomicity is a property of real filesystem interaction under
interruption; idempotency requires double-invocation against a live staged state. All are real-
substrate/process properties requiring a harness that runs the actual migration against a live
tempdir and injects failures/re-runs — the same harness class VP-124 uses for the mechanism-A
backfill and VP-128 uses for multi-file corpus integrity — not a pure unit test. The byte-for-byte
content-preservation half is a DISTINCT-method (proptest) property proven separately by VP-132, per
BC-1.18.011 §Invariant 2's independent-mandatory requirement.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/b2_bcindex_migration_integration_test.rs
// VP-133: BC-1.18.011 PC2/PC3/PC4/PC5/PC6/INV2/INV3/EC-001..EC-006

#[test]
fn test_BC_1_18_011_PC2_every_bc_id_in_exactly_one_shard() {
    let cx = B2MigrationHarness::with_fixture_known_ids(/* 2005 synthetic BC-IDs across 10 SS */);
    let out = cx.run();
    assert!(out.every_census_id_in_exactly_one_shard());     // never zero, never two
    assert_eq!(out.union_shard_row_count(), cx.census_count());
    assert_eq!(out.total_bcs_oracle(), cx.census_count());   // independent count-oracle agreement
    assert_eq!(out.body_per_bc_row_count(), 0);              // BC-1.18.010 Inv3
}

#[test]
fn test_BC_1_18_011_EC001_duplicated_row_aborts_fail_loud() {
    let cx = B2MigrationHarness::with_injected_duplicated_row("BC-3.14.002");
    let r = cx.run();
    assert!(matches!(r, HookResult::Error { .. }));          // E-SHD-005
    assert!(cx.original_body_untouched());
    if let HookResult::Error { message } = r { assert!(message.contains("BC-3.14.002")); }
}

#[test]
fn test_BC_1_18_011_PC3_crash_at_each_staging_step_leaves_valid_state() {
    for step in 0..cx_expected_staging_steps() {
        let cx = B2MigrationHarness::with_fixture();
        cx.inject_crash_after_step(step);
        let recovered = cx.run_then_restart();
        assert!(recovered.body_fully_original() || recovered.body_fully_split()); // never partial
    }
}

#[test]
fn test_BC_1_18_011_PC5_idempotent_second_run_and_resume() {
    let cx = B2MigrationHarness::already_split();
    let before = cx.shard_count();
    cx.run();
    assert_eq!(cx.shard_count(), before);                    // no re-split (EC-006 no-op)
}

#[test]
fn test_BC_1_18_011_PC6_ss05_ss06_subshard_census() {
    let cx = B2MigrationHarness::with_oversized_ss05_ss06();
    let out = cx.run();
    assert_eq!(out.subshard_row_sum("SS-05"), cx.independent_count("BC-5.*"));
    assert_eq!(out.subshard_row_sum("SS-06"), cx.independent_count("BC-6.*"));
    // sub-shard census failure aborts the ENTIRE operation:
    let cx2 = B2MigrationHarness::with_injected_ss05_subshard_miscount();
    assert!(matches!(cx2.run(), HookResult::Error { .. }));  // whole-operation abort, E-SHD-005
    assert!(cx2.original_body_untouched());
}
```
