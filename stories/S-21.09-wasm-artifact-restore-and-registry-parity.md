# S-21.09: validate-factory-path-staging.wasm artifact restore + per-name registry parity check

## Narrative

- **As a** factory pipeline operator running any Bash tool call
- **I want** the `validate-factory-path-staging` WASM guard to actually execute (its `.wasm`
  artifact is committed and tracked in git) AND a per-name registry parity CI check that
  detects any future declared-but-missing artifact before it reaches production
- **So that** INV-E21-001 Layer-1 enforcement (BC-4.16.001) is not silently inert, and the
  structural class of failure — declared name absent from git — is permanently closed

## Context / Finding Summary

S-21.01 (merged PR #759, `7bb0e797`, 2026-07-23) created the crate source at
`crates/hook-plugins/validate-factory-path-staging/` and registered the plugin in
`hooks-registry.toml` with `event = "PreToolUse"`, `tool = "^Bash$"`, `priority = 140`,
`on_error = "continue"`. The WASM artifact was never built and committed.

**Root cause: release lag, not a parity-check gap.** `v1.0.0-rc.23` was tagged
2026-07-18 — five days BEFORE S-21.01 merged on 2026-07-23. The operator runtime at
rc.23 carries a `hooks-registry.toml` with ZERO occurrences of
`validate-factory-path-staging`, so the guard has been inert for 100% of its existence at
the operator level. The develop branch is 44 commits unreleased
(`v1.0.0-rc.23-44-g62fbcf1a`).

**The missing WASM on develop is a hygiene/self-hosting defect.** The release pipeline
(`release.yml`'s `commit-binaries` job) builds every declared WASM and stages it with
`git add -f`, then verifies parity against both registries before committing. `origin/main`
has 34-tracked/34-declared parity. The develop-branch gap means develop's own tree cannot
run its own guard — state-manager and other agents invoking `git add` on develop are
unprotected. This defect self-heals at rc.24 release time but is a live self-hosting gap
on develop.

**Evidence of non-invocation in session logs.** Dispatcher log grep of
`plugin_name == "validate-factory-path-staging"` across all
`.factory/logs/dispatcher-internal-*.jsonl` files (2026-07-23 to 2026-08-10) returns
**0 records** for all event types. Same-matcher `PreToolUse`/`^Bash$` siblings each show
**14,151** `plugin.invoked` + 14,151 `plugin.completed` events: `verify-git-push`,
`verify-factory-lock-bash`, `validate-heavy-op-delegation`.

**Why CI does not catch this.** `.github/workflows/ci.yml` has a step "Stage WASM plugins
for run-all.sh" that runs a full `--workspace` WASM build and copies every artifact into
the gitignored `plugins/vsdd-factory/hook-plugins/` directory, immediately BEFORE "Run
full bats suite (run-all.sh)". That step does NOT set `CI_REQUIRE_ARTIFACTS`, and
`_require_artifacts` skip-passes on absence of `CI_REQUIRE_ARTIFACTS`. CI validates the
SOURCE (the Rust crate compiles and its unit tests pass) but never the DELIVERY (the
artifact must be tracked in git for the guard to load in production sessions).

## Acceptance Criteria

### AC-001: Artifact is tracked in git (traces to BC-4.16.001 Precondition 3)

The file `plugins/vsdd-factory/hook-plugins/validate-factory-path-staging.wasm` MUST
be present in the git index — i.e., `git ls-files plugins/vsdd-factory/hook-plugins/validate-factory-path-staging.wasm`
returns a non-empty result. File existence on disk alone is insufficient; the artifact must
be committed.

**Note:** `plugins/vsdd-factory/hook-plugins/` is excluded by `.gitignore` (gitignored
directory for WASM binaries not shipped via source control in normal commits). The
established precedent for committing WASM binaries to this path is `git add -f`, which
overrides the gitignore. This same pattern was used to track all 35 existing `.wasm` files
in that directory.

- **Test:** `test_validate_factory_path_staging_wasm_is_git_tracked()` — calls
  `git ls-files` and asserts the file is present

### AC-002: Guard executes (not skips) in bats harness after artifact is committed (traces to BC-4.16.001 Precondition 3)

After the artifact is committed (AC-001), the bats harness `validate-factory-path-staging.bats`
MUST run without any `_require_artifacts` skip on the 27 artifact-dependent tests when
the WASM is sourced from the git-tracked path (without a preceding cargo build step). The
`_require_artifacts` helper skips only when the WASM is absent from
`plugins/vsdd-factory/hook-plugins/validate-factory-path-staging.wasm`. With the artifact
committed, all 27 tests MUST produce concrete block/pass decisions — no
"validate-factory-path-staging.wasm not present" skip lines in bats output.

**Note on live-session invocation:** A live dispatcher session log confirming
`plugin.completed` events requires a fresh Claude Code session, which is outside the

invocation — when the WASM is present, the dispatcher loads and invokes it; the
block/pass decisions produced by AC-003/AC-004/AC-005 ARE the invocation evidence
within the test context.

- **Test:** run `validate-factory-path-staging.bats` with WASM sourced from committed
  artifact (no cargo build step); assert zero `skip` lines matching
  "validate-factory-path-staging.wasm not present" in test output

step produces the WASM). After AC-001 (WASM committed), T-001 MUST run without the
`_require_artifacts` skip in all environments, including production sessions.

**What is genuinely missing:** delivery/reachability coverage for the operator runtime —
the rc.23 bundle lacks the registry entry and WASM entirely. That gap resolves at rc.24
release; it is outside narrow scope.

- **Test:** T-001 in `validate-factory-path-staging.bats` — bats mock with
  `branch = develop`, payload = `git add .factory/STATE.md`; assert exit 2 and
  `FactoryPathOnProductBranch` in output. Must not skip after AC-001 fix.

### AC-006: Exhaustive per-name declared-vs-tracked set-difference (declared→tracked direction) (traces to BC-4.16.001 Precondition 3)

A new Cargo integration test in `crates/factory-dispatcher/tests/bundle_orphan_check.rs`
MUST extend the existing dual-registry orphan machinery (established by S-19.04/S-19.06)
with the INVERSE direction: **declared→tracked**.

The existing T-009 asserts `tracked_set ⊆ declared_set` (zero tracked WASMs absent from
both registries). AC-006's new test (T-012) asserts `declared_set ⊆ tracked_set` (every
declared WASM must be tracked in git — no declared-but-missing artifacts).

**Implementation:** extend `bundle_orphan_check.rs` with a new test function
`test_S_21_09_ac006_T012_declared_set_subset_of_tracked_set()` that:

1. Parses both `hooks-registry.toml` and `resolvers-registry.toml` using the existing
   `parse_plugin_refs()` function — covers dual-registry aggregation, handles
   `vsdd-context-resolvers.wasm` correctly without special-casing
2. Calls `git_tracked_wasm_names()` to get the tracked set
3. Computes `declared_set − tracked_set` (names declared in a registry but absent from git)
4. Asserts the difference is empty — no declared-but-missing artifacts
5. **Red Gate:** MUST FAIL before AC-001 fix because `validate-factory-path-staging.wasm`
   is declared in `hooks-registry.toml` but not tracked in git
6. **Green Gate:** MUST PASS after AC-001 fix

Do NOT create a new crate `crates/plugin-parity-check/` — that would duplicate ~200 lines
of machinery already in `bundle_orphan_check.rs`. Extend the existing file.

**Note on `vsdd-context-resolvers.wasm`:** declared in `resolvers-registry.toml`; also
tracked in git. Because `parse_plugin_refs()` is called on both registries and the
declared set is their UNION, `vsdd-context-resolvers.wasm` is in the declared set and
tracked — no false-positive.

- **Test:** `test_S_21_09_ac006_T012_declared_set_subset_of_tracked_set()` in
  `crates/factory-dispatcher/tests/bundle_orphan_check.rs` — extends existing file; MUST
  FAIL before AC-001 fix (missing artifact in tracked set); MUST PASS after
