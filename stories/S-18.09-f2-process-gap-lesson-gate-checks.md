### AC-003 (gate assertion — L-F2-no-bypass-on-edit-failure: no `|| true` on load-bearing writes in E-18 hook scripts)

A grep scan of E-18 hook bash scripts MUST confirm that no load-bearing write operation uses `|| true` to suppress errors. "Load-bearing write" = any command that writes to `factory-artifacts`, commits to git, or appends to a JSONL log file.

The E-18 hook scripts in scope:
- `plugins/vsdd-factory/hooks/postcompact-reanchor.sh` (S-18.05 deliverable)

**Machine-checkable assertion:**
```bash

BYPASS_HITS=$(grep -En "(git commit|git push|git add|>> .+\.jsonl|tee .+\.jsonl).*\|\| true" \

[ "$BYPASS_HITS" -eq 0 ] || echo "FAIL: load-bearing write with || true bypass found in E-18 hook scripts"
```

### AC-005 (gate assertion — cross-reference title-cite parity: story frontmatter BC IDs match actual BC H1 titles)

For each story in the E-18 set (S-18.00 through S-18.09) that has a non-empty `behavioral_contracts:` frontmatter array, verify that each BC ID in the array corresponds to a BC file whose H1 heading is cited correctly in the story's `## Behavioral Contracts` table row.

The gate cannot verify the exact prose match programmatically, but it CAN verify:
1. Each BC ID in `behavioral_contracts:` matches the pattern `BC-\d+\.\d{2}\.\d{3}`.
2. A BC file for that ID exists in the spec tree.
3. The BC file's H1 heading (line starting with `# BC-`) is present in the file.

**Machine-checkable assertion:**
```bash

  BC_IDS=$(grep -A 20 "^behavioral_contracts:" "$STORY_FILE" \
    | grep -oE "BC-[0-9]+\.[0-9]+\.[0-9]+" || true)

```

### AC-007 (gate assertion — BC-precondition registry-block-shape validator: every `§Preconditions` TOML hook block has both `name` and `plugin` fields per D-576)

For every BC in the E-18 SS-04 set (BC-4.14.001, BC-4.15.001) whose `§Preconditions` section contains a `[[hooks]]` TOML block, the gate MUST verify that the TOML block contains BOTH:
- `name = "..."` field
- `plugin = "hook-plugins/....wasm"` field

A TOML block with `plugin =` but without `name =` (or vice versa) is the canonical native-WASM shape violation per D-576 (originally found in BC-4.14.001 v1.8 → fixed in v1.9 F-P14-002). This gate ensures regressions cannot silently reintroduce the violation.

**Machine-checkable assertion:**
```bash
for BC_FILE in \
  .factory/specs/behavioral-contracts/ss-04/BC-4.14.001.md \
  .factory/specs/behavioral-contracts/ss-04/BC-4.15.001.md; do
  # Find the [[hooks]] block in the §Preconditions section
  # Flag form avoids macOS BSD awk range-collapse when START also matches END /^## /
  TOML_BLOCK=$(awk '/^## Preconditions/{f=1; next} /^## /{f=0} f' "$BC_FILE" \
    | grep -A 10 '\[\[hooks\]\]')

  echo "$TOML_BLOCK" | grep -q 'name = "' \

```

### AC-008 (gate assertion — O-P4-004 process gap: mandatory pre-`status:ready` AC↔PC parity gate — every AC trace in an E-18 story resolves to a real BC clause heading)

**Context:** The AC↔PC mis-numbering defect recurred across S-18.02 (pass-3 fix), S-18.04a (earlier fix), S-18.04b (pass-4 finding). This is a POLICY 5 v1.3.3 sibling-sweep failure. The root cause is the absence of a machine-checkable gate that verifies every `(traces to BC-X.XX.XXX PC-N / INV-N)` parenthetical in an E-18 story body resolves to an actual numbered clause in the cited BC file. This gate closes the process gap permanently.

For every E-18 story that has a non-empty `behavioral_contracts:` frontmatter array, the gate MUST:
1. Extract every `(traces to BC-X.XX.XXX PC-N ...)` and `(traces to BC-X.XX.XXX INV-N ...)` parenthetical from the story's body.
2. For each cite, locate the BC file, grep the `## Postconditions` or `## Invariants` section, and verify that the cited clause number `PC-N` / `INV-N` has a corresponding numbered item in that section.
3. Fail (exit non-zero) if any AC cites a PC or INV number that does not exist in the BC's numbered clause list.

**Definition of "resolves":** A clause cite resolves when the corresponding clause heading is present in the BC file's relevant section. Three label forms are supported:

1. **Numeric:** `postcondition 1`, `postcondition 2a`, `invariant 3`. Resolves if `## Postconditions` (or `## Invariants`) section contains a line beginning `^N\. ` or `^Na\. ` (1-based integer, optional lowercase letter suffix).

2. **PC-letter (BC-4.15.001 scheme):** `postcondition PC-A`, `postcondition PC-B-B1`, `postcondition PC-D`. Resolves if `## Postconditions` section contains a line matching `(^\*\*PC-A\*\*|^### PC-A|^PC-A[ :])` — i.e., the BC uses bold (`**PC-A**`) or heading (`### PC-A`) or bare (`PC-A:`) label form. Do NOT renumber these to integers; the BC uses letter labels.

3. **PC-numeric (stripped):** `postcondition PC1`, `postcondition PC2`. The gate strips the `PC` prefix and resolves as numeric form 1. This covers BCs where the story mistakenly wrote `PC1` instead of `1` but the BC actually uses numeric clause numbering.

A cite for `postcondition PC-A` when the BC has no `PC-A` heading MUST fail. A cite for `postcondition 4` when the BC has only 3 postconditions MUST fail. A cite for "postcondition 2a" resolves if `## Postconditions` contains a line beginning `^2a\. `.

**Gate scope (F-P8-004):** This gate covers `(precondition|postcondition|invariant)` cite forms only. AC traces of the form `(traces to BC-X edge case EC-NNN)` and `(traces to VP-090 section N)` are NOT in scope for this gate — they are not gated by this check. Future gate axis for EC cites is desirable but out of scope for E-18.

**Machine-checkable assertion (extended for all notation forms — F-P7-001; awk flag form — F-P8-001; printf path — F-P8-005):**
```bash
# For each E-18 story with behavioral_contracts, extract BC-X.XX.XXX clause cites
# Gate scope: (precondition|postcondition|invariant) cites only.
#             EC/VP-section cite forms are out of gate scope (F-P8-004).
# Supports clause label forms:
#   - Numeric:           "postcondition 1", "postcondition 2a", "invariant 3"
#   - PC-prefix numeric: "postcondition PC1", "postcondition PC2"  (strip "PC")
#   - PC-letter:         "postcondition PC-A", "postcondition PC-B-B1" (BC-4.15.001 scheme)
#   - INV-prefix:        "invariant INV-1", "invariant INV2"          (if encountered)
# All forms: case-insensitive keyword match; label extracted after normalization
for STORY_FILE in .factory/stories/S-18.*.md; do
  # --- Non-vacuity check (POLICY 11 / TD-VSDD-059 anti-silent-inert) ---
  # For stories with non-empty behavioral_contracts, TRACES_CHECKED must be > 0
  HAS_BC=$(grep -oE "^behavioral_contracts:" "$STORY_FILE" \
    | head -1 || true)
  if [ -n "$HAS_BC" ]; then
    BC_ARRAY=$(awk '/^behavioral_contracts:/,/^[a-z_]+:/' "$STORY_FILE" \
      | grep -oE '"BC-[0-9]+\.[0-9]+\.[0-9]+"' | tr -d '"')
    if [ -n "$BC_ARRAY" ]; then
      # Story has real BC IDs — count the traces below; fail if zero
      # Note: printf form avoids the double-zero bug: when RAW_TRACES is empty,
      # "echo | grep -c ." exits 1 and "|| echo 0" appends a second 0.
      # With printf '%s', an empty RAW_TRACES yields 0 lines and grep -c exits 1;
      # the outer if/then catches the integer comparison without the || echo 0 ambiguity.
      RAW_TRACES=$(grep -oiE \
        "traces to BC-[0-9]+\.[0-9]+\.[0-9]+ (precondition|postcondition|invariant) [^ ))]+" \
        "$STORY_FILE" 2>/dev/null || true)
      TRACES_CHECKED=$(printf '%s' "$RAW_TRACES" | grep -c .)
      [ "$TRACES_CHECKED" -gt 0 ] \
        || { echo "FAIL: $STORY_FILE has non-empty behavioral_contracts but TRACES_CHECKED=0 — gate is vacuously passing (notation not recognized)"; exit 1; }
    fi
  fi

  # --- Per-trace clause resolution ---
  # Canonical extraction: capture all (precondition|postcondition|invariant) LABEL forms
  TRACES=$(grep -oiE \
    "traces to BC-[0-9]+\.[0-9]+\.[0-9]+ (precondition|postcondition|invariant) [^ ))]+" \
    "$STORY_FILE" 2>/dev/null || true)
  while IFS= read -r TRACE; do
    [ -z "$TRACE" ] && continue
    BC_ID=$(echo "$TRACE" | grep -oE "BC-[0-9]+\.[0-9]+\.[0-9]+")
    CLAUSE_TYPE=$(echo "$TRACE" | grep -oiE "(precondition|postcondition|invariant)" \
      | tr '[:upper:]' '[:lower:]')
    # Raw label: everything after the clause type keyword (e.g. "PC-A", "PC-B-B1", "2a", "PC1", "1")
    RAW_LABEL=$(echo "$TRACE" | grep -oiE \
      "(precondition|postcondition|invariant) [^ ))]+" \
      | grep -oE " [^ ))]+$" | tr -d ' ')

    # Normalize label:
    #   "PC-A" / "PC-B-B1" / "PC-D"  → keep as-is (letter-labeled; BC-4.15.001 scheme)
    #   "PC1" / "PC2"                → strip "PC" → "1" / "2" (numeric with PC prefix)
    #   "INV1" / "INV-1"             → strip "INV-?" → "1" (INV prefix)
    #   "2a" / "3" / "1"             → keep as-is (standard numeric)
    if echo "$RAW_LABEL" | grep -qiE "^PC-[A-Z]"; then
      # BC-4.15.001-style letter label: PC-A, PC-B, PC-B-B1, PC-C, PC-D
      # Lookup pattern: bold `**PC-A**` or `### PC-A` or `^PC-A` heading in Postconditions section
      NORM_LABEL="$RAW_LABEL"
      LABEL_FORM="letter"
    elif echo "$RAW_LABEL" | grep -qiE "^PC[0-9]"; then
      NORM_LABEL=$(echo "$RAW_LABEL" | sed 's/^[Pp][Cc]//')
      LABEL_FORM="numeric"
    elif echo "$RAW_LABEL" | grep -qiE "^INV-?[0-9]"; then
      NORM_LABEL=$(echo "$RAW_LABEL" | sed 's/^[Ii][Nn][Vv]-?//')
      LABEL_FORM="numeric"
    else
      NORM_LABEL="$RAW_LABEL"
      LABEL_FORM="numeric"
    fi

    # Build BC file path using printf for correct SS-10+ directory names (F-P8-005)
    BC_SS=$(echo "$BC_ID" | grep -oE "^BC-([0-9]+)" | grep -oE "[0-9]+")
    BC_SS_DIR=$(printf "ss-%02d" "$BC_SS")
    BC_FILE=".factory/specs/behavioral-contracts/${BC_SS_DIR}/${BC_ID}.md"
    [ -f "$BC_FILE" ] \
      || { echo "FAIL: $STORY_FILE cites $BC_ID but file not found at $BC_FILE"; continue; }

    # Determine section heading to search
    SECTION_HEAD="## Postconditions"
    [ "$CLAUSE_TYPE" = "invariant" ] && SECTION_HEAD="## Invariants"
    [ "$CLAUSE_TYPE" = "precondition" ] && SECTION_HEAD="## Preconditions"

    # Clause existence check
    # Flag form: avoids macOS BSD awk range-collapse where the START heading (e.g.
    # "## Postconditions") also matches END pattern /^## /, causing only the heading
    # line to be emitted and never the body. Flag form skips the heading line itself
    # and captures body until the next ## heading. (F-P8-001)
    if [ "$LABEL_FORM" = "letter" ]; then
      # Letter-labeled: match "**PC-A**", "### PC-A", "^PC-A " or "^PC-A:" in section body
      FOUND=$(awk "/^${SECTION_HEAD}/{f=1; next} /^## /{f=0} f" "$BC_FILE" \
        | grep -cE "(^|\*\*)${NORM_LABEL}(\*\*|[: ])")
    else
      # Numeric-labeled: match "^N. " or "^Na. " at start of line in section body
      FOUND=$(awk "/^${SECTION_HEAD}/{f=1; next} /^## /{f=0} f" "$BC_FILE" \
        | grep -cE "^${NORM_LABEL}\. ")
    fi
    # grep -cE returns 0 with exit 0 when matches found; 0 with exit 1 when no match.
    # FOUND will be "0" (the count) in both cases; only the exit code differs.
    # The POSIX $() captures stdout regardless of exit code, so FOUND is always a digit.
    [ "$FOUND" -gt 0 ] \
      || echo "FAIL: $STORY_FILE cites $BC_ID ${CLAUSE_TYPE} ${RAW_LABEL} (normalized: ${NORM_LABEL}) but clause not found in BC ${SECTION_HEAD} section"
  done <<< "$TRACES"
done
```

## Architecture Compliance Rules

1. **Gate scan scope is specified exactly (no over-scanning):** Each AC's grep scan targets specific files, not the entire repository. Over-scanning produces false positives from unrelated content (e.g., historical lesson prose that describes the violation class while not committing the violation itself).
2. **Exclusion filters are required where specified:** AC-003 and AC-006 require exclusion filters. Omitting them causes false positives. The exclusion patterns are load-bearing parts of the gate specification.
3. **Empty discovery is a gate failure (L-F2-exhaustive-sweep-enumerate-and-count):** AC-004 validates that the S-18.08 discovery scan fails explicitly when the discovered BC set is empty. A vacuously-passing loop over an empty set is a specification violation.
4. **No write side effects:** The gate scans are read-only. If a gate assertion fails, the correct action is to route the finding to the owning specialist (product-owner for BC issues, test-writer for bats issues) — NOT to auto-fix in place.
5. **Forbidden dependencies:** The gate bats file MUST NOT import or depend on any E-18 WASM crate. These are the artifacts being scanned.
