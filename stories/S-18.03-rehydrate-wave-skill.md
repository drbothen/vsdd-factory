**Epic:** E-18 — Factory Context Durability (feature #173)
**Wave:** 4 (depends on S-18.04a wave-state.yaml production + S-18.04b wave-boundary checkpoint)
**Depends on:** S-18.04a, S-18.04b
**Blocks:** S-18.06, S-18.07, S-18.08
**Priority:** P1 (closes BC-6.24.001 consumption side of wave-boundary rehydration)
**BC gate:** BC-6.24.001 v1.10 (draft; all postconditions in scope)
**Subsystem anchor:** SS-06 owns this story's scope because SS-06 is the Skill Catalog and `rehydrate-wave` is a new skill under `plugins/vsdd-factory/skills/` per ARCH-INDEX Subsystem Registry.

## Narrative

- **As a** factory agent or human operator starting a new session after a wave-boundary reset
- **I want** to invoke `/rehydrate-wave` as the first skill in the new session, which reads `wave-state.yaml` from the `factory-artifacts` branch via `git show`, injects exactly the listed spec files into the session context, and pauses for operator confirmation
- **So that** every new session after a wave-boundary reset begins with precisely the right spec scope — no stale prior-wave specs, no RAG hallucination, no working-tree override — closing the CAP-032 consumption side of the wave-boundary continuity guarantee produced by `wave-handoff`

## Acceptance Criteria

### AC-001 (traces to BC-6.24.001 postcondition 1 — git-sourced read; no working-tree fallback)

The `rehydrate-wave` skill (`plugins/vsdd-factory/skills/rehydrate-wave/SKILL.md`) MUST fetch `wave-state.yaml` exclusively via:

```
git show factory-artifacts:wave-state.yaml
```

The skill MUST NOT read from the working-tree path `.factory/wave-state.yaml`, from in-context LLM memory, or from any locally cached copy. If the working-tree path differs from the branch version, the branch version is authoritative and the working-tree path is silently ignored.

**Test (bats):** `test_rehydrate_wave_reads_git_not_working_tree()`
— Setup: `factory-artifacts:wave-state.yaml` has `stories: [{id: S-18.02, spec_files: [real.md]}]`; working-tree `.factory/wave-state.yaml` has `stories: [{id: S-18.STALE}]`.
— Assert: injected context names `real.md`; does NOT name `S-18.STALE`.

### AC-002 (traces to BC-6.24.001 postcondition 2 — exactly listed specs injected; VP-088 §2 INJECTED_FILE_COUNT sentinel)

The set of injected files MUST be EXACTLY:

```
Set(stories[*].spec_files) UNION Set(arch_files) UNION {state_pointer}
```

No additions (stale BC files, prior-wave ADR files) and no omissions. The skill MUST emit the `INJECTED_FILE_COUNT=<n>` machine-stable sentinel line on stdout (before or after the human-readable list) where `<n>` is the total count. Test harnesses MUST use this sentinel for count assertions — NOT `grep -c "^  - "` (presentation-coupled; false-green on list reformatting).

**Test (bats):** `test_rehydrate_wave_injects_exactly_union_of_listed_specs()`
— Setup: `wave-state.yaml` with `stories: [{id: S-18.02, spec_files: [A.md, B.md]}]`, `arch_files: [C.md, D.md, E.md]`, `state_pointer: ".factory/STATE.md"`.
— Assert: `INJECTED_FILE_COUNT=6` sentinel present in stdout; each of A.md/B.md/C.md/D.md/E.md/.factory/STATE.md named in output; no additional files; operator confirmation prompt shown.

### AC-003 (traces to BC-6.24.001 postcondition 3 — no stale prior-wave specs)

The skill MUST NOT load any spec file from prior waves that is not explicitly listed in `wave-state.yaml`. Prior-wave BC files, ADR files, or story files outside the manifest are never injected.

**Test (bats):** `test_rehydrate_wave_does_not_inject_prior_wave_specs()`
— Setup: `wave-state.yaml` references only `[S-18.02-foo.md]`; project directory also contains `S-17.04-bar.md` (prior-wave story).
— Assert: `S-17.04-bar.md` NOT present in injected set; `INJECTED_FILE_COUNT` equals manifest count only.

### AC-004 (traces to BC-6.24.001 postcondition 4 — STATE.md pointer always injected first)

The skill MUST always inject `.factory/STATE.md` (the `state_pointer` field value) as a context item, regardless of whether it is also listed in `spec_files`. It MUST appear in the injected set even when `state_pointer` is not explicitly enumerated in `stories[*].spec_files`.

**Test (bats):** `test_rehydrate_wave_always_injects_state_pointer()`
— Setup: `wave-state.yaml` with `state_pointer: ".factory/STATE.md"` but `.factory/STATE.md` not in `spec_files`.
— Assert: `.factory/STATE.md` appears in injected context output; `INJECTED_FILE_COUNT` includes it.

### AC-005 (traces to BC-6.24.001 postcondition 5 — operator confirmation required before proceeding)

After presenting the injected spec list to the operator, the skill MUST pause and output a confirmation prompt requesting the operator to proceed. The session MUST NOT start any pipeline work before the operator has confirmed.

**Test (manual):** Manual session test at F3 — invoke `/rehydrate-wave` in a live Claude Code session; verify that a confirmation prompt is presented and session pauses before any downstream pipeline step is dispatched.

### AC-006 (traces to BC-6.24.001 postcondition 6 — missing spec files: warn not block)

If a path listed in `wave-state.yaml` does not exist on the filesystem or in `factory-artifacts`, the skill MUST emit a warning naming the missing path AND continue injecting the remaining listed files. The operator is informed of the gap; the skill does NOT hard-block.

**Test (bats):** `test_rehydrate_wave_warns_on_missing_spec_file_and_continues()`
— Setup: `wave-state.yaml` lists `[A.md, missing-spec.md, C.md]`; only `A.md` and `C.md` exist.
— Assert: output contains warning mentioning `missing-spec.md`; `A.md` and `C.md` are injected; confirmation prompt shown; skill exits without error.

### AC-007 (traces to BC-6.24.001 postcondition 7 — wave-state.yaml not found: hard block with RehydrationError)

If `wave-state.yaml` does NOT exist on `factory-artifacts` (and EPIC-COMPLETE HANDOFF.md is also not present), the skill MUST hard-block with:

```
RehydrationError: wave-state.yaml not found on factory-artifacts; cannot rehydrate. Run /wave-handoff on wave N to produce the manifest.
```

No files are injected. The skill exits with a non-zero exit code.

**Test (bats):** `test_rehydrate_wave_hard_blocks_on_missing_manifest()`
— Setup: `factory-artifacts` branch has no `wave-state.yaml` and no `HANDOFF.md` with `epic_status: complete`.
— Assert: output contains `RehydrationError: wave-state.yaml not found on factory-artifacts`; no files injected; skill exits with failure.

### AC-008 (traces to BC-6.24.001 postcondition 8 + invariant 3 — no RAG fallback)

The skill MUST NOT fall back to semantic retrieval, RAG, or fuzzy file matching to extend the context beyond the manifest. If `wave-state.yaml` is missing or incomplete, the ONLY valid actions are the hard-block (AC-007) or missing-file warning (AC-006). Any code path that performs vector similarity search or LLM-based file retrieval is a specification violation.

**Test (bats):** `test_rehydrate_wave_no_rag_fallback_on_missing_manifest()`
— Mirrors `test_rehydrate_wave_hard_blocks_on_missing_manifest` but additionally asserts that the skill emits no file injection output at all (no spec files listed in output before the error).

### AC-009 (traces to BC-6.24.001 edge case EC-EPIC — EPIC-COMPLETE path: reads HANDOFF.md only)

When the factory `factory-artifacts` branch has no `wave-state.yaml` but `HANDOFF.md` exists with `epic_status: complete` and `next_wave_stories: []`, the skill MUST:
1. Read `HANDOFF.md` (not `wave-state.yaml`).
2. Detect `epic_status: complete`.
3. Inject `STATE.md` + `arch_files` from `HANDOFF.md` only.
4. Emit `"Epic complete — no next-wave stories"`.
5. NOT emit `RehydrationError` (wave-state.yaml absence is expected on EPIC-COMPLETE).

**Test (bats):** `test_rehydrate_wave_epic_complete_reads_handoff_not_wave_state()`
— Setup: no `wave-state.yaml` on `factory-artifacts`; `HANDOFF.md` has `epic_status: complete`, `next_wave_stories: []`, `arch_files: [C.md]`.
— Assert: exit 0; output contains `"Epic complete — no next-wave stories"`; `.factory/STATE.md` and `C.md` injected; no `RehydrationError`.

### AC-010 (traces to BC-6.24.001 invariant 2 — VP-088 §2 exact-list semantics machine-stable assertion)

The `INJECTED_FILE_COUNT=<n>` sentinel (AC-002) MUST count exactly the union set as defined by Invariant 2. Duplicate paths in `spec_files` across multiple stories are counted once (set semantics). The sentinel MUST appear on its own line, parseable via:

```bash
INJECTED_COUNT=$(skill_output | grep '^INJECTED_FILE_COUNT=' | cut -d= -f2)
```

**Test (bats):** `test_rehydrate_wave_deduplicates_spec_files_in_count()`
— Setup: `wave-state.yaml` with two stories each listing `A.md` in `spec_files`, plus `arch_files: [B.md]`, `state_pointer: ".factory/STATE.md"`.
— Assert: `INJECTED_FILE_COUNT=3` (A.md + B.md + STATE.md, deduplicated); `A.md` appears only once in injected context.

## Architecture Compliance Rules

1. **Git-source mandate (BC-6.24.001 Inv1):** The SKILL.md MUST use `git show factory-artifacts:wave-state.yaml`. Any invocation of `cat .factory/wave-state.yaml`, `read_file .factory/wave-state.yaml`, or any working-tree access is a specification violation.
2. **No RAG (BC-6.24.001 Inv3 / ADR-026 §Decision 4):** The skill MUST NOT invoke any vector similarity search, LLM retrieval, or fuzzy file-matching mechanism. If the manifest is missing, hard-block.
3. **Exact-list semantics (BC-6.24.001 Inv2):** `INJECTED_FILE_COUNT` MUST equal `|Set(stories[*].spec_files) ∪ Set(arch_files) ∪ {state_pointer}|`. Subset and superset are both violations.
4. **INJECTED_FILE_COUNT sentinel is mandatory (VP-088 §2 PC2-SIGNAL):** The `INJECTED_FILE_COUNT=<n>` line on stdout is a normative output requirement, not optional. Absence breaks automated test assertions.
5. **Transparency (BC-6.24.001 Inv4):** The skill MUST print the human-readable injected file list before the confirmation prompt. Silent injection (no output) is a specification violation.
6. **No new files outside skill directories:** Deliverables live exclusively in `plugins/vsdd-factory/skills/rehydrate-wave/SKILL.md` and `plugins/vsdd-factory/skills/wave-reset/SKILL.md` plus the bats test file.
