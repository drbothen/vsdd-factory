# S-19.01 — pr-manager hardening: READY verdict HEAD-SHA pinning + release-PR merge-strategy guard + shell-dialect simulation discipline

**Epic:** E-19 — Post-rc.22 Operator Hardening
**Wave:** 1 (no hard predecessor in E-19; can begin immediately)
**Depends on:** none
**Priority:** P1 (process-gap hardening; prevents silent merge-race data loss and erroneous squash-merges of release PRs)
**Subsystem anchor:** SS-05 (Pipeline Orchestration) owns the pr-manager agent and orchestrator agent behavior. No skill catalog changes in this story.

## Narrative

Three lessons codified from the rc.22 brownfield-backfill cycle expose gaps in the pr-manager workflow that create silent failure modes in production:

**L-BB-merge-race-ready-report-stale-head (D-749):** The pr-manager issues a READY verdict after reviewing a PR, but does not record the HEAD SHA it evaluated. If a subsequent push lands before the orchestrator issues the merge instruction, the READY verdict silently covers a different commit than the one that was actually merged. The operator has no way to detect that the reviewed commit and the merged commit differ.

**L-BB-release-pr-squash-merge-not-mechanically-enforced (D-750):** Release PRs (branches matching `^release/v`) MUST be merged with `--merge` per RELEASING.md (TD #69). The pr-manager has no explicit merge-strategy gate; a squash-merge could strip develop's commits from being ancestors of main, violating the release invariant. The pr-manager should detect and block squash-merge attempts on release PRs.

**L-BB-simulation-shell-dialect-gap (D-750):** When validating release.yml darwin-leg scripts (e.g., bash scripts in CI that run on macOS runners with Bash 3.2.57), the test harness must invoke those scripts explicitly under `/bin/bash`, not the operator's default `bash` (which on macOS Ventura/Sonoma may be Bash 5.x from Homebrew). The gap was discovered when a script failed on the macOS CI runner in production but appeared to pass in local testing because the validator used Homebrew's `bash` instead of `/bin/bash`. Apple's patched 3.2.57 is not identical to vanilla GNU 3.2, so Linux-based emulation is non-faithful — a dedicated macOS CI job is required.

**BC-5.42.001 v1.6 (v1.6 VP-table-only — VP-094 row-3 proof-method fix; v1.5 traceability-only — L2 Domain Invariants TBD→none; v1.4 input-hash placeholder retired; v1.3 WASM path anchoring fix E-19 pass-22)** specifies the three mechanically-enforced implementation components for this story: (a) `pr-manager-completion-guard` WASM SubagentStop hook emitting `READY_SHA_MISSING`; (b) `check-stale-verdict.sh` stale-verdict detection script; (c) `enforce-merge-strategy.sh` merge-strategy enforcement script wrapping `gh pr merge`.

## Architecture Mapping

This story modifies the pr-manager agent definition in SS-05 and adds bats integration tests, plus three new enforcement scripts/hooks per BC-5.42.001:
- `plugins/vsdd-factory/agents/pr-manager.md` — adds §READY Verdict Format (covered_sha field), §Merge-Strategy Gate (release branch check via `enforce-merge-strategy.sh`), §Darwin-Leg Validation Discipline, §Stale-Verdict Detection (check-stale-verdict.sh prerequisite)
- `plugins/vsdd-factory/bin/check-stale-verdict.sh` — new script; invoked by orchestrator before every `gh pr merge`; calls `gh pr view <pr_number> --json headRefOid`; exits non-zero with `STALE_READY_VERDICT` on mismatch (BC-5.42.001 part b)
- `plugins/vsdd-factory/bin/enforce-merge-strategy.sh` — new script; wraps `gh pr merge`; forces `--merge` on `release/v*` branches; exits non-zero with `RELEASE_PR_SQUASH_FORBIDDEN` on squash/rebase attempt (BC-5.42.001 part c)
- `plugins/vsdd-factory/hook-plugins/pr-manager-completion-guard.wasm` — WASM SubagentStop hook; inspects `last_assistant_message` for READY verdict + `covered_sha: <40-hex>`; emits `READY_SHA_MISSING` advisory if field absent (BC-5.42.001 part a); extension to the existing pr-manager-completion-guard hook (crate crates/hook-plugins/pr-manager-completion-guard/ + [[hooks]] registry entry + built WASM all exist; File Structure row: modify (extend))
- Orchestrator-per-story delivery workflow — adds stale-verdict check (`check-stale-verdict.sh`) before merge instruction, enforces merge via `enforce-merge-strategy.sh`
- Test harness (bats files in `plugins/vsdd-factory/tests/`) — adds darwin-leg preflight discipline for release script validation; gated by `bats-darwin-leg-macos` CI job
- CI job matrix note: `bats-full-suite` (existing, Linux), `bats-wave-handoff-macos` (existing, macOS), `bats-darwin-leg-macos` (NEW — this story, macOS).

**ADR-030** — pr-manager merge-operation integrity: formalizes the merge-strategy enforcement (`enforce-merge-strategy.sh` wrapping `gh pr merge`, `--merge`-only on `release/v*` branches) and stale-verdict detection (`check-stale-verdict.sh` prerequisite before every merge) as architectural decisions binding this story's scope.
