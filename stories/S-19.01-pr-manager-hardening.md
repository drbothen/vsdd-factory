# S-19.01 — pr-manager hardening: READY verdict HEAD-SHA pinning + release-PR merge-strategy guard + shell-dialect simulation discipline

**Epic:** E-19 — Post-rc.22 Operator Hardening
**Wave:** 1 (no hard predecessor in E-19; can begin immediately)
**Depends on:** none
**Priority:** P1 (process-gap hardening; prevents silent merge-race data loss and erroneous squash-merges of release PRs)
**Subsystem anchor:** SS-05 (Pipeline Orchestration) owns the pr-manager agent and orchestrator agent behavior. No skill catalog changes in this story.

## Narrative

Three lessons codified from the rc.22 brownfield-backfill cycle expose gaps in the pr-manager workflow that create silent failure modes in production:

**L-BB-merge-race-ready-report-stale-head (D-749):** The pr-manager issues a READY verdict after reviewing a PR, but does not record the HEAD SHA it evaluated. If a subsequent push lands before the orchestrator issues the merge instruction, the READY verdict silently covers a different commit than the one that was actually merged. The operator has no way to detect that the reviewed commit and the merged commit differ.

**L-BB-release-pr-squash-merge-not-mechanically-enforced (D-750):** Release PRs (branches matching `release/v*`) MUST be merged with `--merge` per RELEASING.md (TD #69). The pr-manager has no explicit merge-strategy gate; a squash-merge could strip develop's commits from being ancestors of main, violating the release invariant. The pr-manager should detect and block squash-merge attempts on release PRs.

**L-BB-simulation-shell-dialect-gap (D-750):** When validating release.yml darwin-leg scripts (e.g., bash scripts in CI that run on macOS runners with Bash 3.2.57), the test harness must invoke those scripts explicitly under `/bin/bash`, not the operator's default `bash` (which on macOS Ventura/Sonoma may be Bash 5.x from Homebrew). The gap was discovered when a script failed on the macOS CI runner in production but appeared to pass in local testing because the validator used Homebrew's `bash` instead of `/bin/bash`. Apple's patched 3.2.57 is not identical to vanilla GNU 3.2, so Linux-based emulation is non-faithful — a dedicated macOS CI job is required.

## Acceptance Criteria

| ID | Criterion | Gate |
|----|-----------|------|
| AC-001 | `pr-manager` READY verdict output includes `covered_sha: <40-char-hex>` recording the PR's HEAD SHA at the time READY was assessed. If `gh pr view --json headRefOid` fails or returns empty, the pr-manager exits non-zero with message `READY_SHA_FETCH_FAILED: cannot pin covered HEAD SHA`. | `grep -q "covered_sha:" <READY_output>` exits 0; `covered_sha` value matches `git rev-parse HEAD` on the PR branch at assessment time. Negative control for gh failure: a fixture where `gh pr view` exits non-zero (gh-failure fixture) → pr-manager stderr contains `READY_SHA_FETCH_FAILED:` and process exits non-zero (exit non-zero if this assertion fails). Non-exit test: a READY verdict missing `covered_sha:` must cause the downstream merge gate to fail. |
| AC-002 | Before issuing the merge instruction, the orchestrator fetches the current PR HEAD SHA and compares it to `covered_sha`. If they differ (stale verdict), execution halts with exit code 1 and message `STALE_READY_VERDICT: HEAD <current> has advanced past covered_sha <pinned>; re-review required.` | Shell exit code ≠ 0 when HEAD ≠ covered_sha. Positive control: same SHA → merge proceeds. Negative control: advanced SHA → exits 1 with required message text. |
| AC-003 | Merge instruction gate: when the source branch matches `^release/v`, the merge instruction uses `--merge` (not `--squash`). If a squash flag would be issued, the pr-manager exits non-zero with `RELEASE_PR_SQUASH_FORBIDDEN: release branches must merge with --merge per RELEASING.md`. | Shell exit code ≠ 0 on squash attempt for release branch. Positive control: `--merge` proceeds. Negative control: `--squash` on `release/v*` exits 1. |
| AC-004 | Darwin-leg CI script validation in the test harness uses `/bin/bash` (the macOS system Bash, version 3.2.x) as the interpreter, not `bash` from PATH (which may be Bash 5.x from Homebrew). A preflight assertion in `bats setup_file` verifies that `/bin/bash --version` contains the substring `version 3.2` on macOS (darwin) test runners; if the check fails, the suite exits non-zero with `DARWIN_LEG_WRONG_INTERPRETER: expected /bin/bash 3.2.x, got <actual>`. This suite is gated by a dedicated `bats-darwin-leg-macos` CI job running on `macos-latest`; the job uses `/bin/bash` as the shebang for all generated temp scripts and does NOT install or use Homebrew bash. On Linux CI runners the darwin-leg preflight block is absent because Linux jobs do not run this suite. | On a macOS environment, `/bin/bash --version` substring-matches `version 3.2`; bats tests that invoke a release.yml darwin-leg shell fragment use `#!/bin/bash` as the shebang in generated temp scripts; preflight assertion in `setup_file` exits 1 on wrong interpreter. CI gate: `bats-darwin-leg-macos` job runs on every PR to `develop`/`main` as a required status check. |

## Architecture Mapping

This story modifies the pr-manager agent definition in SS-05 and adds bats integration tests:
- `plugins/vsdd-factory/agents/pr-manager.md` — adds covered_sha pinning to READY verdict format, adds merge-strategy gate specification for release PRs, adds darwin-leg validation discipline
- Orchestrator-per-story delivery workflow — adds stale-verdict check before merge instruction
- Test harness (bats files in `plugins/vsdd-factory/tests/`) — adds darwin-leg preflight discipline for release script validation; gated by `bats-darwin-leg-macos` CI job

No new WASM crates. No hooks-registry.toml changes.

## Edge Cases

| EC-001 | `gh pr view` network failure during covered_sha fetch | pr-manager exits non-zero with `READY_SHA_FETCH_FAILED`; does not issue a READY verdict without the SHA. |
| EC-002 | Merge gate check: PR branch has been force-pushed (HEAD SHA changed, PR still open) | `STALE_READY_VERDICT` message includes both the covered_sha and the current HEAD so the operator can trace the divergence. |

The `bats-full-suite` (Linux) job does not include darwin-leg tests and makes no attempt to simulate bash 3.2 behavior. The darwin-leg coverage gap on Linux is intentional and closed by the dedicated macOS CI job, not by emulation. |
| EC-004 | Release PR merge with `--merge` flag explicitly provided | Gate passes; no false positive. |
