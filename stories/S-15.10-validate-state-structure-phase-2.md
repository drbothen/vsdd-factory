# S-15.10: validate-state-structure WASM Hook Phase 2

**Epic:** E-12 — Engine Governance (brownfield-backfill wave, S-15.03 PRIORITY-A M3)
**Delivery order:** M3 Wave-1 (first of five M3 stories; extends S-15.09's existing crate)
**Depends on:** S-15.09 (merged — Phase 1 crate scaffolding must be in place; this story adds
  checks to the same `crates/hook-plugins/validate-state-structure/` crate)
**Blocks:** none
**Priority:** P1 (closes D-432(a)+D-434(b)+D-431(b)+D-440(b)+D-431(a)+D-435(b)+D-447(d)+D-434(e)+D-446(e))

## Narrative

- **As a** state-manager or agent writing a STATE.md update in a fix burst
- **I want to** receive an immediate PostToolUse block when the STATE.md Decisions Log has
  duplicate D-NNN rows, non-monotonic row ordering, missing Phase Progress rows, or tally cells
  that diverge from INDEX.md
- **So that** the recurring class of STATE.md cross-cell consistency violations — Decisions Log
  monotonicity drift, Phase Progress row gaps, and tally sync failures — is caught mechanically
  at write time rather than discovered by the adversary N bursts later

## Why This Exists

The F5 engine-discipline cycle generated persistent adversary findings around STATE.md's
internal consistency beyond the banner and trajectory-tail (which Phase 1 covers). D-432(a)+
D-434(b) codified that STATE.md and INDEX.md quantitative tally cells must agree. D-431(b)+
D-440(b) codified Decisions Log monotonic-row enforcement. D-431(a) required no-row-coalescence
in decision-log.md. D-435(b)+D-447(d) required Phase Progress rows at every codifying burst.
D-434(e) established a 5-sub-check completeness sweep for every codifying-burst STATE.md.
D-446(e) required single-row-per-D-NNN in the Decisions Log.

Phase 1 (S-15.09, merged) covers banner + trajectory. Phase 2 extends the same WASM crate with
cross-cell consistency and monotonicity checks that require reading an additional file
(INDEX.md) for tally comparison.

## Goal

Extend `crates/hook-plugins/validate-state-structure/` (the Phase 1 crate) with Phase 2 checks
that PostToolUse-block any Edit/Write to `STATE.md` that:
- Contains duplicate D-NNN rows in the Decisions Log (D-446(e))
- Has Decisions Log rows in non-ascending D-NNN order (D-431(b)+D-440(b))
- Is missing Phase Progress rows at the current adversary pass or fix burst (D-435(b)+D-447(d))
- Has quantitative tally cells (pass count, finding count) that diverge from INDEX.md
  Convergence Status values (D-432(a)+D-434(b))

## Behavioral Contract

This story extends **BC-5.39.005** (validate-state-structure Phase 1 hook). Phase 2 checks are
additive to the Phase 1 checks — the existing Phase 1 invariants are unchanged. BC-5.39.005
**is not amended by this story**; Phase 2 scope is specified here as story-level postconditions
and maps to BC-5.39.005's general "multiple violations produce single BlockWithFix" invariant.

**BC ID:** BC-5.39.005
**File:** `.factory/specs/behavioral-contracts/ss-05/BC-5.39.005.md`

### Phase 2 Postconditions (additive to BC-5.39.005)

**P2-PC-1 — Tally sync (D-432(a)+D-434(b)):**
If STATE.md's Convergence Status tally values (pass count integer, finding-total integer)
diverge from INDEX.md's corresponding Convergence Status row values, the hook emits
`HookResult::block_with_fix(...)` naming the divergent fields and their values.
If INDEX.md is unreadable via `host::read_file`, the tally check is fail-open
(`HookResult::Continue` + `host::log_warn`).

**P2-PC-2 — Decisions Log monotonicity (D-431(b)+D-440(b)+D-446(e)):**
If the Decisions Log D-NNN rows are not in monotonically non-decreasing order, or if any
D-NNN ordinal appears more than once (duplicate row), the hook emits
`HookResult::block_with_fix(...)` naming the violation.

**P2-PC-3 — Phase Progress row presence (D-435(b)+D-447(d)):**
If the Phase Progress section is absent from STATE.md, or if it does not contain at least one
row matching `pass-\d+` and at least one row matching the `fix burst` pattern, the hook emits
`HookResult::block_with_fix(...)` citing the missing row type.

**P2-PC-4 — Completeness sub-checks (D-434(e)):**
If any of the 5 D-434(e) sub-checks fail (missing Convergence Status, missing Concurrent
Cycles row, missing Session Resume Checkpoint section, missing Last Updated, missing Phase
Progress row), the hook emits `HookResult::block_with_fix(...)` naming each missing element.

**P2-PC-5 — Decisions Log row-coalescence (D-431(a)):**
If any line within the STATE.md Decisions Log section matches the row-coalescence pattern
— two distinct `| D-\d+` table cells on the same line (e.g., `| D-490 | ... | D-491 | ...`)
— the hook emits `HookResult::block_with_fix(...)` naming the coalesced line and citing
D-431(a). The Decisions Log section is bounded by the `## Decisions Log` h2 heading and
the next h2 heading. Each D-NNN row must occupy exactly one line; no two D-NNN ordinals
may appear on the same `|`-delimited table row.

- [ ] T-5: Add Phase 2 check functions to `src/lib.rs`:

  ```
  fn check_decisions_log_monotonicity(content: &str) -> Option<Violation>
  ```
  Scan STATE.md content for the Decisions Log section (bounded by `## Decisions Log` to the next
  `## ` heading). Iterate lines; for each line that starts with `| D-`, extract the D-number by
  splitting on `|` and stripping whitespace from the second token, then parsing the digits after
  `D-` via `trim_start_matches("D-").parse::<u32>()`.
  Use hand-rolled scanning — no regex crate (WASM fuel exhaustion).
  Collect the integer ordinals. Assert: (a) each ordinal appears exactly once (no duplicate);
  (b) the sequence is monotonically non-decreasing. Return Some(Violation) if either fails,
  naming the problematic row(s), citing D-431(b)+D-440(b)+D-446(e).

  ```
  fn check_tally_sync(state_content: &str, index_content: &str) -> Option<Violation>
  ```
  Extract pass count integer from STATE.md Convergence Status section using hand-rolled scanning
  (no regex crate — WASM fuel exhaustion per established sibling hook convention). Scan lines
  for substrings like `" passes"` or `"pass count"`, extract the adjacent integer token using
  `str::split_whitespace()` and `.parse::<u32>()`. Implementer MUST read actual production
  STATE.md and INDEX.md before writing extraction logic to confirm the exact marker text.
  Extract the same value from INDEX.md Convergence Status section. If extracted values differ,
  return Some(Violation) naming both values and citing D-432(a)+D-434(b). If extraction fails
  for either file, return None (fail-open per P2-PC-1).

  ```
  fn check_phase_progress_rows(content: &str) -> Option<Violation>
  ```
  Find the `## Phase Progress` section (or equivalent heading containing "Phase Progress").
  Use hand-rolled scanning — no regex crate (WASM fuel exhaustion). Within that section, check for:
  (a) at least one row whose text contains `"pass-"` followed by digits (use `str::contains`
  with a prefix scan, or split on `"pass-"` and check if remainder starts with a digit);
  (b) at least one row whose text contains `"fix burst"` (case-insensitive `str::to_lowercase`
  + `contains`).
  Return Some(Violation) naming the missing row type(s), citing D-435(b)+D-447(d). If the
  Phase Progress section is not found, return Some(Violation) citing D-434(e).

  ```
  fn check_row_coalescence(content: &str) -> Option<Violation>
  ```
  Scan the Decisions Log section of STATE.md (bounded by `## Decisions Log` h2 heading to
  the next `## ` heading) for lines that contain two or more distinct `D-\d+` table cells
  coalesced onto one line. Use hand-rolled scanning — no regex crate (WASM fuel exhaustion).
  For each line in the Decisions Log section: split the line on `|`; count how many pipe-
  delimited cells start with `D-` (after trimming whitespace); if two or more cells on the
  same line begin with `D-`, it is a coalesced row.
  Return `Some(Violation)` naming the offending line and citing D-431(a). Return `None` if
  no coalesced rows are found in the section.

  ```
  fn check_d434e_completeness(content: &str) -> Vec<Violation>
  ```
  Check all 5 D-434(e) sub-checks using hand-rolled `str::contains()` — no regex crate
  (WASM fuel exhaustion):
  1. `## Convergence Status` heading present — `content.contains("## Convergence Status")` or
     `content.contains("Convergence Status")` as a fallback substring search
  2. Concurrent Cycles row present — `content.contains("Concurrent Cycles")`
  3. Session Resume Checkpoint section present — `content.contains("Session Resume Checkpoint")`
  4. `Last Updated:` field present — `content.contains("Last Updated:")`
  5. Phase Progress section present — `content.contains("Phase Progress")`
  Return a Vec of violations for each missing element. Empty vec means all 5 present.

  ```
  fn run_hook_phase2(content: &str, file_path: &str) -> Vec<Violation>
  ```
  Orchestrates Phase 2 checks. Called from the main `on_post_tool_use` function AFTER Phase 1 checks
  complete (Phase 1 and Phase 2 violations accumulate into the same Vec). Calls:
  - `check_decisions_log_monotonicity(content)` — adds to violations if Some
  - `check_row_coalescence(content)` — adds to violations if Some (D-431(a))
  - Reads INDEX.md via `host::read_file(".factory/cycles/<cycle>/INDEX.md", 524288, 2000)`;
    if success: calls `check_tally_sync(content, &index_content)` — adds if Some
    if error: logs warn via `host::log_warn` (fail-open)
  - `check_phase_progress_rows(content)` — adds if Some
  - `check_d434e_completeness(content)` — extends violations vec
