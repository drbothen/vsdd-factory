# S-19.02 — verify-factory-lock FINDING-1: frontmatter-only STATE.md read + raised byte budget

**Epic:** E-19 — Post-rc.22 Operator Hardening
**Wave:** 1 (P0 defect; begin immediately; no E-19 predecessor)
**Depends on:** none
**Priority:** P0 (functional defect — lock gate silently degraded in every operator install where STATE.md exceeds 64 KiB; this is production state for the vsdd-factory repo at rc.22)
**Subsystem anchor:** SS-04 (Plugin Ecosystem) owns the `verify-factory-lock` WASM hook plugin crate.

## Narrative

The `verify-factory-lock` PreToolUse WASM guard (S-17.02; BC-4.13.001) is the single-writer enforcement mechanism for the factory-artifacts orphan branch. It reads `.factory/STATE.md` via `host::read_file` with a 64 KiB cap (`STATE_MD_MAX_BYTES = 65536`), then parses the `factory_lock:` YAML frontmatter block.

**The defect:** In the vsdd-factory repo at rc.22, STATE.md is approximately 90 KB — larger than the 64 KiB cap. `read_file.rs::read_bounded()` returns `ReadErr::TooLarge` when the file's on-disk size exceeds `max_bytes`, emitting `internal.capability_denied reason=output_too_large` and returning `OUTPUT_TOO_LARGE (-3)` to the plugin. The plugin maps any non-zero `read_file` return as `StateReadError` and emits a WARN log, then falls back to Continue (fail-open per ADR-025 Decision 7). The lock gate is therefore **silently bypassed on every PreToolUse Edit/Write/MultiEdit/Agent dispatch** in any install where STATE.md has grown beyond 64 KiB.

Evidence from `.factory/logs/dispatcher-internal-2026-07-04.jsonl`: traces `a4b26f12`, `bcc3e6ef`, `cf4c2e4d`, `2551d7db` each show `internal.capability_denied reason=output_too_large` on `plugin_name=verify-factory-lock`, confirming STATE.md is consistently exceeding the cap in the production rc.22 install.

**Fix direction (production-grade, both arms):**

1. **Frontmatter-only extraction (primary):** The plugin only needs the YAML frontmatter — the `factory_lock:` block is always within the opening `---` ... `---` delimiters. Instead of reading the whole file, the plugin should read at most the frontmatter section. The `read_file.rs::read_bounded()` function treats the file as opaque bytes; the plugin already receives raw bytes and parses YAML. The fix is for the plugin to compute the frontmatter boundary after reading: truncate the byte buffer at the second `---\n` occurrence (or at `max_bytes`, whichever comes first). This means a 256 KiB cap covers all realistic STATE.md sizes while the parser only sees the frontmatter.

2. **Raised byte budget (defense-in-depth):** Raise `STATE_MD_MAX_BYTES` from 65536 (64 KiB) to 262144 (256 KiB). STATE.md growth is bounded by D-442(e) (≤4000 lines soft/hard); 256 KiB is safely above any foreseeable STATE.md size for the current document structure.

Both arms are required for production-grade closure: the raised cap prevents regressions as STATE.md grows, and frontmatter-only extraction makes the cap semantically meaningful (we read no more than we need).

## Exceptional Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-001 | STATE.md is exactly 64 KiB (boundary case) | Plugin reads successfully at the new 262144 cap. No regression at the old boundary. |
| EC-002 | STATE.md exceeds 256 KiB | Plugin falls back to fail-open (Continue) per ADR-025 Decision 7 + emits `StateReadError: OutputTooLarge` warn. The 256 KiB cap is intended as a hard ceiling above D-442(e) soft/hard limits; any exceedance indicates a structural anomaly. |
| EC-003 | Frontmatter delimiter appears inside a YAML string value | Extraction algorithm searches for `\n---\n` or `\n---` at EOF as a line unto itself; embedded `---` within a scalar value will not match. |
| EC-004 | STATE.md has no closing frontmatter delimiter (malformed) | Extraction uses full content as frontmatter; YAML parser returns error; plugin falls back to fail-open with WARN. |

## Architecture Mapping

- `crates/hook-plugins/verify-factory-lock/src/lib.rs` — raise `STATE_MD_MAX_BYTES` to 262144; add `extract_frontmatter(bytes: &[u8]) -> &[u8]` function that truncates at the closing `---` boundary; call it before `parse_factory_lock`
- `crates/hook-plugins/verify-factory-lock/src/tests.rs` (or inline tests) — add unit tests for AC-001..AC-005
- No changes to `hooks-registry.toml` (the capability `path_allow` and `on_error` remain unchanged)
- No changes to `read_file.rs` (the fix is fully in the plugin)
