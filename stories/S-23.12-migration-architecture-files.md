# S-23.12: Corpus migration — architecture files document class (26 files, excludes ARCH-INDEX.md)

## Narrative

- **As a** state-manager/consistency-validator executing ADR-045's mechanical corpus migration
- **I want** to run the S-23.02 codemod across the 26 architecture files identified in ADR-045's
  corpus scan (SS-0X module docs, ADR files other than ARCH-INDEX itself), converting live inline
  citations to stable-anchor form, including the anchor-interposed ADR-to-ADR cites this document
  class is expected to contain (an ADR discussing a decision that supersedes or extends another
  ADR)
- **So that** the architecture layer — SS-0X module docs and individual ADR files — no longer
  propagates version-pin churn when a cited ADR or BC is amended

## Context / Problem Statement

ADR-045 §Consequences, Negative/Trade-offs names 26 architecture files (distinct from ARCH-INDEX.md
itself, migrated in S-23.07) in the corpus scan. This document class includes individual ADR files
(which frequently cite sibling/superseded ADRs, e.g. this very ADR-045 citing POLICY 19/TD-VSDD-091
and its own supersession chain) and SS-0X module docs (which cite BCs by ID within their module
catalogs, per the ARCH-INDEX Subsystem Registry pattern observed during this epic's own research,
e.g. "BC-7.06.001 frontmatter subsystem=SS-01"-style cites).

## Acceptance Criteria

### AC-001
Running the codemod in `--dry-run` mode across all 26 architecture files (excluding ARCH-INDEX.md,
already migrated in S-23.07) produces a diff report reviewed before apply. (traces to ADR-045
§Migration Plan Phase A step 5; S-23.02 AC-006/AC-007)

### AC-002
Individual ADR files' own supersession-chain cites (`supersedes: ADR-NNN`, `superseded_by:
ADR-NNN` frontmatter fields) are confirmed out of scope — these are structured frontmatter
identity fields, not prose citations with an inline version token, and the codemod's regex-based
detector (S-23.01) does not match them (no `vN.NN` token present in that field form). (traces to
S-23.01 AC-005 — form recognition; negative-scope confirmation for this document class)

### AC-003
Live prose citations within an ADR's body (e.g., "per ADR-039 §Decision 3 v1.10") are converted
to stable-anchor form, applying the same newline-normalized/anchor-interposed-tolerant detection
exercised in S-23.07. (traces to ADR-045 §Context failure modes 1-2; S-23.01 AC-003/AC-004)

### AC-004
SS-0X module docs' BC-ID citations within their module catalogs are converted where a load-bearing
inline version token is present. (traces to ADR-045 §Decision, Tier 1, "Permitted forms")

### AC-005
The codemod does not modify any architecture file's `modified:`/`last_amended:`/`[Prior:]`/
`## Changelog` sections. (traces to S-23.01 AC-001)

### AC-006
The migration is applied as exactly one atomic commit touching the 26 architecture files. (traces
to ADR-045 §Migration Plan Phase A step 5; TD-VSDD-053)

### AC-007
Post-commit, S-23.03's guard and S-23.05's extended parity gate pass against all 26 migrated
architecture files with zero findings. (traces to S-23.03 AC-001/AC-003; S-23.05 AC-001)

### AC-008 (negative control)
Post-commit, a targeted newline-normalized grep for live-section inline version pins across all
26 architecture files returns zero matches. (traces to ADR-045 §Consequences Positive)
