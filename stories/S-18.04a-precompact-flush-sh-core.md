# S-18.04a — precompact-flush.sh Core

## Narrative

As the factory-dispatcher runtime receiving a PreCompact event,
I want a `precompact-flush.sh` shell hook that commits STATE.md to the
factory-artifacts branch BEFORE compaction proceeds,
so that context-window transitions do not lose uncommitted pipeline state,
and the precompact-flush-log provides an auditable record of every pre-compaction
commit with SHA, timestamp, cycle, and step.

## Behavioral Contracts

| BC ID | Title | Version | PCs Exercised |
|-------|-------|---------|---------------|
| BC-7.07.001 | precompact-flush.sh commits STATE.md to factory-artifacts before compaction | v1.12 | PC1–PC8, INV1–INV7 |

## Acceptance Criteria

### AC-001 (traces to BC-7.07.001 precondition 1 — hooks-registry.toml registration)
`precompact-flush.sh` is registered in `hooks-registry.toml` via
`legacy-bash-adapter.wasm` with:
- `event = "PreCompact"`
- `priority = 100`
- `timeout_ms = 30000`
- `on_error = "continue"`
- `[hooks.config] script_path = "hooks/precompact-flush.sh"`

### AC-002 (traces to BC-7.07.001 postcondition 7 — STATE.md unreadable: exit 0 + warn)
On invocation, the script reads `STATE.md` from the factory-artifacts worktree.
If STATE.md is absent or unreadable, the script exits 0 (fail-open) and writes a
warning to stderr: `precompact-flush: STATE.md unreadable; flush skipped.`
(No commit, no log append, no push on this path.)

### AC-003 (traces to BC-7.07.001 postcondition 3 — factory lock renewal conditional)
The script checks the `factory_lock:` block in STATE.md. If `factory_lock:` is absent
or `factory_lock.holder` is absent/null, the lock is not held and the lock-renewal step
is skipped entirely (no-op per ADR-025 opt-in model). If the lock IS held, the script
invokes `factory-lock-write.sh renew .factory/STATE.md` BEFORE proceeding to commit.
Lock renewal failure is treated as a non-fatal advisory warning; the flush commit is
attempted regardless. Lock renewal failure does NOT cause exit 2 — per BC-7.07.001
PC3 and EC-004.

### AC-004 (traces to BC-7.07.001 postcondition 4 — factory-artifacts commit: git add sub-step)
The script stages STATE.md (and any other factory-artifacts files with pending changes)
via `git add` in the factory-artifacts worktree. This is step 4 of the canonical
execution order per BC-7.07.001 INV3.

### AC-005 (traces to BC-7.07.001 postcondition 4 + postcondition 1 + invariant 4 — LOCAL commit with canonical message)
The script creates a LOCAL git commit (does not push yet). Context identity
(`<cycle>` and `<step>`) is derived from the `current_cycle:` and `current_step:`
fields in STATE.md frontmatter (BC-7.07.001 PC1 — filesystem read; NOT in-context
reasoning, NOT `current_wave:` phantom field). The commit message MUST be:
`PreCompact flush <cycle>/<step> <ISO-8601-timestamp>` (BC-7.07.001 INV4 — canonical
format). The subject MUST begin with the literal prefix `PreCompact flush ` (capital
P, capital C, one space between words, trailing space — case-sensitive per BC-5.41.003
INV3). If there are no pending changes on factory-artifacts, the script exits 0
silently without creating an empty commit (BC-7.07.001 INV5).

### AC-005b (traces to BC-7.07.001 postcondition 6 — exit 2 on git commit LOCAL failure)
If the `git commit` command exits non-zero (lock contention, permission error, disk
full, or other LOCAL filesystem error), the script exits 2. This signals the dispatcher
to propagate `block_intent=true` and block compaction. A diagnostic message is written
to stderr before exiting 2. At this point: no precompact-flush-log entry has been
appended and no push has been attempted. `git commit` is a purely LOCAL operation —
network errors cannot originate here.

### AC-006 (traces to BC-7.07.001 postcondition 8 — SHA_B capture immediately after commit)
IMMEDIATELY after the local commit succeeds, the script captures
`SHA_B=$(git rev-parse HEAD)`. This capture happens BEFORE any append to the
precompact-flush-log (BC-7.07.001 INV3 step 6: SHA_B capture MUST precede the append
attempt so SHA_B is available on append failure).

### AC-007 (traces to BC-7.07.001 postcondition 8 — precompact-flush-log append, newline-termination MANDATORY)
The script appends a 4-field log entry to `.factory/hooks/precompact-flush-log`
using `echo "<ISO-timestamp> <SHA_B> <cycle>/<step> commit" >> <log>` OR
`printf "%s\n" "<ISO-timestamp> <SHA_B> <cycle>/<step> commit" >> <log>`.
The append MUST produce a `\n`-terminated line. Using `printf "%s"` (without `\n`)
is FORBIDDEN. Field-4 is the literal string `commit` (never a variable).

### AC-008 (traces to BC-7.07.001 postcondition 8 — append failure SHA-pinned concurrent-commit guard)
If the log append FAILS (non-zero exit from the append command), the script
compares `git rev-parse HEAD` to `SHA_B`:
- If CURRENT_HEAD == SHA_B (no intervening commits): run `git reset --soft SHA_B^`
  to undo the local commit, then exit 2 (block compaction).
- If CURRENT_HEAD != SHA_B (intervening commits existed): exit 2 with message
  "PreCompact flush: append failed and HEAD has diverged — manual intervention
  required. Do NOT retry automatically."

### AC-009 (traces to BC-7.07.001 postcondition 6b — push failure exit 2; postcondition 5 — push success exit 0)
If the log append SUCCEEDS, the script runs `git push` on the factory-artifacts
worktree.
- If push fails: exit 2 with message "PreCompact flush: push failed — retry with
  git push from factory-artifacts worktree. Compaction is blocked."
- If push succeeds: exit 0.

### AC-010 (traces to BC-7.07.001 invariant 6 — script hardening)
The script uses `set -euo pipefail` as its first non-comment, non-shebang line.
Any unhandled error is a crash, triggering the dispatcher's `on_error = "continue"`
fail-open behavior (BC-7.07.001 PC9).

### AC-011 (traces to BC-7.07.001 invariant 3 — canonical execution order)
The canonical execution order is strictly (per BC-7.07.001 INV3 — no step may be
reordered):
1. Read STATE.md from filesystem (`current_cycle:` + `current_step:` fields) (PC1)
2. Check `factory_lock:` block — skip step 3 if absent/null (PC3)
3. If lock held: invoke `factory-lock-write.sh renew` — advisory on failure; proceed regardless (PC3)
4. `git add STATE.md` (and any other pending factory-artifacts files) (PC4)
5. `git commit` (LOCAL — no network); exit 2 immediately on commit failure (PC6 / AC-005b)
6. `SHA_B=$(git rev-parse HEAD)` — IMMEDIATELY after commit, BEFORE append (PC8)
7. Append 4-field line to precompact-flush-log — MUST be `\n`-terminated (PC8)
8. If append fails: compare CURRENT_HEAD to SHA_B → if equal: `git reset --soft SHA_B^` then exit 2; if not equal: exit 2 with human-intervention message (do NOT reset) (PC8)
9. If append succeeds: execute `git push` to remote factory-artifacts branch (PC6b)
10. If push fails: exit 2 with diagnostic; local commit + log entry retained; retry is push-only (PC6b)
11. If push succeeds: exit 0 (PC5)

### AC-012 (traces to BC-7.07.001 invariant 7 — log pruning deferred; append-only in v1)
The precompact-flush-log is append-only. The script NEVER truncates or rewrites
the log. Log pruning (prune to most-recent-500 entries when count >1000) is
explicitly deferred to `precompact-flush-prune.sh` (S-18.04b, invoked by
check-state-health, NOT by this script per BC-7.07.001 INV7).

### AC-013 (traces to BC-7.07.001 postcondition 3 + invariant 4 — lock renewal failure is advisory)
If `factory-lock-write.sh` is unavailable or exits non-zero during lock renewal
(AC-003), the script writes an advisory warning to stderr and proceeds with the
flush commit anyway. Lock renewal failure does NOT cause exit 2 and does NOT block
compaction. This is the "advisory" semantics per BC-7.07.001 PC3 and EC-004:
"Advisory warning to stderr; flush commit attempted anyway; exit 0 if commit succeeds."
INV4 documents the commit message format requirements — unrelated to lock renewal
behavior.

### AC-014 (traces to BC-7.07.001 invariant 1 — hermetic; VP-085)
The script is hermetic: it depends ONLY on:
- `git` (standard PATH)
- `date` (standard PATH)
- `factory-lock-write.sh` (co-located in hooks directory)
- The factory-artifacts worktree mount (path from environment variable
  `FACTORY_ARTIFACTS_PATH` or conventional `.factory` relative path)
No curl, no jq, no python, no npm, no external network calls except `git push`.

### AC-015 (traces to BC-7.07.001 invariant 3 step 7 — canonical log path)
The precompact-flush-log path is `.factory/hooks/precompact-flush-log` (no
`.log` extension, no `.txt` extension — exact path per BC-7.07.001 Architecture
Anchors and INV3 step 7).

### AC-016 (traces to BC-7.07.001 invariant 7 — log pruning deferred to S-18.04b)
Log pruning is NOT performed by this script. The script MUST NOT call any pruning
logic. Pruning is exclusively handled by `precompact-flush-prune.sh` (S-18.04b),
invoked by `check-state-health` only (never by precompact-flush.sh itself).

as a PostToolUse gate. Key lesson: the factory-artifacts worktree is mounted at a
path that may differ from the main repo CWD. Shell hooks must use explicit absolute

`factory-lock-write.sh` already exists (S-17.04 dependency); this story depends on
its interface but does NOT modify it.

## Architecture Compliance Rules

- `set -euo pipefail` is the first non-comment, non-shebang line (CLAUDE.md convention)
- Commit message MUST begin with exact string `PreCompact flush ` (case-sensitive, single space between words) — this prefix is the exemption key used by validate-burst-log and validate-dispatch-advance (BC-5.41.003 INV3)
- `printf "%s"` (without `\n`) is FORBIDDEN for log append — VP-090 §0 structural precondition requires every entry to be a `\n`-terminated physical line
- No `--no-verify` git flags anywhere in the script (CLAUDE.md absolute prohibition)
- Script must NOT add AI attribution to commit messages (CLAUDE.md explicit directive for vsdd-factory)

- `date` command: ISO-8601 format via `date -u +%Y-%m-%dT%H:%M:%SZ`
