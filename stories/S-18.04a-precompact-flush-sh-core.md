# S-18.04a — precompact-flush Native WASM Plugin Core

## Narrative

As the factory-dispatcher runtime receiving a PreCompact event,
I want a native WASM plugin (`crates/hook-plugins/precompact-flush/`) that commits
STATE.md to the factory-artifacts branch BEFORE compaction proceeds,
so that context-window transitions do not lose uncommitted pipeline state,
and the precompact-flush-log provides an auditable record of every pre-compaction
commit with SHA, timestamp, cycle, and step.

The plugin is implemented as a native Rust WASM crate (not a bash script routed
through legacy-bash-adapter.wasm) per ADR-014 standing policy and ADR-028 migration
decision. Lock renewal is performed natively via `crates/factory-lock::renew_lock()`
with no bash subprocess. The factory-artifacts worktree path is discovered at runtime
via `git worktree list --porcelain` (ADR-028 §Decision 1).

## Behavioral Contracts

| BC ID | Title | Version | PCs Exercised |
|-------|-------|---------|---------------|
| BC-7.07.001 | precompact-flush native WASM plugin fires synchronously on PreCompact; hermetic (STATE.md + git only); renews factory lock natively when held via crates/factory-lock::renew_lock() (no-op when absent); commits (local) with `PreCompact flush <cycle>/<step>` message; appends commit SHA to precompact-flush-log; pushes to remote; on append failure: SHA-pinned reset (`git reset --soft SHA_B^` when HEAD==SHA_B; no-reset + human-intervention exit 2 when HEAD!=SHA_B); exit 2 on commit failure (local; no network) or push failure (network); fail-open on crash | v1.16 | PC1–PC8, INV1–INV7, Precondition 4 |

## Acceptance Criteria

### AC-001 (traces to BC-7.07.001 precondition 1 — hooks-registry.toml registration)
`precompact-flush.wasm` is registered in `hooks-registry.toml` as a native WASM
plugin with the following stanza (exact TOML; no `[hooks.config]` block; no `shell_bypass_acknowledged`):

```toml
[[hooks]]
name = "precompact-flush"
event = "PreCompact"
plugin = "hook-plugins/precompact-flush.wasm"
priority = 100
timeout_ms = 30000
on_error = "continue"
async = false

[hooks.capabilities.read_file]
path_allow = [".factory/"]

[hooks.capabilities.write_file]
path_allow = [".factory/"]

[hooks.capabilities.exec_subprocess]
binary_allow = ["git"]
env_allow = ["HOME", "GIT_CONFIG_GLOBAL", "XDG_CONFIG_HOME", "PATH", "SSH_AUTH_SOCK"]
```

`binary_allow = ["git"]` ONLY — `"bash"` is explicitly absent (ADR-028 §Decision 2).
No `shell_bypass_acknowledged`. No `legacy-bash-adapter.wasm`.
`PATH` is required for git to locate `ssh` and credential helpers (needed by `git push`).
`SSH_AUTH_SOCK` is required for SSH agent communication. Without these, `git push` over
SSH will fail with authentication errors (the dispatcher's `exec_subprocess` runs with
`env_clear` followed by re-injection of only the names listed in `env_allow`).
(traces to BC-7.07.001 Precondition 1 + ADR-028 §Decision 1 F-NW-001)

### AC-002 (traces to BC-7.07.001 postcondition 7 — STATE.md unreadable: exit 0 + warn)
On invocation, the plugin reads `STATE.md` from the factory-artifacts worktree
(discovered via AC-017). If STATE.md is absent or unreadable, the plugin exits 0
(fail-open) and writes a warning to stderr:
`precompact-flush: STATE.md unreadable; flush skipped.`
(No commit, no log append, no push on this path.)

### AC-003 (traces to BC-7.07.001 postcondition 3 + ADR-028 §Decision 2 — factory lock renewal: native Rust, no bash)
The plugin checks the `factory_lock:` block in STATE.md. If `factory_lock:` is absent
or `factory_lock.holder` is absent/null, the lock is not held and the lock-renewal step
is skipped entirely (no-op per ADR-025 opt-in model). If the lock IS held, the plugin
natively updates `factory_lock.expires_at = now + 2700s` (UTC ISO-8601) via
`crates/factory-lock::renew_lock()` — a pure Rust in-process update with NO
`exec_subprocess("bash", ...)` call for renewal. The `holder` and `locked_at` fields
are preserved unchanged. Lock renewal failure is non-fatal (advisory warning to stderr;
flush proceeds). Lock renewal failure does NOT cause exit 2 — per BC-7.07.001 PC3
and EC-004.

### AC-004 (traces to BC-7.07.001 postcondition 4 — factory-artifacts commit: git add sub-step)
The plugin stages STATE.md (and any other factory-artifacts files with pending changes)
via `exec_subprocess("git", &["-C", &wt, "add", "-u"])` in the factory-artifacts
worktree (where `wt` is the absolute worktree path discovered in AC-017). The `-u` flag
stages only tracked files (no untracked files pulled in). This is step 4 of the canonical
execution order per BC-7.07.001 INV3.
Note: `wt` is the absolute worktree path discovered in AC-017. ALL git subprocesses
except the initial `git worktree list --porcelain` MUST use `-C <wt>` (ADR-028 §Decision 3
F-NW-003). Bare `git` commands without `-C` would operate on the main repo, not the
factory-artifacts worktree.

### AC-005 (traces to BC-7.07.001 postcondition 4 + postcondition 1 + invariant 4 — LOCAL commit with canonical message)
The plugin creates a LOCAL git commit (does not push yet) via `exec_subprocess("git",
&["-C", &wt, "commit", "-m", msg])` (where `wt` is the absolute worktree path from
AC-017). Context identity (`<cycle>` and `<step>`) is derived from
the `current_cycle:` and `current_step:` fields in STATE.md frontmatter (BC-7.07.001
PC1 — filesystem read via host `read_file`; NOT in-context reasoning, NOT
`current_wave:` phantom field). The commit message MUST be:
`PreCompact flush <cycle>/<step> <ISO-8601-timestamp>` (BC-7.07.001 INV4 — canonical
format). The subject MUST begin with the literal prefix `PreCompact flush ` (capital
P, capital C, one space between words, trailing space — case-sensitive per BC-5.41.003
INV3). If there are no pending changes on factory-artifacts, the plugin exits 0
silently without creating an empty commit (BC-7.07.001 INV5).

### AC-005b (traces to BC-7.07.001 postcondition 6 — exit 2 on git commit LOCAL failure)
If the `git commit` subprocess exits non-zero (lock contention, permission error, disk
full, or other LOCAL filesystem error), the plugin exits 2. This signals the dispatcher
to propagate `block_intent=true` and block compaction. A diagnostic message is written
to stderr before exiting 2. At this point: no precompact-flush-log entry has been
appended and no push has been attempted. `git commit` is a purely LOCAL operation —
network errors cannot originate here.

### AC-006 (traces to BC-7.07.001 postcondition 8 — SHA_B capture immediately after commit)
IMMEDIATELY after the local commit succeeds, the plugin captures
`SHA_B` via `exec_subprocess("git", &["-C", &wt, "rev-parse", "HEAD"])` (where `wt` is
the absolute worktree path from AC-017). This capture happens
BEFORE any append to the precompact-flush-log (BC-7.07.001 INV3 step 6: SHA_B capture
MUST precede the append attempt so SHA_B is available on append failure).

### AC-007 (traces to BC-7.07.001 postcondition 8 — precompact-flush-log append, newline-termination MANDATORY)
The plugin appends a 4-field log entry to `.factory/hooks/precompact-flush-log`
via host `read_file` + string concatenation + host `write_file` (read-modify-write;
NOT OS-atomic append — `write_file` calls `std::fs::write` which is a full overwrite).
The implementation reads existing log content via `read_file`, concatenates the new
`\n`-terminated 4-field line `<ISO-timestamp> <SHA_B> <cycle>/<step> commit\n`, and
writes the combined result back via `write_file`.
The appended line has the form `<ISO-timestamp> <SHA_B> <cycle>/<step> commit\n` where
the trailing `\n` is part of the string written. The append MUST produce a `\n`-terminated
line as the final byte of the file. Field-4 is the literal string `commit` (never a
variable). The file is created if absent (first write creates it). The implementation
uses host `write_file` — NOT `exec_subprocess("echo", ...)` or `exec_subprocess("printf", ...)`.
Single-writer guarantee: under normal factory operation (factory-lock held), only one
session performs PreCompact flushes (the `precompact-flush` plugin) and one session
performs pruning (the `precompact-flush-prune.sh` invoked by `check-state-health`). The
dispatcher processes hooks synchronously within a plugin tier, preventing concurrent
`precompact-flush` invocations in the same session. A theoretical race between
`precompact-flush` and `precompact-flush-prune.sh` across concurrent sessions could lose
a log entry, but the factory-lock mechanism serializes typical usage. The bounded
data-loss window is acceptable: the flush COMMIT to factory-artifacts is the durability
guarantee; the log is the secondary audit record. The next successful flush will append
its own entry.

### AC-008 (traces to BC-7.07.001 postcondition 8 — append failure SHA-pinned concurrent-commit guard)
If the log append FAILS (host `write_file` returns an error), the plugin compares
`exec_subprocess("git", &["-C", &wt, "rev-parse", "HEAD"])` (CURRENT_HEAD) to `SHA_B`
(where `wt` is the absolute worktree path from AC-017):
- If CURRENT_HEAD == SHA_B (no intervening commits): run
  `exec_subprocess("git", &["-C", &wt, "reset", "--soft", &format!("{}^", sha_b)])` to
  undo the local commit (SHA-PINNED to `SHA_B^`, NOT `HEAD~1`), then exit 2 (block
  compaction). Write diagnostic: `precompact-flush: SHA append to precompact-flush-log failed; orphan commit reverted (SHA_B=<sha>); blocking compaction`.
- If CURRENT_HEAD != SHA_B (intervening commits existed): exit 2 immediately with
  message: `precompact-flush: append failed; concurrent commit advanced HEAD; SHA_B=<sha_b>; current HEAD=<current_head>; human intervention required`.
  Do NOT reset (SOUL.md Rule 4: no silent data loss).
- If the reset itself fails (step 3a reset exits non-zero): exit 2; human intervention
  required.

### AC-009 (traces to BC-7.07.001 postcondition 6b — push failure exit 2; postcondition 5 — push success exit 0)
If the log append SUCCEEDS, the plugin runs
`exec_subprocess("git", &["-C", &wt, "push", "origin", "factory-artifacts"])` (where
`wt` is the absolute worktree path from AC-017) on the factory-artifacts worktree.
- If push fails: exit 2 with message `precompact-flush: git push failed; local commit <SHA_B> and log entry intact; retry is push-only`. Compaction is blocked. Local commit and log entry are retained (NOT rolled back).
- If push succeeds: exit 0.

### AC-010 (traces to BC-7.07.001 invariant 6 — plugin error hardening)
The plugin uses idiomatic Rust error propagation (`Result<T, E>`) throughout. All
fallible operations return `Result` and propagate errors via the `?` operator. No
`unwrap()` or `expect()` in non-test code paths. Panics are treated as crashes
triggering `on_error = "continue"` fail-open behavior (BC-7.07.001 PC9 / INV6).
`set -euo pipefail` does NOT apply (this is a Rust binary, not a shell script).

### AC-011 (traces to BC-7.07.001 invariant 3 — canonical execution order)
The canonical execution order is strictly (per BC-7.07.001 INV3 — no step may be
reordered):
1. Discover factory-artifacts worktree path via `git worktree list --porcelain` (AC-017) — fail-open if not found
2. Read STATE.md via host `read_file` — extract `current_cycle:` + `current_step:` fields (PC1)
3. Check `factory_lock:` block — skip step 3 if absent/null (PC3)
4. If lock held: call `crates/factory-lock::renew_lock()` (native Rust; no bash exec; updates `expires_at = now + 2700s`; preserves `holder` and `locked_at`; renewal failure is non-fatal — emit advisory warning, proceed to step 5)
5. `exec_subprocess("git", &["add", "-u"])` — stage tracked changes (PC4)
6. `exec_subprocess("git", &["commit", "-m", msg])` (LOCAL — no network); exit 2 immediately on commit failure (PC6 / AC-005b)
7. `SHA_B = exec_subprocess("git", &["rev-parse", "HEAD"])` — IMMEDIATELY after commit, BEFORE append (PC8)
8. Append 4-field line to precompact-flush-log via host write_file — MUST be `\n`-terminated (PC8)
9. If append fails: compare CURRENT_HEAD to SHA_B → if equal: `git reset --soft SHA_B^` (SHA-PINNED) then exit 2; if not equal: exit 2 with human-intervention message (do NOT reset) (PC8)
10. If append succeeds: `exec_subprocess("git", &["push", "origin", "factory-artifacts"])` (NETWORK) (PC6b)
11. If push fails: exit 2 with diagnostic; local commit + log entry retained; retry is push-only (PC6b)
12. If push succeeds: exit 0 (PC5)

Note: steps are numbered 1–12 here to reflect the addition of step 1 (worktree
discovery per ADR-028 §Decision 1). BC-7.07.001 INV3 labels them 1–11 with discovery
implicit in "read STATE.md". No behavioral reordering.

### AC-012 (traces to BC-7.07.001 invariant 7 — log pruning deferred; append-only in v1)
The precompact-flush-log is append-only. The plugin NEVER truncates or rewrites
the log. Log pruning (prune to most-recent-500 entries when count >1000) is
explicitly deferred to `precompact-flush-prune.sh` (S-18.04b, invoked by
check-state-health, NOT by this plugin per BC-7.07.001 INV7).

### AC-013 (traces to BC-7.07.001 postcondition 3 + invariant 4 — lock renewal failure is advisory; native path)
If `crates/factory-lock::renew_lock()` returns an error during lock renewal (AC-003)
— malformed frontmatter, parse failure, or write failure — the plugin writes an
advisory warning to stderr and proceeds with the flush commit anyway. Lock renewal
failure does NOT cause exit 2 and does NOT block compaction. This is the "advisory"
semantics per BC-7.07.001 PC3 and EC-004. No bash subprocess is involved in renewal.

### AC-014 (traces to BC-7.07.001 invariant 1 — hermetic; VP-085)
The plugin is hermetic: it interacts with the outside world ONLY via:
- Host `read_file` / `write_file` (path_allow = [".factory/"])
- `exec_subprocess("git", ...)` (binary_allow = ["git"] only)
No `curl`, no `jq`, no `python`, no `bash`, no `node`, no `npm`, no external network
calls except `git push` (via exec_subprocess). The plugin does NOT read from
`custom_instructions`, environment variables set by the LLM, or any in-context mechanism.

### AC-015 (traces to BC-7.07.001 invariant 3 step 7 — canonical log path)
The precompact-flush-log path is `.factory/hooks/precompact-flush-log` (no `.log`
extension, no `.txt` extension — exact path per BC-7.07.001 Architecture Anchors and
INV3 step 7).

### AC-016 (traces to BC-7.07.001 invariant 7 — log pruning deferred to S-18.04b)
Log pruning is NOT performed by this plugin. The plugin MUST NOT contain any pruning
logic. Pruning is exclusively handled by `precompact-flush-prune.sh` (S-18.04b),
invoked by `check-state-health` only (never by the precompact-flush plugin itself).

### AC-017 (traces to ADR-028 §Decision 1 — runtime worktree discovery via git worktree list)
The native WASM plugin discovers the factory-artifacts worktree mount path at runtime
by executing `exec_subprocess("git", &["worktree", "list", "--porcelain"])` and parsing
the stanza whose `branch` line is `refs/heads/factory-artifacts`. The `worktree` line
of that stanza is the absolute path used for all subsequent factory-artifacts filesystem
operations (STATE.md read, log append, git commands).

If no stanza with `branch refs/heads/factory-artifacts` is found in the output, the
plugin exits 0 with advisory warning:
`precompact-flush: factory-artifacts worktree not found via git worktree list; flush skipped.`
This is consistent with BC-7.07.001 PC7 fail-open semantics (a missing worktree is an
equally unrecoverable startup condition). No hard-coded `.factory` path assumption.

### AC-018 (traces to ADR-028 §Decision 2 + BC-7.07.001 PC3 — native lock renewal; no bash subprocess)
The plugin renews `factory_lock.expires_at = now + 2700s` natively in Rust via
`crates/factory-lock::renew_lock(&factory_artifacts_path)`. The `binary_allow` registry
stanza contains only `["git"]` — no `exec_subprocess("bash", ...)` call is ever made
for lock renewal. The renewal function reads STATE.md, parses the YAML frontmatter
`factory_lock:` block (frontmatter-boundary-aware: modifies only inside the first
`---`/`---` fence, preserving body lines unchanged), updates `expires_at`, and writes
STATE.md back via host `write_file`. The TTL constant is `2700s` (non-configurable
per BC-5.40.001 Invariant 2). The `holder` and `locked_at` fields are preserved
unchanged. Renewal is non-fatal (fail-open per EC-004 and BC-7.07.001 PC3).

**`expires_at` format contract (F-NW-008):** `expires_at` MUST be output in EXACTLY
`YYYY-MM-DDTHH:MM:SSZ` format: UTC, second precision, uppercase `Z` suffix. Use
`chrono::Utc::now().format("%Y-%m-%dT%H:%M:%SZ").to_string()` — NOT `to_rfc3339()`
(which emits `+00:00` and may include sub-seconds). This matches `factory-lock-write.sh`
(which uses `date -u +%Y-%m-%dT%H:%M:%SZ`) and BC-5.40.001 §Invariant 2. Any deviation
from the `Z`-suffix form or inclusion of sub-seconds is a spec violation and a failing
Red Gate test.

**`renew_lock()` error semantics and caller-downgrade (F-NW-004/005):**
`crates/factory-lock::renew_lock()` returns:
- `Ok(None)` — factory_lock absent, null, or empty block, or no frontmatter in STATE.md
  → skip renewal (no-op, proceed to git add). No advisory warning.
- `Ok(Some(...))` (or `Ok(RenewOutcome::Renewed(...))`) — valid lock, all fields present
  → update `expires_at`, write back, proceed to git add.
- `Err(LockError::Malformed)` — block present but malformed (missing field, empty field,
  missing closing fence) → the library returns `Err` (preserving bash semantic faithfulness
  at the library layer; library does NOT swallow the error or return `Ok(None)` for
  malformed blocks). The `precompact-flush` hook CALLER is the authoritative fail-open
  policy point: it downgrades `Err` to an advisory warning to stderr and proceeds with
  the flush commit. Future callers requiring fatal semantics may treat `Err` as fatal.

**CRLF normalization and file mode (F-NW-009):** `renew_lock()` outputs LF-only line
endings. CRLF normalization is performed internally by `parse_factory_lock()` (which
calls `content.replace("\r\n", "\n")`) before rewriting; any CRLF in the input STATE.md
is normalized to LF in the output. File mode is NOT preserved — host `write_file`
(which calls `std::fs::write`) creates/overwrites with platform umask defaults; there
is no `chmod` step. This is an accepted behavioral delta from the bash script for
STATE.md in git (git does not track mode for non-executable files).

## Forbidden Dependencies

`crates/hook-plugins/precompact-flush` MUST NOT:
- Invoke `bash` (or any shell interpreter) via `exec_subprocess` — `binary_allow = ["git"]` ONLY
- Use `shell_bypass_acknowledged` in the registry stanza
- Call `precompact-flush-prune.sh` (log pruning is exclusively S-18.04b's responsibility per BC-7.07.001 INV7)
- Use `curl`, `jq`, `python`, `node`, `npm`, or any non-standard binary via exec_subprocess
- Use `unwrap()` or `expect()` in non-test code paths
- Hard-code `.factory` as the worktree path (must use runtime discovery per ADR-028 §Decision 1)
- Add AI attribution to commit messages
- Use `--no-verify` git flags

`crates/factory-lock` MUST NOT:
- Depend on `crates/hook-plugins/precompact-flush` (dependency is unidirectional: plugin → factory-lock)
- Import `crates/factory-lock-parse` in a way that creates a cycle (factory-lock → factory-lock-parse; never the reverse)
- Produce a `[[bin]]` target or a WASM output (it is a pure library crate — no `[[bin]]`)

## Previous Story Intelligence

S-17.04 (mid-burst heartbeat renewal) shipped `verify-state-timestamp-refresh.wasm`
as a PostToolUse gate and established `crates/factory-lock-parse` as the authoritative
parse-only crate for STATE.md lock fields. Key lesson: the factory-artifacts worktree
is mounted at a path that may differ from the main repo CWD. Native WASM plugins must
discover this path at runtime rather than assuming a conventional location — ADR-028
§Decision 1 formalizes this as `git worktree list --porcelain` discovery.

`crates/factory-lock-parse` exists (S-17.04 dependency); this story's
`crates/factory-lock` SHOULD depend on it for the parse half of `renew_lock()`,
avoiding duplicate YAML frontmatter parsing logic. The new crate is write-capable
(CRUD); `factory-lock-parse` remains read-only.

## Architecture Compliance Rules

- Crate `crates/hook-plugins/precompact-flush` MUST have `crate-type = ["cdylib", "rlib"]` in its `[lib]` section AND a `[[bin]]` section pointing to `src/main.rs` (the vsdd-hook-sdk trampoline)
- Commit message MUST begin with exact string `PreCompact flush ` (case-sensitive, single space between words, trailing space) — this prefix is the exemption key used by validate-burst-log and validate-dispatch-advance (BC-5.41.003 INV3)
- All fallible function bodies in non-test code MUST use `Result<T, E>` and `?` — no `unwrap()` or `expect()` (BC-7.07.001 INV6; CLAUDE.md error taxonomy rule)
- `binary_allow = ["git"]` is the ONLY entry in the capabilities block — no `"bash"`, no `shell_bypass_acknowledged` (ADR-028 §Decision 2; binding constraint from human direction)
- `crates/factory-lock` MUST NOT have a `[[bin]]` section (pure library; does not inflate the CI WASM floor count per ADR-028 §Consequences)
- Dependency must be unidirectional: `crates/hook-plugins/precompact-flush` → `crates/factory-lock` → `crates/factory-lock-parse`; no cycles
- No `--no-verify` git flags anywhere in the plugin (CLAUDE.md absolute prohibition)
- Plugin MUST NOT add AI attribution to commit messages (CLAUDE.md explicit directive for vsdd-factory)
- host `write_file` (not exec_subprocess echo/printf) MUST be used for log append — the trailing `\n` must be embedded in the Rust string literal, not produced by a shell command
