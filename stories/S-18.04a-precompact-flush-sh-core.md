# S-18.04a — precompact-flush.sh Core

## Narrative

As the factory-dispatcher runtime receiving a PreCompact event,
I want a `precompact-flush.sh` shell hook that commits STATE.md to the
factory-artifacts branch BEFORE compaction proceeds,
so that context-window transitions do not lose uncommitted pipeline state,
and the precompact-flush-log provides an auditable record of every pre-compaction
commit with SHA, timestamp, cycle, and step.

## Behavioral Contracts

| BC ID | Title | Version | PCs Exercised |
|-------|-------|---------|---------------|
| BC-7.07.001 | precompact-flush.sh commits STATE.md to factory-artifacts before compaction | v1.12 | PC1–PC8, INV1–INV7 |

## Acceptance Criteria

### AC-001 (traces to BC-7.07.001 postcondition 1)
`precompact-flush.sh` is registered in `hooks-registry.toml` via
`legacy-bash-adapter.wasm` with:
- `event = "PreCompact"`
- `priority = 100`
- `timeout_ms = 30000`
- `on_error = "continue"`
- `[hooks.config] script_path = "hooks/precompact-flush.sh"`

### AC-002 (traces to BC-7.07.001 postcondition 2)
On invocation, the script reads `STATE.md` from the factory-artifacts worktree.
If STATE.md is absent, the script exits 0 (no-op — nothing to flush).

### AC-003 (traces to BC-7.07.001 postcondition 3)
The script checks the `factory_lock` field in STATE.md. If a lock is held
(factory_lock_holder is non-null and non-empty), the script invokes
`factory-lock-write.sh` to renew the lock BEFORE proceeding to commit.

### AC-004 (traces to BC-7.07.001 postcondition 4)
The script stages STATE.md via `git add` in the factory-artifacts worktree.

### AC-005 (traces to BC-7.07.001 postcondition 5)
The script creates a LOCAL commit (does not push yet) with commit message
`PreCompact flush <ISO-timestamp> <cycle>/<step>`. The commit message uses
EXACT prefix `PreCompact flush ` (capital P, capital C, one space before flush,
one space after flush — case-sensitive per BC-5.41.003 INV3).

### AC-006 (traces to BC-7.07.001 postcondition 6)
IMMEDIATELY after the local commit, the script captures
`SHA_B=$(git rev-parse HEAD)`. This capture happens BEFORE any append to the
precompact-flush-log.

### AC-007 (traces to BC-7.07.001 postcondition 7 — newline-termination MANDATORY)
The script appends a 4-field log entry to `.factory/hooks/precompact-flush-log`
using `echo "<ISO-timestamp> <SHA_B> <cycle>/<step> commit" >> <log>` OR
`printf "%s\n" "<ISO-timestamp> <SHA_B> <cycle>/<step> commit" >> <log>`.
The append MUST produce a `\n`-terminated line. Using `printf "%s"` (without `\n`)
is FORBIDDEN. Field-4 is the literal string `commit` (never a variable).

### AC-008 (traces to BC-7.07.001 postcondition 8a — append failure SHA-match)
If the log append FAILS (non-zero exit from the append command), the script
compares `git rev-parse HEAD` to `SHA_B`:
- If CURRENT_HEAD == SHA_B (no intervening commits): run `git reset --soft SHA_B^`
  to undo the local commit, then exit 2 (block compaction).
- If CURRENT_HEAD != SHA_B (intervening commits existed): exit 2 with message
  "PreCompact flush: append failed and HEAD has diverged — manual intervention
  required. Do NOT retry automatically."

### AC-009 (traces to BC-7.07.001 postcondition 8b — push and success path)
If the log append SUCCEEDS, the script runs `git push` on the factory-artifacts
worktree.
- If push fails: exit 2 with message "PreCompact flush: push failed — retry with
  git push from factory-artifacts worktree. Compaction is blocked."
- If push succeeds: exit 0.

### AC-010 (traces to BC-7.07.001 invariant 1)
The script uses `set -euo pipefail` as its first non-comment line.

### AC-011 (traces to BC-7.07.001 invariant 2)
The canonical execution order is strictly:
1. Read STATE.md
2. Check factory_lock
3. If lock held: renew via factory-lock-write.sh
4. `git add STATE.md`
5. `git commit` (LOCAL)
6. `SHA_B=$(git rev-parse HEAD)` — IMMEDIATELY after commit, before any append
7. Append 4-field line to precompact-flush-log (MUST be `\n`-terminated)
8. If append fails: SHA-comparison branch (AC-008)
9. If append succeeds: `git push`
10. If push fails: exit 2 with retry message
11. If push succeeds: exit 0

### AC-012 (traces to BC-7.07.001 invariant 3)
The precompact-flush-log is append-only. The script NEVER truncates or rewrites
the log. Log pruning is explicitly deferred to `precompact-flush-prune.sh`
(S-18.04b, invoked by check-state-health, NOT by this script).

### AC-013 (traces to BC-7.07.001 invariant 4)
If `factory-lock-write.sh` is unavailable or exits non-zero during lock renewal
(AC-003), the script exits 2 (block compaction) rather than proceeding with a
stale or unrenewed lock.

### AC-014 (traces to BC-7.07.001 invariant 5 — VP-085 hermetic)
The script is hermetic: it depends ONLY on:
- `git` (standard PATH)
- `date` (standard PATH)
- `factory-lock-write.sh` (co-located in hooks directory)
- The factory-artifacts worktree mount (path from environment variable
  `FACTORY_ARTIFACTS_PATH` or conventional `.factory` relative path)
No curl, no jq, no python, no npm, no external network calls except `git push`.

### AC-015 (traces to BC-7.07.001 invariant 6)
The precompact-flush-log path is `.factory/hooks/precompact-flush-log` (no
`.log` extension, no `.txt` extension — exact path as specified in BC-7.07.001).

### AC-016 (traces to BC-7.07.001 invariant 7)
Log pruning is NOT performed by this script. The script MUST NOT call any pruning
logic. Pruning is exclusively handled by `precompact-flush-prune.sh` (S-18.04b).

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | STATE.md absent in factory-artifacts worktree | No-op, exit 0 (AC-002) |
| EC-002 | factory_lock_holder is null | Skip lock renewal; proceed directly to git add |
| EC-003 | factory_lock_holder is non-empty string | Invoke factory-lock-write.sh; if it fails, exit 2 (AC-013) |

| EC-006 | Log append succeeds but git push fails | exit 2 with retry message (AC-009) |
| EC-007 | Log append succeeds, git push succeeds | exit 0 (AC-009) |
| EC-008 | Intervening commit between git commit and log append (race) | HEAD != SHA_B → no reset + human-intervention message + exit 2 (AC-008) |
| EC-009 | legacy-bash-adapter.wasm timeout (>30000ms) | on_error=continue → advisory; dispatcher does NOT block compaction |
| EC-010 | precompact-flush.sh invoked but harness version < v2.1.105 | Harness may not send PreCompact events at all; script not invoked (BC-1.15.001 INV3 at dispatcher level) |

## Forbidden Dependencies

`precompact-flush.sh` MUST NOT:
- Call `precompact-flush-prune.sh` (log pruning is exclusively S-18.04b's responsibility per BC-7.07.001 INV7)
- Use `curl`, `jq`, `python`, `node`, `npm`, or any non-standard tool
- Use `printf "%s"` for log append (must use `echo` or `printf "%s\n"`)
- Use `--no-verify` git flags
- Add AI attribution to commit messages

## Previous Story Intelligence

S-17.04 (mid-burst heartbeat renewal) shipped `verify-state-timestamp-refresh.wasm`
as a PostToolUse gate. Key lesson: the factory-artifacts worktree is mounted at a
path that may differ from the main repo CWD. Shell hooks must use explicit absolute
paths or the `FACTORY_ARTIFACTS_PATH` environment variable — never assume CWD.
`factory-lock-write.sh` already exists (S-17.04 dependency); this story depends on
its interface but does NOT modify it.

## Architecture Compliance Rules

- `set -euo pipefail` is the first non-comment, non-shebang line (CLAUDE.md convention)
- Commit message MUST begin with exact string `PreCompact flush ` (case-sensitive, single space between words) — this prefix is the exemption key used by validate-burst-log and validate-dispatch-advance (BC-5.41.003 INV3)
- `printf "%s"` (without `\n`) is FORBIDDEN for log append — VP-090 §0 structural precondition requires every entry to be a `\n`-terminated physical line
- No `--no-verify` git flags anywhere in the script (CLAUDE.md absolute prohibition)
- Script must NOT add AI attribution to commit messages (CLAUDE.md explicit directive for vsdd-factory)

## Library & Framework Requirements

- bash >= 4.x (available in CI)
- git (standard factory-artifacts discipline)
- `date` command: ISO-8601 format via `date -u +%Y-%m-%dT%H:%M:%SZ`
- bats-core: version already in use by `plugins/vsdd-factory/tests/`
- No new tool dependencies
