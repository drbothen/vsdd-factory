# S-17.04: Automatic Mid-Burst Heartbeat Renewal Wiring

**Epic:** E-17 — Factory State Durability and Concurrency (brownfield-backfill #170)
**Wave:** 4 (no product dependencies — `factory-lock-write.sh renew` is merged in S-17.01)
**Depends on:** none (S-17.01 delivered `factory-lock-write.sh renew` subcommand; already on develop)
**Blocks:** none
**Priority:** P1 (closes prose/executable gap for BC-5.40.001 PC4 enforcement)
**BC gate:** BC-5.40.001 v1.1 (active; PC4 is the unimplemented enforcement target)

## Narrative

- **As a** factory `state-manager` agent running a burst while a factory lock is held
- **I want** the `state-burst` SKILL to unconditionally call
  `factory-lock-write.sh renew .factory/STATE.md` immediately before staging the commit,
  AND a `verify-lock-renewal.sh` PreToolUse hook to block a `factory-artifacts` push
  when the lock was held but `expires_at` was not refreshed in this burst
- **So that** BC-5.40.001 PC4 (mid-burst TTL renewal) is enforced by a mechanically-
  invocable SKILL step and a push-boundary gate — not by agent memory of prose in
  `state-manager.md` — closing the gap where a correctly-structured burst could omit
  the renewal call and silently allow the 45-minute lease to self-evict mid-session

## Acceptance Criteria

### AC-001 (traces to BC-5.40.001 postcondition PC4 — mid-burst renewal: skill step invoked)

The `state-burst` SKILL (`plugins/vsdd-factory/skills/state-burst/SKILL.md`) MUST
contain a mandatory numbered step immediately before the `git -C .factory add -A` /
`git -C .factory commit` block with the exact invocation:

```
bash plugins/vsdd-factory/bin/factory-lock-write.sh renew .factory/STATE.md
```

The step MUST be annotated: "No-op when factory is unlocked (absent `factory_lock:`
key) — exits 0 with 'no factory_lock block present — renew is a no-op'. Safe to
call unconditionally."

An anti-pattern row MUST be added to the SKILL's "Anti-patterns this skill blocks"
table:

| Anti-pattern | Detection | Recovery |
|---|---|---|
| Skipping renew before `git add` while lock is held | `verify-lock-renewal.sh` gate blocks the subsequent push (exit 2, RenewalMissed) | Run `bash plugins/vsdd-factory/bin/factory-lock-write.sh renew .factory/STATE.md`; then `git -C .factory add STATE.md && git -C .factory commit --amend --no-edit`; then retry the push |

**Test (bats):** `test_state_burst_skill_contains_renew_step()`
— Asserts: `grep -c 'factory-lock-write.sh renew' plugins/vsdd-factory/skills/state-burst/SKILL.md` outputs `>= 1`

### AC-002 (traces to BC-5.40.001 postcondition PC4 — renewal gate: blocks push when renewal not committed)

The hook `verify-lock-renewal.sh` MUST be registered and operational. When ALL of
the following conditions are true:
1. The Bash command matches the pattern `git.*push.*factory-artifacts` (the push is
   targeting the `factory-artifacts` branch)
2. `git -C .factory show HEAD:STATE.md` contains a `factory_lock.holder` value
   (lock is held in the committed HEAD)
3. `origin/factory-artifacts` exists (a remote baseline is available)
4. `factory_lock.expires_at` in HEAD equals `factory_lock.expires_at` in
   `origin/factory-artifacts:STATE.md` (the renewal was NOT committed in this burst)

...the gate MUST return exit code 2 (block) with the following message:

```
RenewalMissed — factory_lock is held but expires_at was not refreshed in this burst.
Run: factory-lock-write.sh renew .factory/STATE.md
Then: git -C .factory add STATE.md && git -C .factory commit --amend --no-edit
Then retry the push.
```

**Error variant:** `RenewalMissed`
**Test (bats):** `test_verify_lock_renewal_blocks_when_lock_held_and_expires_at_unchanged()`

### AC-003 (traces to BC-5.40.001 postcondition PC4 — renewal gate: passes when renewal was committed)

When the lock is held in HEAD AND `factory_lock.expires_at` in HEAD differs from
`factory_lock.expires_at` in `origin/factory-artifacts:STATE.md` (the renewal WAS
committed in this burst), the gate MUST return exit 0 (Continue).

**Test (bats):** `test_verify_lock_renewal_passes_when_expires_at_refreshed()`

### AC-004 (traces to BC-5.40.001 postcondition PC6 — single-dev zero friction: Continue when unlocked)

When `factory_lock.holder` is absent from HEAD's STATE.md (factory is unlocked),
the gate MUST return exit 0 (Continue) immediately without reading
`origin/factory-artifacts`. The unlocked path MUST NOT block factory-artifacts pushes
or add observable latency beyond the initial `git show HEAD:STATE.md` read.

**Test (bats):** `test_verify_lock_renewal_continues_when_no_lock_held()`

### AC-005 (traces to BC-5.40.001 postcondition PC6 — single-dev zero friction: Continue when no remote baseline)

When `origin/factory-artifacts` does not exist (first push to a new branch, or a fresh
clone without the remote ref), the gate MUST return exit 0 (Continue). There is no
remote `expires_at` to compare against; blocking would wedge a new-repo setup.

**Test (bats):** `test_verify_lock_renewal_continues_when_no_remote_baseline()`

### AC-006 (traces to BC-5.40.001 postcondition PC6 — single-dev zero friction: Continue on non-push Bash)

When the Bash command does NOT match `git.*push.*factory-artifacts` (e.g., a `git
commit`, `git add`, `git fetch`, or any non-push command), the gate MUST return exit 0
(Continue) immediately after the pattern check. The gate adds zero overhead to the
99% of Bash tool calls that are not factory-artifacts pushes.

**Test (bats):** `test_verify_lock_renewal_continues_on_non_push_bash()`

### AC-007 (traces to BC-5.40.001 postcondition PC4 + ADR-025 Decision 11 Mechanism 1 — state-burst renew actually refreshes expires_at)

When a lock is held in STATE.md and the state-burst renew step
(`factory-lock-write.sh renew .factory/STATE.md`) is executed as part of a burst
commit, the committed STATE.md MUST have `factory_lock.expires_at` set to a value
that is strictly greater than the pre-renew `expires_at` (the TTL clock was reset to
`now + 2700s`). The `factory_lock.locked_at` and `factory_lock.holder` fields MUST
remain unchanged (BC-5.40.001 Invariant 3).

When no lock is held (absent `factory_lock:` key), the renew call MUST be a no-op:
`factory-lock-write.sh renew` exits 0 with "no factory_lock block present — renew is
a no-op" and STATE.md is unchanged.

**Tests (bats):**
- `test_state_burst_renew_step_refreshes_expires_at_when_lock_held()`
- `test_state_burst_renew_step_noop_when_no_lock()`

## Architecture Compliance Rules

The following rules are extracted from ADR-025 v1.4 Decision 11 and must be enforced
by both implementer and adversarial review:

1. **PreToolUse, NOT PostToolUse (ADR-025 Decision 11 / ADR-019):** The hook MUST be
   registered as `event = "PreToolUse"`. PostToolUse fires AFTER the push has executed —
   it can log but cannot block. Only PreToolUse can prevent the push.

2. **`async = false` is a correctness requirement (ADR-025 Decision 11 / ADR-019):**
   Only sync-group plugins participate in `block_intent` aggregation at
   `executor.rs:100–117`. An `async = true` plugin's block signal is advisory-only.
   For `verify-lock-renewal`, blocking is the entire purpose: `async = false` is
   mandatory, not a performance preference. CI lint invariant: `on_error=continue ⇒`
   `async=false` is allowed (it's `on_error=block` that mandates `async=false` per
   ADR-019). Both `async=false` entries below use `on_error=continue`.

3. **`on_error = "continue"` (ADR-025 Decision 11 / Decision 7):** Consistent with
   the efficiency-class lock model (Kleppmann §8). A broken gate that permanently
   blocks all pushes is a worse failure mode than a missed renewal (bounded by the
   45-minute TTL). Fail-open on crash; crash surfaces via `internal.dispatcher_error`
   (SS-03). Do NOT change to `on_error = "block"`.

4. **Read-only gate (ADR-025 Decision 11):** The hook reads STATE.md via `git show`
   (git object read — no write). It does NOT write STATE.md, does NOT call
   `factory-lock-write.sh renew`, and does NOT modify any file. The hook is a gate,
   not a fixer. If the renewal was missed, the gate blocks and tells the agent how
   to fix it; the agent (not the gate) then runs the renew command.

5. **Reuse, do not re-implement `factory-lock-write.sh` (ADR-025 Decision 11):**
   The renew script already exists and is correct. D10 calls it; D11 does NOT
   re-implement its logic. The gate compares `expires_at` strings; the renewal is
   the caller's job.

6. **`git show HEAD:STATE.md` path (ADR-025 Decision 11):** At PreToolUse time for
   a push command, the `git commit` has ALREADY run (the burst commits before pushing).
   Therefore `HEAD:STATE.md` reflects the post-renew state if Mechanism 1 was followed.
   This is the correct comparison point: HEAD reflects the burst's committed content.

### Registry Entry Spec (D12 — canonical TOML)

The registry entry for `verify-lock-renewal` MUST exactly match:

```toml
# ---------- verify-lock-renewal (PreToolUse, Bash) ----------
# S-17.04: PreToolUse gate — blocks factory-artifacts push when lock is held but
# expires_at was NOT refreshed in this burst (RenewalMissed, BC-5.40.001 PC4).
# Filters on git.*push.*factory-artifacts pattern; non-push Bash returns Continue
# immediately (AC-006). No-op when unlocked or no origin/factory-artifacts baseline.
# async = false REQUIRED — see ADR-019 + ADR-025 Decision 11

[[hooks]]
name = "verify-lock-renewal"
event = "PreToolUse"
tool = "Bash"
plugin = "hook-plugins/legacy-bash-adapter.wasm"
priority = 141
timeout_ms = 5000
on_error = "continue"
async = false

[hooks.config]
script_path = "hooks/verify-lock-renewal.sh"

[hooks.capabilities]
env_allow = ["PATH", "HOME", "TMPDIR", "CLAUDE_PROJECT_DIR", "CLAUDE_PLUGIN_ROOT"]

[hooks.capabilities.exec_subprocess]
binary_allow = ["bash", "git", "jq"]
shell_bypass_acknowledged = "legacy-bash-adapter runs unported hooks"
env_allow = ["PATH", "HOME", "TMPDIR", "CLAUDE_PROJECT_DIR", "CLAUDE_PLUGIN_ROOT"]
```

**Priority = 141:** Placed after `verify-git-push` (priority 140) — both fire on
factory-artifacts pushes; the force-push guard runs first, then the renewal gate.
This ordering ensures that a raw `--force` push is blocked by verify-git-push before
verify-lock-renewal even evaluates the renewal state.

**`async = false` annotation:** The `async = false` field MUST be present explicitly
(it does not default correctly for all dispatcher versions — explicit is correct).

This is intentionally conservative: any push to factory-artifacts (regardless of remote name) requires a renewal check. |
| EC-004 | `git show HEAD:STATE.md` fails (e.g., HEAD is detached and no STATE.md) | `git show` returns non-zero; awk receives no input; `HEAD_EXPIRES` is empty string; `factory_lock.holder` check returns empty → treated as "no lock held" → exit 0 (Continue). Fail-open. |
| EC-005 | `factory_lock.expires_at` is present in HEAD but `origin/factory-artifacts:STATE.md` contains a malformed frontmatter where `expires_at` is absent | `REMOTE_EXPIRES` is empty string; `HEAD_EXPIRES != ""` → they differ → gate returns exit 0 (Continue). Conservative: if the remote is unreadable, don't block. |
| EC-006 | Two pushes in the same burst (e.g., a burst that commits and pushes twice) | Gate fires on each push. On the second push, if HEAD already carries the renewed `expires_at` from the first push's committed burst, the comparison `HEAD_EXPIRES != REMOTE_EXPIRES` is true (renewal was committed before this push) → exit 0. Correct. |
| EC-007 | `factory_lock.holder` is present but `factory_lock.expires_at` is absent (malformed lock block) | `HEAD_EXPIRES` is empty; `factory_lock.holder` check sees non-empty holder. Per EC-002 above: awk returns empty = treat as "expired/absent" → exit 0. Note: `factory-lock-write.sh` prevents writing a lock without all three fields (PC1 SchemaViolation); this case indicates manual STATE.md corruption. Fail-open is correct. |

## Demo Plan

Demonstrable against a git bare-repo fixture (same pattern as `factory-lock-write.bats`):

1. **AC-002 (block path):** Create fixture with: (a) `origin/factory-artifacts` having
   `expires_at: "2026-06-11T10:00:00Z"` in STATE.md; (b) a local HEAD commit with the
   SAME `expires_at` value (renewal NOT committed). Invoke gate with `git push origin
   factory-artifacts` command JSON. Assert: gate exits 2 and stdout contains
   "RenewalMissed".

2. **AC-003 (pass path):** Same fixture but modify HEAD commit to have `expires_at:
   "2026-06-11T10:45:00Z"` (renewal WAS committed, differs from remote). Invoke gate.
   Assert: exits 0.

3. **AC-004 (no lock — pass):** Fixture with HEAD STATE.md that has NO `factory_lock:`
   key. Invoke gate with push command. Assert: exits 0.

4. **AC-006 (non-push — pass):** Invoke gate with `git commit -m "test"` command JSON.
   Assert: exits 0 immediately.

5. **AC-001 (SKILL grep):** `grep -c 'factory-lock-write.sh renew'
   plugins/vsdd-factory/skills/state-burst/SKILL.md` → count `>= 1`.

6. **AC-007 (renew refreshes expires_at):** Create STATE.md with a `factory_lock` block
   whose `expires_at` is `2026-01-01T00:00:00Z` (stale). Run `bash

   `expires_at` is greater than `2026-01-01T00:00:00Z` and `locked_at` is unchanged.
