# S-18.07: E-18 Terminology Disambiguation Docs — compact-state vs PreCompact Flush Cross-References

**Epic:** E-18 — Factory Context Durability (feature #173)
**Wave:** 6 (depends on S-18.03/04a/04b/05 to have the full E-18 artifact set available for cross-reference)
**Depends on:** S-18.03, S-18.04a, S-18.04b, S-18.05
**Blocks:** S-18.08
**Priority:** P2 (documentation; enables S-18.08 gate to scan for terminology inconsistencies)
**BC gate:** N/A — doc-only story (`tdd_mode: facade`; `behavioral_contracts: []`)
**Subsystem anchor:** SS-06 owns this story's full scope per ARCH-INDEX Subsystem Registry. SS-06 is the Skill Catalog; `compact-state/SKILL.md` and `check-state-health/SKILL.md` are skill deliverables under `plugins/vsdd-factory/skills/`. The CLAUDE.md §Conventions callout cross-referencing E-18 skill behavior is also attributed to SS-06 as the functional owner of those operator-facing skill instructions.

## Narrative

- **As a** factory agent or human operator reading E-18 skills after the context-durability feature ships
- **I want** the `compact-state/SKILL.md` and `check-state-health/SKILL.md` documentation to include clear disambiguation callouts that distinguish `/compact-state` (the skill that invokes the Claude Code `/compact` command) from the `PreCompact` hook event (the `precompact-flush.sh` + `postcompact-reanchor.sh` hook chain fired automatically by the harness), and to include cross-references to `rehydrate-wave` and the PostCompact re-anchor advisory hook
- **So that** operator confusion between manual `/compact-state` invocation and automatic PreCompact/PostCompact hook firing is eliminated, reducing incorrect operator actions that could bypass the E-18 context-durability guarantee chain

## Behavioral Contracts

This is a documentation-only story. There are no behavioral contracts. The deliverables are updates to two SKILL.md files and a CLAUDE.md callout.

## Acceptance Criteria

### AC-001 (traces to ADR-026 §Decision 7 / disambiguation requirement — compact-state SKILL.md callout)

`plugins/vsdd-factory/skills/compact-state/SKILL.md` MUST include a new "Terminology Note" section (or equivalent callout block) that:
1. Explicitly distinguishes `/compact-state` (this skill; invokes `/compact` command manually) from the `PreCompact` hook event (`precompact-flush.sh` fires automatically before Claude Code compacts).
2. States that invoking `/compact-state` does NOT fire the `PreCompact` hook chain — `precompact-flush.sh` fires only when the Claude Code harness triggers automatic compaction (e.g., `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=70` threshold).
3. Cross-references `/rehydrate-wave` as the mandatory first step after any session clear or context reset.

**Verification (review gate):** Read `plugins/vsdd-factory/skills/compact-state/SKILL.md` after this story is implemented and confirm all three points above are present in the "Terminology Note" section.

### AC-002 (traces to ADR-026 §Decision 7 + §Decision 4 — check-state-health SKILL.md cross-reference)

`plugins/vsdd-factory/skills/check-state-health/SKILL.md` MUST include a new or updated section that:
1. Cross-references the PostCompact re-anchor advisory hook (`plugins/vsdd-factory/hooks/postcompact-reanchor.sh` — S-18.05 deliverable) and explains that after automatic compaction, the hook emits a `[PostCompact Re-anchor]` block to stdout that operators should verify is visible in the session.
2. Adds a `check-state-health` step that instructs operators to confirm the re-anchor block appeared (or to run `/rehydrate-wave` if it did not) before resuming pipeline work.
3. Does NOT imply that `check-state-health` blocks or prevents compaction (it is advisory).

**Verification (review gate):** Read `plugins/vsdd-factory/skills/check-state-health/SKILL.md` and confirm all three points above are present.

### AC-003 (traces to CLAUDE.md §Conventions — compact-state vs PreCompact flush disambiguation callout in CLAUDE.md)

The project `CLAUDE.md` §Conventions section MUST include a callout that distinguishes:
- `/compact-state` skill: human/agent-initiated manual context compaction.
- `PreCompact` hook event: automatic Claude Code harness event triggering `precompact-flush.sh` before compaction.
- `PostCompact` hook event: automatic Claude Code harness event triggering `postcompact-reanchor.sh` after compaction.

The env-var verification behavior (`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=70`, BC-6.25.001) is owned by S-18.10, not S-18.00. This story's CLAUDE.md callout covers only the compact-state vs PreCompact/PostCompact terminology disambiguation — it does NOT claim to verify the autocompact threshold setting.

Before editing CLAUDE.md, the implementer MUST read the §Conventions section to check whether an equivalent disambiguation callout already exists (from any prior story). If equivalent content is already present, this AC is satisfied by a review gate confirming it is present; do NOT add a duplicate callout (POLICY 1 append-only).

**Verification (review gate):** Read `CLAUDE.md` §Conventions and confirm the three distinctions above are documented.

### AC-004 (traces to ADR-026 §Decision 4 + §Decision 7 — no behavioral changes; doc-only scope boundary)

This story MUST NOT modify any behavioral files (`.sh` hook scripts, `.wasm` binaries, `hooks-registry.toml` entry behaviors, Rust crate source). All changes MUST be limited to:
- `plugins/vsdd-factory/skills/compact-state/SKILL.md`
- `plugins/vsdd-factory/skills/check-state-health/SKILL.md`
- `CLAUDE.md` §Conventions (if equivalent disambiguation content not already present from a prior story; see AC-003)

Any PR for this story that modifies `.sh`, `.wasm`, `.rs`, or `.toml` files is a scope violation and MUST be rejected.

**Verification (review gate):** PR diff for this story shows ONLY `.md` file changes. A `git diff --name-only` over the PR must list only `SKILL.md` and/or `CLAUDE.md` files.

## Architecture Compliance Rules

1. **Doc-only scope (AC-004 absolute):** The implementer (or the technical-writer) MUST NOT modify any `.sh`, `.wasm`, `.rs`, `.toml`, or other executable/config files. The PR diff MUST show only `.md` changes.
2. **Read before Write (POLICY 1 / story-writer mandate):** Before editing each SKILL.md file, the implementer MUST Read the current file content to understand the existing structure and avoid duplicate sections.
3. **Accurate cross-references:** All cross-references to E-18 deliverables (rehydrate-wave, postcompact-reanchor.sh, wave-state.yaml) MUST describe the actual, as-delivered behavior — not aspirational descriptions. Read the delivered SKILL.md/script before writing the cross-reference.
4. **No stub content:** The terminology disambiguation content MUST be substantive. Placeholder text ("TODO: add disambiguation") is a specification violation per the production-grade default principle.
5. **No behavioral additions:** Adding a new `Step N: ...` to a SKILL.md that causes the skill to invoke additional tools or commands is a behavioral addition, not a documentation change. If the implementer believes a behavioral change is needed, the correct action is to escalate to the orchestrator, not to silently add a behavioral step under the guise of a documentation update.
