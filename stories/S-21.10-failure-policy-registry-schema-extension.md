# S-21.10: `failure_policy` dispatcher registry schema extension (ADR-039 Decision 1+2 schema leg — Phase 1, no enforcement change)

## Narrative

- **As a** factory pipeline operator and future S-21.11 implementer
- **I want** the dispatcher registry to parse a new per-plugin `failure_policy` TOML field
  (`"fail-closed"` or `"fail-open"`) independently of `on_error`, store it on `RegistryEntry`,
  and default to `fail-open` when the field is absent
- **So that** Phase 1 of ADR-039's safe migration ordering is complete with zero enforcement
  change, and S-21.11 (the enforcement flip) can build directly on the parsed field without
  needing a schema migration of its own

## Context / Finding Summary

Adversarial pass-7 of S-21.07 raised F-S2107-P7-010 (HIGH) and F-S2107-P7-011 (HIGH):
WASM validator plugins fail open on fuel exhaustion because `plugin_fail_closed` returns
`false` for `Timeout { cause: TimeoutCause::Fuel }` when `on_error = OnError::Continue`
(confirmed by the existing deliberate test `fail_closed_timeout_with_on_error_continue_is_open`
in the `executor` module). The enforcement defect is CWE-636 (primary) + CWE-390 (secondary).

ADR-039 (2026-08-06) rules that the correct fix is a new orthogonal `failure_policy` axis
(§Decision 1), not a resemanticization of `on_error`. The two axes govern distinct failure
classes:

| Field | Failure class | Live example |
|-------|---------------|--------------|
| `on_error` (existing) | Plugin crashes and host-side invocation errors | `Trap::UnreachableCodeReached`; ABI mismatch |
| `failure_policy` (NEW) | Resource exhaustion (`TimeoutCause::Fuel`, `TimeoutCause::Epoch`) | `Trap::OutOfFuel` |

ADR-039 §Decision 3 imposes a hard migration ordering: Phase 1 (schema extension, no
enforcement change) MUST ship before Phase 4 (the enforcement flip). This story delivers
Phase 1 only. Phase 3+4 are in S-21.11, which is blocked on this story.

**Self-lock hazard context (live today):** `lessons.md` already exhausts the fixed
10M fuel budget during PostToolUse validation (D-442(e)). Any premature enforcement flip
without calibrated per-plugin caps would hard-block all `.factory/` writes. Phase 1 is
safe to ship independently because it introduces no enforcement change.

## Acceptance Criteria

### AC-001: `failure_policy = "fail-closed"` parsed to `FailurePolicy::FailClosed` (traces to BC-1.01.016 PC1; ADR-039 §Decision 2 schema leg)

When a `[[hook]]` TOML stanza contains `failure_policy = "fail-closed"`, the registry
loader MUST parse it to the `FailurePolicy::FailClosed` variant of the new `FailurePolicy`
enum. The parsed value MUST be stored on the `RegistryEntry` struct's `failure_policy` field.

- **Test:** `test_registry_parses_failure_policy_fail_closed()` — TOML fixture with
  `failure_policy = "fail-closed"`; assert `entry.failure_policy == FailurePolicy::FailClosed`

### AC-002: `failure_policy = "fail-open"` parsed to `FailurePolicy::FailOpen` (traces to BC-1.01.016 PC2; ADR-039 §Decision 2 schema leg)

When a `[[hook]]` TOML stanza contains `failure_policy = "fail-open"`, the registry
loader MUST parse it to `FailurePolicy::FailOpen`.

- **Test:** `test_registry_parses_failure_policy_fail_open()` — TOML fixture with
  `failure_policy = "fail-open"`; assert `entry.failure_policy == FailurePolicy::FailOpen`

### AC-003: Unknown `failure_policy` values rejected at parse time (traces to BC-1.01.016 PC3; ADR-039 §Decision 2)

A `[[hook]]` TOML stanza with `failure_policy` set to any value other than `"fail-closed"`
or `"fail-open"` (e.g., `"shout"`, `"ignore"`) MUST cause `Registry::parse_str` to return
`Err`. The error MUST be produced by serde at parse time. Unknown values MUST NOT silently
default to any variant.

- **Test:** `test_registry_rejects_unknown_failure_policy()` — TOML fixture with
  `failure_policy = "unknown-value"`; assert `parse_str` returns `Err`

### AC-004: Absent `failure_policy` field defaults to `FailurePolicy::FailOpen` (traces to BC-1.01.016 PC4; ADR-039 §Decision 1 backward-compatibility clause)

When a `[[hook]]` TOML stanza does not contain a `failure_policy` field, the registry
loader MUST store `FailurePolicy::FailOpen` on the `RegistryEntry` as the default. This
ensures backward compatibility with the 52 existing plugin entries that do not carry the
field. The absence of the field MUST NOT cause a parse error.

- **Test:** `test_registry_absent_failure_policy_defaults_to_fail_open()` — TOML fixture
  with no `failure_policy` field (current production format); assert
  `entry.failure_policy == FailurePolicy::FailOpen`

### AC-005: `failure_policy` and `on_error` are stored as independent struct fields (traces to BC-1.01.016 PC5; ADR-039 §Decision 1 axes-separation requirement)

The `RegistryEntry` struct MUST have distinct fields for `on_error: Option<OnError>` and
`failure_policy: FailurePolicy`. These MUST NOT be collapsed into a single enum or
combined field. A plugin with `on_error = "continue"` AND `failure_policy = "fail-closed"`
MUST be representable in the struct simultaneously — the two fields are independent axes
governing distinct failure classes (plugin crash vs. resource exhaustion); setting one does
not constrain the other.

- **Test:** `test_registry_entry_can_hold_continue_and_fail_closed_simultaneously()` — construct
  a `RegistryEntry` with `on_error = Some(OnError::Continue)` and
  `failure_policy = FailurePolicy::FailClosed`; assert both fields hold their respective
  values without conflict

### AC-006: Phase 1 no-enforcement gate — `plugin_fail_closed` behavior UNCHANGED (traces to BC-1.01.016 PC7; ADR-039 §Decision 3 Phase 1 scope boundary)

The existing `plugin_fail_closed` function MUST NOT be modified by this story. The
existing test `fail_closed_timeout_with_on_error_continue_is_open` (in the `executor`
module) MUST pass unmodified after this story's changes land. This AC is a RED Gate: it
fails if `plugin_fail_closed` is extended to consult `failure_policy` before S-21.11.

Any change to `executor.rs` that alters `plugin_fail_closed` behavior for
`Timeout { cause: TimeoutCause::Fuel | TimeoutCause::Epoch }` outcomes is
out-of-scope for this story and MUST be deferred to S-21.11.

- **Test:** existing `fail_closed_timeout_with_on_error_continue_is_open` (must pass
  without modification); verified by `cargo test -p factory-dispatcher`

### AC-007: All production registry entries parse cleanly with `FailOpen` default (traces to BC-1.01.016 PC6; ADR-039 §Decision 1 backward-compat clause)

The full `plugins/vsdd-factory/hooks-registry.toml` file MUST parse successfully with no
errors after this story's changes. Every `[[hook]]` entry that does not carry a
`failure_policy` field (all 52 existing entries) MUST resolve to `FailurePolicy::FailOpen`.
No existing plugin MUST change its block/allow enforcement decision as a result of this
story's schema extension.

This AC is the load-bearing complement to AC-004 (which uses a test fixture). AC-007
drives the actual production `hooks-registry.toml` through the updated registry loader
to confirm the backward-compat default holds in practice, not just in a synthetic fixture.

- **Test:** `test_production_registry_all_entries_default_to_fail_open()` — loads the
  actual `plugins/vsdd-factory/hooks-registry.toml` from the test working directory;
  asserts all entries parse without error; asserts every entry has
  `failure_policy == FailurePolicy::FailOpen`; asserts zero entries received
  `FailurePolicy::FailClosed`
