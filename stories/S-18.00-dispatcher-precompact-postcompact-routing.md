# S-18.00 — Dispatcher PreCompact/PostCompact Routing + check-harness-version.sh

## Narrative

As a factory-dispatcher consuming agent (PreCompact/PostCompact event emitter),
I want the dispatcher to route PreCompact and PostCompact events to registered
plugins (with PreCompact supporting block-intent propagation via exit 2),
so that context-compaction hooks can commit STATE.md to factory-artifacts before
the harness compacts the context window.

## Behavioral Contracts

| BC ID | Title | Version | PCs Exercised |
|-------|-------|---------|---------------|
| BC-1.15.001 | Dispatcher routes PreCompact/PostCompact events to registered plugins | v1.5 | PC1, PC2, PC3, PC4, PC5, PC6, INV1, INV2, INV3 |

## Acceptance Criteria

### AC-001 (traces to BC-1.15.001 postcondition 1)
The dispatcher `invoke.rs` module handles `EventType::PreCompact` by iterating
registered plugins in priority order (descending), invoking each with the
standard invoke protocol (stdin/stdout/stderr, exit-code capture), and
accumulating results exactly as it does for PreToolUse.

### AC-002 (traces to BC-1.15.001 postcondition 2)
The dispatcher handles `EventType::PostCompact` by invoking registered plugins
and propagating exit codes in the response, but does NOT set `block_intent=true`
regardless of plugin exit code. PostCompact is advisory-only.

### AC-003 (traces to BC-1.15.001 postcondition 3)
When no plugins are registered for a PreCompact or PostCompact event, the
dispatcher returns an empty result with `block_intent=false` (no-op).

### AC-004 (traces to BC-1.15.001 postcondition 4)
When any PreCompact plugin exits with code 2, the dispatcher sets
`block_intent=true` in the aggregated response. A single exit-2 plugin is
sufficient to trigger block.

### AC-005 (traces to BC-1.15.001 postcondition 5)
On-error semantics for PreCompact match those for PreToolUse:
- Plugin with `on_error=continue` that crashes: advisory (no block)
- Plugin with `on_error=block` that crashes: block-intent=true propagated

### AC-006 (traces to BC-1.15.001 invariant 1)
`EventType` enum in `crates/factory-dispatcher/src/invoke.rs` and/or registry
module enumerates `PreCompact` and `PostCompact` as first-class variants
alongside `PreToolUse` and `PostToolUse`.

### AC-007 (traces to BC-1.15.001 invariant 2)
Async classification for PreCompact/PostCompact plugins follows the same rules
as for other event types: `async = true` in hooks-registry.toml schedules the
plugin asynchronously.

### AC-008 (traces to BC-1.15.001 invariant 3)
`check-harness-version.sh` is registered as a PreCompact plugin with
`on_error=continue`. The script exits 0 if the harness reports
`claude-code >= v2.1.105` (or equivalent), exits 1 (advisory) if harness
version cannot be determined or is below threshold. The dispatcher continues
even if check-harness-version.sh exits non-zero.

### AC-009 (traces to BC-1.15.001 postcondition 6)
Any change to the factory-dispatcher crate that modifies PreCompact/PostCompact
routing logic requires a release cut (a new rc tag) before operator-level hooks
pick up the change. Story ACs that verify routing behavior must pass on the
released binary, not only on local cargo builds.

## Previous Story Intelligence

S-17.04 (mid-burst heartbeat renewal wiring) shipped PreCompact-adjacent plumbing
(verify-state-timestamp-refresh.wasm). Key lesson: WASM fuel budgets are finite
and PreToolUse/PostToolUse are already handled symmetrically in invoke.rs. The
PreCompact/PostCompact routing in this story must follow the same invocation
protocol exactly — no special-casing except the advisory-only semantics for
PostCompact (PC2).

## Architecture Compliance Rules

- `EventType` must be a closed enum — no string matching at dispatch time (per ADR pattern in factory-dispatcher)
- All new event arms must handle the `timeout_ms` field from hooks-registry.toml (consistent with PreToolUse arm)
- `block_intent` must only be set to `true` on PreCompact (never PostCompact) per BC-1.15.001 PC2
- check-harness-version.sh must use `set -euo pipefail` (bash hook script convention per CLAUDE.md)
- Release requirement (BC-1.15.001 PC6): dispatcher source changes do not affect operator-level cache until a release is cut

- `cargo clippy --workspace --all-targets -- -D warnings` must pass
