# S-21.02 — post-rebase diff-integrity gate: detect and surface silent production-code drops before force-push-with-lease

**Epic:** E-21 — Factory State Data-Loss Hardening
**Wave:** 1 (no inter-E-21 dependencies; can begin immediately in parallel with S-21.01 and S-21.03)
**Depends on:** none
**Priority:** P1 (process-gap; silent production-code drops are high-impact but empirically rare — real silent drops require larger-hunk or moved-code diffs per BC-5.44.001 description)
**Subsystem anchor:** SS-05 (Pipeline Orchestration) owns the devops-engineer agent and the orchestrator per-story delivery playbook.

## Narrative

Issue #365 documents a confirmed process gap: git's ORT 3-way merge algorithm can silently drop production lines during a rebase when adjacent (non-overlapping) code regions on two branches collide in the merge base window. `git rebase --continue` reports success with no conflict markers, but lines added by the parent commit are absent from the rebased branch. The factory's per-story delivery protocol has no detection gate between "rebase clean" and `git push --force-with-lease`.

The canonical detection tool is `git range-diff` (git ≥ 2.19): it compares the pre-rebase and post-rebase commit sequences, flagging commits whose diff hunks changed during replay. BC-5.44.001 mandates a two-step gate:

1. **Primary detector — `git range-diff`:** Compare `<pre-rebase-tip>...<post-rebase-tip>` to detect commits that changed during replay. Any modified commit that touches a file also modified by a recently-merged sibling story requires explicit delta verification.

2. **Backup heuristic — `git diff origin/develop --stat`:** For each file with a net-negative line count, check whether a recently-merged sibling story also modified that file. If unverified net-negative delta is found, STOP with `UnverifiedNetNegativeDelta` before force-push.

This story is entirely skill-doc (no new WASM plugin or shell script). POLICY 21 satisfied.
