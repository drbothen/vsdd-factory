## Acceptance Criteria

### AC-001 (traces to BC-4.17.001 postcondition PC2 — renew_lock_if_holder 6-case decision tree)

`factory_lock::renew_lock_if_holder(content, resolve_identity, now_fn) -> Result<(RenewOutcome, Option<SkipReason>), LockError>`
MUST implement the following 6-case decision tree:

- **Case 0 (absent/fully-null block):** `factory_lock_parse::parse_factory_lock` returns
  `Ok(None)` → return `Ok((RenewOutcome::NoOp, None))` without calling `resolve_identity`.
- **Case 1 (malformed block):** `parse_factory_lock` returns `Err(MalformedLockBlock)` →
  return `Err(LockError::Malformed)` without calling `resolve_identity`.
- **Case 2 (already expired):** `parse_factory_lock` returns `Ok(Some(state))` and
  `now >= state.expires_at` → return `Ok((RenewOutcome::NoOp, Some(SkipReason::AlreadyExpired)))`
  without calling `resolve_identity`.
- **Case 3 (not holder):** identity resolution returns `IdentityResolution::Resolved(email)`
  and `email != state.holder` after `trim_git_email` → return
  `Ok((RenewOutcome::NoOp, Some(SkipReason::NotHolder)))`.
- **Case 4 (identity resolution failed):** identity resolution returns
  `IdentityResolution::Failed(reason)` → return
  `Ok((RenewOutcome::NoOp, Some(SkipReason::IdentityResolutionFailed { reason, holder: state.holder, locked_at: state.locked_at, expires_at: state.expires_at })))`.
- **Case 5 (success — identity match, not expired):** identity resolution returns
  `IdentityResolution::Resolved(email)` and `email == state.holder` (after `trim_git_email`)
  and `now < state.expires_at` → compute new content with `expires_at = now + TTL_SECONDS`,
  return `Ok((RenewOutcome::Renewed(new_content), None))`.

**Tests (Rust unit):** `test_renew_lock_if_holder_absent_block_no_op`,
`test_renew_lock_if_holder_malformed_no_resolve`,
`test_renew_lock_if_holder_already_expired_no_resolve`,
`test_renew_lock_if_holder_not_holder_no_renewal`,
`test_renew_lock_if_holder_identity_resolution_failed_no_renewal`,
`test_renew_lock_if_holder_identity_match_renewed`

### AC-002 (traces to BC-4.17.001 postcondition PC2 — lazy identity, called at most once)

`resolve_identity` MUST be invoked AT MOST ONCE per call to `renew_lock_if_holder`, and
MUST NOT be invoked for Cases 0, 1, or 2. It is invoked only when the lock is present,
valid, and not yet expired (entering identity resolution at Case 3/4/5 boundary).

**Test (Rust unit):** `test_resolve_identity_called_at_most_once`

### AC-003 (traces to BC-4.17.001 postcondition PC2 — SkipReason::IdentityResolutionFailed struct variant)

`SkipReason::IdentityResolutionFailed` MUST be a struct variant carrying exactly four fields:
`reason: String`, `holder: String`, `locked_at: String`, `expires_at: String`. All four
fields MUST be populated from the `LockState` that `renew_lock_if_holder` itself parsed —
not from caller-supplied data.

**Test (Rust unit):** `test_skip_reason_identity_resolution_failed_carries_four_fields`

### AC-004 (traces to BC-4.17.001 postcondition PC2 — classify_identity_resolution 4-shape rule)

`factory_lock::classify_identity_resolution(exec_result: Result<ExecOutput, HostError>) -> IdentityResolution`
MUST implement the following 4-shape mapping:

1. `Err(_)` → `IdentityResolution::Failed("exec error: ...")`
2. `Ok(output)` where `output.exit_code != 0` → `IdentityResolution::Failed("exit N: ...")`
3. `Ok(output)` where `output.exit_code == 0` and `trim_git_email(output.stdout).is_empty()` →
   `IdentityResolution::Failed("empty identity")`
4. `Ok(output)` where `output.exit_code == 0` and `!trim_git_email(output.stdout).is_empty()` →
   `IdentityResolution::Resolved(trim_git_email(output.stdout))`

**Tests (Rust unit):** `test_classify_identity_resolution_exec_error_maps_failed`,
`test_classify_identity_resolution_nonzero_exit_maps_failed`,
`test_classify_identity_resolution_empty_stdout_maps_failed`,
`test_classify_identity_resolution_nonempty_stdout_maps_resolved`

### AC-005 (traces to BC-4.17.001 precondition 2 — trim_git_email canonical home + sibling delegation)

`trim_git_email` MUST live in `crates/factory-lock/src/lib.rs` as the single canonical
implementation (promoted from `verify-factory-lock`, per F-P7-001 single-canonical-home
principle). `crates/hook-plugins/verify-factory-lock/src/lib.rs` MUST be updated to
delegate its local `trim_git_email` call to `factory_lock::trim_git_email` — no
re-implementation permitted in any crate.

**Tests (Rust unit):** `test_trim_git_email_canonical_in_factory_lock`,
`test_verify_factory_lock_delegates_trim_git_email`

### AC-006 (traces to BC-4.17.001 invariant — doc-comment correctness, post-F-P56-001 semantics)

Three stale doc-comment loci in `crates/factory-lock/src/lib.rs` MUST be corrected to
reflect post-F-P56-001 semantics (`Ok(None)` fires ONLY for absent-or-fully-null block;
empty/absent `holder` with siblings present → `Err(MalformedLockBlock)` — never `Ok(None)`):

1. `renew_lock_with_now` algorithm doc (locate by function name `renew_lock_with_now`)
2. The inline comment at the `Ok(None)` match arm inside `renew_lock_with_now`'s body
3. `parse_lock` doc (locate by function name `parse_lock`)

**No behavior change** — doc-comments only; no logic modification. Locate by function name
(TD-VSDD-091; advisory line numbers will have drifted).

This AC has no Red Gate test (doc-comment changes cannot produce a compile-time or test
failure). Verified by adversarial review and code review.

## Architecture Compliance Rules

Extracted from ADR-046 Decisions 1(b) and 2 and BC-4.17.001:

1. **`renew_lock_if_holder` is a pure-core function with injectable `resolve_identity` closure
   (ADR-046 Decision 1(b)):** No direct `host::exec_subprocess` call inside
   `renew_lock_if_holder`; the caller (`main.rs` of S-17.05 and S-17.07) wires the real
   `exec_subprocess` to the closure.
2. **`SkipReason::IdentityResolutionFailed` MUST carry 4 struct fields (F-P21-001):** `reason`,
   `holder`, `locked_at`, `expires_at` — all populated from the parsed `LockState`. No
   fewer fields are acceptable.
3. **`classify_identity_resolution` 4-shape rule (ADR-046 Decision 2 / F-006):** All four
   shapes enumerated in AC-004 are mandatory; no shape may be collapsed or omitted.
4. **`trim_git_email` single canonical home (F-P7-001 / AC-005):** After this story ships,
   the function MUST exist only in `crates/factory-lock/src/lib.rs`. Any
   `crates/hook-plugins/*/src/lib.rs` that contained a local copy MUST be updated to
   delegate. A crate with a duplicate `trim_git_email` body is a build-time violation.
5. **No `serde_yaml`/`serde_norway` / no `regex` crate:** Manual line-by-line YAML scanning
   via `factory_lock_parse` helpers only (established Architecture Compliance Rule across
   this crate family).
6. **Doc-comment corrections are behavior-neutral:** T-4 MUST NOT modify any non-comment
   line in `renew_lock_with_now` or `parse_lock`. Adversarial review will diff-check.
7. **Forbidden dependencies:** `factory-lock` MUST NOT gain a dependency on any
   `hook-plugins/*` crate (it is shared library; a reverse dependency would be circular).
   `factory-lock` MUST NOT depend on `hook-sdk` directly.

   holding a valid unexpired lock and a `resolve_identity` closure returning `Resolved(holder_email)`.
   Assert return is `Ok((RenewOutcome::Renewed(content), None))` and `expires_at` advanced.
2. **AC-001/case 2 (AlreadyExpired):** Fixture with `expires_at` in the past. Assert
   `SkipReason::AlreadyExpired` and `resolve_identity` call counter is 0.
3. **AC-003 (SkipReason struct fields):** Trigger case 4 (resolution failed). Assert
   `SkipReason::IdentityResolutionFailed { reason, holder, locked_at, expires_at }` all
   populated from the parsed lock state.
4. **AC-005 (canonical home):** `grep -r "fn trim_git_email" crates/` outputs ONLY
   `crates/factory-lock/src/lib.rs`. `verify-factory-lock` contains a delegation call, not
   a body.

## Dependency Anchor Justifications

- **`depends_on: []`** — `crates/factory-lock/` is already merged and on develop. All
  functions this story adds are net-new `pub` items in an existing crate. No unmerged
  predecessor work is required.
- **`blocks: ["S-17.05", "S-17.07"]`** — S-17.05 (`stamp-state-timestamp/src/main.rs`)
  calls `factory_lock::renew_lock_if_holder` and `factory_lock::classify_identity_resolution`
  created here. S-17.07 (`precompact-flush/src/lib.rs`) also calls `factory_lock::renew_lock_if_holder`
  created here. Neither downstream story can compile without this story's deliverables.
- **Wave 5 placement:** S-17.06 has no product dependencies, so it is naturally Wave 5 and
  topologically before S-17.05 and S-17.07. DTU-style prerequisite pattern.
