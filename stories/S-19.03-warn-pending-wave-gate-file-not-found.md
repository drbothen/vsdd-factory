# S-19.03 — warn-pending-wave-gate FINDING-2: read_file file_not_found semantics + graceful absent-file handling

**Epic:** E-19 — Post-rc.22 Operator Hardening
**Wave:** 1 (no hard predecessor in E-19; can begin in parallel with S-19.02)
**Depends on:** none
**Priority:** P1 (functional defect — silently incorrect telemetry on every Stop event in fresh installs; masks real capability misconfiguration)
**Subsystem anchor:** SS-04 (Plugin Ecosystem) owns the WASM plugin. SS-01 (Hook Dispatcher Core) owns the `read_file.rs` host function being corrected. SS-02 (Hook SDK) owns the `HostError::NotFound` named variant and `NOT_FOUND` code export in `crates/hook-sdk/src/host.rs` — these are the SS-02 boundary artifacts that enable WASM plugins to exhaustively pattern-match on host error codes without requiring `#[non_exhaustive]`.

## Narrative

The `warn-pending-wave-gate` Stop-event plugin warns operators when a wave gate check is pending (i.e., `.factory/wave-state.yaml` indicates `pending_gate: true`). In a fresh install — or any install where no wave has been handed off yet — `wave-state.yaml` does not exist.

**The defect:** `read_file.rs::path_allowed()` calls `resolved.canonicalize()` to resolve symlinks before checking the path against the allowlist. `canonicalize()` returns `Err` if the file does not exist. On error, `path_allowed()` returns `false`, which causes the dispatcher to emit `internal.capability_denied reason=path_not_allowed` and return `CAPABILITY_DENIED (-1)` — even though `.factory/wave-state.yaml` IS in the allowlist.

The consequence is twofold:
1. The plugin can never detect a pending wave gate in an install where `wave-state.yaml` does not yet exist (it degrades gracefully to Continue, but the detection fails silently).
2. Every Stop event emits a false-positive `capability_denied` telemetry event that misleads operators into thinking there is a capability misconfiguration when there is none. The event type `path_not_allowed` is indistinguishable from a genuine allowlist violation.

**Diagnosis note:** The `path_allow = [".factory/wave-state.yaml"]` entry IS present in both the development `plugins/vsdd-factory/hooks-registry.toml` and the rc.22 operator cache registry. The root cause is entirely in `read_file.rs::path_allowed()` conflating "file does not exist" with "path not allowed".

**Fix direction (two-layer, production-grade):**

1. **Dispatcher fix (SS-01):** Refactor `read_file.rs::path_allowed()` to use the rejoin algorithm for target paths that do not yet exist. If `resolved.canonicalize()` fails (file absent), walk ancestors until one canonicalizes successfully (the deepest existing ancestor), then rejoin the non-existent tail path components back onto the canonical ancestor path, producing a synthesized canonical path. Check that this synthesized path starts_with an allowed prefix. This mirrors the `resolve_path_for_allowlist` helper in `write_file.rs` (cite by function name, not line number — TD-VSDD-091); that helper MUST be extracted to a shared host module (`crates/factory-dispatcher/src/host/path_util.rs`) rather than duplicated in `read_file.rs`. If path is allowed but file absent, `read_bounded()` fails to open → return a distinct `ReadErr::NotFound` variant that emits a new telemetry event `internal.file_not_found` (not `capability_denied`) and returns a new `codes::NOT_FOUND (-5)`. This distinguishes the two failure modes for downstream consumers and operators.

2. **Plugin fix (SS-04):** Update `warn-pending-wave-gate` to explicitly handle `host::read_file` returning `NOT_FOUND (-5)`: treat this as "wave-state.yaml absent = no pending gate → Continue, no WARN log." Also ensure the plugin handles `CAPABILITY_DENIED (-1)` for genuine allowlist violations with an appropriate WARN (not the same silent path as file-not-found).

## Architecture Mapping

**SS-01 changes (crates/factory-dispatcher/src/host/read_file.rs):**
- `path_allowed()` → decomposed into two-step pattern (architect Ruling-2): Step 1 — call `resolve_path_for_allowlist` which returns `Option<PathBuf>`; if `None` (all ancestors exhausted without canonicalizing), emit `internal.capability_denied reason=path_resolution_failed` and return `CAPABILITY_DENIED`; Step 2 — pure prefix check: if resolved path does not start_with an allowed prefix, emit `internal.capability_denied reason=path_not_allowed` and return `CAPABILITY_DENIED`. This decomposition cleanly separates resolution failures (filesystem/traversal issues) from genuine allowlist violations, making each reason token independently testable and semantically unambiguous.
- `prepare()`: add `ReadErr::NotFound` variant; emit `internal.file_not_found` event; return `codes::NOT_FOUND`
- `read_file.rs` unit tests: add AC-001 and AC-002 coverage

**Mandatory write_file.rs sibling-sweep (architect Ruling-2 — TD-VSDD-060):** `write_file.rs` contains the original `path_allowed()` definition that is being extracted into `path_util.rs`. After extraction, `write_file.rs` MUST also adopt the same two-step decomposed pattern (existing `path_allowed()` call becomes/replaced-by pure prefix_check using the resolved path from `resolve_path_for_allowlist`). Add a unit test in `write_file.rs` that injects a mock canonicalize fn returning `Err` for every ancestor and asserts: (a) `path_resolution_failed` reason token is emitted (NOT `path_not_allowed`); (b) return code is `CAPABILITY_DENIED (-1)`. This sibling-sweep is mandatory — omitting it leaves `write_file.rs` with a divergent path-allowed implementation that cannot distinguish the two failure modes.

**SS-01 changes (`pub mod codes` block in `crates/factory-dispatcher/src/host/mod.rs`):**
- Add `pub const NOT_FOUND: i32 = -5;` in the `pub mod codes` block (ADR-025 Decision 13)
- This is the concrete site for `codes::NOT_FOUND` (F-P2-007); "codes.rs or equivalent" language retired

**SS-01 changes (crates/factory-dispatcher/src/host/path_util.rs — new shared module):**
- Extract `resolve_path_for_allowlist` from `write_file.rs` into this shared module; import in both `read_file.rs` and `write_file.rs`

**SS-02 changes (crates/hook-sdk/src/host.rs):**
- Export `NOT_FOUND` code constant and add `HostError::NotFound` named variant so WASM plugins can pattern-match on it (O-P2-002: do NOT add `#[non_exhaustive]` — this attribute would prevent exhaustive pattern matching in plugin code, which is required for correct abandoned-path handling)

**SS-04 changes (crates/hook-plugins/warn-pending-wave-gate/src/lib.rs):**
- Handle `NOT_FOUND` return: return Continue, suppress WARN log
- Handle `CAPABILITY_DENIED`: emit WARN "capability configuration error"
- Add AC-004 / AC-005 / AC-006 tests
