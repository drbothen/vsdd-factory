# S-18.14 — Dispatcher resolver WASM path resolution fix (CLAUDE_PLUGIN_ROOT-relative) + logs/ gitignore + log_dir observability

## Summary

Fix dispatcher resolver WASM path resolution to be CLAUDE_PLUGIN_ROOT-relative instead of process-CWD-relative. Add `logs/` to develop `.gitignore` (done via PR #199). Emit `log_dir` in `dispatcher.started` for observability.

**Status: DRAFT — REQUIRES PO BC AUTHORSHIP per S-7.01 before implementation begins.**

Scope: SMALL (8pts). Epic E-18 (context-durability). Priority P0 (HIGH defect + MEDIUM config defect).

## Defects Captured (architect investigation 2026-06-21, D-676)

### DEFECT 1 — MEDIUM (config; ADDRESSED by PR #199)

**Summary:** root `.gitignore` lacked `logs/` entry.

**Impact:** `state-manager`'s `git stash` on the `factory-artifacts` worktree captures `.factory/logs/*` at the repo-root-relative `logs/` path, leaking dispatcher log files into develop tracked-state on stash/merge artifact access.

**Recurrence pattern:** D-561/D-616/D-629/D-640/D-648/D-664 (six occurrences).

**Fix:** `logs/` gitignore rule added to repo root `.gitignore` via PR #199 (`chore: gitignore repo-root runtime dispatcher logs`). PR #199 OPEN pending human merge approval (autonomy STOP-BEFORE-PR-MERGE D-665).

**Verification:** After PR #199 merges, `git check-ignore -v logs/` must return a match against the root `.gitignore`.

### DEFECT 2 — HIGH (code; OPEN — primary scope of S-18.14)

**Summary:** `resolver_loader::load_registry` / `get_or_compile` resolves relative WASM plugin paths from `resolvers-registry.toml` (e.g. `hook-plugins/vsdd-context-resolvers.wasm`) via `path.canonicalize()` against PROCESS CWD instead of relative to the registry TOML's parent directory (= CLAUDE_PLUGIN_ROOT).

**Result:** `wave_context` context resolver fails to load on EVERY dispatch since rc.21.

**Empirical evidence (orchestrator-confirmed):** Across recent dispatcher logs, **8,560 `resolver.load_error` events vs 0 successful resolver loads**. Error detail: `resolver 'wave_context' — cannot canonicalize hook-plugins/vsdd-context-resolvers.wasm: No such file or directory`.

**Failure mode:** Fails open — pipeline keeps running, resolver silently absent. Wave context is unavailable to all hook plugins that query it, degrading context-awareness silently.

**Behavioral anchor:** `get_or_compile` `path.canonicalize()` call site in `resolver_loader`.

**Recommended fix:** In `load_registry`, join a relative `entry.plugin` path with the TOML's parent directory (`path.parent()` of the registry TOML path) BEFORE calling `get_or_compile`. Apply at ALL `get_or_compile` call sites (both `fail_closed: true` and `fail_closed: false` paths).

**Release dependency:** The operator-level cached dispatcher only picks up this fix after an rc release. Develop-branch edits do not affect the cached plugin. A release must be cut after this story merges.

**Proposed ADR touch:** ADR-024 (add resolver-WASM-path-resolution subsection to Decision 1 documenting the CLAUDE_PLUGIN_ROOT-relative path contract).

**Optional observability fix:** Emit `log_dir` field in `dispatcher.started` event. The `InternalLog::log_dir()` accessor already exists — wire it into the started event payload.

## Test Obligation

Unit test (Rust, `crates/factory-dispatcher/` or `crates/context-resolvers/`):

1. Construct a `resolvers-registry.toml` with a relative WASM path (e.g. `plugin = "hook-plugins/vsdd-context-resolvers.wasm"`).
2. Call `load_registry` passing an ABSOLUTE path to the TOML (simulating `CLAUDE_PLUGIN_ROOT/<registry>`).
3. Assert the resolved WASM path is CLAUDE_PLUGIN_ROOT-relative (i.e. resolved against the TOML's parent dir), NOT CWD-relative.
4. Assert that a CWD-relative resolution would differ (proving the test distinguishes the old behavior).
