# S-23.09: Corpus migration — VP-INDEX.md (268 live pins)

## Narrative

- **As a** state-manager/consistency-validator executing ADR-045's mechanical corpus migration
- **I want** to run the S-23.02 codemod against `.factory/specs/verification-properties/VP-INDEX.md`
  and commit the result as one atomic commit
- **So that** the fourth and smallest-by-count of the 4 INDEX files is migrated, completing the
  1,573-pin (51%) highest-value/highest-risk INDEX-file cluster ADR-045 identifies

## Context / Problem Statement

ADR-045 §Consequences, Negative/Trade-offs names VP-INDEX.md's 268 live pins as the smallest of
the 4-INDEX-files cluster, but still the fourth-largest single-file concentration in the entire
corpus scan. This is the last of the 4 INDEX-file migration commits; once it lands, S-23.10's
Wave-7 story-files migration can proceed with all four registries in stable-anchor form,
consistent VP citation resolution available via S-23.04.

## Acceptance Criteria

### AC-001
Running the codemod in `--dry-run` mode against VP-INDEX.md produces a diff report reviewed
before apply. (traces to ADR-045 §Migration Plan Phase A step 5; S-23.02 AC-006)

### AC-002
The codemod does not modify VP-INDEX.md's own authoritative Version column / VP-registry rows,
nor its `modified:`/`last_amended:`/`[Prior:]`/`## Changelog` sections. (traces to S-23.05 AC-003;
S-23.01 AC-001)

### AC-003
The migration is applied as exactly one atomic commit touching only VP-INDEX.md (plus its S-23.04
row-offset sidecar if regenerated). (traces to ADR-045 §Migration Plan Phase A step 5; TD-VSDD-053)

### AC-004
Post-commit, S-23.03's guard and S-23.05's extended parity gate pass against VP-INDEX.md with
zero findings. (traces to S-23.03 AC-001/AC-003; S-23.05 AC-001)

### AC-005 (negative control)
Post-commit, a targeted grep for `\bVP-\d+\b[^\n]{0,80}\bv\d+(?:\.\d+)*\b` (and BC/ADR/Story
cites present in VP-INDEX's own live prose) in VP-INDEX.md's live sections returns zero matches.
(traces to ADR-045 §Consequences Positive)
