# S-23.07: Corpus migration — ARCH-INDEX.md (287 live pins) + newline-normalized anchor-interposed ADR pass (~30-40 pins)

## Narrative

- **As a** state-manager/consistency-validator executing ADR-045's mechanical corpus migration
- **I want** to run the S-23.02 codemod against `.factory/specs/architecture/ARCH-INDEX.md`,
  paying specific attention to the anchor-interposed/line-wrapped ADR pins (`ADR-039 §Decision 3
  v1.10`-shaped citations) that a naive per-physical-line codemod would miss
- **So that** ARCH-INDEX — the second-largest INDEX-file concentration (287 pins) and the home of
  the ~30-40 ADR pins ADR-045 explicitly calls out as requiring a newline-normalized pass — is
  fully migrated in one commit, closing that specific failure-mode risk

## Context / Problem Statement

ADR-045 §Consequences, Negative/Trade-offs: "~30-40 live ADR pins are anchor-interposed or
line-wrapped (failure modes 1/2) and will not be caught by a naive line-oriented codemod — these
require the newline-normalized migration pass specified in the Migration Plan." ADR-045 §Migration
Plan Phase A step 5 names this explicitly as part of ARCH-INDEX's migration. This is exactly the
scenario S-23.01's detector was built to defeat by construction (AC-003/AC-004 in that story):
newline-normalization within a logical text run, and independent ID/version tokenization tolerant
of an interposed anchor phrase. This story is the first real-corpus exercise of that capability —
if the ~30-40-pin count does not fully resolve after applying the codemod, that is a signal S-23.01's
detector has a gap that must be fixed there, not worked around here with a manual sweep (per
CLAUDE.md's production-grade-default: fix in scope, correct-agent-pattern).

## Acceptance Criteria

### AC-001
Running the codemod in `--dry-run` mode against ARCH-INDEX.md produces a diff report that
includes every anchor-interposed ADR citation (`ADR-NNN §Decision N vX.Y`-shaped) found in live
sections, not merely the simple-adjacency (`ADR-NNN vX.Y`) forms. (traces to ADR-045 §Migration
Plan Phase A step 5, newline-normalized pass; S-23.01 AC-004)

### AC-002
The diff report's count of newly-converted anchor-interposed/line-wrapped ADR citations is
recorded in this story's commit body and compared against ADR-045's estimated ~30-40 count; a
material discrepancy (e.g., fewer than ~20 found) triggers a stop-and-check against S-23.01's
detector before proceeding to apply, per this project's fix-in-scope discipline. (traces to
ADR-045 §Consequences, "~30-40 live ADR pins")

### AC-003
The codemod does not modify ARCH-INDEX.md's own authoritative Version column / subsystem-registry
rows (ground truth, not a citation), mirroring S-23.06 AC-002's BC-INDEX analog. (traces to
S-23.05 AC-003; ADR-045 §Decision, Tier 1)

### AC-004
The codemod does not modify ARCH-INDEX.md's `modified:`/`last_amended:`/`[Prior:]` fields or
`## Changelog`/`## Amendment` sections. (traces to S-23.01 AC-001)

### AC-005
The migration is applied as exactly one atomic commit touching only ARCH-INDEX.md (plus its
S-23.04 row-offset sidecar if regenerated). (traces to ADR-045 §Migration Plan Phase A step 5;
TD-VSDD-053)

### AC-006
Post-commit, S-23.03's guard and S-23.05's extended parity gate pass against ARCH-INDEX.md with
zero findings. (traces to S-23.03 AC-001/AC-003; S-23.05 AC-001)

### AC-007 (negative control)
Post-commit, a targeted newline-normalized grep (`tr '\n' ' '` piped, per the existing D-1079
POLICY 5 multiline-sweep discipline referenced in ADR-045 §Migration Plan step 5) for
`\bADR-\d+\b[^\n]{0,80}\bv\d+(?:\.\d+)*\b` across ARCH-INDEX.md's live sections returns zero
matches. (traces to ADR-045 §Consequences Positive)
