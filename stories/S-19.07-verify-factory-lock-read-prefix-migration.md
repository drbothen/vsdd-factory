## Narrative

BC-4.13.001 v1.6 Phase-B (ADR-025 D18(e)) mandates migrating `verify-factory-lock` from `host::read_file` to `host::read_prefix` for reading `.factory/STATE.md`. Phase-A (S-19.02) raised the `host::read_file` cap to 262144 bytes and added `extract_frontmatter()` parsing discipline — this closed FINDING-1. Phase-B completes the arc by switching to the bounded-prefix read mechanism added in S-19.06.

**Why migrate after Phase-A already works?** Phase-A is correct and operational: the 262144-byte cap covers all realistic STATE.md sizes, `extract_frontmatter()` enforces frontmatter-only parsing, and the soft-warning threshold at 200000 bytes provides leading-indicator observability. Phase-B's value is structural simplification:

1. **Eliminates the `OUTPUT_TOO_LARGE` failure class.** `read_prefix(path, max_bytes=8192)` returns at most 8192 bytes and is guaranteed by BC-1.17.001 to NEVER return `OUTPUT_TOO_LARGE (-3)`. Removing the `TooLarge`/`OutputTooLarge` handling code in the plugin eliminates a degenerate error path entirely — that error class becomes structurally impossible.
2. **Right-sizes the read.** STATE.md frontmatter is <2 KB under compaction discipline (ADR-026 ≤200 lines, typically ≤150 lines at ~40 chars/line ≈ 6 KB worst-case; the 8192-byte bound is chosen with >30% margin). Reading only the frontmatter prefix instead of up to 256 KB eliminates unnecessary I/O.
3. **Defense-in-depth via capability independence.** `[hooks.capabilities.read_prefix]` is a separate capability from `[hooks.capabilities.read_file]` (BC-1.17.001 Invariant 3). The migration to `read_prefix` also migrates the capability declaration, restricting the plugin's file-read surface to the prefix API only.
4. **Removes `STATE_MD_MAX_BYTES` compile-time constant.** The constant was introduced to track the byte cap; it is no longer needed when `max_bytes` is specified per-call in `read_prefix`. Removing it simplifies the plugin.

**`extract_frontmatter` is retained unchanged.** Phase-B does not change the frontmatter extraction algorithm — the function remains as-is from S-19.02. `read_prefix` returns a bounded prefix of the file bytes; `extract_frontmatter` truncates at the closing `---` delimiter. The two operations compose correctly: if the prefix includes the complete frontmatter (guaranteed by the 8192-byte bound combined with the <2 KB frontmatter discipline), `extract_frontmatter` works identically to Phase-A.

**Phase-A is unregressed until this story merges.** The Phase-A `host::read_file` path remains operational in production. S-19.07 is a forward-scheduled migration, not an in-place regression.

**Verification properties note:** `verification_properties` is intentionally empty: Phase-B structurally eliminates the OUTPUT_TOO_LARGE class; AC-003 + the bats fixture are the load-bearing gates; a dedicated VP was evaluated and declined (adversary O-P7-002).

## Architecture Mapping

**SS-04 changes (`crates/hook-plugins/verify-factory-lock/src/lib.rs`):**
- Replace `host::read_file(".factory/STATE.md", STATE_MD_MAX_BYTES)` call with `host::read_prefix(".factory/STATE.md", 8192, <timeout_ms>)`. The `max_bytes=8192` argument covers any realistic STATE.md frontmatter (<2 KB under compaction discipline; 8192 ≥ 4× worst-case frontmatter size).
- Remove `STATE_MD_MAX_BYTES = 262144` compile-time constant (no longer needed; `max_bytes` is per-call in `read_prefix`).
- Remove ALL handling of `TooLarge`, `OutputTooLarge` error variants. `read_prefix` never returns `OUTPUT_TOO_LARGE (-3)` by construction (BC-1.17.001 PC-3); the error class is structurally impossible after migration.
- Remove soft-warning threshold check (`state_md_approaching_cap` diagnostic event, BC-4.13.001 v1.5 Invariant 10) — this is Phase-A `read_file` specific; `read_prefix` does not have a cap-approaching-threshold concept.
- `extract_frontmatter(bytes: &[u8]) -> &[u8]` is **retained unchanged** — it receives the prefix bytes from `read_prefix` and truncates at the `---` delimiter. No changes to the function body.
- `parse_factory_lock(bytes: &[u8])` is **retained unchanged**.
- `crates/factory-dispatcher/src/host/read_file.rs` is **NOT modified** — `read_file` semantics are immutable (BC-1.17.001 Invariant 2).

**Registry changes (`plugins/vsdd-factory/hooks-registry.toml`):**
- Update BOTH `verify-factory-lock` entries (the `Edit|Write|MultiEdit|Agent` entry and the `Bash` entry) to replace `[hooks.capabilities.read_file]` with `[hooks.capabilities.read_prefix]`, keeping `path_allow = [".factory"]` unchanged. Anchored `tool =` patterns from S-19.04 are preserved unchanged. The `[hooks.capabilities.exec_subprocess]` blocks are preserved unchanged.

**`hook-sdk/src/host.rs` is NOT modified** — the `read_prefix` FFI extern was added by S-19.06; this story only calls the wrapper.

**`crates/factory-dispatcher/src/host/read_prefix.rs` is NOT modified** — the dispatcher implementation was added by S-19.06.
