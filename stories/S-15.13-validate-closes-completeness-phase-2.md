# S-15.13: validate-closes-completeness WASM Hook Phase 2

**Epic:** E-12 — Engine Governance (brownfield-backfill wave, S-15.03 PRIORITY-A M3)
**Delivery order:** M3 (must ship AFTER S-15.12 merged; gated on ADR-022 Option c state-manager obligation)
**Depends on:** S-15.12 (Phase 1 crate must be merged; Phase 2 extends the same crate)
**Blocks:** none
**Priority:** P1 (closes D-411(c)+D-413(b)+D-420(a)+D-445(a)+D-447(a))
**ADR gate:** ADR-022 Option c ACCEPTED — state-manager must write `.factory/current-adversary-pass.txt`
  at every Commit A before Phase 2 is functional

## Narrative

- **As a** state-manager or agent writing a closing annotation in a fix burst
- **I want to** receive an immediate PostToolUse block when the Closes set in my burst-log,
  STATE.md, INDEX.md, or decision-log.md entry is missing a finding from the canonical finding
  set established in the current adversary review file
- **So that** the class of cross-cell Closes completeness failures — where a finding is cited
  in some sites but silently omitted from others — is caught mechanically at write time

## Why This Exists

Phase 1 (S-15.12) enforces Closes annotation FORMAT: correct bold-prefix form, no forbidden
annotations, umbrella cite flags. But Phase 1 cannot verify that the SET of findings cited
matches what the adversary actually reported — cross-site staleness (cite ID exists but references
a nonexistent finding) remains advisory-only in Phase 1.

Phase 2 adds cross-document Closes set agreement: the hook reads the current adversary review
file (located via `.factory/current-adversary-pass.txt` written by state-manager at Commit A
per ADR-022 Option c) to extract the canonical finding set, then validates that the 8 prescribed
citation sites each enumerate the complete finding set.

D-411(c)+D-413(b) codified the 8-site closure-set cross-validation. D-420(a) codified
multi-site cardinality agreement. D-445(a) established burst-log Dim-5 + Closes + STATE.md
Decisions Log row Closes must enumerate the complete finding set. D-447(a) established the
downstream-citation-scope coverage at Commit E.

## Precondition: ADR-022 State-Manager Obligation

**Phase 2 becomes operational when:**
1. S-15.12 is merged (Phase 1 shipped) — crate scaffolding exists.
2. state-manager's Commit A sequence writes `.factory/current-adversary-pass.txt` (ADR-022
   Option c obligation). This file contains the path to the current adversary review file.

**Until state-manager's Commit A sequence is updated to write this file, Phase 2 checks
are fail-open** (hook reads the pointer file; if absent, logs advisory and returns Continue).
Phase 2 blocks only when the pointer file is present and the adversary review file is readable.

**Implementer MUST NOT remove the fail-open path** even after state-manager obligation is
activated — hooks that hardcode the pointer path and block when file is absent would break
all workflows that don't use the current-pass pointer (e.g., manual STATE.md edits).

## Scope

**In scope (Phase 2 addition to S-15.12's crate):**
- Extension to `crates/hook-plugins/validate-closes-completeness/src/lib.rs` with Phase 2
  cross-document finding-set validation
- New function: read `.factory/current-adversary-pass.txt` to locate the current adversary file
- New function: parse canonical finding set from the adversary review file (Part A findings)
- New function: cross-validate finding IDs across the 8 prescribed citation sites
- WASM recompilation to `plugins/vsdd-factory/hook-plugins/validate-closes-completeness.wasm`
  (replaces Phase 1 binary)
- New bats integration tests (appended to Phase 1 test suite; same directory)
- PASS + FAIL fixtures for cross-site agreement scenarios
- LOCAL adversary cascade per BC-5.39.001 (3-CLEAN convergence required)

**Not in scope:**
- Phase 1 behavior changes — Phase 1 checks are frozen; Phase 2 is additive
- Modification of state-manager's Commit A obligations (that is state-manager scope; ADR-022
  specifies the obligation but implementation is in state-manager's operating procedure)
- Enforcement of Closes completeness for non-adversary findings (e.g., TD-VSDD-NNN items
  not in the adversary review file are outside Phase 2 scope)

## Behavioral Contract

**BC ID:** BC-5.39.007 (Phase 2 extension)
**File:** `.factory/specs/behavioral-contracts/ss-05/BC-5.39.007.md` (v1.5 — Phase 2 reserved section)

### Phase 2 Additional Postconditions (additive to Phase 1)

**P2-1 — Current-pass pointer resolution:**
If `.factory/current-adversary-pass.txt` is absent or unreadable via `host::read_file`,
the Phase 2 cross-site check is SKIPPED and the hook emits `HookResult::Continue` with
advisory log message: `"validate-closes-completeness Phase 2: current-adversary-pass.txt absent; skipping cross-site validation. Ensure state-manager's Commit A writes this file per ADR-022."` This is the fail-open path.

**P2-2 — Adversary finding set extraction:**
If the adversary review file (path read from the pointer file) is readable, the hook extracts
all finding IDs from Part A (pattern: `F-P\d+-\d+` or `F-BC\d+P\d+-\d+`) as the canonical
set. If Part A section is not found or the set is empty, the hook emits advisory log and
returns Continue (fail-open — cannot block on an unknown canonical set).

**P2-3 — Cross-site finding coverage:**
For each of the 8 citation sites that is accessible from the hook's `path_allow`, the hook
checks that all canonical finding IDs appear in that site's Closes citation. If any site is
missing a finding ID from the canonical set, the hook emits `HookResult::block_with_fix(...)`
naming the site and the missing finding IDs, citing D-411(c)+D-413(b).

**P2-4 — Cardinality parity:**
If the finding count cited at different sites diverges, the hook emits `HookResult::block_with_fix(...)`
naming the sites and their respective counts, citing D-420(a).

### Phase 2 Invariants

1. Phase 2 is fail-open at every step: pointer file absent → Continue + advisory; adversary file
   unreadable → Continue + advisory; Part A empty → Continue + advisory. Only when BOTH files
   are readable AND finding set is non-empty does Phase 2 produce blocking behavior.
2. Phase 1 behavior is unchanged. Phase 2 violations are additive to Phase 1 violations in the
   same BlockWithFix message.
3. The pointer file path is always `.factory/current-adversary-pass.txt` (canonical per ADR-022
   Option c). The hook MUST NOT derive this path from STATE.md parsing (that is ADR-022 Option
   a — the rejected alternative).

- [ ] T-5: Add Phase 2 functions to `src/lib.rs`:

  ```
  fn read_current_adversary_pass_path() -> Option<String>
  ```
  Reads `.factory/current-adversary-pass.txt` via `host::read_file(".factory/current-adversary-pass.txt", 1024, 1000)`.
  On error: returns None (fail-open). On success: returns `Some(path_string.trim().to_string())`.

  ```
  fn extract_canonical_finding_set(adversary_content: &str) -> Vec<String>
  ```
  Find the `## Part A` section (or `# Part A` or `**Part A**` heading) in the adversary review
  file. Within that section, extract all finding IDs matching `F-P\d+-\d+` or `F-BC\d+P\d+-\d+`
  patterns. Return Vec<String> of unique IDs in order of appearance. Empty vec if Part A not found.

  ```
  fn collect_closes_cites(content: &str, site_name: &str) -> Vec<String>
  ```
  Given a document's content and the site name (e.g., "STATE.md Decisions Log row"), extract
  all finding IDs from Closes blocks in that document. The exact extraction strategy depends
  on the site: for STATE.md and decision-log.md, scan all `**Closes:**` lines in the Decisions
  Log section; for lessons.md, scan `**Closes:**` lines in lesson entries; for burst-log.md,
  scan the burst entry's Closes bold-block. Returns Vec<String> of unique cited finding IDs.

  ```
  fn check_cross_site_completeness(
      canonical_set: &[String],
      sites: &[(String, Vec<String>)],  // (site_name, cited_ids)
  ) -> Vec<Violation>
  ```
  For each site in `sites`: check that all IDs in `canonical_set` appear in the site's cited_ids.
  Missing IDs → add Violation naming site + missing IDs + D-411(c). If cardinality diverges
  across sites → add cardinality Violation citing D-420(a).

  ```
  fn run_hook_phase2_cross_site(file_path: &str, content: &str) -> Vec<Violation>
  ```
  Orchestrates Phase 2 cross-site validation:
  1. Read pointer file via `read_current_adversary_pass_path()`. If None → log_warn + return empty vec (fail-open).
  2. Read adversary review file via `host::read_file(adversary_path, 524288, 2000)`. If error → log_warn + return empty vec (fail-open).
  3. Extract canonical finding set. If empty → log_warn + return empty vec (fail-open).
  4. For the triggered file arm, determine which sites are accessible and collect their cites.
     On STATE.md write: collect cites from STATE.md Decisions Log Closes (already in `content`);
     also read burst-log.md and decision-log.md via `host::read_file` if path_allow permits.
  5. Call `check_cross_site_completeness` with canonical set and collected sites.
  6. Return accumulated violations.

  **Important:** Not all 8 sites are readable from every write event. Reads that fail due to
  HostError are individually fail-open (skip that site; log_warn). Do not block because a
  secondary site is unreadable.

  **Integration into `run_hook`:** After Phase 1 check accumulation, call `run_hook_phase2_cross_site`
  and append its violations to the Phase 1 violations Vec. Single combined BlockWithFix emitted.
