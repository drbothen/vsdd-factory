## Narrative

- **As a** engine-discipline cycle operating across F5 pass boundaries (including multi-week pauses)
- **I want** trajectory_tail per-cell presence mechanically enforced across all D-453(d) canonical-mapping-table prescribed sites at PostToolUse write time
- **So that** the per-cell granularity discipline codified in D-454(a) cannot silently degrade during cycle pauses, preventing META-LEVEL-30 route (b) recurrence (codified-without-runtime-gate-permits-silent-degradation-over-time)

## Why This Exists

**F5 pass-75 finding ADV-EDP1-P75-HIGH-002** found that after a 14-day F5 pause, only 2 of the 9
mechanically-checkable D-453(d) prescribed sites for `trajectory_tail` carried the canonical tail
value. D-454(a) codified per-cell granularity discipline at the story (Dim-2 attestation) level,
but codification as a prose narrative check does not prevent silent degradation between passes.

**The structural escape hatch** is META-LEVEL-30 route (b): "codified-without-runtime-gate-permits-
silent-degradation-over-time." The adversary correctly identified that prose Dim-2 attestation
(Section 11 Step 3 narrative check counting ONE cell, not checking all 9) cannot enforce the
discipline at write time. Each STATE.md or cycle artifact edit that omits the trajectory_tail from
a prescribed cell succeeds without detection.

**D-453(d) canonical mapping table** (decision-log.md appendix) prescribes 11 sites for
`trajectory_tail`. Of these, 9 are mechanically checkable via PostToolUse on the artifact files that
contain them:

| Site | Document | Mechanically Checkable |
|------|----------|----------------------|
| STATE.md frontmatter `current_step` | STATE.md | Yes |
| STATE.md Last Updated cell | STATE.md | Yes |
| STATE.md Phase Progress rows (latest pass) | STATE.md | Yes |
| STATE.md Concurrent Cycles row | STATE.md | Yes |
| STATE.md Session Resume Section 1 | STATE.md | Yes |
| INDEX.md Convergence Status row | INDEX.md | Yes |
| INDEX.md adversarial-review summary-table rows (latest pass) | INDEX.md | Yes |
| burst-log latest-pass Dim-7 (Attestation) | burst-log.md | Yes |
| lessons.md latest-lesson trend-table | lessons.md | Yes |
| decision-log.md trajectory-bearing rows | decision-log.md | Advisory only (sparse; not every row) |
| adv-cycle-pass-*.md frontmatter trajectory_tail field | adv-cycle-pass-*.md | Out-of-scope (written by adversary, not by state-manager) |

This story implements a WASM hook that checks the 9 mechanically-enforceable sites at PostToolUse
on edits to `.factory/STATE.md` and active-cycle artifacts (INDEX.md, burst-log.md, lessons.md
within the cycle resolved dynamically from STATE.md `current_cycle:` at runtime — BC v1.8
Precondition 4 F-SP3-001 dynamic resolution). The hook targets whichever cycle is currently active,
not a hardcoded F5 cycle path.

  **Trajectory_tail pattern — LENGTH=4 STRICT EQUALITY (F-SP3-002 mirror; BC v1.8 inv-4):**

  The canonical check uses `→(\d+)` to count arrow-segments via SEPARATE ITERATION and asserts

  FIRST 4 arrows of a LENGTH=5+ sequence — returning a false-pass for `→9→9→9→9→9`. The
  `arrows >= 4` approach in T-5 v1.3 was a PAPER-FIX per TD-VSDD-059 (F-SP3-002 regression).

  fn count_trajectory_arrows(text: &str) -> usize {
      // Count →(\d+) matches via byte-walk with EQUALITY check (not >= check)
      // CRITICAL: equality `count == 4` is required; >= 4 silently accepts LENGTH=5+
      // Per BC-5.39.009 v1.8 inv-4 marker-prefix two-step discipline + BC-5.39.006 inv-6(b) precedent (F-SP3-002 cure)
      // NOTE: This function counts arrows in an ALREADY SCOPED segment (marker-end to first ';').
      // Callers (PC1/PC2/PC4/PC5) MUST first locate the 'trajectory-tail ' marker and pass only
      // the sub-string from marker-end to first ';' (or end-of-text) to this counter.
      let arrow_bytes = "→".as_bytes(); // [0xE2, 0x86, 0x92] — 3 bytes UTF-8
      let mut count = 0usize;
      let mut i = 0;
      let bytes = text.as_bytes();
      while i < bytes.len() {
          if bytes[i..].starts_with(arrow_bytes) {
              i += arrow_bytes.len();
              // skip one or more ASCII digits
              let digit_start = i;
              while i < bytes.len() && bytes[i].is_ascii_digit() { i += 1; }
              if i > digit_start {
                  count += 1; // valid →\d+ match
              }
              // else: arrow not followed by digit — not a valid tail segment; reset? No, count
              // only valid segments. Arrow without digits is malformed; skip.
          } else {
              i += 1;
          }
      }
      count
  }

      // CALLERS must extract the segment BEFORE calling this; do NOT pass full cell/value text.
      // Simplest correct implementation: count all arrows in the scoped segment, check == 4.
      count_trajectory_arrows(segment) == 4
