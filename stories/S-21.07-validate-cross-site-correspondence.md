### AC-013: Class D — non-F- finding-like token triggers advisory, not block (traces to BC-5.39.010 postcondition 17; invariant 6)

A token that (a) matches shape `[A-Za-z][A-Za-z0-9-]*[0-9]+` (starts with letter, ends
with digit), (b) is NOT in the exclusion list, and (c) does NOT start with `F-` MUST
produce `host::log_warn` advisory per token and `HookResult::Continue` (NOT block).
Class D is advisory-only, never blocking (BC-5.39.010 invariant 6).

The advisory message MUST match: `"validate-cross-site-correspondence [Class D] advisory:
non-canonical finding-ID token '<token>' on line '<line>' in <section> of <file>. Finding
IDs must start with 'F-'. Verify this is not a phantom ID or retracted reference."`.

**Gap — Class D format-only limitation (EXPLICITLY OUT OF SCOPE):** Class D Arm checks
syntactic format (does the token start with `F-`?) only. It does NOT check whether a
well-formed `F-<prefix>-<seq>` token actually names an existing finding in any adversary
pass record. A fabricated ID such as `F-S2104-P99-H99` passes Class D cleanly. This is
the exact failure shape from passes 29-30 (e.g., `F-P4-002` in burst-log Closes lines
referencing a re-labeled finding — the format was correct, the semantic existence was not
verified). Semantic existence validation requires corpus enumeration and is routed to a
Rust workspace integration test per BC-5.39.010 §Honest Gap + ADR-035 §Decision 4. This
story does NOT implement that check and MUST NOT be read as having done so.

- **Mutant test:** `test_BC_5_39_010_class_d_non_f_token_b01_advisory` — `Closes: B01,

### AC-019: Build constraints — release WASM only; serde_norway; max_bytes caps; UTF-8 safety (traces to BC-5.39.010 invariant 10; ADR-035 §Decision 5)

**Release build requirement:** The hook MUST be compiled with `cargo build --release
--target wasm32-wasip1 -p validate-cross-site-correspondence`. Debug builds exhaust the
10M-instruction fuel cap during `serde_json` deserialization of the dispatch payload —
`on_error = "continue"` means the hook silently produces no findings, indistinguishable
from a clean pass. A debug WASM binary is a broken gate. The CI step that stages hook
binaries MUST use the `--release` flag. (ADR-035 §Decision 5.)

**`serde_norway` not `serde_yaml`:** The workspace dependency is `serde_norway = "0.9"`.
`serde_yaml` was archived and deprecated in 2024; the workspace migrated in 2026-05 via
TD #72. Any `serde_yaml` import MUST fail to compile via `#[cfg(not)]` deny or absence
from `Cargo.toml`. The crate MUST use `serde_norway` for any YAML deserialization needs.
(YAML is not required for this hook — frontmatter is parsed via line-scanning regex as in
existing hook plugins — but the constraint is recorded to block inadvertent reintroduction.)

**`max_bytes` caps:** `host::read_file` calls MUST use the exact caps from
BC-5.39.010 preconditions:
- BC files (primary and BC cited in story): `max_bytes = 524288`, `timeout_ms = 3000`
- BC-INDEX.md: `max_bytes = 1048576`, `timeout_ms = 3000`
- Story files: `max_bytes = 524288`, `timeout_ms = 3000`
- STORY-INDEX.md (B2): `max_bytes = 1048576`, `timeout_ms = 3000`
- STORY-INDEX.md (B2 — Arm B2 write trigger): `max_bytes = 2097152`, `timeout_ms = 5000`
- Cycle artifacts (D arm): `max_bytes = 2097152`, `timeout_ms = 5000`

**UTF-8 safety:** All byte-index slicing on strings extracted from file content MUST use
`str::is_char_boundary()` checks where multi-byte UTF-8 is possible
(BC-5.39.010 invariant 9; BC-5.39.008 v1.6 inv-11).

- **Test:** `test_BC_5_39_010_multibyte_utf8_no_panic` — fixture content with multi-byte
  UTF-8 characters in BC title or frontmatter values → no panic; clean exit.
