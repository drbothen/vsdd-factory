### AC-019: Build constraints — release WASM only; serde_norway; max_bytes caps; UTF-8 safety (traces to BC-5.39.010 invariant 10; ADR-035 §Decision 5)

**Release build requirement:** The hook MUST be compiled with `cargo build --release
--target wasm32-wasip1 -p validate-cross-site-correspondence`. Debug builds exhaust the
operator-effective fuel cap (10,000,000 instructions through v1.0.0-rc.23; source-HEAD
raised `DEFAULT_FUEL_CAP` to 20,000,000 per ADR-042 §Decision 1 / PR #774, but that raise
is not yet operator-effective for this hook's own live PostToolUse enforcement — neither
"10M" nor "20M" alone is accurate without this source-vs-operator qualifier; BC-5.39.010
v1.18 §Gate Spec, F-S2107-P10-004) during `serde_json` deserialization of the dispatch
payload — `on_error = "continue"` means the hook silently produces no findings,
indistinguishable from a clean pass. A debug WASM binary is a broken gate regardless of
which cap governs. The CI step that stages hook binaries MUST use the `--release` flag.
(ADR-035 §Decision 5.)

from `Cargo.toml`. The crate MUST use `serde_norway` for any YAML deserialization needs.
(YAML is not required for this hook — frontmatter is parsed via line-scanning regex as in
existing hook plugins — but the constraint is recorded to block inadvertent reintroduction.)

**`max_bytes` caps:** `host::read_file` calls MUST use the exact caps from

- `priority = 460`: next available slot after `validate-wave-handoff-completeness` (450);
  PostToolUse tier ordered ascending.
- `on_error = "continue"`: fuel exhaustion (ADR-035 §Decision 5) and crash → silent
  non-finding, not a spurious block. **The prior claim that the `max_bytes` caps "are
  calibrated to keep reads within the fuel budget" is RETRACTED as FALSE (BC-5.39.010
  v1.15, F-S2107-P9-002; propagated here per F-S2107-P12-001).** Measured fuel
  consumption against a production-scale BC-INDEX fixture (576,396 bytes / 1,985 rows)
  was `fuel_consumed = 9,920,913` against the then-operative 10,000,000-instruction cap —
  99.21% consumed, 79,087 fuel of headroom (0.79%). The 1 MiB `max_bytes` cap on PC4
  permits a file of 1,048,576 bytes, which is ~76% *above* the ~594 KB point at which the
  former 10M cap actually exhausted — the caps bounded nothing; they simply had not yet
  been exercised by a large-enough corpus. See the `fuel_cap` bullet below for the
  current cap figure and its source-HEAD-vs-operator-effective distinction (BC-5.39.010
  v1.19 §Gate Spec, F-S2107-P10-004).
- `tool = "^(Edit|Write|MultiEdit)$"`: aligns with all 41 Edit/Write hooks in the live

  regex `tool = "^(Edit|Write|MultiEdit)$"`. This AC traces to the BC-5.39.010 v1.19 §Gate Spec.
- `fuel_cap` field — **prohibition LIFTED (BC-5.39.010 v1.16 §Gate Spec, ADR-042

  retracted: its premise — that the existing `max_bytes` caps keep reads inside the fuel

### AC-022: Class A Arm1 — primary-newer-than-index is advisory only (traces to BC-5.39.010 postcondition 2a)

that BC ID still says `v1.5` (primary newer than index), the hook MUST emit
`host::log_warn` advisory and return `HookResult::Continue` (exit 0). This direction
reflects a POLICY 3 burst-ordering artefact: state-manager writes the BC-INDEX row AFTER
the product-owner writes the BC file; "index behind primary" is the guaranteed intermediate
state of every conforming burst and must not block correct authoring.

Under BC-5.39.010 v1.19 PC2a (unchanged since v1.14): primary-newer-than-index → advisory + Continue.

for <id> cites v<index_version> but frontmatter version: is \"<fm_version>\" — primary

### AC-024: Class B Arm1 — half-present case is advisory only (traces to BC-5.39.010 postcondition 13c)

When a story file is written with `input-hash: "d4f8a12"` in frontmatter (B1), and exactly
one of the two STORY-INDEX.md sites is present and differs from B1 — either the catalog row
(B2) is `"47a65c9"` (present and differs from B1) while the blockquote (B3) is absent, OR
B3 is present and differs from B1 while B2 is absent — the hook MUST emit `host::log_warn`
advisory and return `HookResult::Continue` (exit 0). The implementation MUST NOT block for
`(Some(b2), None)` or `(None, Some(b3))` cases.

Under BC-5.39.010 v1.19 PC13c (ADR-038 §Decision 3; unchanged since v1.14): the half-present case is an extension
of PC12's inclusive-or ("B2 or B3 absent"). The absent site cannot be verified at PostToolUse
trigger time; the present-but-differing site may reflect a mid-burst state where only one
STORY-INDEX update has completed. Blocking produces a self-lock on stories with permanently
missing blockquote entries (live instances: S-18.11, S-18.12) that have no burst-ordering
escape path. The long-term remedy is state-manager adding the missing blockquote entries, not
a hook block. This carve-out extends PC12's existing absent-site advisory to the
mixed-present/absent case.

- **Mutant test (B2 present and differs, B3 absent):**
  `test_BC_5_39_010_arm_b1_half_present_catalog_mismatch_is_advisory_not_block` —
  B1=d4f8a12, B2=47a65c9 (present, differs from B1), B3=absent → assert exit code 0
  (Continue), `host::log_warn` advisory emitted. The test name asserts advisory-not-block;
  a blocking implementation makes this test RED.
- **Mutant test (B3 present and differs, B2 absent):**
  `test_BC_5_39_010_arm_b1_half_present_blockquote_mismatch_is_advisory_not_block` —
  B1=d4f8a12, B2=absent, B3=47a65c9 (present, differs from B1) → assert exit code 0
  (Continue), `host::log_warn` advisory emitted. Symmetric to the B2 case; confirms both
  `(Some(b2), None)` and `(None, Some(b3))` are advisory.
- **Control test (B2 present and matches B1, B3 absent):**
  `test_BC_5_39_010_arm_b1_half_present_catalog_match_is_advisory` —
  B1=d4f8a12, B2=d4f8a12 (present, matches B1), B3=absent → assert exit code 0 (Continue),
  advisory emitted. Confirms that even when the present site agrees with B1, the absent-B3
  still triggers PC12 advisory (not the PC13c mismatch path, but the PC12 absent path).

## Forbidden Dependencies

The following MUST NOT appear in `crates/hook-plugins/validate-cross-site-correspondence/Cargo.toml`.
If any appears, the build MUST fail (CI enforces this via `cargo deny` or similar):

| Forbidden Crate | Reason |
|-----------------|--------|
| `serde_yaml` | Deprecated, archived 2024; workspace migrated to `serde_norway = "0.9"` via TD #72. Any import is a regression. |
| `wasmtime` | Hook plugins are WASM binaries; they must NOT link against wasmtime. Only the dispatcher binary links wasmtime. A hook crate depending on wasmtime creates a circular compile dependency. |
| `factory-dispatcher` | Same reason — binary crate; hook plugins must not depend on the dispatcher binary. |

Note: `serde_norway` is permitted (YAML deserialization if needed) but YAML parsing is
not required for this hook — frontmatter is extracted via line-scanning regex as in all
existing hook plugins. `serde` + `serde_json` (for payload deserialization) are permitted.
