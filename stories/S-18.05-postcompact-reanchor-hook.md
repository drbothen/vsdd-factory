# S-18.05: postcompact-reanchor.sh Advisory Hook — PostCompact re-anchor from git-sourced STATE.md

**Epic:** E-18 — Factory Context Durability (feature #173)
**Wave:** 3 (depends on S-18.00 for harness-version gate; no other product story deps)
**Depends on:** S-18.00
**Blocks:** S-18.07, S-18.08
**Priority:** P1 (best-effort advisory; closes DI-024 implementation gap)
**BC gate:** BC-7.07.002 v1.12 (draft; all postconditions in scope)
**Subsystem anchor:** SS-07 owns this story's scope because SS-07 is the Hook Bash Layer covering all `plugins/vsdd-factory/hooks/*.sh` scripts and their `hooks-registry.toml` registry entries per ARCH-INDEX Subsystem Registry.

## Narrative

- **As a** factory agent whose session context has been compacted by the Claude Code harness
- **I want** the `PostCompact` event to fire `postcompact-reanchor.sh`, which reads `current_cycle`, `current_step`, and `last_verified_develop_sha` from the `factory-artifacts` branch STATE.md via `git show` and emits a structured re-anchor block to stdout
- **So that** the LLM session can re-ground itself on externally persisted pipeline state after compaction may have corrupted in-context understanding — without this hook ever blocking, committing, or interrupting the session

## Behavioral Contracts

| BC ID | Title | Version | Postconditions Exercised |
|-------|-------|---------|--------------------------|
| BC-7.07.002 | postcompact-reanchor.sh fires on PostCompact (advisory only; best-effort; cannot block); emits re-anchor block to stdout from factory-artifacts STATE.md; logs to .factory/logs/; does NOT commit to factory-artifacts | v1.12 | postcondition 1 (re-anchor block to stdout; git-sourced), postcondition 2 (log written to .factory/logs/; 6 fields; no wave_id), postcondition 3 (cannot block compaction), postcondition 4 (does NOT commit to factory-artifacts), postcondition 5 (fail-open on any error), postcondition 6 (on_error=continue), postcondition 7 (compaction summary optional), invariant 1 (no factory-artifacts write), invariant 2 (git-sourced values) |

## Acceptance Criteria

### AC-001 (traces to BC-7.07.002 postcondition 1 — re-anchor block emitted to stdout; git-sourced; correct format)

The hook `plugins/vsdd-factory/hooks/postcompact-reanchor.sh` MUST emit a re-anchor block to stdout in the exact format:

```
[PostCompact Re-anchor] context=<current_cycle>/<current_step> sha=<last_verified_develop_sha>
Source: factory-artifacts STATE.md (verified at <ISO-timestamp>)
```

Where `<current_cycle>`, `<current_step>`, and `<last_verified_develop_sha>` are read from `factory-artifacts` via `git show factory-artifacts:.factory/STATE.md`, NOT from in-context LLM knowledge or any environment variable set by the LLM. There is NO `current_wave:` field on STATE.md — the hook MUST NOT reference or emit one.

**Test (bats):** `test_postcompact_reanchor_emits_anchor_block_with_git_sourced_values()`
— Setup: `factory-artifacts` STATE.md has `current_cycle: v1.0-feature-context-durability-E18`, `current_step: S-18.04`, `last_verified_develop_sha: abc123def456`.
— Assert: stdout contains `[PostCompact Re-anchor] context=v1.0-feature-context-durability-E18/S-18.04 sha=abc123def456`; stdout contains `Source: factory-artifacts STATE.md`; stdout does NOT contain `current_wave`.

### AC-002 (traces to BC-7.07.002 postcondition 2 — log appended; 6 fields; no wave_id)

The hook MUST append a structured JSONL log entry to `.factory/logs/postcompact-reanchor-YYYY-MM-DD.jsonl` with exactly 6 fields: `event`, `current_cycle`, `current_step`, `last_verified_develop_sha`, `timestamp`, `status` ("ok" or "warn"). There is NO `wave_id` field in the log entry.

**Test (bats):** `test_postcompact_reanchor_appends_jsonl_log_with_correct_fields_no_wave_id()`
— Invoke hook with valid `factory-artifacts` STATE.md fixture.
— Assert: daily log file has one new JSONL line; line is valid JSON with all 6 required fields; line does NOT contain `wave_id`; `status` is `"ok"` on happy path.

### AC-003 (traces to BC-7.07.002 postcondition 3 — cannot block compaction)

The hook's exit code MUST NOT prevent or reverse compaction. PostCompact is advisory-only in the Claude Code harness; the hook MUST NOT rely on exit-code semantics for any correctness guarantee. Even if the hook exits with a non-zero code (which AC-008 prohibits), the PostCompact event is processed regardless.

**Test (bats):** `test_postcompact_reanchor_cannot_block_compaction()`
— Assert: hook exits 0 on happy path (harness ignores block-intent on PostCompact per BC-7.07.002 PC3); no `block_intent=true` emitted by the hook; session continues after hook invocation.

### AC-004 (traces to BC-7.07.002 postcondition 4 — does NOT commit to factory-artifacts; invariant 1 absolute prohibition)

The hook MUST NOT execute `git commit`, `git push`, `git add`, or any write operation targeting `factory-artifacts`. It reads from `factory-artifacts` via `git show` but produces NO write side effects on the branch.

**Test (bats):** `test_postcompact_reanchor_does_not_commit_to_factory_artifacts()`
— Capture `factory-artifacts` HEAD before hook invocation.
— Invoke hook.
— Assert: `factory-artifacts` HEAD is unchanged; no staged changes exist on `factory-artifacts`; no `git commit` command appears in hook source.

### AC-005 (traces to BC-7.07.002 postcondition 5 + edge case EC-002 — fail-open on factory-artifacts unreachable)

When `factory-artifacts` is unreachable or `git show` fails, the hook MUST:
1. Emit an advisory to stdout: `[PostCompact Re-anchor] WARN: factory-artifacts unreachable; re-anchor skipped`.
2. Append a log entry with `status: "warn"`.
3. Exit 0.

**Test (bats):** `test_postcompact_reanchor_exits_0_and_warns_on_factory_artifacts_unreachable()`
— Setup: disable git access (e.g., use a non-existent directory).
— Assert: exit 0; stdout contains `[PostCompact Re-anchor] WARN: factory-artifacts unreachable`; daily log has `status: "warn"` entry.

### AC-006 (traces to BC-7.07.002 edge case EC-003 — STATE.md fields absent: emit context=UNKNOWN; exit 0)

When `factory-artifacts` STATE.md is present but `current_cycle:` or `current_step:` fields are absent, the hook MUST emit `context=UNKNOWN` in the re-anchor block and exit 0.

**Test (bats):** `test_postcompact_reanchor_emits_context_unknown_when_fields_absent()`
— Setup: `factory-artifacts` STATE.md exists but has no `current_cycle:` or `current_step:` fields.
— Assert: exit 0; stdout contains `context=UNKNOWN`; log entry has `status: "warn"`.

### AC-007 (traces to BC-7.07.002 edge case EC-005 — log directory missing: attempt create; fail-open)

When `.factory/logs/` does not exist, the hook MUST attempt to create it. If creation fails (e.g., read-only filesystem), the hook MUST fall back to stdout-only advisory and exit 0.

**Test (bats):** `test_postcompact_reanchor_exits_0_when_log_dir_creation_fails()`
— Setup: `.factory/logs/` does not exist; filesystem is read-only.
— Assert: exit 0; stdout contains advisory; no unhandled error.

### AC-008 (traces to BC-7.07.002 postcondition 5 + postcondition 6 — exit 0 on ALL error paths)

The hook MUST exit 0 under ALL conditions, including: `factory-artifacts` unreachable, STATE.md absent, `current_cycle:`/`current_step:` absent, log dir creation failure, and hook crash (`on_error=continue`). Exit 2 from this hook is a specification violation per DI-024.

**Test (bats):** `test_postcompact_reanchor_exits_0_on_all_error_paths()`
— Run hook with each error scenario (unreachable factory-artifacts, missing STATE.md fields, unwritable log dir) in sequence.
— Assert: exit 0 in each case; no non-zero exit code for any scenario.

### AC-009 (traces to BC-7.07.002 invariant 2 — values sourced from factory-artifacts; not in-context; no current_wave phantom field)

The hook MUST read `current_cycle:` and `current_step:` from `git show factory-artifacts:.factory/STATE.md`, never from the LLM's in-context knowledge, environment variables set by the LLM, or any other source. There is no `current_wave:` field on STATE.md — the hook MUST NOT emit one.

**Test (bats):** `test_postcompact_reanchor_values_are_git_sourced_not_in_context()`
— Setup: `factory-artifacts` STATE.md has `current_cycle: A`; a stale in-memory environment variable `CURRENT_CYCLE=B` is set.
— Assert: stdout output contains `context=A/...` (git value), not `context=B/...` (environment variable); `current_wave` not present in output.

### AC-010 (traces to BC-7.07.002 precondition 1 — hooks-registry.toml PostCompact entry correct shape)

The `hooks-registry.toml` entry for `postcompact-reanchor` MUST be present with the exact canonical shape:

```toml
[[hooks]]
name = "postcompact-reanchor"
event = "PostCompact"
plugin = "hook-plugins/legacy-bash-adapter.wasm"
priority = 100
timeout_ms = 10000
on_error = "continue"
async = false

[hooks.config]
script_path = "hooks/postcompact-reanchor.sh"
```

`on_error = "continue"` is mandatory. `plugin` MUST be `"hook-plugins/legacy-bash-adapter.wasm"` (the canonical bash adapter for shell hooks). No other fields in `[hooks.config]` beyond `script_path`.

**Test (bats):** `test_postcompact_reanchor_registry_entry_has_correct_shape()`
— Assert: `grep -A 10 'name = "postcompact-reanchor"' plugins/vsdd-factory/hooks-registry.toml` produces the expected block; `on_error = "continue"` present; `event = "PostCompact"` present; `plugin = "hook-plugins/legacy-bash-adapter.wasm"` present.

## Architecture Compliance Rules

1. **No factory-artifacts writes (BC-7.07.002 Inv1):** Any `git commit`, `git push`, or `git add` to `factory-artifacts` in the hook source is a specification violation — not a warning, a violation. Test AC-004 MUST verify HEAD is unchanged.
2. **Git-sourced values only (BC-7.07.002 Inv2):** `current_cycle:`, `current_step:`, `last_verified_develop_sha:` values MUST be read from `git show factory-artifacts:.factory/STATE.md`. No environment variables, no in-context reads.
3. **No `current_wave:` field:** STATE.md has no `current_wave:` frontmatter field. The hook MUST NOT reference it. Emitting `wave=...` in the re-anchor block is a specification violation.
4. **Log schema exactly 6 fields (BC-7.07.002 PC2):** The JSONL log entry has exactly `event`, `current_cycle`, `current_step`, `last_verified_develop_sha`, `timestamp`, `status`. No `wave_id`. Adding extra fields is not a violation but removing any of the 6 is.
5. **Exit 0 unconditionally (BC-7.07.002 PC5/DI-024):** The hook MUST exit 0 on every code path. Trapping `set -e` errors and exiting 0 is the correct implementation pattern (e.g., `git show ... 2>/dev/null || { warn_stdout; exit 0; }`).
6. **`on_error = "continue"` in registry (BC-7.07.002 PC6):** This is the harness-level fail-open guarantee. The hook's own exit-0 discipline provides defense-in-depth.
