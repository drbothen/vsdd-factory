## Narrative

As an operator or factory orchestrator invoking `check-state-health`,
I want the skill to verify that `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` is present in
`settings.json` (project-local `.claude/settings.json` preferred; global
`~/.claude/settings.json` as fallback) and that its value does not exceed 80,
so that I am alerted when the proactive compaction threshold required by ADR-026
§Decision 5 is absent or misconfigured — preventing silent context-window saturation
that would undermine the PreCompact flush safety net that CAP-032 depends on.

| BC-6.25.001 | check-state-health verifies CLAUDE_AUTOCOMPACT_PCT_OVERRIDE in settings.json and emits advisory if absent or value exceeds 80 | v1.1 | PC1, PC2, PC3, PC4, PC5, INV1–INV5, EC-012 |

## Acceptance Criteria

### AC-001 (traces to BC-6.25.001 postcondition 1 — key absent: emit advisory)
When `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` is absent from the `env` block of the
resolved `settings.json` (or no `settings.json` exists), `check-state-health`
emits an advisory row in the check table:
- Check name: `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`
- Status: `ADVISORY`
- Details: `"Missing — add env: {CLAUDE_AUTOCOMPACT_PCT_OVERRIDE: \"70\"} to .claude/settings.json (ADR-026 §Decision 5: proactive compaction threshold; 70% gives PreCompact flush headroom)"`
The advisory does NOT block any subsequent checks or the overall skill output.

### AC-002 (traces to BC-6.25.001 postcondition 2 — key present, value > 80: emit advisory)
When `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` is present in the `env` block but its
numeric value exceeds 80, `check-state-health` emits an advisory row:
- Check name: `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`
- Status: `ADVISORY`
- Details: `"Value <N> exceeds ADR-026 §Decision 5 ceiling of 80 (MEDIUM-confidence 83% harness cap); recommend 70 for safe PreCompact flush headroom"`
where `<N>` is the actual configured value. The advisory does NOT block.

### AC-003 (traces to BC-6.25.001 postcondition 3 — key present, value ≤ 80: GREEN)
When `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` is present and its numeric value is ≤ 80,
`check-state-health` emits a passing row:
- Check name: `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`
- Status: `PASS`
- Details: `"Present, value <N> ≤ 80 (70 is canonical per ADR-026 §Decision 5)"` where `<N>` is the actual value.
No advisory is emitted. The canonical value 70 satisfies this check (70 ≤ 80).

### AC-004 (traces to BC-6.25.001 postcondition 4 — settings.json path resolution precedence)
The skill resolves the settings.json path with the following precedence:
1. Project-local: `.claude/settings.json` relative to the project root (directory
   containing `.factory/`). If this file exists and is readable, it is authoritative.
2. Global: `~/.claude/settings.json`. Used only when the project-local file does
   not exist.
3. Neither present: treated as key-absent (AC-001 advisory fires); the advisory
   additionally notes `"(no settings.json found at .claude/settings.json or ~/.claude/settings.json)"`.
When BOTH files exist, the global file is NEVER consulted for this check — project-local
always takes precedence (BC-6.25.001 INV2; mirrors Claude Code settings resolution order).

### AC-005 (traces to BC-6.25.001 postcondition 5 — advisory-only semantics; non-blocking)
This check is a diagnostic advisory. It does NOT cause the skill to exit with a
non-zero status, does NOT block the calling session, and does NOT block any E-18
skill or pipeline operation. The overall skill result (`HEALTHY`, `WARNINGS`,
`NEEDS-COMPACT`) MAY be elevated to `WARNINGS` when this advisory fires — consistent
with existing check-state-health advisory escalation semantics. It does NOT cause
`NEEDS-COMPACT`. The gate MUST NOT emit exit 2, set block_intent=true, or prevent
any downstream operation (BC-6.25.001 INV1).

### AC-006 (traces to BC-6.25.001 invariant 3 — numeric value comparison, valid range 1–100)
The `env` block value for `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` in `settings.json` is
a string (JSON strings for env values). The skill parses the string as a decimal
integer for comparison. Non-numeric or empty values (e.g., `""`, `"auto"`) are
treated as absent (AC-001 fires) with a note in the advisory:
`"Value '<raw>' is not a valid integer; treating as absent"`.
The valid integer range is **1–100 inclusive**. A parsed integer value ≤ 0 (zero or
negative) is out-of-range: it emits a distinct ADVISORY row (see AC-008/EC-012) —
distinct in message from the PC2 ceiling advisory (value > 80) and from the PC1
non-numeric "treating as absent" advisory.

### AC-008 (traces to BC-6.25.001 invariant 3 — value ≤ 0 out-of-range: emit distinct ADVISORY — EC-012)
When `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` is present and its parsed integer value is ≤ 0
(e.g., `"0"` or `"-5"`), `check-state-health` emits a distinct ADVISORY row:
- Check name: `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`
- Status: `ADVISORY`
- Details: `"Value <N> is not a valid compaction percentage (must be in range 1–100); treating as misconfigured — recommend 70 per ADR-026 §Decision 5"`
  where `<N>` is the actual parsed value (e.g., `0` or `-5`).
This advisory is distinct from the PC2 ceiling advisory (`value > 80`) and from the
PC1 non-numeric "treating as absent" advisory. It never blocks (BC-6.25.001 INV1).

### AC-007 (traces to BC-6.25.001 invariant 5 — row always emitted)
A check table row for `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` MUST always appear in the
`check-state-health` output table — `PASS`, `ADVISORY`, or error-notation. Silent
omission of the row is a specification violation.

## Architecture Compliance Rules

1. **Advisory-only, never blocking (BC-6.25.001 INV1):** The check MUST NOT emit
   exit 2, set block_intent=true, or prevent any downstream operation. Any implementation
   that blocks is a specification violation.
2. **Project-local precedence (BC-6.25.001 INV2):** `.claude/settings.json` always
   takes precedence over `~/.claude/settings.json`. Both are read only if project-local
   is absent.
3. **Numeric parse only (BC-6.25.001 INV3):** String-to-int conversion with non-numeric
   treated as absent.
4. **No side effects (BC-6.25.001 INV4):** Read settings.json only; no writes, no
   factory-artifacts writes, no dispatcher log emissions.
5. **Row always emitted (BC-6.25.001 INV5):** A check row MUST appear in every
   check-state-health invocation regardless of settings.json state.
6. **`set -euo pipefail`** in all new bash scripts (CLAUDE.md convention).
7. **No `--no-verify` git flags** (though this story has no git operations).

## Library and Framework Requirements

- bash >= 4.x (available in CI)
- `jq` — required toolchain per `plugins/vsdd-factory/skills/setup-env/SKILL.md`; used for `settings.json` parsing. If `jq` is absent at runtime the check degrades to an ADVISORY row (never fatal, consistent with BC-6.25.001 INV1). **Do NOT use `python3 -c` or ad-hoc string parsing** — the converged implementation uses `jq` with graceful degrade.
- bats-core: version already in use by `plugins/vsdd-factory/tests/`
