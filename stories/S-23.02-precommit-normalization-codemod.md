# S-23.02: Pre-commit normalization codemod

## Narrative

- **As a** state-manager/consistency-validator running the mechanical corpus migration
  (S-23.06..S-23.13)
- **I want** a Rust CLI tool that, given a file or set of files, strips load-bearing inline
  version tokens from cross-references in live sections and converts them to stable-anchor
  form, while leaving exempt/historical sections untouched
- **So that** the ~3,074 live pins across 156 files can be migrated mechanically and
  idempotently, one document-class commit at a time, without hand-editing every citation

## Context / Problem Statement

ADR-045 §Alternatives Considered explicitly adopts "Pre-commit normalization codemod + thin
new-pin guard, without the full Tier-3 AST validator" as the Phase-A build target (not the
heavier AST-validator alternative), per the independent validation's Claim 6/R5 finding that the
correct-by-construction win lives almost entirely in Tier 1 and the guard/codemod pair captures
most of the benefit at a fraction of the cost. This story builds that codemod: a one-shot tool
that strips patterns shaped like
`\b(ADR-\d+|BC-\d+(?:\.\d+)+|S-\d+\.\d+|VP-\d+)\b .{0,N}? \bv\d+(?:\.\d+)*\b` from live sections
identified by S-23.01's classifier, converting e.g. `BC-1.03.017 v1.27` → `BC-1.03.017` and
`ADR-039 §Decision 3 v1.10` → `ADR-039 §Decision 3`.

The tool MUST run in dry-run/diff-report mode as well as apply mode, MUST be idempotent (running
it twice produces no further change), and MUST correctly execute the newline-normalized pass
required for the ~30–40 anchor-interposed/line-wrapped ADR pins (ADR-045 §Migration Plan Phase A
step 5). A naive per-physical-line codemod will miss these; the codemod must consume S-23.01's
`detect_pins` output (which already normalizes across line-wraps and tolerates interposed
anchors) rather than re-implementing its own simpler pattern match.

## Acceptance Criteria

### AC-001
Given a file with a live-section citation `BC-1.03.017 v1.27`, running the codemod in apply mode
rewrites it to `BC-1.03.017` and leaves everything else in the file byte-identical. (traces to
ADR-045 §Decision, Tier 1, "Prohibited forms" → "Permitted forms" conversion)

### AC-002
Given a file with an anchor-interposed citation `ADR-039 §Decision 3 v1.10`, running the codemod
rewrites it to `ADR-039 §Decision 3`, preserving the `§Decision 3` anchor. (traces to ADR-045
§Migration Plan Phase A step 5, "newline-normalized" pass requirement; ADR-045 §Context failure
mode 2)

### AC-003
Given a file with a line-wrapped citation (ID at end of one physical line, version token at
start of the next), running the codemod rewrites it to remove the version token while preserving
the original line-wrap position of the surrounding prose (i.e., the codemod does not
re-flow/re-wrap paragraphs it did not need to touch). (traces to ADR-045 §Context failure mode
1; ADR-045 §Migration Plan Phase A step 5)

### AC-004
Given a file with a `modified:` frontmatter array entry, a `[Prior: ...]` changelog-chain
suffix, or a `## Changelog` table row citing a specific historical version, running the codemod
leaves that content byte-identical (it is exempt per S-23.01 AC-001). (traces to ADR-045
§Decision, Tier 1, "Permitted exceptions" bullet list)

### AC-005
Running the codemod twice in sequence on the same file produces no diff on the second run
(idempotence). (traces to ADR-045 §Migration Plan Phase A step 5, "mechanical corpus migration"
— implicit idempotence requirement for a tool run across 156 files in a phased, per-document-
class commit sequence)

### AC-006
The codemod supports a `--dry-run` mode that reports every proposed change (file, line, before,
after) without writing any file, and an `--apply` mode that writes the changes. (traces to
ADR-045 §Migration Plan Phase A step 5, "one atomic commit per document class" — dry-run enables
per-document-class review before commit)

### AC-007
The codemod accepts a file-list or glob argument scoped to a single document class (e.g., all
files under `.factory/specs/behavioral-contracts/**`), so state-manager/consistency-validator
can invoke it once per document class per TD-VSDD-053 single-commit-per-burst discipline. (traces
to ADR-045 §Migration Plan Phase A step 5, "one atomic commit per document class to respect
TD-VSDD-053")

### AC-008 (negative control)
Given a file with a version-token-looking string inside a fenced code block (e.g., a Cargo
dependency pin), the codemod does NOT modify it — code fences are excluded from live-section
scanning by S-23.01's classifier. (traces to S-23.01 EC-003; ADR-045 §Decision, Tier 3 item 2,
"Excludes ... all code blocks" — applied at this story's lighter tier)

| Module | Classification | Justification |
|--------|-----------------|----------------|
| `xref-codemod::rewrite_pins` | pure-core | Computes a rewrite plan from `&str` + findings; no I/O |
| `xref-codemod::main` (CLI shell) | effectful-shell | Reads files from disk, invokes S-23.01's detector, applies `rewrite_pins`'s plan, writes files or prints a diff report |

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|--------------------|
| EC-001 | File has zero live pins to strip | Codemod reports "no changes" and exits 0; does not touch the file's mtime unnecessarily |
| EC-002 | File does not exist / path typo in the glob | Codemod reports a clear error for that path and continues processing the rest of the file list (does not abort the whole batch) |
| EC-003 | Two overlapping candidate matches on the same line (e.g., a malformed double citation) | Codemod applies the leftmost, longest match first and re-scans; never produces overlapping edits that corrupt the line |
| EC-004 | A version token that is part of a URL (e.g., `https://.../v1.2.3/...`) | Not misidentified as a load-bearing pin — S-23.01's ID-prefix requirement (`BC-`/`ADR-`/`S-`/`VP-` immediately preceding) prevents false positives on bare version-looking substrings |

## Previous Story Intelligence

**From S-23.01:** the classifier and detector are pure functions with no I/O; this story's CLI
shell is the first place in E-23 that touches the filesystem, and it must not duplicate S-23.01's
tokenization/exemption logic — any codemod-specific pattern matching beyond byte-range deletion
(computed from S-23.01's `PinFinding` results) is a signal the two tools' definitions of
"load-bearing" have drifted and must be corrected by extending S-23.01's crate, not by adding a
second implementation here.

## Architecture Compliance Rules

- `rewrite_pins` MUST be pure (no I/O); only `main.rs`'s CLI shell touches the filesystem.
- No `unwrap()`/`expect()` on user-supplied file paths — a missing or unreadable file must
  produce a named error variant and a per-file continuation (EC-002), not a panic.
- No `println!` in the pure module; the CLI shell may use `println!` for its diff-report/CLI
  output (CLAUDE.md Conventions permit `println!` in CLI formatting helpers).
- MUST NOT modify `.factory/policies.yaml`, `.factory/STATE.md`, or any of the 4 INDEX files'
  own governance metadata beyond the inline pin text itself — this tool only rewrites citation
  text; it is not a general-purpose editor.
