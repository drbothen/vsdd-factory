# S-7.12 — CHANGELOG delivery discipline — retroactive BC-8.31.001 traceability and two cosmetic follow-up fixes

**Epic:** E-7 — Process Codification (Self-Improvement)
**Source:** BC-8.31.001, PR #714 (`fix(templates): add mandatory CHANGELOG delivery task to story template`), D-879 burst
**Owner:** story-writer (retroactive traceability registration) / spec-steward (RELEASING.md wording) / implementer (bump-version.sh fix)
**Priority:** P2 (follow-up cosmetic fixes; main behavior shipped by PR #714)
**Subsystem anchor:** SS-08 (Template Catalog) + SS-10 (Release Scripts)

## Narrative

- **As a** vsdd-factory implementer following the story template
- **I want** the mandatory CHANGELOG delivery discipline (task 12: add a `## [Unreleased]` entry before creating the PR) to be anchored to BC-8.31.001 and for two cosmetic follow-up issues from the re-review to be resolved
- **So that** BC-8.31.001 has a tracking story, the bats regression guards remain authoritative, and the RELEASING.md invariants table and bump-version.sh stub generator are cosmetically correct

PR #714 (`fix(templates): add mandatory CHANGELOG delivery task to story template`) introduced the CHANGELOG delivery discipline across all seven artifacts governed by BC-8.31.001: the story template (task 12), story-writer.md, create-story/SKILL.md, CHANGELOG.md structural invariant (`## [Unreleased]` first H2), bump-version.sh anchor preservation, RELEASING.md drain documentation, and two bats regression guards in template-compliance.bats. The core behavior is fully implemented.

A re-review of PR #714 surfaced two non-blocking cosmetic issues that were not gated for the merge but should be resolved in a follow-up:

1. **bump-version.sh printf cosmetic (AC-007):** The STUB format string at line 110 ends with `\n\n` (two trailing newlines). When `printf '%s' "$STUB"` outputs the STUB followed immediately by `tail -n +3 "$CHANGELOG"`, the STUB's trailing `\n\n` creates one blank line before the existing CHANGELOG content. A `printf '%s\n\n'` callsite (two additional newlines after the stub) would produce a triple-blank-line gap. The fix is to ensure no `printf '%s\n\n'` pattern exists in the stub-generation path and to confirm the STUB's trailing blank is exactly one newline (not two).

2. **RELEASING.md invariants table precision (AC-008):** The invariants table entry reads `CHANGELOG.md has a ## <full-semver> heading at the top`. This wording pre-dates the PR #714 restructuring. After PR #714, the first H2 in CHANGELOG.md is `## [Unreleased]` (not the version heading). The `release.yml` validation step uses `grep -qE "^## ${TAG_VERSION}"` which checks for the heading anywhere in the file, not specifically at the top. The wording `"at the top"` is now misleading; it should say "present in the file" (matching actual enforcement) and optionally note that `## [Unreleased]` must remain the first H2 (per BC-8.31.001 PC-5).
