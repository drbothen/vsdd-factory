# S-17.01: factory_lock STATE.md Frontmatter Schema + state-burst Fetch-then-CAS Push

**Epic:** E-17 — Factory State Durability and Concurrency (brownfield-backfill #170)
**Wave:** 1 (no dependencies — delivers immediately)
**Blocks:** S-17.02 (guard reads schema), S-17.03 (skills write schema)
**Priority:** P1 (closes primary blind-push gap independently of the guard)
**BC gate:** BC-5.40.001 v1.0 (draft; POL-14 auto-promotion on PR merge)

## Narrative

- **As a** factory `state-manager` agent pushing to the `factory-artifacts` orphan branch
- **I want to** store the authoritative cross-session lock state in a canonical
  `factory_lock` frontmatter block in STATE.md and push that branch using a
  fetch-then-`--force-with-lease` CAS primitive
- **So that** (a) the lock record is human-readable, travels with the branch, and is
  available to all readers including the WASM guard, and (b) concurrent pushes from any
  source — another developer, a guard-crash fail-open scenario, or a self-vs-self
  two-session case — are detected as collisions rather than silently clobbering remote
  state

## Acceptance Criteria

### AC-001 (traces to BC-5.40.001 postcondition PC1 — schema correctness)

When `state-manager` writes a lock record (via the `/factory-lock` acquire path —
implemented in S-17.03), the resulting STATE.md frontmatter MUST contain a well-formed
`factory_lock` block:
```yaml
factory_lock:
  holder: "<exact git config user.email output>"
  locked_at: "YYYY-MM-DDTHH:MM:SSZ"
  expires_at: "YYYY-MM-DDTHH:MM:SSZ"  # locked_at + exactly 2700 seconds
```
All three fields MUST be present; `holder` MUST be the trimmed (trailing-newline-only
removal) output of `git config user.email`; `locked_at` and `expires_at` MUST be
ISO-8601 UTC (format `YYYY-MM-DDTHH:MM:SSZ`); `expires_at` MUST equal `locked_at +
2700s` exactly.

**Error variant on violation:** `SchemaViolation`
**Test:** `factory-lock-write.bats` — `test_BC_5_40_001_schema_correctness_on_acquire`

### AC-002 (traces to BC-5.40.001 postcondition PC2 — unlock clears block)

When `state-manager` writes an unlock, the `factory_lock` key MUST be absent from
STATE.md frontmatter entirely after the write. A null placeholder
(`factory_lock: null`) is NOT an acceptable representation — the key must be removed.

**Error variant on violation:** `StaleNullBlock`
**Test:** `factory-lock-write.bats` — `test_BC_5_40_001_unlock_removes_key_not_nulls`

### AC-003 (traces to BC-5.40.001 postcondition PC3 — TTL auto-expiry guard pass)

When `factory_lock.expires_at` is in the past at the time the guard checks
(BC-4.13.001 PC2), the lock is treated as absent and the operation proceeds.
The expired block remains in STATE.md until the next `state-manager` write (which
either refreshes or removes it). The schema definition in STATE.md is the precondition
for this behavior — the `expires_at` field MUST be present and valid for expiry
comparison to work.

**Test:** `factory-lock-write.bats` — `test_BC_5_40_001_ttl_expired_block_persists_until_next_write`

### AC-004 (traces to BC-5.40.001 postcondition PC4 — mid-burst TTL renewal)

At EVERY intermediate `state-manager` commit within a burst while a lock is held,
`state-manager` MUST refresh `factory_lock.expires_at = now + 2700s` alongside the
commit payload. The renewal MUST be atomic with the same commit. The `locked_at` field
MUST remain unchanged (it records the original acquire instant, not the last renewal).

After a 3-commit burst (each committing intermediate STATE.md changes), the final
`expires_at` MUST be `≈ now + 2700s` measured from the last commit (not from the
original `locked_at`).

**Error variant on violation:** `RenewalMissed`
**Test:** `factory-lock-write.bats` — `test_BC_5_40_001_mid_burst_renewal_updates_expires_at_preserves_locked_at`

### AC-005 (traces to BC-5.40.001 postcondition PC5 — state-burst CAS push)

The `state-burst` skill's push command MUST be replaced from:
```bash
git push origin factory-artifacts
```
to an invocation of `plugins/vsdd-factory/bin/factory-cas-push.sh` which internally
executes:
```bash
git -C .factory fetch origin factory-artifacts
EXPECTED_SHA=$(git -C .factory rev-parse origin/factory-artifacts)
git -C .factory push --force-with-lease=factory-artifacts:"${EXPECTED_SHA}" origin factory-artifacts
```

When the CAS push is rejected (non-zero exit from `--force-with-lease`), the helper
MUST exit non-zero and emit the human-readable error:
```
state-burst CAS push failed — concurrent write detected.
Fetch origin/factory-artifacts and retry.
```
The remote state MUST NOT be silently clobbered.

**Error variant on rejection:** `CASPushRejected`
**Test:** `factory-cas-push.bats` — `test_BC_5_40_001_cas_push_rejected_on_concurrent_write`

### AC-006 (traces to BC-5.40.001 postcondition PC6 — single-developer zero friction)

A developer who holds the lock and runs normal `state-manager` burst operations sees
no added friction. The guard (BC-4.13.001 PC3 — implemented in S-17.02) reads STATE.md
locally (sub-5ms), compares identities, and returns `Continue` on self-held lock
immediately. This story is responsible for the schema being present and well-formed so
that the guard can correctly identify the self-held case.

A developer who has NOT run `/factory-lock` operates with `factory_lock` absent —
the guard reads absent block and passes all checks (BC-4.13.001 PC4 fail-open path).

**Test:** `factory-lock-write.bats` — `test_BC_5_40_001_absent_block_is_unlocked_state`

### AC-007 (traces to BC-5.40.001 invariant 2 — default TTL is 45 minutes)

The TTL constant used by `factory-lock-write.sh` when writing `expires_at` MUST be
exactly 2700 seconds (45 minutes). This constant MUST NOT be configurable by users.
Any invocation path that computes `expires_at` MUST use this constant directly:
`expires_at = now + 2700s`.

**Test:** `factory-lock-write.bats` — `test_BC_5_40_001_ttl_constant_is_2700_seconds`

### AC-008 (traces to BC-5.40.001 invariant 3 — expires_at always = now + 2700s at write time)

Whether the write is the initial acquire, a mid-burst renewal, or any state-manager
write that refreshes the lock, `expires_at` MUST be computed as the wall-clock instant
of the commit + 2700 seconds. The `locked_at` field is immutable after acquire.

Specifically: on acquire, BOTH `locked_at` and `expires_at` MUST be derived from the
SAME captured epoch instant (one `date -u` call, not two independent calls). This means
`expires_at - locked_at` MUST equal EXACTLY 2700 seconds with zero tolerance — no
clock-skew between the two fields is acceptable because they are computed from one
captured instant, not two separate measurements.

**Error variant on violation:** `SchemaViolation` (invariant 3)
**Test:** `factory-lock-write.bats` — `test_BC_5_40_001_expires_at_derived_from_captured_locked_at`
(assert: parse `locked_at` and `expires_at` from the written frontmatter as epoch integers;
assert `expires_at_epoch - locked_at_epoch == 2700` exactly; this is distinct from
`test_BC_5_40_001_ttl_constant_is_2700_seconds` which verifies the TTL constant value —
this test verifies the implementation uses a SINGLE epoch capture, not two independent
`date` calls that could diverge by 1 second under a second boundary)

### AC-009 (traces to BC-5.40.001 invariant 5 — force-with-lease already permitted)

The existing `plugins/vsdd-factory/hooks/verify-git-push.sh` hook MUST NOT require
modification for the CAS push. `--force-with-lease` is already in the push-hook
allow-list (ADR-025 §Decision 8 source verification). The story's implementation
MUST NOT modify `verify-git-push.sh`.

**Test:** `factory-cas-push.bats` — `test_BC_5_40_001_verify_git_push_hook_unchanged`
(bats: confirm `hooks/verify-git-push.sh` permits `--force-with-lease` before and
after this story's changes — contents diff MUST be empty for that file)

### AC-010 (traces to BC-5.40.001 edge case EC-003 — fetch failure before CAS push)

When `git fetch origin factory-artifacts` fails (non-zero exit) during the state-burst
CAS push sequence, `factory-cas-push.sh` MUST exit non-zero and emit:
```
state-burst CAS push failed — fetch error before push. Retry after resolving network.
```
The push MUST NOT proceed with a potentially stale `EXPECTED_SHA`.

**Test:** `factory-cas-push.bats` — `test_BC_5_40_001_fetch_failure_aborts_push`

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | `state-manager` crashes mid-burst before writing `expires_at` renewal | Existing `expires_at` remains; auto-expires at TTL boundary (max 45-min wedge); next developer can acquire |
| EC-002 | `state-burst` CAS push rejected (concurrent write) | Non-zero exit; `CASPushRejected` error emitted; local `.factory/` commit preserved; developer fetches and re-runs |
| EC-003 | `git fetch origin factory-artifacts` fails (network error) | Non-zero exit; error emitted; push MUST NOT proceed (per AC-010) |
| EC-004 | `EXPECTED_SHA` fetch succeeds but remote advances before push | `--force-with-lease` rejects push; `CASPushRejected`; safe — no clobber |
| EC-005 | Lock held by self; `expires_at` within 5 minutes of current time | Mid-burst renewal MUST still refresh `expires_at = now + 2700s` on the next commit; approaching expiry does not trigger any special behavior |
| EC-006 | STATE.md `factory_lock` block has `holder`, `locked_at`, `expires_at` but additional unknown fields | Unknown fields are ignored (fail-open to unlocked is NOT triggered; the block is valid if the three required fields are present and parseable) |
| EC-007 | Factory is unlocked (`factory_lock` absent); `state-burst` CAS push proceeds | Fetch + CAS push proceeds normally; if remote has advanced (another developer pushed), `CASPushRejected` error; developer fetches and retries |
| EC-008 | `git -C .factory rev-parse origin/factory-artifacts` returns a SHA that does not exist locally after fetch | This condition has two sub-cases, each guarded and tested: (a) rev-parse FAILS / ref unresolvable after fetch — **Test:** `factory-cas-push.bats` — `test_BC_5_40_001_cas_push_stale_sha_after_fetch` (stub `rev-parse` to exit non-zero; assert non-zero helper exit + error in stderr); (b) rev-parse SUCCEEDS but the SHA's object is absent locally (the BC-5.40.001 EC-008 literal condition — fetch/parse race) — **Test:** `factory-cas-push.bats` — `test_BC_5_40_001_cas_push_object_absent_after_fetch` (stub `rev-parse` to return a SHA not present in the local object store; assert non-zero exit + "stale SHA after fetch" detail in stderr). In both cases `factory-cas-push.sh` MUST exit non-zero and emit `CASPushRejected`. |
| EC-009 | Long burst: 3 intermediate commits, each refreshing `expires_at`; total burst duration ≈ 70 min | Lock remains valid throughout: each commit resets `expires_at = now + 45 min`; `locked_at` UNCHANGED across all three renewals; at burst-end, `expires_at` is 45 minutes from the last commit; **Test:** `factory-lock-write.bats` — `test_BC_5_40_001_three_sequential_renewals_preserve_locked_at` (invoke `factory-lock-write.sh renew` three times on a fixture; assert `locked_at` is identical across all three; assert each `expires_at` is later than the previous) |

## Architecture Compliance Rules

From `architecture/module-decomposition.md` and ADR-025 v1.2:

1. **`state-manager` is the SOLE writer of `factory_lock`** (TD-VSDD-053 single-writer
   discipline). No other agent, skill, or tool writes the `factory_lock` block directly.
   Skills delegate to `state-manager`. The helpers (`factory-lock-write.sh`,
   `factory-cas-push.sh`) are TOOLS invoked BY `state-manager` — they do not circumvent
   the single-writer rule; they make the mechanical parts of that obligation testable.

2. **`factory_lock` MUST be removed entirely (not nulled) on unlock.** A null value
   (`factory_lock: null`) violates BC-5.40.001 PC2. `factory-lock-write.sh clear` MUST use
   key deletion, not value assignment. The bats test verifies this distinguishes `absent`
   from `null`.

3. **`--force-with-lease` is already permitted by `hooks/verify-git-push.sh`** (ADR-025
   Decision 8). No changes to the push-hook allow-list are required or permitted by this
   story. `verify-git-push.sh` MUST be unchanged. `factory-cas-push.sh` uses the
   `--force-with-lease=<refname>:<sha>` explicit form (requires git ≥2.6).

4. **The TTL constant is 2700 seconds (non-configurable).** `factory-lock-write.sh` MUST
   embed the literal `2700` (or a named constant `TTL_SECONDS=2700` at the top of the
   script). No environment variable or argument override for TTL.

5. **`expires_at` is always `now + 2700s` at write time.** `locked_at` is immutable
   after acquire. `factory-lock-write.sh renew` refreshes `expires_at` ONLY; `locked_at`
   MUST NOT change on renewal.

6. **Prose/script boundary for `agents/state-manager.md`:** The SEQUENCING obligation
   (which commits invoke renew, the burst-close ordering) remains prose because it is
   agent behavior. The MECHANICAL operations (compute ISO-8601 timestamp, add 2700s,
   format YAML block, remove key) live in `factory-lock-write.sh` and are bats-testable.
   Do not over-extract: if a portion requires agent judgment (e.g., "renew on every
   Commit-A through Commit-E"), it belongs in prose.

## Risk

| Risk | Severity | Mitigation |
|------|----------|-----------|
| Mid-burst renewal missed on one of multiple intermediate commits | HIGH | AC-004 bats test covers renewal path; prose obligation in state-manager.md identifies WHICH commits must renew |
| CAS push using `--force-with-lease=factory-artifacts:<sha>` form (explicit sha) not supported by older git | MEDIUM | ADR-025 §Decision 8 cites git ≥2.6 for `--force-with-lease=<refname>:<expect>` form; documented in Library section |
| `factory-cas-push.sh` swallows non-fast-forward exit and returns 0 | HIGH | `test_BC_5_40_001_cas_push_rejected_on_concurrent_write` bats test explicitly mocks rejection with stub git and asserts non-zero exit |
| `factory-lock-write.sh clear` writes `factory_lock: null` instead of removing the key | HIGH | `test_BC_5_40_001_unlock_removes_key_not_nulls` bats test asserts key absent from frontmatter (grep returns non-zero) |
| ISO-8601 date arithmetic diverges between macOS BSD `date` and GNU `date` | MEDIUM | Test fixtures use known epoch timestamps; bats suite runs on the same platform as CI (darwin); if GNU `date` is needed, detect and branch in script with `date --version 2>&1 | grep -q GNU` |
