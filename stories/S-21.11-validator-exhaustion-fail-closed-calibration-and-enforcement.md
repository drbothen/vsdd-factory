# S-21.11: Per-plugin fuel-cap calibration + fail-closed enforcement flip (ADR-039 Phase 3+4 — CWE-636 closure for validator-class WASM plugins)

## Narrative

- **As a** factory pipeline operator whose validator writes are currently approved silently
  when a WASM plugin exhausts its fuel budget
- **I want** each of the six validator-class plugins to have a measured, corpus-calibrated
  `fuel_cap` and an enforced `failure_policy = "fail-closed"` annotation, so that exhaustion
  blocks the write (exit 2) rather than silently approving it
- **So that** CWE-636 is closed for the authorization-class WASM validator tier, the
  pipeline's write-gating guarantee is semantically meaningful, and D-442(e)'s
  size-workaround is superseded by a calibrated budget that accommodates production-scale
  `lessons.md` without exhausting

## Context / Finding Summary

ADR-039 §Context establishes:

1. **The detection mechanism is already correct.** `Trap::OutOfFuel` is distinguished from
   clean completion in `invoke.rs` → `PluginResult::Timeout { cause: TimeoutCause::Fuel }`.
   The defect is enforcement, not detection.

2. **The enforcement defect is CWE-636.** `plugin_fail_closed` returns `false` when
   `on_error == OnError::Continue`, regardless of `TimeoutCause`. The existing deliberate
   test `fail_closed_timeout_with_on_error_continue_is_open` encodes this policy. Any change
   requires revising that test **deliberately** (TD-VSDD-059: not deleting it, not renaming
   it; revising it to cover the new semantics for the `fail-open` configuration case).

3. **Self-lock hazard is live today.** `lessons.md` already exhausts the 10M fuel budget
   (D-442(e); ≤3500 soft / ≤4000 hard line-count workaround). The ADR-039 authoring session
   itself triggered `fail-closed: plugin timed out` blocks from `validate-factory-path-root`,
   `validate-input-hash`, and `validate-template-compliance`. A naive global flip would
   immediately hard-block all `.factory/` writes.

4. **Safe migration ordering (ADR-039 §Decision 3):** S-21.10 (Phase 1, now merged as
   prerequisite) added the `failure_policy` TOML field to the registry schema with a
   `fail-open` default. This story delivers Phase 3 (calibration) + Phase 4 (enforcement
   flip) as a single delivery unit. Phase 3 and Phase 4 MUST be atomic per-plugin (see
   AC-001 gate).

**Targeted validator-class plugins (ADR-039 §Decision 2):**
- `validate-factory-path-root`
- `validate-input-hash`
- `validate-template-compliance`
- `validate-wave-gate-prerequisite`
- `validate-pr-merge-prerequisites`
- `validate-cross-site-correspondence`

## Acceptance Criteria

### AC-001: No `failure_policy = "fail-closed"` entry may carry default `fuel_cap` — structural Phase-3-before-Phase-4 gate (traces to BC-1.03.017 PC8; ADR-039 §Decision 3 atomicity constraint)

A Cargo integration test MUST assert that no `[[hook]]` entry in `hooks-registry.toml`
carries both `failure_policy = "fail-closed"` AND a `fuel_cap` value ≤ 20,000,000 (twice
the factory default of 10M; any value at or below this floor is uncalibrated per
ADR-039 §Decision 4 minimum floor of 50M).

This test is the structural enforcement mechanism for the Phase-3-before-Phase-4 ordering
constraint. It MUST be RED before any `failure_policy = "fail-closed"` annotation is added
(no such annotation exists yet) and MUST remain GREEN at every CI-passing commit after
Phase 4 lands.

The combined requirement: a plugin entry MUST NOT have `failure_policy = "fail-closed"`
without simultaneously carrying a `fuel_cap > 20_000_000`. The CI gate makes an intermediate
half-state (annotated but uncalibrated) impossible to merge.

- **Test:** `test_no_fail_closed_plugin_with_uncalibrated_cap()` — parses `hooks-registry.toml`;
  for each entry where `failure_policy = "fail-closed"`, asserts `fuel_cap > 20_000_000`;
  MUST FAIL if any entry has `failure_policy = "fail-closed"` with `fuel_cap ≤ 20_000_000`

### AC-002: Exhaustion + fail-closed → block (exit 2) (traces to BC-1.03.017 PC1; ADR-039 §Decision 6 test case 1)

A unit test MUST invoke the dispatcher's `plugin_fail_closed` (or its replacement function)
with `PluginResult::Timeout { cause: TimeoutCause::Fuel, ... }` and
`failure_policy = FailurePolicy::FailClosed`. The function MUST return `true` (block
intent). The test exercises the `Timeout + FailClosed` branch, not configuration intent.

Separately, an integration or bats test MUST verify that a real dispatch with a plugin
configured `failure_policy = "fail-closed"` and a deliberately tiny `fuel_cap = 100`
produces dispatcher exit code 2 (BLOCK).

- **Test:** `test_exhaustion_fail_closed_blocks()` — unit: `Timeout { cause: Fuel }` +
  `FailClosed` → `plugin_fail_closed` returns `true`
- **Test:** bats/integration test — dispatch with `fuel_cap = 100` + `failure_policy = "fail-closed"`
  on a payload that exhausts the budget → exit 2 asserted on observed dispatcher output

### AC-003: Exhaustion + fail-open → advisory, not block (exit 0) (traces to BC-1.03.017 PC2; ADR-039 §Decision 6 test case 2)

The same exhaustion scenario (`Timeout { cause: TimeoutCause::Fuel }`) with
`failure_policy = FailurePolicy::FailOpen` MUST produce exit 0 (advisory, not block).
This verifies the `fail-open` path is preserved for plugins that legitimately need it.

- **Test:** `test_exhaustion_fail_open_is_advisory()` — unit: `Timeout { cause: Fuel }` +
  `FailOpen` → `plugin_fail_closed` returns `false`; exit 0 asserted

### AC-004: `on_error = "continue"` + `failure_policy = "fail-closed"` + exhaustion → BLOCK (axes are independent) (traces to BC-1.03.017 PC3; ADR-039 §Decision 6 test case 3)

A plugin with BOTH `on_error = "continue"` AND `failure_policy = "fail-closed"` that
exhausts its fuel budget MUST produce a block (exit 2). The `on_error` field governs crash
outcomes only; it MUST NOT override `failure_policy` for exhaustion outcomes.

This is the primary correctness test of the axes-independence design. It directly validates
the behavior that the prior `fail_closed_timeout_with_on_error_continue_is_open` test
denied.

- **Test:** `test_on_error_continue_with_fail_closed_exhaustion_still_blocks()` — unit:
  `Timeout { cause: Fuel }` + `on_error = Continue` + `failure_policy = FailClosed` →
  `plugin_fail_closed` returns `true`; axes do not interfere

### AC-005: Crash vs exhaustion as distinct paths (traces to BC-1.03.017 PC4+PC5; ADR-039 §Decision 6 test case 4)

Two scenarios MUST be verified as distinct paths:

(a) A crashed plugin (`on_error = "block"`, `failure_policy = "fail-open"`) MUST block
    via the `on_error` path. `PluginResult::Error` + `on_error = Block` → block (exit 2).

(b) A fuel-exhausted plugin (`on_error = "block"`, `failure_policy = "fail-open"`) MUST
    NOT block — exhaustion is not a crash. `Timeout { cause: Fuel }` + `on_error = Block`
    + `failure_policy = FailOpen` → exit 0.

This verifies that `on_error = "block"` does not accidentally gate exhaustion outcomes,
preserving the original semantics of `on_error` for crash paths only.

- **Test:** `test_crash_blocks_via_on_error_not_failure_policy()` — `PluginResult::Error` +
  `Block` + `FailOpen` → exit 2
- **Test:** `test_exhaustion_with_on_error_block_but_fail_open_is_advisory()` — `Timeout { cause: Fuel }` +
  `Block` + `FailOpen` → exit 0

### AC-006: `fail_closed_timeout_with_on_error_continue_is_open` revised, not deleted (traces to BC-1.03.017 PC7; TD-VSDD-059)

The existing test `fail_closed_timeout_with_on_error_continue_is_open` in `executor.rs`
(or its module) encodes the current deliberate fail-open policy. When Phase 4 enforcement
ships, this test MUST be revised to assert the new invariant for the `fail-open`
configuration case — it is not the unconditional policy it once was, but it still describes
valid behavior when `failure_policy = FailOpen`.

Specifically, the revised test MUST:
- Retain the function name (or a derivative that clearly conveys the same intent)
- Assert: `Timeout { cause: Fuel } + on_error=Continue + failure_policy=FailOpen → NOT block`
- NOT be deleted, as deletion would allow silent regression of the `fail-open` path

Deletion of this test without an equivalent replacement is a TD-VSDD-059 (paper-fix) violation.

- **Test:** revised `fail_closed_timeout_with_on_error_continue_is_open` (or
  `fail_closed_timeout_with_continue_and_fail_open_is_open`) — asserts the fail-open
  config case remains advisory; MUST exist in the PR diff

### AC-007: Per-plugin fuel-cap calibration against production-scale corpus (traces to BC-1.03.017 Preconditions 2–4, enabling PC9; ADR-039 §Decision 4 Option A)

For each of the six targeted validator-class plugins, `fuel_cap` MUST be set to at least
`max(measured_p99 × 1.5, 50_000_000)` where p99 is measured over a calibration corpus
that MUST include:

1. `lessons.md` at ≥3000 lines (above the D-442(e) soft limit)
2. `STATE.md` at current live size
3. `decision-log.md` at current live size
4. The ≥574 KB synthetic fixture from S-21.07 task #33 (prerequisite from Decision 5 near-term mitigations)

A calibration run MUST be executed for each plugin by the devops-engineer role before the
implementer annotates hooks-registry.toml. The measured `fuel_consumed` p99 and the chosen
`fuel_cap` MUST be recorded in the PR description or a calibration log artifact, not merely
asserted in code.

Any plugin whose calibration reveals a required `fuel_cap` that would exceed a practical
ceiling (e.g., >500M even at p99×1.5 for STATE.md) MUST be surfaced to the orchestrator
rather than silently annotated with an insufficient cap.

- **Test:** AC-001 gate (`test_no_fail_closed_plugin_with_uncalibrated_cap`) enforces the
  structural invariant; the calibration log provides the human-auditable evidence

### AC-008: Each targeted validator's `failure_policy` and `fuel_cap` annotated atomically (traces to BC-1.03.017 Invariant 2, enforced via PC8 gate; ADR-039 §Decision 3 per-plugin atomic commit)

For each of the six targeted validator-class plugins, the commit that adds
`failure_policy = "fail-closed"` to its `hooks-registry.toml` entry MUST be the same
commit that replaces the default `fuel_cap = 10_000_000` with the calibrated value from
AC-007. No plugin MAY carry `failure_policy = "fail-closed"` with an uncalibrated
`fuel_cap ≤ 20_000_000` at any CI-passing commit.

This constraint is enforced structurally by AC-001's gate test (the test would fail on
any half-state commit), and by the PR review gate — the reviewer MUST verify that no
intermediate commits in the PR carry the annotated-but-uncalibrated state.

- **Gate:** AC-001 test plus PR-level review of commit history

### AC-009: All six validator-class plugins carry `failure_policy = "fail-closed"` in final state (traces to BC-1.03.017 PC9; ADR-039 §Decision 2)

After all six calibration-and-annotation commits land, `hooks-registry.toml` MUST contain
`failure_policy = "fail-closed"` for all of:
- `validate-factory-path-root`
- `validate-input-hash`
- `validate-template-compliance`
- `validate-wave-gate-prerequisite`
- `validate-pr-merge-prerequisites`
- `validate-cross-site-correspondence`

Advisory-only and observability plugins MUST NOT receive `failure_policy = "fail-closed"`.
Classification of any ambiguous plugin MUST be surfaced to the orchestrator rather than
decided silently by the implementer.

- **Test:** `test_all_six_validator_class_plugins_are_fail_closed()` — parses
  `hooks-registry.toml`; asserts each of the six plugin entries has
  `failure_policy = "fail-closed"` and `fuel_cap > 50_000_000`

### AC-010: Epoch exhaustion treated identically to fuel exhaustion under fail-closed enforcement (traces to BC-1.03.017 PC6; ADR-039 §Decision 1)

`PluginResult::Timeout { cause: TimeoutCause::Epoch }` with
`failure_policy = FailurePolicy::FailClosed` MUST cause the executor decision function to
return `true` (block intent); the dispatcher exit code MUST be 2. `TimeoutCause::Epoch`
(epoch deadline exceeded) is a resource-exhaustion outcome identical to
`TimeoutCause::Fuel` for enforcement purposes per ADR-039 §Decision 1. Both exhaustion
causes trigger the `failure_policy` enforcement path; `on_error` is not consulted for
either.

- **Test:** `test_epoch_exhaustion_fail_closed_blocks()` — unit:
  `Timeout { cause: TimeoutCause::Epoch }` + `FailurePolicy::FailClosed` →
  `plugin_fail_closed` returns `true`; exit 2 asserted
