# S-18.08: O-P8-002 Pure-Parse Invariant Consistency Gate — BC Body Scan for Substrate-Read Violations

**Epic:** E-18 — Factory Context Durability (feature #173)
**Wave:** 7 (depends on S-18.01 through S-18.07 — all E-18 behavioral artifacts must exist before scanning them)
**Depends on:** S-18.01, S-18.02, S-18.03, S-18.04a, S-18.04b, S-18.05, S-18.06, S-18.07
**Blocks:** S-18.09
**Priority:** P1 (gate-enforcement; closes O-P8-002 finding from F2 adversarial pass)
**BC gate:** Gate-enforcement story — no new BC authored. References BC-4.14.001 Invariant 1 and BC-4.15.001 Invariant 1 as the invariants being enforced. The gate's correctness is asserted by concrete machine-checkable gate assertions (see AC-001 through AC-005 below).
**Subsystem anchor:** SS-06 owns the consistency-validator skill (Skill Catalog; `plugins/vsdd-factory/skills/consistency-validator/`) per ARCH-INDEX Subsystem Registry. SS-05 (Pipeline Orchestration) owns the bats gate automation in `plugins/vsdd-factory/tests/` per ARCH-INDEX. SS-08 is not in scope for this story (DECISION-1/F-MAJOR-002).

## Narrative

- **As a** factory consistency-validator running at the wave-7 gate boundary
- **I want** a machine-checkable gate that scans every BC file declaring "Invariant N: pure-parse" or "no filesystem" in its body, then greps the same BC file's BC/EC/Invariant sections and any associated VP body files for load-bearing substrate-read patterns (`sprint-state.yaml`, `HANDOFF.md`, `git-log`, `git-cat-file`) that would contradict the pure-parse claim
- **So that** any BC that declares a pure-parse invariant but also contains a substrate-read reference in its body is flagged as a consistency violation (0 load-bearing hits required per O-P8-002 / D-572 VP-body extension)

## Behavioral Contracts

This is a gate-enforcement story. No new BC is authored. The gate enforces the existing invariants:

| BC ID | Title | Invariant Enforced |
|-------|-------|--------------------|
| BC-4.14.001 | validate-wave-handoff-completeness WASM gate | Invariant 1: "No git or filesystem side effects: The WASM gate reads only the Write/Edit tool call payload... It is a pure-parse WASM function." |
| BC-4.15.001 | validate-heavy-op-delegation WASM gate | Invariant 1: "Pure-parse; no filesystem, subprocess, or context access: The WASM gate reads ONLY the `command` field from the PreToolUse payload... It is a pure function of the command string and the configured pattern list." |

## Acceptance Criteria

### AC-001 (gate assertion — BC-4.14.001 Invariant 1 pure-parse body scan: 0 load-bearing substrate-read hits)

A `grep -Ei` scan of `BC-4.14.001.md` body content (sections: §Preconditions, §Postconditions, §Invariants, §Edge Cases, §Canonical Test Vectors) for the following substrate-read substrate patterns MUST return 0 load-bearing hits:

```
sprint-state\.yaml|HANDOFF\.md[^-]|git-log|git-cat-file
```

The following are NOT load-bearing hits (they are excluded from the count):
- References inside `§Related BCs`, `§Architecture Anchors`, `§Story Anchor`, `§VP Anchors`, `§Traceability`, or `§Changelog` sections (these are references to the shell layer, not to the WASM gate itself).
- Quoted in `§Description` prose explaining that the SHELL layer (not the WASM gate) derives wave identity from real substrate — this is documented as a "caller's responsibility" note, not a behavioral claim about the gate.

The scan MUST produce exactly 0 hits in the normative behavioral sections (§Preconditions, §Postconditions, §Invariants, §Edge Cases, §Canonical Test Vectors).

**Machine-checkable assertion:**
```bash
HITS=$(grep -Ei "sprint-state\.yaml|HANDOFF\.md[^-]|git-log|git-cat-file" \
  .factory/specs/behavioral-contracts/ss-04/BC-4.14.001.md \
  | grep -Ev "^(##? (Related BCs|Architecture Anchors|Story Anchor|VP Anchors|Traceability|Changelog)|.*caller|.*shell wave-handoff|.*shell layer|.*derives from real substrate)" \
  | wc -l)
[ "$HITS" -eq 0 ]
```

**Test (bats):** `test_bc_4_14_001_pure_parse_invariant_zero_substrate_reads_in_normative_sections()`

## Previous Story Intelligence

O-P8-002 finding from the F2 adversarial pass cycle: during F2, the adversary found that some BCs declared "pure-parse" invariants but their body prose or VP bodies contained references to substrate-read patterns (`sprint-state.yaml`, `git-log`, etc.) that contradicted the invariant. D-572 expanded the VP-body scan scope to include VPs associated with pure-parse BCs. This story implements the machine-checkable gate that closes O-P8-002.

The exclusion filter pattern in AC-001 was derived from BC-4.14.001's specific `§Description` prose structure (which explains the SHELL layer's substrate-read responsibility as a "caller's responsibility" note — NOT a behavioral claim about the WASM gate itself). The exclusion MUST be carefully calibrated: too-broad exclusions mask real violations; too-narrow exclusions produce false positives on valid prose.

## Architecture Compliance Rules

1. **Gate scan scope is BC normative sections only (AC-001/AC-002):** The grep scans MUST exclude `§Related BCs`, `§Architecture Anchors`, `§Story Anchor`, `§VP Anchors`, `§Traceability`, and `§Changelog` sections from the hit count. Hits in non-normative sections are expected (they reference the shell layer's substrate reads, not the WASM gate's).
2. **Discovery-first pattern (AC-005):** The gate MUST use dynamic discovery (`grep -rl "pure-parse"`) rather than a hardcoded list of BC IDs. Hardcoded lists create drift as new pure-parse BCs are authored.
3. **0-hit assertion is strict:** Any non-zero hit count in normative behavioral sections is a gate FAILURE, not a warning. The gate MUST report the failing file and hit count.
4. **No write side effects:** The gate scan is read-only. It MUST NOT modify any BC or VP file as a result of a scan hit. Findings route to product-owner via the orchestrator for BC amendment.
5. **Forbidden dependencies:** The gate scan script MUST NOT import or depend on any E-18 WASM crate (`validate-heavy-op-delegation`, `validate-wave-handoff-completeness`). These are the artifacts being scanned, not tools for scanning.

## Library and Framework Requirements

- **Shell:** `bash` with `grep -Ei` (POSIX extended regex; case-insensitive)
- **No external libraries** — pure grep + wc pipeline
- **bats-core:** project standard; `plugins/vsdd-factory/tests/run-all.sh`
- **No new Rust crates or WASM binaries** — pure shell + bats deliverable
