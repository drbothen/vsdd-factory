## Acceptance Criteria

**Detection algorithm (ADR-026 §Decision 14):** All BC scans (AC-001, AC-002, AC-003) use the same three-layer pipeline:
1. **Normative-section extraction** — `awk` extracts text from `## Preconditions` through (but not including) the first non-normative heading (whitelist terminator: stops at any `## ` heading that is NOT one of `Preconditions`, `Postconditions`, `Invariants`, `Edge Cases`, `Error Paths`, `Canonical Test Vectors`); this scopes the scan to normative behavioral content only, structurally excludes the gate's own HANDOFF.md payload description and traceability prose, and is robust to `## Related BCs (Recommended)` and other variant headings.
2. **Verb+substrate collocation** — `grep -Ei` matches lines containing a read-action verb within ~80 characters of a substrate identifier; this distinguishes active *violations* ("reads sprint-state.yaml") from *affirmations* ("does not read sprint-state.yaml").
3. **Negation/comment exclusion** — a second `grep -Eiv` strips lines containing negation markers (`no `, `not `, `NOT `, `without`, `never`, `does not`, `MUST NOT`, `is NOT`, `cannot`, `do NOT`, `only from`, `exclusively`); a third `grep -Ev` strips lines that are Rust/bash comment lines (for VP scans in AC-004).

VP scans (AC-004) run layers 2 and 3 only — no section extraction — because VPs are shorter and their full content is normative.

### AC-001 (gate assertion — BC-4.14.001 Invariant 1 pure-parse body scan: 0 verb+substrate collocation hits in normative sections)

```bash
HITS=$(awk '/^## Preconditions$/{ found=1 }

  | grep -Eiv "no |not |NOT |without|never|does not|MUST NOT|is NOT|cannot|do NOT|only from|exclusively" \
  | wc -l)
[ "$HITS" -eq 0 ]
```

### AC-003 (gate assertion — dynamic discovery: all BCs declaring "pure-parse" in their `## Invariants` section, Invariants-anchored discovery, three-layer scan, 0 hits each; scannability guard)

The gate discovers ALL BC files under `.factory/specs/behavioral-contracts/` (not just ss-04) that contain "pure-parse" in their `## Invariants` section (anchored discovery — excludes BC-INDEX.md, SS-07 prose-mentions, and any BC where "pure-parse" appears only in non-Invariants sections). For each discovered BC, a fail-loud scannability guard verifies the file declares `## Preconditions`; BCs lacking that heading are structurally un-scannable and the gate MUST emit a loud FAIL (not silently skip). The gate then applies the three-layer pipeline to each scannable BC and asserts 0 hits per file. The gate MUST FAIL if zero files are discovered (discovery guard prevents a broken glob from silently passing).

**Machine-checkable assertion:**
```bash
DISCOVERED=$(find .factory/specs/behavioral-contracts -name "BC-*.md" -print0 \
  | while IFS= read -r -d '' f; do
      MATCH=$(awk '/^## Invariants$/{ found=1; next } found && /^## /{ exit } found{ print }' "$f" | grep -i "pure-parse")
      [ -n "$MATCH" ] && echo "$f"
    done)
[ -n "$DISCOVERED" ] || { echo "FAIL: discovery returned 0 files"; exit 1; }
OVERALL_STATUS=0
while IFS= read -r BC_FILE; do
  if ! grep -q "^## Preconditions$" "$BC_FILE"; then
    echo "FAIL: $BC_FILE lacks ## Preconditions — structurally un-scannable"; OVERALL_STATUS=1; continue
  fi
  HITS=$(awk '/^## Preconditions$/{ found=1 }
              found && /^## / && !/^## (Preconditions|Postconditions|Invariants|Edge Cases|Error Paths|Canonical Test Vectors)$/{ exit }
              found{ print }' "$BC_FILE" \
    | grep -Ei "(reads?|loads?|fetches|derives?|access(es)?|retrieves?)\s+.{0,80}(sprint-state\.yaml|git-log|git-cat-file)" \
    | grep -Eiv "no |not |NOT |without|never|does not|MUST NOT|is NOT|cannot|do NOT|only from|exclusively" \
    | wc -l)
  [ "$HITS" -eq 0 ] || { echo "FAIL: $BC_FILE has $HITS genuine pure-parse violations"; OVERALL_STATUS=1; }
done <<< "$DISCOVERED"
exit "$OVERALL_STATUS"
```

## Previous Story Intelligence

O-P8-002 finding from the F2 adversarial pass cycle: during F2, the adversary found that some BCs declared "pure-parse" invariants but their body prose or VP bodies contained references to substrate-read patterns (`sprint-state.yaml`, `git-log`, etc.) that contradicted the invariant. D-572 expanded the VP-body scan scope to include VPs associated with pure-parse BCs. This story implements the machine-checkable gate that closes O-P8-002.

**v1.0–v1.5 design (noun-only grep, now superseded):** The original AC-001..005 used a single-pass noun-only grep with per-line exclusion filters. Three structural flaws were identified: (1) no section-scoping — the scan would flag `HANDOFF.md` references in the gate's own payload description; (2) pure-parse *affirmations* ("no sprint-state.yaml access") were indistinguishable from *violations* ("reads sprint-state.yaml"); (3) the per-line exclusion list was fragile and required manual expansion with each new exclusion case.

**v1.6 design (three-layer pipeline, ADR-026 §Decision 14, human-adjudicated):** The architect redesigned the detection algorithm using: (1) awk normative-section extraction (structurally scopes the scan; HANDOFF.md payload excluded by the `## Related BCs` boundary without any per-line filter); (2) verb+substrate collocation grep (distinguishes active reads from affirmations); (3) negation/comment exclusion grep (strips prohibition statements). Validated: 0 hits on the current clean BC/VP set, 1 hit on the injected positive control (AC-005). The positive control is now a continuous invariant — any verb-pattern regression causes AC-005 to fail before other ACs are trusted.

**v1.7 refinement (LOCAL adv P1 F-P1-001/F-P1-002, architect-refined §Decision 14):** Two MEDIUM adversary findings against the v1.6 design: F-P1-001 (over-broad discovery — `grep -rl "pure.parse"` matched BC-INDEX.md and ~190 SS-07 prose-mentions, producing false positives and bloating the scan scope) and F-P1-002 (fragile section boundary — hardcoded `## Related BCs` string match breaks on `## Related BCs (Recommended)` heading variants used in some BCs). Architect-refined fixes: (1) Discovery anchored to `## Invariants` section — awk scans only that section of each BC-*.md file for "pure-parse" hits, structurally excluding BC-INDEX.md and any non-BC file; (2) Layer-1 awk uses a whitelist terminator instead of a named-heading match — stops at the first `## ` heading not in `{Preconditions, Postconditions, Invariants, Edge Cases, Error Paths, Canonical Test Vectors}`, robust to all heading variants; (3) Scannability guard added to AC-003 loop — a discovered BC that lacks `## Preconditions` emits a loud FAIL rather than vacuously passing (vacuous pass would mask violations in structurally malformed BCs). AC-004 (VP scan) and AC-005 (positive control) are unchanged.

## Architecture Compliance Rules

1. **Three-layer pipeline is the canonical detection algorithm (ADR-026 §Decision 14):** BC scans MUST use awk normative-section extraction (layer 1) + verb+substrate collocation grep (layer 2) + negation exclusion grep (layer 3) in that exact order. Single-pass noun-only grep is forbidden — it cannot distinguish violations from affirmations and produces false positives on HANDOFF.md payload descriptions.
2. **BC normative-section boundary uses whitelist terminator:** The awk extraction stops at the first `## ` heading that is NOT in the whitelist `{Preconditions, Postconditions, Invariants, Edge Cases, Error Paths, Canonical Test Vectors}`. This is robust to `## Related BCs (Recommended)` and any other variant headings. Do NOT use a hardcoded `## Related BCs` string match — it will break on BCs that use heading variants.
3. **VP scans are whole-file (layers 2+3 only):** VP files are shorter and fully normative. Apply verb+substrate collocation and negation exclusion directly without awk section extraction. Add `grep -Ev "^\s*//"` to strip Rust/bash comment lines.
4. **Discovery is Invariants-anchored, tree-wide (AC-003):** The dynamic discovery command MUST search the full `.factory/specs/behavioral-contracts/` tree using `find ... -name "BC-*.md"` and must scope the "pure-parse" match to the `## Invariants` section of each BC (awk pattern). This anchoring structurally excludes BC-INDEX.md and any BC where "pure-parse" appears only in prose outside the Invariants section. A loose `grep -rl "pure.parse"` over the tree is FORBIDDEN — it matches ~190 SS-07 prose-mentions and BC-INDEX.md, producing false positives. The discovery guard (`[ -n "$DISCOVERED" ]`) MUST be present. The scannability guard (FAIL if discovered BC lacks `## Preconditions`) MUST be present — vacuously passing un-scannable BCs is a gate failure mode.
5. **Positive control is a continuous invariant (AC-005):** The positive-control test MUST remain GREEN at all times. Any refactor of the verb pattern that causes AC-005 to fail has introduced a false-negative regression and ALL other ACs become untrusted until AC-005 is GREEN again.
6. **0-hit assertion is strict:** Any non-zero hit count in the scanned content is a gate FAILURE, not a warning. The gate MUST emit `echo "FAIL: $FILE has $HITS ..."` and exit non-zero.
7. **No write side effects:** The gate scan is read-only. It MUST NOT modify any BC or VP file as a result of a scan hit. Findings route to product-owner via the orchestrator for BC amendment.
8. **Forbidden dependencies:** The gate scan script MUST NOT import or depend on any E-18 WASM crate (`validate-heavy-op-delegation`, `validate-wave-handoff-completeness`). These are the artifacts being scanned, not tools for scanning.
