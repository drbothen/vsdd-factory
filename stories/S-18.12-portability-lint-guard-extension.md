## Narrative

As a CI maintainer or factory implementer writing bash scripts for wave-handoff or any hook,
I want the portability-lint bats guard to detect bash 4+-gated syntax, global IFS mutations, and undeclared runtime dependencies (Python/PyYAML, jq),
so that macOS CI failures caused by these issues are caught statically before code is merged — eliminating the class of runtime portability failures that required four emergency CI fixes in S-18.01's merge.

## Background

The S-18.01 PR (#193) required four post-cascade CI portability fixes before merging:
1. `2b40dfd5` — IFS mutation in parse-sprint-state.sh: `IFS='|'` global assignment replaced with `awk -F'|'` (IFS-mutation-static-analysis gap).
2. `ea7328ac` — `local -A` bash 3.2 incompatibility in write-handoff.sh: added bash version guard (`${BASH_VERSINFO[0]} -lt 4`) + brew bash hint on macOS.
3. `aaa8da8a` — PyYAML runtime dep: `pip install pyyaml` failed with PEP 668 "externally managed environment" error on macOS GitHub Actions runner.
4. `3fe11ea1` — PyYAML PEP 668 follow-up: `--break-system-packages` flag added.

The existing static lint guard (`test_BC_5_41_001_F_P11_001_bsd_portability_no_pcre_classes_in_grep_sed`) scans wave-handoff scripts for PCRE shorthand classes (`\s`, `\d`, `\w`, `\S`, `\D`, `\W`, `\b`) but does NOT detect any of the four categories above. This story extends the guard to catch these four categories.

## Acceptance Criteria

### AC-001: bash 4+ feature detection — `local -A` / `declare -A` associative arrays
The portability-lint guard (bats test in `wave-handoff.bats` or a new dedicated `portability-lint.bats`) scans all `plugins/vsdd-factory/skills/wave-handoff/*.sh` scripts (and optionally all `plugins/vsdd-factory/hooks/*.sh` scripts) for unguarded use of `local -A` or `declare -A`.

"Unguarded" means the associative array declaration appears without a preceding bash version check of the form:
```
if [[ ${BASH_VERSINFO[0]} -lt 4 ]]; then ... fi
```
or equivalent (e.g., `if (( BASH_VERSINFO[0] < 4 ))`).

The test FAILS if any unguarded `local -A` or `declare -A` is found. It PASSES after the S-18.01-era guard is confirmed present, or after confirming no associative arrays exist in the scanned scripts.

### AC-002: bash 4+ feature detection — `${var^^}` and `${var,,}` case modifiers
The portability-lint guard scans for `${...^^}` (uppercase) and `${...,,}` (lowercase) parameter expansion modifiers, which require bash 4+. These MUST either be absent or guarded by a bash version check. The test FAILS if any unguarded instance is found.

### AC-003: global IFS mutation detection
The portability-lint guard scans for `IFS=` assignments that are NOT:
- Inside a function body following `local IFS=` (locally scoped), OR
- Inside a subshell `(IFS=...; command)`.

A bare `IFS=` at script scope or as a non-local assignment inside a function is flagged. The test FAILS if any unguarded global IFS mutation is found. PASSES after confirming all IFS uses are locally scoped or subshell-scoped.

### AC-004: undeclared python/pyyaml runtime dependency detection
The portability-lint guard scans for `python3 -c` or `python3 ...pyyaml` or `pip install pyyaml` invocations in wave-handoff scripts. If any are found, the script MUST have a corresponding preflight check that either:
- Verifies `python3` and `pyyaml` are available before use (e.g., `python3 -c "import yaml" 2>/dev/null || ...`), OR
- Is replaced with a POSIX-portable alternative (e.g., awk-based YAML key extraction).

The test FAILS if a python3/pyyaml invocation is found without a preflight guard. The canonical fix from S-18.01 (`--break-system-packages` workaround) is NOT accepted as a long-term resolution in new scripts — proper preflight or removal of the dependency is required.

### AC-005: undeclared jq runtime dependency detection
The portability-lint guard scans for `jq` invocations in wave-handoff scripts. If any are found, the script MUST have a preflight check that verifies `jq` is installed (`command -v jq >/dev/null 2>&1 || { echo "jq required"; exit 1; }`). The test FAILS if a bare `jq` invocation is found without a preflight guard.

### AC-006: extended guard is scoped to wave-handoff scripts and is not a false-positive source
The guard scans only `plugins/vsdd-factory/skills/wave-handoff/*.sh` (and optionally `plugins/vsdd-factory/hooks/*.sh`). It does NOT scan test fixtures or bats helper files, which intentionally contain negative test examples. The guard uses the same scope exclusion approach as the existing PCRE guard (scans the source scripts, not the test corpus).

### AC-007: existing PCRE shorthand guard is preserved and still passes
The pre-existing guard `test_BC_5_41_001_F_P11_001_bsd_portability_no_pcre_classes_in_grep_sed` continues to pass after S-18.12 changes. The new tests are additive; they do not modify or remove the existing guard.

## Architecture Compliance Rules

1. **Static-analysis only, no script execution (preserves Pure classification):** The guard tests grep the script source files. They MUST NOT execute the wave-handoff scripts. Executing untested scripts in bats context creates test-isolation violations.
2. **Non-vacuity assertion (EC-005):** The guard must verify at least one `.sh` file was scanned. A grep that finds nothing because the scope is empty is a false-pass. Add an explicit `[[ $found_scripts -gt 0 ]]` check after the file discovery step.
3. **Exclusion of fixture files:** The grep scope MUST NOT include `tests/fixtures/`, `tests/*.bats`, or other test-corpus files. Only production scripts in `plugins/vsdd-factory/skills/wave-handoff/` are in scope.
4. **`set -euo pipefail` in all new bash code** (CLAUDE.md convention; applies to any helper scripts used within the bats tests).
5. **Additive, not replacing:** The new tests are added to `wave-handoff.bats` or a new `portability-lint.bats`. The existing PCRE guard test is NOT modified.
