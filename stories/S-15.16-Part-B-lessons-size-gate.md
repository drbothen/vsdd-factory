# S-15.16 Part B: lessons.md Size Gate — Extend validate-state-size Hook

**Epic:** E-12 — Engine Governance (brownfield-backfill wave, S-15.03 PRIORITY-A M3)
**Delivery order:** M3 (independent; can ship any time in Milestone 3)
**Depends on:** none
**Blocks:** none
**Priority:** P1 (closes D-442(e) structural fix; adds lessons.md fuel-exhaustion prevention)
**Note:** S-15.16 Part A (lessons.md compaction) already SHIPPED (pure .factory/ content edit;
  MERGED 2026-05-15; lessons.md compacted 3668→925 lines). This story is Part B only: the
  mechanical line-count enforcement gate.

## Narrative

- **As a** state-manager or agent writing to `lessons.md`
- **I want to** receive a PostToolUse advisory when lessons.md exceeds 3500 lines and a
  PostToolUse block when it exceeds 4000 lines
- **So that** the WASM fuel-exhaustion risk documented at D-442(e) is caught mechanically
  before lessons.md grows large enough to trigger hook timeouts in subsequent PostToolUse
  hook invocations that read or validate lessons.md

## Why This Exists

D-442(e) identified that `lessons.md` growing beyond ~3000 lines risks WASM fuel exhaustion
during PostToolUse validators (fuel-limit blocks during hook invocations that read lessons.md).
This is a structural risk, not a cosmetic concern: large lessons.md causes false-positive hook
blocks and corrupts session telemetry.

Part A (compaction, SHIPPED) reduced the line count below the risk threshold. Part B (this story)
adds a mechanical enforcement gate that prevents lessons.md from growing back to dangerous size
without triggering an advisory or block.

The existing `validate-state-size.sh` hook already enforces STATE.md line-count limits (warn at
>200, block at >500). This story extends the same bash script with a parallel lessons.md check
using the D-442(e) thresholds: soft advisory at >3500, hard block at >4000.

## Scope

**In scope:**
- Extend `plugins/vsdd-factory/hooks/validate-state-size.sh` with a lessons.md arm
- lessons.md path pattern: `*/.factory/cycles/*/lessons.md` OR `*.factory/cycles/*/lessons.md`
  (same path pattern as the production lessons.md file location)
- Soft advisory at line count >3500: emit warning to stderr, exit 0
- Hard block at line count >4000: emit block via `block_pre`, exit 2
- Compaction-in-progress allow: if write REDUCED line count (comparing against `git show HEAD`),
  always allow regardless of absolute count (same pattern as existing STATE.md arm)
- New bats integration tests for the lessons.md arm
- LOCAL adversary cascade per BC-5.39.001

**Not in scope:**
- Changing existing STATE.md behavior (it is frozen; only additive)
- Converting validate-state-size from bash to WASM (separate future story if needed)
- Checking other `.factory/cycles/` files
- Changing the advisory/block thresholds in D-442(e) — the 3500/4000 values are canonical

## D-442(e) Thresholds

| Threshold | Value | Action |
|-----------|-------|--------|
| Soft advisory | >3500 lines | `stderr` warning + exit 0 |
| Hard block | >4000 lines | `block_pre` + exit 2 |
| Compaction-in-progress | LINE_COUNT < PRIOR_COUNT | exit 0 unconditionally |

**Rationale (from D-442(e)):**
- ≤3500: normal operating range after Part A compaction
- 3501–4000: soft warning zone; state-manager should plan compaction
- >4000: hard block; lessons.md is too large for reliable hook invocation

### lessons.md Extension Postconditions (additive to BC-7.04.051)

**L1 — lessons.md target detection:**
The lessons.md arm fires when `$FILE_PATH` matches `*/.factory/cycles/*/lessons.md` pattern.
Path-component detection uses a `case` statement (same pattern as existing STATE.md arm).

**L2 — Compaction-in-progress exemption:**
If `LINE_COUNT < PRIOR_COUNT` (comparing against `git -C $PARENT_DIR show HEAD:relative-path`),
exit 0 unconditionally. Same logic as STATE.md arm.

**L3 — Soft advisory at >3500:**
If `LINE_COUNT > 3500` (and not reducing), emit to stderr:
```
LESSONS.MD SIZE WARNING:
  lessons.md has <N> lines (recommended: ≤3500, hard limit: 4000).
  Run /vsdd-factory:compact-lessons to extract historical content before growing further.
```
Exit 0 (advisory only; not a block).

**L4 — Hard block at >4000:**
If `LINE_COUNT > 4000` (and not reducing), call `block_pre`:
```
block_pre "validate-state-size" \
  "lessons.md exceeds 4000-line hard limit ($LINE_COUNT lines). WASM fuel exhaustion risk per D-442(e)" \
  "Run /vsdd-factory:compact-lessons to archive historical content" \
  "lessons_md_fuel_risk"
```
Exit 2.

**L5 — Pass within threshold:**
If `LINE_COUNT ≤ 3500`, exit 0 (clean pass).

**L6 — Non-target file:**
If `$FILE_PATH` does not match the lessons.md pattern, exit 0 immediately (no action).

### BC-7.04.051 Key Invariants (existing; extension must not violate)

- Hook fires PostToolUse only — signals AFTER the write; cannot prevent the write
- Compaction is ALWAYS allowed (LINE_COUNT < PRIOR_COUNT → exit 0)
- Fail-open: if `git show` or `wc -l` fail, the hook does NOT block
- `jq` absence → exit 0 (no input parsing possible; graceful no-op)

### Phase: implementer

- [ ] T-5: Read `plugins/vsdd-factory/hooks/validate-state-size.sh` in full (must have read before edit).

- [ ] T-6: Refactor the top-level `case "$FILE_PATH"` in `validate-state-size.sh` to handle
  BOTH the STATE.md path and the lessons.md path. The existing script has:

  ```bash
  case "$FILE_PATH" in
    */.factory/STATE.md|*.factory/STATE.md) ;;
    *) exit 0 ;;
  esac
  ```

  This exits 0 for ALL non-STATE.md paths, so a second lessons.md `case` appended after the
  STATE.md arm's final `exit 0` would be dead code (never reached). The correct fix is to
  refactor the top-level case to route to named targets, then use separate logic blocks:

  ```bash
  # Determine target arm
  case "$FILE_PATH" in
    */.factory/STATE.md|*.factory/STATE.md)
      TARGET="state"
      ;;
    */.factory/cycles/*/lessons.md|*.factory/cycles/*/lessons.md)
      TARGET="lessons"
      ;;
    *)
      exit 0
      ;;
  esac

  # ─── STATE.md arm ────────────────────────────────────────────────────────────
  if [[ "$TARGET" == "state" ]]; then
    if [[ ! -f "$FILE_PATH" ]]; then
      exit 0
    fi

    LINE_COUNT=$(wc -l < "$FILE_PATH" | tr -d ' \t\n')

    # Check if this write reduced the file size (compaction).
    PARENT_DIR=$(dirname "$FILE_PATH")
    PRIOR_COUNT=0
    if command -v git &>/dev/null; then
      _git_out=$(git -C "$PARENT_DIR" show HEAD:STATE.md 2>/dev/null | wc -l | tr -d ' ' 2>/dev/null) || _git_out=0
      PRIOR_COUNT="${_git_out//[[:space:]]/}"
      PRIOR_COUNT="${PRIOR_COUNT:-0}"
      [[ "$PRIOR_COUNT" =~ ^[0-9]+$ ]] || PRIOR_COUNT=0
    fi

    if [[ "$LINE_COUNT" -lt "$PRIOR_COUNT" ]]; then
      exit 0
    fi

    if [[ "$LINE_COUNT" -gt 500 ]]; then
      block_pre "validate-state-size" \
        "STATE.md exceeds 500-line limit ($LINE_COUNT lines). STATE.md should be a quick status check, not a history log" \
        "Run /vsdd-factory:compact-state to extract historical content to cycle files" \
        "state_md_bloat"
    elif [[ "$LINE_COUNT" -gt 200 ]]; then
      echo "STATE.md SIZE WARNING:" >&2
      echo "  STATE.md has $LINE_COUNT lines (recommended: <200, limit: 500)." >&2
      echo "  Consider running /vsdd-factory:compact-state to extract" >&2
      echo "  historical content to cycle files before it grows further." >&2
      exit 0
    fi
    exit 0
  fi

  # ─── lessons.md arm ──────────────────────────────────────────────────────────
  # D-442(e) lessons.md size gate: advisory >3500, block >4000.
  if [[ "$TARGET" == "lessons" ]]; then
    if [[ ! -f "$FILE_PATH" ]]; then
      exit 0
    fi

    LESSONS_LINE_COUNT=$(wc -l < "$FILE_PATH" | tr -d ' \t\n')

    # Compaction-in-progress: always allow if write REDUCED lines.
    LESSONS_PARENT_DIR=$(dirname "$FILE_PATH")
    LESSONS_PRIOR_COUNT=0
    if command -v git &>/dev/null; then
      _lessons_git_rel="${FILE_PATH##*/.factory/}"
      _lessons_git_out=$(git -C "$LESSONS_PARENT_DIR" show HEAD:"$_lessons_git_rel" 2>/dev/null | wc -l | tr -d ' ' 2>/dev/null) || _lessons_git_out=0
      LESSONS_PRIOR_COUNT="${_lessons_git_out//[[:space:]]/}"
      LESSONS_PRIOR_COUNT="${LESSONS_PRIOR_COUNT:-0}"
      [[ "$LESSONS_PRIOR_COUNT" =~ ^[0-9]+$ ]] || LESSONS_PRIOR_COUNT=0
    fi

    if [[ "$LESSONS_LINE_COUNT" -lt "$LESSONS_PRIOR_COUNT" ]]; then
      exit 0
    fi

    if [[ "$LESSONS_LINE_COUNT" -gt 4000 ]]; then
      block_pre "validate-state-size" \
        "lessons.md exceeds 4000-line hard limit ($LESSONS_LINE_COUNT lines). WASM fuel exhaustion risk per D-442(e)" \
        "Run /vsdd-factory:compact-lessons to archive historical content to lessons-archive-*.md" \
        "lessons_md_fuel_risk"
    elif [[ "$LESSONS_LINE_COUNT" -gt 3500 ]]; then
      echo "LESSONS.MD SIZE WARNING:" >&2
      echo "  lessons.md has $LESSONS_LINE_COUNT lines (recommended: ≤3500, hard limit: 4000)." >&2
      echo "  Consider running /vsdd-factory:compact-lessons before it grows further (D-442(e))." >&2
      exit 0
    fi
    exit 0
  fi
  ```

  **Critical implementation notes:**
  1. The top-level case MUST route to a `$TARGET` variable, then use separate `if [[ "$TARGET" == ... ]]`
     blocks. Do NOT attempt to put both arms in separate standalone `case` statements — the original
     script's `*) exit 0 ;;` branch makes any second case dead code after `exit 0` at line 77.
  2. The existing STATE.md logic is extracted unchanged into the `if [[ "$TARGET" == "state" ]]` block.
     Line-by-line, the behavior is identical to the original. The refactor is structural only.
  3. `LESSONS_PARENT_DIR` is derived separately from `PARENT_DIR` (which is the STATE.md arm's
     variable) to avoid any cross-arm variable coupling.
  4. The git `show HEAD:relative-path` invocation requires computing the correct relative path
     from the git root (`.factory/` worktree). The `${FILE_PATH##*/.factory/}` strip produces
     the relative path portion inside the `.factory/` worktree.
  5. Boundary conditions: strict greater-than (`-gt 4000`, `-gt 3500`), NOT greater-than-or-equal.
     At exactly 4000 lines: advisory only. At exactly 3500 lines: clean pass.
  6. The `block_pre` function is defined in `lib/block.sh` and sourced at the top of the script
     (existing code). The source is already present — do not add it again.
  7. **State.md arm non-regression:** After the refactor, run ALL existing STATE.md bats tests
     against the modified script to confirm zero regression. The STATE.md arm behavior is
     byte-for-byte equivalent to the original.

## Test Seam Description

The bats tests invoke `validate-state-size.sh` directly by:
1. Setting up a temp directory that simulates the `.factory/cycles/*/` structure
2. Creating or generating the `lessons.md` file with the test line count
3. Constructing a mock hook dispatch JSON payload: `{"tool_input": {"file_path": "/path/to/lessons.md"}}`
4. Piping the payload to `bash plugins/vsdd-factory/hooks/validate-state-size.sh`
5. Asserting on exit code (0 for pass/advisory, 2 for block)
6. For advisory tests: asserting stderr contains "LESSONS.MD SIZE WARNING"
7. For block tests: asserting stderr contains "D-442(e)" and "compact-lessons"

**Git mock:** For `pass-lessons-compaction-allowed.bats`, the test uses a temp git repo fixture
that has a committed lessons.md with higher line count than the in-progress write (simulating
compaction). See `crates/hook-plugins/validate-dispatch-advance/` tests for git-fixture pattern.
