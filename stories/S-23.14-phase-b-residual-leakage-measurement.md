# S-23.14: Phase-B residual-leakage measurement (gates Phase C)

## Narrative

- **As the** human decision-maker who must decide whether ADR-045 Phase C (Tiers 2/3: Doorstop
  fingerprint/suspect-link model, full AST-based residual validator) is built
- **I want** a defined measurement window, post-Phase-A-migration, that counts new or
  reintroduced load-bearing inline version pins the thin new-pin guard (S-23.03) did NOT catch
  (a false negative), plus any suspect false-negatives in the guard's stale-only decision logic
- **So that** the Phase-C build decision is made on measured evidence, not assumption — exactly
  as ADR-045 §Decision preamble item 2 and §Migration Plan Phase B require

## Context / Problem Statement

ADR-045 §Decision preamble: "Tiers 2 and 3 are ratified here as the correct *direction*... but
**not authorized for build**. Their build is **gated on measured residual leakage** after the
Tier 1 migration lands: if the thin new-pin guard plus INDEX-resolution is sufficient in practice
(few or no new stale/reintroduced pins observed over a defined measurement window — see Migration
Plan Phase B), Tiers 2/3 may never need to be built at full scope." ADR-045 §Migration Plan Phase
B, step 7: "Measure residual leakage over a defined window post-Phase-A (e.g., the next N
adversarial passes or M calendar weeks, set at ratification time): count new/reintroduced
load-bearing inline version pins caught only by manual review rather than the thin guard, and any
suspect false-negatives. This measurement is the gate for Phase C."

This story is NOT a build story for Tiers 2/3 — building either is explicitly out of scope (epic
Forbidden Dependencies). It is an instrumentation-and-reporting story: define the measurement
window, define the counting method, run it, and produce a report with a Phase-C go/no-go
recommendation. ADR-045 did not specify an exact window length at ratification time (it says "set
at ratification time"); this story's implementer must either find that the ratification recorded
a concrete window (check ADR-045's `modified:` changelog ratification entry and STATE.md D-NNN
ratification record) or, if genuinely unspecified, propose a concrete default (e.g., the next 10
adversarial passes across all active stories, OR a 4-calendar-week window, whichever completes
first) and surface it to the orchestrator/human for confirmation rather than silently picking one
— per CLAUDE.md's "genuine human decisions... should be surfaced" boundary.

## Acceptance Criteria

### AC-001
This story's implementer confirms (or, if not already fixed, proposes and gets human confirmation
of) the exact Phase-B measurement window per ADR-045 §Migration Plan Phase B step 7. (traces to
ADR-045 §Migration Plan Phase B step 7, "set at ratification time")

### AC-002
A mechanical counting method is defined and run via literal shell command with captured stdout
(not narrative attestation), consistent with D-449(a): count of new/reintroduced load-bearing
inline version pins found by manual review or a subsequent adversarial pass that the S-23.03
guard did NOT block at write time. (traces to ADR-045 §Rationale, "Tier 3 aligns with D-449(a)...
the validator is a mechanical gate, not a narrative attestation"; ADR-045 §Migration Plan Phase B
step 7)

### AC-003
The measurement additionally counts any case where S-23.03's guard blocked a write it should NOT
have (a false positive — a correctly-migrated stable-anchor citation incorrectly flagged), since
an over-triggering guard is also evidence relevant to the Phase-C decision (a high false-positive
rate might argue for Tier 3's more precise AST-based detection even if leakage is low). (traces to
ADR-045 §Decision, Tier 3, "if and when the Tier 1 thin new-pin guard proves insufficient" — false
positives are a form of guard insufficiency alongside false negatives)

### AC-004
At the end of the measurement window, this story produces a report (a new file under
`.factory/research/` or `.factory/cycles/v1.0-brownfield-backfill/` — the executing agent
determines the correct artifact-path-registry-compliant location) stating: the measured
residual-leakage count, the false-positive count, and an explicit Phase-C go/no-go recommendation
with its rationale. (traces to ADR-045 §Migration Plan Phase B step 7, "This measurement is the
gate for Phase C")

### AC-005
The report explicitly states which of the three Phase-C outcomes applies per ADR-045 §Migration
Plan Phase C steps 8/9/10: (a) non-trivial leakage → spike contextlint/mdbook-lint + bake-offs +
build Tier 3 crate; (b) content-dependent citations warrant Tier 2 → design the fingerprint
sidecar; (c) negligible leakage → Tiers 2/3 remain unbuilt indefinitely, thin guard + INDEX-
resolution is the standing steady-state architecture. (traces to ADR-045 §Migration Plan Phase C
steps 8, 9, 10)

### AC-006 (negative control)
This story does NOT build any Tier 2 or Tier 3 component regardless of what the measurement
finds — even a strong go-signal for Phase C only produces a recommendation and a handoff; the
actual Tier 2/3 build is explicitly a separate, future follow-up epic, not this story's own scope.
(traces to ADR-045 §Decision preamble item 2, "not authorized for build"; epic E-23 Forbidden
Dependencies)

## Tasks

1. Confirm or propose the Phase-B measurement window (AC-001); surface to orchestrator/human if
   not already fixed at ratification.
2. Define the literal-shell measurement method: how "leakage" is detected (e.g., a subsequent
   adversarial pass or state-manager consistency sweep finding a new/reintroduced pin the guard
   did not block) and how it is counted, with captured stdout per D-449(a).
3. Define the false-positive counting method (AC-003): review of the guard's `.factory/logs/`
   block records for any block that, on inspection, was a correctly-migrated citation.
4. Run the measurement across the confirmed window.
5. Author the report (AC-004) at an artifact-path-registry-compliant location, stating the
   leakage count, false-positive count, and the AC-005 explicit Phase-C recommendation.
6. Hand off the report to the orchestrator/human for the actual Phase-C go/no-go decision — this
   story's job ends at "produce the evidence and a recommendation," not at "decide."
