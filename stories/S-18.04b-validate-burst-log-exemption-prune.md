# S-18.04b — validate-burst-log / validate-dispatch-advance PreCompact Exemption + precompact-flush-prune.sh

## Narrative

As a factory hook-chain consumer making commits after a PreCompact flush,
I want validate-burst-log and validate-dispatch-advance WASM gates to exempt
commits with the canonical `PreCompact flush ` prefix from the
MULTI_COMMIT_CHAIN_NOT_ALLOWED detector (with SHA corroboration),
and a `precompact-flush-prune.sh` helper to prune the precompact-flush-log when
it exceeds 1000 entries (invoked by check-state-health, not by the flush hook itself),
so that PreCompact flush commits do not falsely trigger chain-detection guards
and the log remains bounded.

## Behavioral Contracts

| BC ID | Title | Version | PCs Exercised |
|-------|-------|---------|---------------|
| BC-5.41.003 | validate-burst-log and validate-dispatch-advance exempt commits with "PreCompact flush " prefix from MULTI_COMMIT_CHAIN_NOT_ALLOWED (F-8: SHA corroboration via precompact-flush-log append-log last-line FOURTH FIELD pre-embedded `commit` token — WASM reads embedded field, does NOT exec git; commit context injected host-side by dispatcher via git_context in payload.extra per ADR-029) | v2.0 | PC1–PC5, INV1–INV4 |

## Acceptance Criteria

### AC-001 (traces to BC-5.41.003 postcondition 1 — exemption with log present + FIELD-4=commit)
When `validate-burst-log` inspects a commit whose message begins with
`PreCompact flush ` AND the precompact-flush-log exists AND its last line's
FIELD-4 equals `commit`, the gate exempts the commit ONLY if the commit's SHA
matches FIELD-2 of the last log line. SHA-mismatch with a valid FIELD-4 is
NOT EXEMPT; the gate emits MULTI_COMMIT_CHAIN_NOT_ALLOWED as normal.

**Exec-free constraint (ADR-029 §Decision 3 + BC-5.41.003 v2.0 PC1 addendum):**
The commit subject and SHA evaluated by this AC are obtained HOST-SIDE by the
dispatcher (via S-18.04b-prereq) and delivered in `payload.extra.get("git_context")`.
The WASM gate MUST read `head_subject`, `head_sha`, `head_parent_subject`,
`head_parent_sha` from the `git_context` JSON object in `payload.extra`. Neither
`validate-burst-log` nor `validate-dispatch-advance` may call `host::exec_subprocess`
for commit-context acquisition. The trigger event is PostToolUse Bash (not Edit/Write)
per ADR-029 §Decision 1.

### AC-002 (traces to BC-5.41.003 postcondition 1 case (c) — log absent: prefix-match-only exemption)
When `validate-burst-log` inspects a commit with `PreCompact flush ` prefix AND
the precompact-flush-log is ABSENT (verified by `test -f` returning false or
equivalent WASM file-read absence), the gate exempts the commit based on prefix
match alone (no SHA corroboration available — case (c) of PC1 three-case logic).

### AC-003 (traces to BC-5.41.003 postcondition 1 case (b) — FIELD-4 corrupted: treat as absent, prefix-match-only exemption)
When the precompact-flush-log exists but the last line's FIELD-4 is absent, empty,
or not the literal string `commit` (indicating log corruption or truncation), the
gate treats the log entry as stale and falls through to case (c): prefix-match-only
exemption applies. This is case (b) of PC1: FIELD-4 corruption triggers the same
outcome as log absence — the gate does NOT use SHA corroboration when FIELD-4 is
not valid.

### AC-004 (traces to BC-5.41.003 postcondition 1 in-body + invariant 1 — SHA mismatch with valid FIELD-4 is NOT exempt)
When the precompact-flush-log exists, FIELD-4=`commit` (valid), and the commit's SHA
does NOT match FIELD-2 of the last log line, the commit is NOT exempt.
MULTI_COMMIT_CHAIN_NOT_ALLOWED is emitted as if no exemption exists. This is the
SHA-mismatch clause in PC1 body AND is reinforced by INV1 (which explicitly states
"a SHA-mismatch with valid `<type-field>==commit` is NOT EXEMPT — prevents
arbitrary-prefix bypass"). SHA-mismatch with a valid log is a security-relevant
discrepancy, not a tolerable stale-entry.

### AC-005 (traces to BC-5.41.003 invariant 3 + EC-004 — case sensitivity)
The prefix match is case-sensitive: `PreCompact flush ` (capital P, capital C,
space-space-space). A commit with message `precompact flush <args>` is NOT exempt.

### AC-006 (traces to BC-5.41.003 invariant 1 — symmetric implementation)
Both `validate-burst-log.wasm` AND `validate-dispatch-advance.wasm` implement
the exemption identically (same 3-case logic: log-absent, log-corrupted, log-valid
with SHA corroboration). The two WASM gates MUST behave symmetrically. Neither
may implement a superset or subset of the exemption logic.

**Exec-free constraint (ADR-029 §Decision 3):** Both WASM gates MUST read
commit subjects and SHAs exclusively from `payload.extra.get("git_context")`
(injected by the dispatcher per BC-1.16.001). Existing `host::exec_subprocess`
calls in `check_chain_from_git_context()` (the Bash-path chain-detection function; formerly `check_factory_artifacts_chain()` prior to ADR-029 rewire) in both crates MUST be removed in
this story. If `git_context` is absent or all fields are empty (dispatcher
fail-open), both gates return `None` (skip check).

### AC-007 (traces to BC-5.41.003 invariant 2 — VP-084 invocation discipline + ADR-029 §Decision 6 proof-model)
The bats/Rust proof harness for VP-084 MUST invoke `validate-burst-log` and
`validate-dispatch-advance` via the factory-dispatcher (NOT by calling the WASM
file directly via `wasmtime` or equivalent). The gates are native WASM plugins
registered in hooks-registry.toml; proof tests must exercise them through the
dispatcher invoke path to match production behavior.

**ADR-029 §Decision 6 proof-model update:** The bats proof envelope MUST use
`tool = "Bash"` (not `tool = "Edit"`) and include `tool_input.command` containing
`git commit`. The `git_context` object MUST be supplied in the envelope with all
four fields (`head_subject`, `head_sha`, `head_parent_subject`, `head_parent_sha`)
as the dispatcher would inject them — NOT sourced from exec. The negative-control
test MUST supply sentinel-containing subjects (`head_subject: "stage 1 backfill"`,
`head_parent_subject: "stage 2 backfill"`) via `git_context` to exercise the
MULTI_COMMIT_CHAIN_NOT_ALLOWED detection path. The dispatcher's `git_context`
injection (from S-18.04b-prereq) is exercised end-to-end (not bypassed).
The corrected schema for the bats negative-control envelope is:

```bash
envelope=$(printf '{"event":"PostToolUse","tool":"Bash","tool_input":{"command":"git -C .factory commit -m \"stage 1 backfill\""},"git_context":{"head_subject":"stage 1 backfill","head_sha":"<40-char-hex>","head_parent_subject":"stage 2 backfill","head_parent_sha":"<40-char-hex>"}}' ...)
```

### AC-008 (traces to BC-5.41.003 invariant 3 — exact prefix string)
The exempt prefix is exactly the string `PreCompact flush ` as produced by
`precompact-flush.sh` (AC-005 in S-18.04a). Implementer must import this
constant from a shared location or hardcode the exact byte sequence — no
substring match, no regex, no case-fold.

### AC-009 (traces to VP-090 section 0 — structural precondition)
`precompact-flush-prune.sh` validates that the precompact-flush-log file ends
with `\n` BEFORE counting entries. If the file does NOT end with `\n`, the
script exits non-zero with message "precompact-flush-log structural violation:
file must end with newline before pruning". No modification is performed.

### AC-010 (traces to VP-090 section 1 — prune threshold)
`precompact-flush-prune.sh` counts entries by counting physical lines. When
line count EXCEEDS 1000 (i.e., >= 1001 lines), the script prunes to the most
recent 500 entries (last 500 lines). When count is <= 1000, the script exits 0
with no modification.

### AC-011 (traces to VP-090 section 2 — atomic write)
The prune operation writes the pruned content to a temporary file in the same
directory, then atomically renames it to the log path. The original log MUST NOT
be modified if the atomic write fails. The last line (most recent entry) MUST be
preserved in the pruned output.

### AC-012 (traces to VP-090 section 3 — invocation context)
`precompact-flush-prune.sh` is invoked ONLY by `check-state-health` (or equivalent
maintenance entrypoint). It MUST NOT be invoked by `precompact-flush.sh`. The prune
script must not register itself as a hook plugin.

### AC-013 (traces to VP-090 section 4 — boundary conditions)
Exact boundary behavior:
- 1000 lines: no prune (threshold is >1000 — strictly greater than)
- 1001 lines: prune to 500 (threshold met)
- 500 lines: no prune
- 501 lines: no prune (well below threshold)
- 0 lines (empty file): exit 0 no-op (but structural precondition check: empty file vacuously satisfies `\n`-terminated if empty? No — empty file has NO trailing `\n`. The script must treat an empty file as a no-op without structural violation error, since an empty log has no entries to prune.)

## Forbidden Dependencies

`crates/hook-plugins/validate-burst-log` and `crates/hook-plugins/validate-dispatch-advance` MUST NOT:
- Read from the filesystem directly (WASM, pure parse)
- Shell out
- Implement the exemption as a substring match or case-insensitive match
- Call `host::exec_subprocess` for commit-context acquisition (exec-free constraint per ADR-029 §Decision 3 + BC-5.41.003 v2.0 PC1 + AC-006/AC-007) — HEAD/HEAD^ subjects and SHAs MUST be read from `payload.extra.get("git_context")` as injected by the dispatcher (BC-1.16.001)

`plugins/vsdd-factory/hooks/precompact-flush-prune.sh` MUST NOT:
- Be registered as a hook plugin (no hooks-registry.toml entry)
- Be called from precompact-flush.sh
- Use `python`, `jq`, `node`, or non-standard tools

## Previous Story Intelligence

S-18.04a defines the exact commit message prefix (`PreCompact flush `) and the
4-field log format (`<ISO-timestamp> <SHA> <cycle>/<step> commit`). This story's
exemption logic depends on that format being stable. Key architecture lesson from
existing validate-burst-log.wasm: the MULTI_COMMIT_CHAIN_NOT_ALLOWED check
examines the HEAD and HEAD^ commit messages. The exemption must be inserted into
this existing check path — not as a separate pre-check. The implementer must read
the existing MULTI_COMMIT_CHAIN_NOT_ALLOWED logic in validate-burst-log/src/lib.rs
before adding the exemption branch.

VP-084 invocation discipline (AC-007): validate-burst-log is a native WASM plugin,
NOT a bash script. Previous sessions have incorrectly tried to test it by calling
`wasmtime validate-burst-log.wasm` directly. The correct approach is to invoke it
through the factory-dispatcher's dispatch mechanism, matching how it runs in
production. Bats tests for VP-084 must use a dispatcher invocation fixture.

**ADR-029 re-architecture (S-18.04b-prereq / S-18.04b split — v1.7 addition):**
S-18.04b-prereq delivers the dispatcher-side git_context injection (BC-1.16.001).
This story (S-18.04b) delivers the WASM-side consumption: `check_factory_artifacts_chain()` → `check_chain_from_git_context()` (renamed during ADR-029 rewire)
is redesigned to read `payload.extra.get("git_context")` and extract the four fields
(`head_subject`, `head_sha`, `head_parent_subject`, `head_parent_sha`) instead of
calling `host::exec_subprocess`. The pure 3-case exemption logic (`check_multi_commit_chain`,
`is_precompact_flush_exempt`) is UNCHANGED — only the I/O wiring changes (ADR-029
§Decision 5). Key practical consequence: the WASM changes in this story FAIL (Red Gate)
until S-18.04b-prereq is merged, because `payload.extra.get("git_context")` returns
`None` without the dispatcher injection. This is intentional: the prereq/story split
preserves Red Gate discipline across the story boundary.

The vp084-proof.bats envelope must be updated to PostToolUse Bash schema per ADR-029
§Decision 6 (see AC-007). The prior `tool = "Edit"` envelope schema and the missing
`head_sha`/`head_parent_sha` fields are corrected in this story's bats deliverable.

## Architecture Compliance Rules

- Exemption logic must be in the EXISTING MULTI_COMMIT_CHAIN_NOT_ALLOWED code path, not a separate guard
- Symmetric implementation: copy-paste the 3-case exemption function into both crates, or extract to a shared crate (preferred for DRY compliance)
- **Exec-free constraint (ADR-029 §Decision 3):** `check_chain_from_git_context()` (the Bash-path chain-detection function; formerly `check_factory_artifacts_chain()` prior to ADR-029 rewire) in both `validate-burst-log/src/lib.rs` and `validate-dispatch-advance/src/lib.rs` MUST NOT call `host::exec_subprocess` for commit-context acquisition. All `host::exec_subprocess("git", ...)` calls for HEAD/HEAD^ subjects and SHAs MUST be removed. Commit context is obtained from `payload.extra.get("git_context")` as injected by the dispatcher (BC-1.16.001 via S-18.04b-prereq).
- **Fail-open for absent git_context:** If `payload.extra.get("git_context")` returns `None` or all four fields are empty strings (dispatcher fail-open case), the WASM gate MUST return `None` from `check_chain_from_git_context()` — skip the chain check, do not block (BC-5.41.003 Invariant 5; BC-1.16.001 INV3).
- **vp084-proof.bats schema update:** The existing negative-control envelope must be updated to `tool = "Bash"` with `tool_input.command` containing `git commit`, and `git_context` must include `head_sha` and `head_parent_sha` fields (ADR-029 §Decision 6 bats schema alignment). The `tool = "Edit"` schema was an ADR-029 gap identified by the re-architecture.
- `precompact-flush-prune.sh` must NOT appear in hooks-registry.toml
- `set -euo pipefail` in precompact-flush-prune.sh (CLAUDE.md convention)
- Atomic write via `mv` (POSIX rename) — not `cp` then `rm`
- No `--no-verify` git flags anywhere
