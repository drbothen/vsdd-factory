# S-18.04b — validate-burst-log / validate-dispatch-advance PreCompact Exemption + precompact-flush-prune.sh

## Narrative

As a factory hook-chain consumer making commits after a PreCompact flush,
I want validate-burst-log and validate-dispatch-advance WASM gates to exempt
commits with the canonical `PreCompact flush ` prefix from the
MULTI_COMMIT_CHAIN_NOT_ALLOWED detector (with SHA corroboration),
and a `precompact-flush-prune.sh` helper to prune the precompact-flush-log when
it exceeds 1000 entries (invoked by check-state-health, not by the flush hook itself),
so that PreCompact flush commits do not falsely trigger chain-detection guards
and the log remains bounded.

| BC ID | Title | Version | PCs Exercised |
|-------|-------|---------|---------------|
| BC-5.41.003 | PreCompact flush commits are exempt from MULTI_COMMIT_CHAIN_NOT_ALLOWED | v1.8 | PC1–PC5, INV1–INV3 |

## Acceptance Criteria

### AC-001 (traces to BC-5.41.003 postcondition 1 — exemption with log present + FIELD-4=commit)
When `validate-burst-log` inspects a commit whose message begins with
`PreCompact flush ` AND the precompact-flush-log exists AND its last line's
FIELD-4 equals `commit`, the gate exempts the commit ONLY if the commit's SHA
matches FIELD-2 of the last log line. SHA-mismatch with a valid FIELD-4 is
NOT EXEMPT; the gate emits MULTI_COMMIT_CHAIN_NOT_ALLOWED as normal.

### AC-002 (traces to BC-5.41.003 postcondition 2 — log absent)
When `validate-burst-log` inspects a commit with `PreCompact flush ` prefix AND
the precompact-flush-log is ABSENT, the gate exempts the commit based on prefix
match alone (no SHA corroboration available).

### AC-003 (traces to BC-5.41.003 postcondition 3 — FIELD-4 corrupted)
When the precompact-flush-log exists but the last line's FIELD-4 is not `commit`
(log corruption), the gate treats the log as absent and applies prefix-match-only
exemption (same as AC-002).

### AC-004 (traces to BC-5.41.003 postcondition 4 — SHA mismatch = not exempt)
When the precompact-flush-log exists, FIELD-4=`commit`, and the commit's SHA does
NOT match FIELD-2, the commit is NOT exempt. MULTI_COMMIT_CHAIN_NOT_ALLOWED is
emitted as if no exemption exists.

### AC-005 (traces to BC-5.41.003 postcondition 5 — case sensitivity)
The prefix match is case-sensitive: `PreCompact flush ` (capital P, capital C,
space-space-space). A commit with message `precompact flush <args>` is NOT exempt.

### AC-006 (traces to BC-5.41.003 invariant 1 — symmetric implementation)
Both `validate-burst-log.wasm` AND `validate-dispatch-advance.wasm` implement
the exemption identically (same 3-case logic: log-absent, log-corrupted, log-valid
with SHA corroboration). The two WASM gates MUST behave symmetrically. Neither
may implement a superset or subset of the exemption logic.

### AC-007 (traces to BC-5.41.003 invariant 2 — VP-084 invocation discipline)
The bats/Rust proof harness for VP-084 MUST invoke `validate-burst-log` and
`validate-dispatch-advance` via the factory-dispatcher (NOT by calling the WASM
file directly via `wasmtime` or equivalent). The gates are native WASM plugins
registered in hooks-registry.toml; proof tests must exercise them through the
dispatcher invoke path to match production behavior.

### AC-008 (traces to BC-5.41.003 invariant 3 — exact prefix string)
The exempt prefix is exactly the string `PreCompact flush ` as produced by
`precompact-flush.sh` (AC-005 in S-18.04a). Implementer must import this
constant from a shared location or hardcode the exact byte sequence — no
substring match, no regex, no case-fold.

### AC-009 (traces to VP-090 section 0 — structural precondition)
`precompact-flush-prune.sh` validates that the precompact-flush-log file ends
with `\n` BEFORE counting entries. If the file does NOT end with `\n`, the
script exits non-zero with message "precompact-flush-log structural violation:
file must end with newline before pruning". No modification is performed.

### AC-010 (traces to VP-090 section 1 — prune threshold)
`precompact-flush-prune.sh` counts entries by counting physical lines. When
line count EXCEEDS 1000 (i.e., >= 1001 lines), the script prunes to the most
recent 500 entries (last 500 lines). When count is <= 1000, the script exits 0
with no modification.

### AC-011 (traces to VP-090 section 2 — atomic write)
The prune operation writes the pruned content to a temporary file in the same
directory, then atomically renames it to the log path. The original log MUST NOT
be modified if the atomic write fails. The last line (most recent entry) MUST be
preserved in the pruned output.

### AC-012 (traces to VP-090 section 3 — invocation context)
`precompact-flush-prune.sh` is invoked ONLY by `check-state-health` (or equivalent
maintenance entrypoint). It MUST NOT be invoked by `precompact-flush.sh`. The prune
script must not register itself as a hook plugin.

### AC-013 (traces to VP-090 section 4 — boundary conditions)
Exact boundary behavior:
- 1000 lines: no prune (threshold is >1000 — strictly greater than)
- 1001 lines: prune to 500 (threshold met)
- 500 lines: no prune
- 501 lines: no prune (well below threshold)
- 0 lines (empty file): exit 0 no-op (but structural precondition check: empty file vacuously satisfies `\n`-terminated if empty? No — empty file has NO trailing `\n`. The script must treat an empty file as a no-op without structural violation error, since an empty log has no entries to prune.)

## Previous Story Intelligence

S-18.04a defines the exact commit message prefix (`PreCompact flush `) and the
4-field log format (`<ISO-timestamp> <SHA> <cycle>/<step> commit`). This story's
exemption logic depends on that format being stable. Key architecture lesson from
existing validate-burst-log.wasm: the MULTI_COMMIT_CHAIN_NOT_ALLOWED check
examines the HEAD and HEAD^ commit messages. The exemption must be inserted into
this existing check path — not as a separate pre-check. The implementer must read
the existing MULTI_COMMIT_CHAIN_NOT_ALLOWED logic in validate-burst-log/src/lib.rs
before adding the exemption branch.

VP-084 invocation discipline (AC-007): validate-burst-log is a native WASM plugin,
NOT a bash script. Previous sessions have incorrectly tried to test it by calling
`wasmtime validate-burst-log.wasm` directly. The correct approach is to invoke it
through the factory-dispatcher's dispatch mechanism, matching how it runs in
production. Bats tests for VP-084 must use a dispatcher invocation fixture.

## Architecture Compliance Rules

- Exemption logic must be in the EXISTING MULTI_COMMIT_CHAIN_NOT_ALLOWED code path, not a separate guard
- Symmetric implementation: copy-paste the 3-case exemption function into both crates, or extract to a shared crate (preferred for DRY compliance)
- `precompact-flush-prune.sh` must NOT appear in hooks-registry.toml
- `set -euo pipefail` in precompact-flush-prune.sh (CLAUDE.md convention)
- Atomic write via `mv` (POSIX rename) — not `cp` then `rm`
- No `--no-verify` git flags anywhere

## Library & Framework Requirements

- Rust: existing crate dependencies in validate-burst-log and validate-dispatch-advance — no new external crates
- bash >= 4.x for precompact-flush-prune.sh
- `mv` (POSIX rename) for atomic write — available in all CI environments
- `wc -l` for line counting in prune script
- `tail -n 500` for extracting last 500 lines
