# S-24.01: vsdd-factory:wrap skill — session pause, checkpoint, and lock-release orchestration

## Narrative

- **As a** factory operator who needs to pause the pipeline cleanly at any point
- **I want** a single `/vsdd-factory:wrap` skill invocation that orchestrates all
  pause-and-checkpoint steps (health check, WIP persistence, STATE.md PAUSED
  transition via state-manager, lock release, durability verification, and resume
  guidance)
- **So that** I can `/clear` or close the session with zero data loss and resume
  exactly from where I left off by opening a fresh session and running
  `/vsdd-factory:rehydrate-wave` then `/vsdd-factory:next-step`

## Behavioral Contracts

| BC ID | Title | Anchor Justification |
|-------|-------|---------------------|
| BC-6.28.001 | `/vsdd-factory:wrap` MUST halt new work, persist all in-flight changes to durable branches, delegate STATE.md PAUSED transition and dated Session Resume Checkpoint to state-manager (never editing STATE.md directly), release the factory lock, verify a clean factory-artifacts working tree, and emit resume guidance that names `/vsdd-factory:rehydrate-wave` before `/vsdd-factory:next-step` | This BC is the exhaustive behavioral specification for the wrap skill; every AC in this story maps directly to one or more of its 16 postconditions or 3 invariants. The skill (`plugins/vsdd-factory/skills/wrap/SKILL.md`) is the sole implementation vehicle for CAP-040 and the sole artifact this story delivers. |

## Acceptance Criteria

### AC-001 — Halt new work; no pipeline sub-agents post-halt
The SKILL.md Step 1 instructs the operator not to spawn any new pipeline sub-agents
(orchestrator, implementer, test-writer, holdout-evaluator, etc.) from Step 1 onward.
If pipeline sub-agents are currently running, each is allowed to complete its current
atomic step (e.g., a micro-commit or a single test run); the exact state at halt is
recorded in the Session Resume Checkpoint at Step 4. No new pipeline work is initiated
after Step 1 executes.
(traces to BC-6.28.001 INV-3: "Skill MUST NOT spawn new pipeline sub-agents after Step 1")

### AC-002 — Step 2 factory health routing
Step 2 invokes `/vsdd-factory:check-state-health` and routes as follows:
(a) HEALTHY or WARNINGS: proceed directly to Step 3.
(b) NEEDS-COMPACT: `/vsdd-factory:compact-state` runs before state-manager delegation;
    the pause checkpoint lands in the slimmed STATE.md; all 16 PCs are verified against
    the compacted file.
(c) STATE.md missing or corrupted: `/vsdd-factory:recover-state` runs; human approval
    of the reconstruction is REQUIRED before the wrap continues past Step 2; Step 7
    is NOT emitted until PC-1 through PC-15 are satisfied on the reconstructed file.
(traces to BC-6.28.001 preconditions 2 and 4; EC-002; EC-003)

### AC-003 — WIP persistence (PC-13)
Step 3 ensures no uncommitted changes in the main product repo checkout or any active
`.worktrees/STORY-*` story worktrees that were intended to be saved are left uncommitted.
For each worktree, exactly one of the following two conditions holds:
(a) WIP committed to the story's feature branch — never to main, develop, or the
    default branch — with commit message `wip(<STORY-ID>): session wrap checkpoint —
    <what is half-done>`, and pushed to remote if a remote is configured; OR
(b) The exact un-committable state (mid-red-gate, merge conflict, build failure) is
    explicitly documented in the Session Resume Checkpoint at PC-8 field (c) rather
    than forced into a broken commit.
(traces to BC-6.28.001 PC-13)

### AC-004 — STATE.md PAUSED transition and Session Resume Checkpoint via state-manager (PC-1 through PC-10)
Step 4 delegates ALL STATE.md mutations to `vsdd-factory:state-manager` via the Agent
tool. The wrap skill makes ZERO direct Write or Edit tool calls on STATE.md at Step 4
or any other step. State-manager performs all of the following in a single burst:
(a) `pipeline:` frontmatter set to `PAUSED` (PC-1).
(b) `timestamp:` refreshed to the pause instant ISO-8601 string (PC-2).
(c) `phase:` updated to `PAUSED <YYYY-MM-DD>. <position string>` (PC-3).
(d) `current_step:` updated per verbatim-strict chain (D-441/D-442/D-443/D-444/D-449):
    no meta-commentary, no clause-reordering, no justification-suffix injection (PC-4).
(e) `last_amended:` updated with today's date, version token, `state-manager` identity,
    and single-line pause description (PC-5).
(f) `version:` bumped by exactly one point; no double-bump (PC-6; TD-VSDD-053).
(g) Banner `wc-l` claim and dual-margin updated to match actual `wc -l .factory/STATE.md`
    after the pause commit (PC-7; BC-5.39.005).
(h) Prior `## Session Resume Checkpoint` archived to `cycles/<cycle>/session-checkpoints.md`
    before the new one is written (content-routing discipline).
(i) New `## Session Resume Checkpoint` written with all six minimum fields: date +
    position; convergence counter if applicable; in-flight work; pending human decisions
    and blockers; WIP branch list with SHAs (or "none"); exact resume command (PC-8).
(j) Phase Progress row `SESSION-WRAP-PAUSE-<YYYY-MM-DD>` appended (PC-9).
State-manager commits with subject prefix `factory(pause):` (single commit per
TD-VSDD-053; PC-11) and pushes to remote if configured (PC-12). Wrap skill waits for
state-manager completion report before proceeding to Step 5.
(traces to BC-6.28.001 PC-1 through PC-10; INV-1)

### AC-005 — Factory lock release via factory-unlock (PC-14)
Step 5 invokes `/vsdd-factory:factory-unlock` if this session holds the factory lock,
emitting `factory.lock.released` per BC-6.23.001 PC4. If no lock is held, Step 5 is
skipped silently and the Step 7 report shows `Lock: not held`. A lock that remains
held at the time the Step 7 report is emitted is a wrap failure.
(traces to BC-6.28.001 PC-14; EC-001)

### AC-006 — Step 6 durability verification (PC-11, PC-12)
Step 6 verifies ALL of the following before declaring the wrap complete:
(a) `git -C .factory status --porcelain` returns empty (factory-artifacts working
    tree clean; PC-12).
(b) STATE.md frontmatter reads `pipeline: PAUSED`.
(c) Exactly one `## Session Resume Checkpoint` section exists in STATE.md and reflects
    today's date.
(d) Product repo and active story worktrees have no uncommitted intended-to-be-saved
    changes, or their state is explicitly documented in the checkpoint (PC-13 double-check).
If any check fails, the specific failure is addressed (re-delegate to state-manager if
STATE.md is wrong; re-run porcelain check if tree is dirty) and Step 6 is re-verified.
Step 7 is NOT emitted until all checks pass.
(traces to BC-6.28.001 PC-11; PC-12; INV-2)

### AC-007 — Resume guidance ordering: rehydrate-wave BEFORE next-step (PC-15)
The Step 7 "To resume" block names `/vsdd-factory:rehydrate-wave` BEFORE
`/vsdd-factory:next-step`. The ordering is non-negotiable per BC-6.24.001: rehydrate-wave
must execute first in a fresh session to inject the correct wave scope before next-step
attempts to route work. A wrap report that lists only `next-step` (without
`rehydrate-wave`) is a behavioral violation. A report that lists them in reverse order
(next-step first) is also a behavioral violation.
(traces to BC-6.28.001 PC-15; BC-6.24.001 Postcondition 4)

### AC-008 — "Factory Wrapped" report content (PC-16)
Step 7 emits a `## Factory Wrapped` report containing all five required items:
(a) `Pipeline: PAUSED at <phase> / <current_step>` (verbatim from the updated STATE.md
    frontmatter fields).
(b) `.factory/STATE.md checkpoint: committed <sha>, pushed: yes` OR `pushed: no (<reason>)`.
(c) `WIP commits: <branch>@<sha>, ...` OR `none`.
(d) `Lock: released` OR `Lock: not held`.
(e) `Safe to /clear or close this session.` (exact wording — this is the human-facing
    confirmation signal that all postconditions have been verified).
Step 7 is NOT emitted while any PC-1 through PC-15 postcondition is unmet (INV-2
enforced absolutely).
(traces to BC-6.28.001 PC-16; INV-2)

### AC-009 — Invariants INV-1 and INV-2: no direct STATE.md edit; verify-then-report
INV-1: Zero direct Write or Edit tool calls targeting `.factory/STATE.md` appear in the
skill body at any step, including error-recovery steps. If state-manager is unavailable
at Step 4, the wrap fails with a clear error message; it does NOT fall back to direct
STATE.md editing.
INV-2: The `## Factory Wrapped` report and the `Safe to /clear or close this session.`
declaration are NOT emitted until all Step 6 durability checks pass completely. Reporting
success ahead of verified durability is a behavioral violation identical in severity to
data loss.
(traces to BC-6.28.001 INV-1 + INV-2; Precondition 3)
