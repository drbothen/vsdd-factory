# S-23.06: Corpus migration — BC-INDEX.md (421 live pins)

## Narrative

- **As a** state-manager/consistency-validator executing ADR-045's mechanical corpus migration
- **I want** to run the S-23.02 codemod against `.factory/specs/behavioral-contracts/BC-INDEX.md`,
  review its dry-run output, and commit the result as a single atomic commit
- **So that** BC-INDEX — the single highest-concentration file (421 of the ~3,074 live pins, per
  ADR-045's corpus scan) — is migrated to stable-anchor form first, delivering the largest single
  chunk of Tier-1's leverage in one commit

## Context / Problem Statement

ADR-045 §Consequences, Negative/Trade-offs quantifies BC-INDEX.md at 421 live pins — the single
largest concentration of any file in the corpus, and part of the 4-INDEX-files 1,573-pin (51%)
cluster ADR-045 §Migration Plan Phase A step 5 explicitly calls out as "simultaneously the
highest-value and highest-risk atomic commits, and the locus of Tier 1's maximum leverage."
BC-INDEX.md is also POLICY 7's H1-title-source-of-truth registry and the target of S-23.04's
BC-INDEX row-offset sidecar resolution — this migration must not disturb the row-offset
invariants that sidecar depends on (row start-byte positions), only the inline version-token
text within each row's citation cells (if any exist within BC-INDEX's own body — most of
BC-INDEX's 421 pins are expected to be within its own Version column cells, which are Arm A1's
authoritative source, not a "citation" in ADR-045's sense; the implementer must confirm at
execution time exactly which of BC-INDEX's 421 counted pins are load-bearing *citations to other
IDs* within BC-INDEX's own narrative/changelog text, versus BC-INDEX's own authoritative Version
column, which is explicitly out of Tier-1's migration scope per S-23.05 AC-003).

## Acceptance Criteria

### AC-001
Running the S-23.02 codemod in `--dry-run` mode against `.factory/specs/behavioral-contracts/BC-INDEX.md`
produces a diff report; the diff report is reviewed by the executing agent (state-manager or
consistency-validator) before apply. (traces to ADR-045 §Migration Plan Phase A step 5; S-23.02
AC-006)

### AC-002
The codemod does NOT modify BC-INDEX.md's own authoritative Version column cells (these are the
ground-truth source S-23.04's resolver reads from, not a citation) — only load-bearing inline
version pins found in BC-INDEX's own live narrative/prose sections that cite OTHER stable IDs
(e.g., an ADR cite within a BC-INDEX changelog-adjacent live note). (traces to S-23.05 AC-003;
ADR-045 §Decision, Tier 1 — the INDEX row itself remains ground truth)

### AC-003
The codemod does NOT modify BC-INDEX.md's `modified:`/`last_amended:`/`[Prior:]` frontmatter
fields or any `## Changelog`/`## Amendment` section content (S-23.01 AC-001 exempt zones).
(traces to ADR-045 §Decision, Tier 1, "Permitted exceptions")

### AC-004
The migration is applied as exactly one atomic commit touching only BC-INDEX.md (plus, if S-23.04's
BC-INDEX row-offset sidecar requires regeneration because row byte-offsets shifted, the sidecar
file in the same commit), per TD-VSDD-053 single-commit-per-burst. (traces to ADR-045 §Migration
Plan Phase A step 5, "one atomic commit per document class"; CLAUDE.md TD-VSDD-053)

### AC-005
Post-commit, S-23.05's extended `validate-cross-site-correspondence` gate and S-23.03's thin
new-pin guard both pass a re-run against BC-INDEX.md with zero findings. (traces to S-23.03
AC-001/AC-003; S-23.05 AC-001/AC-006)

### AC-006 (negative control)
Post-commit, a targeted grep for any remaining `\bBC-\d+\.\d{2}\.\d{3}\b[^\n]{0,80}\bv\d+(?:\.\d+)*\b`
pattern within BC-INDEX.md's live (non-exempt) sections returns zero matches. (traces to ADR-045
§Consequences Positive, "Cohort re-anchoring eliminated by construction")

## Tasks

1. Run `xref-codemod --dry-run` against `.factory/specs/behavioral-contracts/BC-INDEX.md`.
2. Review the diff report; exclude any row incorrectly flagged inside the authoritative Version
   column (EC-002).
3. Apply the codemod (`--apply`).
4. Regenerate the BC-INDEX row-offset sidecar (S-23.04) if row byte-offsets shifted.
5. Run S-23.03's guard and S-23.05's extended parity gate against the migrated file; confirm zero
   findings (AC-005).
6. Commit BC-INDEX.md (+ sidecar if regenerated) as one atomic commit.
7. Run the AC-006 negative-control grep and record its zero-match result in the commit body.
