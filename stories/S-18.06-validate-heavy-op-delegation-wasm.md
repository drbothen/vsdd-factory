# S-18.06: validate-heavy-op-delegation WASM Gate — Advisory DelegationRecommended on Heavy Bash Operations

**Epic:** E-18 — Factory Context Durability (feature #173)
**Wave:** 5 (depends on S-18.03 wave-management skill set being present)
**Depends on:** S-18.03
**Blocks:** S-18.07, S-18.08
**Priority:** P1 (closes ADR-026 §Decision 12 advisory gate; pure-parse WASM per §Decision 8)
**BC gate:** BC-4.15.001 v1.2 (draft; all postconditions PC-A/PC-B/PC-C/PC-D and all 4 invariants in scope)
**Subsystem anchor:** SS-04 owns this story's scope because SS-04 is the Plugin Ecosystem and `validate-heavy-op-delegation` is a new native WASM crate under `crates/hook-plugins/` per ARCH-INDEX Subsystem Registry.

## Narrative

- **As a** factory orchestrator or agent issuing Bash tool calls that may saturate the context window
- **I want** the factory-dispatcher to emit a `DelegationRecommended` advisory nudge (to both stderr and the structured `plugin.log` channel) whenever a Bash command matches a configured heavy-operation pattern (first-match), while NEVER blocking the command
- **So that** agents are guided to delegate heavy operations (large cargo test runs, recursive grep traversals, full bats suites) to sub-agents or background worktrees, reducing context-window pressure and the probability of uncoordinated mid-wave auto-compaction events that violate DI-020 — implementing ADR-026 §Decision 12 (advisory-only in v1; never blocks) and §Decision 8 (WASM for pure-function command-string matching; no side effects)

## Behavioral Contracts

## Acceptance Criteria

### AC-001 (traces to BC-4.15.001 postcondition PC-B-B1 — stderr emission on pattern match; nudge message; no stdout write)

When a Bash command matches any configured heavy-operation pattern (first-match; substring containment; case-sensitive), the gate MUST emit a human/LLM-visible nudge message to **stderr** containing:
- The matched pattern string.
- A `command_preview` of the first ≤120 characters of the command string (truncated with `…` / U+2026 if the command exceeds 120 characters).
- The delegation recommendation text.

The gate MUST NOT write any advisory content to stdout (stdout is the dispatcher's tool-result channel).

**Test (bats):** `test_heavy_op_gate_emits_stderr_nudge_on_pattern_match()`
— Setup: Bash command `cargo test --release --workspace`; default pattern list includes `cargo test --release`.
— Assert: stderr contains `cargo test --release` and the command preview; stdout does NOT contain the advisory message; dispatcher exit 0.

### AC-002 (traces to BC-4.15.001 postcondition PC-B-B2 — plugin.log structured record on pattern match; 5 required fields)

When a Bash command matches a configured pattern (first-match), the gate MUST emit a structured advisory record to the dispatcher's `plugin.log` channel with exactly the following fields:
- `level: warn`
- `code: DelegationRecommended`
- `matched_pattern`: the exact first-matching pattern string
- `command_preview`: the first ≤120 characters of the command string (truncated with `…` if longer)
- `message`: human-readable delegation recommendation string

**Test (bats):** `test_heavy_op_gate_emits_plugin_log_delegation_recommended_on_match()`
— Setup: Bash command `grep -r "TODO" .`; pattern `grep -r` in the list.
— Assert: dispatcher `plugin.log` contains exactly one record with `code: DelegationRecommended`; `matched_pattern` is `"grep -r"`; `level` is `warn`; `command_preview` is present and ≤121 chars (120 + ellipsis).

### AC-003 (traces to BC-4.15.001 postcondition PC-A — no emission on no-match; Continue)

When a Bash command does NOT match any configured pattern after exhausting the full pattern list, the gate MUST return Continue with NO stderr emission and NO `plugin.log` record. The absence of any emission is a load-bearing postcondition.

**Test (bats):** `test_heavy_op_gate_no_emission_on_no_match()`
— Setup: Bash command `cargo fmt --check --all`; default pattern list does not contain this string.
— Assert: dispatcher exit 0; no `DelegationRecommended` record in `plugin.log`; stderr from gate is empty or contains no advisory for this command.

### AC-004 (traces to BC-4.15.001 invariant 2 — never blocks; always returns Continue under ALL conditions)

The gate MUST return `block_intent = false` (Continue) under ALL conditions: pattern match, no match, and crash. Setting `block_intent = true` or returning a non-Continue result from within the gate's own non-crash logic is a specification violation.

**Test (unit):** `test_heavy_op_gate_always_returns_continue_on_match()`
— Assert: for every test vector in BC-4.15.001 §Canonical Test Vectors that expects a match, the dispatcher response indicates Continue (not blocked); dispatcher exit 0 in each case.

**Test (unit):** `test_heavy_op_gate_always_returns_continue_on_no_match()`
— Assert: for `cargo fmt --check --all` (no match), dispatcher exit 0; no block registered.

**Test (unit):** `test_heavy_op_gate_fail_open_on_wasm_panic()`
— Simulate WASM panic mid-pattern-scan; assert dispatcher exit 0 (Continue); `plugin.crashed` in dispatcher internal log; no advisory emitted.

### AC-005 (traces to BC-4.15.001 invariant 3 — first-match; deterministic; single advisory per invocation)

When multiple patterns from the configured list would match the same command string, the gate MUST stop at the FIRST matching pattern and emit exactly ONE `DelegationRecommended` advisory. Subsequent patterns are not evaluated after a match.

**Test (unit):** `test_heavy_op_gate_first_match_semantics_single_advisory()`
— Setup: Bash command `grep -r TODO . | grep -R FIXME`; pattern list has `grep -r` before `grep -R`.
— Assert: exactly one `DelegationRecommended` record in `plugin.log`; `matched_pattern` is `"grep -r"` (first match).

### AC-006 (traces to BC-4.15.001 invariant 4 — command_preview ≤120-char truncation; identical in both channels)

The `command_preview` field in BOTH the stderr message (AC-001) and the `plugin.log` record (AC-002) MUST be:
- Equal to the full command string if it is ≤120 characters.
- The first 120 characters followed by `…` (U+2026; one Unicode code point) if the command exceeds 120 characters, yielding a 121-character field.

The truncation MUST be applied identically in both emission channels. A preview that differs between stderr and `plugin.log` is a specification violation.

**Test (unit):** `test_heavy_op_gate_truncates_command_preview_at_120_chars()`
— Setup: Bash command of 200 characters containing `grep -r`.
— Assert: `command_preview` in `plugin.log` is exactly 121 code points (120 chars + U+2026); stderr nudge message carries the same 121-code-point preview; gate returns Continue.

**Test (unit):** `test_heavy_op_gate_no_truncation_on_short_command()`
— Setup: Bash command `grep -r .` (9 characters; well under 120).
— Assert: `command_preview` equals the full command string (no truncation; no ellipsis appended).

### AC-007 (traces to BC-4.15.001 postcondition PC-D — non-Bash tool call: no-op via registry tool filter)

The registry `tool = "Bash"` filter MUST prevent the dispatcher from invoking the plugin on non-Bash tool calls. For a Write, Edit, or Read PreToolUse event, the plugin is NOT dispatched; no `DelegationRecommended` record appears in `plugin.log`; effective Continue.

**Test (bats):** `test_heavy_op_gate_not_dispatched_on_write_tool_call()`
— Setup: synthetic PreToolUse Write event with `file_path = "/tmp/test.md"`.
— Assert: dispatcher exit 0; no `DelegationRecommended` record in `plugin.log`; no advisory in stderr.

### AC-008 (traces to BC-4.15.001 precondition 1 — hooks-registry.toml entry has canonical shape; name + plugin + tool filter + [hooks.config] patterns)

The `hooks-registry.toml` entry for `validate-heavy-op-delegation` MUST be present with the exact canonical shape (native-WASM form; both `name` and `plugin` fields required per sibling BC-4.14.001 PC1 precedent):

```toml
[[hooks]]
name = "validate-heavy-op-delegation"
event = "PreToolUse"
plugin = "hook-plugins/validate-heavy-op-delegation.wasm"
tool = "Bash"
on_error = "continue"
async = false
timeout_ms = 5000

[hooks.config]
patterns = [
  "cargo test --release",
  "grep -r",
  "grep -R",
  "find . -name",
  "find . -type",
  "./run-all.sh",
  "./run-bats.sh"
]
```

`on_error = "continue"` is mandatory. The `[hooks.config] patterns` list is the v1 default set. The `name` and `plugin` fields MUST both be present (canonical native-WASM shape; bare logical name in `plugin =` without `name =` is a specification violation per BC-4.14.001 v1.9 F-P14-002 precedent).

**Test (bats):** `test_heavy_op_gate_registry_entry_has_canonical_shape()`
— Assert: `grep -A 15 'name = "validate-heavy-op-delegation"' plugins/vsdd-factory/hooks-registry.toml` produces the expected block; `event = "PreToolUse"` present; `tool = "Bash"` present; `on_error = "continue"` present; `plugin = "hook-plugins/validate-heavy-op-delegation.wasm"` present; `[hooks.config]` block with `patterns` list present.

### AC-009 (traces to BC-4.15.001 invariant 1 — pure-parse; no filesystem, subprocess, or context access)

The WASM gate MUST read ONLY the `command` field from the PreToolUse payload. It MUST NOT execute any git subprocess, read any file from the filesystem, read from the context window, or make any network call. This invariant makes WASM the correct implementation choice per ADR-026 §Decision 8.

**Test (unit):** `test_heavy_op_gate_pure_parse_no_filesystem_access()`
— Uses `include_str!` to embed `src/lib.rs` and `src/main.rs` as string literals at compile time, then asserts that neither source file contains the substrings `std::fs`, `std::process`, or `std::net`. This source-fence test runs in CI via `cargo test --workspace` and fails automatically if a forbidden import is introduced into the crate. There is no `cargo clippy` disallowed-types configuration for this gate — the unit test IS the enforcement mechanism.

### AC-010 (traces to BC-4.15.001 postcondition PC-C — crash: fail-open Continue; plugin.crashed in dispatcher log)

When the WASM gate panics (fuel exhaustion, ABI violation, logic error) during pattern evaluation, the dispatcher MUST return Continue (fail-open per `on_error = "continue"`). A `plugin.crashed` event MUST appear in the dispatcher's internal log. The Bash tool call MUST proceed unblocked.

**Test (bats):** `test_heavy_op_gate_fail_open_on_crash_dispatcher_continues()`
— Simulate gate crash by deploying a stub WASM that immediately panics.
— Assert: dispatcher exit 0; Bash command is not blocked; `plugin.crashed` present in dispatcher internal log.

### AC-011 (traces to BC-4.15.001 edge case EC-012 — empty patterns list: no emission on any Bash command)

When an operator configures `patterns = []` (empty list), no pattern can ever match. ALL Bash commands MUST pass silently (PC-A for every command); no advisory emitted for any command.

**Test (unit):** `test_heavy_op_gate_empty_pattern_list_no_emission()`
— Setup: registry override with `patterns = []`.
— Setup: Bash command `cargo test --release --workspace` (would normally match).
— Assert: dispatcher exit 0; no `DelegationRecommended` in `plugin.log`; no advisory in stderr.

## Architecture Compliance Rules

1. **Pure-parse; no side effects (BC-4.15.001 Inv1; ADR-026 §Decision 8):** The WASM crate source MUST NOT import `std::fs::`, `std::process::`, `std::net::`, or any external I/O crate. CI `cargo clippy` must be configured to flag these as errors in the `validate-heavy-op-delegation` crate.
2. **Never blocks (BC-4.15.001 Inv2):** The crate source MUST NOT contain any code path that sets `block_intent = true`. Promotion to blocking mode requires a separate BC-4.15.001 amendment by the product-owner — no implementer-directed blocking is permitted.
3. **First-match deterministic (BC-4.15.001 Inv3):** Pattern matching iterates the `patterns` list in declaration order; on first match, the function returns with exactly one advisory emission. The loop MUST use an early-exit construct (not collect all matches then filter).
4. **command_preview truncation (BC-4.15.001 Inv4):** The truncation logic MUST be extracted into a shared utility function used by BOTH the stderr emission (B-1) and the plugin.log emission (B-2). Two independent truncation implementations would create a channel-divergence drift risk.
5. **Canonical TOML shape (BC-4.15.001 PC1):** The registry entry MUST include all required fields from PC1 verbatim. Do NOT copy the shape from older hook entries that pre-date the BC-4.14.001 v1.9 canonical-native-WASM fix.
6. **Forbidden dependencies:** `crates/hook-plugins/validate-heavy-op-delegation/` MUST NOT depend on `crates/factory-lock-parse/`, `crates/context-resolvers/`, or any crate that reads from `factory-artifacts`. If this crate gains such a dependency, the build MUST fail (add to `[workspace.package] deny` or CI lint).
