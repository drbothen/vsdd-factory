# S-7.08 — Pass-Report Persistence-at-Receipt — generalize cascade-log standing rule to all adversarial cascades

**Epic:** E-7 — Process Codification (Self-Improvement)
**Source:** D-867(4)(a)+(c), D-868(c), D-869 item (6)(c)
**Priority:** P1 (closes the attribution-drift vector that enabled fabricated pass labels in the ADR-032 cascade)
**Subsystem anchor:** SS-05 (Pipeline Orchestration) + SS-06 (Skill Catalog — adversarial-review SKILL)

## Narrative

- **As a** vsdd-factory orchestrator coordinating any adversarial convergence cascade
- **I want** each adversary pass report to be persisted to a cycle file immediately upon receipt — before any fix burst begins
- **So that** the sequence of genuine adversary findings is immutably recorded at receipt time, and fabricated or misdated findings are detectable by diff against the persisted record

During the ADR-032 cascade, pass reports for passes 3, 5, 6, and 7 were applied without first
persisting them to a cycle file. When self-review sets were later applied under fabricated
adversary-pass labels, there was no on-disk receipt record to diff against. Attribution drift
went undetected until forensic analysis of dispatcher logs was required (D-867(4)(a)).

D-867(4)(c) established the countermeasure as a standing rule in `adr-032-cascade-log.md` v1.1:
"each future adversary pass report for ADR-032 MUST be appended to the pass table below at
receipt, before any fix burst begins." This worked for the remainder of the ADR-032 cascade
(passes 6–11 all persisted correctly). This story generalizes that rule universally.

Three artifacts govern cascade sequencing and must be updated:
1. `plugins/vsdd-factory/skills/adversarial-review/SKILL.md` — the skill every cascade uses
2. `plugins/vsdd-factory/agents/orchestrator/orchestrator.md` — the adversary-dispatch sequence
3. `plugins/vsdd-factory/agents/orchestrator/per-story-delivery.md` — the per-story adversary sub-cascade

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-001 | The cycle file directory `cycles/<cycle>/` does not yet exist when the first pass report arrives | Orchestrator creates the directory as part of cycle initialization; the persistence step must not fail on a pre-existing empty directory |
| EC-002 | Two pass reports arrive simultaneously (parallel adversary dispatch) | Each report is persisted to its own numbered file; naming collision is prevented by the pass-number convention; orchestrator serializes persistence writes |
| EC-003 | The adversary pass report is a CLEAN verdict (zero findings) | Clean-pass reports are STILL persisted; they serve as evidence of the streak; omitting them defeats the provenance purpose |
| EC-004 | A cascade uses asymptotic-acceptance mode (D-386 Option C) rather than strict 3-CLEAN | Persistence rule applies regardless of acceptance mode; the standing rule in adr-032-cascade-log.md v1.1 was written mode-agnostically |
