# S-4.11 — Strengthen AC-007 jitter-uncorrelation test to hard sequence-level assertion

**Epic:** E-4 — Observability Sinks and RC Release
**Depends on:** none (test-file-only change; no dependency on in-flight stories)
**Blocks:** none
**Priority:** P2 (test quality; no user-visible behavior change; no production code change)
**Scope:** Test-only — changes only `crates/sink-http/tests/bc_3_07_001_backoff.rs`

> **Origin:** Deferred from PR #201 review NIT-1 (human-approved deferral 2026-06-23).
> AC-007 in S-4.09 traces to BC-3.07.001 invariant 2 (per-instance PRNG uncorrelated jitter).
> The implementing test `test_BC_3_07_001_per_instance_prng_uncorrelated` currently SOFT-passes:
> it verifies liveness (both sinks slept ≥50ms) but does NOT hard-assert uncorrelation, because
> a single-draw `assert_ne!` on jitter values has a ~2% incidental-collision rate and would be flaky.
> Consequence: a global-static-PRNG regression would only appear as CI log noise, never a red test.

## Narrative

As a test-infrastructure maintainer, I want the per-instance PRNG uncorrelation test
for BC-3.07.001 invariant 2 to hard-assert that two sink instances produce different
jitter sequences, so that a global-static-PRNG regression causes a CI red, not
invisible log noise.

## Acceptance Criteria

### AC-001 — BC-3.07.001 invariant 2: sequence-level uncorrelation hard assertion
`test_BC_3_07_001_per_instance_prng_uncorrelated` draws N≥8 jitter values per sink
instance by submitting N events to a 503-always mock server with `max_retries=2`, so
each event triggers exactly one backoff draw. The test collects the N inter-attempt
elapsed durations for each sink instance and asserts that the two N-length sequences
are not identical (element-wise). The probability of an accidental full-sequence match
under correct per-instance PRNG seeding is astronomically small (≈ (1/50)^8 ≈ 4e-14
for N=8 draws from a [0, 50ms] uniform distribution); a global-static-PRNG regression
causes the sequences to be byte-identical and the assertion fails with 100% reliability.

(traces to BC-3.07.001 invariant 2: "Jitter source must be seeded from a thread-local
or per-instance PRNG — not a global static (prevents correlated thundering herd across
concurrent sink instances)")

### AC-002 — Removal of the soft-pass `eprintln!` path
The existing `let _ = diff; // liveness verified above` soft-pass pattern and any
associated `eprintln!` note is removed and replaced by a hard `assert_ne!` or
equivalent structural assertion on the two sequences. No soft-pass commentary remains
as the primary behavioral gate for invariant 2.

(traces to BC-3.07.001 invariant 2: the invariant requires test enforcement, not
review enforcement)

### AC-003 — Liveness assertions retained
The existing liveness assertions (`elapsed1 >= Duration::from_millis(50)` and
`elapsed2 >= Duration::from_millis(50)`) are retained to confirm both sinks actually
exercised the backoff path. They are complementary to — not a replacement for — the
sequence-level uncorrelation assertion from AC-001.

(traces to BC-3.07.001 postcondition 1: the delay formula is mandatory; liveness is a
necessary precondition for the uncorrelation assertion to be meaningful)

### AC-004 — No flakiness introduced
The test MUST NOT be flaky under correct per-instance PRNG seeding. N is chosen large
enough (N≥8) that the probability of an accidental full-sequence match under correct
seeding is negligible (≪1e-10). No sleep-timing assertions are introduced that could
fail under CI scheduler jitter; comparisons are structural (sequence equality), not
absolute-timing assertions.

(traces to BC-3.07.001 invariant 2: the invariant test must be both reliable and
non-flaky — soft-passing was the prior compromise to avoid flakiness; this story
eliminates the trade-off by switching from single-draw to sequence comparison)

### AC-005 — No production code change
The diff is confined exclusively to `crates/sink-http/tests/bc_3_07_001_backoff.rs`.
No changes to `crates/sink-http/src/`, `crates/sink-http/Cargo.toml`, or any other
file outside the test module. `cargo test --workspace --all-targets` passes GREEN after
the change.

(traces to BC-3.07.001 invariant 2: the invariant already holds in production code per
S-4.09 implementation; this story improves test coverage of an existing invariant, not
the invariant itself)

sequence comparison, which reduces collision probability to negligible levels.
