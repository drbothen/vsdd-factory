# S-18.13 — wave-handoff skill writes HANDOFF.md via the Write tool so the PostToolUse completeness gate fires (gate-trigger fix)

**Epic:** E-18 — Factory Context Durability (feature #173)
**Wave:** 4 (depends on S-18.01 merged + S-18.02 WASM gate built; placed immediately after the gate is in place)
**Depends on:** S-18.01 (the skill being amended), S-18.02 (the gate this fix makes effective)
**Blocks:** none
**Priority:** P0 — the BC-4.14.001 gate (S-18.02) is functionally inert in production until this story ships; without it, wave-handoff completeness is never validated at write-time

## Originating Finding

**Finding ID:** F-S1802-02
**Source:** S-18.02 LOCAL pass-3 adversary review
**Classification:** [process-gap] — ADR-026 §Decision 8 constrained the WASM gate's hook registration (PostToolUse on Write|Edit) but did NOT constrain the HANDOFF.md *producer's* write path. The wave-handoff skill (`plugins/vsdd-factory/skills/wave-handoff/lib/write-handoff.sh`) writes HANDOFF.md using bash redirection (`} > "$output_path"`), which emits NO PostToolUse event. The BC-4.14.001 gate therefore never fires on the production wave-close path — it is dead code in the current integration.

**Architect determination:** Option A — replace the bash-redirect write in the wave-handoff skill with a Claude Code **Write tool**-mediated write. This is the minimal-impact fix: the skill already orchestrates a Claude Code session; writing via the Write tool (via a skill instruction) instead of bash redirection is a one-line change in `write-handoff.sh` and ensures the PostToolUse gate fires naturally.

**ADR gap:** ADR-026 §Decision 8 defined the hook split (WASM gate for completeness, shell for flush) but did not include a constraint requiring the HANDOFF.md producer to write via the Write tool. This story's scope INCLUDES adding that constraint to §Decision 8.

## SPEC AMENDMENT NEEDED

This story requires a spec-evolution step (F2) before implementation (F3):

1. **Product-owner:** Amend BC-5.41.001 to add an explicit postcondition (or strengthen an existing one) requiring that the wave-handoff skill writes HANDOFF.md via the Claude Code Write tool, not bash redirection.
2. **Architect:** Amend ADR-026 §Decision 8 to add: "HANDOFF.md MUST be written via the Write tool (Claude Code native tool call), not bash redirection. This ensures the PostToolUse gate registered for Write|Edit events fires on every HANDOFF.md write."

Until the PO amends BC-5.41.001 with this write-path constraint, `behavioral_contracts: [BC-5.41.001]` is the closest existing anchor; the ACs below trace to the postconditions that the write-path fix enables.

**Status must remain `draft`** until the PO has authored/amended the BC and the architect has amended ADR-026 §Decision 8 with the explicit write-path constraint.

## Narrative

As a factory-dispatcher hook runtime,
I want the wave-handoff skill to write HANDOFF.md via the Claude Code Write tool (not bash redirection),
so that the PostToolUse `validate-wave-handoff-completeness` gate (BC-4.14.001, S-18.02) actually fires on every production wave-close path and malformed or incomplete HANDOFF.md files are caught at write-time.

## Scope

This story makes a targeted change to ONE file: `plugins/vsdd-factory/skills/wave-handoff/lib/write-handoff.sh`. The change replaces the bash-redirect write (`} > "$output_path"`) with a skill instruction that causes the Claude Code Write tool to be used for the HANDOFF.md file write. The skill already runs inside a Claude Code session; the Write tool is natively available.

This story also amends ADR-026 §Decision 8 to make the write-path constraint explicit.

This story does NOT change: the HANDOFF.md schema (S-18.01), the WASM gate logic (S-18.02), the hooks-registry.toml entry, or any other E-18 skill.

## Acceptance Criteria

### AC-001 (traces to BC-5.41.001 postcondition 1 — HANDOFF.md write path)
The wave-handoff skill writes HANDOFF.md by invoking the Claude Code **Write tool** (not via bash redirection `} > "$output_path"`). The change must be applied in `plugins/vsdd-factory/skills/wave-handoff/lib/write-handoff.sh` (or the skill entry point that orchestrates the write).

### AC-002 (traces to BC-5.41.001 postcondition 1 — PostToolUse gate fires in production)
An integration test confirms that running the wave-handoff skill end-to-end causes the factory-dispatcher to emit a `PostToolUse` event for the HANDOFF.md Write tool call, and the `validate-wave-handoff-completeness` gate is invoked. The gate must fire — not be skipped — on the production wave-close path.

### AC-003 (traces to BC-5.41.001 postcondition 2 — no behavioral regression)
The HANDOFF.md content produced by the amended skill is byte-identical to the content produced by the previous bash-redirect implementation for the same inputs. The write-path change is purely mechanical; it must not alter HANDOFF.md schema, field values, or ordering.

### AC-004 (traces to ADR-026 §Decision 8 — spec constraint codified)
ADR-026 §Decision 8 carries the explicit write-path constraint: "HANDOFF.md MUST be written via the Write tool (Claude Code native tool call), not bash redirection. This ensures the PostToolUse gate registered for Write|Edit events fires on every HANDOFF.md write." The amendment must be present in the ADR before this story's story-status advances to `ready`.

## Architecture Compliance Rules

- The Write tool call must target the same path that bash redirection previously wrote to (no path change)
- The factory-artifacts worktree path conventions from ADR-026 §Decision 1 must be respected
- `on_error = "continue"` on the WASM gate (S-18.02) means a gate crash is fail-open; this story's fix ensures the gate fires, but a gate crash still results in Continue per BC-4.14.001 PC6 / AC-013 in S-18.02
- `#[deny(warnings)]` in lib.rs is not applicable here (this is a shell skill, not a Rust crate); the equivalent discipline is `set -euo pipefail` in the amended shell script
