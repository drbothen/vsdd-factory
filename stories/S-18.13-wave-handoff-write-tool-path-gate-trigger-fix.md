# S-18.13 — wave-handoff skill writes HANDOFF.md via the Write tool so the PostToolUse completeness gate fires (gate-trigger fix)

**Epic:** E-18 — Factory Context Durability (feature #173)
**Wave:** 4 (depends on S-18.01 merged + S-18.02 WASM gate built; placed immediately after the gate is in place)
**Depends on:** S-18.01 (the skill being restructured), S-18.02 (the gate this fix makes effective)
**Blocks:** none
**Priority:** P0 — the validate-wave-handoff-completeness gate (S-18.02) is functionally inert in production until this story ships; without it, wave-handoff completeness is never validated at write-time

## Originating Finding

**Finding ID:** F-S1802-02
**Source:** S-18.02 LOCAL pass-3 adversary review
**Classification:** [process-gap] — ADR-026 §Decision 8 constrained the WASM gate's hook registration (PostToolUse on Write|Edit) but did NOT constrain the HANDOFF.md *producer's* write path. The wave-handoff skill (`plugins/vsdd-factory/skills/wave-handoff/lib/write-handoff.sh`) writes HANDOFF.md using bash redirection (`} > "$output_path"`), which emits NO PostToolUse event. The validate-wave-handoff-completeness gate therefore never fires on the production wave-close path — it is dead code in the current integration.

**Architect determination (v1.23 redesign):** The v1.22 fix was insufficient. The v1.22 normative rule stated `write-handoff.sh` MUST "route its HANDOFF.md output through the Write tool", which is IMPOSSIBLE for a monolithic bash run: `wave-handoff.sh` ends in `main "$@"` and has no agent seam between Step 4 (write_handoff call) and Step 6 (commit_to_artifacts). The correct fix is an **agent-orchestrated subcommand restructure** per ADR-026 §Decision 8 (v1.23).

**ADR gap:** ADR-026 §Decision 8 (v1.23) now specifies the four-step agent-orchestrated flow (emit→Write→emit-wave-state→commit). This story's scope implements that restructure.

## Spec Amendments: COMPLETE

Both spec amendments required for this story are in place. This story may proceed to TDD (status: ready).

1. **BC-5.41.001 v1.24** (product-owner, 2026-06-19): PC10 rewritten to reflect architect-designed four-step agent-orchestrated flow: (1) `--emit-handoff` bash subcommand assembles HANDOFF.md payload → stdout, NO disk write, NO commit; (2) agent invokes Write tool with that payload targeting `${ARTIFACTS_WT}/HANDOFF.md`; (3) PostToolUse validate-wave-handoff-completeness gate fires on the Write tool call; (4) `--commit` bash subcommand stages HANDOFF.md (on disk from Write tool) + wave-state.yaml (on disk from `--emit-wave-state`) in ONE atomic git commit. Bash redirection forbidden as primary or fallback. EC-017 added (`--commit` invoked but HANDOFF.md absent on disk → hard error `HandoffFileAbsent`).

2. **BC-5.41.002 v1.17** (product-owner, 2026-06-19): PC6 atomicity boundary clarification added — atomicity is defined at the git-commit boundary, not the disk-write boundary. HANDOFF.md is written by the agent Write tool; wave-state.yaml is written by bash (`--emit-wave-state`); `--commit` stages BOTH in ONE git commit. Two separate git commits remain forbidden. The two files being written at different times does NOT violate PC6.

3. **ADR-026 §Decision 8 v1.23** (architect, 2026-06-19): Four-step agent-orchestrated emit→Write→commit control flow specified. Fail-loud-no-fallback obligation unchanged: if Write tool is unavailable, emit hard error `HandoffWriteToolUnavailable`; no bash-redirect fallback permitted; no partial HANDOFF.md committed.

The ACs below trace to BC-5.41.001 PC10 (four-step flow postcondition) and BC-5.41.002 PC6 (atomicity postcondition) and ADR-026 §Decision 8 as established.

## Narrative

As a factory-dispatcher hook runtime,
I want the wave-handoff skill to be restructured into an agent-orchestrated subcommand model where HANDOFF.md is written by the agent via the Claude Code Write tool (not by bash redirection),
so that the PostToolUse `validate-wave-handoff-completeness` gate (BC-4.14.001, S-18.02) actually fires on every production wave-close path and malformed or incomplete HANDOFF.md files are caught at write-time.

## Scope

This story restructures the wave-handoff skill across **four files** and creates **one new fixture directory**. The current skill is a MONOLITHIC bash run (`wave-handoff.sh` ends in `main "$@"`) with no agent seam that permits a Write tool call between Step 4 (write_handoff) and Step 6 (commit_to_artifacts). The proper fix is to split the monolith into agent-orchestrated subcommands.

### Files and changes

1. **`plugins/vsdd-factory/skills/wave-handoff/wave-handoff.sh`** — Split `main()` into three bash subcommands dispatched via `$1`:
   - `--emit-handoff`: assembles the complete HANDOFF.md payload with full anti-fabrication cross-checks (all PC3 checks), emits the assembled YAML to stdout. NO file written to disk. NO git commit. Returns the payload for the agent to consume.
   - `--emit-wave-state`: writes wave-state.yaml to `${ARTIFACTS_WT}/wave-state.yaml` via bash; skipped on EPIC-COMPLETE (consistent with BC-5.41.002 PC3 EPIC-COMPLETE exception).
   - `--commit`: stages `HANDOFF.md` and `wave-state.yaml` from `${ARTIFACTS_WT}`, then creates ONE atomic git commit via `commit_to_artifacts`. MUST verify BOTH files are present on disk before staging; if either is absent, MUST abort with a hard error (EC-017 for HANDOFF.md absent; equivalent guard for wave-state.yaml). One git commit — not two.

2. **`plugins/vsdd-factory/skills/wave-handoff/lib/write-handoff.sh`** — Change `write_handoff()` to emit the assembled HANDOFF.md payload to stdout (remove `} > "$output_path"` bash-redirect construct). Update all callers of `write_handoff()` to capture stdout rather than relying on file side-effects.

3. **`plugins/vsdd-factory/skills/wave-handoff/SKILL.md`** — Rewrite from a descriptive "Behavior Overview" to GENUINE numbered agent steps that reflect the new subcommand model:
   - **S1 (Bash):** invoke `wave-handoff.sh --emit-handoff` to assemble and emit HANDOFF.md payload to stdout; capture the output.
   - **S2 (Agent Write tool):** write the captured payload to `${ARTIFACTS_WT}/HANDOFF.md` via the Claude Code Write tool. The PostToolUse `validate-wave-handoff-completeness` gate fires at this step.
   - **S3 (Agent verifies):** confirm the written content is byte-identical to the `--emit-handoff` payload before proceeding.
   - **S4 (Bash):** invoke `wave-handoff.sh --emit-wave-state` to write wave-state.yaml (skipped on EPIC-COMPLETE).
   - **S5 (Bash):** invoke `wave-handoff.sh --commit` to stage both files and create the single atomic git commit.
   This is a genuine agent-orchestration rewrite per ADR-026 §Decision 8 (v1.23) — the SKILL.md body MUST be numbered steps that drive the agent, not a description of what the bash script does internally.

4. **`plugins/vsdd-factory/tests/fixtures/wave-handoff-golden/`** (CREATE) — Frozen golden HANDOFF.md fixture(s) captured from the CURRENT bash-redirect path BEFORE the T-2 refactor (T-4a). Serves as the regression oracle for AC-003 byte-identity verification.

5. **`plugins/vsdd-factory/tests/wave-handoff.bats`** — Add:
   - AC-002 gate-fires test (PostToolUse event for the HANDOFF.md Write tool call)
   - AC-003 golden-byte-identity test
   - EC-017 HandoffFileAbsent test (`--commit` invoked but HANDOFF.md absent → hard error)

Atomicity is preserved: `--emit-wave-state` writes wave-state.yaml to disk via bash; `--commit` co-stages HANDOFF.md (already on disk from the Write tool step) and wave-state.yaml in ONE git commit. The two files being written at different times (Write tool vs bash) does NOT violate BC-5.41.002 PC6 — atomicity is defined at the git-commit boundary per BC-5.41.002 PC6 v1.17 clarification.

This story does NOT change: the HANDOFF.md schema (S-18.01), the WASM gate logic (S-18.02), or any other E-18 skill.

## Acceptance Criteria

### AC-001 (traces to BC-5.41.001 PC10 — four-step agent-orchestrated flow; Write tool mandate)
The restructure is applied in BOTH `plugins/vsdd-factory/skills/wave-handoff/wave-handoff.sh` (subcommand dispatch: `--emit-handoff` arm present; no HANDOFF.md written in the `--emit-handoff` code path) AND `plugins/vsdd-factory/skills/wave-handoff/lib/write-handoff.sh` (`write_handoff()` emits to stdout; the `} > "$output_path"` bash-redirect construct is ABSENT from the file). Oracle: (a) `grep -n '} > "$output_path"' lib/write-handoff.sh` returns no matches; (b) `grep -n '\-\-emit-handoff' wave-handoff.sh` returns the dispatch arm. No bash-redirection path may remain as primary or fallback HANDOFF.md write mechanism (BC-5.41.001 PC10 fail-loud-no-silent-fallback).

### AC-002 (traces to BC-5.41.001 PC10 — PostToolUse gate fires on the agent Write-tool HANDOFF.md call)
An integration test confirms that running the wave-handoff skill end-to-end causes the factory-dispatcher to emit a `PostToolUse` event for the HANDOFF.md Write tool call, and the `validate-wave-handoff-completeness` gate (BC-4.14.001) is invoked. The gate must fire — not be skipped — on the production wave-close path.

**Test strategy — production-grade requirement:** The existing bats suite runs `wave-handoff.sh` directly as a bash script; this produces no PostToolUse event. The production-grade AC-002 test requires one of the following approaches (in preference order):
1. **Dispatcher-integration test:** A bats test that drives the full `claude` harness in a sandbox session, invoking the wave-handoff SKILL.md steps via the agent, and verifies the dispatcher emits a `PostToolUse` event logged in `dispatcher-internal-<date>.jsonl` for the HANDOFF.md Write call.
2. **Mock PostToolUse event injection:** A bats harness that directly invokes the `validate-wave-handoff-completeness` WASM gate with a synthesized PostToolUse payload matching a HANDOFF.md Write tool call, and asserts the gate fires (not a no-op). This genuinely exercises the gate-firing path.

If neither approach is feasible with the current bats infrastructure, the implementer MUST document the structural constraint explicitly in the bats test file with a `skip` or `@test ... # INFRASTRUCTURE-GAP: requires dispatcher-integration test harness` annotation — do NOT silently substitute a `grep` check on the SKILL.md for a genuine gate-firing assertion. The fallback of asserting that the gate would fire because SKILL.md contains a Write-tool step is a structural assertion, not a gate-firing verification, and must be labeled as such. Per the production-grade principle, the implementer must pursue the real test first and document explicitly if a genuine limitation prevents it.

Additionally: if the Write tool is unavailable at invocation time, the skill MUST surface `HandoffWriteToolUnavailable` and NOT fall back to bash redirection (BC-5.41.001 PC10 / EC-016).

### AC-003 (traces to BC-5.41.001 PC10 — byte-identity write-path verification)
After the Write tool call completes (SKILL.md step S2/S3), the skill MUST verify that the written content is byte-identical to the `--emit-handoff` payload before the `--commit` subcommand is invoked. An integration test confirms this verification fires and that the HANDOFF.md content produced by the amended skill is byte-identical to the frozen golden fixture committed under `plugins/vsdd-factory/tests/fixtures/wave-handoff-golden/`. The golden fixture is captured during T-4a (BEFORE any T-2 changes are made) and serves as the cross-version regression oracle. If content verification fails, the skill surfaces a hard error identifying the byte-count discrepancy before attempting to commit (BC-5.41.001 PC10 write-path verification clause).

### AC-004 (traces to ADR-026 §Decision 8 — spec constraint codified in restructured form)
ADR-026 §Decision 8 (v1.23) carries the explicit agent-orchestrated emit→Write→commit control flow constraint. The implementer must verify this amendment is in place before beginning T-1. The stable anchor is `ADR-026 §Decision 8` per POLICY 19 (informational, non-load-bearing; the behavioral anchor is the section heading, not the version number).

### AC-005 (traces to BC-5.41.002 PC6 — single atomic git commit contains BOTH HANDOFF.md and wave-state.yaml)
Under the restructured flow, the `--commit` bash subcommand stages BOTH `HANDOFF.md` (on disk from the agent Write tool step) AND `wave-state.yaml` (on disk from the `--emit-wave-state` step) and creates ONE atomic git commit via `commit_to_artifacts`. A bats test verifies that the git log on `factory-artifacts` after a full wave-handoff run contains a single new commit that includes both files (two separate commits — one for HANDOFF.md and one for wave-state.yaml — are a BC-5.41.002 PC6 violation). This atomicity guarantee is preserved across the agent-Write/bash-commit boundary per BC-5.41.002 PC6 v1.17 clarification.
