# S-18.13 — wave-handoff skill writes HANDOFF.md via the Write tool so the PostToolUse completeness gate fires (gate-trigger fix)

**Epic:** E-18 — Factory Context Durability (feature #173)
**Wave:** 4 (depends on S-18.01 merged + S-18.02 WASM gate built; placed immediately after the gate is in place)
**Depends on:** S-18.01 (the skill being amended), S-18.02 (the gate this fix makes effective)
**Blocks:** none
**Priority:** P0 — the BC-4.14.001 gate (S-18.02) is functionally inert in production until this story ships; without it, wave-handoff completeness is never validated at write-time

## Originating Finding

**Finding ID:** F-S1802-02
**Source:** S-18.02 LOCAL pass-3 adversary review
**Classification:** [process-gap] — ADR-026 §Decision 8 constrained the WASM gate's hook registration (PostToolUse on Write|Edit) but did NOT constrain the HANDOFF.md *producer's* write path. The wave-handoff skill (`plugins/vsdd-factory/skills/wave-handoff/lib/write-handoff.sh`) writes HANDOFF.md using bash redirection (`} > "$output_path"`), which emits NO PostToolUse event. The BC-4.14.001 gate therefore never fires on the production wave-close path — it is dead code in the current integration.

**Architect determination:** Option A — replace the bash-redirect write in the wave-handoff skill with a Claude Code **Write tool**-mediated write. This is the minimal-impact fix: the skill already orchestrates a Claude Code session; writing via the Write tool (via a skill instruction) instead of bash redirection is a one-line change in `write-handoff.sh` and ensures the PostToolUse gate fires naturally.

**ADR gap:** ADR-026 §Decision 8 defined the hook split (WASM gate for completeness, shell for flush) but did not include a constraint requiring the HANDOFF.md producer to write via the Write tool. This story's scope INCLUDES adding that constraint to §Decision 8.

## Spec Amendments: COMPLETE

Both spec amendments required for this story are in place. This story may proceed to TDD (status: ready).

1. **BC-5.41.001 v1.23** (product-owner, 2026-06-19): PC10 added — HANDOFF.md MUST be written via the Claude Code `Write` tool (not bash redirection); fail-loud-no-fallback obligation codified (`HandoffWriteToolUnavailable` hard error); byte-identity write-path verification before git-commit step; ADR-026 §Decision 8 anchored. EC-016 added (Write tool unavailable → hard error, no fallback). Test vectors `write-tool-enforcement` (AC-001/AC-002/AC-003) and `write-tool-unavailable-hard-error` added.

2. **ADR-026 §Decision 8 v1.22** (architect, 2026-06-19): Normative write-path constraint added — "HANDOFF.md MUST be written via the Write tool (Claude Code native tool call), not bash redirection. This ensures the PostToolUse gate registered for Write|Edit events fires on every HANDOFF.md write." The wave-handoff skill MUST NOT silently fall back to bash redirection if the Write tool is unavailable — it must fail loudly (see EC-016 / AC hard-error scenario).

The ACs below trace to BC-5.41.001 PC10 (the canonical write-path postcondition) and ADR-026 §Decision 8 as established.

## Narrative

As a factory-dispatcher hook runtime,
I want the wave-handoff skill to write HANDOFF.md via the Claude Code Write tool (not bash redirection),
so that the PostToolUse `validate-wave-handoff-completeness` gate (BC-4.14.001, S-18.02) actually fires on every production wave-close path and malformed or incomplete HANDOFF.md files are caught at write-time.

## Scope

This story makes a targeted change to TWO files:

1. **`plugins/vsdd-factory/skills/wave-handoff/lib/write-handoff.sh`** — The `write_handoff()` function is changed to EMIT the assembled HANDOFF.md payload to stdout (removing the `} > "$output_path"` bash-redirect), returning the payload to the orchestrating agent rather than writing directly to disk.

2. **`plugins/vsdd-factory/skills/wave-handoff/SKILL.md`** — A new numbered agent step is added instructing the agent to capture the stdout payload from `write_handoff()` and WRITE it to `${ARTIFACTS_WT}/HANDOFF.md` via the Claude Code **Write tool**. This is what makes the PostToolUse `validate-wave-handoff-completeness` gate fire — the Write tool emits a PostToolUse event; bash redirection does not.

The wave-handoff skill is AGENT-ORCHESTRATED (confirmed by architect: SKILL.md `allowed-tools` includes Write; the skill body consists of numbered agent steps, not a monolithic bash run). PC10 is therefore implementable without BC or ADR amendment: the agent executing the skill natively has Write tool access; the change is a skill-instruction addition, not an architectural departure.

Atomicity is preserved: wave-state.yaml continues to be bash-produced (existing step 5); the single `commit_to_artifacts` git commit (existing step 6) co-commits both HANDOFF.md and wave-state.yaml already on disk — BC-5.41.002 PC6 atomicity is NOT broken.

This story also confirms ADR-026 §Decision 8 (amended by architect at v1.22) carries the explicit write-path constraint.

This story does NOT change: the HANDOFF.md schema (S-18.01), the WASM gate logic (S-18.02), the hooks-registry.toml entry, or any other E-18 skill.

## Acceptance Criteria

### AC-001 (traces to BC-5.41.001 PC10 — Write tool mandate)
The wave-handoff skill writes HANDOFF.md by invoking the Claude Code **Write tool** (not via bash redirection `} > "$output_path"`, `echo ... >`, `cat >`, `tee`, or any other shell redirection). The change must be applied in `plugins/vsdd-factory/skills/wave-handoff/lib/write-handoff.sh` (or the skill entry point that orchestrates the write). No bash-redirection path may remain as a primary or fallback write mechanism (BC-5.41.001 PC10 fail-loud-no-silent-fallback).

### AC-002 (traces to BC-5.41.001 PC10 — PostToolUse gate fires in production)
An integration test confirms that running the wave-handoff skill end-to-end causes the factory-dispatcher to emit a `PostToolUse` event for the HANDOFF.md Write tool call, and the `validate-wave-handoff-completeness` gate (BC-4.14.001) is invoked. The gate must fire — not be skipped — on the production wave-close path. Additionally: if the Write tool is unavailable at invocation time, the skill MUST surface `HandoffWriteToolUnavailable` and NOT fall back to bash redirection (BC-5.41.001 PC10 / EC-016).

### AC-003 (traces to BC-5.41.001 PC10 — byte-identity write-path verification)
After the Write tool call completes, the skill MUST verify that the written content is byte-identical to the intended HANDOFF.md payload before proceeding to the `git commit` step (PC6). An integration test confirms this verification fires and that the HANDOFF.md content produced by the amended skill is byte-identical to a **frozen golden fixture** generated from the same inputs using the pre-amendment bash-redirect path and committed to the bats test suite under `plugins/vsdd-factory/tests/fixtures/wave-handoff-golden/`. The golden fixture is captured during T-4a (BEFORE the bash-redirect path is removed in T-2) and serves as the cross-version regression oracle. If content verification fails, the skill surfaces a hard error identifying the byte-count discrepancy before attempting to commit (BC-5.41.001 PC10 write-path verification clause).

### AC-004 (traces to ADR-026 §Decision 8 — spec constraint codified)
ADR-026 §Decision 8 (v1.22) carries the explicit write-path constraint: "HANDOFF.md MUST be written via the Write tool (Claude Code native tool call), not bash redirection. This ensures the PostToolUse gate registered for Write|Edit events fires on every HANDOFF.md write." The amendment is present in the ADR (v1.22, 2026-06-19). The implementer must verify this amendment is in place before beginning implementation (T-6 is complete).
