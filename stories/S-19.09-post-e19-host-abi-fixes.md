# S-19.09 — post-E-19 host ABI fixes: `read_prefix` production path registration, `timeout_ms` framing, telemetry hygiene

**Epic:** E-19 — Post-rc.22 Operator Hardening
**Wave:** 3 (depends on S-19.06 — `host::read_prefix` FFI entry point and dispatcher host function must exist on develop; depends on S-19.08 — W3 starts after all W2 stories merge to develop)
**Depends on:** S-19.06 (creates `host::read_prefix` in `setup_linker` and `host/read_prefix.rs`; S-19.09 extends to the production path in `invoke.rs`); S-19.08 (confirm all W2 merges landed before W3 begins; no code overlap but wave-ordering gate)
**Priority:** P1 (D19 is CRITICAL — no operator-visible `read_prefix` call is currently functional on the production dispatch path; this blocks S-19.07, the BC-4.13.001 Phase-B migration which requires functional `read_prefix` on production path)
**Subsystem anchor:** SS-01 (Hook Dispatcher Core) owns all five affected files in `crates/factory-dispatcher/`.

## Narrative

S-19.06 delivered `host::read_prefix` — the bounded partial-read host function. The E-19 cascade reviews, wave gate, and post-delivery analysis surfaced four implementation gaps that require a follow-on story before S-19.07 (BC-4.13.001 Phase-B migration) can proceed.

**D19 — Production path gap (CRITICAL; ADR-025 §Decision 16):**

`read_prefix` is registered in `setup_linker` (`Linker<HostContext>`, the dispatcher-internal unit-test invocation path in `crates/factory-dispatcher/src/host/mod.rs`) but is **absent from `setup_host_on_store_data`** (`Linker<StoreData>`, the production dispatch path in `crates/factory-dispatcher/src/invoke.rs`).

**SDK-grounding evidence (literal grep, 2026-07-15 at develop 9787c056):**
```
$ grep -c "read_prefix" crates/factory-dispatcher/src/invoke.rs
0
```

`proxy_host_imports` in `invoke.rs` calls `setup_host_on_store_data` directly and ignores the `_host_linker_reference` argument; the `host/mod.rs::setup_linker` registration of `read_prefix` (added in S-19.06) never propagates to the production dispatch path. Any plugin compiled with a `vsdd::read_prefix` import fails at plugin instantiation time on the production path with a wasmtime link error (missing import). S-19.06 all-green in CI because CI tests exercise `read_prefix` through the test-path linker only — no existing test exercises `setup_host_on_store_data` with a `read_prefix`-importing plugin.

The production implementation **MUST** follow the memory-grow protocol established for `read_file` at the `read_file` `func_wrap` block in `setup_host_on_store_data` (`invoke.rs`): grow WASM linear memory by `ceil(body_len / 65536)` pages, write body at `current_bytes` (the prior memory end, always `> 0` for non-empty files), and return the real write offset via `out_ptr_out`. Capability enforcement gates on `ctx.capabilities.read_prefix.path_allow`. For empty body, write `ptr=0, len=0` and return `codes::OK`.

**HOST_ABI_VERSION** remains `1`. This is a production-path fill for a function that ADR-025 §Decision 15 already allocated; no ABI wire-shape changes.

**D20 — Documentation corrections (non-behavioral; ADR-025 §Decisions 17–18):**

In both `read_file.rs` and `read_prefix.rs`, the drop comment on `timeout_ms` formerly read:
- `read_file.rs` (on the `let _ = timeout_ms;` drop line): the former `// accepted for ABI stability; enforced in S-1.5 via epoch interruption`
- `read_prefix.rs` (on the `let _ = timeout_ms;` drop line): the former `// accepted for ABI stability; enforced via epoch interruption`

Both are technically incorrect (ADR-025 §Decision 18). Epoch interruption fires at WASM yield points — bytecode-level control-flow transfers within the guest. A synchronous `func_wrap` host closure executes on the dispatcher thread in native Rust; no WASM yield point exists during its execution. Once `std::fs::File::open` or `read_to_end` begins inside the closure, no epoch tick can interrupt it. The per-plugin store-level deadline (`store.set_epoch_deadline(...)` in `invoke_plugin`) provides coarse plugin-level time, not per-host-function timeout.

The corrected form per ADR-025 §Decision 18: `// accepted for ABI forward-compatibility; per-host-function timeout is structurally unenforced in the current synchronous func_wrap dispatch path; the store-level epoch deadline governs coarse plugin-level time.`

Additionally, `read_file.rs` currently lacks a comment distinguishing the test-path `out_ptr=0` constant return (used by `register()` in `host/mod.rs` for unit tests — `prepare()` returns `Ok((bytes, 0))`) from the production-path memory-grow protocol in `invoke.rs::setup_host_on_store_data` (writes at `current_bytes > 0`). This two-linker protocol boundary (ADR-025 §Decision 17) must be documented in `read_file.rs` adjacent to the `prepare()` call or the `Ok((bytes, 0))` return form, to prevent future implementers from conflating the two paths.

**D21 — Named constants for telemetry event types (F-WG-002; extended F-P1-002):**

The string literals `"internal.file_not_found"` and `"plugin.abandoned"` appear as bare string literals in production code across three files. Additionally, `"plugin.completed"` (in `emit_plugin_completed_async`) and `"plugin.timeout"` (in `emit_plugin_timeout_async`) in `emit_event.rs` remain as bare literals despite named constants `PLUGIN_COMPLETED` and `PLUGIN_TIMEOUT` already existing in `internal_log.rs` — leaving the file internally inconsistent with the same sweep that introduces `PLUGIN_ABANDONED` (F-P1-002; TD-VSDD-060 sibling-sweep). The D21 sweep therefore covers all four telemetry event type literals.

**SDK-grounding evidence (literal grep, 2026-07-15):**
```
$ grep -c '"internal\.file_not_found"\|"plugin\.abandoned"' \
    crates/factory-dispatcher/src/host/read_file.rs \
    crates/factory-dispatcher/src/host/read_prefix.rs \
    crates/factory-dispatcher/src/host/emit_event.rs
read_file.rs:   2
read_prefix.rs: 5
emit_event.rs:  2
$ grep -c '"plugin\.completed"\|"plugin\.timeout"' \
    crates/factory-dispatcher/src/host/emit_event.rs

```

These duplications create a maintenance risk: a future rename requires finding all sites. Named constants exported from `crates/factory-dispatcher/src/internal_log.rs` provide a single definition point. The D21 sweep covers all four telemetry event type literals: call sites for `"internal.file_not_found"` and `"plugin.abandoned"` in `read_file.rs`, `read_prefix.rs`, and `emit_event.rs`, AND call sites for `"plugin.completed"` and `"plugin.timeout"` in `emit_event.rs`, are all swept to reference the named constants. All existing tests that assert on event type strings (`assert_eq!(e.type_, "internal.file_not_found")`) continue to pass unmodified — the constant values are unchanged.

**D22 — Missing `timestamp` field in `plugin.completed` async event (F-WG-003):**

`emit_plugin_completed_async` in `emit_event.rs` builds its `InternalEvent` chain with `with_trace_id`, `with_session_id`, `with_plugin_name`, `with_plugin_version`, `with_field("entry_index", ...)`, `with_field("exit_code", ...)`, `with_field("elapsed_ms", ...)`, `with_field("fuel_consumed", ...)` — but omits `with_field("timestamp", ts.as_str())`. All sibling emitters in the same file (`emit_plugin_async_block_discarded`, `emit_dispatcher_schema_mismatch`, `emit_registry_invalid_e_reg002`, `emit_plugin_abandoned`) capture `let ts = ev.ts.clone()` and chain `.with_field("timestamp", ts.as_str())`. BC-3.08.001 §Common Fields mandates `timestamp` for all `plugin.*` events.

**Purity boundary:** This story is confined to `crates/factory-dispatcher/`. No spec files, no hook-sdk files, no `hooks-registry.toml` changes, no `HOST_ABI_VERSION` bump.

## Architecture Mapping

**SS-01 changes — `crates/factory-dispatcher/src/invoke.rs` (behavioral, D19):**

Add `read_prefix` host function binding to `setup_host_on_store_data` following the `read_file` `func_wrap` block in `setup_host_on_store_data` (`invoke.rs`) as the exact template. Steps:

1. Call `read_wasm_string_sd` to parse path from WASM memory; return `codes::INVALID_ARGUMENT` on error.
2. Capability check: use `caller.data().host.capabilities.read_prefix.path_allow`; return `codes::CAPABILITY_DENIED` if absent or path not covered (same deny-by-default sequence as `read_file`).
3. Call `crate::host::read_prefix::prepare(&ctx, &path, max_bytes)` for the bounded read. `Err(code)` → `return code` (passes through `CAPABILITY_DENIED`, `NOT_FOUND`, `INVALID_ARGUMENT`, `INTERNAL_ERROR` matching `read_file` pattern).
4. Empty body: write `ptr=0, len=0` via `write_wasm_u32_sd`; return `codes::OK`.
5. Non-empty body: call `get_memory_sd`; capture `current_bytes`; grow by `body.len().div_ceil(65536)` pages; write body at `current_bytes` via `write_wasm_bytes_sd`; write `current_bytes as u32` to `out_ptr_out` and `body.len() as u32` to `out_len_out`; return `codes::OK`. `current_bytes` is always `> 0` after growth for non-empty body.
