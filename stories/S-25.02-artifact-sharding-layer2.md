# S-25.02: Artifact Sharding Layer 2 — Size-Triggered Shard Rotation for Cycle Artifacts

## Narrative

- **As a** factory pipeline operator who has Layer 1 (INDETERMINATE markers) deployed
- **I want** the append-only cycle artifacts (decision-log, burst-log, lessons) to be
  automatically split into capped shards when they approach the validator-completion fuel
  envelope, with a deterministic size rule enforced by a PreToolUse hook (or append helper)
  rather than LLM-side awareness
- **So that** no shard ever exceeds the size at which fuel-exhaustion INDETERMINATE events
  fire, eliminating the root cause of Layer-1 marker writes BY CONSTRUCTION and making the
  Cohort B validators (`validate-burst-log-structure`, `regression-gate`, `convergence-tracker`)
  safe to flip to `failure_policy = "fail-closed"`

## Context / Feature Summary

**Registered at:** F3 story-decomposition burst, validation-integrity-layer1 cycle,
2026-08-30 (story-writer). Source: ADR-047 §Decision 8b (Ratified Future Phase Layer 2).

**Why Layer 2 follows Layer 1 (not concurrent):**
Layer 1 instruments the INDETERMINATE failure mode (detects and surfaces it). Layer 2 attacks
the root cause (large artifacts). Without Layer 1 in production, we lack the forensic data
(plugin.indeterminate event counts per file per plugin) needed to empirically validate the shard
cap formula. Layer 2's shard cap derivation requires production observation of fuel consumption
vs. artifact size correlation — data only available after Layer 1 lands.

**Shard cap formula (production-grade; from ADR-047 §Decision 8b):**
```
shard_cap_bytes <= (PRACTICAL_FUEL_CEILING / WORST_CASE_FUEL_PER_BYTE) - MAX_SINGLE_RECORD_BYTES - SAFETY_MARGIN
```
Where:
- `PRACTICAL_FUEL_CEILING` = the fuel budget at which validators reliably complete
  (calibrated from Layer 1 INDETERMINATE event data)
- `WORST_CASE_FUEL_PER_BYTE` = worst-case (super-linear validators: monotonicity-checking,
  cross-reference checks) fuel consumption per byte, NOT average-case
- `MAX_SINGLE_RECORD_BYTES` = largest single appended block (worst-case decision-log entry)
- `SAFETY_MARGIN` = buffer for per-shard metadata overhead

**Per-file bounding:** Each artifact file (decision-log.md, burst-log.md, lessons.md) is
independently bounded. A write to one does not affect shard state of others.

**Shard count is unbounded absent compaction:** Layer 2 MUST include a retention/compaction
companion policy (archive shards older than N cycles). Without it, whole-corpus validators
become O(shards) rather than O(1), merely shifting the scalability problem in time.

**Cohort B flip:** Once Layer 2 bounds the inputs of `validate-burst-log-structure`,
`regression-gate`, and `convergence-tracker`, these three validators become safe to flip to
`failure_policy = "fail-closed"` (ADR-047 §Decision 8a — Cohort B candidates).

### AC-001: Shard cap derived from fuel budget (traces to ADR-047 §D8b shard-cap formula — BC-TBD)

The shard cap (maximum bytes per shard file) MUST be computed from the formula:
`shard_cap_bytes <= (PRACTICAL_FUEL_CEILING / WORST_CASE_FUEL_PER_BYTE) - MAX_SINGLE_RECORD_BYTES - SAFETY_MARGIN`.
The cap MUST use worst-case fuel-per-byte (not average-case). The computed value MUST be
validated against Layer 1 plugin.indeterminate event forensics before hardcoding.

### AC-002: Rotation trigger is deterministic (traces to ADR-047 §D8b — BC-TBD)

Shard rotation MUST be triggered by a deterministic size rule: either a PreToolUse hook that
checks the current shard size before the append, or an append helper that checks size
pre-write. No LLM-side awareness of shard size is required or permitted (per the human
directive: mechanistic enforcement, never agent).

### AC-003: Roll-before-write policy (traces to ADR-047 §D8b — BC-TBD)

If a single appended block exceeds the shard cap, the append helper MUST roll to a new shard
BEFORE writing the block (Kafka log-segment roll-before-write pattern; RFC 9162 precedent).
Writing an oversized shard is forbidden.

### AC-004: Atomic shard index publication (traces to ADR-047 §D8b; TD-VSDD-053 alignment — BC-TBD)

The shard index (listing all shards for a given artifact) MUST be published atomically (temp +
rename) to align with TD-VSDD-053 single-commit-per-burst. The index update and the new shard
file MUST be committed together in a single factory-artifacts commit.

### AC-005: Retention/compaction companion policy (traces to ADR-047 §D8b honest-shard-count-accounting — BC-TBD)

S-25.02 MUST include a retention/compaction policy specifying: the maximum shard count before
old shards are archived (e.g., N=10 most recent cycles), the archive format, and the
whole-corpus validator O(shards) behavior acknowledged explicitly. This is a MANDATORY
companion to sharding, not a follow-up deferral.

### AC-006: Cohort B validators flipped to fail-closed (traces to ADR-047 §D8a Cohort B — BC-TBD)

After Layer 2 bounds the inputs of `validate-burst-log-structure`, `regression-gate`, and
`convergence-tracker`, hooks-registry.toml MUST assign `failure_policy = "fail-closed"` to
all three validators. The flip MUST be accompanied by ADR-039 §Decision 3 calibration
confirmation for each validator.

### AC-007: Full regression suite stays green (traces to ADR-047 §D7 backward-compat — BC-TBD)

`cargo test --workspace --all-targets` and `plugins/vsdd-factory/tests/run-all.sh` MUST stay
green after Layer 2 lands. Existing shard-unaware validators MUST continue to work (they simply
validate individual shards instead of the monolithic file).

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-001 | Single appended block exceeds shard cap | Roll to new shard BEFORE writing block (roll-before-write; ADR-047 §D8b) |
| EC-002 | Shard count reaches retention limit | Oldest shard archived per retention/compaction policy (AC-005) |
| EC-003 | Validator reads a sealed shard that was retroactively edited | Shard re-validated; checkpoint recomputed; downstream seam validations re-run (S-25.03 §retroactive-edits; coordination with Layer 3) |
| EC-004 | Concurrent dispatch attempts to write to the same shard | Atomic temp+rename ensures no torn shard write; TD-VSDD-053 single-commit-per-burst prevents concurrent factory-artifacts commits |
| EC-005 | Shard index unavailable or corrupt | Fail-loud; dispatch blocked; operator must restore from git history |
