# S-15.15: validate-policies-schema WASM Hook + policies.yaml Structural Remediation

**Epic:** E-12 — Engine Governance (brownfield-backfill wave, S-15.03 PRIORITY-A M3)
**Delivery order:** M3 (independent of other M3 stories; no dependencies)
**Depends on:** none
**Blocks:** none
**Priority:** P1 (closes F-PASS14-004 + F-PASS14-006 + D-472 POLICY 13+16 codification)
**ADR gate:** ADR-021 Option b ACCEPTED (2026-05-15) — cargo-audit Part C is immediately
  implementable; bash provisioner + WASM cache reader model is settled

## Narrative

- **As a** state-manager or agent editing `.factory/policies.yaml`
- **I want to** receive an immediate PostToolUse block when the policies.yaml file I just wrote
  is structurally invalid — missing required header fields, non-canonical policy `id` format,
  duplicate IDs, missing required policy fields, or a referenced `lint_hook` plugin not present
  in hooks-registry.toml
- **So that** the class of governance policy registry structural violations discovered by the
  adversary during F-PASS14 is caught mechanically at write time rather than requiring a human
  adversary pass to detect schema drift

Additionally:
- **As a** state-manager writing a dispatch package (`td-*-dispatch.md`) that recommends crate
  dependencies
- **I want to** receive an advisory or block when the recommended crates have known RUSTSEC
  advisories
- **So that** security regressions introduced via dispatch packages are detected before they
  propagate to downstream story implementations

## Why This Exists

F-PASS14-004 (HIGH) found that `.factory/policies.yaml` was missing a required `frontmatter:`
block in its header. F-PASS14-006 identified an inconsistency in the POLICY ID format (human
direction 2026-05-15: three-digit IDs are canonical per production policies.yaml `id: 1..18`
integer format). TD #74 Option b (per ADR-021) requires a WASM hook to check dispatch packages
against known cargo-audit advisories.

This story has three parts:

**Part A (one-time content fix):** State-manager adds the required `frontmatter:` block to
`.factory/policies.yaml`. This is a content edit, not hook logic. Part A ships in the same
commit as the hook story authoring (no separate PR needed for Part A alone).

**Part B (validate-policies-schema hook):** New WASM crate `crates/hook-plugins/validate-policies-schema/`
at priority 156. PostToolUse on `policies.yaml` writes. Schema validation: required header
fields, integer id [1, 999], no duplicates, 7 required fields per policy entry, lint_hook
existence in hooks-registry.toml, codified_at D-NNN format. All violations cascade-reported.

**Part C (cargo-audit cache reader):** Same WASM binary, second arm. PostToolUse on
`td-*-dispatch.md` writes. Reads `.factory/hooks/cargo-audit-cache.json` (written by
`update-cargo-audit-cache.sh` bash provisioner per ADR-021 Option b). HIGH/CRITICAL
advisory → block; MEDIUM/LOW → advisory log + Continue. Absent cache → Continue + log_warn
(fail-open per ADR-021 absent-file advisory policy).

## Behavioral Contract

**BC ID:** BC-5.39.008 (v1.5)
**File:** `.factory/specs/behavioral-contracts/ss-05/BC-5.39.008.md`

### Key Postconditions (BC-5.39.008)

**Part A/B — policies.yaml arm (PostToolUse on policies.yaml writes):**

1. YAML parse failure → `HookResult::block_with_fix(...)` with parse-error location.
2. Missing required header field (`document_type`, `version`, `last_amended`) → block naming missing field, citing F-PASS14-004.
3. Policy entry missing any of 7 required fields → block naming missing field(s) and policy id.
4. `id` not bare YAML integer in [1, 999] → block citing non-conforming id format.
5. Duplicate `id` across entries → block naming duplicated id.
6. `lint_hook` non-null AND plugin not in hooks-registry.toml → block naming missing plugin.
7. `lint_hook` non-null AND `codified_at` not matching `D-\d+` → block naming malformed value.
8. Extra/unknown fields in a policy entry → advisory log (`host::log_warn`) + Continue (not block; forward-compat).
9. All checks pass → `HookResult::Continue`.
10. All violations cascade-reported in a single Block (schema-violation cascade invariant).
11. `host::read_file` HostError for policies.yaml → Continue + log_warn (fail-open).

**Part C — dispatch package arm (PostToolUse on `td-*-dispatch.md` writes):**

12. `cargo-audit-cache.json` absent or unreadable → Continue + log_warn advisory (no block).
13. Cache present + parseable: extract crate+version lines from dispatch package. For each matched advisory: HIGH/CRITICAL → Block citing RUSTSEC ID; MEDIUM/LOW → log_warn + Continue.
14. `host::read_file` HostError for dispatch package → Continue + log_warn (fail-open).

### Key Invariants (BC-5.39.008)

1. Hook NEVER writes any file (read-only PostToolUse validator).
2. Hook fires PostToolUse only — signals AFTER the write has completed.
3. Path-component-strict: `Path::new(file_path).file_name() == Some("policies.yaml")` for Part B. Part C: filename matches `^td-.*-dispatch\.md$` regex on basename only. `ends_with` MUST NOT be used.
4. `id` field: bare YAML integer scalar in [1, 999]. String forms, negative integers, zero, `POLICY NNN`-prefixed strings → Block.
5. Required policy entry fields: `id` (integer), `name` (non-empty str), `severity` (`HIGH` or `MEDIUM`), `scope` (non-empty str), `description` (non-empty str), `lint_hook` (str or null), `codified_at` (D-\d+ when lint_hook non-null).
6. YAML anchors resolved before schema checks. YAML comments stripped before checks.
7. Schema-violation cascade: hook must NOT stop on first violation — all violations across all entries reported together in a single Block.
8. Fail-open: HostError on any read → Continue + log_warn. Registry-read failure skips lint_hook-existence check only; other checks continue.
9. No `HookResult::Advisory` variant exists in hook-sdk — advisory behavior is `HookResult::Continue` + `host::log_warn`.
10. `host::read_file` calls: `max_bytes = 524288` (512 KiB), `timeout_ms = 2000`. Registry-level `timeout_ms = 5000`.
11. All byte-index slice expressions on content strings MUST use `is_char_boundary()` guards.

  **Main hook orchestration:**

  ```rust
  pub fn run_hook(file_path: &str) -> HookResult {
      if is_policies_yaml_target(file_path) {
          // Part B arm
          let content = match host::read_file(file_path, 524288, 2000) {
              Ok(c) => c,
              Err(e) => {
                  host::log_warn(&format!("validate-policies-schema: read failed for {}: {:?}; skipping", file_path, e));
                  return HookResult::Continue;
              }
          };
          let violations = validate_policies_schema(&content);
          if violations.is_empty() {
              HookResult::Continue
          } else {
              let combined = violations.iter().map(|v| v.message.clone()).collect::<Vec<_>>().join("\n");
              HookResult::block_with_fix(
                  "validate-policies-schema",
                  &format!("policies.yaml schema violations:\n{}", combined),
                  "Fix all policy schema violations listed above and re-save the file",
                  "policies_schema_violation",
              )
          }
      } else if is_dispatch_package_target(file_path) {
          // Part C arm
          let content = match host::read_file(file_path, 524288, 2000) {
              Ok(c) => c,
              Err(e) => {
                  host::log_warn(&format!("validate-policies-schema: read failed for {}: {:?}; skipping advisory check", file_path, e));
                  return HookResult::Continue;
              }
          };
          let cache_path = ".factory/hooks/cargo-audit-cache.json";
          let advisory_violations = check_cargo_advisory(&content, cache_path);
          if advisory_violations.is_empty() {
              HookResult::Continue
          } else {
              let combined = advisory_violations.iter().map(|v| v.message.clone()).collect::<Vec<_>>().join("\n");
              HookResult::block_with_fix(
                  "validate-policies-schema",
                  &format!("Dispatch package recommends crates with HIGH/CRITICAL RUSTSEC advisories:\n{}", combined),
                  "Remove or update the flagged crate dependencies before using this dispatch package",
                  "cargo_advisory_violation",
              )
          }
      } else {
          HookResult::Continue
      }
  }
  ```
