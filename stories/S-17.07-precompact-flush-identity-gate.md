# S-17.07: precompact-flush Step-4 Identity-Gate Amendment — renew_lock_if_holder Call-Site + 4-Outcome Test Coverage

**Epic:** E-17 — Factory State Durability and Concurrency (brownfield-backfill #170 lineage)
**Wave:** 5
**Depends on:** S-17.06 (`factory_lock::renew_lock_if_holder` and related types created there)
**Blocks:** none
**Priority:** P1 (completes ADR-046 Decision 3 — precompact-flush identity gate)
**BC gate:** BC-7.07.001 v1.40 (implementing story; S-17.07 is the story anchor per Phase B
re-anchor in v1.40)

## Narrative

- **As a** `precompact-flush` PreCompact WASM plugin (SS-04, SS-07)
- **I want** the Step-4 lock-renewal call-site in `crates/hook-plugins/precompact-flush/src/lib.rs`
  replaced from `factory_lock::renew_lock(&state_md_content)` to
  `factory_lock::renew_lock_if_holder(&state_md_content, resolve_identity_closure, now_fn)`,
  with proper handling for all 4 renewal outcomes including the new
  `IdentityResolutionFailed` observable outcome
- **So that** the precompact-flush plugin applies the same identity-gated renewal logic as
  `stamp-state-timestamp` (ADR-046 Decision 3 consistency), never resurrects a foreign
  holder's expired lock during a PreCompact flush, and makes the `IdentityResolutionFailed`
  case observable via a `factory.lock.renewal_indeterminate` event (ADR-046 Decision 4)

## Acceptance Criteria

### AC-001 (traces to BC-7.07.001 postcondition PC3 — already-expired: no renewal, no resolve_identity call)

When the factory_lock in STATE.md content is present and valid but `now >= expires_at`
(AlreadyExpired case), `renew_lock_if_holder` MUST return `SkipReason::AlreadyExpired`,
the flush content MUST NOT be renewed, `resolve_identity` MUST NOT be called (no
`git config user.email` exec subprocess on this path), and the flush MUST proceed
unblocked with the un-renewed content.

**Test (Rust unit):** `test_precompact_flush_step4_already_expired_no_exec_subprocess`

### AC-002 (traces to BC-7.07.001 postcondition PC3 — identity match: renews content)

When `renew_lock_if_holder` returns `RenewOutcome::Renewed(new_content)` (identity match,
not expired), the flushed STATE.md content MUST use `new_content` (with `expires_at`
advanced by `TTL_SECONDS`), NOT the original un-renewed content.

**Test (Rust unit):** `test_precompact_flush_step4_identity_match_renews_content`

### AC-003 (traces to BC-7.07.001 invariant 3 — not holder: no renewal, flush proceeds)

When `renew_lock_if_holder` returns `SkipReason::NotHolder` (identity mismatch), the
flush MUST proceed with the un-renewed content. `expires_at` MUST be byte-identical to
its pre-renewal value. The flush MUST NOT block or abort due to the mismatch.

**Test (Rust unit):** `test_precompact_flush_step4_not_holder_no_renewal`

### AC-004 (traces to BC-7.07.001 invariant 3b — IdentityResolutionFailed: emit event, log warn, flush proceeds)

When `renew_lock_if_holder` returns `SkipReason::IdentityResolutionFailed { reason, holder, locked_at, expires_at }`,
the plugin MUST:
1. Emit a `factory.lock.renewal_indeterminate` event via `host::emit_event` with payload
   fields: `plugin`, `holder`, `locked_at`, `expires_at`, `resolution_error` (= `reason`)
2. Emit a `host::log_warn` message documenting the indeterminate outcome
3. Allow the flush to proceed unblocked with the un-renewed content
4. Leave `expires_at` byte-identical (no renewal attempted)

**Test (Rust unit):** `test_precompact_flush_step4_resolution_failed_emits_event_and_logs`

## Architecture Compliance Rules

Extracted from ADR-046 Decisions 3 and 4 and BC-7.07.001:

1. **`renew_lock_if_holder` replaces `renew_lock` at Step-4 (ADR-046 Decision 3 — no
   coexistence):** After this story, the old `renew_lock` call at Step-4 MUST NOT remain.
   Adversarial review will check for any surviving `renew_lock` call in the Step-4 context.
2. **`resolve_identity` closure MUST use `factory_lock::classify_identity_resolution` (ADR-046
   Decision 2 / AC-004):** Not a raw `exec_subprocess` call directly passed to `renew_lock_if_holder`.
3. **Flush MUST proceed for ALL non-error outcomes (BC-7.07.001 Invariant 3 / flush-proceeds-unblocked
   invariant):** The plugin MUST NOT abort or block the flush for `NotHolder`, `AlreadyExpired`,
   or `IdentityResolutionFailed`. Only a `LockError::Malformed` may optionally log a warning;
   even then, the flush proceeds.
4. **`factory.lock.renewal_indeterminate` event payload: 5 fields required (ADR-046 Decision 4
   / AC-004):** `plugin`, `holder`, `locked_at`, `expires_at`, `resolution_error`. Emitting
   fewer fields is a BC violation.
5. **Injectable-callback harness consistency (established by S-18.04a):** The `resolve_identity`
   wiring in `main.rs` must be injectable as a mock closure in unit tests — do not wire
   `host::exec_subprocess` directly inside the guard logic function body.
6. **No `serde_yaml`/`serde_norway` / no `regex` crate:** Consistent with the whole crate family.

## Demo Plan

1. **AC-002 (identity match — renews):** Fixture STATE.md with valid lock where `holder`
   matches the test harness identity. Assert flushed content contains `expires_at` advanced
   by `TTL_SECONDS`.
2. **AC-001 (AlreadyExpired — no exec):** Fixture with `expires_at` in the past. Assert
   `resolve_identity` closure was NOT called (counter = 0); assert flushed content uses
   original `expires_at`.
3. **AC-004 (IdentityResolutionFailed — event emitted):** Fixture where `resolve_identity`
   returns `IdentityResolution::Failed("test error")`. Assert `host::emit_event` was called
   with `factory.lock.renewal_indeterminate` and all 5 payload fields; assert flush proceeds.
4. **AC-003 (not holder — no renewal):** Fixture where `resolve_identity` returns
   `Resolved("other@example.com")` but `holder` is `"me@example.com"`. Assert flushed
   content `expires_at` is byte-identical to input.
