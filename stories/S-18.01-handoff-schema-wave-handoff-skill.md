# S-18.01 — HANDOFF.md Schema + wave-handoff Skill; wave-state.yaml Atomic Production

## Narrative

As an orchestrator agent closing a wave boundary,
I want the wave-handoff skill to write a verified HANDOFF.md (9 base required fields)
and an atomically co-committed wave-state.yaml (6 required fields derived from
sprint-state.yaml) to the factory-artifacts branch,
so that the next wave can rehydrate from a complete, auditable checkpoint without
RAG or phantom-wave hallucination.

## Behavioral Contracts

| BC ID | Title | Version | PCs Exercised |
|-------|-------|---------|---------------|
| BC-5.41.001 | wave-gate writes verified HANDOFF.md with 9 base required fields | v1.18 | PC1–PC9, INV1–INV3 |
| BC-5.41.002 | wave-gate produces curated wave-state.yaml | v1.13 | PC1–PC7, INV1–INV4 |

## Acceptance Criteria

### AC-001 (traces to BC-5.41.001 postcondition 1)
The wave-handoff skill writes HANDOFF.md to the factory-artifacts branch containing
all 9 base required fields:
`wave_id`, `last_verified_develop_sha`, `active_bcs`, `next_wave_stories`,
`open_decisions`, `pending_fixes`, `process_gaps`, `precompact_flush_sha`,
`factory_lock_holder`.

### AC-002 (traces to BC-5.41.001 postcondition 2)
`wave_id` is derived from sprint-state.yaml topological sort (current wave) OR from
`STATE.md current_step:` when sprint-state.yaml is absent. No `current_wave:` phantom
field is read from any source.

### AC-003 (traces to BC-5.41.001 postcondition 3)
`last_verified_develop_sha` is a 40-character lowercase hex SHA obtained from
`git rev-parse origin/develop` at skill invocation time — never hardcoded, never
derived from a cache older than the current dispatch.

### AC-004 (traces to BC-5.41.001 postcondition 4)
`active_bcs` is a non-empty YAML list. The skill hard-errors (exit 1) if no active
BCs can be determined at wave close.

### AC-005 (traces to BC-5.41.001 postcondition 5)
`next_wave_stories` is a list of `{id, status}` objects. It may be an empty list
ONLY in the EPIC-COMPLETE case (see AC-012).

### AC-006 (traces to BC-5.41.001 postcondition 6)
`open_decisions` is a list of `{id, anchor_type, anchor_ref}` objects. An empty
list is valid when no decisions are open.

### AC-007 (traces to BC-5.41.001 postcondition 7)
`pending_fixes` is a list of `{finding_id, pr_or_issue_ref}` objects. An empty
list is valid when no fixes are pending.

### AC-008 (traces to BC-5.41.001 postcondition 8)
`process_gaps` is a list. An empty list is valid when no gaps are identified.

### AC-009 (traces to BC-5.41.001 postcondition 9)
`precompact_flush_sha` is either a 40-character hex SHA (read from the last line
of `.factory/hooks/precompact-flush-log` FIELD-2 when the log exists and FIELD-4
equals `commit`) or the explicit YAML value `null` (when the log is absent or
FIELD-4 is not `commit`). This is a three-state rule: present-valid | null |
absent-field is an error.

### AC-010 (traces to BC-5.41.001 postcondition 9 continued)
`factory_lock_holder` is either a string (identity of the lock holder) or `null`.

### AC-011 (traces to BC-5.41.001 invariant 1)
HANDOFF.md is committed to factory-artifacts with commit message
`HANDOFF wave-<N> <ISO-timestamp>` (exact format, no deviation).

### AC-012 (traces to BC-5.41.001 invariant 2 + BC-5.41.002 postcondition 5)
When all sprint-state.yaml entries have terminal status (merged/withdrawn/cancelled),
the skill writes HANDOFF.md with `epic_status: complete` and
`next_wave_stories: []`. wave-state.yaml is NOT written in the EPIC-COMPLETE case.
The skill MUST emit the following stdout announcement verbatim (where `<epic-id>` is
derived from the `current_cycle:` field of STATE.md):

```
EPIC-COMPLETE: All stories in sprint-state.yaml have reached terminal status.
Epic <epic-id> is complete. No wave-state.yaml written for next wave.
HANDOFF.md committed to factory-artifacts with epic_status: complete.
```

A silent exit 0 without this announcement is a specification violation
(BC-5.41.001 PC8 / BC-5.41.002 PC7).

### AC-013 (traces to BC-5.41.002 postcondition 1)
wave-state.yaml is written to factory-artifacts (when NOT EPIC-COMPLETE) containing
6 required fields: `wave_id`, `generated_at`, `generated_from_handoff_sha`,
`stories`, `arch_files`, `state_pointer`.

### AC-014 (traces to BC-5.41.002 postcondition 2)
`generated_from_handoff_sha` in wave-state.yaml is the git SHA of the most
recent HANDOFF.md commit that already exists on `factory-artifacts` BEFORE the
current wave-close atomic commit — i.e., the prior verified HANDOFF.md commit
captured as `prior_handoff_sha = git -C <factory-artifacts-worktree> rev-parse HEAD`
immediately before the atomic commit step (AC-011/AC-017). For wave 1 (no prior
HANDOFF.md commit exists on factory-artifacts), the value is `null`. The skill
MUST NOT populate this field with the SHA of the commit being created (not
computable before commit — cryptographic fixed-point).

### AC-015 (traces to BC-5.41.002 postcondition 3)
`stories` in wave-state.yaml is derived EXCLUSIVELY from sprint-state.yaml
entries with `status: pending` or `status: draft`, sorted in dependency-graph
topological order. No phantom wave frontmatter, no RAG, no other source.

### AC-016 (traces to BC-5.41.002 postcondition 4)
`arch_files` in wave-state.yaml lists architecture reference files relevant to
the upcoming wave (derived from the stories' `anchored_adrs` and subsystem
membership, not hardcoded).

### AC-017 (traces to BC-5.41.002 postcondition 6)
HANDOFF.md and wave-state.yaml are committed atomically in a SINGLE git commit.
The skill MUST NOT produce two separate commits (one for HANDOFF.md, one for
wave-state.yaml).

### AC-018 (traces to BC-5.41.002 postcondition 7 + invariant 1)
BrokenSprintState: when sprint-state.yaml has entries in non-terminal,
non-pending/draft states (e.g., `status: in-progress`, `status: review-pending`)
but no pending/draft entries, the skill exits 1 with canonical message:
"BrokenSprintState: stories in non-terminal, non-pending states exist but no
next-wave stories are pending/draft. Update sprint-state.yaml to reflect actual
story states."

### AC-019 (traces to BC-5.41.001 postcondition 9 — HandoffMissing)
When the WASM gate (validate-wave-handoff-completeness) is invoked at wave-close
and HANDOFF.md is ABSENT on factory-artifacts, the shell-side wave-gate script
emits `HandoffMissing` error and exits non-zero before the WASM gate is triggered.
(Shell-side responsibility; wave-handoff skill ensures the file is written, making
HandoffMissing structurally impossible if skill completes successfully.)

### AC-020 (traces to BC-5.41.002 invariant 2)
`status: review-pending` in sprint-state.yaml is treated as a non-terminal,
non-pending/draft state — triggering BrokenSprintState if it is the only
non-terminal state class present. (Discriminating fixture VP-087.)

## Canonical Wiring Contract (ADR-027-factory-artifacts-path-discipline)

**Resolution of F-S1801-P3-001 BLOCKER — factory-artifacts worktree path model.**

The factory-artifacts orphan branch is mounted as a git worktree at `.factory/` inside the
repository root (confirmed by `git worktree list`: path `/…/vsdd-factory/.factory`, branch
`factory-artifacts`). This means `.factory/` IS the worktree root — it is not a subdirectory
of the worktree.

### Canonical Path Model (Single-Worktree, Two-Arg)

The skill operates with **one worktree path argument** and **two separate read-path arguments**:

| Argument / Env Var | Value in production | Role |
|--------------------|--------------------|----|
| `--artifacts-worktree ARTIFACTS_WT` | `.factory` (repo-relative) or absolute `$REPO_ROOT/.factory` | Root of the factory-artifacts worktree. git commit target: `git -C "$ARTIFACTS_WT" commit`. HANDOFF.md written to `$ARTIFACTS_WT/HANDOFF.md`. wave-state.yaml written to `$ARTIFACTS_WT/wave-state.yaml`. precompact-flush-log read from `$ARTIFACTS_WT/hooks/precompact-flush-log`. BC dir read from `$ARTIFACTS_WT/specs/behavioral-contracts` (unless overridden by `--bc-dir`). |
| `--sprint-state SPRINT_STATE_YAML` | `.factory/stories/sprint-state.yaml` | Path to sprint-state.yaml. In production equals `$ARTIFACTS_WT/stories/sprint-state.yaml`. Passed separately so bats fixtures can supply synthetic files without nesting. |
| `--state-md STATE_MD_PATH` | `.factory/STATE.md` | Path to STATE.md. In production equals `$ARTIFACTS_WT/STATE.md`. Passed separately for hermetic bats fixture isolation. |
| `--bc-dir BC_DIR` (optional, default: `$ARTIFACTS_WT/specs/behavioral-contracts`) | `.factory/specs/behavioral-contracts` | Directory scanned for active BC files. |

### Why Two-Arg (not single-root)?

The bats fixture constructs a hermetic git repo where the factory-artifacts worktree is a
linked worktree under a temp directory (`$WORK/factory-wt`). In this fixture the main repo
root (`$WORK`) and the artifacts worktree root (`$ARTIFACTS_WT=$WORK/factory-wt`) differ.
`sprint-state.yaml` and `STATE.md` are placed in `$WORK` (not `$WORK/factory-wt`) to mirror
the production layout where these files are at the repo root's `.factory/stories/` and
`.factory/STATE.md` — which are inside the factory-artifacts worktree, not inside a separate
main-repo directory. The two-arg model lets the same `wave-handoff.sh` binary work correctly
in both production (where `$ARTIFACTS_WT` = `.factory` and `$SPRINT_STATE_YAML` =
`$ARTIFACTS_WT/stories/sprint-state.yaml`) and in bats fixtures (where the worktree and the
repo root are different temp directories).

### What is NOT correct

The following path patterns are FORBIDDEN in `wave-handoff.sh` and its lib scripts:

| Forbidden pattern | Why |
|-------------------|-----|
| `${ARTIFACTS_WT}/.factory/STATE.md` | Double-nesting: in production `ARTIFACTS_WT` = `.factory`, so this resolves to `.factory/.factory/STATE.md` — does not exist. |
| `${ARTIFACTS_WT}/.factory/specs/...` | Same double-nesting: produces `.factory/.factory/specs/...` — does not exist. |
| Hardcoded `.factory/STATE.md` without using `$ARTIFACTS_WT` or `$STATE_MD_PATH` | Breaks bats fixtures; non-hermetic. |
| `git -C "$REPO_ROOT" commit` targeting develop/feature branch | Commits HANDOFF.md to the wrong branch. Must use `git -C "$ARTIFACTS_WT" commit` so the commit lands on factory-artifacts. |

### Production invocation example

```bash
bash plugins/vsdd-factory/skills/wave-handoff/wave-handoff.sh \
  --artifacts-worktree .factory \
  --sprint-state .factory/stories/sprint-state.yaml \
  --state-md .factory/STATE.md \
  --bc-dir .factory/specs/behavioral-contracts
```

All paths are relative to the repository root (which is the caller's CWD when the skill is
invoked from the project root). The git commit runs `git -C .factory commit`, which commits
to the factory-artifacts branch (the branch that `.factory` worktree is checked out on).

### STORY-INDEX.md and arch_files resolution

`STORY-INDEX.md` is read from `$ARTIFACTS_WT/stories/STORY-INDEX.md` (i.e., `.factory/stories/STORY-INDEX.md` in production). Architecture reference files in `arch_files` are resolved relative to `$ARTIFACTS_WT` (e.g., `$ARTIFACTS_WT/specs/architecture/ARCH-INDEX.md`). The skill MUST use the full slug paths (e.g., `specs/architecture/decisions/ADR-026-wave-boundary-checkpoint-reset-and-lossless-intra-wave-compaction.md`) not short-form aliases — verified to exist on disk before inclusion.

## Previous Story Intelligence

S-18.00 establishes PreCompact/PostCompact as first-class event types. The
wave-handoff skill does not dispatch PreCompact events itself — it reads the
precompact-flush-log (written by S-18.04a) to populate `precompact_flush_sha`.

Key lesson from factory pipeline history (S-18.04a §Previous Story Intelligence):
every shell skill that writes to factory-artifacts must use `git -C "$ARTIFACTS_WT" …`
path discipline and must NOT assume CWD equals the factory-artifacts worktree mount point.
The `FACTORY_ARTIFACTS_PATH` environment variable or an explicit `--artifacts-worktree`
CLI arg is required.

Additional lesson codified via ADR-027 (resolved F-S1801-P3-001 BLOCKER): the
factory-artifacts worktree IS mounted at `.factory/` directly (not inside a subdirectory).
Therefore `$ARTIFACTS_WT` = `.factory` in production, and all paths inside factory-artifacts
are `${ARTIFACTS_WT}/STATE.md`, `${ARTIFACTS_WT}/specs/…`, etc. — never
`${ARTIFACTS_WT}/.factory/STATE.md` (double-nesting). Bats fixtures supply sprint-state.yaml
and STATE.md as separate CLI args (`--sprint-state`, `--state-md`) pointing to files in the
main repo temp dir; this is correct hermetic test practice, not a divergence from the
production model.

- `set -euo pipefail` mandatory in all bash scripts (CLAUDE.md convention)
- No `--no-verify` git flags (CLAUDE.md absolute prohibition)
- **No double-nested paths (ADR-027 §Canonical Path Model):** `${ARTIFACTS_WT}/.factory/…` is FORBIDDEN. All factory-artifacts reads and writes use `${ARTIFACTS_WT}/…` directly (e.g., `${ARTIFACTS_WT}/STATE.md`, `${ARTIFACTS_WT}/specs/behavioral-contracts`). Violations produce `.factory/.factory/…` paths that do not exist in production.
- **Git commit discipline:** All commits to factory-artifacts use `git -C "${ARTIFACTS_WT}" commit` — not `git -C "$REPO_ROOT" commit`. Using the repo root targets the develop/feature branch, not factory-artifacts.
- **Hermetic bats fixtures:** Bats tests supply `--sprint-state` and `--state-md` as explicit path args pointing to files in the temp repo dir (not inside `$ARTIFACTS_WT`). The invocation contract must accept these as separate args so production and test scenarios both work without path hacks.

- bash >= 4.x (available in CI — no bash 3 compatibility required)
- git (standard factory-artifacts discipline)
- bats-core: version already in use
- No new external tool dependencies permitted without architect review
