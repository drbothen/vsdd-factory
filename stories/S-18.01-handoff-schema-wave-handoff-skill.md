# S-18.01 — HANDOFF.md Schema + wave-handoff Skill; wave-state.yaml Atomic Production

## Narrative

As an orchestrator agent closing a wave boundary,
I want the wave-handoff skill to write a verified HANDOFF.md (9 base required fields)
and an atomically co-committed wave-state.yaml (6 required fields derived from
sprint-state.yaml) to the factory-artifacts branch,
so that the next wave can rehydrate from a complete, auditable checkpoint without
RAG or phantom-wave hallucination.

## Behavioral Contracts

| BC ID | Title | Version | PCs Exercised |
|-------|-------|---------|---------------|
| BC-5.41.001 | wave-gate writes verified HANDOFF.md with 9 base required fields | v1.17 | PC1–PC9, INV1–INV3 |
| BC-5.41.002 | wave-gate produces curated wave-state.yaml | v1.12 | PC1–PC7, INV1–INV4 |

## Acceptance Criteria

### AC-001 (traces to BC-5.41.001 postcondition 1)
The wave-handoff skill writes HANDOFF.md to the factory-artifacts branch containing
all 9 base required fields:
`wave_id`, `last_verified_develop_sha`, `active_bcs`, `next_wave_stories`,
`open_decisions`, `pending_fixes`, `process_gaps`, `precompact_flush_sha`,
`factory_lock_holder`.

### AC-002 (traces to BC-5.41.001 postcondition 2)
`wave_id` is derived from sprint-state.yaml topological sort (current wave) OR from
`STATE.md current_step:` when sprint-state.yaml is absent. No `current_wave:` phantom
field is read from any source.

### AC-003 (traces to BC-5.41.001 postcondition 3)
`last_verified_develop_sha` is a 40-character lowercase hex SHA obtained from
`git rev-parse origin/develop` at skill invocation time — never hardcoded, never
derived from a cache older than the current dispatch.

### AC-004 (traces to BC-5.41.001 postcondition 4)
`active_bcs` is a non-empty YAML list. The skill hard-errors (exit 1) if no active
BCs can be determined at wave close.

### AC-005 (traces to BC-5.41.001 postcondition 5)
`next_wave_stories` is a list of `{id, status}` objects. It may be an empty list
ONLY in the EPIC-COMPLETE case (see AC-012).

### AC-006 (traces to BC-5.41.001 postcondition 6)
`open_decisions` is a list of `{id, anchor_type, anchor_ref}` objects. An empty
list is valid when no decisions are open.

### AC-007 (traces to BC-5.41.001 postcondition 7)
`pending_fixes` is a list of `{finding_id, pr_or_issue_ref}` objects. An empty
list is valid when no fixes are pending.

### AC-008 (traces to BC-5.41.001 postcondition 8)
`process_gaps` is a list. An empty list is valid when no gaps are identified.

### AC-009 (traces to BC-5.41.001 postcondition 9)
`precompact_flush_sha` is either a 40-character hex SHA (read from the last line
of `.factory/hooks/precompact-flush-log` FIELD-2 when the log exists and FIELD-4
equals `commit`) or the explicit YAML value `null` (when the log is absent or
FIELD-4 is not `commit`). This is a three-state rule: present-valid | null |
absent-field is an error.

### AC-010 (traces to BC-5.41.001 postcondition 9 continued)
`factory_lock_holder` is either a string (identity of the lock holder) or `null`.

### AC-011 (traces to BC-5.41.001 invariant 1)
HANDOFF.md is committed to factory-artifacts with commit message
`HANDOFF wave-<N> <ISO-timestamp>` (exact format, no deviation).

### AC-012 (traces to BC-5.41.001 invariant 2 + BC-5.41.002 postcondition 5)
When all sprint-state.yaml entries have terminal status (merged/withdrawn/cancelled),
the skill writes HANDOFF.md with `epic_status: complete` and
`next_wave_stories: []`. wave-state.yaml is NOT written in the EPIC-COMPLETE case.
A stdout announcement "EPIC-COMPLETE: all stories in terminal state" is emitted.

### AC-013 (traces to BC-5.41.002 postcondition 1)
wave-state.yaml is written to factory-artifacts (when NOT EPIC-COMPLETE) containing
6 required fields: `wave_id`, `generated_at`, `generated_from_handoff_sha`,
`stories`, `arch_files`, `state_pointer`.

### AC-014 (traces to BC-5.41.002 postcondition 2)
`generated_from_handoff_sha` in wave-state.yaml equals the git SHA of the
HANDOFF.md commit produced in AC-011.

### AC-015 (traces to BC-5.41.002 postcondition 3)
`stories` in wave-state.yaml is derived EXCLUSIVELY from sprint-state.yaml
entries with `status: pending` or `status: draft`, sorted in dependency-graph
topological order. No phantom wave frontmatter, no RAG, no other source.

### AC-016 (traces to BC-5.41.002 postcondition 4)
`arch_files` in wave-state.yaml lists architecture reference files relevant to
the upcoming wave (derived from the stories' `anchored_adrs` and subsystem
membership, not hardcoded).

### AC-017 (traces to BC-5.41.002 postcondition 6)
HANDOFF.md and wave-state.yaml are committed atomically in a SINGLE git commit.
The skill MUST NOT produce two separate commits (one for HANDOFF.md, one for
wave-state.yaml).

### AC-018 (traces to BC-5.41.002 postcondition 7 + invariant 1)
BrokenSprintState: when sprint-state.yaml has entries in non-terminal,
non-pending/draft states (e.g., `status: in-progress`, `status: review-pending`)
but no pending/draft entries, the skill exits 1 with canonical message:
"BrokenSprintState: stories in non-terminal, non-pending states exist but no
next-wave stories are pending/draft. Update sprint-state.yaml to reflect actual
story states."

### AC-019 (traces to BC-5.41.001 postcondition 9 — HandoffMissing)
When the WASM gate (validate-wave-handoff-completeness) is invoked at wave-close
and HANDOFF.md is ABSENT on factory-artifacts, the shell-side wave-gate script
emits `HandoffMissing` error and exits non-zero before the WASM gate is triggered.
(Shell-side responsibility; wave-handoff skill ensures the file is written, making
HandoffMissing structurally impossible if skill completes successfully.)

### AC-020 (traces to BC-5.41.002 invariant 2)
`status: review-pending` in sprint-state.yaml is treated as a non-terminal,
non-pending/draft state — triggering BrokenSprintState if it is the only
non-terminal state class present. (Discriminating fixture VP-087.)

## Previous Story Intelligence

S-18.00 establishes PreCompact/PostCompact as first-class event types. The
wave-handoff skill does not dispatch PreCompact events itself — it reads the
precompact-flush-log (written by S-18.04a) to populate `precompact_flush_sha`.
Key lesson from factory pipeline history: every shell skill that writes to
factory-artifacts must use `git -C .factory ...` path discipline and must not
assume CWD equals the factory-artifacts worktree mount point.

## Architecture Compliance Rules

- `plugins/vsdd-factory/skills/wave-handoff/SKILL.md` must follow the canonical skill definition format (invocation contract, required args, optional args, exit codes)
- Single atomic git commit for HANDOFF.md + wave-state.yaml (BC-5.41.002 PC6) — no multi-commit chain
- wave_id derivation must NOT read any `current_wave:` field — this field does not exist in any source document
- `set -euo pipefail` mandatory in all bash scripts (CLAUDE.md convention)
- No `--no-verify` git flags (CLAUDE.md absolute prohibition)

## Library & Framework Requirements

- bash >= 4.x (available in CI — no bash 3 compatibility required)
- git (standard factory-artifacts discipline)
- bats-core: version already in use
- No new external tool dependencies permitted without architect review
