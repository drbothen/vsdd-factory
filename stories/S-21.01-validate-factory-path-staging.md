# S-21.01 — validate-factory-path-staging WASM guard + orchestrator merge pre-check: prevent dual-tracking and intercept product-branch merges that would clobber `.factory/` paths

**Epic:** E-21 — Factory State Data-Loss Hardening
**Wave:** 1 (no inter-E-21 dependencies; can begin immediately)
**Depends on:** none
**Priority:** P0 (data-loss prevention; the dual-tracking condition is a silent P0 landmine per issue #342)
**Subsystem anchor:** SS-04 (Plugin Ecosystem) owns the new WASM crate. SS-05 (Pipeline Orchestration) owns the skill-doc merge-gate step.
**POLICY 21 note:** This story introduces one new WASM crate (`crates/hook-plugins/validate-factory-path-staging/`, per ADR-031 §Decision 3). No new `.sh` files are introduced. The skill-doc merge-gate step (BC-5.43.001) is a required orchestrator action documented in agent prompt step instructions — no shell script needed. POLICY 21 is satisfied.

## Narrative

Issue #342 documents a confirmed-live data-loss scenario: when a `.factory/**` file is accidentally staged and committed on the product branch (dual-tracking condition), a subsequent `git merge` or `git pull` on the product branch can resolve a path deletion in favor of the product branch, silently destroying the factory artifact. The existing `factory-branch-guard.sh` intercepts Edit/Write/MultiEdit tool calls, but it does NOT intercept Bash-tool `git add` commands. No gate prevents the dual-tracking condition from forming.

ADR-031 §Decision 2 mandates a two-layer defense for INV-E21-001:

**Layer 1 — Invariant layer (BC-4.16.001):** A new `validate-factory-path-staging` native WASM PreToolUse plugin fires on every Bash tool call. If the Bash payload contains `git add` AND any argument resolves to a `.factory/`-rooted path AND the current branch is a product branch (not `factory-artifacts`), the plugin blocks with `block_intent = true` (exit 2) and `FactoryPathOnProductBranch` error message. All other commands pass unconditionally. Crate: `crates/hook-plugins/validate-factory-path-staging/` (ADR-031 §Decision 3 — distinct from `validate-artifact-path/` which serves BC-4.11.001/S-13.01).

**Layer 2 — Safety-net layer (BC-5.43.001):** A mandatory `Main-Checkout Sync Protocol` pre-check constraint is added to `plugins/vsdd-factory/agents/orchestrator/per-story-delivery.md`: before any `git pull`/`git merge` on the main product checkout (where `.factory/` is physically mounted as a nested worktree), the orchestrator MUST run `git diff --name-only HEAD..<target-ref>`. If the result contains any path matching `^\.factory/`, the operation is halted with `FactoryPathDeletionInMergeDiff`. This layer intercepts pre-existing dual-tracking regardless of how it formed — including the server-side origination threat vector: a contributor PR merged via GitHub `gh pr merge` adds `.factory/`-pathed files without triggering Layer-1 (no local `git add` Bash call fires). The next `git pull origin develop` on the main checkout delivers the tracked `.factory/` content; without this gate, the subsequent merge silently destroys factory artifact content. Layer-2 is the **primary guard** for this server-side vector. Layer-1 scope stays narrow (git add/stage only — NOT extended to pull/merge per ADR-031 v1.3 §Decision 2 + §Rationale; `orchestrator/per-story-delivery.md` is the correct enforcement site).

Both layers are required for full coverage (ADR-031 §Rationale).

## Architecture Mapping

This story creates a new WASM crate and amends multiple skill/agent files:

- `crates/hook-plugins/validate-factory-path-staging/` — **new crate** (ADR-031 §Decision 3; MUST NOT reuse or modify `crates/hook-plugins/validate-artifact-path/`); compiles to `hook-plugins/validate-factory-path-staging.wasm`; implements BC-4.16.001 PC1–PC4 and Invariants 1–5
- `plugins/vsdd-factory/hooks-registry.toml` — add `[[hooks]]` entry for `validate-factory-path-staging` with `event = "PreToolUse"`, `tool = "^Bash$"`, `priority = 140`, `on_error = "continue"`, `tier = "sync"`
- `plugins/vsdd-factory/agents/orchestrator/per-story-delivery.md` — add `§Main-Checkout Sync Protocol` section: mandatory pre-check constraint before any `git pull`/`git merge` on the main product checkout; `git diff --name-only HEAD..<target-ref>`; halt with `FactoryPathDeletionInMergeDiff` on `.factory/` path detection; covers both documented steps and ad-hoc operator Bash (ADR-031 v1.3 §Decision 2, BC-5.43.001 v1.3)
- `plugins/vsdd-factory/tests/validate-factory-path-staging.bats` — new bats suite for AC-001..AC-009

**Server-side origination threat vector:** Contributor PRs merged via GitHub server-side (`gh pr merge`) do not fire any local `git add` command — Layer-1 never fires for this vector. The merged branch may carry `.factory/`-pathed files that now exist on `origin/develop`. The next `git pull origin develop` on the main checkout (where `.factory/` is physically mounted) delivers this content. Without Layer-2, the subsequent merge would silently destroy factory artifact content. Layer-2 in `per-story-delivery.md` is the **primary guard** for this vector. Layer-1 scope stays narrow — extending the WASM guard to intercept `git pull`/`git merge` is explicitly prohibited by ADR-031 v1.3 §Decision 2.

**ADR-031** — E-21 factory state data-loss hardening: §Decision 2 (two-layer INV-E21-001 defense; Layer-2 enforcement site = `orchestrator/per-story-delivery.md` §Main-Checkout Sync Protocol; server-side origination residual risk documented; Layer-1 scope narrow), §Decision 3 (crate naming — `validate-factory-path-staging/` is mandatory; `validate-artifact-path/` serves BC-4.11.001/S-13.01 and MUST NOT be reused).
