# S-21.01 — validate-factory-path-staging WASM guard + orchestrator merge pre-check: prevent dual-tracking and intercept product-branch merges that would clobber `.factory/` paths

**Epic:** E-21 — Factory State Data-Loss Hardening
**Wave:** 1 (no inter-E-21 dependencies; can begin immediately)
**Depends on:** none
**Priority:** P0 (data-loss prevention; the dual-tracking condition is a silent P0 landmine per issue #342)
**Subsystem anchor:** SS-04 (Plugin Ecosystem) owns the new WASM crate. SS-05 (Pipeline Orchestration) owns the skill-doc merge-gate step.
**POLICY 21 note:** This story introduces one new WASM crate (`crates/hook-plugins/validate-factory-path-staging/`, per ADR-031 §Decision 3). No new `.sh` files are introduced. The skill-doc merge-gate step (BC-5.43.001) is a required orchestrator action documented in agent prompt step instructions — no shell script needed. POLICY 21 is satisfied.

## Narrative

Issue #342 documents a confirmed-live data-loss scenario: when a `.factory/**` file is accidentally staged and committed on the product branch (dual-tracking condition), a subsequent `git merge` or `git pull` on the product branch can resolve a path deletion in favor of the product branch, silently destroying the factory artifact. The existing `factory-branch-guard.sh` intercepts Edit/Write/MultiEdit tool calls, but it does NOT intercept Bash-tool `git add` commands. No gate prevents the dual-tracking condition from forming.

ADR-031 §Decision 2 mandates a two-layer defense for INV-E21-001:

**Layer 1 — Invariant layer (BC-4.16.001):** A new `validate-factory-path-staging` native WASM PreToolUse plugin fires on every Bash tool call. If the Bash payload contains `git add` AND any argument resolves to a `.factory/`-rooted path AND the current branch is a product branch (not `factory-artifacts`), the plugin blocks with `block_intent = true` (exit 2) and `FactoryPathOnProductBranch` error message. All other commands pass unconditionally. Crate: `crates/hook-plugins/validate-factory-path-staging/` (ADR-031 §Decision 3 — distinct from `validate-artifact-path/` which serves BC-4.11.001/S-13.01).

**Layer 2 — Safety-net layer (BC-5.43.001):** Every orchestrator/agent merge protocol step is extended: before any `git merge`, `git pull`, or `git checkout` that advances HEAD on the product branch, the agent MUST run `git diff --name-only HEAD..<target-ref>`. If the result contains any path matching `^\.factory/`, the operation is halted with `FactoryPathDeletionInMergeDiff`. This layer intercepts pre-existing dual-tracking that formed before Layer 1 was active.

Both layers are required for full coverage (ADR-031 §Rationale).
