# S-21.05 — pr-manager factory-side PR protocol: restore-original-branch, ff-only sync, and chore-branch cleanup

**Epic:** E-21 — Factory State Data-Loss Hardening
**Wave:** 2 (independent of Wave 1 stories; benefits from S-21.01 `validate-factory-path-staging` WASM guard being active as defense-in-depth, but is independently viable without it — no formal `depends_on` block; Wave 2 placement reflects shared-mutable-worktree theme adjacency with S-21.04)
**Depends on:** none
**Priority:** P1 (confirmed-live: pr-manager leaves the shared `.factory/` worktree stranded on a chore branch after factory-side PRs; subsequent state-manager dispatches inherit the stranded branch silently)
**Subsystem anchor:** SS-06 (Skill Catalog) owns pr-manager agent definition.

## Narrative

Issue #588 documents a confirmed-live failure: when pr-manager creates a chore branch on `factory-artifacts` to update it via a PR (VP anchor true-up, merge-SHA annotation), merges the PR, and returns to the calling context — the shared `.factory/` worktree is left stranded on the chore branch. Subsequent state-manager dispatches that write to `.factory/` inherit the stranded branch silently. `factory-branch-guard.sh` blocks Edit/Write tool calls when `.factory/` is on the wrong branch, but does NOT catch Bash-mediated `git -C .factory commit` operations. History accumulates on the stray branch until it is eventually lost or creates divergence.

The issue comment (arcaven, 2026-07-13) confirms: "pr-manager.md has no factory-side PR flow section even after the S-19.01 hardening."

Two complementary protocol requirements close the stranding window:

**Factory-side PR protocol — 5-step restore sequence (BC-6.27.001 PC1):** After any factory-side PR merges, pr-manager MUST execute the 5-step restore sequence in order before declaring the PR "done": (1) `git -C .factory checkout factory-artifacts`, (2) `git -C .factory pull --ff-only origin factory-artifacts`, (3) `git -C .factory branch -d chore/<name>`, (4) `git push origin --delete chore/<name>`, (5) assert `git -C .factory branch --show-current` equals `factory-artifacts`.

**Dispatch-preamble branch assertion — defense-in-depth (BC-6.27.001 PC2):** Every agent dispatch that writes to `.factory/` (state-manager, pr-manager factory-side flow) MUST assert `git -C .factory branch --show-current` equals `factory-artifacts` as the FIRST step of the dispatch preamble, before any file read, state check, or write. If the assertion fails, STOP and report `FactoryWorktreeOnWrongBranch` with recovery instructions.

This story is entirely skill-doc. POLICY 21 satisfied (no new WASM or shell script).

## Architecture Mapping

This story amends `pr-manager.md` and adds one bats suite:

- `plugins/vsdd-factory/agents/pr-manager.md` — two amendments:
  - **Add "Factory-Side PR Protocol" section:** 5-step restore sequence (checkout factory-artifacts → pull --ff-only → delete local chore branch → delete remote chore branch → final branch assertion); failure modes for each step; `FFOnlyPullFailed`, `CheckoutRestoreFailed`, `FinalBranchAssertionFailed` error variants (BC-6.27.001 PC1 + Invariants 1/2/3)
  - **Add dispatch-preamble branch assertion:** FIRST step in all `.factory/` write dispatches — `ASSERT git -C .factory branch --show-current == factory-artifacts`; `FactoryWorktreeOnWrongBranch` STOP + recovery if fails (BC-6.27.001 PC2 + Invariant 4)
- `plugins/vsdd-factory/tests/pr-manager-factory-side-pr-protocol.bats` — new bats suite for AC-002..AC-008

**ADR-031** §Decision 5 governs: INV-E21-003 (factory worktree branch integrity) enforced via skill-doc. No new WASM or shell script. Distinct from CAP-031 (BC-6.23.001 cooperative lock/lease per ADR-025).
