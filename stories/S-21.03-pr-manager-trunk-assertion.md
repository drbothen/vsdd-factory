# S-21.03 — pr-manager trunk-assertion hardening: post-create baseRefName check and post-merge ancestry assertion

**Epic:** E-21 — Factory State Data-Loss Hardening
**Wave:** 1 (no inter-E-21 dependencies; parallel with S-21.01 and S-21.02)
**Depends on:** none
**Priority:** P1 (process gap; the `gh pr create --base develop` invocation in pr-manager.md Step 3 is already in place — this story adds the load-bearing post-create and post-merge assertions that detect gh CLI base-inference edge cases and orphan-merge scenarios)
**Subsystem anchor:** SS-06 (Skill Catalog) owns BC-6.10.002 (deliver-story 9-step dispatch sequence).

## Narrative

Issue #358 documents a partially-fixed process gap. `pr-manager.md` already emits `gh pr create --base develop` at Step 3. The open gap is the absence of two post-action assertions:

1. **Post-create baseRefName assertion (BC-6.10.002 PC2):** After `gh pr create`, read back the PR's `baseRefName` via `gh pr view <num> --json baseRefName` and assert it equals the configured trunk. This catches the case where `gh` resolved the base from `gh-merge-base` git config or the repository's GitHub default branch rather than the explicit `--base` flag value.

2. **Post-merge ancestry assertion (BC-6.10.002 PC3):** After `gh pr merge` reports `state: MERGED`, run `git fetch origin <trunk> && git merge-base --is-ancestor <merge_sha> origin/<trunk>` and assert exit 0. This is the load-bearing check: it catches the orphan-merge scenario where the PR merged into a non-trunk branch and `state: MERGED` is superficially true but the content is not on trunk.

Both assertions are implemented as skill-doc amendments to `pr-manager.md`. No new WASM plugin or shell script. POLICY 21 satisfied.

## Architecture Mapping

This story amends `pr-manager.md` with two new post-action assertion steps:

**Step-numbering note:** Step numbers below follow pr-manager.md's internal 9-step sequence. In deliver-story terms, the entire pr-manager dispatch is deliver-story step 7; within pr-manager's internal numbering: Step 3 = PR creation, Step 8 = merge execution, Step 9 = post-merge checklist.

- `plugins/vsdd-factory/agents/pr-manager.md` — two amendments:
  - **Step 3 (pr-manager internal; post-create):** After `gh pr create --base develop`, delegate to `github-ops` to run `gh pr view <num> --json baseRefName`; assert returned value equals trunk; hard-fail with `BaseRefNameMismatch` if not (BC-6.10.002 PC2)
  - **Step 9 (pr-manager internal; post-merge):** After `gh pr merge` succeeds, delegate to `github-ops` to run `git fetch origin <trunk> && git merge-base --is-ancestor <merge_sha> origin/<trunk>`; raise P0 with `MergeNotAncestorOfTrunk` if non-zero (BC-6.10.002 PC3)
- `plugins/vsdd-factory/tests/pr-manager-trunk-assertion.bats` — new bats suite for AC-001..AC-005

**ADR-031** §Decision 6 context: this story is a skill-doc amendment — no new WASM or shell script. **§Decision 8** (INV-E21-006 enforcement via BC-6.10.002 amendment + CAP-038 allocation) governs the trunk-ancestry postconditions implemented by this story.
