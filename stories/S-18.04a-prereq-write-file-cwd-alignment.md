# S-18.04a-prereq — write_file.rs cwd alignment + BC-2.02.011 §Inv3 + bats equal-roots fix

## Narrative

As the implementer preparing to build S-18.04a (native WASM precompact-flush plugin),
I want the write_file.rs unit-test facade, the BC-2.02.011 invariant, and the
precompact-routing.bats harness to correctly reflect production `ctx.cwd` semantics,
so that the S-18.04a Red Gate tests are non-tautological and downstream TDD is grounded
in the actual production write path rather than a stale unit-test artifact.

This story contains NO native WASM plugin code and NO new host capability. It is a
BLOCKING prerequisite that must merge to `develop` before S-18.04a branches.

**Production behavior is ALREADY correct:** `crates/factory-dispatcher/src/invoke.rs`
(lines 746-800) resolves relative paths under `ctx.cwd = CLAUDE_PROJECT_DIR`, matching
`read_file.rs` (lines 83-89: `resolve_for_read` uses `ctx.cwd`). Shipped plugins
(`regression-gate`, `update-wave-state-on-merge`) already write `.factory/` files via
this cwd-rooted production path. This story fixes the unit-test facade inconsistency,
the stale spec invariant, and the tautological bats test — not the production runtime.

## Acceptance Criteria

### AC-001 (traces to BC-2.02.011 invariant 3 — relative path resolution uses ctx.cwd)
In `crates/factory-dispatcher/src/host/write_file.rs`, the `resolve_for_write()`
function MUST resolve relative paths under `base: &Path` where `base` is `ctx.cwd`
(not `ctx.plugin_root`). Specifically:

```rust
// Before (stale):
let resolved = resolve_for_write(Path::new(path), &ctx.plugin_root);
if !path_allowed(&resolved, &caps.path_allow, &ctx.plugin_root) { ... }

// After (correct — matching invoke.rs production semantics and read_file.rs §resolve_for_read):
let resolved = resolve_for_write(Path::new(path), &ctx.cwd);
if !path_allowed(&resolved, &caps.path_allow, &ctx.cwd) { ... }
```

The `resolve_for_write` function signature remains unchanged (accepts a `base: &Path`
parameter). The `prepare()` caller passes `&ctx.cwd` instead of `&ctx.plugin_root`.
The `path_allowed` allowlist check is also updated to use `&ctx.cwd` as the base.
(traces to BC-2.02.011 invariant 3; ADR-028 §Decision 8 F-NW2-001/002/003)

### AC-002 (traces to BC-2.02.011 invariant 3 — unit tests updated to reflect ctx.cwd)
The unit tests in `write_file.rs` (lines ~200-265) that construct a `HostContext` for
testing MUST set `ctx.cwd` (not `ctx.plugin_root`) as the path-resolution base.
Specifically, every test that previously set `ctx.plugin_root = some_temp_dir` for the
purpose of resolving write paths MUST be changed to set `ctx.cwd = some_temp_dir`
instead. `ctx.plugin_root` should be set to a DISTINCT directory (not equal to `ctx.cwd`)
so the tests are non-tautological with respect to path-domain distinction.

After this change, the unit tests exercise the same path-domain as the production
`invoke.rs` implementation: relative paths are resolved under `ctx.cwd =
CLAUDE_PROJECT_DIR`, not `ctx.plugin_root = CLAUDE_PLUGIN_ROOT`.
(traces to BC-2.02.011 invariant 3; ADR-028 §Decision 8 F-NW2-001/002/003)

### AC-003 (traces to BC-2.02.011 invariant 3 — doc comment updated)
The `resolve_for_write` doc comment in `write_file.rs` MUST reflect `base` = `ctx.cwd`
(matching `read_file.rs::resolve_for_read`). The comment MUST include a note:
> "Resolves relative `path` under `base` = `ctx.cwd` (`CLAUDE_PROJECT_DIR`), mirroring
> `resolve_for_read` as of S-8.07. The prior `plugin_root`-rooted resolution in
> `prepare()` was a unit-test facade bug; production `invoke.rs` has always used
> `ctx.cwd`. S-18.04a-prereq aligns the unit-test facade to production semantics."
(traces to BC-2.02.011 invariant 3; ADR-028 §Decision 8 F-NW2-001/002/003)

### AC-004 (traces to BC-2.02.011 invariant 3 — Red Gate: write resolves under cwd not plugin_root)
A cargo unit test in `write_file.rs` MUST assert that a relative path (e.g., `.factory/STATE.md`)
resolves under `ctx.cwd`, NOT `ctx.plugin_root`, when both are set to distinct directories.

```rust
// Red Gate: fails before fix (resolve_for_write uses plugin_root)
// Passes after fix (resolve_for_write uses cwd)
#[test]
fn test_write_file_resolves_relative_path_under_cwd_not_plugin_root() {
    let cwd = tempdir().unwrap();
    let plugin_root = tempdir().unwrap();
    // cwd and plugin_root are DISTINCT directories
    assert_ne!(cwd.path(), plugin_root.path());
    let mut ctx = HostContext::default();
    ctx.cwd = cwd.path().to_path_buf();
    ctx.plugin_root = plugin_root.path().to_path_buf();
    // prepare() should resolve ".factory/STATE.md" under cwd, not plugin_root
    let resolved = resolve_for_write(Path::new(".factory/STATE.md"), &ctx.cwd);
    assert!(resolved.starts_with(cwd.path()));
    assert!(!resolved.starts_with(plugin_root.path()));
}
```

This test MUST FAIL before the AC-001 fix is applied (because the old code uses
`plugin_root`) and MUST PASS after.
(traces to BC-2.02.011 invariant 3; ADR-028 §Decision 8 F-NW2-003)

### AC-005 (traces to BC-2.02.011 invariant 3 — bats harness uses distinct CLAUDE_PLUGIN_ROOT and CLAUDE_PROJECT_DIR)
In `plugins/vsdd-factory/tests/precompact-routing.bats`, the `_run_dispatcher()` helper
at line ~216 MUST be updated so that `CLAUDE_PLUGIN_ROOT` and `CLAUDE_PROJECT_DIR` are
set to DISTINCT directories (not equal). The current tautological form:
```bash
# Before (tautological — both roots equal; path-domain tests are meaningless):
run bash -c "printf '%s' '$envelope' | CLAUDE_PLUGIN_ROOT='$WORK' CLAUDE_PROJECT_DIR='$WORK' '$DISPATCHER' 2>&1"
```
MUST be changed to:
```bash
# After (non-tautological — project dir is a subdirectory of WORK):
PROJECT_DIR="$WORK/project"
mkdir -p "$PROJECT_DIR"
run bash -c "printf '%s' '$envelope' | CLAUDE_PLUGIN_ROOT='$WORK' CLAUDE_PROJECT_DIR='$PROJECT_DIR' '$DISPATCHER' 2>&1"
```
All `path_allow` entries in the test registry stanzas that reference `$WORK` for
factory-artifacts paths MUST be updated to reference `$PROJECT_DIR` (or absolute paths)
so that the allowlist checks continue to pass under the new distinct-roots setup.
(traces to BC-2.02.011 invariant 3; ADR-028 §Decision 8 F-NW2-003)

### AC-006 (traces to BC-2.02.011 invariant 3 — Rust integration test: write lands under ctx.cwd not ctx.plugin_root)
The authoritative proof that the host `write_file` cwd-rooting is correct is the Rust
integration test `test_BC_2_02_011_invariant_3_relative_path_resolves_via_linker` in
`crates/factory-dispatcher/tests/host_write_file_integration.rs`. This test MUST:
- Set `ctx.cwd` and `ctx.plugin_root` to DISTINCT temporary directories
- Issue a `.factory/`-relative write via the host `write_file` linker path
- Assert the resolved write path starts_with `ctx.cwd`, NOT `ctx.plugin_root`

This test FAILS before the AC-001 fix (because `prepare()` used `&ctx.plugin_root`) and
PASSES after (because `prepare()` uses `&ctx.cwd`). It supersedes the previously planned
bats env-propagation assertion (TC-AC006-CWD-ENV), which was removed as redundant: the
bats test exercised subprocess env propagation of CLAUDE_PROJECT_DIR into the dispatcher,
not the host `write_file` resolution path itself. The Rust integration test is the
authoritative, direct proof of the cwd-rooting invariant at the host function level.

Note: AC-005 retains the bats distinct-roots de-masking infrastructure (CLAUDE_PLUGIN_ROOT
!= CLAUDE_PROJECT_DIR in `_run_dispatcher()`). AC-006 coverage of the write-resolution
path is carried by this Rust integration test rather than a duplicative bats assertion.
(traces to BC-2.02.011 invariant 3; ADR-028 §Decision 8 F-NW2-003)
