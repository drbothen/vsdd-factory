## Narrative

The E-21 W1 wave-gate security review identified W-SEC-001 (MEDIUM, CWE-693 — Protection Mechanism Failure): the Layer-2 main-checkout sync protocol delivered by S-21.01 in `plugins/vsdd-factory/agents/orchestrator/per-story-delivery.md §Main-Checkout Sync Protocol` is enforced exclusively by behavioral mandate (skill-doc). No technical control prevents an agent or operator from issuing `git pull origin develop`, `git merge <ref>`, or `git checkout <branch>` on the main checkout without first running the `git diff --name-only HEAD..<target-ref>` pre-check. If an agent skips the pre-check and a server-side-merged PR has dual-tracked `.factory/` paths on `develop`, the subsequent pull silently destroys factory artifact content — the exact scenario issue #342 documents.

ADR-031 §Decision 2 accepted this two-layer separation as a defense-in-depth trade-off: Layer-1 WASM prevents new dual-tracking at `git add` time; Layer-2 skill-doc mandates the merge pre-check. At the time of E-21 W1, the human directed that Layer-2 would remain skill-doc only (EMPTY host-set at v1.2, corrected to ad-hoc Bash surface at v1.3). The W-SEC-001 security review now directs a hardening story: a WASM PreToolUse guard that technically enforces the Layer-2 pre-check before any Bash `git pull`, `git merge`, or `git checkout` on the main product checkout can execute.

**What the WASM guard does:** The `validate-main-checkout-sync` plugin fires as a PreToolUse hook on every Bash tool call. If the command is a product-branch-advancing operation on the main checkout (`git pull`, `git pull --ff-only`, `git pull --rebase`, `git merge <ref>`, `git checkout <branch>`) AND NOT one of the documented PC3 exclusions (factory-worktree-only operations, non-working-tree operations), the plugin extracts the target-ref, runs `git diff --name-only HEAD..<target-ref>`, and:
- **Clean diff** → passes the command unconditionally (block_intent=false)
- **`.factory/`-rooted path detected** → blocks with block_intent=true (exit 2) and `FactoryPathDeletionInMergeDiff` error listing the at-risk paths
- **Pre-check fails** (unresolvable ref, network error, non-zero exit) → fail-open: logs a warning and passes (block_intent=false; BC-5.43.001 Invariant 4)

**Relationship to S-21.01 Layer-1:** Layer-1 (`validate-factory-path-staging`, priority 140) intercepts `git add`/`git stage` calls — it prevents new dual-tracking from forming at staging time. Layer-2 (this story, priority 141) intercepts `git pull`/`git merge`/`git checkout` — it prevents pre-existing dual-tracking (including the server-side origination vector: a contributor PR merged via GitHub carries `.factory/` paths that Layer-1 never saw) from destroying factory artifact content at merge time. The two layers together provide full coverage for INV-E21-001. Neither layer can replace the other.

**Target-ref extraction:** The plugin must correctly extract the target-ref from each command form:
- `git pull origin develop` → `origin/develop`
- `git pull --ff-only origin develop` → `origin/develop`
- `git pull --rebase origin develop` → `origin/develop`
- `git pull --ff-only` (no explicit remote/branch) → `origin/<current-branch>` (via `git symbolic-ref HEAD`)
- `git merge feature/S-21.06` → `feature/S-21.06`
- `git checkout develop` → `develop`
- `git -C <path> pull ...` (CWD-redirect) → if `<path>` names a `.factory/`-class directory → excluded (PC3: factory-worktree-only); otherwise same extraction logic

**Fail-open semantics on `origin/<branch>` form for `git pull`:** When the target-ref resolves to `origin/<branch>` and the remote ref is not yet available locally (because the fetch has not yet happened), `git diff --name-only HEAD..origin/<branch>` exits non-zero → fail-open per Invariant 4. This is the correct behavior for the pull-without-prior-fetch scenario: no hazard is known yet, so the command is allowed to proceed. In practice, the highest-value interception point is when `git fetch origin` has already updated the remote tracking refs before `git pull` runs — a common orchestrator pattern.

## Architecture Mapping

This story introduces one new WASM crate and one registry entry:

- **`crates/hook-plugins/validate-main-checkout-sync/`** — new Rust crate (native WASM). Single entry point: PreToolUse Bash hook. Responsibilities: (1) command classifier — identify product-branch-advancing git operations; (2) target-ref extractor — parse `git pull`/`git merge`/`git checkout` arguments to determine the target-ref; (3) pre-check executor — run `git diff --name-only HEAD..<target-ref>` via `exec_subprocess`; (4) path scanner — detect `^\.factory/` lines in diff output; (5) block emitter — emit `FactoryPathDeletionInMergeDiff` structured error on match; (6) fail-open handler — pass on pre-check subprocess failure. Follow the `validate-factory-path-staging/` crate structure (BC-4.16.001 / ADR-031 §Decision 3) as the reference pattern: `src/lib.rs` (hook entry point), `src/classifier.rs` (command detection), `src/extractor.rs` (target-ref parsing). Compiled WASM artifact: `plugins/vsdd-factory/hook-plugins/validate-main-checkout-sync.wasm`.

- **`plugins/vsdd-factory/hooks-registry.toml`** — add registry entry for `validate-main-checkout-sync` immediately after the `validate-factory-path-staging` block (priority 141, PreToolUse, `^Bash$`, on_error=continue). Comment header follows the established format (see `validate-factory-path-staging` comment block pattern).

- **`plugins/vsdd-factory/tests/validate-main-checkout-sync.bats`** — new bats suite. Covers AC-003..AC-009 using mock git scripts from `plugins/vsdd-factory/tests/fixtures/main-checkout-sync/`.

- **`plugins/vsdd-factory/tests/fixtures/main-checkout-sync/`** — mock git scripts for bats. Same fixture pattern as `plugins/vsdd-factory/tests/fixtures/validate-factory-path-staging/` (mock `git diff`, `git symbolic-ref`, `git -C`).

**ADR-031 §Decision 2** governs: this story hardened the Layer-2 enforcement from skill-doc-only to WASM PreToolUse guard. The Layer-1 `validate-factory-path-staging` crate (priority 140) is NOT modified. The Layer-2 skill-doc mandate in `per-story-delivery.md §Main-Checkout Sync Protocol` (S-21.01 deliverable, BC-5.43.001) remains in place as a defense-in-depth behavioral complement.

**Priority slot 141:** The Bash PreToolUse tier at priority 140 is occupied by `validate-factory-path-staging`. Priority 141 is the next available slot. The dispatcher sorts ascending; `validate-factory-path-staging` (140) fires first on every Bash tool call, then `validate-main-checkout-sync` (141) fires. Both are fail-open (`on_error=continue`); the order between them is not semantically significant for correctness.
